QA context engineering implementation

Reason once.
Enforce every time.

Give each model a bounded, complete, cited context pack. Let a stronger arbiter challenge and override investigator claims. Keep evidence, promotion, mutation, and verification under deterministic control.

Decision boundary

The arbiter can overrule an investigator.

Its authority is semantic, not operational. Every override must point to immutable evidence and pass a code-enforced gate.

  • Replace, merge, split, confirm, or refute a theory.
  • Cannot invent evidence, weaken acceptance criteria, or authorize a patch.

What worked

What failed

  • Cache-read share fell from 81.8% to 41.8% of input-plus-cache-read accounting.
  • The arbiter failed strict output validation and used deterministic fallback.

Keep the architecture; tighten the projections before claiming efficiency.

The implementation now has the intended immutable context, validation, authority, repair, and telemetry boundaries. This one paired trial does not support an effectiveness or cost claim. The next experiment should shrink mapper and arbiter inputs, reserve defect-generation capacity for adversarial hypotheses, add explicit asymmetric-set and boundary-value invariants, and require arbiter correction to converge without fallback.

01 / SYSTEM FLOW

The old pipeline asked agents to discover. The implemented pipeline asks them to decide.

The intended efficiency mechanism is not a shorter instruction header. It is moving repository discovery into one reusable, deterministic foundation and projecting only the relevant slices downstream; the measured result shows those slices still need to become smaller.

Current

Thin packets, repeated discovery

Stage names imply semantic judgment, but much of synthesis and adjudication is exact matching and validation.

Deterministic

Path-based shard mapper

Groups by directory and extension. Assigns every expectation ID to every shard.

Agent per shard

Investigator reads the repository

Receives paths, risk tags, fingerprints, and check IDs. It must rediscover requirement meaning, source behavior, and relationships.

Round trip

Context expansion becomes a new task

Approved paths are handed to a fresh follow-up shard, causing repeated reads and lost reasoning state.

Deterministic

Synthesis by normalized string keys

Sorts and groups claims, detects narrow contradictions, and schedules inconclusive follow-ups.

Deterministic

Evidence and adjudication

Validates fingerprints, containment, repeatability, and accepted failing evidence before promotion.

Agent per issue

Repair from another thin packet

Gets IDs and path bounds, but not the complete theory, exact requirement, failure excerpt, or relevant source blocks.

Efficiency failure: the same facts are rediscovered across mapper, investigators, follow-ups, and repairs. The system spends tool calls reconstructing context it already possessed upstream.
Implemented

Complete packs, bounded judgment

Models receive the evidence needed for their decision. Code validates every boundary and owns side effects.

Built once

Frozen QA foundation

Exact requirements, diff hunks, symbols, review facts, source excerpts, dependency edges, check catalog, provenance, and fingerprints.

Strong structured model

Semantic mapper

Proposes behavioral shards and exact requirement ownership from the foundation. No repository tools unless the pack has a declared gap.

Deterministic

Map validator and projector

Checks coverage, path containment, budgets, and freshness. Produces a minimal cited pack for each shard.

Model first, agent fallback

Shard investigators

Decide from exact criteria and cited source blocks. Any expansion appends a delta to the same session.

More powerful model

Cross-shard arbiter

Challenges claims, resolves semantic conflicts, merges root causes, and emits explicit override records tied to evidence.

Deterministic

Adjudication, repair bounds, verification

Validates arbiter references and promotion rules, builds issue packs, applies patches, and runs deduplicated checks.

Authority remains layered.

Models interpret. Deterministic code validates evidence and policy. Only the product applies mutations.

03 / ARBITER AUTHORITY

A stronger arbiter can change the conclusion, never the record.

The investigator is a witness, not the final semantic authority. The arbiter receives a broader cross-shard view and may supersede a local claim when its cited reasoning is stronger.

Arbiter may

  • Confirm, refute, or replace an investigator’s claim.
  • Merge duplicate theories or split an over-broad theory.
  • Resolve contradictions using cross-shard context.
  • Identify a shared root cause or interaction.
  • Request a precisely scoped follow-up when evidence is insufficient.

Arbiter may not

  • Create, edit, or relabel immutable evidence results.
  • Cite a source block, theory, or check that does not exist.
  • Relax an acceptance criterion or path boundary.
  • Promote a claim without the required failing evidence.
  • Apply a patch or decide that verification passed.
04 / CONTEXT PACKS

A context pack is a cited projection, not a larger prompt.

It should contain the minimum complete evidence for one decision. Every block is addressable, attributable, and reusable without another repository search.

Foundation contract

Stable facts, once

Build after implementation and execution are frozen. Address each unit as kind:id@hash, then project by consumer.

  • Exact text, not just IDs
  • Source and execution provenance
  • Snapshot fingerprint
  • Explicit omissions and budgets
01

Identity

Run, map, baseline, implementation, and check-plan fingerprints. Stale packs fail closed.

02

Acceptance

Exact requirement and acceptance-criterion text keyed by ID, including source provenance.

03

Change

Baseline-to-current diff hunks, enclosing symbols, full small files, and content-addressed excerpts for large files.

04

Relationships

Call, data, interface, configuration, dependency, and test edges relevant to the changed behavior.

05

Prior knowledge

Execution handoff, path-relevant review findings, post-execution source excerpts, and known uncertainties.

06

Evidence

Approved check descriptors, sanitized results, repeatability metadata, expected versus observed behavior, and bounded logs.

07

Authority

Readable and writable paths, live-read policy, tool budget, output schema, and required citation fields.

When code approves extra paths, append the exact excerpts and relationships to the same investigator session. Start a fresh follow-up only when the investigative objective changes.

05 / REPAIR EFFICIENCY

Keep per-issue repair until grouping changes the unit of work.

The two current modes perform the same number of model proposals and isolated mutations. Grouped mode only reuses a conversation session, while resending full packets into an ever-growing history.

Recommendation: per issue, with a complete issue pack and a cached stable prefix.

Later, add semantic repair clusters only when issues share a root cause, writable paths, and verification surface. Cap clusters at two or three issues.

Most efficient now

Repair pack additions

  • Complete promoted theory and arbiter override chain.
  • Exact acceptance text and expected versus observed behavior.
  • Bounded failure output and accepted evidence records.
  • Relevant source excerpts and dependency edges.
  • Separate read-only context and writable path allowlists.
  • Current target delta, including prior campaign patches.

Mechanical savings

  • Run identical evidence checks once per frozen snapshot.
  • Map one result to every shard that cites the check.
  • Deduplicate identical repair gates before execution.
  • Defer campaign-wide smoke once, then run it at the end.
  • Cache stable repair instructions and project metadata.
  • Do not call an unused three-vote evaluator.
