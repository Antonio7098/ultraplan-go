## Summary

Agent Framework has no first-class `Plan` object with explicit lifecycle/status machine. "Plan" is implemented as two complementary substrates: (1) a **Todo list** (`TodoProvider` / `TodoStore` / `TodoItem`) that is the authoritative executable plan, and (2) a **markdown plan file** in session file-memory (`FileMemoryProvider`) produced during `plan` mode. Lifecycle is driven by `AgentModeProvider` (`plan` → `execute` via `mode_set`), `AgentLoopMiddleware` (`todos_remaining` / `with_judge`), and—only in multi-agent orchestrations—the Magentic manager's `TaskLedger` (facts + plan) with stall-aware `replan()` and human plan-review gate. Mutations are immediate tool calls (`todos_add`/`todos_complete`/`todos_remove`), persisted per-session (atomically) but overwriting in place without versioned revision history. Completion is checked via `todos_get_remaining`, `TodoCompletionLoopEvaluator`, and Magentic `ProgressLedger.is_request_satisfied`. Drift/stuck detection exists only in Magentic (`is_in_loop`/`is_progress_being_made` + `stall_count` > `max_stall_count=3` → `_reset_and_replan`), not in the single-agent harness.

## Rating

**5/10 — Present but inconsistent, weakly documented and fragile for lifecycle guarantees**

Rationale: Creation, atomic mutation, and persistence exist with tests, per-session locks, and atomic file writes. However: (a) plan revisions overwrite in place — no preserved history/diff, no invalidation protocol; (b) justification is limited to the `reason` string on `todos_complete`; (c) single-agent drift detection is instructional text only, no framework validator; (d) status transitions are implicit booleans (`is_complete`) rather than an observable state machine with events; (e) Magentic's replanning is the only mature closed-loop lifecycle, and it does not apply to the harness/todo path that most samples use. Score would rise to 7 with versioned `PlanStore`, status events on `PlanUpdate`, and a cross-harness drift guard.

## Answers to Dimension Questions

### 1. Can plans change?
**Yes, freely and by design.** For harness plans (Todo list): `todos_add` appends, `todos_remove` deletes, `todos_complete` flips `is_complete` (`python/packages/core/agent_framework/_harness/_todo.py:550-625`). File-memory plan files are overwritten ("Keep memories up-to-date by overwriting files when information changes" `python/packages/core/agent_framework/_harness/_file_memory.py:60-66` and `python/packages/core/agent_framework/_harness/_mode.py:53`). For orchestrated plans (Magentic): `StandardMagenticManager.replan()` regenerates facts+plan via LLM prompts and replaces `self.task_ledger` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:642-680`), and any user edit during plan review triggers the same path (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1017-1020`).

### 2. Are changes justified?
**Partially.** `todos_complete` enforces a natural-language justification per item (`TodoCompleteInput.reason`, non-empty check `python/packages/core/agent_framework/_harness/_todo.py:162-178` and handler `python/packages/core/agent_framework/_harness/_todo.py:585-610`). Mode instructions require the agent to note its choice when encountering ambiguity (`python/packages/core/agent_framework/_harness/_mode.py:62-63`). Magentic replanning is justified structurally: progress ledger returns `reason` fields for each verdict (`MagenticProgressLedgerItem.reason` `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:295-310`) and replanning prompt asks model to "briefly explain what went wrong ... root cause" (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:185-192`). However, `todos_add`/`todos_remove` carry no reason field, no diff/reason is persisted alongside the todo mutation, and the final plan file overwrite is not annotated.

### 3. Is old plan history preserved?
**No — revision history is not preserved.** `TodoSessionStore` and `TodoFileStore` both persist only the current snapshot `{"items":[...],"next_id":N}` (`python/packages/core/agent_framework/_harness/_todo.py:265-295,395-425`); `todos_remove` physically deletes entries, and completion flips a boolean in place. File-memory writes overwrite. `AgentLoopMiddleware` aggregates transcript messages (`python/packages/core/agent_framework/_harness/_loop.py:715-745`) and Magentic appends prompts to `chat_history` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:670-675`), but the prior `_MagenticTaskLedger` is replaced and only a `REPLANNED` event (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1163-1170`) is emitted — there is no version store, no `revision_id`, no diff chain, and `WorkflowCheckpoint` (`python/packages/core/agent_framework/_workflows/_checkpoint.py:40-110`) snapshots state but is not wired as a plan revision log.

### 4. Can the agent abandon a plan?
**Yes.** Explicit abandonment primitives: `todos_remove(ids)` removes any subset (`python/packages/core/agent_framework/_harness/_todo.py:612-625`), `file_memory_delete_file` deletes the persisted plan file, `MagenticContext.reset()` clears `chat_history` and resets stall state (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:385-393`), and the progress ledger can declare `is_request_satisfied=true` to short-circuit to `_prepare_final_answer` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1104-1108`). Workflow-level abandonment is implicit via `OutputDesignation`/`max_rounds`/`max_reset_count` termination (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1239-1245`) or loop `max_iterations` (`python/packages/core/agent_framework/_harness/_loop.py:200-210`). Mode instructions explicitly allow removing irrelevant items when the user changes topic (`python/packages/core/agent_framework/_harness/_todo.py:27-32`).

### 5. Can plan drift be detected?
**Only in Magentic; not in the single-agent harness.** Magentic detects drift/stuck via model-generated `MagenticProgressLedger`: `is_in_loop=true` or `is_progress_being_made=false` increments `stall_count`, which triggers `_reset_and_replan` when exceeding `max_stall_count` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1110-1118`). The generic harness has no validator: drift guidance is advisory text ("ensure you update the todo list accordingly" `python/packages/core/agent_framework/_harness/_todo.py:27-32`, "check the current mode" `python/packages/core/agent_framework/_harness/_mode.py:20-23`), and `AgentLoopMiddleware` only detects drift if caller supplies a custom `should_continue` or `with_judge` predicate (`python/packages/core/agent_framework/_harness/_loop.py:165-310`). There is no automatic cross-check between executed actions and todo plan; `background_tasks_running`/`todos_remaining` are the closest loop guards.

## Architectural Decisions

- **Todo list as de-facto plan** — No `Plan` class; executable `TodoItem(id,title,description,is_complete)` (`python/packages/core/agent_framework/_harness/_todo.py:45-112` .NET `dotnet/src/Microsoft.Agents.AI/Harness/Todo/TodoItem.cs:12-40`) is the plan. Decision favors flexibility over typed lifecycle state machine. Consequence: status transitions are `bool` toggles, not observable `PlanStatus` enum with events.
- **Dual persistence (session vs file)** — `TodoSessionStore` (in-memory `session.state`, default) vs `TodoFileStore` (JSON per owner/session/source_id, atomic `os.replace`) (`python/packages/core/agent_framework/_harness/_todo.py:265-425`). Atomic writes and path-traversal validation are production-grade, but neither store versions history.
- **Mode-mediated planning** — `AgentModeProvider` splits `plan` (interactive, clarifications, write file, ask approval, `mode_set` to execute) vs `execute` (autonomous) (`python/packages/core/agent_framework/_harness/_mode.py:36-64`). Writes plan to `FileMemoryProvider` for compaction resilience. External `set_agent_mode` injects a user notification on next `before_run` so system instructions aren't ignored (`python/packages/core/agent_framework/_harness/_mode.py:150-260`).
- **Loop middleware superstructure** — `AgentLoopMiddleware` with `todos_remaining` predicate re-invokes agent until todos cleared (`python/packages/core/agent_framework/_harness/_loop.py:773-785`, .NET `TodoCompletionLoopEvaluator` `dotnet/src/Microsoft.Agents.AI/Harness/Loop/TodoCompletionLoopEvaluator.cs:100-135`). Loop caps `max_iterations` and optionally `fresh_context`/progress injection.
- **Magentic as separate replanning island** — Fact/plan ledger + progress ledger (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:285-355`) with stall-counter-driven `replan()` and human-in-the-loop `MagenticPlanReviewRequest` gate. Replanning is model-driven (prompts `ORCHESTRATOR_TASK_LEDGER_FACTS_UPDATE_PROMPT`/`ORCHESTRATOR_TASK_LEDGER_PLAN_UPDATE_PROMPT`) and emits `REPLANNED` workflow events, but is not reused by the harness todo flow.

## Notable Patterns

- **Per-session serialized mutations** — `TodoProvider._mutation_locks: WeakKeyDictionary[AgentSession, asyncio.Lock]` (`python/packages/core/agent_framework/_harness/_todo.py:480-500`) and .NET `ConditionalWeakTable<AgentSession, SemaphoreSlim>` (`dotnet/src/Microsoft.Agents.AI/Harness/Todo/TodoProvider.cs:45-65`) prevent duplicate IDs and lost updates under concurrent tool calls; lock auto-evicts on GC (`python/packages/core/tests/core/test_harness_todo.py:130-145`).
- **Reason-gated completion** — `TodoCompleteInput(reason)` validated non-empty and threaded into `todos_complete` (`python/packages/core/agent_framework/_harness/_todo.py:160-210`). Minimal but explicit justification channel.
- **Notification trick for external mode changes** — `_PREVIOUS_MODE_STATE_KEY` (`python/packages/core/agent_framework/_harness/_mode.py:110-130`) injected as user message because "system instructions alone are insufficient to redirect a model that has already seen its own `set_mode` tool call" (`python/packages/core/agent_framework/_harness/_mode.py:240-260`).
- **Progress ledger as structured drift sensor** — Model returns JSON with `{reason, answer}` for satisfaction/loop/progress (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:310-330`), used to select next speaker and decide stall.
- **Judge-pattern replanning** — `with_judge(criteria, instructions)` where `{{criteria}}` placeholder is replaced and verifier text feeds back as `feedback` kwarg to next iteration (`python/packages/core/agent_framework/_harness/_loop.py:120-215`).

## Tradeoffs

- **Flexibility vs. auditability** — Free-form todo edits and file overwrites make planning ergonomic but lose the why/when of each revision. `todos_remove` deletes rather than tombstones; `todos_complete` reason is not persisted alongside the item's history.
- **Session persistence vs. cross-session durability** — `TodoSessionStore` is default (ephemeral to `AgentSession.state`); `TodoFileStore` is opt-in and namespaced by `owner_prefix`/`kind`/`source_id`. Neither provides retention policy or export, and there is no migration for schema changes to todo JSON.
- **Magentic quality vs. applicability** — Best-in-class stall detection and LLM-replanning with `max_stall_count`/`max_reset_count` bounds, but confined to multi-agent orchestrations. Harness single-agent path has no equivalent automatic drift guard — relies on prompt compliance.
- **Atomicity vs. history** — Atomic file replacement prevents corruption (`TodoFileStore._save_state_sync` `python/packages/core/agent_framework/_harness/_todo.py:410-425`, test `test_harness_todo_file_store_writes_state_atomically` `python/packages/core/tests/core/test_harness_todo.py:85-100`) but sacrifices recoverability of prior plans.
- **Explicit mode switch vs. implicit intent** — Requiring `mode_set` tool call or external `set_agent_mode` (`python/packages/core/agent_framework/_harness/_mode.py:170-230`) makes transitions explicit and observable in transcript, but adds friction and creates the anchoring problem that needs the notification workaround.

## Failure Modes / Edge Cases

- **Silent plan divergence** — Harness instructions to update todos on user topic change (`python/packages/core/agent_framework/_harness/_todo.py:27-32`) are not enforced. Agent can add new tasks without removing obsolete ones; `todos_remaining` will keep looping on stale items or, conversely, `todos_get_all` will show phantom open work. No framework validator compares executed tool calls to todo titles.
- **Lost reason context** — `todos_complete` reason is consumed as tool argument but not stored on `TodoItem`; only `is_complete` persists (`python/packages/core/agent_framework/_harness/_todo.py:45-70`, `TodoItem.cs`). Audit query "why was plan item 7 completed?" cannot be answered from state; must scrape transcript.
- **Collision after corrupted next_id** — Mitigated by `_safe_next_id` clamping (`python/packages/core/agent_framework/_harness/_todo.py:222-224`, test `test_todo_stores_clamp_next_id...` `python/packages/core/tests/core/test_harness_todo.py:130-150`) but file corruption still throws `ValueError` on load (`python/packages/core/agent_framework/_harness/_todo.py:192-230`) with no recovery/repair path.
- **Path traversal / state poisoning** — `TodoFileStore._path_segment` rejects `/`/`\` in `session_id` and Windows reserved stems (`python/packages/core/agent_framework/_harness/_todo.py:360-395`), and `test_todo_file_store_rejects_session_path_traversal` confirms. However, `TodoSessionStore` trusts `session.state[source_id]` is a dict; malformed state raises `ValueError` mid-tool-call, aborting the planning turn.
- **Stall oscillation** — Magentic decrements `stall_count` on progress (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1113`) but caps at 0; flapping between progress/no-progress can prevent ever reaching `max_stall_count` and delay replanning indefinitely. Conversely, a transient `is_in_loop` false positive increments and may trigger premature reset+LLM replan (costly, clears `chat_history`).
- **Progress ledger parse failure** — `_run_inner_loop_helper` catches any exception from `create_progress_ledger` and triggers `_reset_and_replan` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1083-1085`). Persistent model inability to emit valid JSON causes infinite reset loop bounded only by `max_reset_count` (default `None` = unlimited).
- **Fresh-context session discard** — `AgentLoopMiddleware` with `fresh_context=True` snapshots session before loop and restores baseline before each iteration (`python/packages/core/agent_framework/_harness/_loop.py:360-400,450-500`). In-loop file-memory plan writes and todo mutations between iterations are discarded except the progress log — can silently drop a plan revision if developer enables fresh_context alongside `TodoProvider`.
- **Invalid next_speaker** — Magentic falls back to first participant if ledger returns non-string (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1130-1145`), masking model error as silent mis-routing rather than surfacing it.

## Future Considerations

- Introduce a versioned `PlanStore` (backed by `TodoFileStore` pattern but with append-only JSONL or `previous_checkpoint_id` chain like `WorkflowCheckpoint` `python/packages/core/agent_framework/_workflows/_checkpoint.py:35-90`) so every `todos_add/complete/remove` and file-memory plan write produces an immutable revision with `reason`, `author` (user vs model), and diff.
- Replace `is_complete: bool` with explicit `TodoStatus` enum (`pending/in_progress/blocked/completed/abandoned`) and emit `WorkflowEvent(type="todo_updated")` for observability; wire to `AGENT_FORWARDED_EVENT_TYPES` if plan events should surface via `workflow.as_agent()`.
- Promote Magentic stall/progress ledger to a shared harness utility: provide a default `should_continue = drift_detector(llm_client, todos)` so single-agent loops get automatic stuck detection without per-caller predicate.
- Persist `TodoCompleteInput.reason` on the `TodoItem` (e.g., `completion_reason` field) and retain removed items as tombstones with `removed_at`/`removed_reason` instead of deleting — enables post-hoc "why did the plan change?" queries.
- Add `PlanValidator` hook executed before each loop iteration (compare remaining todos to recent tool calls/observations, flag orphaned or contradicted items) and surface drift as `warning` workflow event (`python/packages/core/agent_framework/_workflows/_events.py:80-110`).
