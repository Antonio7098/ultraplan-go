## Summary

CrewAI implements a Plan-and-Execute lifecycle centered on `AgentReasoning` → `TodoList` → `StepExecutor` → `PlannerObserver` inside `AgentExecutor` (Flow). Initial plan creation generates a natural-language plan plus structured `PlanStep[]` via function calling (`AgentReasoning.handle_agent_reasoning()`), converted to tracked `TodoItem[]` in `AgentExecutorState.todos`. Plan mutation is tiered: lightweight in-place refinements (`StepRefinement` via `PlannerObserver.apply_refinements`, no second LLM call) versus full regeneration (`replace_pending_todos` preserving completed/failed/running). Replanning is gated by `PlanningConfig.reasoning_effort` (low/medium/high) and `max_replans`, triggered by per-step `StepObservation` fields (`needs_full_replan`, `step_completed_successfully`, `goal_already_achieved`, `remaining_plan_still_valid`) rather than free-form drift detection. Completion is an explicit state machine (`TodoList.is_complete` checks all items are terminal `completed|failed`, plus dedicated `goal_achieved` and `finalize` synthesis). Revision history is in-memory only: `state.observations` (per-step `StepObservation`), `state.execution_log` (audit trail, explicitly NOT sent to LLM), `replan_count`/`last_replan_reason`, and `ToolUsage`/`PlanRefinement`/`PlanReplanTriggered` events persisted only if Flow checkpointing is enabled — no durable versioned plan store, no cross-run plan audit, and no plan-drift metric.

## Rating

**5 / 10** — Present but inconsistent/fragile.

**Rationale:** The plan model, update/replan contracts, and completion guards are explicit, typed, and covered by unit tests. However persistence is ephemeral, revision history is limited to the live `AgentExecutorState` (wiped on `invoke()`), drift detection is implicit LLM judgment with no quantitative threshold, abandonment is not safe (replan preserves history but cannot cancel running parallel steps), and the legacy `CrewPlanner` (task-level string plan) coexists without alignment to the `TodoList` lifecycle. The implementation mentions durability via `state.execution_log` but that log is reset each execution and only survives via optional Flow checkpoints.

## Answers to Dimension Questions

**1. Can plans change?**
Yes — explicitly and via two distinct mechanisms. *Lightweight refinement*: `PlannerObserver.observe()` returns `StepRefinement[]` (`lib/crewai/src/crewai/utilities/planning_types.py:198-209`) applied directly by `PlannerObserver.apply_refinements()` (`lib/crewai/src/crewai/agents/planner_observer.py:215-242`) mutating pending `TodoItem.description` in-place without a second LLM call, triggered via `handle_refine_and_continue` (`lib/crewai/src/crewai/experimental/agent_executor.py:969-1013`). *Full regeneration*: `AgentExecutor._trigger_replan()` re-invokes `AgentReasoning.handle_agent_reasoning()` with `_enhance_task_for_replan()` context and `TodoList.replace_pending_todos()` (`lib/crewai/src/crewai/utilities/planning_types.py:185-195`, `lib/crewai/src/crewai/experimental/agent_executor.py:2626-2701`). Both preserve completed/failed/running items.

**2. Are changes justified?**
Partially. Every mutation has a required reason field: `StepObservation.replan_reason` (`lib/crewai/src/crewai/utilities/planning_types.py:271-273`), `AgentExecutorState.last_replan_reason` and `replan_count` (`lib/crewai/src/crewai/experimental/agent_executor.py:158-163`), `PlanReplanTriggeredEvent.replan_reason/replan_count/completed_steps_preserved` (`lib/crewai/src/crewai/events/types/observation_events.py:110-121`), `PlanRefinementEvent.refinements` (`lib/crewai/src/crewai/events/types/observation_events.py:98-108`), and `StepObservationCompletedEvent` capturing `key_information_learned`, `remaining_plan_still_valid`, `needs_full_replan`, `goal_already_achieved` (`lib/crewai/src/crewai/events/types/observation_events.py:70-84` plus `lib/crewai/src/crewai/agents/planner_observer.py:171-187`). `execution_log` stores observation reason alongside `reasoning_effort`/`llm_observation` (`lib/crewai/src/crewai/experimental/agent_executor.py:715-727`). Weakness: `replan_reason` is LLM-generated free text with no schema validation, and heuristic path (`heuristic_observation`) produces empty justification (`key_information_learned=""`, `lib/crewai/src/crewai/agents/planner_observer.py:105-111`).

**3. Is old plan history preserved?**
No durable history — only ephemeral in-memory preservation. `replace_pending_todos` explicitly discards old pending items (“Preserves completed, failed, and running todos, replaces only pending ones”, `lib/crewai/src/crewai/utilities/planning_types.py:186-189`). Completed/failed items and their `result` strings are kept in `state.todos.items` and `state.observations` (`lib/crewai/src/crewai/experimental/agent_executor.py:136-172`). `execution_log` is process-local and cleared on every `invoke()`/`invoke_async()`/`_prepare_feedback_iteration()` (`lib/crewai/src/crewai/experimental/agent_executor.py:2879-2883,2965-2968,3305-3308`). `state.plan` (the natural-language summary string) is overwritten on replan (`lib/crewai/src/crewai/experimental/agent_executor.py:2685-2686`) with no prior-plan snapshot array. No file, DB, or checkpoint-backed plan version list exists; only optional Flow checkpointing (`CheckpointConfig`, `lib/crewai/src/crewai/crew.py:397-404`) can snapshot the entire `AgentExecutorState`, which is unrelated to plan-versioning semantics and not tested for plan history.

**4. Can the agent abandon a plan?**
Yes, via three abandonment paths, but not via explicit “cancel plan” API. (a) *Early goal achievement*: `StepObservation.goal_already_achieved==True` routes `decide_next_action→goal_achieved→handle_goal_achieved` emitting `GoalAchievedEarlyEvent` and returning `all_todos_complete` which skips remaining todos (`lib/crewai/src/crewai/experimental/agent_executor.py:910-920,1022-1046`). (b) *Max replans exhaustion*: `handle_replan_now` / `handle_replan` / `_should_replan` gate on `max_replans` (default 3, `lib/crewai/src/crewai/agent/planning_config.py:122-126`) and finalize with current results (`lib/crewai/src/crewai/experimental/agent_executor.py:1058-1065,2588-2589`). (c) *Fallback without todos*: `check_todos_available → planning_disabled/no_todos` falls back to ReAct loop (`lib/crewai/src/crewai/experimental/agent_executor.py:1090-1103`). There is no safe “abort current plan” that cancels already-dispatched parallel `StepExecutor` threads — `execute_todos_parallel` (`lib/crewai/src/crewai/experimental/agent_executor.py:1258-1391`) fires `asyncio.gather` with no cancellation token.

**5. Can plan drift be detected?**
Weakly/indirectly. The intended detector is `PlannerObserver` LLM judgment: after every step, `observe()` (`lib/crewai/src/crewai/agents/planner_observer.py:113-213`) is prompted with `observation_system_prompt` to assess step verifiability and decide `remaining_plan_still_valid` vs `needs_full_replan` (`lib/crewai/src/crewai/translations/en.json:88`). `TodoList._dependencies_satisfied` treats `failed` as terminal to avoid permanent blocking (`lib/crewai/src/crewai/utilities/planning_types.py:112-131`), and `get_ready_todos` + deadlock replan handles structural drift (`lib/crewai/src/crewai/experimental/agent_executor.py:1119-1132`). `_should_replan` adds heuristic markers (≥2 failures, error prefix, last message keywords, `lib/crewai/src/crewai/experimental/agent_executor.py:2592-2622`). However there is no numeric drift score, no divergence threshold, no step-vs-plan compliance checker, and `low` reasoning effort deliberately skips the LLM observer entirely (`lib/crewai/src/crewai/experimental/agent_executor.py:590-602`), so drift is invisible at low effort.

## Architectural Decisions

* **Plan-and-Execute as a Flow graph, not a plain loop** (`lib/crewai/src/crewai/experimental/agent_executor.py:384-1409`): `generate_plan` is a `@start()` node, `observe_step_result` is a `@router`, and refinement/replan/continue are distinct routers/listeners. Benefit: formal state machine with eventBus integration; cost: high complexity, duplicated executor file (`experimental/agent_executor.py` vs `experimental/experimental/agent_executor.py`), and reliance on Flow’s implicit kickoff ordering.
* **Two planning subsystems**: crew-level `CrewPlanner` producing per-task natural-language `PlanPerTask.plan:str` (`lib/crewai/src/crewai/utilities/planning_handler.py:15-164`) vs agent-level `AgentReasoning` producing structured `PlanStep[]`/`TodoList`. Decision retains backward compatibility (`planning:bool` in `crew.py:344-347` vs `PlanningConfig` in `agent/core.py:310-342`) but creates duplicate concepts and the legacy `task.description += Planning:` mutation (`lib/crewai/src/crewai/agent/agent/utils.py:55`) that newer executor explicitly avoids (“Do NOT mutate task.description”, `lib/crewai/src/crewai/experimental/agent_executor.py:419-421`).
* **Structured `PlanStep` via OpenAI function calling with fallback text parsing** (`lib/crewai/src/crewai/utilities/reasoning_handler.py:351-445`): function calling preferred for dependency tracking; fallback uses string search for `"READY: ..."`. Decision enables dependency-aware parallel execution but fallback drops structured steps (`return plan, [], ready`).
* **Observation is LLM-first with heuristic fallback** (`lib/crewai/src/crewai/agents/planner_observer.py:88-213`, `lib/crewai/src/crewai/experimental/agent_executor.py:616-646`): when `observe_steps=False` or `reasoning_effort=="low"` the system uses `heuristic_observation` (no LLM). `observe()` failure defaults to `step_completed_successfully=True, remaining_plan_still_valid=True` (`lib/crewai/src/crewai/agents/planner_observer.py:208-213`) — i.e., “keep going” — whereas unparseable LLM output defaults to `success=False, valid=False` (`lib/crewai/src/crewai/agents/planner_observer.py:342-352`). The asymmetry is intentional for resilience but hides failures.
* **In-place refinement vs pending replacement** (`lib/crewai/src/crewai/utilities/planning_types.py:185-195` and `lib/crewai/src/crewai/agents/planner_observer.py:215-242`): refinement is cheapest (no LLM regeneration), replan is complete but preserves non-pending. Decision minimizes token cost but refinement can only rewrite `description`, not `tool_to_use` or `depends_on`.
* **`failed` is terminal for `is_complete`** (`lib/crewai/src/crewai/utilities/planning_types.py:69-71`): plan can be “complete” without succeeding. Decision allows synthesis to run and replan guards to trigger, but conflates success/completion for status consumers.

## Notable Patterns

* **Tiered reasoning effort as a policy knob**: `low` (heuristic, no refinement/replan unless hard `needs_full_replan`), `medium` (replan on failure only), `high` (full routing: goal-achieved → replan → failed → refine → continue). Implemented via three separate router handlers (`lib/crewai/src/crewai/experimental/agent_executor.py:747-968`) rather than a single parameterized branch, making per-tier behavior testable.
* **Dependency-aware ready queue**: `TodoList._dependencies_satisfied` + `get_ready_todos` + `can_parallelize` (`lib/crewai/src/crewai/utilities/planning_types.py:112-154`) and `execute_todos_parallel` (`lib/crewai/src/crewai/experimental/agent_executor.py:1258-1391`) enable DAG-parallel step execution with isolation via `StepExecutionContext` (`lib/crewai/src/crewai/utilities/step_execution_context.py:13-31`).
* **Event-sourced audit without durability**: every lifecycle mutation emits a typed event (`PlanStepStarted/Completed`, `StepObservationStarted/Completed/Failed`, `PlanRefinement`, `PlanReplanTriggered`, `GoalAchievedEarly`, `AgentReasoning*`); in-memory `execution_log` mirrors them but is not replayable. Useful for tracing when a listener is attached.
* **Synthesis validator as completion gate**: `finalize()` (`lib/crewai/src/crewai/experimental/agent_executor.py:2376-2569`) synthesizes a coherent answer from `todo.result[]` via LLM (`synthesis_system_prompt/user_prompt` in `lib/crewai/src/crewai/translations/en.json:98-99`), with structured `response_model` support and concatenation fallback.
* **Context fencing**: `StepExecutor._build_isolated_messages` + `_build_context_for_todo` pass only `dependency_results: dict[int,str]` (`lib/crewai/src/crewai/experimental/agent_executor.py:647-678`, `lib/crewai/src/crewai/agents/step_executor.py:244-326`) — no shared `messages` history, reducing cross-step leakage.

## Tradeoffs

* **Expressiveness vs durability**: Rich `StepObservation` captures nuanced judgment, but its free-text fields (`key_information_learned`, `replan_reason`) are not validated and stored only ephemerally; operators cannot query “why did plan change last Tuesday.”
* **Latency vs adaptivity**: `reasoning_effort` lets users trade per-step LLM observation cost for responsiveness (`low` adds ~0 ms, `high` adds one LLM call per step). The default `medium`/`observe_steps=None` inconsistency (`lib/crewai/src/crewai/agent/planning_config.py:89-97`) — code defaults to `medium` even when no config set (`lib/crewai/src/crewai/experimental/agent_executor.py:564-567`) — means the verbose path is on by default despite docs presenting `low` as fastest.
* **Safety vs liveness in replacement**: `replace_pending_todos` preserves failed todos so they do not recur, but failed steps remain counted toward `is_complete` and toward `failed_todos>=2` replan threshold — a plan that “completed” with failures can still trigger another replan, risking oscillation up to `max_replans`.
* **Parallelism vs determinism**: `get_ready_todos` + `asyncio.gather` + `ThreadPoolExecutor` for native tool batches improves throughput but makes observation ordering non-deterministic for parallel steps (observed sequentially post-gather, `lib/crewai/src/crewai/experimental/agent_executor.py:1342-1377`) and abandons drift detection inside a parallel batch until all siblings finish.
* **Dual-planner tax**: maintaining `CrewPlanner` (task string plan) and `AgentReasoning` (agent todo plan) increases surface area and configuration drift (`planning:bool` vs `planning_config:PlanningConfig`), requiring consumers to reason about two planning flags.

## Failure Modes / Edge Cases

* **Heuristic path hides failures**: `heuristic_observation` returns `success=step_success` with `key_information_learned=""` and no drift analysis; at `low` effort, `handle_step_observed_low` only triggers `replan_now` when `success==False AND needs_full_replan==True` (`lib/crewai/src/crewai/experimental/agent_executor.py:767-789`) — a failed step that the heuristic does not mark as needing replan is recorded as `failed` but execution continues linearly, potentially cascading.
* **Inconsistent fallback semantics**: `PlannerObserver.observe()` LLM exception defaults to `success=True` (`lib/crewai/src/crewai/agents/planner_observer.py:208-213`), while unparseable response defaults to `success=False, valid=False` (`lib/crewai/src/crewai/agents/planner_observer.py:348-352`). Timeout/error vs garbled response are treated oppositely.
* **Lost plan history on reset**: `invoke()` clears `plan`, `todos`, `observations`, `execution_log`, `replan_count` (`lib/crewai/src/crewai/experimental/agent_executor.py:2879-2883`) — a human-in-loop `invoke→feedback→invoke` loop loses prior plan lineage (mitigated only by `_prepare_feedback_iteration` resetting same fields, `lib/crewai/src/crewai/experimental/agent_executor.py:3294-3308`).
* **Replan context growth**: `_build_replan_context` concatenates all `completed` and `failed` `result` strings verbatim (`lib/crewai/src/crewai/experimental/agent_executor.py:2713-2754`) into `_enhance_task_for_replan` (`lib/crewai/src/crewai/experimental/agent_executor.py:2756-2773`) then re-injects via `replan_enhancement_prompt` (`lib/crewai/src/crewai/translations/en.json:100`). Long-running plans can blow up prompt length; no truncation or summarization guard exists.
* **Dependency deadlock without escape**: `get_ready_todos_method` detects “pending but none ready” and emits a canned `last_replan_reason` string (`lib/crewai/src/crewai/experimental/agent_executor.py:1128-1132`). If the replan itself regenerates the same dependency cycle, the loop can waste up to `max_replans` iterations before finalizing.
* **Refinement limited to description**: `apply_refinements` only rewrites `TodoItem.description` (`lib/crewai/src/crewai/agents/planner_observer.py:235-240`). If the LLM decides a step needs a different tool or dependency, the structured diff cannot express it — the only escape is a full replan.
* **No plan-drift metric**: there is no `plan_version`, `diff`, or drift percentage; the closest is `remaining_plan_still_valid:bool` which is binary and LLM-subjective, so incremental divergence (e.g., three small description tweaks) is not distinguishable from no drift.
* **Thread-pool non-cancellability on abort**: `execute_todos_parallel` catches `ToolExecutionFailedError` and calls `pool.shutdown(cancel_futures=True)` but notes “ones already in flight cannot be interrupted — Python threads are not cancellable” (`lib/crewai/src/crewai/experimental/agent_executor.py:1808-1814`).
* **Step-level timeout silent**: `step_timeout` returns the accumulated string rather than marking `failed` (`lib/crewai/src/crewai/agents/step_executor.py:348-351,558-565`), so a timed-out step can appear `success=True` to the observer.
