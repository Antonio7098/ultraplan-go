## Summary

Letta has an explicit, persisted tool catalog and a separate per-agent attachment set. The catalog distinguishes core, memory, multi-agent, built-in, file, MCP, and custom tools, while agents receive selected tool IDs/names plus type-specific defaults. Runtime tool rules compute an allowlist from the attached tools and current tool-call history, and the agent sends only the resulting JSON schemas to the model. Request-scoped client tools are merged into that list and override server tools with the same name.

Task-oriented semantic discovery exists as an optional Turbopuffer-backed API, with vector, full-text, and hybrid modes and type/tag filters. No evidence found that semantic search is automatically invoked by the agent loop to choose a smaller runtime tool set; it is exposed as a separate search operation. Availability is partially observable through traced request payloads and tool-execution spans, but there is no clear external record of every omitted tool or the exact rule that excluded it.

## Rating

**7/10 — Clear and tested model, with explicit interfaces and operational safeguards, but incomplete runtime discovery and explainability.** Per-agent catalog membership, organization scoping, base-tool policy, dynamic allowlists, approval rules, client-tool precedence, and failure behavior are implemented and tested. The score is held below 8 because retrieval is optional and disconnected from runtime selection, project checks are not consistently visible in attachment/resolution paths, and traces expose execution/request data more clearly than tool-availability decisions or exclusion reasons.

## Answers to Dimension Questions

1. **Does every agent see every tool? — No.** The agent state has its own attached `tools` collection, and creation resolves only requested names/IDs plus selected defaults (`studies/agent-harness-study/sources/letta/letta/schemas/agent.py:112`, `studies/agent-harness-study/sources/letta/letta/services/agent_manager.py:389-427`). The model receives the current allowlist rather than the whole organization catalog (`studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:2038-2065`).

2. **Are tools filtered by task? — Partly.** Tool rules filter by execution state, previous tool, tool output, and count, so the next-turn set can be task/workflow-specific (`studies/agent-harness-study/sources/letta/letta/schemas/tool_rule.py:111-161`, `studies/agent-harness-study/sources/letta/letta/schemas/tool_rule.py:198-223`, `studies/agent-harness-study/sources/letta/letta/helpers/tool_rule_solver.py:104-125`). Semantic query search can rank tools by text relevance, but no evidence found that the agent loop calls that search before constructing its runtime tool list; the runtime path reads `agent_state.tools` directly (`studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:2038-2045`, `studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1388-1428`).

## Architectural Decisions

- **Persist the catalog separately from agent membership.** Tool records are organization/project-scoped catalog objects, and `tools_agents` is the explicit attachment boundary (`studies/agent-harness-study/sources/letta/letta/orm/tool.py:17-59`, `studies/agent-harness-study/sources/letta/letta/orm/tools_agents.py:7-18`).
- **Use typed tool families and generated schemas.** Base tools are loaded from known function-set modules and assigned a `ToolType`; built-in tool schemas are regenerated from their source modules (`studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1147-1193`, `studies/agent-harness-study/sources/letta/letta/schemas/tool.py:74-105`).
- **Separate availability from approval.** Rules such as child/parent/conditional rules control which tools are valid, while `RequiresApprovalToolRule` preserves availability but routes execution through human approval (`studies/agent-harness-study/sources/letta/letta/helpers/tool_rule_solver.py:113-125`, `studies/agent-harness-study/sources/letta/letta/schemas/tool_rule.py:348-357`).
- **Apply routing at the schema boundary.** The loops filter attached tools before building the provider request, rather than relying only on prompt instructions (`studies/agent-harness-study/sources/letta/letta/agents/letta_agent.py:1693-1709`, `studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:2050-2073`).
- **Keep semantic search optional.** Tool embedding is disabled by default, and search fails explicitly unless Turbopuffer/tool embeddings are enabled (`studies/agent-harness-study/sources/letta/letta/settings.py:441-446`, `studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1414-1417`).

## Notable Patterns

- **Default sets vary by agent type.** Voice, sleeptime, v2, v1, React, and workflow agents receive different base-tool behavior; v1 removes `send_message` and defaults to no base rules unless configured (`studies/agent-harness-study/sources/letta/letta/services/agent_manager.py:389-425`).
- **Rules form a state machine.** Initial rules select the first call, child/parent rules constrain transitions, conditional rules use the previous function response, and terminal/continue/required-before-exit rules control loop progression (`studies/agent-harness-study/sources/letta/letta/helpers/tool_rule_solver.py:104-125`, `studies/agent-harness-study/sources/letta/letta/agents/letta_agent.py:1888-1919`).
- **Client tools are request-scoped overrides.** The same tool name can resolve to a client-provided schema for one request while the server tool remains attached and executes directly when client tools are omitted (`studies/agent-harness-study/sources/letta/tests/integration_test_client_side_tools.py:242-318`).
- **Discovery indexes descriptive capability data.** Embeddings include tool name, descriptions, schema parameter descriptions/types, and tags, and results include vector/FTS/hybrid ranking metadata (`studies/agent-harness-study/sources/letta/letta/helpers/tpuf_client.py:352-396`, `studies/agent-harness-study/sources/letta/letta/helpers/tpuf_client.py:2076-2129`).
- **Operational indexing is asynchronous.** Tool upsert/update/delete schedules or performs embedding maintenance outside the main catalog operation, with errors logged (`studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:361-370`, `studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1071-1084`, `studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1120-1130`).

## Tradeoffs

- **Small model-facing set versus discoverability:** Per-agent attachment and rule filtering reduce the list sent to the model, but a large manually attached set remains available when no restrictive rule is active; semantic discovery does not automatically shrink it (`studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:2040-2045`, `studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1388-1428`).
- **Strong execution controls versus model compatibility:** Base tool rules can disable parallel tool calls, and model keyword exclusions can turn base rules off; this avoids unsupported provider behavior but makes policy behavior model-dependent (`studies/agent-harness-study/sources/letta/letta/services/agent_manager.py:466-491`, `studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:1111-1139`).
- **Organization isolation versus project precision:** Catalog listing includes project/global filtering, while the shown agent resolver and attachment check organization ownership; this simplifies cross-project global tools but leaves unclear whether project-local tools can be attached through direct IDs (`studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:699-703`, `studies/agent-harness-study/sources/letta/letta/services/agent_manager.py:195-226`).
- **Search quality versus consistency:** Rich embeddings improve semantic matching, but background indexing can fail or lag after catalog updates, and deleted tools are skipped when search results are rehydrated (`studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1362-1384`, `studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1433-1441`).
- **Observability versus sensitive payload handling:** Request data is prioritized for tracing while large state, messages, tool returns, and source code are excluded or bounded, which protects trace size but limits full reconstruction of the selection context (`studies/agent-harness-study/sources/letta/letta/otel/tracing.py:252-289`, `studies/agent-harness-study/sources/letta/letta/tests/test_otel_tracing.py:155-188`).

## Failure Modes / Edge Cases

- **Empty restrictive allowlists can fall back to all attached tools.** The solver can return an empty set when rules produce no valid tools (`studies/agent-harness-study/sources/letta/letta/helpers/tool_rule_solver.py:118-125`), but both the v1 and v3 model-facing paths use `... or list(set(t.name for t in tools))`, which converts an empty result into all attached tools (`studies/agent-harness-study/sources/letta/letta/agents/letta_agent.py:1680-1685`, `studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:2041-2045`). This is especially relevant for strict conditional rules that intentionally return no valid tools (`studies/agent-harness-study/sources/letta/letta/schemas/tool_rule.py:203-223`).
- **Rule references can name unavailable tools.** Rule evaluation intersects rule output with the attached set, but configuration validation shown here does not prove that every rule target exists or is attached (`studies/agent-harness-study/sources/letta/letta/helpers/tool_rule_solver.py:113-125`, `studies/agent-harness-study/sources/letta/letta/schemas/tool_rule.py:13-33`).
- **Provider violations are possible even after schema filtering.** The runtime validates returned tool names and emits an error result, so a provider that ignores the advertised schema does not directly execute an unallowlisted tool (`studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:1770-1781`).
- **Approval state can pause mixed tool calls.** Client tools and approval rules are split from directly executable calls, returning a `requires_approval` stop reason and requiring a later approval/tool-return request (`studies/agent-harness-study/sources/letta/letta/agents/letta_agent_v3.py:1686-1709`, `studies/agent-harness-study/sources/letta/tests/integration_test_client_side_tools.py:92-145`).
- **Search index inconsistency is tolerated rather than surfaced as a hard error.** A search hit whose database tool no longer exists is silently omitted while preserving other result ordering (`studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:1433-1448`).
- **Malformed catalog records are deleted during listing.** Tool listing attempts Pydantic conversion and queues malformed records for deletion, making catalog reads self-healing but potentially destructive (`studies/agent-harness-study/sources/letta/letta/services/tool_manager.py:780-797`).
