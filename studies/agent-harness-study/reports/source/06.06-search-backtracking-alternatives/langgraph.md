## Summary

LangGraph is a deterministic BSP graph engine (Pregel) with explicit channel-based state. It does **not implement algorithmic search** (no branch-and-bound, scoring, or beam) but provides the **substrate for building search/backtracking externally**: deterministic conditional branching (`BranchSpec`, `Command.goto`, `Send`), isolated parallel fan-out via `Send`/`Topic`, durable checkpoint history with explicit time-travel/fork clones (`get_state_history`, `update_state`/`bulk_update_state`, `__copy__` fork), and automatic retention of failed branches (`ERROR` pending_writes) via retry and optional per-node error handlers. Alternatives are compared only by user code; cost is bounded by `recursion_limit`, `RetryPolicy.max_attempts`, and `TimeoutPolicy` (run/idle). The model is clear, tested, and observable, but higher-level search abstractions are left to the application.

## Rating

**7 / 10** — Clear model with explicit interfaces, durable history, and operational safeguards; branching/forking/backtracking are well-defined and tested, but ranked search over alternatives and extensible scoring are absent by design.

Rationale: static branching (`libs/langgraph/langgraph/graph/_branch.py:83`), dynamic fan-out (`Send` at `libs/langgraph/langgraph/types.py:704`, `TASKS` Topic at `libs/langgraph/langgraph/pregel/main.py:809`), time-travel fork (`libs/langgraph/langgraph/pregel/_loop.py:952`, `libs/langgraph/langgraph/pregel/main.py:1800`), failure retention (`ERROR` in `libs/langgraph/langgraph/pregel/_algo.py:765`, `libs/langgraph/langgraph/pregel/_loop.py:745`), and bounded execution (`recursion_limit` at `libs/langgraph/langgraph/pregel/main.py:2563`, `RetryPolicy` at `libs/langgraph/langgraph/types.py:418`, `TimeoutPolicy` at `libs/langgraph/langgraph/types.py:452`) are present and exercised by `test_run_from_checkpoint_id_retains_previous_writes` and `test_invoke_checkpoint_three`. Scoring/ranking of alternatives is not provided; the engine treats all triggers as equally valid successors.

## Answers to Dimension Questions

### 1. Can the system try alternatives?
**Yes, via three mechanisms but not as ranked search.** (a) Static conditional edges: `StateGraph.add_conditional_edges` backed by `BranchSpec` (`libs/langgraph/langgraph/graph/_branch.py:122-225`) mapping a node's output to one or more named successors; a list return yields parallel alternatives. (b) Dynamic fan-out: returning `list[Send(node, arg)]` from a node creates one PUSH task per Send executed next superstep (`libs/langgraph/langgraph/pregel/_algo.py:442-467`, `libs/langgraph/langgraph/types.py:704`). (c) Explicit navigation: `Command(goto=...)` and `Command(goto=Send(...))` let any node redirect to arbitrary successors or inject custom args (`libs/langgraph/langgraph/types.py:824`). Tests like `test_cond_edge_after_send` (`libs/langgraph/tests/test_pregel.py:1147-1171`) and `test_concurrent_emit_sends` (`libs/langgraph/tests/test_pregel.py:1173-1217`) verify multiple successors in one step. No built-in scoring or backtracking search algorithm selects among them; selection is deterministic by trigger availability (channel versions).

### 2. Are alternatives isolated?
**Yes.** Each alternative runs as an isolated `PregelExecutableTask` with its own `id` (xxhash/uuid5 of `checkpoint_id + checkpoint_ns + step + name + PUSH + idx` at `libs/langgraph/langgraph/pregel/_algo.py:989-996`), own `path` (e.g., `(PUSH, idx)` vs `(PULL, name)`), own `writes: deque[tuple[str,Any]]`, own `scratchpad` and `Runtime`/`ExecutionInfo`. `prepare_single_task` builds a fresh `config` per task with `CONFIG_KEY_TASK_ID`, `CONFIG_KEY_SEND`, `CONFIG_KEY_READ`, `CONFIG_KEY_CHECKPOINT_NS` (`libs/langgraph/langgraph/pregel/_algo.py:706-756`, `libs/langgraph/langgraph/pregel/_algo.py:1056-1105`). For `Send`-based fan-out, isolation is per `idx` in `TASKS` Topic, so one failed Send does not corrupt another's args. Cross-task visibility is deferred to next superstep via `apply_writes` (`libs/langgraph/langgraph/pregel/_algo.py:232-345`), enforcing BSP bulk-sync isolation.

### 3. How are alternatives compared?
**They are not compared/ranked by the engine.** There is no scoring function, priority queue, or utility comparator. Triggering is binary: `_triggers` checks whether any subscribed channel's version exceeds `versions_seen` (`libs/langgraph/langgraph/pregel/_algo.py:1260-1277`), and `prepare_next_tasks` optionally optimizes via `updated_channels ∩ trigger_to_nodes` to enumerate candidate nodes (`libs/langgraph/langgraph/pregel/_algo.py:475-512`) then iterates them in `sorted(triggered_nodes)` for determinism. Ordering where relevant (e.g., `TASKS` sends) follows insertion index; `tasks` dict sorting uses `task_path_str` (`libs/langgraph/langgraph/pregel/_algo.py:256`) for deterministic apply order, not cost. Ranking must be implemented in user code (e.g., node that scores branches and emits highest-scoring `Send` or `Command.update`).

### 4. Is backtracking explicit?
**Yes, via persistent checkpoints, not in-graph search backtrack.** LangGraph exposes: `get_state_history(config)` yielding `StateSnapshot` with `values, next, config, parent_config, tasks, interrupts` (`libs/langgraph/langgraph/pregel/main.py:1480-1531`); `get_state(config+checkpoint_id)` to load any historic checkpoint (`libs/langgraph/langgraph/pregel/main.py:1392-1434`); `update_state`/`bulk_update_state`/`aupdate_state` to rewrite history as if a node produced different output (`libs/langgraph/langgraph/pregel/main.py:2515-2541`, `libs/langgraph/langgraph/pregel/main.py:1590-2054`); and time-travel re-invocation `graph.invoke(None, {checkpoint_id:...})` which detects `is_time_traveling` and creates a fork checkpoint `source=fork` to isolate the new branch (`libs/langgraph/langgraph/pregel/_loop.py:952-972`), proven by `test_run_from_checkpoint_id_retains_previous_writes` (`libs/langgraph/tests/test_pregel.py:592-669`) asserting history length +2 and `metadata["source"]=="fork"`. `_first` also clears stale `INTERRUPT` writes on fork to avoid confusion (`libs/langgraph/langgraph/pregel/_loop.py:968-970`). For intra-run retry/backoff, `run_with_retry`/`arun_with_retry` explicitly clears `task.writes` and sleeps with exponential backoff before retry (`libs/langgraph/langgraph/pregel/_retry.py:615-683`). `Command`+`interrupt` provides human-in-loop pause/resume but not automatic backtrack.

### 5. Are costs bounded?
**Yes, at three layers.** (1) Step bound: `recursion_limit` (default 25, validated `>=1` at `libs/langgraph/langgraph/pregel/main.py:2563`) defines `stop = step + recursion_limit +1` (`libs/langgraph/langgraph/pregel/_loop.py:1701`); `tick()` returns `status="out_of_steps"` when `step > stop` (`libs/langgraph/langgraph/pregel/_loop.py:606-609`) and `stream` raises `GraphRecursionError` (`libs/langgraph/langgraph/pregel/main.py:3005-3012`). (2) Per-node retry bound: `RetryPolicy.max_attempts` (default 3) caps attempts, with bounded interval `min(max_interval, initial_interval * backoff_factor**(attempts-1)) + jitter` (`libs/langgraph/langgraph/pregel/_retry.py:664-674`, `libs/langgraph/langgraph/pregel/_retry.py:819-829`). (3) Per-attempt timeout: `TimeoutPolicy.{run_timeout,idle_timeout}` with `refresh_on: auto|heartbeat`, enforced by watchdogs `_run_timeout_watchdog` / `scope.wait_for_idle_timeout` and `_TimedAttemptScope` guarding writes/stream after timeout (`libs/langgraph/langgraph/pregel/_retry.py:417-518`). No global token/cost or branch-count limiter exists; fan-out cost scales with number of `Send`s and recursion_limit.

## Architectural Decisions

- **BSP graph, not search tree:** The engine is a Bulk Synchronous Parallel executor (`plan -> execution -> update` in `libs/langgraph/langgraph/pregel/main.py:464-476` and `libs/langgraph/langgraph/pregel/_loop.py:599-682`). This yields deterministic, observable supersteps but delegates any search strategy to user nodes.
- **Channels as sole state:** All communication via typed channels (`LastValue`, `Topic`, `BinaryOperatorAggregate`, `DeltaChannel`, etc. in `libs/langgraph/langgraph/channels/*.py`). This makes branching decisions pure functions of channel versions (`libs/langgraph/langgraph/pregel/_algo.py:1260`), enabling time-travel replay (`libs/langgraph/langgraph/pregel/_checkpoint.py:229-276`).
- **Reserved `TASKS` Topic for dynamic control flow:** Hard-wired `TASKS = Topic(Send, accumulate=False)` (`libs/langgraph/langgraph/pregel/main.py:809`) separates dynamic orchestration from user state; `Command` and `Send` writes target it, preparing PUSH tasks next step. Keeps graph static while allowing data-dependent parallelism.
- **Fork-on-read via checkpoint_id:** Invoking with a historic `checkpoint_id` does not mutate history in place; `_first` synthesizes a `fork` checkpoint with fresh `checkpoint_id` and clears stale interrupts (`libs/langgraph/langgraph/pregel/_loop.py:952-971`). Combined with `bulk_update_state`'s `StateUpdate(as_node, task_id)` and `__copy__` fork (`libs/langgraph/langgraph/pregel/main.py:1800-1878`), this provides git-like branching without explicit branch API.
- **Durable pending writes before progress:** Failed branches write `ERROR`/`ERROR_SOURCE_NODE` to `pending_writes` and are awaited via `_delta_write_futs` / `_error_handler_write_futs` before advancing the checkpoint (`libs/langgraph/langgraph/pregel/_loop.py:495-505`, `libs/langgraph/langgraph/pregel/_loop.py:1538-1547`). This preserves failure evidence across restarts (tested in `libs/langgraph/tests/test_pregel.py:1050-1104`).
- **Separate retry and error-handler paths:** `RetryPolicy` is per-node/task (`libs/langgraph/langgraph/types.py:418`) and re-executes the same task in place with resume flag (`libs/langgraph/langgraph/pregel/_retry.py:682`). Node-level error handlers (`prepare_node_error_handler_task` at `libs/langgraph/langgraph/pregel/_algo.py:1110`) are a distinct fallback that creates a new PUSH handler task after durability, enabling alternative recovery plans.

## Notable Patterns

- **Static + dynamic branching duality:** `BranchSpec.from_path` infers `Literal` return types into `path_map` (`libs/langgraph/langgraph/graph/_branch.py:88-120`) for type-safe static edges, while `Send`/`Command` enable runtime-computed successors — e.g., map-reduce `continue_to_jokes(state) -> [Send("generate_joke", {"subject": s}) ...]` (`libs/langgraph/langgraph/types.py:737-745`).
- **Deterministic task IDs for replay:** IDs are derived from `checkpoint_id_bytes + checkpoint_ns + step + name + trigger` via `_xxhash_str`/`_uuid5_str` (`libs/langgraph/langgraph/pregel/_algo.py:550-551`, `libs/langgraph/langgraph/pregel/_algo.py:616-624`), making time-travel replays stable and allowing `update_state` to reuse `prepare_next_tasks` IDs via `node_to_task_ids` (`libs/langgraph/langgraph/pregel/main.py:1882-1903`).
- **Human-in-loop interrupt as suspendable branch:** `interrupt(value)` raises `GraphInterrupt([Interrupt.from_ns(value, ns)])` (`libs/langgraph/langgraph/types.py:967-974`), persisted as `INTERRUPT` writes and resumed via `Command(resume=...)` or `update_state`; `get_state` surfaces pending `Interrupt` tuples (`libs/langgraph/langgraph/types.py:701`). Multi-interrupt resumption differentiates by id (`libs/langgraph/langgraph/pregel/_loop.py:916-920`).
- **Exit-mode delta accumulator:** When `durability="exit"`, intermediate checkpoints are skipped but delta writes are accumulated in `_exit_delta_writes` with step-prefixed synthetic task_ids (`libs/langgraph/langgraph/pregel/_checkpoint.py:39`, `libs/langgraph/langgraph/pregel/_loop.py:1283-1316`) to preserve order without per-step durability cost.

## Tradeoffs

- **Generality vs out-of-box search:** By not shipping a scorer/beam, LangGraph avoids opinionated search semantics and keeps the runtime small and predictable, but every planning agent must reinvent evaluation, pruning, and best-first selection — increasing integration burden and risk of inconsistent implementations.
- **Full history durability vs storage/throughput:** Retaining every checkpoint and `pending_writes` (plus delta-channel ancestor walks in `libs/langgraph/langgraph/pregel/_checkpoint.py:260-276`) gives powerful backtracking and auditability, but grows storage unboundedly; no built-in GC or branch-pruning policy, only `recursion_limit` bounds execution.
- **BSP determinism vs latency:** Bulk-sync `apply_writes` isolation prevents race conditions and makes backtracking sound, but forces all parallel Sends to synchronize per superstep, adding latency versus streaming DAG execution.
- **Fork-on-read copy semantics `__copy__`:** Copying a checkpoint with `values= [StateUpdate,...]` via `bulk_update_state` (`libs/langgraph/langgraph/pregel/main.py:1800`) reuses `prepare_next_tasks` IDs to preserve `task.result` lineage, which is powerful but subtle; misuse can create orphaned `parents` maps or ambiguous `as_node` errors (`InvalidUpdateError: Ambiguous update` at `libs/langgraph/langgraph/pregel/main.py:1934`).

## Failure Modes / Edge Cases

- **No built-in ranking leads to silent nondeterminism if user neglects tie-break:** When a conditional edge returns multiple destinations, order follows `sorted(triggered_nodes)` and Send index, not cost; without user scoring, a "best" alternative is undefined and may appear stochastic to end users.
- **Unbounded fan-out:** A node returning `n` Sends spawns `n` PUSH tasks; there is no `max_branching` guard. Combined with cycles, this can explode task count until `GraphRecursionError` or OOM. `TASKS` channel size is not bounded in protocol (`libs/langgraph/langgraph/pregel/protocol.py` no cap).
- **Checkpoint-less backtracking impossible:** All time-travel requires a `BaseCheckpointSaver` (`ValueError: No checkpointer set` at `libs/langgraph/langgraph/pregel/main.py:1401`, `libs/langgraph/langgraph/pregel/main.py:1616`). Graphs compiled without checkpointer silently lose the ability to fork or retry across restarts.
- **Stale error/interrupt accumulation without fork cleanup:** Prior to `is_time_traveling` fix, replaying an interrupted checkpoint without `source==fork` would accumulate old `INTERRUPT` writes and confuse multi-interrupt resume (`libs/langgraph/langgraph/pregel/_loop.py:964-970` explicitly clears them). If forks are created manually without this path, interrupts leak.
- **Update ambiguity:** Calling `update_state` without `as_node` when multiple nodes last updated state raises `InvalidUpdateError: Ambiguous update` (`libs/langgraph/langgraph/pregel/main.py:1934`); single-node assumption (`len(nodes)==1`) hides the requirement until graph grows.
- **Retry masking with `durability="exit"`:** With exit durability, `pending_writes` for successful siblings before a failed peer may not be durable until exit (`libs/langgraph/tests/test_pregel.py:1104-1109` notes writes not saved), so resume after crash can replay already-successful branches.

## Future Considerations

- Add an optional **branch scorer interface** (`Callable[[Sequence[PregelTask]], ranked[TaskId]]` or `ScorePolicy`) that integrates with `prepare_next_tasks` trigger-set optimization, allowing best-first or beam search without user reimplementing filter logic; store scores in `CheckpointMetadata` for ranking in `get_state_history`.
- Expose **branch pruning/GC helpers** (e.g., `prune_checkpoints(before, keep=latest N forks)`) and a `max_forks` per thread to bound storage while preserving time-travel ergonomics; current `checkpointer.list` has `limit` but no retention policy.
- Introduce **fan-out budget** (`max_concurrent_sends`, per-superstep `max_tasks`) enforced in `prepare_next_tasks` with early `GraphRecursionError` variant to fail fast on combinatorial explosion.
- Consider **parallel search isolation via thread fork** primitive that wraps the existing `__copy__` fork + `invoke` with checkpoint_id in a single `fork(thread_id)` API, reducing boilerplate for alternative plan coexistence and making alternative branches queryable via namespaced `checkpoint_ns`.

## Questions / Gaps

- No evidence of framework-level A*/MCTS or learned ranking; scoring is delegation-only — confirmed by empty grep for `score|rank|best` in engine (`libs/langgraph/langgraph/stream/run_stream.py:285` relates to stream timestamp, not search).
- Whether multiple `invoke`s with distinct `thread_id`s are intended as the primary "alternative plans coexistence" mechanism vs. in-thread forks: docs promote thread forks, but engine supports both; no explicit "branch set" abstraction found.
- Cost controls do not include LLM token/price budgets — timeouts bound wall-clock only; any token-cost search budget would need to be built atop `RetryPolicy.retry_on` predicate or custom `CachePolicy`/`ManagedValue`.
- `CachePolicy` (`libs/langgraph/langgraph/types.py:520-530`) and `TimeoutPolicy.refresh_on="auto"` interaction for long-running scored branches not documented as a backtracking aid; unclear if cache hits should influence branch ranking.
