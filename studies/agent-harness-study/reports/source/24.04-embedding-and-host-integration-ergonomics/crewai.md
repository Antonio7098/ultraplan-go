## Summary

CrewAI embeds primarily as a **Python library**: hosts construct plain objects (`Agent`, `Task`, `Crew`, `Flow`) and invoke `Crew.kickoff(...)` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/crew.py:992`) or `Flow` runtime kickoff (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/runtime/__init__.py:2026`). Two further modes are supported out of the box: a **CLI subprocess** (`crewai = "crewai_cli.cli:crewai"` console script, `studies/agent-harness-study/sources/crewai/lib/cli/pyproject.toml:34-35`) and a **server-style integration** via A2A, where agent methods are wrapped with server/client delegation methods and A2A config types are part of the top-level export surface (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/a2a/wrapper.py:237`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:102-117`). A hosted-platform client (`PlusAPI`) is also exposed as a stable import path (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/plus_api.py:1-11`).

Host-supplied dependencies are unusually broad for this framework category: custom LLM backends subclass `BaseLLM` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/llms/base_llm.py:150`, abstract `call` at `:315`); tools extend `BaseTool` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/tools/base_tool.py:103`); memory backends implement the `StorageBackend` protocol and can be injected through a registered factory (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/memory/storage/backend.py:45`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/memory/storage/factory.py:33,48-51`); flow persistence is pluggable behind the `FlowPersistence` ABC with a factory setter (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/persistence/base.py:18`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/persistence/factory.py:31`); human input and feedback are delegated to a host-implemented `InputProvider` protocol (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/input_provider.py:93,130-135`).

Observability to the host flows through three channels: (1) typed events on a process-wide singleton bus with sync/async handlers (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:95-143,245-280`), including ordered stream-chunk events for token streaming (`event_bus.py:628-637`) and context-local stream sinks (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/stream_context.py:17-27`); (2) a streaming result object returned when `Crew.stream` is enabled (`crew.py:1014-1038`); and (3) coarse-grained callbacks (`step_callback`/`task_callback`, `crew.py:296,300`).

The main ergonomic costs are process-wide effects: importing `crewai` monkeypatches `warnings.warn` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:28-49`) and rewrites several modules' namespaces in `sys.modules` (`__init__.py:133-145`); the event bus spawns a background daemon event-loop thread plus a 10-worker thread pool on first emit (`event_bus.py:166-191`) and registers an `atexit` shutdown (`event_bus.py:952-954`); and settings silently fall back to writing config files into the temp directory or current working directory when `$HOME/.config` is unwritable (`studies/agent-harness-study/sources/crewai/lib/crewai-core/src/crewai_core/settings.py:76-107`). There is no first-class cancellation API: `KeyboardInterrupt` is handled only inside interactive chat/flow helpers (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/crew_chat.py:205`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/runtime/__init__.py:3475`).

Overall: a clear, well-typed embedding model with strong dependency-injection surfaces, weakened by implicit global state (singletons, atexit hooks, import-time patching) and by observer errors being printed instead of propagated to the host.

Rationale against the rubric:

- Present and clear: library entry points are explicitly exported (`__all__` in `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:187-205`); host-replaceable dependencies cover LLM, tools, memory storage, persistence, and input providers (evidence above); telemetry can be disabled via documented environment variables (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/telemetry/telemetry.py:161-166`).

## Answers to Dimension Questions

**1. Can the harness run inside another application without owning the whole process?**
Largely yes, with caveats. Embedding is a normal library import: hosts instantiate `Crew`/`Flow` and call `kickoff` synchronously or asynchronously (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/crew.py:992,1127`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/runtime/__init__.py:2026,2091`). Per-run state is scoped through contextvars rather than module globals (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:84-92`), which permits multiple logical runs in one process. However, importing `crewai` mutates global warning filters (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:28-49`), rewrites `sys.modules` entries for core modules (`__init__.py:133-145`), and first event emission starts a daemon event-loop thread plus a fixed-size thread pool inside the host process (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:166-191`). These are process-wide effects a host cannot scope or opt out of.

**2. Can the host supply policy, tools, identity, storage, telemetry, and secrets?**
Tools: yes, via `BaseTool` subclasses (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/tools/base_tool.py:103`). Policy: yes, through before/after LLM and tool-call hooks whose reducers can veto or rewrite calls (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/hooks/tool_hooks.py:142-153`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/hooks/llm_hooks.py:169-180`), though hook registries are global with only a context-manager escape hatch (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/hooks/dispatch.py:149`). Storage: yes for memory backends (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/memory/storage/backend.py:45`; `.../factory.py:33`) and flow persistence (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/persistence/base.py:18`). Telemetry: cannot be replaced by a host sink implementation in-process, only disabled via env vars (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/telemetry/telemetry.py:161-166`); general event subscription is the substitute (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:245-280`). Identity/secrets: partially — enterprise identity is configured through a persisted `Settings` model with OAuth2 fields (`studies/agent-harness-study/sources/crewai/lib/crewai-core/src/crewai_core/settings.py:168-192`) rather than an injected credential-provider interface, and LLM keys follow provider-standard env conventions inside each completion class.

**3. Are lifecycle, cancellation, shutdown, and error propagation explicit?**
Partially. Lifecycle has explicit primitives: `flush(timeout)` drains observer futures (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:734-769`) and `shutdown(wait)` tears down threads and registries (`event_bus.py:897-949`), and kickoff uses try/finally to detach tracing baggage, end execution tracking, exit runtime scope, and drain memory writes even on failure (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/crew.py:1079-1086`). But the default wiring is implicit: `atexit.register(crewai_event_bus.shutdown)` (`event_bus.py:954`) means most hosts never call shutdown themselves. Execution failures propagate correctly (kickoff emits `CrewKickoffFailedEvent` and re-raises, `crew.py:1068-1078`), yet observer/handler failures are deliberately contained and merely printed (`event_bus.py:401-427,445-456`) — the host learns nothing about broken listeners unless it watches stderr/console. Cancellation is the weakest area: there is no documented cancel handle or timeout plumbing at the harness level; interruption appears only as `KeyboardInterrupt` handling inside interactive loops (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/crew_chat.py:205`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/runtime/__init__.py:3475`).

**4. Does the integration model work for both local-first and service deployments?**
Yes, structurally. Local-first: everything works in-process with SQLite/LanceDB defaults and console input providers (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/persistence/sqlite.py:24`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/input_provider.py:99-100`). Service deployments: A2A wrapping exposes agents as networked services with client/server configs exported publicly (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/a2a/wrapper.py:237`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:109-115`); pluggable persistence and storage factories let services back state with their own databases; `CREWAI_STORAGE_DIR` relocates local artifacts (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/memory/storage/lancedb_storage.py:56-68`). Residual friction for services: settings fall back to writing JSON files into the temp dir or CWD when `$HOME/.config` is unavailable (`studies/agent-harness-study/sources/crewai/lib/crewai-core/src/crewai_core/settings.py:76-107`), which is surprising in ephemeral containers, and the singleton event-bus thread pool (max 10 workers, hardcoded) is not tunable per host (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:179-182`).

## Architectural Decisions

1. **Facade-first public API with lazy heavy imports.** The package exports a curated `__all__` and resolves `Memory` lazily through PEP 562 `__getattr__` so lightweight embeddings do not pay for vector-store imports until used (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:53-66,187-205`).
2. **Singleton event bus as the universal observability spine.** One process-wide bus carries kickoff/task/tool/LLM/stream events to both internal listeners (console formatter, tracing) and host subscribers (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:95-143`), with dependency-ordered handler plans and replay support for reconstruction (`event_bus.py:458-521,673-732`).
3. **Protocol/ABC-based dependency seams instead of constructor-injected containers.** Each capability (LLM, tool, memory storage, flow persistence, input provider) defines its own interface and a small factory/setter, avoiding a single heavyweight DI framework (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/persistence/factory.py:31`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/memory/storage/factory.py:33`).
4. **Contextvars for per-run state in shared processes.** Runtime state, replay flags, and stream sinks live in context variables so nested/concurrent kickoffs do not clobber each other (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:68-92`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/stream_context.py:17-27`).
5. **Monorepo split isolating CLI/platform concerns.** `crewai-core` holds settings/token/platform clients shared by framework and CLI, keeping the embeddable library decoupled from CLI-only machinery (`studies/agent-harness-study/sources/crewai/lib/crewai-core/src/crewai_core/settings.py:1-3`; re-export shim at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/settings.py:1-18`).
6. **Method-wrapping for cross-cutting A2A behavior.** Instead of subclassing, A2A support binds wrapper functions onto agent instances (`object.__setattr__(agent, "kickoff", MethodType(...))`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/a2a/wrapper.py:166-169,232-235`), making the server mode opt-in per agent.

## Notable Patterns

- **Ordered stream delivery:** stream chunks bypass the thread-pool dispatch path and execute inline to guarantee ordering, while all other sync handlers run concurrently (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:505-519,628-637`).
- **Scope-aware cleanup:** `Crew.kickoff` attaches tracing baggage, begins execution tracking, enters a runtime scope, and releases all four in `finally` regardless of outcome (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/crew.py:1040-1086`).
- **Temporary-handler sandboxing:** `scoped_handlers()` snapshots, removes, and restores handler registrations so tests and short-lived integrations leave no residue (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:831-895`).

## Tradeoffs

- **Global registries vs. multi-tenant isolation:** hooks, event handlers, and storage factories are process-global singletons (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/hooks/dispatch.py:98-135`; `event_bus.py:952`). This simplifies the common case but means two embedded subsystems in one process share policy unless each carefully uses scoped contexts (`dispatch.py:149`, `event_bus.py:831-895`).
- **Import-time convenience vs. host predictability:** suppressing pydantic warnings globally improves first-run UX but mutates host logging/warning behavior invisibly (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:28-49`).
- **Fire-and-forget async handlers vs. delivery guarantees:** async observers are scheduled on a private daemon loop; hosts must remember to `flush()` or rely on `atexit` to know whether events were delivered (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:734-769,954`).
- **Env-var configuration vs. explicit configuration objects:** telemetry opt-out and storage relocation depend on environment variables read at operation time (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/telemetry/telemetry.py:161-166`; `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/memory/storage/lancedb_storage.py:68`), which is convenient for CLIs but awkward for long-lived services that prefer programmatic control.
- **Rich callback/event surface vs. error visibility tradeoff:** containing observer failures keeps runs alive, but silent-print semantics make misconfigured integrations hard to detect programmatically (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:423-427`).

## Failure Modes / Edge Cases

- **Handler storms under load:** every emit acquires locks and submits to a bounded (10-thread) pool; a chatty host listener can saturate `CrewAISyncHandler` workers, delaying non-stream events since ordering across emissions is not guaranteed once queued (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:179-182,633-637`).
- **Unwritable-home environments:** `get_writable_config_path` falls back to `/tmp/crewai_settings.json` and then the process CWD, so credentials/org settings may land in world-readable locations or pollute container filesystems; failure to find any location downgrades to in-memory with no host-visible signal (`studies/agent-harness-study/sources/crewai/lib/crewai-core/src/crewai_core/settings.py:76-107,198-201`).
- **Silent settings corruption tolerance:** a malformed `settings.json` is swallowed into empty defaults, and `dump()` failures pass silently (`studies/agent-harness-study/sources/crewai/lib/crewai-core/src/crewai_core/settings.py:211-217,249-250`).
- **Shutdown races:** emitting during `shutdown` prints a warning and drops the event (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/event_bus.py:602-607`); a host calling `shutdown()` early will silently discard subsequent activity from still-running crews.
- **Unresolved forward refs degrade quietly:** if the import-time `model_rebuild()` choreography fails, the library logs a warning and sets `RuntimeState = None`, later skipping entity registration with a log line — embedding continues in a degraded observability mode (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/__init__.py:178-185`; `event_bus.py:356-363`).
- **No cooperative cancellation:** a runaway kickoff can only be interrupted by SIGINT reaching an interactive helper; otherwise the host must kill the thread/process, losing the flush/drain guarantees (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/flow/runtime/__init__.py:3475`; contrast `event_bus.py:897-949`).
- **Background egress on behalf of the host:** the tracing listener batches and ships events to a remote backend and defers finalization while nested executions occur; hosts unaware of this may observe unexpected outbound traffic after kickoff returns (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/events/listeners/tracing/trace_listener.py:140,156,781-799`).
