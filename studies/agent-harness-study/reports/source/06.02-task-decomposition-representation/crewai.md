## Summary

CrewAI decomposes tasks through **two disjoint mechanisms** that do not share a plan registry. The primary, structured mechanism is **Agent-level Plan-and-Execute** via `AgentExecutor` + `AgentReasoning` + `TodoList`: the LLM generates a `ReasoningPlan{plan, steps: list[PlanStep], ready}` via function-calling (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:30-104`), which is converted into `TodoItem`/`TodoList` subtasks (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:14-196`) and executed by isolated `StepExecutor`s orchestrated as a `Flow[AgentExecutorState]` graph (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:136-446`). The secondary mechanism is **Crew-level pre-planning** via `CrewPlanner` that emits `PlannerTaskPydanticOutput{list_of_plans_per_task: list[PlanPerTask]}` and mutates `task.description += plan` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:15-34`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:57-78`). A third, coarser layer is `Task.context: list[Task]` for crew-level DAG precedence. Subtasks are typed as `PlanStep`/`TodoItem` Pydantic models with explicit `depends_on: list[int]`, `tool_to_use`, and four-state `status`, executed with dependency-aware scheduling (`get_ready_todos`, `can_parallelize`), and evaluated/revised via `PlannerObserver` + `StepObservation` with effort-gated heuristic vs LLM observation and in-place refinement vs full replan.

## Answers to Dimension Questions

**1. How is a task decomposed?**
Two layers, only one is structured. **Agent-level:** `AgentReasoning._create_initial_plan` calls `llm.call(..., tools=[FUNCTION_SCHEMA])` to produce `ReasoningPlan{plan, steps: list[PlanStep], ready}` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:256-276`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:351-404`), optionally refined via `_refine_plan_if_needed` loop bounded by `PlanningConfig.max_attempts` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:278-349`). `AgentExecutor.generate_plan` stores `plan/plan_ready` and converts steps via `_create_todos_from_plan` into `TodoList` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:384-444`). **Crew-level:** `CrewPlanner._handle_crew_planning` creates a synthetic `Agent(role="Task Execution Planner")` and a `Task(output_pydantic=PlannerTaskPydanticOutput)` executed synchronously to produce `PlanPerTask` per crew task, then string-appends to `task.description` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:57-78`). A third coarser decomposition is `Task.context` which declares inter-task DAG edges at crew schedule time (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/task.py:167-170`). Decomposition is LLM-authored, not framework-authored, and gated by `Agent.planning_enabled` / `Crew.planning`.

**2. Are subtasks typed?**
Yes, at the agent layer, no at the crew layer. `PlanStep` and `TodoItem` are typed Pydantic models: `step_number: int`, `description: str`, `tool_to_use: str|None`, `depends_on: list[int]`, plus `TodoItem.status: TodoStatus` and `result` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:14-43`). `TodoList` groups them with typed accessors. There is no `kind`/`priority`/`cost` taxonomy beyond `tool_to_use`, and crew-level `PlanPerTask.plan` is an untyped `str` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:22-25`). Subtask routing to tools uses `tool_to_use` as a loose type proxy validated by `_validate_expected_tool_usage` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:515-538`).

**3. Can dependencies be represented?**
Yes at agent level, limited at crew level. Agent subtasks carry `depends_on: list[int]` on both `PlanStep` and `TodoItem` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:22-39`). Satisfaction is checked by `_dependencies_satisfied` requiring terminal states `completed|failed` to avoid deadlock when a dependency fails (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:112-145`), and `get_ready_todos` returns the ready set used by `AgentExecutor.get_ready_todos_method` to decide `single_todo_ready` vs `multiple_todos_ready` vs `needs_replan` on deadlock (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1105-1139`). Parallel execution preserves order via `asyncio.gather` + `zip(ready, gathered)` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1257-1321`). Crew-level dependencies use `Task.context: list[Task]` for sequential/hierarchical ordering (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/task.py:167-170`), but there is no `depends_on` between crew-level `PlanPerTask`s.

**4. Are statuses tracked?**
Yes, with a state machine persisted in `AgentExecutorState`. `TodoStatus` is `pending|running|completed|failed` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:11`). `TodoList` tracks `current_todo`, `is_complete` (all terminal), `pending/completed/running` counts, and transitions via `mark_running/completed/failed` which also store `result` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:50-183`). `AgentExecutor` emits `PlanStepStarted/PlanStepCompleted` on transitions and `PlanReplanTriggered/PlanRefinement/GoalAchievedEarly` on plan updates (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:446-523`). `StepResult{success, result, error, tool_calls_made, execution_time}` and `execution_log`/`observations` map provide step records (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/step_execution_context.py:44-64`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:164-172`). The answer to "which subtask is blocking?" is directly answerable via `get_ready_todos` (pending with unsatisfied deps) and `get_failed_todos`/`running_count`, though no explicit `blocked` status exists.

**5. Can decomposition be evaluated?**
Structurally and behaviorally, yes via the Observe-Decide pipeline, though not via a single coverage metric. Structural evaluation: `_dependencies_satisfied` considers a dependency satisfied if `completed|failed` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:112-131`), and `get_ready_todos_method` treats "pending but none ready" as `needs_replan` deadlock detection (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1124-1132`). Behavioral evaluation: `PlannerObserver.observe` is called after every step (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:680-745`), producing `StepObservation{step_completed_successfully, remaining_plan_still_valid, needs_full_replan, goal_already_achieved}` via LLM (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:113-214`) or `heuristic_observation` when `reasoning_effort="low"` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:88-111`). Decisions route through effort-gated handlers to `refine_and_continue` (in-place `StepRefinement` via `apply_refinements`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:215-242`) or `replan_now` via `replace_pending_todos` bounded by `max_replans` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:185-196`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1048-1089`). Evaluation prompts are explicit (`observation_system_prompt`, `create_plan_prompt` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/translations/en.json:81-88`). No plan-coverage score or "is decomposition complete/minimal?" metric exists beyond `is_complete` + `goal_already_achieved`.

## Architectural Decisions

| Decision | Why it was made (inferred) | Consequence for this dimension |
|----------|-----------------------------|--------------------------------|
| **Pydantic TodoList as authoritative plan holder inside Flow state** (`AgentExecutorState.todos: TodoList` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:155-157`) | Keep plan durable across Flow routers without external store; reuse Flow's state validation and serialization | Enables dependency-aware scheduling, parallel execution, and replan via `replace_pending_todos` without a separate planner service; but plan is memory-only and not checkpoint-persisted separately |
| **LLM function-calling for plan generation with text fallback** (`FUNCTION_SCHEMA` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:50-104`, text fallback at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:270-276`) | Support structured `PlanStep` on capable models while degrading gracefully on others | Structured `depends_on`/`tool_to_use` available when function calling works; otherwise `steps=[]` and no `TodoList` created, losing decomposition entirely with only a log warning |
| **Isolated StepExecutor per todo with dependency-only context** (`StepExecutionContext` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/step_execution_context.py:13-31`, `StepExecutor._build_isolated_messages` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:244-326`, `_build_context_for_todo` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:647-678`) | Prevent prompt bloat and cross-step contamination | Predictable per-step prompt, but step loses conversational history beyond `dependency_results`; off-dependency references require replanning |
| **Dependency satisfaction includes `failed` as terminal** (`_dependencies_satisfied` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:112-131`) | Prevent permanently blocked downstream todos when a dependency fails | Unblocks execution graph; observer (`needs_full_replan`/`step_completed_successfully`) becomes responsible for deciding skip vs replan vs refine |
| **Effort-graded observation (low/medium/high) with `observe_steps` override** (`PlanningConfig.reasoning_effort` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agent/planning_config.py:79-97`, `_should_observe_steps/_get_reasoning_effort` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:555-603`) | Single knob to trade latency/cost vs adaptivity | Explicit operational tradeoff but coarse granularity; fine control requires `observe_steps` override and reading executor source |
| **Dual planners disconnected** (`CrewPlanner` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:37-114` vs `AgentReasoning/AgentExecutor` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:107-244` and `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:173-446`) | Keep crew prompt-augmentation simple without per-step observation cost | Crew plan never becomes `TodoList` and agent plan ignores crew plan; no unified `plan_id` or registry |
| **In-place refinement vs full replan** (`StepObservation.suggested_refinements` + `PlannerObserver.apply_refinements` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:215-242`, `TodoList.replace_pending_todos` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:185-196`) | Cheap adaptation for new info without paying a second planning LLM call | Avoids regeneration cost; `max_replans` caps expensive full replans, but refinement is limited to description mutation |

## Notable Patterns

- **Flow-as-planner-executor**: `AgentExecutor extends Flow[AgentExecutorState]` with routers `generate_plan → check_todos_available → get_ready_todos_method → execute_todo_sequential/execute_todos_parallel → observe_step_result → handle_*/decide_next_action` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:174-191`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:384-1139`) — planning is a runtime graph, not prompt prose.
- **Typed plan chain**: `PlanStep → TodoItem → TodoList → StepExecutionContext/StepResult → StepObservation/StepRefinement` is fully Pydantic/dataclass validated with `field_validator` for single-refinement coercion (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:259-265`).
- **Minimal DAG scheduler without importing Flow**: `TodoList.get_ready_todos` + `can_parallelize` implements parallel ready-set detection (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:133-154`) used by `AgentExecutor` to branch to `execute_todos_parallel`.
- **Effort as policy cross-cut**: `reasoning_effort` controls observation (LLM vs heuristic), replan on failure, early goal detection, and refinement in one enum (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:680-968`).
- **Result-only dependency propagation**: Only `dependency_results: dict[int,str]` final strings are passed to `StepExecutor`, not traces or tool calls (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/step_execution_context.py:31`).

## Tradeoffs

| Tradeoff | Pro | Con |
|----------|-----|-----|
| **Flat TodoList vs hierarchical plan** | Simple `depends_on` DAG, trivial `get_ready_todos`/`replace_pending_todos`, easy parallelization | Cannot represent subtask-of-subtask or group/phase structure; large `max_steps=20` plans remain flat |
| **Four-state status without `blocked`** | Clear terminal states; `_dependencies_satisfied` treats `failed` as unblocking so graph never permanently deadlocks | "Which subtask is blocking?" requires computing `pending - ready` set; no first-class blocked reason or `blocked_by` edge |
| **String-append crew plan** | Zero new runtime objects; works with any downstream LLM | Lossy, untyped, not queryable, not versioned, accumulates on re-kickoff without `copy()`; cannot carry `depends_on` |
| **Text fallback producing zero steps** | Keeps execution moving when model lacks function calling | Silent loss of decomposition — `TodoList` stays empty and flow falls back to unplanned path |
| **Isolated step messages** | Prevents contamination, limits token bloat | Loses off-dependency conversational memory; agent must rely on replanning to surface needed history |
| **Per-step LLM observation (medium/high)** | Captures `goal_already_achieved` and subtle invalidations via structured `StepObservation` | Adds N extra LLM calls per task; latency/cost scale with plan length |

## Failure Modes / Edge Cases

- **Non-function-calling fallback drops decomposition**: `_create_initial_plan` returns `plan, [], ready` when `llm.supports_function_calling()==False` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:270-276`) — no `TodoList` created, execution proceeds unplanned without warning.
- **Dependency deadlock without replan budget**: `get_ready_todos_method` returns `needs_replan` when `ready==[] and not is_complete` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1124-1132`); if LLM repeatedly produces unsatisfiable/circular `depends_on`, `handle_replan_now` hits `max_replans` and returns `all_todos_complete` dropping remaining pending todos (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1056-1064`).
- **Observation LLM failure defaults diverge**: `PlannerObserver.observe` outer exception returns `StepObservation(success=True, remaining_valid=True)` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:208-213`) while `_parse_observation_response` fallback returns `success=False, valid=False` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:348-352`) — inconsistent defaults risk masking failures vs spuriously replanning.
- **Expected tool enforcement aborts semantic success**: `_validate_expected_tool_usage` raises `ValueError` if `todo.tool_to_use` not called (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:515-538`), converting a correct text answer into `StepResult(success=False)`.
- **Per-step timeout is advisory**: `step_timeout` checked only between loop iterations (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:348-351`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:558-565`); a hung `llm.call` blocks past timeout until return.
- **Max replans silently completes**: When `replan_count >= max_replans`, remaining pending todos are not marked failed but execution finalizes with partial results (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1058-1064`).

## Future Considerations

- Unify crew and agent planning behind a single `TodoList` registry with `plan_id` and versioned artifact persistence, deprecating `task.description += plan` mutation.
- Persist `AgentExecutorState.todos`/`observations`/`execution_log` into `RuntimeState` checkpoint (today only memory views are rebound, not plan state) so resume-from-checkpoint retains the graph.
- Add hierarchical decomposition: `TodoItem.children: list[TodoItem]` or `parent_step_number` to represent phases and enable group-level status/evaluation.
- Expose explicit reorder/prioritize APIs (`TodoList.reorder`, `move_before`) instead of requiring full `replace_pending_todos` replanning.
- Add plan visualization distinct from Flow DAG visualization, and a structural coverage metric (required subtask count, dependency cycle detection, minimality check) beyond `is_complete`.
- Consider pluggable `BasePlanner` interface so deterministic decomposers can replace LLM for structured domains and enable plan caching keyed by `(task hash, tools hash, PlanningConfig hash)`.
