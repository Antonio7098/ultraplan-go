## Summary

Agent Framework implements context selection as an **explicit, two-phase, provider-pipeline architecture** rather than an implicit prompt-assembly convention. In both language stacks, a per-invocation "context engineering" pipeline decides what enters the model: caller input is merged with conversation history (loaded by pluggable history providers), then enriched by ordered `AIContextProvider` / `ContextProvider` plugins that can inject messages, instructions, tools, and middleware; finally an optional compaction stage annotates messages into groups and projects only "included" groups into the request. Every injected message is stamped with machine-readable provenance (source id/type), every compaction exclusion records a reason, and the model itself can pull additional context on demand via loader tools (RAG search tool, MCP progressive disclosure, skill loading). Selection policy is dynamic per run and configurable via flags and filter delegates; sensitive-data handling exists but is fragmented across opt-in packages (Purview governance, telemetry redaction, experimental FIDES information-flow labels), and the framework core deliberately does not sanitize provider-contributed content — it documents that responsibility as belonging to the developer.

## Rating

**8 / 10** — Clear model with tests, explicit interfaces, and operational safeguards.

Rationale:
- The selection mechanism is explicit and inspectable: dedicated base classes (`ContextProvider` at `python/packages/core/agent_framework/_sessions.py:793`, `AIContextProvider` at `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:42`) with a documented two-phase lifecycle, invoked at deterministic seams (`python/packages/core/agent_framework/_agents.py:1625-1637`, `dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:778-791`).
- Provenance is first-class: `_attribution` metadata with source id/type/cross-session origins in Python (`python/packages/core/agent_framework/_sessions.py:661-694`) and `AgentRequestMessageSourceAttribution` stamping in .NET (`dotnet/src/Microsoft.Agents.AI.Abstractions/AgentRequestMessageSourceAttribution.cs:14-19`, applied at `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:174-176`). The system can answer *which component* put a document into context; it cannot answer a deeper semantic *why* beyond the source's identity.
- Compaction is observable and reversible-by-design (exclusion flags + reasons rather than destructive deletion): `python/packages/core/agent_framework/_compaction.py:705-736`; .NET adds telemetry activities (`dotnet/src/Microsoft.Agents.AI/Compaction/CompactionTelemetry.cs:20`).
- Extensive test coverage: 138 tests in `python/packages/core/tests/core/test_sessions.py`, 74 in `python/packages/core/tests/core/test_compaction.py`, plus dedicated .NET suites (`dotnet/tests/Microsoft.Agents.AI.UnitTests/AIContextProviderDecorators/AIContextProviderChatClientTests.cs`, `.../Data/TextSearchProviderTests.cs`, `.../Compaction/*Tests.cs`).
- Why not 9–10: core provider APIs are still marked experimental in .NET (`MAAI001` suppressions at `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:152,301`); the FIDES labeling system is explicitly `@experimental(feature_id=ExperimentalFeature.FIDES)` (`python/packages/core/agent_framework/security.py:91`); governance post-checks do not support streaming (`python/packages/purview/agent_framework_purview/_middleware.py:240-241`); and there is no unified policy engine that explains inclusion decisions across all sources in one place.

## Answers to Dimension Questions

**1. What decides what goes into context?**
A deterministic, layered pipeline. For Python: (a) caller-supplied messages normalized at `python/packages/core/agent_framework/_agents.py:1371`; (b) a decision about whether history lives server-side or locally (`store` option vs `STORES_BY_DEFAULT`, `python/packages/core/agent_framework/_agents.py:1377-1405`); (c) each registered `ContextProvider.before_run` contributes messages/instructions/tools/middleware into a `SessionContext` in registration order (`python/packages/core/agent_framework/_agents.py:1625-1637`, `python/packages/core/agent_framework/_sessions.py:624-755`); (d) the flattened `get_messages(include_input=True)` list becomes the request (`python/packages/core/agent_framework/_agents.py:1516-1517`); (e) just before each model call (including loop iterations), compaction annotates groups and projects included messages (`python/packages/core/agent_framework/_clients.py:366-394`, `python/packages/core/agent_framework/_compaction.py:1475-1488`). .NET mirrors this: history load then sequential `InvokingAsync` over a shared mutable `AIContext` (`dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:762-808`). Signals covered: conversation history (history providers), retrieved documents (TextSearchProvider), system prompt (merged `instructions`), tools (provider-contributed + progressive disclosure). There is no built-in user-profile signal beyond what a custom provider supplies.

**2. Is selection policy explicit or implicit?**
Explicit. Policy is expressed through typed interfaces (`ContextProvider.before_run/after_run` at `python/packages/core/agent_framework/_sessions.py:830-870`; `AIContextProvider.InvokingAsync/InvokedAsync` at `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:115-116,258-259`), configurable flags (`HistoryProvider.load_messages/store_inputs/store_context_from` at `python/packages/core/agent_framework/_sessions.py:967-1000`), and first-class filter delegates on the .NET side (default External-only provide/store filters at `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:57-65`, options-level filters at `dotnet/src/Microsoft.Agents.AI.Abstractions/InMemoryChatHistoryProviderOptions.cs:62-86`). Ordering semantics are documented (first provider receives raw caller context; later providers see earlier providers' output: `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:408-417`).

**3. Can the model influence what it sees?**
Yes, through three sanctioned mechanisms: (a) on-demand retrieval — `TextSearchBehavior.OnDemandFunctionCalling` swaps automatic RAG injection for a `Search` tool the model may call (`dotnet/src/Microsoft.Agents.AI/TextSearchProvider.cs:96-123`); (b) MCP progressive disclosure — the model starts with only `list_mcp_tools`/`load_tool`/`unload_tool` and pulls specific tools onto the next iteration (`python/packages/core/agent_framework/_mcp.py:93-95,524-531`), mirrored by `FunctionInvocationContext.add_tools` ("progressive tool exposure", `python/packages/core/agent_framework/_middleware.py:354-358`); (c) skills — the model reads an advertised index and calls `load_skill`/`read_skill_resource` to pull skill bodies/resources into context (`python/packages/core/agent_framework/_skills.py:1931`, advertisement prompt builder at `python/packages/core/agent_framework/_skills.py:2299`). This is deliberate context-on-demand rather than front-loading everything.

**4. Are sensitive fields redacted?**
Partially, and mostly outside the core path. Concrete mechanisms: Purview middleware can block prompts/responses entirely based on policy (`python/packages/purview/agent_framework_purview/_middleware.py:192-203,227-239`; .NET equivalent `dotnet/src/Microsoft.Agents.AI.Purview/PurviewChatClient.cs:31-33`); log redaction defaults to replacing sensitive values with `<redacted>` (`dotnet/src/Microsoft.Agents.AI/TextSearchProvider.cs:94`); OpenTelemetry capture of prompts/results is off unless `enable_sensitive_data` is set (`python/packages/core/agent_framework/observability.py:771-786`); and an experimental FIDES label system can prevent private data flowing to public destinations (`python/packages/core/agent_framework/security.py:109-124,267-298`). However, message content flowing into the model is not scanned or masked by the framework: .NET docs explicitly state provider data "is accepted as-is and merged into the request context" (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:34-39`). No field-level redaction of PII inside messages exists in core.

**Bonus — can the system explain why a particular document was included?**
Provenance yes, intent partially. Injected messages carry attribution (`_attribution.source_id/source_type/origin_session_ids` at `python/packages/core/agent_framework/_sessions.py:661-694`; `AgentRequestMessageSourceAttribution` at `dotnet/src/Microsoft.Agents.AI.Abstractions/AgentRequestMessageSourceAttribution.cs:14-45`), so any context message can be traced to the component that supplied it and, for cross-session memory, to originating sessions. Excluded messages carry a reason string (`python/packages/core/agent_framework/_compaction.py:718-727`) and .NET emits compaction telemetry spans (`dotnet/src/Microsoft.Agents.AI/Compaction/CompactionTelemetry.cs:20`). What is missing is a semantic rationale (e.g., relevance score from retrieval) surfaced alongside the injected document; the TextSearchProvider formats results with source name/link but does not attach scores or an explanation object to the message (`dotnet/src/Microsoft.Agents.AI/TextSearchProvider.cs:275-309`).

## Architectural Decisions

1. **Single choke-point enrichment via decorators/middleware.** All context enters at one seam — the chat-client invocation — either as an agent-side provider loop before the call (`dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:778-791`) or as a delegating `IChatClient` wrapper (`dotnet/src/Microsoft.Agents.AI/AIContextProviderDecorators/AIContextProviderChatClient.cs:51-73`), and in Python via the agent run-prep + chat-middleware pipeline (`python/packages/core/agent_framework/_agents.py:1530-1556`). This makes the "what did the model see?" question answerable at one place.
2. **Attribution-first provenance.** Both stacks stamp every provider-injected message with source metadata at merge time (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:174-176`; `python/packages/core/agent_framework/_sessions.py:670-695`), enabling downstream filtering (e.g., .NET's default External-only filters exclude provider/history messages from being re-provided or re-stored).
3. **Non-destructive compaction with reasons.** Compaction marks messages excluded with a reason and inserts summary placeholders instead of deleting them (`python/packages/core/agent_framework/_compaction.py:370-415,718-727,1475-1488`); the same design appears in .NET's `CompactionMessageIndex.GetIncludedMessages()` used by `CompactionProvider.CompactAsync` (`dotnet/src/Microsoft.Agents.AI/Compaction/CompactionProvider.cs:91-101`). Preserving the original transcript supports audit and stable group re-annotation across iterations.
4. **Local-vs-service history duality made explicit.** The framework models both client-managed and service-managed history and detects conflicts: warning/throwing/clearing when a conversation id coexists with a local `ChatHistoryProvider` (`dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:827-852`), and warning when a load-capable HistoryProvider meets a service-managed conversation (`python/packages/core/agent_framework/_agents.py:1417-1435`).
5. **Security guidance embedded in the API contract.** Prompt-injection risk from external retrieval sources is documented directly on the provider base class and compaction provider (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:34-39`; `dotnet/src/Microsoft.Agents.AI/Compaction/CompactionProvider.cs:38-41`), making trust boundaries part of the interface documentation instead of tribal knowledge.

## Notable Patterns

- **Two-phase lifecycle symmetry**: `before_run`/`after_run` (Python, `python/packages/core/agent_framework/_sessions.py:830-870`) and `InvokingAsync`/`InvokedAsync` (.NET, `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:115,258`); failure notification is guaranteed even on exceptions (`dotnet/src/Microsoft.Agents.AI/AIContextProviderDecorators/AIContextProviderChatClient.cs:64-68`).
- **Composable strategy pipelines**: Python `TokenBudgetComposedStrategy` runs ordered sub-strategies with early-stop plus a deterministic fallback that enforces budget down to anchors (`python/packages/core/agent_framework/_compaction.py:1400-1472`); .NET `PipelineCompactionStrategy` composes strategies similarly (`dotnet/src/Microsoft.Agents.AI/Compaction/PipelineCompactionStrategy.cs:28`).
- **Progressive disclosure everywhere**: MCP tools, skills, and RAG search all follow advertise → on-demand load, keeping baseline context small.
- **Cross-session provenance**: `origin_session_ids` on injected memory messages enables downstream governance/audit detection of content that came from other sessions (`python/packages/core/agent_framework/_sessions.py:646-659`).
- **Group-atomic tool pairs**: reasoning/function-call/result groups must be preserved atomically during compaction and replay; ambiguous duplicate call declarations stay separate (`python/packages/core/agent_framework/_compaction.py:105-123`; approval-control pairing at `python/packages/core/agent_framework/_sessions.py:878-918`).

## Tradeoffs

- **Order dependence without precedence rules for messages**: instructions from multiple sources are naively concatenated with `"\n"` (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:166-172`; `python/packages/core/agent_framework/_agents.py:1647-1649`); there is no conflict resolution or priority scheme between provider instructions.
- **Trust shifted to integrators**: no sanitization/validation of injected content keeps the core neutral but pushes prompt-injection defense to every provider author (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:34-39`).
- **Fail-open retrieval**: if search throws, `TextSearchProvider.ProvideMessagesAsync` logs and returns an empty context rather than failing the run (`dotnet/src/Microsoft.Agents.AI/TextSearchProvider.cs:199-203`) — resilient, but silently changes what the model sees.
- **Experimental core surfaces**: .NET context-provider contexts require `MAAI001` pragma suppression (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:152-162`); Python FIDES labels are gated behind an experimental feature flag (`python/packages/core/agent_framework/security.py:91`).
- **Governance gaps under streaming**: Purview response evaluation is skipped for streaming runs (`python/packages/purview/agent_framework_purview/_middleware.py:240-241`).

## Failure Modes / Edge Cases

- **Unsatisfiable budgets**: truncation/token-budget strategies retain the minimum group needed for a valid projection, so the result may stay above `compact_to`/budget when that single group exceeds it (`python/packages/core/agent_framework/_compaction.py:797-815,1400-1408`).
- **Ambiguous call/result pairing**: duplicate function-call declarations with reused `call_id`s remain unpaired and are kept separate rather than guessed (`python/packages/core/agent_framework/_compaction.py:105-123`).
- **History-provider/service conflict**: misconfiguration surfaces as a logged warning, an exception, or silent clearing depending on `WarnOnChatHistoryProviderConflict`/`ThrowOnChatHistoryProviderConflict`/`ClearOnChatHistoryProviderConflict` (`dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:827-852`).
- **In-place compaction aliasing**: compaction must operate on the caller's list so summaries survive the tool-loop's reused list; operating on a copy silently drops older groups (regression fixed per issue #4991, documented at `python/packages/core/agent_framework/_clients.py:383-394`).
- **Pending-approval replay safety**: resolved approval control-plane contents are filtered from later model replay, but unresolved requests/responses are preserved until terminal, avoiding orphaned approvals (`python/packages/core/agent_framework/_sessions.py:921-940`).

## Future Considerations

- Attach retrieval metadata (scores, query, source ranking) as structured annotations on injected documents so inclusion can be explained quantitatively, building on the existing `_attribution` channel (`python/packages/core/agent_framework/_sessions.py:661-694`).
- Promote the FIDES confidentiality/integrity labels from experimental to a supported enforcement point inside `SessionContext.extend_messages` / `AIContextProvider.InvokingCoreAsync` so sensitivity checks apply uniformly rather than via separate middleware (`python/packages/core/agent_framework/security.py:91`).
- Extend policy-governance post-evaluation to streaming responses (`python/packages/purview/agent_framework_purview/_middleware.py:240-241`).
- Stabilize the `[Experimental]` AIContextProvider surface in .NET and converge naming with the Python `ContextProvider` API to reduce cross-language divergence.

## Questions / Gaps

- **No evidence found** of a declarative, centralized context-selection policy file (e.g., rules like "include document X because Y"); searched `docs/design`, `docs/specs`, and both cores — policy is code-defined per provider instance, not configuration-driven.
- No built-in PII detection/redaction applied to message bodies before they enter model context; only telemetry paths redact by default. Searched `redact|PII|sensitive` across `python/packages/core` and `dotnet/src/Microsoft.Agents.AI`.
- User-profile/workspace-state signals have no dedicated first-class abstractions (unlike history/RAG/skills); they would be implemented as custom `ContextProvider`s. Nothing in `python/packages/core/agent_framework/__init__.pyi` suggests otherwise.
- Go SDK internals were not analyzable here: the repo's `go/` directory defers to the external `microsoft/agent-framework-go` repository (`README.md`, "Go Support" section at `README.md:26`), so findings cover the Python and .NET implementations only.
- Whether compaction exclusion reasons are ever surfaced to end users (vs. logs/debugging) — no UI/hosting code was found that renders `_exclude_reason`; searched hosting/devui packages.
