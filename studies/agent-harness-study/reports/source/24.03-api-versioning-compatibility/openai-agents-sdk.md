## Summary

The SDK uses a two-tier versioning model: package version `0.Y.Z` (`pyproject.toml:3` = `0.22.0`, `src/agents/version.py:4` via `importlib.metadata`) for release-level breaking vs non-breaking changes, and a durable persisted contract `RunState.$schemaVersion` (`src/agents/run_state.py:182` `CURRENT_SCHEMA_VERSION="1.17"`) for the human-in-the-loop resume boundary. Package versioning is informal `0.Y.Z` semver documented in `docs/release.md:3-19` (minor `Y` = breaking for non-beta public interfaces, patch `Z` = bugfix/feature/private/beta). `RunState` versioning is mature and executable: every bump adds a one-line summary in `SCHEMA_VERSION_SUMMARIES` (`src/agents/run_state.py:186-217`), validation is fail-fast forward (`src/agents/run_state.py:3852-3853` rejects unknown/newer versions), and backward reads are gated by minimum-version checks for newer payload shapes (e.g., `1.13` for Programmatic Tool Calling at `src/agents/run_state.py:183,3888-3898` and `1.14` for hosted MCP approvals). A frozen historical corpus (`tests/fixtures/run_state/`) with `tests/test_run_state_compatibility_corpus.py` verifies that every durable field survives upgrade, that `to_json()` idempotently rewrites to current, and that old approvals remain runnable; a separate `tests/fixtures/released_api_contract.json` plus `tests/fixtures/released_api_contract_policy.json` and `tests/test_released_api_contract.py` freezes every top-level export signature, Pydantic field, TypedDict requiredness and `__all__` membership to detect breaking changes at test time. Breaking changes are documented per minor in `docs/release.md:20-235` with migration snippets. Deprecation policy is ad-hoc (e.g., docstring-only `LocalShellTool will be deprecated` at `src/agents/tool.py:1364`), and there is no generic capability/version negotiation, feature-flag framework, or compatibility shims for unreleased schemas (intentionally renumbered/squashed — `src/agents/run_state.py:177`).

## Rating

**7 / 10** — Clear model with executable safeguards for the two critical surfaces (package API contract and `RunState` durable schema), detailed changelogs and migration guides, and automated backward-read and signature-compatibility tests. Deducted because deprecation warning/staging is inconsistent, beta/experimental vs stable is marked by comments/package layout rather than versioned interfaces, and compatibility relies partly on policy prose (`0.Y.Z` + `experimental` notes) and fails closed for forward compatibility without negotiation. A production integration can upgrade safely if it pins `0.Y` and validates against `RunState`/`released_api_contract` fixtures, but must audit every `0.Y` bump.

## Answers to Dimension Questions

**1. Which APIs are stable, experimental, deprecated, or internal?**
- Stable: Top-level exports in `src/agents/__init__.py:366-617` (`__all__`) constitute the released contract, frozen in `tests/fixtures/released_api_contract.json:1` and curated by `tests/fixtures/released_api_contract_policy.json:1-831` (which also whitelists canonical cross-module imports and optional bindings). This includes `Agent`, `Runner`/`RunConfig`/`RunState`/`RunContextWrapper`, `Session` family, `FunctionTool`/`HostedMCPTool`/`ShellTool`, guardrails, handoffs, models, tracing spans. Field order and `__all__` membership are explicit compat contracts per `AGENTS.md:85-95` and validated in `tests/test_released_api_contract.py:82-111`.
- Experimental: `src/agents/extensions/experimental/__init__.py:1` (“could be changed until being GAed”) exposes `codex` and `hosted_multi_agent`. `src/agents/run.py:193,219,545` `AgentRunner`/`DEFAULT_AGENT_RUNNER` are `WARNING: experimental and not part of public API`. `src/agents/extensions/experimental/hosted_multi_agent/model.py:78,101` labels hosted multi-agent as `beta` on Responses, validates `reasoning.summary`/`max_tool_calls` incompatibility at `model.py:425-431`, and injects `betas` at `model.py:464`. `src/agents/realtime/README.md:3` also notes Realtime beta may break.
- Deprecated: No formal deprecation framework. `src/agents/tool.py:1364` states `LocalShellTool will be deprecated in favor of` `ShellTool` as a docstring note only, with no `DeprecationWarning`. `src/agents/stream_events.py:32` freezes a misspelling `handoff_occured` for backward compat. Narrow `warnings.warn` exists for mount permissions at `src/agents/sandbox/entries/mounts/base.py:410` but is not a general API deprecation. Thus deprecation is ad-hoc and leaves `ShellTool`/`LocalShellTool` coexistence ambiguous.
- Internal: `src/agents/run_state.py:175-177`, `src/agents/run_internal/`, `src/agents/sandbox/` helpers, `src/agents/tracing/` internals, and anything not in `__all__` or behind `optional_exports` in `released_api_contract_policy.json:452` (e.g., `CloudflareSandboxSession` gated on `aiohttp`, `RedisSession` etc.) are intentionally not contracted. `AGENTS.md:42` explicitly allows rewriting unreleased internal/persisted formats without shims.

**2. How are users warned before breaking changes?**
Users are warned primarily via `docs/release.md:1-236` which is the canonical breaking-change changelog linked from `docs/llms.txt:60` and `mkdocs.yml:92`. Every `0.Y.0` that carries a break lists the affected APIs, before/after behavior, and concrete migration code (e.g., `0.22.0` `OpenAIProvider` `UserError` for `organization`/`project` duplication at `release.md:30`, `0.21.0` httpx→httpx2 migration at `release.md:42-44`, `0.20.0` MCP v1→v2 pin-or-migrate at `release.md:57`, `0.17.0` `SandboxPathGrant` for outside `base_dir` at `release.md:88-112`, `0.8.0`/`0.7.0` handoff/mcp thread and default-history migrations). Versioning policy tells users to pin `0.0.x` to avoid breaks (`release.md:9`) and notes that `Y` signals breaking for non-beta public interfaces. There is no runtime deprecation warning for broken symbols: `grep warnings.warn|Deprecation` finds only mount-permission and sandbox warnings (`src/agents/sandbox/entries/mounts/base.py:410`) and the `run.py:2266` deprecation filter ignore. So warning is changelog/policy-driven, not executable via `DeprecationWarning`/`FutureWarning` at import/call time, and no automated compat-shim period is advertised.

**3. Are old clients, plugins, traces, or persisted artifacts still usable?**
- Persisted artifacts (`RunState`): Yes for in-support versions. `src/agents/run_state.py:182-218` supports `1.0`–`1.17`; `tests/fixtures/run_state/README.md:1` freezes a corpus per version and `tests/test_run_state_compatibility_corpus.py:178-199` asserts that every minimal/feature fixture (including `resume/v1_13_pending_tool_approval.json`) loads, maps every durable field, rewrites idempotently to `1.17`, and enables real `Runner` resume (approve/reject). Security artifacts (`security/v1_13_legacy_mount_credentials.json`) are deliberately migrated by stripping credentials/driver_options and requiring trusted rebind (`tests/test_run_state_compatibility_corpus.py:371-407`). Older than `1.0` or newer than `1.17` is intentionally rejected (fail-fast, `src/agents/run_state.py:3852`), so old clients with pre-1.0 or future newer artifacts cannot be read without SDK upgrade.
- Plugins/extensions: Partially. Optional dependencies (`pyproject.toml:36-59`) declare narrow ranges (`openai>=3,<4`, `mcp>=1.19,<3`, `websockets>=15,<17`) and are reflected in `released_api_contract_policy.json:370-400` `optional_bindings` (e.g., `voice`→`numpy`, `cloudflare`→`aiohttp`). MCP ordinary stdio/SSE/StreamableHTTP connections auto-adapt via `mcp.Client(mode="auto")` with fallback (described in `docs/release.md:57`), so old SSE servers still work; but custom `httpx.Auth`/`AsyncClient` callers must migrate to `httpx2` or pin `mcp<2`. Tool-search, sandbox backends, and voice/Realtime plugins that stay within the curated surfaces remain usable.
- Clients/Sessions: No evidence of session schema versioning; `docs/sessions/index.md:1-30` describes `SQLiteSession` etc. but no persisted session migration is shown in grep. Server-managed `conversation_id`/`previous_response_id` continuation is separate from client-managed session history, so client-side histories are not version-negotiated.
- Traces: Traces are span data, not a persisted durable schema with version; resumption relies on `TraceState.tracing_api_key_hash` equality (`src/agents/tracing/context.py:38-44`) so old hash-only traces remain attachable without leaking secrets. No trace version migration was found, so trace compatibility is best-effort and redaction-first (`tests/test_run_state_compatibility_corpus.py:123-127` redaction observables test).

**4. Does compatibility rely on policy alone or executable tests?**
Both, with meaningful executable coverage but uneven distribution. Policy: `docs/release.md` versioning, `AGENTS.md` compat-boundary and review gates, `experimental/__init__.py:1` prose, and MCP httpx migration notes. Executable:
- `RunState` backward-read is exercised over real historical writers (`tests/fixtures/run_state/generate_corpus.py` extracts each `git archive` commit and runs that commit's writer, not the current checkout) and then validated for every field, type, idempotence, approval resume, and redaction (`tests/test_run_state_compatibility_corpus.py:141-162,178-272,371-432`). A tamper test ensures comparison uses immutable expected payloads (`test_historical_fixture_comparison_uses_immutable_expected_payload:230-247`).
- Released API contract is built by `integration_tests/_contract_support` (imported at `tests/test_released_api_contract.py:23`) and compared against `tests/fixtures/released_api_contract.json:1`; the policy file `tests/fixtures/released_api_contract_policy.json:1` is the executable boundary for what counts as public. The suite checks literal default-type preservation (`False` vs `0` at `test_released_api_contract.py:66-89`), Pydantic fields, TypedDict requiredness, and optional binding guards.
- Positional constructor guard: `tests/test_source_compat_constructors.py:34` prevents silent `RunConfig` reordering breaks.
- Release gate: `.agents/skills/final-release-review/` checklist and `tests/README.md:48-50` enforce `make update-released-api-contract VERSION=<version>` from the release branch. Still, deprecation staging, general session-store versioning, and MCP/Responses wire-version negotiation have no dedicated compat tests, so those surfaces rely on policy/migration prose.

## Notable Patterns

- **Single-writer, many-reader durable schema.** `RunState.to_json()` always emits `1.17` while `_validate_run_state_schema_version` reads `1.0`–`1.17`, embodying a classic “write current, read N” pattern with explicit forward reject (`src/agents/run_state.py:182,3842-3860`). Provenance is tracked per fixture (`canonical_compatibility` vs `historical_writer` in `tests/fixtures/run_state/sources.json:45-54`).
- **Field-level idempotent rewrite.** Corpus tests assert that after `from_json` → `to_json`, not only does the version label stay `1.17`, but `_normalized_durable_state` of historical vs canonical must be subset-equal, and second read must not mutate expected payload (`tests/test_run_state_compatibility_corpus.py:178-272`), ensuring upgrade is lossless and repeatable.
- **Trusted-error gating during resume.** `src/agents/run_state.py:5409-5414,5460` plus `tests/test_run_state_compatibility_corpus.py:691-805` validates that only SDK-owned error producers (`_validate_run_state_schema_version`, `_build_agent_map`, etc.) with `_agents_run_state_validation` markers and untampered tracebacks are trusted; foreign `UserError` or JSON-decode errors with injected args/`__traceback__` are redacted (`RuntimeError("Error details are redacted.")`). This couples compatibility with security (mount credential and exception payload redaction).
- **Versioned optional exports.** `released_api_contract_policy.json:452` `optional_bindings`/`optional_exports` per `agents.extensions.sandbox`, `agents.voice` etc. models platform gating: same source exports differently depending on `numpy`/`aiohttp`/`modal` presence, so contract validation is installation-aware rather than assuming all extras are present.
- **Capability-tied model requests.** `src/agents/sandbox/capabilities/capability.py:47-63` `required_capability_types()` and `get_model_request_params()` plus `src/agents/sandbox/runtime.py:269-272` binding show that sandbox capabilities can contribute request params (compaction, skills, memory) — an implicit capability evolution path, but without a wire negotiator; parameter injection is local.

## Tradeoffs

- **Breadth of `SUPPORTED_SCHEMA_VERSIONS` vs forward strictness.** Keeping 18 versions readable (`1.0`–`1.17`) maximizes old artifact reusability (corpus proves it) but forces the SDK to carry deprecated deserializers (e.g., `pending_input` list coercion at `src/agents/run_state.py:4036`) and prevents opportunistic cleanup. The alternative — prune very old versions — would shrink code but break long-paused HITL runs. The team chose durability over code slimness, documenting the tradeoff via `canonical_compatibility` exceptions for versions without writers (`tests/fixtures/run_state/README.md:13`).
- **`0.Y.Z` with breaking on `Y` vs conventional semver.** For `0.Y.Z`, every minor is potentially breaking, so consumers cannot use `~=` or `^` like post-1.0 libraries. The tradeoff is captured in `docs/release.md:9` (“pin to `0.0.x`”) — early adopters who pinned narrowly are safe, but anyone on `0.Y.*` wildcard or `>=0.Y` will ingest breaks. This speeds shipping but shifts auditing burden to integrators.
- **Fail-fast on unknown schema vs best-effort downgrade.** `src/agents/run_state.py:3852` rejects newer `$schemaVersion` outright with a list of `Supported versions`. This is safe (prevents mis-resume) but not recoverable — old SDKs cannot resume new artifacts even if they only use old fields. A lenient “ignore unknown fields” policy would improve survivability but risk silent loss of new invariants (e.g., invocation identity/scope at `src/agents/run_state.py:1164-1174`).
- **Corpus fidelity vs maintenance cost.** Generating each fixture from `git archive` in a locked env (`tests/fixtures/run_state/README.md:8`) gives high fidelity but requires retaining source trees/commits for every version (`tests/fixtures/run_state/sources.json:36-37` `baseline v0.19.4`). Cheaper hand-edited version bumps would be lighter but could hide reader bugs; hence the four `canonical_compatibility` exceptions are explicitly called out and justify their non-writer provenance.
- **Curated public contract vs inferred contract.** `released_api_contract_policy.json:1-831` manually lists `canonical_imports`, `public_properties`, `public_typed_dicts`, and abstract class members. This is precise but requires a manual `make update-released-api-contract` step before review (`tests/README.md:50`). Auto-inference would be zero-effort but would freeze internals accidentally.
- **MCP auto-probe vs pin.** `docs/release.md:57` describes `mcp.Client(mode="auto")` that tries newest protocol then falls back to legacy `initialize`. Auto-probe gives compatibility with both v1 and v2 servers without user pinning, but it hides version choice and adds a retry path; the alternative — require `mcp<2` pin — is presented as the escape hatch for custom `httpx.Auth` users.

## Failure Modes / Edge Cases

- **Upgrading across multiple `0.Y` releases without reading `release.md`.** Because patch `Z` may carry features and beta changes that also affect behavior (`docs/release.md:11-17`), a consumer who only tracks breaking minors will miss tightening like `0.22.0` guardrail-blocked output rewriting (`function_call_output` replaced with `"Output withheld..."` at `release.md:28`) that discards current-response suffix for unsupported shapes. No deprecation shim precedes this, so the failure is silent data-shape loss if session history is assumed intact.
- **Old SDK reading new `RunState`.** Any `RunState` produced by `1.17` writer read by an older reader (e.g., `1.12` era) triggers `UserError: Run state schema version is not supported. Supported versions are: ...` at `src/agents/run_state.py:3852-3857` and hard-fails resume. There is no Compat layer or downgrade exporter, so long-lived persisted `RunState` blobs must be drained before downgrading SDKs.
- **Legacy `SandboxSessionState` with embedded credentials.** Pre-`1.15` fixtures like `security/v1_13_legacy_mount_credentials.json` persisted `MountConfig` credential fields and `driver_options`. Current reader strips them and sets `mount_authority_redacted=true` (`tests/test_run_state_compatibility_corpus.py:371-407`); any subsequent `rebind_persisted_mount_authority(None)` raises `ValueError: requires a current trusted manifest`. Code that assumed credentials travel with `RunState` will unexpectedly fail with missing authority after upgrade.
- **Custom `httpx` → `httpx2` mixing.** Apps that pass a legacy `httpx.AsyncClient`/`httpx.Auth` to `AsyncOpenAI(http_client=...)` (per `docs/config.md:76`) hit runtime errors under `openai>=3` because the SDK does not convert arbitrary legacy `httpx` objects (`docs/release.md:44`). The fix is either migrate to `DefaultAsyncHttpx2Client` or install `httpx` and rely on the temporary compatibility bridge — without it, provider calls fail.
- **MCP v2 incompatibility with `ignore_initialized_notification_failure`.** `docs/release.md:57` notes this param is `v1-only`; after resolver picks MCP v2, that StreamableHTTP option no longer applies. Apps that set it for flaky SSE servers will see it silently ignored or error after MCP minor upgrade.
- **Positional `RunConfig` / `FunctionTool`/`AgentHookContext` field reordering risk.** Pre-`1.7` code that called `RunConfig(10, agent, ...)` positionally would silently swap args if field order changed. `tests/test_source_compat_constructors.py:34` now guards this, and `AGENTS.md:85-95` mandates append-only. Absent that test, a field insertion in the middle would be a silent breaking change.
- **Exception payload leaking through redaction bypass.** Corpus tests show providers can craft `ForeignMapping` (`tests/test_run_state_compatibility_corpus.py:490-510`), `ForeignContextWrapper` subclass (`tests/test_run_state_compatibility_corpus.py:516-559`), or hostile `__dict__`/`__getattribute__` slots (`1032-1106`) whose `__getitem__`/`__iter__`/`__len__` callbacks would execute if the SDK invoked them. Current code avoids calling them (never iterates untrusted `__iter__`), but a future change that adds a new mapping operation could reintroduce an exfil path. Similarly, trusting a mutated `_agents_run_state_validation` marker (`tests/test_run_state_compatibility_corpus.py:720-741`, `744-770`) would let forged `UserError` messages escape redaction — the code currently cross-checks with traceback identity.
- **Beta-to-GA promise break.** `src/agents/extensions/experimental/hosted_multi_agent/model.py:464` injects `betas=[_BETA_ID]` and `model.py:417-431` validates unsupported settings; downstream who pins behavior on the beta wire shape will break when the beta is GA’d and the header is removed, without a version gate.
- **Sandbox path-grant assumption.** `0.17.0` tightens `LocalFile.src`/`LocalDir.src` to stay within `base_dir` unless covered by `Manifest.extra_path_grants` (`docs/release.md:88-112`). Apps that previously copied from outside `base_dir` without grants will now get `SandboxPathGrant` required errors — a fail-closed security change that looks like a compat break if not migration-noted.
- **Tracing key loss on strictContext misuse.** `src/agents/run_state.py:3932-3934` raises if `strict_context=True` and context metadata requires deserializer, but silent warning path (not strict) can yield a placeholder `{"custom": True}` mapping that loses behavior. Consumers that store custom context objects without providing `context_deserializer` will resume with degraded context.
