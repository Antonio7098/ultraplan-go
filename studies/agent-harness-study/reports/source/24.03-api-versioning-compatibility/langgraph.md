## Summary

LangGraph implements a clear, code-enforced versioning model for its most critical compatibility surface — persisted checkpoints — and a disciplined deprecation-warning taxonomy for public Python APIs. Checkpoint format is versioned via `Checkpoint["v"]` (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/langgraph/checkpoint/base/__init__.py:92`) with `LATEST_VERSION=4` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_checkpoint.py:23`) and explicit migration functions in `Pregel._migrate_checkpoint` and `CompiledStateGraph._migrate_checkpoint`. Streaming/event protocols are version-negotiated via `stream_events(version="v1"|"v2"|"v3")` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:3643`). Deprecations use typed subclasses of `LangGraphDeprecationWarning` carrying `since`/`expected_removal` tuples (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/warnings.py:13`). Backwards-compatibility is tested executably (checkpoint migration fixtures, DeltaChannel migration tests, deprecation-warning tests), not just documented. Gaps: no in-repo `CHANGELOG.md`/migration guide (changelog points to GitHub Releases `studies/agent-harness-study/sources/langgraph/libs/langgraph/pyproject.toml:32`), no automated API-break detection, SDK/CLI remain pre-1.0 with divergent stability expectations, and experimental surfaces (`v3` streaming, `DeltaChannel`) are explicitly marked unstable with no negotiated capability handshake.

## Rating

**7 / 10 — Clear model with tests, explicit interfaces, and operational safeguards**

Rationale: persisted-contract versioning is mature (integer `v`, deterministic migrations, large fixture-based tests), deprecation has first-class warning hierarchy with removal SemVer baked into the exception class, and streaming has explicit version dispatch. Deducted because (a) changelog/breaking-change documentation lives off-repo, (b) experimental vs stable labeling is ad-hoc (`@beta`, `!!! warning "Beta"`), (c) no executable contract tests for SDK/CLI/plugin surfaces, and (d) no capability/version negotiation between SDK and server beyond internal `CONFIG_KEY_*` interned strings — so a production upgrade requires reading release notes and checkpoint fixtures, not just bumping a range.

## Answers to Dimension Questions

**1. Which APIs are stable, experimental, deprecated, or internal?**

*Stable:* Core `StateGraph`/`Pregel` invoke/stream APIs, checkpoint `v=4` format, `langgraph` 1.x (classifier `Development Status :: 5 - Production/Stable` in `studies/agent-harness-study/sources/langgraph/libs/langgraph/pyproject.toml:12`). Channel primitives `LastValue`, `BinaryOperatorAggregate`, `Topic` are mature; `CompiledStateGraph` public surface in `graph/state.py` is stable.

*Deprecated (with executable warnings):* 14+ sites each emitting a typed `LangGraphDeprecatedSinceV*` warning with explicit `since`/`expected_removal` majors: `retry` → `retry_policy` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/func/__init__.py:217`), `input`/`output` → `input_schema`/`output_schema` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/graph/state.py:244`), `config_schema`/`config_type` → `context_schema` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:789`), `checkpoint_during` → `durability` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:2726`), `Send`/`Interrupt` from `langgraph.constants` → `langgraph.types` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/constants.py:34`), `Interrupt.interrupt_id` → `id` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:620`), `GraphOutput` dict access (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:388`), `MessageGraph` → `StateGraph(messages)` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/graph/message.py:364`), `PREVIOUS` private (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/constants.py:53`).

*Experimental / Beta:* `stream_events(version="v3")` and `GraphRunStream` are `@beta(message="The v3 streaming protocol on Pregel is experimental.")` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:3504`, `studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/stream/run_stream.py:36`); `DeltaChannel` is `!!! warning "Beta"` with unstable on-disk contract except for readability guarantee (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/channels/delta.py:34`); `checkpoint` storage extensions (`BaseCheckpointSaver.get_delta_channel_history`, `_DeltaSnapshot` ext code, `counters_since_delta_snapshot` metadata) noted as not yet stable (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/channels/delta.py:36`).

*Internal:* `CONFIG_KEY_*` interned constants (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/_internal/_constants.py:41-74`), `_loop.py`, `_algo.py`, `_checkpoint.py` helpers, `utils/config.py` and `utils/runnable.py` are explicitly "Backwards compat imports ... to be removed in v1" (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/utils/config.py:1`). No evidence of a formal `stable`/`experimental` annotation registry beyond these ad-hoc markers — no `py.typed` stability file or lint rule enforces it.

**2. How are users warned before breaking changes?**

Through runtime `warnings.warn(..., LangGraphDeprecationWarning, stacklevel=2)` that renders `"{message}. Deprecated in LangGraph V{x}.{y} to be removed in V{a}.{b}."` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/warnings.py:43-48`). Each subclass bakes the removal major: e.g., `LangGraphDeprecatedSinceV10(since=(1,0), expected_removal=(2,0))` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/warnings.py:58-62`). Some APIs also use `typing_extensions.deprecated` decorator with the same message (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:950`). Tests enforce that every deprecated path actually warns (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_deprecation.py:28-379`). Change *announcements* are delegated to GitHub Releases via `project.urls.Changelog = "https://github.com/langchain-ai/langgraph/releases"` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/pyproject.toml:32`); no in-repo `CHANGELOG.md`, `MIGRATION.md`, or `UPGRADE.md` was found (searched at repo root and `docs/`). No codemod or `pyupgrade` script ships. The warning is the only in-code affordance; surfacing depends on `PYTHONWARNINGS` / pytest `filterwarnings` config.

**3. Are old clients, plugins, traces, or persisted artifacts still usable?**

*Persisted checkpoints:* Yes — with migrations that run on read. `Pregel._migrate_checkpoint` handles `v<4` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:1136`) and `CompiledStateGraph._migrate_checkpoint` handles `v<3` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/graph/state.py:1626`), both called before building `StateSnapshot` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:1164`). `test_checkpoint_migration.py` replays 6-checkpoint chains from `v=1` and `v=2` fixtures and asserts post-migration equality (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_checkpoint_migration.py:1475-1506`). `DeltaChannel` migration is specially tested: a thread written with `BinaryOperatorAggregate` remains readable after swapping to `DeltaChannel` via ancestor-walking `get_delta_channel_history` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_delta_channel_migration.py:28-40`). Serialization layer preserves old JSON-typed checkpoints via msgpack migration path (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:64`) and allowlist-gated fallback (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:226`).

*Traces / store:* Memory saver tests explicitly cover multi-checkpoint chains spanning the migration boundary and verify `checkpoint_id` ordering still works after migration (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/tests/test_memory.py:568-580`). `EncryptedSerializer` accepts unencrypted payloads for backwards compat (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/langgraph/checkpoint/serde/encrypted.py:30`).

*Old SDK clients:* LangGraph SDK is versioned `0.4.3` (`studies/agent-harness-study/sources/langgraph/libs/sdk-py/langgraph_sdk/__init__.py:6`) with dependency pin `langgraph-sdk>=0.4.2,<0.5.0` in `langgraph` — a pre-1.0 range implying breaking changes allowed per SemVer. No evidence of server ↔ SDK version negotiation or client-capability handshake; `langgraph-sdk` is vendored as a path dep in tests (`studies/agent-harness-study/sources/langgraph/libs/langgraph/pyproject.toml:54`). Old clients against LangGraph Server (separate `langgraph-api` repo, not in this source) were not inspectable — Source Isolation forbids checking `../`. Within this source, old `InMemorySaver` alias `MemorySaver` is preserved (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/langgraph/checkpoint/memory/__init__.py:625`).

*Caveat:* `_DeltaSnapshot` blob shape and `counters_since_delta_snapshot` metadata are flagged unstable — future reads are promised but no schema-freeze is committed (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/channels/delta.py:36`).

**4. Does compatibility rely on policy alone or executable tests?**

Both, but executable tests carry most weight for the checkpoint surface. Policy is encoded as `since`/`expected_removal` tuples in warning classes (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/warnings.py:28-41`) and `pyproject.toml` version ranges (`studies/agent-harness-study/sources/langgraph/libs/langgraph/pyproject.toml:20-24`). Tests enforce:

- Every deprecated entry point emits the correct warning subclass and `match=` regex (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_deprecation.py:28-379`).
- Real historical checkpoint blobs (including pending writes, int/float channel versions, interrupt metadata) survive `_migrate_checkpoint` round-trips (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_checkpoint_migration.py:272-1506`).
- `DeltaChannel` migration invariants are property-checked across sync/async, time-travel, continuation, and fallback `BaseCheckpointSaver.get_delta_channel_history` paths (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_delta_channel_migration.py:136-360`).

What is *policy-only:* streaming `version="v1"/"v2"/"v3"` contract has no semver or deprecation test — `version` is a runtime `Literal` with no `LangGraphDeprecatedSince` wrapper; `v3` is simply marked `@beta` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:3504`) without an expected-removal timeline. SDK/CLI/server API versioning has no contract tests in this source. No CI job was found that diffs public API surface or enforces `pyproject.toml` upper-bound bumps.

## Notable Patterns

- **Lazy migration on read, not eagerly on write.** Saves in `pregel/_checkpoint.py:create_checkpoint` always write `v=LATEST_VERSION` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_checkpoint.py:207`), but reads tolerate any `v` and call `_migrate_checkpoint` before hydrating channels (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:1164`). Mirrors DB schema-migration pattern; no separate `alembic`-style tool.
- **Typed warning as version contract.** Instead of free-form `DeprecationWarning("... will be removed in v2")`, the removal version is a typed tuple argument (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/warnings.py:38-41`), enabling programmatic linting and test `match=` assertions on the rendered string.
- **Dual dispatch on `version` without content negotiation.** Streaming handlers inspect `version` and `CONFIG_KEY_STREAM_MESSAGES_V2` flag rather than negotiating via `Accept` header or capability exchange (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:2814`). Similar to `Accept-Version` header but implemented as a Python kwarg.
- **Fixture-anchored migration tests.** `SAVED_CHECKPOINTS["3"]`, `"2-start:*"`, `"2-quadratic"` embed real-world blobs with `channel_versions` as `000000...major.minor` strings (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_checkpoint_migration.py:272`). Any regression that changes `create_checkpoint` output by a single character fails snapshot comparison.
- **Shim layer for deprecated import paths.** `langgraph.constants.__getattr__` proxies `Send`/`Interrupt` to `langgraph.types` with a warning and falls back to private constants via `import_module` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/constants.py:34-59`), preserving import compatibility during the `constants` → `types` move without duplicating definitions.

## Tradeoffs

- **Pre-1.0 SDK vs 1.x core:** `langgraph-sdk 0.4.3` (`studies/agent-harness-study/sources/langgraph/libs/sdk-py/langgraph_sdk/__init__.py:6`) signals no SemVer guarantees, while `langgraph` core is `1.2.11` Production/Stable (`studies/agent-harness-study/sources/langgraph/libs/langgraph/pyproject.toml:12`). Pin `langgraph-sdk>=0.4.2,<0.5.0` tolerates patch releases but a core minor could break SDK without a major bump — consumer must monitor both changelogs.
- **Tight upper pins vs loose compatibility:** `<5.0.0` on checkpoint and `<0.5.0` on SDK avoid accidental major upgrades, but prevent automatic security fixes across majors; every checkpoint major requires a coordinated `langgraph` release just to bump the pin (`studies/agent-harness-study/sources/langgraph/libs/langgraph/pyproject.toml:21-23`).
- **Beta `DeltaChannel` performance vs stability promise:** Snapshot every 1000 updates + 5000-superstep bound (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/_internal/_config.py:14-18`, `studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/channels/delta.py:76`) cuts blob size dramatically, but the contract is explicitly-beta — early adopters trade IO savings for future replay-logic churn.
- **In-place checkpoint mutation vs copy:** `_migrate_checkpoint` mutates the loaded `Checkpoint` dict directly (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:1138`). Avoids copying large `channel_values` but means cached saver objects observed by concurrent readers could see half-migrated state if the saver returns the same dict reference (mitigated because tests use `copy_checkpoint` first: `studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_checkpoint_migration.py:1487`).
- **GitHub Releases as changelog vs in-repo file:** Saves maintenance burden but breaks offline auditability and `git log --follow CHANGELOG.md` workflows; consumer cannot `diff` compatibility notes without network access.

## Failure Modes / Edge Cases

- **Replay depth unbounded if snapshot frequency mis-tuned.** `DELTA_MAX_SUPERSTEPS_SINCE_SNAPSHOT` defaults to 5000 (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/_internal/_config.py:15`). A channel with `snapshot_frequency=1000` that receives sparse writes but many supersteps could still accumulate 5000 steps of `checkpoint_writes` before the next snapshot; `get_delta_channel_history` scan is O(history length) via `ORDER BY task_id, idx` with `exit_delta_task_id` embedding step (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_checkpoint.py:39-47`). Under Postgres, this is an indexed scan but can still be heavy for long-running threads.
- **Missing `pending_sends` field on v3/v4 checkpoints.** `_migrate_checkpoint` checks `checkpoint.get("pending_sends")` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:1138`), so a checkpoint that already migrated but retains an empty list would not re-enter the branch — safe. A checkpoint fabricated without `v` field would `KeyError` on `checkpoint["v"]`.
- **Cross-thread contamination if saver not namespace-scoped.** Delta migration tests explicitly assert `delta_and_migrated_threads_do_not_cross_contaminate` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_delta_channel_migration.py:328`). The parent-chain walk is scoped by `config["configurable"]["thread_id"]` and `checkpoint_ns`; a custom `BaseCheckpointSaver` that ignores `checkpoint_ns` would mix seeds across threads.
- **Deprecation silenced by warning filters.** Users running `python -W ignore::DeprecationWarning` or frameworks that suppress `warnings` will miss `LangGraphDeprecationWarning` (a subclass of `DeprecationWarning`) entirely; `stacklevel=2` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/constants.py:39`) still requires the caller to opt into `-W default`. No `FutureWarning` fallback is used, so silent breakage at major bump is possible.
- **Streaming version mismatch.** Calling `stream(stream_mode="messages", version="v1")` silently strips the V2 messages handler (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:2773`) — no warning is emitted, so a user expecting V2 coercion gets V1 text blocks without notice. `_reject_v3_invariant_kwargs` raises on `stream_mode`/`subgraphs` collisions for v3 (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:387`), but v1/v2 collisions are not validated.
- **Serde allowlist blocks real checkpoints.** `JsonPlusSerializer` refuses constructors not in `allowed_msgpack_modules` (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:226`). A checkpoint containing a custom `BaseChannel` subclass or private type saved before the allowlist hardened will fail to deserialize after upgrade, even though `v` migration succeeded — the checkpoint version and serde version are independent.
- **Task ID hash migration (v1→v2).** `_algo.py` switches from `_uuid5_str` to `_xxhash_str` based on `checkpoint["v"] > 1` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_algo.py:550`). A v1 checkpoint resumed after upgrade will compute different task IDs for the same logical task, potentially creating duplicate pending writes if the saver still holds v1 `task_id`s.
