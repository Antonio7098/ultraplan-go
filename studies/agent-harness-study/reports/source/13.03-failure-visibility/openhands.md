## Summary

This source is the OpenHands "Agent Canvas" frontend. Per the repo's own boundary document (`studies/agent-harness-study/sources/openhands/AGENTS.md`, "Repository Map" section), the agent loop and event production live in a sibling `software-agent-sdk` repo; this repo owns the UI, launcher scripts, packaging, and the E2E harness. Failure visibility here is therefore studied as **what this layer surfaces, relays, redacts, and records** when failures occur.

Four distinct visibility channels are implemented:

1. **Chat-stream failure events (user).** The WebSocket layer classifies incoming error events: `AgentErrorEvent`s render inline in the chat as error cards (`studies/agent-harness-study/sources/openhands/src/components/conversation-events/chat/event-message-components/error-event-message.tsx:10`), while `ConversationErrorEvent`/`ServerErrorEvent` raise a banner above the composer with structured code headers, retry/reauth recovery actions, collapse/expand of long messages, and copy-to-clipboard (`studies/agent-harness-study/sources/openhands/src/components/features/chat/error-message-banner.tsx:22-208`). Connection errors auto-clear on recovery; conversation errors (e.g., wrong API key) are sticky until explicit dismissal (`studies/agent-harness-study/sources/openhands/src/stores/error-message-store.ts:4-9`).
2. **Global API-failure toasts (user).** A central TanStack Query `QueryCache`/`MutationCache` `onError` shows toasts extracted from Axios errors, with per-query `disableToast` opt-out, a 3-second duplicate suppression window, and special-casing of cloud auth errors (`studies/agent-harness-study/sources/openhands/src/query-client-config.ts:29-77`). Opaque network/CORS failures are rewritten into actionable user guidance instead of raw browser jargon (`studies/agent-harness-study/sources/openhands/src/utils/user-facing-error.ts:81-92`).
3. **Backend/runtime health (user + operator).** Every registered backend is probed every 30 s with a 4 s timeout and quick retries; verdicts drive colored connectivity dots, a persisted failure cap that disables polling after 5 consecutive failures, and root-level recovery screens (manage-backends modal, API-key entry) (`studies/agent-harness-study/sources/openhands/src/hooks/query/use-backends-health.ts:31-40,140-186`; `studies/agent-harness-study/sources/openhands/src/root.tsx:352-372`). Version incompatibility is a first-class failure with explicit error classes carrying actual vs required versions (`studies/agent-harness-study/sources/openhands/src/api/agent-server-compatibility.ts:72-103`).
4. **Telemetry + test artifacts (developer/operator).** Consent-gated PostHog telemetry captures an `error_outcome` event with reserved dimensions (`error_source`, `error_kind`, `error_id`) while deliberately excluding raw error messages (`studies/agent-harness-study/sources/openhands/src/utils/error-handler.ts:42-44`); coarse request headers (`X-OpenHands-Client`, `X-OpenHands-Client-Version`) are specified as Datadog facets (`studies/agent-harness-study/sources/openhands/src/api/client-source.ts:6-15`). Developer failure detail is rich but redaction-disciplined: live-E2E screenshots/videos mask credential-shaped text (`studies/agent-harness-study/sources/openhands/tests/e2e/live/utils/agent-server-conversation.ts:88-102`), traces are disabled because setup sends LLM credentials (`studies/agent-harness-study/sources/openhands/playwright.live.config.ts:47`), and assertion messages deliberately omit response bodies (`studies/agent-harness-study/sources/openhands/tests/e2e/live/utils/agent-server-conversation.ts:135-138`).

**Model-facing visibility** is mostly out of this repo's boundary (the loop lives in the SDK), but the frontend does inject model-relevant service-topology information via the `<RUNTIME_SERVICES>` system-prompt suffix so the agent avoids probing dead endpoints (`studies/agent-harness-study/sources/openhands/src/api/agent-server-adapter.ts:210-222,749-785`), and failed tool observations remain visible in chat rather than being hidden.

## Rating

**7 / 10 — Clear model with tests, explicit interfaces, and operational safeguards.**

Rationale against the rubric:

- **Explicit interfaces:** A typed error-event taxonomy reaches the UI (`ServerErrorEvent.code/detail`, `AgentErrorEvent.error`, `ErrorClassification`), with type guards deciding presentation (`studies/agent-harness-study/sources/openhands/src/types/agent-server/type-guards.ts:80-89,259-262`).
- **Tests:** Unit tests pin banner behavior, store stickiness semantics, and telemetry field discipline (`studies/agent-harness-study/sources/openhands/__tests__/components/chat/error-message-banner.test.tsx:1`, `studies/agent-harness-study/sources/openhands/__tests__/stores/error-message-store.test.ts:6`, `studies/agent-harness-study/sources/openhands/__tests__/utils/error-handler.test.ts:21`); E2E specs assert degraded-stack visibility down to the exact modal shown on backend loss (`studies/agent-harness-study/sources/openhands/tests/e2e/mock-llm/backends/mock-llm-partial-stack.spec.ts:232-238`).
- **Operational safeguards:** health caps, sticky-vs-transient error lifecycle, secret redaction before display/persistence (`studies/agent-harness-study/sources/openhands/src/api/mcp-health/probe-mcp-server-health.ts:25-36`; `studies/agent-harness-study/sources/openhands/src/utils/redact-mcp-secrets.ts:15-33`), and crash-resilient containers returning 502s (`studies/agent-harness-study/sources/openhands/docker/entrypoint.sh:458-482`).
- **Why not higher:** operator monitoring is delegated to external SaaS with no in-repo dashboards or metrics endpoints beyond Helm liveness/readiness probes (`studies/agent-harness-study/sources/openhands/helm/agent-canvas/values.yaml:199-215`); one legacy status surface appears unused (see Gaps); error-detail verbosity for users is hard-coded rather than configurable; and model-side failure formatting cannot be verified within this source's isolation boundary.

## Answers to Dimension Questions

**1. Is the model informed of failures?**
Largely out of boundary: the perception/action loop and its error formatting live in the sibling `software-agent-sdk` repo, so this cannot be verified here (search boundary: full `src/`, `scripts/`, `tools/` trees). What this repo contributes: (a) it forwards SDK-produced `ObservationEvent`s with `is_error` flags unchanged into the conversation stream and keeps them visible (`studies/agent-harness-study/sources/openhands/src/types/agent-server/core/base/observation.ts:17`; `studies/agent-harness-study/sources/openhands/src/components/conversation-events/chat/event-content-helpers/should-render-event.ts:91-102`); (b) it pre-informs the model of reachable services via the `<RUNTIME_SERVICES>` system suffix, preventing a class of predictable failures (`studies/agent-harness-study/sources/openhands/src/api/agent-server-adapter.ts:210-222`); (c) the mock-LLM harness can verify exactly what reached the LLM by replaying captured `/v1/chat/completions` bodies (`studies/agent-harness-study/sources/openhands/tests/e2e/mock-llm/scripts/mock-llm-server.py` admin endpoints, consumed via `getMockLLMRequests()` in `studies/agent-harness-study/sources/openhands/tests/e2e/mock-llm/utils/mock-llm-helpers.ts`). No model-facing retry/error-text formatting logic exists in this repository — no evidence found despite searching for LLM message construction outside `MessageEvent` echo handling.

**2. Is the user informed appropriately?**
Yes, with layered detail. Inline cards for agent/tool failures; banner above the composer for conversation/server errors with code-derived headers, retry (connection) or re-auth (credential) actions, long-message collapse at 220 chars, and copy-for-support (`studies/agent-harness-study/sources/openhands/src/components/features/chat/error-message-banner.tsx:22-208`; wiring at `studies/agent-harness-study/sources/openhands/src/components/features/chat/chat-interface.tsx:583-600`). Toasts cover non-chat API failures with dedup and opt-out (`studies/agent-harness-study/sources/openhands/src/query-client-config.ts:41-77`). Raw browser jargon is replaced by actionable text for CORS/timeout (`studies/agent-harness-study/sources/openhands/src/utils/user-facing-error.ts:1-5`). Backend loss routes to recovery modals instead of broken pages (`studies/agent-harness-study/sources/openhands/src/root.tsx:127-159`).

**3. Can developers debug failures?**
Substantially. The event stream itself is inspectable (typed events with ULIDs/timestamps/codes, `studies/agent-harness-study/sources/openhands/src/types/agent-server/core/base/event.ts:10-22`). CI publishes structured PR-comment reports plus per-test screenshots, accessibility-tree `error-context.md` snapshots, and HTML reports; live runs record video for QA (`studies/agent-harness-study/sources/openhands/AGENTS.md`, "Debugging E2E Test Failures" section). Desktop boot failures keep a startup log console and append the last five service errors to the failure dialog (`studies/agent-harness-study/sources/openhands/electron/main.mjs:556-591,692-697`). Correlation across client/server is supported via promoted `error_id`s matching server-side event ids (`studies/agent-harness-study/sources/openhands/src/utils/error-handler.ts:28-40`). Limitation: raw error text is intentionally absent from telemetry, so post-hoc debugging of consented-analytics-only deployments relies on reproducing locally or on server logs outside this repo.

**4. Can operators detect failure patterns?**
Partially, via delegated SaaS. Consented PostHog captures typed `error_outcome` events with `error_source`/`error_kind`/`error_telemetry` dimensions suitable for funneling and alerting (`studies/agent-harness-study/sources/openhands/src/utils/error-handler.ts:17-48`); cloud ingress retains coarse client/version headers as Datadog facets (`studies/agent-harness-study/sources/openhands/src/api/client-source.ts:7-15`). On the deployment surface, Helm probes detect liveness/readiness regressions (`studies/agent-harness-study/sources/openhands/helm/agent-canvas/values.yaml:199-215`) and the Docker design converts backend crashes into visible 502s rather than silent death (`studies/agent-harness-study/sources/openhands/docker/entrypoint.sh:458-469`). No in-repo metrics endpoint, dashboard-as-code, or alert definitions were found (searched `helm/`, `docker/`, `config/`, `scripts/`): pattern detection depends entirely on external PostHog/Datadog tenants.

## Architectural Decisions

1. **Classify errors at the event layer, present by category.** Type guards partition the stream into inline-renderable agent errors vs banner-displayable conversation/server errors (`studies/agent-harness-study/sources/openhands/src/types/agent-server/type-guards.ts:80-89,259-262`), keeping presentation policy centralized in the websocket handler (`studies/agent-harness-study/sources/openhands/src/contexts/conversation-websocket-context.tsx:570-594`).
2. **Two-lifetime error store.** Transient connection errors self-heal on the next healthy signal; conversation errors require explicit user action — a deliberate semantic split encoded in the store contract (`studies/agent-harness-study/sources/openhands/src/stores/error-message-store.ts:4-9,62-65`).
3. **Opt-out toast pipeline.** Every query/mutation inherits global failure toasts unless `meta.disableToast` is set, letting feature hooks replace generic toasts with tailored ones (pattern documented at `studies/agent-harness-study/sources/openhands/src/hooks/mutation/use-switch-llm-profile.ts:46`).
4. **Privacy-first observability.** Telemetry carries correlation ids and classifications, never raw messages (`studies/agent-harness-study/sources/openhands/src/utils/error-handler.ts:42-44`); MCP errors are redacted against config secrets plus generic token patterns before display or persistence (`studies/agent-harness-study/sources/openhands/src/utils/redact-mcp-secrets.ts:15-33`).
5. **Failure states persist across reloads.** Backend health (failure counts, last truncated error, disabled flag) survives page refresh in localStorage with defensive validation, preventing silent re-arm of doomed polling (`studies/agent-harness-study/sources/openhands/src/api/backend-registry/health-storage.ts:24-39`).
6. **Degraded > dead infrastructure.** Both Docker (`502` for downed routes, `studies/agent-harness-study/sources/openhands/docker/entrypoint.sh:458-469`) and the frontend-only ingress mode (`503` for missing backend, asserted in `studies/agent-harness-study/sources/openhands/tests/e2e/mock-llm/backends/mock-llm-partial-stack.spec.ts:205-230`) convert partial failure into machine-readable, UI-detectable signals.
7. **Redaction discipline extends to test artifacts.** Traces off, masked screenshots, body-less assertions — developer ergonomics traded against credential leakage (`studies/agent-harness-study/sources/openhands/tests/e2e/live/utils/agent-server-conversation.ts:88-102,135-138`; `studies/agent-harness-study/sources/openhands/playwright.live.config.ts:47`).

## Notable Patterns

- **Guard-driven presentation policy**: small predicate functions (`isDisplayableErrorEvent`, `isAgentErrorEvent`) are reused by both the websocket handler and the renderer, so routing and rendering can't drift (`studies/agent-harness-study/sources/openhands/src/types/agent-server/type-guards.ts:80-262`).
- **Anti-flap health probing**: quick in-query retries with a documented rationale (one recorded outcome per logical probe; auth failures excluded as "a decided server response"), then a hard disable cap — a three-tier sensitivity design (`studies/agent-harness-study/sources/openhands/src/hooks/query/use-backends-health.ts:136-171`).
- **Suppression-until-connected**: websocket errors are ignored before the first successful connection, eliminating cold-start false alarms (`studies/agent-harness-study/sources/openhands/src/contexts/conversation-websocket-context.tsx:142-144,989-992`).
- **Cause-chain walking**: error normalization traverses `cause` chains (depth-capped, cycle-safe) before classification (`studies/agent-harness-study/sources/openhands/src/utils/user-facing-error.ts:13-45`).
- **Boot-phase breadcrumbs**: each desktop startup stage writes a headline + log line "so the log records which stage a failed boot died in" (`studies/agent-harness-study/sources/openhands/electron/main.mjs:547-554`).
- **Conservative reclassification**: MCP handshake rejections containing 401/403 markers are upgraded from `connection` to `credentials` so users get the right guidance even though the backend couldn't classify them (`studies/agent-harness-study/sources/openhands/src/api/mcp-health/probe-mcp-server-health.ts:16-23`).

## Tradeoffs

- **Sanitized telemetry vs debuggability**: dropping raw messages from `error_outcome` protects privacy but means operators must reproduce issues locally or correlate through server-side logs; the design accepts this explicitly (`studies/agent-harness-study/sources/openhands/src/utils/error-handler.ts:42-44`).
- **Sticky errors vs noise**: sticky conversation errors guarantee visibility of e.g. bad API keys, but recovery depends on the user noticing dismiss/retry affordances; there is no automatic re-validation that clears them.
- **Fixed detail budget**: chat observation content truncates at a constant `MAX_CONTENT_LENGTH` and banners collapse at 220 characters with no user preference controlling verbosity (`studies/agent-harness-study/sources/openhands/src/components/conversation-events/chat/event-content-helpers/get-observation-content.ts:146-148`; `studies/agent-harness-study/sources/openhands/src/components/features/chat/error-message-banner.tsx:22`).
- **SaaS-dependent operations**: pattern detection quality depends on PostHog consent rates; opted-out installs produce no operator-visible failure signal beyond local UI state.
- **Known-brittle prompt matching**: goal-loop re-prompts are filtered from chat by matching English prompt prefixes, acknowledged in-code as "Brittle by design" pending a persisted flag on the event (`studies/agent-harness-study/sources/openhands/src/components/conversation-events/chat/event-content-helpers/should-render-event.ts:15-26`) — a failure-visibility risk where judge feedback could leak or vanish if SDK wording changes.

## Failure Modes / Edge Cases

- **Narrow 401 window during bootstrap**: if connectivity drops between the `/server_info` and settings probes, the app loads with an unvalidated key and subsequent 401s won't trigger the auth screen; accepted in-code as narrow and recoverable by refresh (`studies/agent-harness-study/sources/openhands/src/api/agent-server-compatibility.ts:381-385`).
- **Duplicate-toast suppression can swallow distinct failures**: identical messages within the 3-second window are dropped regardless of origin (`studies/agent-harness-study/sources/openhands/src/query-client-config.ts:54-61`).
- **Health-disable blind spot**: after 5 consecutive failures, a backend stops being polled and renders disconnected until user action or a modal-triggered one-shot re-probe (`studies/agent-harness-study/sources/openhands/src/api/backend-registry/health-storage.ts:5-13`; `studies/agent-harness-study/sources/openhands/src/hooks/query/use-backends-health.ts:203-210`) — a recovered backend stays "red" until interaction by design.
- **Malformed history anchor**: an oldest event lacking a timestamp makes pagination throw and flip `hasMore` off (`studies/agent-harness-study/sources/openhands/src/hooks/use-load-older-events.ts:137,159`), surfacing via the shared error banner in `ChatInterface` rather than failing silently (contract documented in `studies/agent-harness-study/sources/openhands/AGENTS.md`, "useLoadOlderEvents" bullets).
- **Tampered localStorage health entries** are rejected range-wise so a forged `-1` counter can't defeat the disable mechanism (`studies/agent-harness-study/sources/openhands/src/api/backend-registry/health-storage.ts:27-34`).
- **Misleading MCP connection errors**: ENOENT-spawn failures surface as `MCP$TEST_ERROR_CONNECTION`, documented as misleading since no URL is involved (mitigated operationally by bundling Node in desktop builds; see `studies/agent-harness-study/sources/openhands/AGENTS.md`, Electron PATH bridging notes).
