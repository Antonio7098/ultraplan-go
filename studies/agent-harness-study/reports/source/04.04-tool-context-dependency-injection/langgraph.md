## Summary

LangGraph exposes tool context through a two-layer model: a framework-level `Runtime[ContextT]` (`libs/langgraph/langgraph/runtime.py:124-258`) injected into graph nodes and a tool-specific `ToolRuntime[ContextT, StateT]` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1750`) injected into individual tool calls. Both are explicit, typed, frozen dataclasses, populated by the Pregel runtime via `config[CONF][CONFIG_KEY_RUNTIME]` (constant at `libs/langgraph/langgraph/_internal/_constants.py:70`) and constructed per tool call (`libs/prebuilt/langgraph/prebuilt/tool_node.py:806-816`, `841-851`). Dependencies (state, store, context, stream_writer, config, tool_call_id, tools list, execution_info, server_info) are bound to the runtime once per run and cloned via `Runtime.override`/`merge` per task (`libs/langgraph/langgraph/pregel/_algo.py:688-701`, `882-892`, `1044-1055`). Tools opt in to injection via field annotations (`InjectedState`, `InjectedStore`, `ToolRuntime` — `libs/prebuilt/langgraph/prebuilt/tool_node.py:1753-1901`) — no global runtime; without a graph, the tool can be exercised by passing a mock `__pregel_runtime` in the config (`libs/prebuilt/tests/test_tool_node.py:55-81`). The system is testable end-to-end without booting a graph and has explicit defense layers against LLM-supplied injection overrides (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1422-1429`). There is no first-class permission/ACL primitive for tools in the open-source library.

## Rating

**8 / 10**

Rationale:
- **`+`** Single, fully typed `Runtime[ContextT]` dataclass carrying context, store, stream_writer, heartbeat, previous, execution_info, server_info, control (`libs/langgraph/langgraph/runtime.py:124-258`). `get_runtime()` helper resolves it from contextvars (`libs/langgraph/langgraph/config.py:17-29`).
- **`+`** Separate, but composable `ToolRuntime[ContextT, StateT]` dataclass for tools adding `state`, `config`, `tool_call_id`, `tools` list, `execution_info`, `server_info`, and `emit_output_delta()` stream helper (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1750`). Documented as distinct from `Runtime` (lines 1668-1671).
- **`+`** Explicit injection annotations: `InjectedState(field)` for state fields, `InjectedStore` for `BaseStore`, `ToolRuntime` for the full per-call context (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1753-1901`). Detection is single-pass and cached in `_get_all_injected_args` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1967-2029`).
- **`+`** Tools can be unit tested without booting a graph: a mock `__pregel_runtime` plus `ToolNode.invoke(input, config={...})` exercises the full injection path (`libs/prebuilt/tests/test_tool_node.py:55-81`); both sync and async paths covered (`libs/prebuilt/tests/test_tool_node.py:1684-1868`, `2019-2027`).
- **`+`** Context is typed differently per surface: graph nodes get `Runtime[ContextT]` (`libs/langgraph/langgraph/graph/_node.py:61-64`), tools get the broader `ToolRuntime` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1750`), and `injected_state` returns a sub-state (lines 1367-1405). State extraction supports dict, list, Pydantic, dataclass, and TypedDict via `get_type_hints` / `getattr` (lines 1389-1405).
- **`+`** Defense-in-depth against LLM-supplied injection: stripping LLM-supplied values for injected keys (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1424-1428`), system-injected values win on collision (lines 1429, 1415, 1419), validation errors filtered to LLM-controlled args only (`libs/prebuilt/langgraph/prebuilt/tool_node.py:510-563`).
- **`+`** Per-call `Config_KEY_READ` (channel reader) used to hydrate state when the input is a list of `ToolCall` dicts from `Send` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1281-1313`). Documented contract: managed values flow through `ToolRuntime.context`, not state hydration (lines 1308-1310).
- **`+`** Run-scoped cooperative draining via `RunControl` in `Runtime` (`libs/langgraph/langgraph/runtime.py:79-104`) and `heartbeat` callable for idle-timeout progress (`libs/langgraph/langgraph/runtime.py:209-217`).
- **`-`** No first-class permission/ACL primitive. The only "permission" surface is wrapper middleware (`wrap_tool_call`, `awrap_tool_call` — `libs/prebuilt/langgraph/prebuilt/tool_node.py:755-778`, `1031-1067`) and an early `ValidationNode` (deprecated — `libs/prebuilt/langgraph/prebuilt/tool_validator.py:43-47`). The `LangGraph Server` exposes a `BaseUser`/`BaseStore.auth` system in `langgraph_sdk.auth.types`, but no concrete tool-level enforcement lives in the open-source runtime.
- **`-`** Secrets are passed through `Runtime.context` (user-defined dataclass — `libs/langgraph/langgraph/runtime.py:198-201`) and through `BaseStore`. There is no framework-managed secret store, scoped redaction, or scrubbing in logs beyond `langchain_core` defaults. The example doc at `libs/langgraph/langgraph/runtime.py:154-188` demonstrates `user_id` but not secrets.
- **`-`** `Runtime` (graph nodes) and `ToolRuntime` (tools) are *separate* types with overlapping fields. A node author uses `Runtime`; a tool author uses `ToolRuntime`. The conceptual overlap is documented (`libs/langgraph/langgraph/runtime.py:138-142`) but has led to deprecations (`config_schema` → `context_schema`, `create_react_agent` → `create_agent` in `langchain.agents`) visible across `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:53-116`.
- **`-`** Tool-side access to `Runtime` is mediated through `ToolRuntime` but the `Runtime.control`, `Runtime.heartbeat`, `Runtime.previous` fields are **not** forwarded to `ToolRuntime` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1722-1730`). A tool that needs a heartbeat for long-running work would have to receive it differently. Compare with `Runtime` forwarding in `libs/prebuilt/langgraph/prebuilt/tool_node.py:806-816`.
- **`-`** Several injection paths depend on LangChain conventions (`InjectedToolArg`, `_DirectlyInjectedToolArg`, `get_all_basemodel_annotations` — `libs/prebuilt/langgraph/prebuilt/tool_node.py:76-84`, `1663`, `1981`). Tools that use a raw `Callable` (not a `BaseTool`) end up partially-injected unless the schema is rebuilt at runtime (lines 1356-1360).
- **`-`** Async dependency on `asyncio.create_task` context propagation: `get_config()` raises on Python<3.11 in async contexts (`libs/langgraph/langgraph/config.py:18-25`). Documented at `libs/langgraph/langgraph/config.py:53-57`.

Score placement: solid 8 — explicit, typed, tested, with defense-in-depth against LLM-override of injected values, and a documented override/merge mechanism (`libs/langgraph/langgraph/runtime.py:240-264`). Penalty for missing permission/secret primitives and the splitting between `Runtime` and `ToolRuntime` types.

## Answers to Dimension Questions

1. **What context does a tool receive?**
   A `ToolRuntime[ContextT, StateT]` dataclass (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1750`) carrying:
   - `state` — the current graph state (dict, list, Pydantic, dataclass, or TypedDict)
   - `context` — the per-run user context (typed `ContextT`, shared with `Runtime`)
   - `config` — `RunnableConfig` for the current call
   - `stream_writer` — `StreamWriter` for `stream_mode="custom"` writes
   - `tool_call_id` — the id of the current LLM-emitted tool call
   - `store` — `BaseStore | None` for persistent storage
   - `tools` — `list[BaseTool]` of all tools registered on the node
   - `execution_info` — `ExecutionInfo` (thread/run/checkpoint/task ids)
   - `server_info` — `ServerInfo | None` (assistant/graph id, authenticated user)
   - `emit_output_delta(delta)` — helper for partial-output streaming under `stream_mode="tools"`
   Tools that don't want the full context can opt in to narrower injection via `InjectedState`, `InjectedState("field")`, or `InjectedStore` (lines 1753-1901). For graph nodes, the equivalent is `Runtime[ContextT]` with `context`, `store`, `stream_writer`, `heartbeat`, `previous`, `execution_info`, `server_info`, `control` (`libs/langgraph/langgraph/runtime.py:124-258`).

2. **Is context explicit or global?**
   Explicit. Tools attach themselves via typed annotations (`InjectedState`, `InjectedStore`, `ToolRuntime`); nodes use a typed `runtime: Runtime[ContextT]` parameter. The framework injects `Runtime` from `config[CONF][CONFIG_KEY_RUNTIME]` (`libs/langgraph/langgraph/_internal/_runnable.py:371-398`), and `ToolNode` constructs a per-call `ToolRuntime` from that `Runtime` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:802-817`). The only "global" channel is the `get_config()` / `get_runtime()` / `get_store()` / `get_stream_writer()` helpers (`libs/langgraph/langgraph/config.py:17-29`, `32-122`, `126-195`) which read from `var_child_runnable_config` (`libs/langgraph/langgraph/_internal/_runnable.py:75`). There is no module-level global; tools run identically in production and in isolation tests.

3. **Are secrets passed safely?**
   Secrets are passed via `Runtime.context` (user-defined dataclass — `libs/langgraph/langgraph/runtime.py:198-201`) and via `BaseStore`. The framework does not provide a managed secret store, scoped redaction, or log scrubbing. The threat model documents explicit guidance: "InjectedState/InjectedStore/ToolRuntime values for tool injection" / system-injected values overwrite LLM-supplied collisions — a safe-by-construction injection boundary (`.github/THREAT_MODEL.md:207`, `libs/prebuilt/langgraph/prebuilt/tool_node.py:1422-1429`). LangChain-core filters injected params from the LLM-visible schema; pydantic `extra="ignore"` drops unknown keys; output construction only includes declared model fields — four-layer defense documented in the threat model.

4. **Can tools be unit tested?**
   Yes. `ToolNode` can be invoked directly with a mock `__pregel_runtime` in the config (`libs/prebuilt/tests/test_tool_node.py:55-81`, `libs/prebuilt/tests/test_tool_node_validation_error_filtering.py:27-38`, `libs/prebuilt/tests/test_injected_state_not_required.py:48-80`). Both sync and async paths are covered (`libs/prebuilt/tests/test_tool_node.py:1684-2016`). Tests cover all three injection types (`InjectedState`, `InjectedStore`, `ToolRuntime`), validation error filtering, optional state fields, dynamically registered tools (via `wrap_tool_call`), and security properties (LLM cannot override injected values). The runtime test (`libs/langgraph/tests/test_runtime.py:23-1220`) covers `Runtime` end-to-end including override, merge, context coercion, `RunControl`, drain, and subgraph context propagation.

5. **Can context enforce permissions?**
   Partially. The open-source `langgraph`/`prebuilt` libraries do **not** provide a first-class permission/ACL primitive. Permissions are enforced via injection ordering security (system values win — `libs/prebuilt/langgraph/prebuilt/tool_node.py:1422-1429`), the `wrap_tool_call`/`awrap_tool_call` middleware for retries/caching/short-circuiting (lines 202-283, 1031-1222), and the `langgraph_sdk.auth.types.BaseUser` surface that becomes available via `Runtime.server_info.user` when the LangGraph Server is present (`libs/langgraph/langgraph/runtime.py:70-77`, `libs/langgraph/langgraph/pregel/main.py:4321-4349`). The deprecated `ValidationNode` only validates tool-call arguments against a Pydantic schema, not roles/permissions (`libs/prebuilt/langgraph/prebuilt/tool_validator.py:43-114`). A tool author can implement per-call RBAC by reading `Runtime.server_info.user` (when available) and rejecting inside the tool body, but no framework primitive enforces it.

## Architectural Decisions

- **Two runtime types, one shared lifecycle.** `Runtime[ContextT]` for graph nodes/middleware and `ToolRuntime[ContextT, StateT]` for tools share `context`, `store`, `stream_writer`, `execution_info`, `server_info` but `ToolRuntime` adds `state`, `config`, `tool_call_id`, `tools`, and `emit_output_delta` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1750`). The split is documented at `libs/langgraph/langgraph/runtime.py:138-142`. The cost is `ToolRuntime` is not a strict subclass of `Runtime`; the benefit is each surface has only the fields it actually needs.
- **Single static `config[CONF][CONFIG_KEY_RUNTIME]` carrier.** All dependencies travel in one `Runtime` dataclass on the `RunnableConfig` (constant at `libs/langgraph/langgraph/_internal/_constants.py:70`). `RunnableCallable.invoke` reads this once per call (`libs/langgraph/langgraph/_internal/_runnable.py:371-398`). The same mechanism works for `ToolNode`: `runtime` is supplied by `RunnableCallable` to `_func`/`_afunc` and `ToolRuntime` is constructed per call (`libs/prebuilt/langgraph/prebuilt/tool_node.py:793-826`).
- **Per-call `ToolRuntime` construction inside `ToolNode`.** Tools do not share a `ToolRuntime`; each call gets its own copy at `libs/prebuilt/langgraph/prebuilt/tool_node.py:806-816` (sync) and `841-851` (async). This makes parallel tool calls independent, supports the `Send` API (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:849-858`), and lets middleware wrappers retry independently via `ToolCallRequest.override()` (lines 170-199).
- **Single-pass injection analysis with cached `_InjectedArgs`.** Tool signatures are scanned once at `ToolNode.__init__` into `_injected_args: dict[str, _InjectedArgs]` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:773-786`, `1967-2029`). Injection decisions are tree walks of `Annotated[...]` / `Union[...]` types via `get_type_hints` + `get_all_basemodel_annotations` (lines 1980-2028). Dynamically registered tools (via `wrap_tool_call`) compute on the fly (lines 1354-1360).
- **System-injected values overwrite LLM-supplied collisions.** Even if the LLM supplies a field named after an injected param, the merge `{**stripped_args, **injected_args}` strips and re-adds (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1422-1429`). Combined with four schema-level layers (LangChain `tool_call_schema` filtering, merge order, pydantic `extra="ignore"`, output construction filter), the injection boundary is documented as a hardened trust boundary (`.github/THREAT_MODEL.md:207-303`).
- **Configurable key based on `ContextVar` for `get_config()`.** `var_child_runnable_config` is set by `set_config_context` before each node call (`libs/langgraph/langgraph/_internal/_runnable.py:67-132`). This lets `get_config()`/`get_store()`/`get_stream_writer()` work inside any graph node or task without threading the config through every signature (`libs/langgraph/langgraph/config.py:17-29`).
- **State and managed values are different paths.** Graph state is injected via `InjectedState` (or `ToolRuntime.state` for the full snapshot) and reads from `config[CONF][CONFIG_KEY_READ]` when the input is a list of `ToolCall` dicts from `Send` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1281-1313`). Managed values (e.g. `IsLastStep`, `RemainingSteps`) are NOT included in the `_extract_state` output by design — they flow through `ToolRuntime.context` instead (lines 1308-1310).
- **Cooperative draining via `RunControl`.** `Runtime.control: RunControl` is a single-attribute signal that any thread can request (`libs/langgraph/langgraph/runtime.py:79-104`). Properties `drain_requested` and `drain_reason` expose it. This is the framework's only "cancellation" surface — there is no `asyncio.CancelledError`-style cancellation token passed to tools.
- **`Heartbeat` callable for idle-timeout progress.** `Runtime.heartbeat: Callable[[], None]` is a no-op by default but is the only signal honored under `TimeoutPolicy(refresh_on="heartbeat")` (`libs/langgraph/langgraph/runtime.py:209-217`). It is forwarded to `_func`/`_afunc` via `Runtime` but NOT to `ToolRuntime` — a tool that needs to heartbeat has to receive it via `ToolRuntime` forwarding, which currently does not happen (see "Tradeoffs").

## Notable Patterns

- **Annotation-driven injection with cached analysis.** `ToolNode._injected_args` is built once (`libs/prebuilt/langgraph/prebuilt/tool_node.py:773-786`, `1967-2029`) and reused per call; runtime cost is a dict lookup. Dynamic tools re-scan via `_get_all_injected_args` (lines 1356-1360).
- **Spec-extending `BaseTool` markers.** `InjectedState`, `InjectedStore`, `ToolRuntime` subclass `InjectedToolArg` / `_DirectlyInjectedToolArg` from langchain-core, so LangChain's tool-schema generator automatically hides them from the LLM-visible schema (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1753-1901`, `1663`).
- **Layered trust boundary at injection.** Strip LLM-supplied values for injected keys, then re-add trusted system values, then validate, then construct output (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1422-1453`). The threat model treats this as a hardened boundary (`.github/THREAT_MODEL.md:207-303`).
- **Per-call `ToolRuntime` for parallel tool isolation.** `tools_by_name` is shared but `ToolRuntime` is per call (`libs/prebuilt/langgraph/prebuilt/tool_node.py:802-816`). This is what makes `Send`-distributed tool calls (v2) and `wrap_tool_call`-based retry independent (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:849-858`).
- **Middleware wrapper with multi-call `execute`.** `wrap_tool_call`/`awrap_tool_call` receive `ToolCallRequest` and an `execute` callable that can be invoked multiple times for retry/caching (`libs/prebuilt/langgraph/prebuilt/tool_node.py:202-283`, `1031-1067`, `1191-1222`). The wrapper is the closest thing to a hook for cross-cutting policy on tool calls.
- **Immutable `ToolCallRequest.override()`.** Direct attribute assignment is deprecated and emits a `DeprecationWarning`; the recommended pattern is `request.override(...)` producing a new dataclass (`libs/prebuilt/langgraph/prebuilt/tool_node.py:151-199`).
- **`StreamToolCallHandler` + `ContextVar` for per-tool streaming.** `StreamToolCallHandler.on_tool_start` sets `_tool_call_writer` so `ToolRuntime.emit_output_delta` can stream partial tool output without threading the writer through the tool signature (`libs/langgraph/langgraph/pregel/_tools.py:25-86`, `libs/prebuilt/langgraph/prebuilt/tool_node.py:1732-1750`).
- **Frozen, slotted `Runtime`/`ExecutionInfo`/`ServerInfo`.** All three are `@dataclass(frozen=True, slots=True)` for cheap copying and immutability (`libs/langgraph/langgraph/runtime.py:26-77`). `Runtime.patch_execution_info` rebuilds via `dataclasses.replace` (lines 266-274).
- **`merge`/`override` for runtime composition.** `Runtime.merge(other)` aligns with `parent.merge(runtime)` at graph start (`libs/langgraph/langgraph/runtime.py:240-258`, `libs/langgraph/langgraph/pregel/main.py:2882-2897`). Subgraphs inherit context across calls via `parent_runtime.merge(runtime)`.
- **Memoization of dynamic tool injection.** Tools added via `wrap_tool_call` middleware are still supported at injection time via `_get_all_injected_args(tool)` on the fly (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1354-1360`).
- **`get_config()` deferred through `var_child_runnable_config`.** Frameworks tools can call `get_config()` without explicit threading (`libs/langgraph/langgraph/config.py:17-29`). Documented caveat: Python <3.11 in async contexts is unsupported (lines 18-25).

## Tradeoffs

- **Two runtime types add cognitive cost.** `Runtime` (nodes) and `ToolRuntime` (tools) are similar but distinct. `Runtime` carries `heartbeat`, `previous`, `control`; `ToolRuntime` does not (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1722-1730`). A tool author cannot heartbeat for idle-timeout without a workaround. The cost is tight scoping per surface; the benefit is no field confusion.
- **No first-class permission/ACL primitive.** The only enforcement layers are middleware (`wrap_tool_call`), the order-of-merge security boundary, and the deprecated `ValidationNode` schema check. A malicious tool sees whatever `Runtime.context` carries, with no framework-level role/scope model.
- **ContextVar reliance on Python ≥3.11 for async.** `get_config()` / `get_store()` / `get_stream_writer()` rely on `var_child_runnable_config` propagation, which only works through `asyncio.create_task` natively on Python ≥3.11 (`libs/langgraph/langgraph/config.py:18-25`, `53-57`). Older Python versions cannot safely use these helpers in async graph nodes.
- **Secrets are user-managed.** `Runtime.context` is a user-defined dataclass; the framework does not provide a secret store, scoped redaction, or trace scrubbing. The threat model documents the boundary, but practical secret rotation/haunting is the user's responsibility.
- **Injected `state` and `context` are different fields.** `ToolRuntime.state` is the graph state; `ToolRuntime.context` is the per-run user context. The former is mutable and serializable; the latter is intentionally opaque (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1722-1723`). Migrating data between them is the user's responsibility.
- **`LangGraph Server` features are out-of-tree in the open-source repo.** `ServerInfo.user` only populates when the Server is in front; the open-source `langgraph` library alone may leave `server_info`/`user` as `None` (`libs/langgraph/langgraph/runtime.py:230-232`, `libs/langgraph/langgraph/pregel/main.py:4321-4349`). Self-hosted deployments that don't run the server lose the auth/permission layer.
- **Deprecated `create_react_agent`/`AgentState`/`config_schema` accumulated during the 0.x → 1.0 evolution.** `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:53-116` carries deprecation warnings pointing at `langchain.agents`. The split between `langgraph` and `langchain.agents` adds a maintenance burden.
- **Middleware is the only hook for tool permission.** `wrap_tool_call`/`awrap_tool_call` is the closest thing to a "before/after each tool call" hook, but it lives inside `ToolNode` and is not a global interceptor (`libs/prebuilt/langgraph/prebuilt/tool_node.py:755-778`). Adding a new cross-cutting concern (e.g., audit logging) is a code change to `ToolNode`.

## Failure Modes / Edge Cases

- **LLM-supplied injected-field name is stripped.** Tested at `libs/prebuilt/tests/test_tool_node.py:2149-2205` — `auth: Annotated[dict, InjectedToolArg()]` and `InjectedState("auth")` are safe-by-construction. Failure mode is a missing field error, not a silent override.
- **Missing required state field raises `KeyError`/`AttributeError`.** `InjectedState("foo")` on a tool where the graph state lacks `foo` raises unless the field is `Optional` or default-typed (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1390-1405`). The `NotRequired` workaround is documented at `libs/prebuilt/tests/test_injected_state_not_required.py:1-148`.
- **Validation errors propagate filtered.** `_filter_validation_errors` removes errors for injected args; tests verify this in `libs/prebuilt/tests/test_tool_node_validation_error_filtering.py:41-262`. Failure mode is loss of error messages for system-controlled fields.
- **Injected `Store` requires `Runtime.store` to be set.** If a tool declares `InjectedStore` but the graph was compiled without a store, `ToolNode._inject_tool_args` raises `ValueError("Cannot inject store into tools...")` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1408-1414`).
- **Tool returns `None` outside a graph context.** `ToolRuntime.emit_output_delta` uses a `ContextVar`; outside `stream_mode="tools"` the var is `None` and the call is a silent no-op (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1747-1750`).
- **Async `get_config()` on Python <3.11.** `RuntimeError("Python 3.11 or later required to use this in an async context")` (`libs/langgraph/langgraph/config.py:18-25`).
- **Heartbeat not threaded to tools.** `Runtime.heartbeat` is not in `ToolRuntime`; a tool that needs to call `Runtime.heartbeat()` for `TimeoutPolicy(refresh_on="heartbeat")` has no direct path. This is a known gap documented in `Runtime` (`libs/langgraph/langgraph/runtime.py:209-217`) but not in `ToolRuntime`.
- **Parallel tool calls share `tools_by_name` but not `ToolRuntime`.** Each call gets its own `ToolRuntime` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:802-816`), but the `tools` field is `list(self.tools_by_name.values())` (lines 813, 848), so it is a snapshot at parallel-dispatch time. Mid-flight `wrap_tool_call`-introduced tools are not in this snapshot.
- **Dynamic tool via `wrap_tool_call`.** Injection analysis is recomputed for tools not registered at init (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1354-1360`). Failure mode: a tool whose signature uses `Annotated` with a custom subclass that is not on the `InjectedToolArg` hierarchy will silently not be injected.
- **`ToolCallRequest.__setattr__` deprecation.** Direct attribute assignment is deprecated and emits `DeprecationWarning` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:151-168`). Future removal will require `override()`.
- **Runtime detection via `isinstance(runtime, Runtime)`.** Multiple call sites (`libs/langgraph/langgraph/pregel/_retry.py:178`, `351, 590, 602, 704, 721`) gate behavior on `isinstance(runtime, Runtime)`. If a non-`Runtime` value is stored under `CONFIG_KEY_RUNTIME` (e.g. by a subclass), the retry/run-control layers are bypassed silently.
- **`Runtime.control` borrowed from parent.** `control or parent_runtime.control or RunControl()` falls through to a fresh `RunControl` if both are `None` (`libs/langgraph/langgraph/pregel/main.py:2887-2895`). A long-lived parent with no `RunControl` will not see drain requests.

## Future Considerations

- **Forward `Runtime.control` and `Runtime.heartbeat` to `ToolRuntime`.** A tool that needs to heartbeat for idle-timeout or honor a drain request has no direct path. Adding `control`, `heartbeat`, and `previous` to `ToolRuntime` (or a separate `ToolControl` mixin) would close the gap. The `Runtime` doc explicitly notes the gap (`libs/langgraph/langgraph/runtime.py:209-217`).
- **First-class permission surface on `ToolRuntime` or `Runtime`.** A `Runtime.permissions: PermissionSet` or `ToolRuntime.authorized_scopes: set[str]` would let middleware gate tools without ad-hoc user checks. No concrete proposal in the source.
- **Secret envelope with redaction hook.** `Runtime.context` could carry a `SecretsResolver` or `Secret` marker that the framework scrubs from logs/traces. Today there is no `redact` hook between tool result and message history.
- **Stop splitting `Runtime` and `ToolRuntime`.** Either merge via inheritance (cost: tools leak `previous`/`control`) or split into `NodeRuntime`/`ToolRuntime` interface (cost: more types). The current overlap is the worst of both worlds.
- **Stable async-context guarantee on Python <3.11.** `get_config()` raises on Python <3.11 in async contexts; a portable shim would lower the floor.
- **Move `create_react_agent`/`AgentState`/`ValidationNode` into `langchain.agents` cleanly.** The deprecation patterns in `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:53-116` and `libs/prebuilt/langgraph/prebuilt/tool_validator.py:43-47` indicate an ongoing migration; full removal would simplify the surface.
- **Document a tested `wrap_tool_call` policy pattern.** The middleware API is the only enforcement surface in the open-source library; promote the test fixtures in `libs/prebuilt/tests/test_on_tool_call.py:1-1473` to a docs page.
- **Expose `ToolRuntime` from `langgraph.runtime` as a re-export.** Today `ToolRuntime` lives in `langgraph.prebuilt` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1662`) while `Runtime` lives in `langgraph.runtime`. Tool authors searching for "tool context" find the type in two places.

## Questions / Gaps

- **`Runtime` does not carry a `logger`.** `libs/langgraph/langgraph/runtime.py:124-258` lists fields and inherits nothing logger-related. Search confirms no `logger` field. Tools and nodes fall back to LangChain's `BaseCallbackHandler` for tracing. No evidence of a planned addition.
- **No `cancel()`/`asyncio.CancelledError` propagation path to tools.** `RunControl` is the only signal and it is cooperative. A tool that never reads `Runtime.control.drain_requested` will not stop. No framework-level cancellation token.
- **No `Timeout` / `Deadline` field on `Runtime` or `ToolRuntime`.** Idle-timeout / `TimeoutPolicy` lives in the graph node layer (`libs/langgraph/langgraph/pregel/_retry.py`); no deadline is plumbed into `ToolRuntime`. No evidence of a planned change.
- **No `permissions`/`scopes`/`acl` field on either runtime.** Confirmed at `libs/langgraph/langgraph/runtime.py:124-258` and `libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1750`. The only authorization data is `ServerInfo.user` (when Server is present) and is sourced from `langgraph_sdk.auth` — not part of the open-source runtime.
- **No secret store / `SecretsResolver` / redaction hook.** Confirmed by searching `libs/langgraph/langgraph/` and `libs/prebuilt/langgraph/prebuilt/`. The closest is the SDK-level encryption framework in `libs/sdk-py/langgraph_sdk/encryption/` (out of scope for tool DI).
- **No `docs/dependencies.md` or equivalent.**

  Searched `docs/` — `docs/` exists in the source tree (`studies/agent-harness-study/sources/langgraph/docs/`) but a target dependency-injection doc was not pinpointed without reading the full docs. The behavior is documented in source docstrings (`libs/langgraph/langgraph/runtime.py:124-258`, `libs/prebuilt/langgraph/prebuilt/tool_node.py:1662-1901`). A consolidated `docs/guides/tool-context.md` would lower the barrier.
- **No `docs/testing.md` for tool-injection patterns.** Test fixtures in `libs/prebuilt/tests/test_tool_node.py:55-81` and `libs/prebuilt/tests/test_injected_state_not_required.py:48-80` are the canonical contract; promoting them would help new contributors.
- **`Runtime` vs `ToolRuntime` field divergence (`control`, `heartbeat`, `previous`).** Documented in `Runtime` (`libs/langgraph/langgraph/runtime.py:209-217`) but not in `ToolRuntime`. A future migration should reconcile.
- **`runtime` resolution path includes `get_runtime()` (via `var_child_runnable_config`) but `ToolNode` does not consume `Runtime` via that path — it reads from `config[CONF][CONFIG_KEY_RUNTIME]` via `RunnableCallable`.** As a result, `ToolNode` requires the config to be set up correctly before invocation; outside a graph, tests must seed `__pregel_runtime` manually (`libs/prebuilt/tests/test_tool_node.py:55-81`). A `ToolNode.from_runtime()` factory would close the gap.
