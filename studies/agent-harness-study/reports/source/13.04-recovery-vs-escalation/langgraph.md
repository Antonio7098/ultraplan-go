## Summary

LangGraph implements a layered recovery-vs-escalation model centered on the Pregel execution loop. **Recovery** is handled by (1) per-node retry policies with exponential backoff, configurable exception filters, and timeout watchdogs (`libs/langgraph/langgraph/pregel/_retry.py`); (2) dedicated error-handler nodes that can absorb a failed node's exception and continue the run (`libs/langgraph/langgraph/pregel/_runner.py:222-248`, `libs/langgraph/langgraph/graph/state.py:699`); and (3) durable checkpoint/resume — every superstep's state plus ERROR/INTERRUPT pending writes are persisted to the checkpointer, so a crashed or drained run can be resumed (`libs/langgraph/langgraph/pregel/_runner.py:574-613`). **Escalation** takes three forms: in-node human-in-the-loop interrupts via `interrupt()` (`libs/langgraph/langgraph/types.py:851-969`) which pause the graph and surface a value to the client; compile-time `interrupt_before`/`interrupt_after` breakpoints (`libs/langgraph/langgraph/graph/state.py:1183-1184`); and parent-graph escalation via `Command.PARENT` / `ParentCommand` for subgraphs (`libs/langgraph/langgraph/errors.py:129-133`). **Graceful stop** exists as cooperative draining (`RunControl.request_drain()`, e.g., on SIGTERM) that stops at a superstep boundary with the checkpoint saved (`libs/langgraph/langgraph/runtime.py:95-104`, `libs/langgraph/langgraph/errors.py:54-64`). Every failure and escalation decision is auditable: errors and interrupts are written to the checkpoint as pending writes retrievable via `CheckpointTuple.pending_writes` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:146`), retries are logged with full tracebacks (`libs/langgraph/langgraph/pregel/_retry.py:677-680`), and a timed-attempt observer emits structured attempt lifecycle events for server-side observability (`libs/langgraph/langgraph/pregel/_retry.py:87-125`).

## Rating

**8/10.** The retry model is explicit (`RetryPolicy`, `libs/langgraph/langgraph/types.py:418-437`), heavily tested (~60 tests in `libs/langgraph/tests/test_retry.py`), configurable at node and graph level, and composes with timeouts and error handlers in a documented precedence order (retry exhaustion → error handler → run failure, per `libs/langgraph/tests/test_retry.py:2009`). Escalation to humans is a first-class primitive (`interrupt()` + `Command(resume=...)`) with durable state. What keeps it from 9–10: there is no built-in "escalate to a human after N failed retries" policy — retry exhaustion simply raises, and human notification is entirely the client's responsibility (no notification code ships in-repo); retry auditing is `logger.info` only by default, while structured attempt events require an internal observer config key not exposed as public API; and `default_retry_on` retries *unknown* exceptions broadly (`libs/langgraph/langgraph/_internal/_retry.py:28-29`), a permissive default that can mask bugs.

## Answers to Dimension Questions

### 1. When does the system retry vs escalate?

The decision is made per-exception inside the retry wrappers. For each failed attempt, `run_with_retry`/`arun_with_retry` find the first matching policy via `_should_retry_on` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:647-655`, `:802-810`); no match, exhausted `max_attempts`, or a `GraphBubbleUp` (interrupt/drain/parent command) means raise — never retry (`:654-661`, `:632-634`). The default classifier retries transient-looking failures (connection errors, HTTP 5xx) and refuses known programming errors (ValueError, TypeError, etc.) but retries anything unrecognized (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/_internal/_retry.py:1-29`). If retries exhaust and the node has an `error_handler`, escalation continues *in-process* to the handler node rather than failing the run (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_runner.py:222-248`); only unhandled failures panic the run and cancel siblings (`:616-630`). Escalation to humans happens only where application code calls `interrupt()` — the framework itself never decides to involve a human after repeated failures.

### 2. Are escalation thresholds configurable?

Yes, extensively, though "threshold" here means retry/timeout budgets rather than human-escalation rules. `RetryPolicy(max_attempts, initial_interval, backoff_factor, max_interval, jitter, retry_on)` is fully configurable per node (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:418-437`), with graph-wide defaults overridable per node via `set_node_defaults` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/graph/state.py:272-335`). Multiple ordered policies per node are supported (first match wins, `studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:648-652`). Timeout budgets (`TimeoutPolicy.run_timeout`/`idle_timeout`/`refresh_on`) are separately configurable (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:452-514`). However, there is **no configurable policy of the form "after N failures, notify/escalate to a human"** — no such config key, callback, or middleware was found in `libs/langgraph` or `libs/prebuilt`. Human escalation thresholds must be implemented in user nodes (e.g., counting failures in state and calling `interrupt()`).

### 3. Can the system stop gracefully?

Yes, via three mechanisms. (a) Cooperative drain: `runtime.control.request_drain(reason)` stops future supersteps at the current boundary and raises `GraphDrained`; its docstring guarantees "The checkpoint is saved and the run can be resumed later" (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/errors.py:54-64`, `studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/runtime.py:95-104`, enforced at `studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/main.py:3012-3015`), with cross-thread safety tests (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_runtime.py:585-634`). (b) Interrupts pause execution durably at a superstep boundary with interrupt writes persisted (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_runner.py:585-591`). (c) The recursion limit halts runaway graphs deterministically (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_loop.py:606-609`). Note the docstring caveat that timeouts rely on cooperative asyncio cancellation — CPU-bound sync work can delay them (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:455-459`).

### 4. Are recovery decisions auditable?

Largely yes, with caveats. Durable audit: every task failure, interrupt, and cancellation is committed to the checkpointer as pending writes `(ERROR, exc)` / `(INTERRUPT, ...)` / `(ERROR_SOURCE_NODE, name)` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_runner.py:574-613`), retrievable through `CheckpointTuple.pending_writes` (`studies/agent-harness-study/sources/langgraph/libs/checkpoint/langgraph/checkpoint/base/__init__.py:146`) and surfaced in `PregelTask.error/.interrupts` snapshots (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:637-646`). In-run audit: each retry logs at INFO with the sleeping interval and full traceback (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:677-680`, `:833-836`), and attempt counts/timestamps are exposed to nodes via `Runtime.execution_info.node_attempt` (asserted in `studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_retry.py:262-264`). Structured machine-readable audit (start/progress/finish events with error type/message) exists but is gated behind the internal `CONFIG_KEY_TIMED_ATTEMPT_OBSERVER` key, documented as consumed by langgraph-server rather than public API (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:92-96`). OSS users get logs + checkpointed writes; rich metrics require the server layer.

## Architectural Decisions

1. **Retry as a wrapper around task execution, not a loop feature.** Retries live in `run_with_retry`/`arun_with_retry` around `task.proc.invoke` (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:600-683`), keeping the Pregel superstep machinery agnostic and letting subgraphs receive a `CONFIG_KEY_RESUMING=True` signal between attempts so nested runs resume rather than restart (`:681-682`).
2. **Control-flow exceptions vs failures.** A single `GraphBubbleUp` base class separates interrupts/drains/parent commands from real failures; bubble-ups bypass both retry and error-handler routing (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_runner.py:224-226`, `:299-300`), making "pause and ask" structurally distinct from "recover."
3. **Error handlers as first-class graph nodes.** Handlers are compiled into hidden nodes (`__error_handler__<node>`, `studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/graph/state.py:867-874`) scheduled by the runner upon failure (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_algo.py:1110-1154`), inheriting the same persistence model — hence they survive process death via `ERROR_SOURCE_NODE` replay (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_loop.py:751-812`).
4. **Durable-first recovery.** Rather than in-memory recovery, all state needed to recover (checkpoints + pending writes) is externalized to the checkpointer abstraction, enabling resume after crashes, drains, and interrupts across processes.
5. **Deliberate exception-taxonomy choices.** `NodeTimeoutError` avoids subclassing built-in `TimeoutError` purely so the default retry policy retries it (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/errors.py:193-194`); user-raised `CancelledError` is laundered into `NodeCancelledError` to preserve failure visibility (`:168-187`) — taxonomy serving policy.

## Notable Patterns

- **Ordered policy chain**: a node may declare multiple `RetryPolicy`s; the first whose `retry_on` matches governs backoff/give-up (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:647-652`), enabling e.g. aggressive retry for network errors and single-attempt for auth errors.
- **Write-discard on failed attempts**: clearing `task.writes` per attempt (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:613-615`) and discarding pre-timeout writes via the guarded `_TimedAttemptScope.close()` (`:492-494`) prevents partially-completed side effects from being committed.
- **Progress-based idle timeouts**: idle_timeout refreshes on stream chunks, LangChain callbacks, child-task scheduling, and explicit heartbeats, rate-limited to ~4 emissions per window (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:195-209`, `:274-312`, `:439-441`) — a liveness model tuned to LLM token streaming.
- **Escalation by command routing**: `Command(graph=Command.PARENT)` lets a subgraph delegate decisions upward with namespace rewriting (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:618-631`) — hierarchical escalation without callbacks.
- **Handled-exception identity tracking**: the runner tracks `id(exc)` in `_handled_exception_ids` so an exception absorbed by an error handler is not also re-raised via the fatal path (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_runner.py:166-169`).
- **Cache exclusion for control writes**: INTERRUPT/ERROR results never populate the task cache (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_loop.py:1872-1874`), so failures always re-execute.

## Tradeoffs

- **Permissive default retry**: `default_retry_on` returning `True` for unknown exceptions favors availability over correctness — a persistent bug will be retried `max_attempts` times before surfacing (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/_internal/_retry.py:28-29`).
- **Retry exhaustion has no built-in human fallback**: after `max_attempts`, the only options are raise, or a developer-authored error-handler node; teams wanting "page a human after 3 failures" must build it themselves (no evidence found in `libs/langgraph` or `libs/prebuilt`).
- **Observability split between OSS and server**: structured attempt telemetry is reserved for the platform via an internal config key (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:92-96`); OSS operators rely on stdlib logging.
- **Cooperative timeouts**: documented inability to preempt GIL-bound sync work (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:455-459`) — a hung sync node can stall the drain/timeout story.
- **Handler scope restrictions**: default error handlers apply only to regular nodes and cannot catch themselves (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/graph/state.py:1314-1321`, `:298-302`), so a failing handler always fails the run — simple mental model, but limits chained fallbacks.
- **HITL ergonomics moved out of repo**: `HumanInterruptConfig`/`HumanInterrupt` are deprecated shims pointing to `langchain.agents.interrupt` (`studies/agent-harness-study/sources/langgraph/libs/prebuilt/langgraph/prebuilt/interrupt.py:7-10`), splitting the escalation vocabulary across packages.

## Failure Modes / Edge Cases

- **Unhandled failure cancels siblings mid-flight**: `_should_stop_others` breaks the futures wait loop and cancels peers (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_runner.py:330-333`); cancelled tasks persist their `CancelledError` as ERROR writes so the superstep can finish (`:579-583`).
- **User-raised `CancelledError` previously vanished silently**: fixed by converting to `NodeCancelledError` when `Task.cancelling()==0`, with Python <3.11 falling back to treating it as framework cancellation (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:315-334`, `:52-56`) — version-dependent behavior.
- **Stale interrupt writes after time travel**: old INTERRUPT pending writes accumulate across forks and confuse multi-interrupt resumes; cleared explicitly when forking (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_loop.py:952-971`).
- **Watchdog double-fire race**: `FIRST_COMPLETED` can deliver both bg result and fired watchdog; code suppresses late `TimeoutError` from cancelled watchdogs (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/pregel/_retry.py:472-481`).
- **Nested `interrupt()` matching is positional**: resume values map to interrupts by call order within a task (`studies/agent-harness-study/sources/langgraph/libs/langgraph/langgraph/types.py:866-868`), fragile if node code changes between interrupt and resume.
- **Jitter makes timing nondeterministic**: enabled by default; tests disable it for assertions (`studies/agent-harness-study/sources/langgraph/libs/langgraph/tests/test_retry.py:277`).

## Future Considerations

- Add a first-class escalation hook to `RetryPolicy` (e.g., `on_exhaustion: Callable | Literal["raise","interrupt"]`) so retry exhaustion can deterministically trigger an `interrupt()` without custom error-handler boilerplate.
- Promote the timed-attempt observer (`CONFIG_KEY_TIMED_ATTEMPT_OBSERVER`) to a public API so OSS users get the same structured attempt audit as the server.
- Ship a supported human-notification/interrupt middleware in-repo (the deprecated `prebuilt/interrupt.py` shim shows this responsibility migrated to `langchain.agents.interrupt`; documenting that boundary would help harness builders).
- Expose retry events as stream modes or callback events (today `logger.info` is the only OSS-visible retry trace), easing integration with external audit pipelines.
