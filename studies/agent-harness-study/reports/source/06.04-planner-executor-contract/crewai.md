## Summary

CrewAI implements a **dual planner / isolated executor** model. The primary Plan-and-Act loop is per-Agent: `AgentReasoning` produces a typed `ReasoningPlan` → `TodoList[TodoItem]` which `AgentExecutor` (a `Flow[AgentExecutorState]`) orchestrates step-by-step via `StepExecutor` (one isolated `LLM→tool→Observation` turn per `TodoItem`). A secondary crew-level `CrewPlanner` generates `PlannerTaskPydanticOutput` text plans that are string-appended into `Task.description` before sequential task execution. The contract is Pydantic-typed (`PlanStep`, `TodoItem`, `TodoList`, `StepObservation`, `StepExecutionContext`/`StepResult`, `PlanningConfig`) with strict `FUNCTION_SCHEMA` for LLM function-calling, and is observable via `CrewaiEventBus` and `AgentExecutorState.execution_log/observations`. Feedback is closed via `PlannerObserver` (LLM or heuristic) after every step, driving continuance, lightweight refinement, early goal achievement, or bounded full replan. Cross-agent planning is absent — plans are per-agent `TodoList`s; crew-level planning is untyped string concatenation.

## Rating

**7/10 — Clear model with tests, explicit interfaces, and operational safeguards; not yet mature/durable.**

Rationale: Planner outputs and executor inputs are explicitly typed Pydantic models with dependency DAG semantics, validated by JSON schema and Pydantic, and covered by dedicated unit tests. `StepExecutionContext` is intentionally minimal/frozen, `StepResult` is audit-only, and the observer-driven feedback loop is bounded (`max_replans`, `max_step_iterations`, `step_timeout`, `reasoning_effort` tiers). Execution cannot proceed *blind* on a bad plan — dependency gating, tool-expectation checks, and observer-triggered replanning provide containment. Downgraded from 9 because: (a) two disjoint planners (typed per-agent vs string-append per-crew) create an inconsistent contract surface; (b) the LLM contract relies heavily on prompt engineering (`"READY: I am ready..."` sentinel) plus fallback parsing, with no plan-signature or versioning; (c) executor's ability to reject is implicit (exception/`StepResult.success=False`/replan) rather than an explicit `reject(reason)` API; (d) not proven under scale/chaos (no property/fuzz tests for plan corruption).

## Answers to Dimension Questions

### 1. What does the planner output?

Two disjoint planners exist:

**A. Agent-level structured planner (primary, typed).** `AgentReasoning` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:107`) produces `AgentReasoningOutput` → `ReasoningPlan` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:30`) containing:
- `plan: str` — narrative summary
- `steps: list[PlanStep]` (`lib/crewai/src/crewai/utilities/planning_types.py:14`) with `step_number:int`, `description:str`, `tool_to_use:str|None`, `depends_on:list[int]`
- `ready: bool` — self-assessed executability flag.
On `ready==True` and non-empty `steps`, `AgentExecutor.generate_plan()` (`lib/crewai/src/crewai/experimental/agent_executor.py:384`) stores `plan/plan_ready` in `AgentExecutorState` and calls `_create_todos_from_plan` (`lib/crewai/src/crewai/experimental/agent_executor.py:427`) to materialize `TodoList` of `TodoItem` (`lib/crewai/src/crewai/utilities/planning_types.py:27,45`) with `id`, `status`, `result`. This typed `TodoList` is the executable contract.

**B. Crew-level planner (secondary, untyped string).** `CrewPlanner` (`lib/crewai/src/crewai/utilities/planning_handler.py:37`) produces `PlannerTaskPydanticOutput` (`lib/crewai/src/crewai/utilities/planning_handler.py:28`) containing `list[PlanPerTask(task_number:int, task:str, plan:str)]` via a planning `Agent` + `Task(output_pydantic=PlannerTaskPydanticOutput)`. `Crew._handle_crew_planning()` (`lib/crewai/src/crewai/crew.py:1451`) concatenates `task.description += plan` per `task_number`. No `TodoItem`, no DAG.

**C. Per-step observer output.** After each `TodoItem` execution, `PlannerObserver` produces `StepObservation` (`lib/crewai/src/crewai/utilities/planning_types.py:212`) and optional `StepRefinement` (`lib/crewai/src/crewai/utilities/planning_types.py:198`) — not an initial plan but a structured replanning steering signal.

### 2. Can the executor trust it?

**No — correctly, it does not blindly trust.** The contract is typed but LLM-generated and therefore treated as untrusted advisory input, with multiple guards:

- **Pydantic + JSON-schema enforcement:** `PlanStep`, `TodoItem`, `ReasoningPlan`, `StepObservation` are `BaseModel`s; LLM calls use strict `FUNCTION_SCHEMA` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:50` with `additionalProperties:false`). Parsing tolerates missing fields with defaults (`lib/crewai/src/crewai/utilities/reasoning_handler.py:392`) and per-step `try/except`.
- **Readiness gating + retry loop:** `_refine_plan_if_needed` loops `while not ready and attempt < max_attempts` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:296`), otherwise logs warning `maximum attempts without being ready — proceeding` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:343`) — so a non-ready plan still executes (weakness).
- **Tool validation:** `StepExecutor._validate_expected_tool_usage` (`lib/crewai/src/crewai/agents/agents/step_executor.py:515`) checks that an expected `tool_to_use` was actually called; raises `ValueError` if violated but only when tool is in `available_tool_names` — pass-through otherwise.
- **Dependency gating:** `TodoList._dependencies_satisfied` (`lib/crewai/src/crewai/utilities/planning_types.py:112`) ensures only `get_ready_todos()` execute; treats `failed` as satisfied to avoid permanent deadlock (executor decides to replan/skip).
- **Stuck-state replan:** `get_ready_todos_method` detects `ready==[]` but `not is_complete` as deadlock → `needs_replan` (`lib/crewai/src/crewai/experimental/agent_executor.py:1128`).
- **Crew planner hardening:** duplicate `task_number` deduplicated (first wins, warning) (`lib/crewai/src/crewai/crew.py:1460`), missing plan warns but does not crash (`lib/crewai/src/crewai/crew.py:1474`).

Remaining trust gap: a hallucinatory but well-formed plan (wrong step numbers, nonsense `depends_on`, wrong `tool_to_use`) passes Pydantic and executes; worst consequence is wasted `max_step_iterations` per step (15) × `max_steps` (20) before observation flags `needs_full_replan`.

### 3. Can the executor modify it?

**Yes — executor modifies the pending plan through three controlled, bounded mechanisms mediated by `PlannerObserver` and `AgentExecutor`:**

- **Lightweight refinement (no new LLM planning call):** `PlannerObserver.apply_refinements` (`lib/crewai/src/crewai/agents/agents/planner_observer.py:215`) mutates `remaining_todos[i].description = refinement.new_description` in-place based on `StepObservation.suggested_refinements` (`lib/crewai/src/crewai/utilities/planning_types.py:250`). Tracked via `handle_refine_and_continue()` emitting `PlanRefinementEvent` (`lib/crewai/src/crewai/experimental/agent_executor.py:969`).
- **Full replan (bounded):** `handle_replan_now()` (`lib/crewai/src/crewai/experimental/agent_executor.py:1048`) increments `replan_count`, checks `replan_count >= max_replans (default 3)` → `all_todos_complete`, else calls `_trigger_replan(reason)` → invokes `AgentReasoning` again for remaining work, then `TodoList.replace_pending_todos(new_items)` (`lib/crewai/src/crewai/utilities/planning_types.py:185`) which preserves `completed/failed/running` and swaps only `pending`.
- **Per-step executor autonomy (multi-turn within step):** `StepExecutor._execute_native`/`_execute_text_parsed` (`lib/crewai/src/crewai/agents/agents/step_executor.py:539,328`) loop up to `max_step_iterations` (default 15) issuing multiple tool calls until LLM produces a text answer; `StepResult` returns final `result` and `tool_calls_made` for the orchestrator.
- **Early termination:** `goal_already_achieved==True` in high-effort `decide_next_action` (`lib/crewai/src/crewai/experimental/agent_executor.py:910`) routes to `handle_goal_achieved()` (`lib/crewai/src/crewai/experimental/agent_executor.py:1022`) emitting `GoalAchievedEarlyEvent` and skipping remaining todos.
- **Final synthesis:** `_synthesize_final_answer_from_todos()` (`lib/crewai/src/crewai/experimental/agent_executor.py:2481`) turns accumulated `todo.result` strings into coherent output via one LLM call (with `response_model` if set), bypassing raw concatenation.

Executor **cannot** mutate `completed`/`failed` items except via status transitions (`mark_running`/`mark_completed`/`mark_failed` emitting `PlanStepStarted/Completed`). The `TodoList` contract preserves history.

### 4. How is failure fed back?

Closed loop after **every** step (not only errors), via `PlannerObserver` → `AgentExecutor` state → routing:

1. **Step execution → `StepResult`:** `StepExecutor.execute()` (`lib/crewai/src/crewai/agents/agents/step_executor.py:127`) returns `StepResult(success, result, error, tool_calls_made, execution_time)`, with `ToolExecutionFailedError` re-raised as abort (`lib/crewai/src/crewai/agents/agents/step_executor.py:184`). `AgentExecutor.execute_todo_sequential` (`lib/crewai/src/crewai/experimental/agent_executor.py:1140`) stores `current.result = result.result` and appends to `state.execution_log` with `success/result_preview/error/tool_calls`.
2. **Observation:** `AgentExecutor.observe_step_result()` (`lib/crewai/src/crewai/experimental/agent_executor.py:681`) selects `_observe_completed_step()` — if `_should_observe_steps()==True` (medium/high, default medium) calls `PlannerObserver.observe()` (`lib/crewai/src/crewai/agents/agents/planner_observer.py:113`) with `completed_step + result + all_completed + remaining_todos` → LLM `StepObservation`; else `heuristic_observation(step_success, result)` (no LLM). Parsing handles `StepObservation` instance / JSON string / dict / fenced code (`lib/crewai/src/crewai/agents/agents/planner_observer.py:304`). Result stored `state.observations[step_number] = observation` and appended to `execution_log` as `"type":"observation"` (`lib/crewai/src/crewai/experimental/agent_executor.py:713`).
3. **Routing by `reasoning_effort`:**
   - `low` (`handle_step_observed_low`, `lib/crewai/src/crewai/experimental/agent_executor.py:747`): `heuristic` → mark success; only triggers `replan_now` when `step_completed_successfully==False && needs_full_replan==True`, else marks `failed` but `continue_plan`.
   - `medium` (`handle_step_observed_medium`, `lib/crewai/src/crewai/experimental/agent_executor.py:819`): on success → `continue_plan`; on failure only replans if `needs_full_replan==True`, else marks `failed` and continues.
   - `high` (`decide_next_action`, `lib/crewai/src/crewai/experimental/agent_executor.py:885`): evaluates `goal_already_achieved → needs_full_replan → step_completed_successfully==False → remaining_plan_still_valid && suggested_refinements → refine_and_continue` else `continue_plan`.
4. **Refine vs replan vs terminate:** `handle_refine_and_continue` applies refinements (`lib/crewai/src/crewai/experimental/agent_executor.py:969`), `handle_replan_now` enforces `max_replans` cap (`lib/crewai/src/crewai/experimental/agent_executor.py:1058`), `handle_goal_achieved` emits early achievement (`lib/crewai/src/crewai/experimental/agent_executor.py:1022`).
5. **Parallel path:** `execute_todos_parallel` (`lib/crewai/src/crewai/experimental/agent_executor.py:1257`) runs ready todos concurrently via `asyncio.gather`, then observes each sequentially, marking completed/failed per observation.
6. **Crew-level path lacks feedback:** `CrewPlanner` output is fire-and-forget string injection; no observer verifies whether `task.description += plan` actually helped.

Failure plumbing at tool layer: `detect_tool_failure` / `handle_tool_failure` / `ToolUsageErrorEvent` + `ToolUsageFinishedEvent(failure=...)` (`lib/crewai/src/crewai/experimental/agent_executor.py:78,2162`) wired into events, but `StepResult.success` originates from Python exception path, not from LLM self-report, so observer's `step_completed_successfully` is LLM judgment and may diverge from `StepResult.success`.

### 5. Is the contract typed?

**Mostly yes — the agent-level Plan-and-Act contract is strongly typed; the crew-level contract is not.**

- **Typed:** `PlanStep`, `TodoItem`, `TodoList`, `StepObservation`, `StepRefinement`, `ReasoningPlan`/`AgentReasoningOutput` are all `Pydantic BaseModel` with field validators, literal status (`TodoStatus = Literal["pending","running","completed","failed"]` at `lib/crewai/src/crewai/utilities/planning_types.py:11`), `ge` constraints (`PlanningConfig.max_steps/max_replans/max_step_iterations`). LLM I/O uses strict `FUNCTION_SCHEMA` + `response_model=StepObservation` with four-format parser and validator `coerce_single_refinement_to_list` (`lib/crewai/src/crewai/utilities/planning_types.py:259`). `StepExecutionContext`/`StepResult` are `frozen dataclass`. `AgentExecutorState` is a `BaseModel` with typed `todos:TodoList` and `observations:dict[int,StepObservation]` (`lib/crewai/src/crewai/experimental/agent_executor.py:136`).
- **Weakly typed / untyped:** `CrewPlanner` output `PlanPerTask.plan: str` is free text; its injection `task.description += plan` erases structure, making downstream executor unable to distinguish plan from original description (`lib/crewai/src/crewai/crew.py:1472`). `reasoning_handler._parse_planning_response` falls back to substring check `"READY: I am ready to execute the task."` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:596`) — a string sentinel rather than a typed enum, fragile to LLM phrasing variations. `AgentExecutor` message list (`list[LLMMessage]`) is untyped dict.
- **Partial typing loss at synthesis:** `_synthesize_final_answer_from_todos` coerces all `todo.result: str` into one LLM prompt and re-parses with optional `response_model`, but intermediate step results are always strings even when tools returned structured JSON/Pydantic.

Overall: the *contract boundary that matters* (`StepExecutor` ↔ `AgentExecutor` via `TodoItem`/`StepExecutionContext`/`StepResult`) is typed and guarded; the *prompt-level contract* (LLM producing `ReasoningPlan`/`StepObservation`) is typed on the Python side but enforced only by schema + parsing heuristics, not by guaranteeing LLM compliance.

## Architectural Decisions

- **Per-agent isolated TodoList, not shared crew plan.** Each `AgentExecutor` owns its `state.todos: TodoList` (`lib/crewai/src/crewai/experimental/agent_executor.py:155`). Crew sequentialism is at `Task` granularity (`lib/crewai/src/crewai/crew.py:1558`); steps inside a task are agent-scoped. No shared mutable plan store.
- **Dual planning stack (historical layering).** Crew-level `CrewPlanner` predates agent-level Plan-and-Act; retained for `crew.planning=True` while agent-level `PlanningConfig` is opt-in via `agent.planning_config` or `planning=True` (`lib/crewai/src/crewai/agent/core.py:429,440`). This preserves backward compatibility at cost of two contracts.
- **Isolated step execution (Plan-and-Act §3.2).** `StepExecutor` builds a fresh `messages = [system, user]` per todo (`lib/crewai/src/crewai/agents/agents/step_executor.py:244`), never mutates `AgentExecutor.messages`, and returns `StepResult` only (`lib/crewai/src/crewai/utilities/step_execution_context.py:64` notes `tool_calls_made NOT passed to subsequent steps`). Multi-turn tool loops are step-local (`lib/crewai/src/crewai/agents/agents/step_executor.py:328,539`).
- **Minimal context isolation.** `StepExecutionContext` carries only `task_description/task_goal/dependency_results` (`lib/crewai/src/crewai/utilities/step_execution_context.py:14`), preventing context window bloat and leakage of full message history between steps — but also starving executor of earlier reasoning unless dependency graph explicitly wires it.
- **Observation-as-judgment, not error detector.** `PlannerObserver` runs on *every* step (`lib/crewai/src/crewai/agents/agents/planner_observer.py:1`). Docstring stresses `This is NOT an error detector`. This lets successful steps refine future work via `StepRefinement`, at cost of an extra LLM call per step under medium/high effort.
- **Three-tier reasoning effort to trade latency vs adaptivity.** `PlanningConfig.reasoning_effort` low → heuristic, skip LLM observe + skip decide pipeline; medium → LLM observe, replan only on failure; high → full pipeline with refinement + early termination (`lib/crewai/src/crewai/agent/planning_config.py:79`, `lib/crewai/src/crewai/experimental/agent_executor.py:555,590`). Default is `medium` (`lib/crewai/src/crewai/experimental/agent_executor.py:564`) unless `planning=True` bare forces `low, max_attempts=1` (`lib/crewai/src/crewai/agent/core.py:430`).
- **Bounded adaptivity.** `max_steps=20`, `max_replans=3`, `max_step_iterations=15`, `max_attempts=None` (unbounded by default, but clamped by `low` preset). Prevents infinite planning loops at expense of potentially truncating complex tasks.

## Notable Patterns

- **Typed plan → frozen context → result → observation → refined plan cycle.** Full loop visible in `AgentExecutor`: `generate_plan` (`lib/crewai/src/crewai/experimental/agent_executor.py:384`) → `get_ready_todos_method` (`lib/crewai/src/crewai/experimental/agent_executor.py:1105`) → `execute_todo_sequential` (`lib/crewai/src/crewai/experimental/agent_executor.py:1140`) → `observe_step_result` (`lib/crewai/src/crewai/experimental/agent_executor.py:680`) → `handle_refine/replan/continue` routers.
- **DAG with satisfied-on-failure semantics.** `TodoList._dependencies_satisfied` treats `failed` as satisfied (`lib/crewai/src/crewai/utilities/planning_types.py:115`), delegated to executor to decide skip/replan. Enables parallelism (`get_ready_todos` + `can_parallelize` + `execute_todos_parallel` at `lib/crewai/src/crewai/experimental/agent_executor.py:1257`) without deadlocking on failed branches.
- **Structured refinements without second planning call.** `StepObservation.suggested_refinements: list[StepRefinement]` applied directly by `apply_refinements` (`lib/crewai/src/crewai/agents/agents/planner_observer.py:215`) — cheap, low-latency adaptation.
- **Hybrid state: Flow + BaseAgentExecutor.** `AgentExecutor` inherits `Flow[AgentExecutorState]` for router/listener orchestration while also inheriting `BaseAgentExecutor` memory mixin, bridging two execution models (`lib/crewai/src/crewai/experimental/agent_executor.py:174`).
- **Event-sourced audit trail.** Every planning decision and tool call goes through `crewai_event_bus.emit` with typed events (`AgentReasoning*`, `PlanStep*`, `StepObservation*`, `ToolUsage*`, `PlanRefinement`, `PlanReplanTriggered`, `GoalAchievedEarly`) enabling tracing without polluting `StepExecutionContext`.
- **Vision sentinel handling.** `StepExecutor._parse_vision_sentinel` + `_build_observation_message` (`lib/crewai/src/crewai/agents/agents/step_executor.py:473,486`) converts `VISION_IMAGE:<mime>:<b64>` into `image_url` content blocks — contract handles multimodal tool outputs.

## Tradeoffs

- **Isolation vs context richness.** Freezing `StepExecutionContext` to only dependency results avoids prompt pollution but forces planner to explicitly encode dependencies (`depends_on`); forgetting an edge drops useful signal (e.g., web-search result needed transitively but not declared as dependency won't appear).
- **Strict Pydantic vs LLM freedom.** `FUNCTION_SCHEMA` with `additionalProperties:false` yields reliable parsing but pressures LLMs that add explanatory text to fail; the fallback `json.loads(str(response))` plus string sentinel check is brittle and may misclassify `ready`.
- **Heuristic observe (low) vs LLM observe (medium/high).** Low skips ~1 LLM call/step, fastest but earliest detection of bad plan is delayed until `max_replans` via error results; medium/high catch semantic failures but double/triple LLM cost per step. Bare `planning=True` intentionally picks low with `max_attempts=1` to bound cost (`lib/crewai/src/crewai/agent/core.py:432`).
- **Failed-as-satisfied DAG semantics.** Unblocks parallelism and prevents permanent stall, but risks downstream steps executing on garbage results from a failed dependency unless observer flags `needs_full_replan`; the executor's decision to continue anyway under low/medium (`continue_plan` despite `step_completed_successfully==False` when `needs_full_replan==False`) can compound errors.
- **Crew string-append planning is cheap but lossy.** Injecting `plan` text into `task.description` requires zero upstream changes, but downstream `AgentReasoning` or ReAct cannot distinguish plan from task, cannot validate DAG, and `synthesize` fallback just concatenates step results if planner was purely textual.
- **Parallel todo execution simplifies scheduling** (`asyncio.gather` + sequential observation) but all parallel steps share the same pre-observation state — e.g., two parallel steps learning the same API shape cannot inform each other until after both complete; no speculative execution or mid-batch refinement.

## Failure Modes / Edge Cases

- **LLM returns well-formed but wrong plan.** Example: `depends_on=[99]` referencing non-existent step number, or circular deps. `TodoList.get_ready_todos()` will never satisfy, deadlock → detected as `ready==[] && not is_complete` → `needs_replan` (`lib/crewai/src/crewai/experimental/agent_executor.py:1124`), bounded by `max_replans=3` then `all_todos_complete` (data loss: remaining work abandoned).
- **Non-ready plan accepted anyway.** `_refine_plan_if_needed` warns but proceeds when `attempt >= max_attempts` even if `ready==False` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:342`). Executor receives `plan` but `todos==[]`, falls through `check_todos_available → no_todos` → runs non-planned ReAct path, silently discarding planner failure.
- **Ready but empty `steps`.** Text-parsed fallback (`lib/crewai/src/crewai/utilities/reasoning_handler.py:274` returns `plan, [], ready`) yields `plan_ready==True` but no `TodoItem`s — same silent fallback to ReAct; no error surfaced except log.
- **Step never calls declared `tool_to_use`.** `_validate_expected_tool_usage` raises `ValueError` which `_execute_text_parsed` / outer `execute` turns into `StepResult(success=False, error=...)` or `ToolExecutionFailedError` abort — but only if tool name matches `available_tool_names`; typo in `tool_to_use` passes silently (`lib/crewai/src/crewai/agents/agents/step_executor.py:529` returns early).
- **Observation diverges from execution truth.** `StepResult.success` vs `observation.step_completed_successfully` may disagree (LLM thinks success though tool threw, or vice versa). `low/medium` handlers gate on observer flag, not exec flag (`lib/crewai/src/crewai/experimental/agent_executor.py:769`); misprediction can mark failed steps as `completed` or conversely trigger unnecessary `replan_now`.
- **Step timeout half-applied.** `step_timeout` is wall-clock checked inside `StepExecutor` iteration loops (`lib/crewai/src/crewai/agents/agents/step_executor.py:348,558`) but not enforced at executor level; a hung tool call inside `execute_single_native_tool_call` could block past timeout. On timeout, result is `last_tool_result or "Step timed out…"` with `success=True` — misleading status.
- **Tool failure policy vs plan failure.** `detect_tool_failure`/`handle_tool_failure` (`lib/crewai/src/crewai/experimental/agent_executor.py:2166`) may `warn` vs `stopExecution` per `ToolFailurePolicy`, but `StepExecutor` catches `ToolExecutionFailedError` as abort; interaction between per-tool failure reason and todo-level `failed` vs plan-level `replan` is not explicitly tested.
- **Crew planner string pollution.** `task.description += plan` mutates the shared `Task` object; on retry/replay the appended text accumulates unless `task._original_description` checkpoint restore trims it (`lib/crewai/src/crewai/crew.py:523`). Between that guard and the comment `Do NOT mutate task.description — it's a shared object` in `generate_plan` (`lib/crewai/src/crewai/experimental/agent_executor.py:419`), ownership is confused — crew path mutates, agent path explicitly avoids.
- **Parallel exception mapping fragility.** `execute_todos_parallel` zips `ready` with `gathered` using `strict=True` (`lib/crewai/src/crewai/experimental/agent_executor.py:1297`) but `return_exceptions=True` allows `BaseException` sentinels; any non-conforming gather result shape would mis-align todo↔result, marking wrong todo as failed.

## Future Considerations

- Unify planners: deprecate crew-level string injection and route `PlannerTaskPydanticOutput` through the same `ReasoningPlan→TodoList` path with task-scoped `TodoList` partitioning; preserves typed contract and lets crew tasks carry step DAGs natively.
- Make plan rejection an explicit first-class operation (`TodoValidationError` / `executor.reject_plan(reason, diagnostics)`), instead of conflating with generic exception/`success=False`. Add `plan_signature`/`version` and `plan_ref` foreign key from `StepResult` for traceability.
- Replace `"READY: …"` sentinel with `ready:bool` in schema only — remove string matching (`lib/crewai/src/crewai/utilities/reasoning_handler.py:596`) and enforce `supports_function_calling()` gate; add property tests for plan parser round-trip.
- Add per-step budget: include `step_timeout` inside the atomic tool call with cancellation (thread interruption or async timeout), and return `StepResult(success=False, reason="timeout")` correctly rather than `success=True` with timeout message.
- For cross-agent plans, introduce a crew-level `CrewPlan { tasks: list[TaskPlan{agent_role, todos:TodoList}] }` with merge semantics and delegation edges, so manager-agent routing can participate in planning, not just execution.
- Strengthen testing: add fuzz tests for malformed `PlanStep` (`depends_on` out-of-range, dupe step numbers, non-existent `tool_to_use`), determinism tests asserting `get_ready_todos` order stability, and integration tests for deadlock→replan and `max_replans` exhaustion.
