## Summary

Agent Framework has **no single planner→executor contract**; it exposes three disjoint contracts for different subsystems, none of which is versioned, observable as a lifecycle event stream, or shared across subsystems.

1. **Harness / Todo contract (LLM-as-planner, Agent-as-executor).** The LLM plans by calling `todos_add`/`todos_remove`/`todos_complete` tools; the executable plan is `list[TodoItem]` (`id/title/description/is_complete`) persisted in `TodoSessionStore` or `TodoFileStore` (`python/packages/core/agent_framework/_harness/_todo.py:51-95`). Execution is driven by `AgentLoopMiddleware` looping while `todos_remaining(provider)` is true (`python/packages/core/agent_framework/_harness/_loop.py:925-973`) or `background_tasks_running()`. The loop re-invokes the same Agent; there is no separate planner output artifact validated before execution.

2. **Workflow DAG contract (developer-as-planner, Pregel engine-as-executor).** The developer builds a typed DAG via `WorkflowBuilder` + `Executor` + `Edge` (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:53-85`, `python/packages/core/agent_framework/_workflows/_executor.py:31-170`). Planner output is the immutable `Workflow` object (edge_groups + executors + start_executor + output designation). Executor inputs are strongly typed handler signatures (`@handler` with `WorkflowContext[OutT,W_OutT]` generics, `python/packages/core/agent_framework/_workflows/_workflow_context.py:217-489`). Contract validation is structural at `build()` time via `WorkflowGraphValidator` (`python/packages/core/agent_framework/_workflows/_validation.py:101-163`).

3. **Magentic contract (LLM-manager-as-planner, group-chat-as-executor).** `StandardMagenticManager.plan()` produces `_MagenticTaskLedger{facts: Message, plan: Message}` from prompts `ORCHESTRATOR_TASK_LEDGER_FACTS_PROMPT`/`ORCHESTRATOR_TASK_LEDGER_PLAN_PROMPT` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:107-167,272-286,621-641`), and `create_progress_ledger()` produces `MagenticProgressLedger` JSON with five `MagenticProgressLedgerItem{reason,answer}` fields (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:290-334,699-733`). `MagenticOrchestrator` executes by routing `next_speaker`/`instruction_or_question` to participant agents; stall detection (`is_in_loop`/`is_progress_being_made`) triggers `replan()` which replaces the ledger and emits `REPLANNED` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:642-685,787-811,996-1030`).

Trust is asymmetric: workflow validation is strict (type-compatibility, connectivity, output designation), but harness and Magentic plans are untrusted LLM free-text verified only for JSON shape, not semantic correctness. Executor can reject structurally invalid plans at build/runtime but cannot reject semantically bad LLM plans except via heuristics (max_iterations, stall_count, judge).

## Rating

**5/10 — Present but inconsistent, weakly documented and fragile for safety**

Rationale: Three contracts exist with explicit interfaces and some validation/tests, but no unified typed `Plan` schema, no versioned revision history, and no safe-failure guarantee for bad LLM plans. Workflow DAG has mature validation (`WorkflowValidationError` + type-compatibility + execution lock per executor) and would score 7-8 alone, but the dominant LLM-planned path (Todo) validates only structural fields (`TodoItem.from_dict` checks `id:int/title:str`) and trusts model tool calls implicitly (`approval_mode="never_require"`). Executor cannot semantically reject a bad todo list; it blindly loops until `todos_remaining` is false or `max_iterations` fires. Feedback loops exist (progress log, judge `JudgeVerdict`, Magentic `reason` fields) but are best-effort prose, not typed well-formedness checks. Cross-agent planning is confined to Magentic and not exposed as a general contract. A bad planner can silently produce divergent or empty plans that execute to completion without safeguard, hence execution is not safe under bad plans.

## Answers to Dimension Questions

### 1. What does the planner output?

Three distinct outputs, each bound to a subsystem:

* **Todo (LLM) planner** → append-only `list[TodoItem]` per session (`python/packages/core/agent_framework/_harness/_todo.py:51-96`). No `Plan` object; the plan is the mutable todo store snapshot `{"items":[...],"next_id":N}` (`python/packages/core/agent_framework/_harness/_todo.py:245-285`) plus an optional human-readable markdown plan file written via `FileMemoryProvider` in plan mode (`python/packages/core/agent_framework/_harness/_mode.py:52-53`). Titles/descriptions are free-form strings produced by the model.
* **Workflow (developer) planner** → immutable `Workflow` DAG (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:727-882`): `dict[str,Executor]` + `list[EdgeGroup]` + `start_executor` + `output_from`/`intermediate_output_from` designation. `Executor` handlers declare `input_types/output_types/workflow_output_types` via `WorkflowContext[OutT,W_OutT]` generics (`python/packages/core/agent_framework/_workflows/_executor.py:438-478`, `python/packages/core/agent_framework/_workflows/_workflow_context.py:217-350`).
* **Magentic (LLM manager) planner** → `_MagenticTaskLedger{facts: Message, plan: Message}` bullet-point plan plus `MagenticProgressLedger` routing instruction (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:272-334,621-641`). Plan is free-text, not typed subtasks.

No single `Plan` type spans subsystems.

### 2. Can the executor trust it?

**No—trust is weak and uneven.** The executor validates only shape, not semantics, and trust differs by path:

* **Todo:** Executor (the loop) trusts planner implicitly. `TodoProvider` tools are `approval_mode="never_require"` (`python/packages/core/agent_framework/_harness/_todo.py:505`), so any LLM tool call mutates the plan without gating. `TodoItem.from_dict` validates only `id:int/title:non-empty str/description?:str/is_complete:bool` (`python/packages/core/agent_framework/_harness/_todo.py:83-95`); it does not validate that the plan covers the request, has no duplicates, or is ordered correctly. A hallucinated todo list (wrong tasks, missing steps) passes validation and is executed.
* **Workflow:** Executor can trust structure because `WorkflowBuilder.build()` calls `WorkflowGraphValidator.validate_workflow` (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:844-851`, `python/packages/core/agent_framework/_workflows/_validation.py:101-163`) checking edge duplication, handler output annotations, type compatibility via `is_type_compatible` (`python/packages/core/agent_framework/_workflows/_validation.py:211-284`), and graph connectivity. Remaining executors unreachable from start, isolated nodes, or self-loops are flagged. However semantic correctness (plausibility of graph for task) is not checked.
* **Magentic:** Executor (orchestrator) validates only JSON shape of `MagenticProgressLedger` via `MagenticProgressLedger.from_dict` with coercion of non-str/bool `answer` to `""` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:302-304`); a malformed ledger can still produce a plausible `next_speaker`/`instruction` that mis-routes.

Result: execution proceeds unsafely if planner is bad—the harness has no semantic plan verifier.

### 3. Can the executor modify it?

**Yes for two paths, no for one:**

* **Todo – fully mutable by executor (and planner, since they are same LLM):** `todos_add` appends, `todos_complete` flips `is_complete`, `todos_remove` deletes (`python/packages/core/agent_framework/_harness/_todo.py:506-576`). Modifications are immediate tool calls serialized by per-session `asyncio.Lock` in `WeakKeyDictionary` (`python/packages/core/agent_framework/_harness/_todo.py:485-491`) and clamped via `_safe_next_id` (`python/packages/core/agent_framework/_harness/_todo.py:223-225`). The generic `AgentLoopMiddleware` could also mutate via custom `next_message` injectors, but the canonical `todos_remaining` path is tool-driven. `todos_complete` requires a `reason` string but that reason is not persisted on the `TodoItem` (`python/packages/core/agent_framework/_harness/_todo.py:544-561`), so modification is not auditable from state.
* **Workflow – immutable:** After `WorkflowBuilder.build()`, the `Workflow` graph is immutable; executor cannot add/remove executors or edges mid-run. Mutation requires rebuilding a new `Workflow` instance and restarting. `WorkflowCheckpoint` (`python/packages/core/agent_framework/_workflows/_checkpoint.py`) snapshots execution state, not plan edits.
* **Magentic – replannable only via manager:** `MagenticContext.reset()` clears history, `StandardMagenticManager.replan()` replaces `self.task_ledger` with a new LLM-generated ledger (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:654-685`), triggered by stall detection (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1120`) or human `MagenticPlanReviewResponse` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:996-1030`). Executors (participant agents) themselves do not edit the plan; only the manager does.

### 4. How is failure fed back?

* **Harness loop – progress log + judge + max_iterations:** `AgentLoopMiddleware._record_progress` captures `last_result.text` or custom `record_feedback` into `progress: list[str]` (`python/packages/core/agent_framework/_harness/_loop.py:731-745`), injects it via `_render_progress` into next iteration (`python/packages/core/agent_framework/_harness/_loop.py:798-843`). `should_continue` may return `(bool, feedback:str)` surfaced as `feedback` kwarg to `next_message/record_feedback` (`python/packages/core/agent_framework/_harness/_loop.py:747-764`). `JudgeVerdict` structured output (`answered:bool, reasoning:str`) is the typed failure signal; fallback text markers `VERDICT: DONE/MORE` are parsed if structured output fails (`python/packages/core/agent_framework/_harness/_loop.py:104-116,188-199`). `max_iterations` (default 10, judge 5) is the only hard failure bound (`python/packages/core/agent_framework/_harness/_loop.py:122-127,755-758`). Approval requests escape the loop via `_has_pending_approval_request` (`python/packages/core/agent_framework/_harness/_loop.py:442-459`). No dedicated plan-failure type; failures are prose in `progress`.
* **Workflow – executor_failed events:** `Executor.execute` emits `WorkflowEvent.executor_invoked` then `WorkflowEvent.executor_failed(WorkflowErrorDetails.from_exception(exc))` and re-raises (`python/packages/core/agent_framework/_workflows/_executor.py:303-313`). The runner surfaces failures as workflow error events; `WorkflowConvergenceException` / `WorkflowRunnerException` propagate to caller. No automatic feedback to planner—caller must handle.
* **Magentic – progress ledger reason + stall count + REPLANNED:** `MagenticProgressLedger` items each carry `reason` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:290-315`) used to explain `is_in_loop/is_progress_being_made/is_request_satisfied`. `_run_inner_loop_helper` increments `stall_count` on `is_in_loop` or `!is_progress_being_made`, triggers `_reset_and_replan` when `stall_count > max_stall_count` (default 3) (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1120`), and emits `MagenticOrchestratorEventType.REPLANNED` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:786-800,996-1030`). Human plan review injects `MagenticPlanReviewRequest` with `task_ledger` and `current_progress` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:835-860,1049-1070`).

In all cases failure feedback is best-effort text or counts, not a typed `PlanExecutionError{step,expected,actual}`.

### 5. Is the contract typed?

**Partially typed—strong for workflow, weak for LLM plans:**

* **Workflow:** Strongly typed. Handlers must declare `WorkflowContext[OutT,W_OutT]` (`python/packages/core/agent_framework/_workflows/_workflow_context.py:125-209`); `handler` decorator introspects signatures or uses explicit `input/output/workflow_output` params (`python/packages/core/agent_framework/_workflows/_executor.py:575-738`). `WorkflowGraphValidator._validate_edge_type_compatibility` checks `is_type_compatible` per edge (`python/packages/core/agent_framework/_workflows/_validation.py:211-284`); missing annotations warn but skip validation. `WorkflowBuilder` also validates output designation executors have `workflow_output_types` (`python/packages/core/agent_framework/_workflows/_validation.py:361-396`). This is the only durable typed contract.
* **Todo:** Minimally typed. `TodoItem`/`TodoInput`/`TodoCompleteInput` have typed dataclass + `from_dict` validators (`python/packages/core/agent_framework/_harness/_todo.py:51-177`), and tool schemas use `TypedDict` (`python/packages/core/agent_framework/_harness/_todo.py:179-191`), but plan semantics are untyped free-text titles. No `PlanStatus` enum, no `depends_on`, no priority—just `is_complete: bool`.
* **Magentic:** Pseudo-typed. `_MagenticTaskLedger` and `MagenticProgressLedger` implement `DictConvertible` with `to_dict/from_dict` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:272-334`) but the plan content is a `Message` bullet list string, not a structured subtask list. `MagenticProgressLedgerItem.answer` is `str|bool` with lenient coercion (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:292-304`).

Overall: typed where developer defines the graph, untyped where LLM invents the plan.

## Architectural Decisions

| Decision | Evidence | Consequence |
|----------|----------|-------------|
| **Flat todo list as de-facto plan** – no `Plan` class, just `TodoItem{id,title,description,is_complete}` | `python/packages/core/agent_framework/_harness/_todo.py:51-96` | Simple tool surface, LLM-friendly, but no dependency graph, no priority, no blocking state; executor cannot reason about ordering. |
| **Tool-based plan mutation with no approval** – `approval_mode="never_require"` on all todo tools | `python/packages/core/agent_framework/_harness/_todo.py:505,529,563,578,586` | Low friction, but executor trusts any planner edit; bad plan tool calls are not拦截able without middleware. |

## Notable Patterns

- **Weak-typed LLM plan + strong-typed developer graph duality** — todo path optimizes for LLM ergonomics (free-text), workflow path optimizes for developer safety (generics). No adapter converts one to the other (`python/packages/core/agent_framework/_harness/_todo.py:51-96` vs `python/packages/core/agent_framework/_workflows/_executor.py:438-478`).
- **Reason-gated completion with lost justification** — `TodoCompleteInput(reason)` is validated non-empty (`python/packages/core/agent_framework/_harness/_todo.py:152-157`) but not persisted on `TodoItem`; audit query "why was item 3 completed?" requires scraping transcript, not state.
- **Judge as external verifier** — `with_judge(judge_client, criteria)` builds `JudgeVerdict` predicate internally (`python/packages/core/agent_framework/_harness/_loop.py:349-415`), forwarding original messages verbatim and feeding `reasoning` back as `feedback`. Security notice warns of exfiltration/prompt-injection via untrusted judge (`python/packages/core/agent_framework/_harness/_loop.py:373-385`).
- **Stall-counter replanning** — Magentic decrements `stall_count` on progress, increments on `is_in_loop||!is_progress_being_made`, replans at `stall_count>max_stall_count` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1120`), emitting `REPLANNED` workflow event.
- **Per-executor serialization lock** — `Executor._get_execution_lock()` lazily bound to running loop, serialized per superstep dispatch (`python/packages/core/agent_framework/_workflows/_executor.py:211-245`), matching `TodoProvider`'s per-session lock pattern.
- **Output designation contract** — `output_from/intermediate_output_from` with literals `"all"`/`"all_other"` resolved at build (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:637-693`) and validated (`python/packages/core/agent_framework/_workflows/_validation.py:361-396`), controlling which `yield_output` surfaces as caller-visible events.
- **Approval escape hatch** — both `AgentLoopMiddleware` and `LoopAgent` check `type=="function_approval_request"` and break loop to surface HITL (`python/packages/core/agent_framework/_harness/_loop.py:442-459`), ensuring planner tool calls that need approval do not silently execute.

## Tradeoffs

- **Flexibility vs. safety:** Free-form todo titles allow any decomposition but prevent machine validation of coverage; workflow generics enforce safety but require developer to pre-declare graph.
- **Trust vs. autonomy:** `approval_mode="never_require"` on todos (`python/packages/core/agent_framework/_harness/_todo.py:505`) gives planner full autonomy to mutate plan, but executor cannot interpose validation. Switching to approval-gated todos would restore trust at cost of autonomy and streaming complexity.
- **Atomicity vs. history:** `TodoFileStore._save_state_sync` atomic `os.replace` (`python/packages/core/agent_framework/_harness/_todo.py:432-443`) prevents corruption but overwrites prior plan revision, losing provenance needed to detect planner drift.
- **Session persistence vs. cross-session durability:** `TodoSessionStore` is ephemeral to `AgentSession.state`; `TodoFileStore` is opt-in file-backed. Neither provides retention policy or schema migration; `_safe_next_id` clamping (`python/packages/core/agent_framework/_harness/_todo.py:223-225`) is the only migration-like guard.
- **Magentic quality vs. applicability:** Best-in-class replanning with `max_stall_count/max_reset_count` bounds and human review gate, but not reused by harness; single-agent path relies on prompt compliance ("adjust your todos accordingly" `python/packages/core/agent_framework/_harness/_todo.py:35-40`).
- **Explicit mode switch vs. implicit intent:** Requiring `mode_set` tool or `set_agent_mode` (`python/packages/core/agent_framework/_harness/_mode.py:154-194`) makes planner state explicit but creates anchoring problem requiring user-message notification injection (`python/packages/core/agent_framework/_harness/_mode.py:283-325`).
- **One planner, one executor (harness) vs. many executors (Magentic):** Harness loop has 1:1 planner/executor (same LLM), so feedback is self-referential; Magentic has 1 manager : N participants with typed progress ledger routing, enabling genuine cross-agent delegation at cost of prompt complexity.

## Failure Modes / Edge Cases

- **Silent plan divergence:** Harness instructions to update todos on topic change (`python/packages/core/agent_framework/_harness/_todo.py:35-40`) are unenforced. Agent can add tasks without removing obsolete ones; `todos_remaining` loops on stale items or shows phantom open work. No framework validator compares executed tool calls to todo titles.
- **Empty or vacuous plan:** `todos_add` validates `todos: list[_TodoAddItemSchema]` non-empty (`python/packages/core/agent_framework/_harness/_todo.py:508-509`) but does not validate that titles are meaningful. Planner can output `[{"title":"..."}]` or skip `todos_add` entirely for complex tasks (instruction says "If simple, don't add a todo"), executor then runs with no plan and immediately satisfies `todos_remaining==False`.
- **Lost reason context:** `todos_complete` reason consumed but not stored (`python/packages/core/agent_framework/_harness/_todo.py:544-561`); post-hoc "why was plan item 7 completed?" unanswerable from state, must scrape transcript.
- **Collision after corrupted next_id:** Mitigated by `_safe_next_id` clamping (`python/packages/core/agent_framework/_harness/_todo.py:223-225`, test `python/packages/core/tests/core/test_harness_todo.py:180-197`) but file corruption still throws `ValueError` on load (`python/packages/core/agent_framework/_harness/_todo.py:406-417`) with no repair path—subsequent tool calls all fail.
- **Path traversal / state poisoning:** `TodoFileStore._path_segment` rejects `/`/`\` and Windows reserved stems (`python/packages/core/agent_framework/_harness/_todo.py:364-372`); `TodoSessionStore` trusts `session.state[source_id]` is dict, raising `ValueError` mid-tool-call on malformed state (`python/packages/core/agent_framework/_harness/_todo.py:256-259`), aborting planning turn.
- **Stall oscillation:** Magentic decrements `stall_count` on progress (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1118`) but caps at 0; flapping between progress/no-progress can prevent reaching `max_stall_count` and delay replanning indefinitely. Conversely, transient `is_in_loop` false positive triggers premature reset+LLM replan (costly, clears `chat_history` via `MagenticContext.reset()` `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:385-393`).
- **Progress ledger parse failure:** `_run_inner_loop_helper` catches any exception from `create_progress_ledger` and triggers `_reset_and_replan` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1083-1085`); persistent model inability to emit valid JSON causes infinite reset loop bounded only by `max_reset_count` (default `None`=unlimited).
- **Workflow type bypass via missing annotations:** If source or target has no output/input types, validation warns and skips (`python/packages/core/agent_framework/_workflows/_validation.py:240-252`), allowing incompatible edges to pass build and fail only at runtime `RuntimeError` (`python/packages/core/agent_framework/_workflows/_executor.py:499-520`).
- **Fresh-context discard:** `AgentLoopMiddleware(fresh_context=True)` snapshots session before loop and restores baseline before each iteration (`python/packages/core/agent_framework/_harness/_loop.py:436-437,582-586`), discarding in-loop file-memory plan writes and todo mutations except the progress log—can silently drop a plan revision.
- **Cross-subsystem drift:** Workflow `State` and harness `AgentSession.state` (todos) are independent stores; `WorkflowCheckpoint` restores workflow state but not harness todos (`python/packages/core/agent_framework/_workflows/_checkpoint.py:1-80` vs `python/packages/core/agent_framework/_harness/_todo.py:245-285`), so plan resurrection is partial.
- **No backpressure from executor:** `todos_remaining` predicate only checks `any(not is_complete)` (`python/packages/core/agent_framework/_harness/_loop.py:959-973`); it does not surface executor resource exhaustion, tool failure rate, or budget, so planner can keep adding todos while executor is failing.

## Future Considerations

- Introduce a unified `Plan`/`PlanStep` schema (e.g., `Plan{id, revision, steps:[{id,title,depends_on,status,owner}]}`) shared by todo and workflow, with `depends_on` edges and `TodoStatus{pending,in_progress,blocked,completed,abandoned}` instead of `is_complete:bool`, and versioned `PlanStore` with append-only JSONL keyed by `previous_checkpoint_id` (pattern already used by `WorkflowCheckpoint`).
- Persist `TodoCompleteInput.reason` on `TodoItem` as `completion_reason` and retain removed items as tombstones (`removed_at/removed_reason`) to enable "why did plan change?" queries; emit `WorkflowEvent(type="todo_updated")` on each mutation for observability.
- Promote Magentic's `MagenticProgressLedger` stall detection to a shared harness utility: provide default `should_continue = drift_detector(llm_client, todos)` so single-agent loops get automatic stuck detection without per-caller predicate.
- Add `PlanValidator` hook executed before each `AgentLoopMiddleware` iteration (compare remaining todos to recent tool calls/observations, flag orphaned or contradicted items) and gate executor with `validate_plan(plan)->ValidationResult` before loop continues; allow executor to reject via `WorkflowValidationError`-like typed error rather than looping forever.
- Wire `WorkflowCheckpoint` and `AgentSession.state` todo plan into a single checkpoint envelope so `run(checkpoint_id=...)` restores both executor state and plan revision atomically.
- Gate todo mutations behind `ToolApprovalMiddleware` for high-risk plans (`FileAccessProvider` already uses approval; todos should optionally) and require explicit `approve_plan` step when transitioning `plan→execute` mode, making the mode change an observable contract boundary.
- Enforce `output_from/intermediate_output_from` designation as executor trust boundary at runtime: `WorkflowContext.yield_output` already classifies via `classify_yielded_output` (`python/packages/core/agent_framework/_workflows/_workflow_context.py:374-380`); extend to drop or quarantine undeclared outputs rather than silently hiding.
