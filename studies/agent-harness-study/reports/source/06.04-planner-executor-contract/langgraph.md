## Summary

LangGraph has no LLM "planner" that hallucinates a plan JSON; the planner is the deterministic Pregel superstep scheduler. `prepare_next_tasks` / `prepare_single_task` (`libs/langgraph/langgraph/pregel/_algo.py:349-762`) plans strictly from channel versions and `trigger_to_nodes` maps; `PregelLoop.tick()` (`libs/langgraph/langgraph/pregel/_loop.py:599-629`) is the plan phase; `PregelLoop.after_tick()` (`libs/langgraph/langgraph/pregel/_loop.py:683-726`) and `PregelRunner.tick/atick` (`libs/langgraph/langgraph/pregel/_runner.py:176-573`) execute. The contract is a set of strongly-typed Python objects (`PregelExecutableTask`, `Send`, `Command`, `PregelTaskWrites`) exchanged via typed dataclasses/NamedTuples rather than a serialized schema. Validation exists at compile-time (`validate_graph`) and at execution (channel existence, reserved-name checks, `Send.node` existence), but runtime writes to unknown channels are silently warned-and-dropped, not hard-rejected. Feedback is durable and bidirectional via checkpointer `pending_writes` (`ERROR`, `INTERRUPT`, `RESUME`, `TASKS`), retry/timeout policies, and interrupt-resume `Command` loops.

## Rating

**7 / 10** — Clear model with tests, explicit interfaces, and operational safeguards.

Rationale: Planner outputs (`PregelExecutableTask`, `Send`, `Command`) are typed (`libs/langgraph/langgraph/types.py:637-784`) with static validators (`libs/langgraph/langgraph/pregel/_validate.py:13-107`). Executor inputs are the same types plus `ChannelWrite`/`ChannelRead` contracts (`libs/langgraph/langgraph/pregel/_write.py:46-192`, `libs/langgraph/langgraph/pregel/_read.py:25-92`). Validation is present but inconsistent — compile-time graph validation is strict, run-time plan validation degrades to warnings (`libs/langgraph/langgraph/pregel/_algo.py:310-313`, `libs/langgraph/langgraph/pregel/_algo.py:972-979`). Executor can reject/modify plans only through narrow mechanisms (filter unknown channels, route to `node_error_handler`, cancel siblings on `GraphBubbleUp`). Feedback loops are rich (checkpointer, retry, interrupt) but encoded as implicit `PendingWrite` tuples, not a versioned contract. Cross-agent planning (subgraphs, `Command.PARENT`, distributed `Send`) is implemented and typed but relies on string namespace conventions (`NS_SEP`, `NS_END`) rather than a schema-validated RPC.

## Answers to Dimension Questions

**1. What does the planner output?**
Deterministically, the planner `prepare_next_tasks` (`libs/langgraph/langgraph/pregel/_algo.py:392-513`) outputs `dict[str, PregelTask] | dict[str, PregelExecutableTask]` keyed by task id. For `for_execution=False` it emits lightweight `PregelTask(id,name,path)` (`libs/langgraph/langgraph/types.py:637-646`); for `for_execution=True` it emits `PregelExecutableTask` full executables (`libs/langgraph/langgraph/types.py:666-681`) containing `input` (channel values via `_proc_input` `libs/langgraph/langgraph/pregel/_algo.py:1348-1392`), `proc` (`Runnable`), `writes:deque[tuple[str,Any]]` (initially empty, mutated by node), `config` (with `CONFIG_KEY_SEND=writes.extend`, `CONFIG_KEY_READ=local_read`, `CONFIG_KEY_SCRATCHPAD`, `CONFIG_KEY_RUNTIME`), `triggers`, `retry_policy`, `cache_key`, `writers`, `subgraphs`, `timeout`. Higher-level planner signals are `Send(node,arg,timeout)` (`libs/langgraph/langgraph/types.py:704-792`) enqueued on the `TASKS: Topic[Send]` channel (`libs/langgraph/langgraph/pregel/main.py:809`), and `Command(update,resume,goto)` (`libs/langgraph/langgraph/types.py:798-848`) mapped to writes via `map_command` (`libs/langgraph/langgraph/pregel/_loop.py:903-931`). No free-form JSON plan; outputs are typed objects.

**2. Can the executor trust it?**
Partially. Graph-structure trust is enforced at compile: `validate_graph` rejects reserved names, missing channels, orphan input channels (`libs/langgraph/langgraph/pregel/_validate.py:23-107`) and `Pregel.validate()` calls `validate_timeout_supported` (`libs/langgraph/langgraph/pregel/main.py:933-948`). Per-superstep trust is weak: `apply_writes` at `libs/langgraph/langgraph/pregel/_algo.py:310-313` logs and drops writes to unknown channels; `prepare_push_task_send` at `libs/langgraph/langgraph/pregel/_algo.py:972-979` logs and drops `Send` to unknown nodes or invalid packet types without raising. Node return values flow through `ChannelWrite._assemble_writes` (`libs/langgraph/langgraph/pregel/_write.py:172-192`) where `InvalidUpdateError` is raised only for `TASKS`-channel writes or `PASSTHROUGH` leaks. So an erroneous planner (e.g., stale `trigger_to_nodes`, corrupted checkpoint `channel_versions`) would not be caught before execution — executor would silently skip tasks or drop writes, violating fail-closed. `tests/test_pregel.py:5510+` exercises bad plans (empty commands) showing `EmptyInputError` only for `Command` with no writes, not for silent drops.

**3. Can the executor modify it?**
Yes, but via narrow, structured mutations. `PregelExecutableTask.writes` is a mutable `deque` shared via `CONFIG_KEY_SEND=writes.extend` (`libs/langgraph/langgraph/pregel/_algo.py:722-735`): nodes call `ChannelWrite.do_write` which invokes `write(_assemble_writes(...))` into that deque (`libs/langgraph/langgraph/pregel/_write.py:106-126`). `PregelLoop.put_writes` can deduplicate `WRITES_IDX_MAP` specials and filter `UntrackedValue`/`DeltaChannel` (`libs/langgraph/langgraph/pregel/_loop.py:415-454`). `PregelRunner.commit` appends error markers (`ERROR`, `ERROR_SOURCE_NODE`, `INTERRUPT`, `NO_WRITES`) to `task.writes` (`libs/langgraph/langgraph/pregel/_runner.py:574-613`). `accept_push` can inject newly spawned `PUSH` tasks mid-step via `prepare_single_task((PUSH, task.path,...))` (`libs/langgraph/langgraph/pregel/_loop.py:550-587`). `_call`/`_acall` schedule functional `Call` tasks similarly (`libs/langgraph/langgraph/pregel/_runner.py:700-786`). Executor cannot rewrite the planner's `triggers`/`channels` routing without going through the next `tick`; modification is limited to enriching writes and spawning dependent tasks.

**4. How is failure fed back?**
Four interlocking loops:
- **Persisted pending writes**: `put_writes` → `checkpointer_put_writes` → `checkpoint_pending_writes: list[PendingWrite]` (`libs/langgraph/langgraph/pregel/_loop.py:456-505`). On `tick` re-entry, `_reapply_writes_to_succeeded_nodes` and `_resume_error_handlers_if_applicable` (`libs/langgraph/langgraph/pregel/_loop.py:736-816`) replay successes and route `ERROR_SOURCE_NODE` to handlers.
- **Retry/timeout**: `run_with_retry`/`arun_with_retry` clear `task.writes`, invoke `task.proc`, catch `Exception`, match `RetryPolicy.retry_on` (`libs/langgraph/langgraph/pregel/_retry.py:841-853`), backoff with jitter, signal `CONFIG_KEY_RESUMING:True` for subgraphs. Timeout via `TimeoutPolicy` uses `_TimedAttemptScope` (`libs/langgraph/langgraph/pregel/_retry.py:128-247`) — `run_timeout`/`idle_timeout` kills with `NodeTimeoutError` (`libs/langgraph/langgraph/errors.py:190-241`).
- **Interrupts/resume**: `interrupt(value)` raises `GraphInterrupt((Interrupt,))` (`libs/langgraph/langgraph/types.py:851-974`); `PregelRunner.commit` persists `(INTERRUPT, [Interrupt])` (`libs/langgraph/langgraph/pregel/_runner.py:585-591`); `_first` in loop (`libs/langgraph/langgraph/pregel/_loop.py:848-1079`) handles `Command(resume=...)` via `map_command` and `CONFIG_KEY_RESUME_MAP`/`RESUME` writes; `_pending_interrupts` tracks hang (`libs/langgraph/langgraph/pregel/_loop.py:818-846`).
- **Panic/stop**: `_should_stop_others` cancels siblings on non-`GraphBubbleUp` failure (`libs/langgraph/langgraph/pregel/_runner.py:616-634`); `_panic_or_proceed` re-raises first non-handled exception or combined `GraphInterrupt` (`libs/langgraph/langgraph/pregel/_runner.py:650-697`); error handlers suppressed via `_handled_exception_ids` and `SKIP_RERAISE_SET`.

**5. Is the contract typed?**
Yes — fully statically typed with runtime coercion, but no external JSON schema. Core types: `Send`, `Command[N]`, `PregelTask`, `PregelExecutableTask`, `CacheKey`, `RetryPolicy`, `TimeoutPolicy`, `StateSnapshot`, `PregelNode` (`libs/langgraph/langgraph/types.py:418-847`, `libs/langgraph/langgraph/pregel/_read.py:97-250`). Channels carry `UpdateType`/`ValueType` generics via `get_input_schema`/`get_output_schema` producing Pydantic models (`libs/langgraph/langgraph/pregel/main.py:1014-1061`). `validate_keys` (`libs/langgraph/langgraph/pregel/_validate.py:110-120`) and `coerce_timeout_policy` (`libs/langgraph/langgraph/_internal/_timeout.py`) enforce types at construction. However `PendingWrite = tuple[str,str,Any]` and `WritesProtocol.writes: Sequence[tuple[str,Any]]` (`libs/langgraph/langgraph/pregel/_algo.py:93-108`) erase channel value types at the persistence boundary — the strongest typing is at the in-memory `PregelExecutableTask` layer, not at the durability/checkpoint layer.

## Architectural Decisions

- **BSP superstep separation (Plan → Execution → Update)** — `PregelLoop.tick` prepares `tasks`, `PregelRunner.tick` runs them, `PregelLoop.after_tick` calls `apply_writes` and `_put_checkpoint`. This isolates inconsistent channel views and makes execution idempotent for replay (`libs/langgraph/langgraph/pregel/_loop.py:599-726`).
- **Channel-version-driven planning vs. LLM intent** — Planner compares `channel_versions` vs `versions_seen` (`libs/langgraph/langgraph/pregel/_algo.py:1260-1277`) and `trigger_to_nodes` inverted index (`libs/langgraph/langgraph/pregel/main.py:947`), not semantic goals. Keeps planning deterministic and testable.
- **Deque-backed write capture via config injection** — `CONFIG_KEY_SEND` points to `writes.extend` (`libs/langgraph/langgraph/pregel/_algo.py:724`), deque thread-safety assumed, `ChannelWrite.do_write` writes directly into task's deque. Avoids return-value plumbing but couples executor to shared mutable state.
- **Checkpointer as feedback bus** — `pending_writes` is the single source of truth for in-flight plans, errors, interrupts, and `TASKS:Topic[Send]` queue (`libs/langgraph/langgraph/pregel/_loop.py:526-549`, `libs/langgraph/langgraph/pregel/_algo.py:443-467`). Enables persistence, time-travel, and distributed delegation.
- **Per-node retry/timeout/error-handler policies** — `PregelNode.retry_policy/cache_policy/timeout/error_handler_node` (`libs/langgraph/langgraph/pregel/_read.py:122-149`, `libs/langgraph/langgraph/graph/state.py:867-924`) plus graph-level defaults (`libs/langgraph/langgraph/pregel/main.py:743-746`) and `set_node_defaults` (`libs/langgraph/langgraph/graph/state.py:272-335`) allow heterogeneous reliability without global orchestration.

## Notable Patterns

- **Producer-consumer via `Topic[Send]` channel**: `Send` objects are ordinary channel values on `TASKS` (`libs/langgraph/langgraph/pregel/main.py:809`, `libs/langgraph/langgraph/pregel/_algo.py:442-466`), scheduled as `PUSH` tasks next superstep (`libs/langgraph/langgraph/pregel/_algo.py:938-1005`), enabling dynamic fan-out (map-reduce) visible in `chat_agent_executor.py:848-859` where `should_continue` returns `list[Send]`.
- **Error-handler as first-class task**: `prepare_node_error_handler_task` (`libs/langgraph/langgraph/pregel/_algo.py:1110-1248`) creates a `PUSH` task with `CONFIG_KEY_NODE_ERROR:NodeError`, routed only if `task.name in node_error_handler_map` (`libs/langgraph/langgraph/pregel/_runner.py:171-174`), with resume-time rehydration (`libs/langgraph/langgraph/pregel/_loop.py:751-816`).
- **Functional `Call` API with handler Task**: `Call` (`libs/langgraph/langgraph/pregel/_algo.py:120-152`) + `prepare_push_task_functional` (`libs/langgraph/langgraph/pregel/_algo.py:800-935`) + `_call/_acall` (`libs/langgraph/langgraph/pregel/_runner.py:700-941`) implements a separate planner for `entrypoint`/`task` style, reusing same executor but bypassing channel triggers.
- **Namespace-encoded task identity for deterministic replay**: `task_id = _xxhash_str(checkpoint_id_bytes, checkpoint_ns, step, name, PULL/PUSH, triggers)` (`libs/langgraph/langgraph/pregel/_algo.py:616-623`) plus `task_path` tuples and `task_path_str` (`libs/langgraph/langgraph/pregel/_algo.py:1412-1420`) guarantee stable IDs across restarts; `delta_channels_with_overwrite` + `counters_since_delta_snapshot` handle `DeltaChannel` idempotence.

## Tradeoffs

- **Silent degradation vs. fail-fast**: Dropping unknown channel writes (`libs/langgraph/langgraph/pregel/_algo.py:311-313`) and invalid `Send` (`libs/langgraph/langgraph/pregel/_algo.py:972-979`) keeps supersteps from crashing on stale checkpoints but masks planner bugs; a typed schema validation (e.g., `Pydantic` for `Send`) would catch errors earlier at cost of flexibility for dynamic tools.
- **Mutable writes deque vs. immutable plan**: Sharing `deque` via config enables nodes to `write` imperatively (`libs/langgraph/langgraph/pregel/_write.py:125-126`) and tools via `Command`/`Send` (`libs/langgraph/langgraph/pregel/_retry.py:618-630`) without returning, but introduces data-race surface (`threading.Lock` only in `_TimedAttemptScope`, not in deque itself) and makes plan immutability unverifiable.
- **Inversion of control through config dict**: Executor policies are threaded via `RunnableConfig[CONF][CONFIG_KEY_*]` string keys (`libs/langgraph/langgraph/_internal/_constants.py` referenced throughout `_loop.py`, `_retry.py`), which is extensible but stringly-typed and discoverable only via grep, not IDE completion.
- **Two planning paths (channel-pull vs. Send-push vs. functional Call)**: Maximizes expressiveness (StateGraph edges, `add_conditional_edges`, `Send` fan-out, `call()` future), but triples contract surface; `validate_graph` only validates channel-pull path, not `Send` node existence until runtime.
- **Compile-time strict, runtime lenient**: `validate_graph` is strict (`libs/langgraph/langgraph/pregel/_validate.py:23-60` raises), runtime `apply_writes`/`prepare_push_task_send` are lenient (warns). Favors availability during long-running threaded graphs (e.g., `create_react_agent` v2) at expense of debuggability.

## Failure Modes / Edge Cases

- **Bad plan with unknown `Send.node`**: `prepare_push_task_send` checks `packet.node not in processes` → `logger.warning` and `return None` (`libs/langgraph/langgraph/pregel/_algo.py:977-978`). No exception; fan-out silently shrinks, downstream `add_messages` reducer waits forever or recursion limit fires (`GraphRecursionError` `libs/langgraph/langgraph/errors.py:68-85`).
- **Bad plan writes to non-existent channel**: `apply_writes` groups but `if chan in channels: pending_writes else logger.warning … ignoring` (`libs/langgraph/langgraph/pregel/_algo.py:308-313`). Node believed write succeeded; checkpoint diverges from expectation; next superstep's `prepare_next_tasks` won't trigger dependent nodes (`trigger_to_nodes` missing entry).
- **Concurrent `Overwrite` on `BinaryOperatorAggregate`**: `apply_writes` doc warns `Overwrite` duplicates in one superstep raise `InvalidUpdateError` downstream (`libs/langgraph/langgraph/types.py:977-1018`, `_algo.py:316-323`). No planner deduplication; requires user to serialize via conditional edge.
- **Interrupts without resume map mismatch**: `_pending_interrupts` (`libs/langgraph/langgraph/pregel/_loop.py:818-846`) + `_first` resume handling (`libs/langgraph/langgraph/pregel/_loop.py:914-919`) raises `RuntimeError` if multiple interrupts pending and `resume` is not a `dict[interrupt_id, value]` (`libs/langgraph/langgraph/pregel/_loop.py:916-917`).
- **Timeout vs. retry interaction**: Sync nodes with timeout fail at compile (`validate_timeout_supported`) but functional `Call` with timeout on sync bypasses until `_call_with_options` raises `sync_timeout_unsupported` (`libs/langgraph/langgraph/pregel/_call.py:285-287`). `idle_timeout` refresh only on `refresh_on="auto"`; CPU-bound `time.sleep` blocks event loop and timeout fires late (`libs/langgraph/langgraph/types.py:455-460` doc note).
- **Checkpoint namespace injection for `Command.PARENT`**: `_checkpoint_ns_for_parent_command` (`libs/langgraph/langgraph/pregel/_retry.py:544-571`) drops numeric segments; an adversarially crafted `checkpoint_ns` with numeric node name (e.g., `"123"`) would be mis-stripped, misrouting `Command.PARENT` writes.
- **Tool validation errors swallowed as content**: `ToolNode._execute_tool_sync` catches `ToolInvocationError` and, if `handle_tool_errors=True`, returns `ToolMessage(status="error")` (`libs/prebuilt/langgraph/prebuilt/tool_node.py:956-1012`), so executor never sees the failure; planner's next LLM call receives error text as normal message — planner must self-correct without explicit failure signal.

## Future Considerations

- **Versioned, schema-validated `PendingWrite`/`Send` contract**: Replace `tuple[str,Any]` with typed `BaseModel` and `TypeAdapter` validation at `put_writes`/`apply_writes` boundaries to turn warn-and-drop into typed rejection with `InvalidUpdateError` and structured telemetry.
- **Fail-closed planner option**: Add `strict: bool` flag to `Pregel(checkpointer=...)` that promotes `logger.warning` on unknown channels/`Send.node` to `InvalidUpdateError`, useful for testing and for LLM-generated plans where silent drops are unacceptable.
- **Formalize planner ↔ executor interface as Protocol**: Extract `PlannerProtocol.prepare(config, checkpoint) -> Mapping[str,PregelExecutableTask]` and `ExecutorProtocol.execute(tasks) -> Writes` from current concrete `prepare_next_tasks`/`PregelRunner`, enabling pluggable LLM planners and alternative executors (e.g., distributed `RemotePregel` `libs/langgraph/langgraph/pregel/remote.py`) without duplicating config-key plumbing.
- **Explicit `Plan` artifact for observability**: Emit a per-superstep `Plan` struct (`step, checkpoint_id, tasks:[{name, triggers, input_schema, plan_rationale}]`) via `map_debug_tasks` (`libs/langgraph/langgraph/pregel/_loop.py:581`) to LangSmith callbacks, so bad plans are inspectable post-hoc, not just inferred from `ChannelVersions`.
- **Typed `Command` routing validation at compile**: Statically check `Command(goto=...)` return annotations (`Literal["node"]` extraction in `StateGraph.add_node` `libs/langgraph/langgraph/graph/state.py:812-858`) against actual `nodes` set and `path_map`, and surface in `get_graph` visualization to prevent cross-agent goto errors before runtime.

## Questions / Gaps

- **Planner trust boundary for external input**: `map_input`/`map_command` parsing in `_loop.py:_first` (`libs/langgraph/langgraph/pregel/_loop.py:848-930`) accepts `Any` input; no schema validation against `InputType` beyond `get_input_schema` model generation — unclear if LLM-provided `Command.update` could inject arbitrary channel keys without error.
- **Distributed executor contract**: `RemotePregel` (`libs/langgraph/langgraph/pregel/remote.py`) and `TaskNotFound` (`libs/langgraph/langgraph/errors.py:142-144`) suggest distributed task fetching, but no evidence of plan serialization format or executor rejection over RPC in this source snapshot.
- **Cache key determinism**: `CacheKey(ns,key,ttl)` (`libs/langgraph/langgraph/types.py:654-663`) uses `default_cache_key` hashing (`libs/langgraph/langgraph/_internal/_cache.py` not inspected); behavior under planner change (e.g., added conditional edge) may produce cache collisions — no test evidence for this edge case in searched tests.
- **No evidence of plan modification by executor beyond writes**: Planner tasks' `triggers`/`channels` are immutable; executor cannot reorder or cancel planned tasks except via sibling cancellation on failure (`_should_stop_others`). No test shows executor re-planning within a superstep.
- **Cross-agent planning provenance**: `PregelNode.subgraphs` detection via `find_subgraph_pregel` (`libs/langgraph/langgraph/pregel/_read.py:190-195`) and namespace `NS_SEP`/`NS_END` string manipulation is implementation-defined; no typed `SubgraphPlan` evidence — how a planner chooses which subgraph to `Send` to is left to user conditional edge, not framework policy.
