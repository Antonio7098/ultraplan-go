## Executive Summary

The headline answer splits cleanly along trust boundaries. **No** for temporal: no tenant-triggered fetch exists, and the one class of caller-supplied URLs (completion callbacks) is validated against a per-namespace allowlist whose zero value rejects everything external (`chasm/lib/callback/config.go:71-114`). **Not by default** for agent-framework's sandboxed tiers: Docker runs get `--network none` unless deliberately overridden and Python rejects `--network` smuggled through extra args (`python/packages/tools/agent_framework_tools/shell/_docker.py:68-73,80-100`), while Hyperlight sandboxes have no outbound access until domains are allow-listed (`dotnet/src/Microsoft.Agents.AI.Hyperlight/Internal/SandboxExecutor.cs:214-217`). **Yes, by default** for opa: an unconfigured instance running a malicious policy can fetch any host because the shipped `capabilities.json` omits `allow_net`, and omission means "any host allowed" (`v1/ast/capabilities.go:94-100`). **Yes, unresolved here** for openhands: nothing in the repository restricts agent egress at all — no NetworkPolicy exists in the chart, the browser tool ships enabled (`src/api/agent-server-adapter.ts:114-118`), and enforcement is explicitly delegated upstream.

Beneath that split, the convergent findings are strong. All four sources govern network egress with **allowlists rather than deny-lists**, minimize process spawning to **zero or one statically-configured argv-array call site**, perform cleanup as **ordered choreography with deadlines and escalation** rather than ad-hoc finalizers, bound resource consumption **before parsing/work begins** (byte caps, size prechecks, timeouts), and are unusually **honest about which of their layers are not actually walls**. The divergences track product shape: agent-framework pays enormous complexity for real isolation tiers because its input is adversarial; opa buys auditability by deleting filesystem/process capabilities from its language entirely but then ships availability-first defaults; temporal protects a trusted process with config surfaces and quotas instead of OS containment; openhands demonstrates the delegation pattern — solid hygiene on the surfaces it owns, silence on the ones it doesn't.

## Core Thesis

Filesystem/network/process controls converge on a small set of mechanisms regardless of stack, and the maturity differentiator is almost never mechanism choice — it is **defaults and consistency**. Every source has some form of egress allowlist; they differ on whether the unset state denies (temporal callbacks, agent-framework Hyperlight domains) or permits (opa's omitted `allow_net`, openhands' default-enabled browser tool). Every source that spawns processes does so through narrow, timed, argv-array sites; they differ on whether the ambient tier (local shell, raw bash passthrough) admits that fact or hides behind a regex filter. And cleanup rigor splits by resource kind in every source: process teardown is choreographed and deadline-bounded everywhere, while **data/workspace cleanup is systematically weaker** — openhands' automation workspaces are created but never reaped (`docker/entrypoint.sh:53,317-319`), temporal's filestore archiver has no delete path at all (`common/archiver/filestore/history_archiver.go`), opa persists bundles with `os.ModePerm` unlike its own disk store's `0700` (`internal/bundle/utils.go:129`; `v1/storage/disk/config.go:46`), and agent-framework documents container-leak paths when both kill and rm-f fail (`python/packages/tools/agent_framework_tools/shell/_docker.py:561-574`). A system's true containment posture is therefore read from three places: the value of the empty configuration, the label on the weak tier, and the fate of the artifacts left behind.

## Approach Models

### Tiered isolation portfolio (agent-framework)

Model-generated code is declared untrusted (ADR-0024: `docs/decisions/0024-codeact-integration.md:24`), and the framework offers five execution tiers with escalating containment: local shell gated by human approval; Docker shell with restrictive-by-default flags (`--cap-drop ALL`, `--network none`, non-root UID 65534, read-only rootfs, 512 MiB / 256-pids caps: `dotnet/src/Microsoft.Agents.AI.Tools.Shell/DockerShellExecutor.cs:360-418`); a LocalCodeAct child process with AST allow-listing explicitly labeled "NOT a sandbox" (`dotnet/src/Microsoft.Agents.AI.LocalCodeAct/LocalCodeActProvider.cs:26-29`); a Hyperlight microVM restored from a clean snapshot per invocation with in-sandbox domain allow-lists (`dotnet/src/Microsoft.Agents.AI.Hyperlight/Internal/SandboxExecutor.cs:130-135,214-217`); and Monty, a Rust interpreter where OS calls resume as `PermissionError` (`python/packages/monty/agent_framework_monty/_monty_bridge.py:262-268`). The division of labor is architectural: *backend provides isolation, framework provides capabilities* — mounts, approvals, and allow-list plumbing span all tiers through one vocabulary (`docs/decisions/0024-codeact-integration.md:24,40`).

### Deny-by-construction language surface (opa)

Rather than gating dangerous operations behind flags, Rego simply never defined filesystem or process builtins — the complete builtin inventory ships in `capabilities.json` (206 builtins, none touching files or processes), and the compiler rejects any function outside the configured capability set (`v1/ast/compile.go:1014-1027`). Network egress is the one deliberate hole, and it is gated synchronously: `Capabilities.AllowNet` is checked at request construction, again on every redirect hop, and covers `http.send`, DNS lookups, and remote schema fetches (`v1/topdown/http.go:402-423,646-650`; `v1/net.go:20-30` → `v1/topdown/net.go:20-30`; `v1/ast/compile.go:990-1003`). The OPA process itself, by contrast, reads and writes plain OS paths with no sandbox layer — containment is delegated to deployment context.

### Operator trust boundary + single enforcement plane (temporal)

Temporal assumes trusted deployment and spends its effort on two things. First, all inbound controls compose into one explicitly ordered gRPC interceptor chain — error masking, authZ, namespace validation, concurrent-limit, three rate-limit families — with the ordering rationale documented in place (`service/frontend/fx.go:286-315`). Second, the sensitive egress class (caller-supplied callback URLs) is **default-deny**: `AddressMatchRules{}` means no rules means every external URL fails validation, https required unless explicitly permitted (`chasm/lib/callback/config.go:74,104-113,141-168`), validated at attach time with count/length/header bounds (`chasm/lib/callback/validator.go:40-84`). Process spawning is reduced to exactly one production site — the DB password resolver — using an argv array, a 30s timeout, and a `WaitDelay` pipe cap, deliberately lint-flagged and commented (`common/config/persistence.go:284-297,301-322`).

### Delegation with local guardrails (openhands)

The repository map assigns agent/tool/sandbox behavior to an upstream SDK; this source therefore invests only in what it owns: non-root container identity (UID 10001, `helm/agent-canvas/values.yaml:169-178`; `docker/Dockerfile:157`), an ingress proxy serving only registered prefixes with startup-fail on misconfiguration (`scripts/static-server.mjs:111-124,194-206`), generated-at-boot credentials persisted `chmod 600` (`docker/entrypoint.sh:178-208`), and client-side upload sanitization with regression-tested traversal rejection (`src/api/workspace-upload-path.ts:15-56`; `__tests__/api/workspace-upload-path.test.ts:94-110`). Shell execution is a raw passthrough to the upstream runtime with a 30s timeout and zero inspection (`src/api/runtime-service/agent-server-runtime-service.ts:25-56`). The model is coherent, but it means every hard guarantee about the agent's actual power lives outside the audited boundary.

## Pattern Catalog

### P1. Egress allowlists with encoded empty-set semantics

- **Problem:** Caller- or code-initiated outbound requests are the primary SSRF/exfiltration channel; deny-lists cannot enumerate the internet.
- **Demonstrated by:** All four. Temporal's `callback.allowedAddresses` zero value rejects all external URLs while always permitting pinned `temporal://system` internal targets (`chasm/lib/callback/config.go:74,91-93`). Agent-framework's Hyperlight exposes `AllowedDomain(target, methods)` CRUD with method scoping, serialized as `network_enabled: bool(allowed_domains)` — network off until configured (`dotnet/src/Microsoft.Agents.AI.Hyperlight/AllowedDomain.cs:8-31`; `python/packages/hyperlight/agent_framework_hyperlight/_execute_code_tool.py:1291-1297`). opa encodes duality in data: `allow_net` omitted = any host, `[]` = no host, pinned by tests (`v1/ast/capabilities.go:96-98`; `v1/topdown/jsonschema_test.go:545-550`). Agent-framework's Docker tier enforces the coarsest version: `--network none` default plus a construction-time blocklist rejecting `--network`/`-v`/`--privileged` spliced through extra args (`python/packages/tools/agent_framework_tools/shell/_docker.py:68-100`).
- **Why it works:** Allowlists convert an unbounded threat space into an enumerable configuration artifact; encoding the empty/unset case explicitly and testing it prevents the classic "unset means allow everything" accident — though see opa, where the shipped default *is* the permissive pole of that duality.
- **Copy when:** Any egress your system initiates on behalf of less-trusted parties (model code, policies, tenants).
- **Overkill/risky when:** Applied hostname-only to infrastructure that needs port/CIDR precision (opa grants an allowed host to *every* gated builtin, `v1/ast/capabilities.go:94-100`), or when the allowlist is checked at one lifecycle moment only (see P6's counterexample).

### P2. Process spawning as exceptional, reviewed event

- **Problem:** Arbitrary subprocess execution is the highest-consequence primitive an agent surface can expose.
- **Demonstrated by:** opa contains zero production `exec.Command` sites — matches were build tooling only (`build/bench-comment/main.go:128,145,161`). Temporal has exactly one: `ResolvePassword`, argv-array form, mutually exclusive with static passwords, context timeout, `WaitDelay=5s` against hung pipes, explanatory comments and a deliberate `//nolint:gosec` (`common/config/persistence.go:284-297,301-322,311`). Agent-framework narrows spawning inside sandboxes (Monty denies OS functions outright; LocalCodeAct AST-blocks `subprocess`/`multiprocessing`) while making the local-shell tier's permissiveness its explicit design, gated by mandatory approval that refuses construction without `requireApproval` or `acknowledgeUnsafe: true` (`dotnet/src/Microsoft.Agents.AI.Tools.Shell/LocalShellExecutor.cs:43-50,339-373`).
- **Why it works:** Concentrating exec into few, loudly-marked sites keeps the audit surface small enough to review by hand, and pairing each site with timeout + pipe-wait bounds forecloses the hang-forever startup failure.
- **Copy when:** Always, for the service's own process needs. For agent-requested commands, copy agent-framework's honesty: name the human approval loop as the boundary rather than shipping regex theater (P5).
- **Contrast:** openhands shows the unmanaged version — a raw string passthrough to `/api/bash/execute_bash_command` with no filtering (`src/api/runtime-service/agent-server-runtime-service.ts:25-56`), acceptable only because filtering is claimed upstream.

### P3. Cleanup as staged choreography with deadlines and escalation

- **Problem:** Teardown that trusts a single graceful path leaks children, connections, and containers under failure.
- **Demonstrated by:** All four implement ordered chains. Agent-framework kills process trees two-phase (SIGTERM→SIGKILL via psutil with stdlib fallback; Windows `taskkill.exe` resolved to absolute System32 path against PATH poisoning) then force-removes containers with retry and explicit leak logging, including a `docker kill` → `docker rm -f` fallback specifically because `--rm` reapers fail (`python/packages/tools/agent_framework_tools/shell/_killtree.py:36-96`; `_docker.py:520-574,635-676`). opa's shutdown runs signal → wait period → graceful server → telemetry exporters → `storage.Closer` → plugins under a manager-wide deadline (`v1/runtime/runtime.go:1032-1071`; `v1/plugins/plugins.go:920-965`). Temporal fails health first, drains, applies `GracefulStop` with an `AfterFunc` hard-stop deadline, and stops services in reverse init order (`service/frontend/service.go:544-591`; `temporal/server_impl.go:109-146`). openhands combines PID-trap cleanup, `tini` zombie reaping, and detached-process-group SIGTERM→SIGKILL escalation after 3s (`docker/entrypoint.sh:276-284`; `docker/Dockerfile:170`; `scripts/dev-with-automation.mjs:1063-1098`).
- **Why it works:** Deadlines convert hangs into bounded degradation; reverse-order/init-order discipline prevents tearing down dependencies before dependents; leak logging converts silent drift into observable events.
- **Copy when:** Every long-lived process owner. This is the most uniformly mature pattern across the corpus.
- **Gap to note:** Choreography covers *processes*; *data* teardown is weak in all four (see Notable Absences).

### P4. Bound resources before work begins

- **Problem:** Unbounded decode/allocation is a DoS vector that no downstream limiter can undo.
- **Demonstrated by:** opa rejects oversized requests at Content-Length before reading, threads decompressed ceilings through context, caps bundles at 1 GB against gzip bombs, and bounds caches per-entry (`v1/server/handlers/decoding.go:20-52`; `v1/plugins/server/decoding/validate.rego:15-17`; `v1/bundle/bundle.go:53`; `v1/topdown/cache/cache.go:60-90`) — with the config limits themselves validated by embedded Rego (`v1/plugins/server/decoding/config.go:27-34`). Agent-framework caps stdout/stderr/result/captured-files at byte granularity (10 MiB streams, 1 MiB per-file, 10 MiB total capture) and truncates terminal output head+tail (`dotnet/src/Microsoft.Agents.AI.LocalCodeAct/ProcessExecutionLimits.cs:13-35`; `dotnet/src/Microsoft.Agents.AI.Tools.Shell/LocalShellExecutorOptions.cs:82-83`). Temporal enforces payload caps at HTTP/gRPC layers (`MaxHTTPAPIRequestBytes=4MiB`, internode recv 128MiB: `common/rpc/grpc.go:30-44`) and sheds overload through layered rate limiters including a latency-adaptive persistence limiter (`common/persistence/client/health_request_rate_limiter.go:29-76`). openhands caps uploads client-side at 3 MB with concurrency 5 and paginates bash output at 20 pages (`src/utils/file-validation.ts:1-2`; `src/api/conversation-file-upload.api.ts:13`; `src/bash-service/bash-service.api.ts:23` → `src/api/bash-service/bash-service.api.ts:23`).
- **Why it works:** Pre-parse rejection is cheap, deterministic, and testable; post-hoc limits arrive after the damage.
- **Copy when:** Handling any externally-supplied bytes, compressed or nested.
- **Known evasion:** Chunked requests bypass opa's Content-Length precheck by acknowledged design (`v1/server/handlers/decoding.go:23-24`) — the fallback context ceiling is the compensating layer, illustrating that P4 wants *two* stages, not one.

### P5. Honest labeling of non-boundaries (and executable honesty)

- **Problem:** Weak controls presented as strong create false confidence worse than absence.
- **Demonstrated by:** Agent-framework is the exemplar: `ShellPolicy` ships *no* default deny-list because regex "cannot see what the shell will actually execute after expansion" (`python/packages/tools/agent_framework_tools/shell/_policy.py:8-34,70-121`), and the Python suite permanently encodes known bypass classes (base64 smuggling, `${RM:=rm}`, newline injection) as xfail contracts asserting the bypass works (`python/packages/tools/tests/test_security.py:124-164`). Mount docs state plainly they are not isolation ("Real isolation must come from the surrounding sandbox": `dotnet/src/Microsoft.Agents.AI.LocalCodeAct/FileMount.cs:22-30`), and LocalCodeAct self-describes as not a sandbox. Temporal documents its unauthenticated pprof (`common/pprof/pprof.go:41-65`) and archiver's existence-only path validation (`common/archiver/filestore/util.go:182-197`). openhands documents its editor token exposure under `--network host` with an upstream tracking issue (`docker/entrypoint.sh:20-25`).
- **Why it works:** Residual risk that is written down, tested, and issue-tracked stays maintained; undeclared weak layers rot invisibly.
- **Copy when:** Everywhere. Negative-space testing is cheap and turns documentation into an executable contract.
- **Risk:** Honesty without remediation tracking becomes permanent debt — openhands' commented-out chart hardening (`helm/agent-canvas/values.yaml:195-199`) is documented but still ships disabled.

### P6. Capability-change invalidation for long-lived sandboxes

- **Problem:** Sandboxes reused across invocations accumulate stale privileges when their configuration changes underneath them.
- **Demonstrated by:** Agent-framework hashes tools+mounts+domain-allowlists into a config fingerprint; any change forces a sandbox rebuild, so stale capabilities cannot persist (`dotnet/src/Microsoft.Agents.AI.Hyperlight/Internal/SandboxExecutor.cs:82-116,157-172`). Temporal shows the missing half of this pattern: callback URLs are validated against `callback.allowedAddresses` **at attach time only**, so later narrowing the rules leaves already-persisted callbacks firing — the dispatch router never re-checks (`chasm/lib/callback/validator.go:42`; `chasm/lib/callback/request.go:106-123`).
- **Why it works:** Fingerprinting binds the lifetime of granted capability to the exact configuration that justified it.
- **Copy when:** Any pooled/reused execution environment (VM snapshots, warm containers, cached clients) whose permissions are mutable.
- **Cost:** Rebuild latency on every capability change — accepted deliberately by agent-framework.

## Key Differences

**Who is the adversary determines everything.** Agent-framework designs against model-generated code — actively hostile, arbitrarily creative — hence five tiers and defense-in-depth capture logic (symlink-skipping snapshot walks on both stacks: `dotnet/src/Microsoft.Agents.AI.LocalCodeAct/Internal/FileMountHelper.cs:227-230`; `python/packages/monty/agent_framework_monty/_execute_code_tool.py:452-477`). opa designs against policy authors — semi-trusted insiders who should compute but not touch infra — hence language amputation plus an SSRF gate. Temporal designs against tenant API callers who can supply URLs but not code — hence admission-time URL rules plus quotas. openhands designs against nobody in this repo; its adversary management is upstream. Comparing their mechanisms head-to-head without this frame produces false rankings.

**Defaults split fail-closed from availability-first.** Temporal's callbacks reject-all when unconfigured; agent-framework's Docker tier drops all capabilities and networking by default and requires an explicit `acknowledge_unsafe` token to shed the approval gate. opa ships the opposite posture on every axis: `allow_net` absent ⇒ any host, authentication off, v0-compat binding `:8181` on all interfaces (`v1/ast/capabilities.go:94-100`; `v1/server/server.go:67-69`; `cmd/run.go:389-391`), preferring warnings over refusals even for root execution (`v1/runtime/check_user_linux.go:15-22`). openhands leans usability-first too: browser tool enabled unless env-disabled. Both postures are defensible — opa serves as an embeddable library where lockdown breaks users — but only temporal's and agent-framework's defaults survive contact with an untrusted caller.

**Enforcement timing ranges from static-first to never.** opa rejects unknown builtins at compile time (`v1/ast/compile.go:1014-1027`); agent-framework validates Docker flags at executor construction and AST-validates code before execution; temporal validates callbacks at workflow-start; openhands pushes checks to CI guard tests (`src/api/no-direct-agent-server-calls.test.ts`). Static-first enforcement ages better — it fails fast, leaves audit trails, and cannot be raced — but each source also shows a seam: opa's chunked-transfer precheck gap, temporal's attach-only validation, agent-framework's mtime-coincidence capture miss (`dotnet/src/Microsoft.Agents.AI.LocalCodeAct/Internal/FileMountHelper.cs:144-149`).

**Re-validation on policy change is implemented in exactly one source.** Agent-framework's config fingerprint (P6) versus temporal's attach-time-only callback rules is the sharpest mechanism contrast in the study: identical problem (mutable policy governing long-lived capability), opposite solutions, and only one survives a policy *tightening* mid-flight.

**Cleanup depth diverges by resource kind, consistently.** Processes: excellent everywhere (P3). Connections/caches: good (temporal sweeps internode conns on a 30-min cycle, `common/rpc/rpc.go:353-371`; opa closes watchers on ctx cancellation, `v1/runtime/runtime.go:1002-1004`). Data/workspaces: weak everywhere — openhands never reaps automation run dirs, temporal's archiver never deletes, opa's persisted bundles outlive retention policy, agent-framework's containers can leak past both kill attempts. None of the four treats workspace-artifact GC as a first-class subsystem.

## Tradeoffs

- **Isolation depth vs. operational complexity.** Agent-framework's five tiers, snapshot restore per invocation, and capability fingerprinting deliver real containment at the cost of rebuild latency, dual-stack parity burden (the .NET executor still lacks Python's flag blocklist: compare `python/packages/tools/agent_framework_tools/shell/_docker.py:103-127` against `dotnet/src/Microsoft.Agents.AI.Tools.Shell/DockerShellExecutor.cs:410-413`), and best-effort teardown complexity. Temporal/opa spend nearly nothing on OS containment because their trust models don't require it — portable and simple, but a mistyped archive URI silently widens the envelope (`common/archiver/filestore/util.go:182-197`).
- **Fail-closed defaults vs. embeddability.** Temporal's deny-all callback posture is safe but requires operators to opt namespaces in, and soft-failing pattern conversion can leave a namespace accidentally locked down until logs are noticed (`chasm/lib/callback/config.go:152-160`). opa's warnings-over-refusals keeps it runnable everywhere but ships an unhardened posture — its own security guide requires operator assembly (`docs/docs/security.md:607+`).
- **Quotas vs. hard ceilings.** Temporal and opa protect via rate limits, payload caps, and adaptive limiters — predictable under orchestrators that provide cgroups, unprotected in bare embeds (both report searches confirming no rlimit/cgroup/GOMEMLIMIT usage). Agent-framework's Docker tier uses kernel-enforced `--memory`/`--pids-limit`, but only there; its LocalCodeAct subprocess has wall-clock and byte caps only (`ProcessExecutionLimits.cs:15-28`).
- **Client-side hygiene vs. enforcement-side guarantees.** openhands' traversal-tested upload anchoring and 3 MB caps add defense-in-depth but prove nothing about the server, which is upstream; meanwhile its `downloadFile` passes arbitrary paths through untouched (`src/api/runtime-service/agent-server-runtime-service.ts:70-96`) — asymmetric rigor on the write path only.
- **Expressiveness vs. safety in restricted code tiers.** Blocking `getattr/setattr/open/import` in LocalCodeAct excludes many legitimate programs and forces explicit extension lists (`validator.py:435-444`); Monty's overlay mounts give free write containment but files vanish after the run (`python/packages/monty/README.md:144-145`). opa faces the same tension structurally: custom builtins registered by embedders can reintroduce filesystem/process reach, so "safe by absence" holds for stock OPA but is not guaranteed for forks (`v1/ast/compile.go:1014-1027` caveat).
- **Usability escapes vs. boundary integrity.** Agent-framework's auto-approval matches by tool *name*, so a colliding name silently bypasses the human gate — warned about in both SDKs (`dotnet/src/Microsoft.Agents.AI.Tools.Shell/LocalShellExecutor.cs:331-338`). openhands' token-in-editor-URL pragmatism ships a `Referrer-Policy` mitigation while deferring the fix (`docker/entrypoint.sh:415-447`). Both trade a known leak vector for velocity, consciously documented.

## Decision Guide

Choosing between the approaches found in these sources:

1. **Are you executing model-generated (or otherwise hostile) code?** Adopt agent-framework's model: make isolation a property of the selectable backend, offer tiers matched to risk, and refuse to construct executors without an explicit approval or acknowledgment token. Do not rely on import blocklists or regex filters as boundaries — label them guardrails.
2. **Do you own a DSL or interpreter where dangerous capabilities can simply not exist?** Follow opa: deny-by-construction beats permission systems for auditability. Then add exactly one explicit, tested egress gate for the network primitives you *do* ship — and make sure *every* ingestion path (bundles, discovery, embedder registrations) flows through the same capability check, since opa's own operator-configured services bypass `allow_net`.
3. **Are you a trusted service where tenants can influence outbound destinations but not execute code?** Copy temporal: default-deny address-match rules for caller-supplied URLs, admin-gated registration for anything persistent, scheme validation, and quota-based overload shedding through a single ordered interceptor/authz chain rather than scattered handler checks.
4. **Do you own only part of the stack?** Follow openhands' discipline — harden packaging identity, ingress, and credentials you control; make the delegation explicit in your repo map; add fail-fast config guards — but treat its gaps as the cautionary half of the lesson: uncomment the hardening, add the NetworkPolicy, and don't leave workspace GC to nobody.
5. **Rule of thumb for defaults:** if the consumer of the surface might be untrusted, the unset/empty configuration must mean *deny* (temporal's `AddressMatchRules{}`, agent-framework's mount-less/network-less sandboxes). Reserve "unset means allow" (opa's `AllowNet`) for surfaces where the operator is demonstrably the only author — and document that assumption next to the field.
6. **Rule of thumb for exec sites:** zero is best, one reviewed argv-array site with timeout and pipe-wait bounds is acceptable, N string-typed passthroughs require an ownership story for where filtering actually happens.

## Practical Tips

- Encode empty-vs-absent semantics for every allowlist field deliberately, and pin them with tests the way opa does for `allow_net` (`v1/topdown/http_test.go:793-851`).
- Extract side-effect-free argv/config builders so isolation flags are unit-testable without daemons — agent-framework tests its entire Docker baseline purely from constructed argv (`python/packages/tools/tests/test_docker_shell_tool.py:150-201`).
- Give every subprocess a wall-clock timeout *on by default*, a `WaitDelay`-style pipe cap, and process-group/session setup so children are killable (`python/packages/tools/agent_framework_tools/shell/_executor.py:26-31`). Agent-framework's disabled-by-default timeouts are the anti-example its own reports flag.
- Kill process trees, not processes: two-phase SIGTERM→SIGKILL over the group, resolving kill binaries to absolute paths so a poisoned PATH can't redirect teardown (`_killtree.py:39-47`).
- Stage shutdown: signal → drain window → graceful stop with deadline → hard stop → dependency-ordered component close, with leak logging at each forced step (all four sources converge here).
- Snapshot-then-diff for write capture, skipping symlinks/reparse points at every walk level, and know your diff key's blind spot (size+mtime coincidence) (`FileMountHelper.cs:144-149,227-230`).
- Write negative-space tests: parametrize known bypasses and assert they currently work, so silent "improvements" to filters surface as contract failures (`test_security.py:124-164`).
- Validate egress at request construction *and* on redirect hops; re-check host allowlists per hop as opa does (`v1/topdown/http.go:646-650`).
- Treat shell-script configuration as code: extract route/flag normalization into testable seams and fail startup on contradictions (openhands refusing to advertise an unserved editor route: `scripts/static-server.mjs:194-206`).

## Anti-Patterns / Caution Signs

- **Regex/string-level command filtering as a security control.** Newline injection (`echo ok\nrm -rf /`) defeats single-line matching; base64 smuggling defeats content inspection. Agent-framework documents these as permanent bypass contracts rather than pretending otherwise (`test_security.py:140`). If your design's threat model ends at a deny-list regex, it has no threat model.
- **Approval gates keyed by name.** Auto-approval by tool-name collision is a silent bypass class (`LocalShellExecutor.cs:331-338`); any identity scheme for permissions must be collision-proof.
- **Shipped-but-commented-out hardening.** openhands' chart carries `capabilities.drop: [ALL]` / `readOnlyRootFilesystem` as suggestions (`helm/agent-canvas/values.yaml:180-186`); production deploys inherit the weaker default unless an operator knows to look.
- **Unset-means-anything defaults on network knobs.** opa's omitted `allow_net`, its authn-off default, and its all-interfaces v0 binding compound into a posture requiring operator assembly to secure.
- **One-lifecycle-moment validation for mutable policy.** Attach-time-only callback rules mean tightenings never apply in flight (`chasm/lib/callback/request.go:106-123`); any rule set governing durable artifacts needs either dispatch-time rechecks or invalidation-on-change.
- **Timeouts and resource limits that must be opted into.** Null-default timeouts (`LocalShellExecutorOptions.cs:75-80`) and absent CPU/memory caps outside containers let a runaway consume the host indefinitely.
- **Debug endpoints bound wide without auth** (temporal pprof under misconfiguration, `common/pprof/pprof.go:41-65`) **and tokens in navigable URLs** (openhands editor `?tkn=`) — convenience features whose exposure grows quietly with deployment creativity.
- **Soft-fail parsing that shifts security posture silently.** Skipped malformed patterns lock namespaces down (temporal); `raise_error=false` turns egress misconfiguration into undefined decisions instead of loud failures (opa, `v1/topdown/http.go:201-220`). Silent-in-either-direction is still silent.
- **Caution signs a controls surface is going brittle:** growing lists of blocked imports/flags needing manual parity across SDKs (agent-framework's .NET/Python drift); cleanup paths accumulating fallback stages with "never raises" semantics; capture/diff logic acquiring documented coincidence holes; retention bounded only by "whatever the PVC holds."

## Notable Absences

- **No in-process OS confinement anywhere.** Searches across all four sources found no seccomp profiles, AppArmor, namespaces, chroot, ulimits, cgroups, `SetMemoryLimit`, or privilege-dropping code in production paths; containment outside Docker flags is uniformly delegated to the deployment environment (agent-framework Q&A; opa `Questions/Gaps`; temporal `Questions/Gaps`).
- **No global network-policy layer in any source.** There is no egress proxy, DNS filtering, or unified outbound-policy engine; governance is per-tier (agent-framework), per-field (`AllowNet`, opa), per-URL-class (temporal callbacks vs. Nexus endpoints vs. JWKS), or absent (openhands).
- **No data/workspace garbage collection.** openhands automation run workspaces are never reaped (`docker/entrypoint.sh:53,317-319`); temporal's filestore archiver is write/read-only with no delete path; retention elsewhere is PVC-capacity-bounded.
- **No pids/fork protection outside containers.** openhands' Helm chart sets CPU/memory but no pids limit despite unrestricted spawn ability; opa/temporal have no fork governance at all (safe only by having no exec sites).
- **No metrics on control-plane denials** in agent-framework beyond logs and the `on_command` audit hook; opa distinguishes cache-hit vs. real egress counters (`v1/topdown/http.go:40-42`) — the closest thing to control observability in the corpus.
- **No ingress IP/CIDR filtering** in temporal (bind address + Host-header matching only); no Kubernetes NetworkPolicy object in openhands' chart templates.
- **agent-framework's Go implementation does not exist yet** — the `go/` directory is a placeholder README, so no fourth-stack comparison was possible.

## Per-Source Notes

**agent-framework (8/10).** The reference implementation for this dimension: five execution tiers under one capability vocabulary, restrictive-by-default Docker baselines tested via pure argv builders, symlink-hardened mount capture on both stacks, interpreter-level `PermissionError` denial in Monty, and residual risk maintained as executable xfail contracts. Kept from 9–10 by null-default timeouts, the .NET/Python parity gap on `ExtraRunArgs` validation, absent CPU/memory limits for LocalCodeAct, and documented container-leak paths in teardown.

**opa (6/10).** The strongest *auditability* story: zero filesystem/process builtins means the fs/process surface is provably empty by compiler admission (`v1/ast/compile.go:1014-1027`), and `AllowNet` gating is redirect-aware and well-tested. Held back by availability-first defaults (any-host egress when unconfigured, root-run warning only), hostname-only allowlist precision, operator services bypassing the gate, and no process-level hardening whatsoever.

**openhands (5/10).** The delegation archetype executed with real craft on owned surfaces — non-root identity, fail-fast ingress guards, generated credentials, tested upload hygiene, exemplary process teardown — but with no agent-facing egress/filesystem/command mechanism in-repo, a browser tool on by default, hardening suggestions left commented, and automation workspaces that accumulate forever. Auditing this source alone cannot establish agent safety; that is simultaneously its honest scope statement and its structural limitation.

**temporal (7/10).** The strongest *server self-protection* story: one ordered interceptor plane, default-deny callback allowlists with https-by-default, a single ceremonially-reviewed exec site, cluster-aware and latency-adaptive quotas, crash-resumable staged deletion, and dynamic-config hot-reload for nearly every knob. Gaps: no hard memory/CPU ceilings, attach-time-only egress validation, existence-only archiver path checks, and an unauthenticated pprof listener when enabled.

## Open Questions

- Whether platform-hosted deployments impose service-side network policy for agent-framework Foundry agents is outside repository evidence (agent-framework report, Questions/Gaps).
- Whether opa's decision-log/status plugins enforce outbound payload-size caps was not traced; the download side is bounded but upload-side limits were out of the studied boundary.
- DNS rebinding between opa's `verifyHost` check and dial resolution remains theoretically possible since verification precedes resolution (`v1/topdown/http.go:402-423`) — unmitigated in the audited code.
- Whether Nexus *operation dispatch* (as opposed to callbacks) honors temporal's `callback.allowedAddresses` could not be confirmed from the frontend code inspected; observed gates are admin registration plus scheme validation (`service/frontend/nexus_endpoint_client.go:360-361`).
- The upstream runtime's actual sandbox internals (software-agent-sdk): server-side upload/download path validation, mount namespacing, and egress enforcement are all unverifiable from the openhands frontend; only volume declarations describe intent (`docker/Dockerfile:159-164`).
- No evidence was found in any source of Windows-specific confinement deeper than working-directory re-anchoring (no Job Objects/AppContainer in agent-framework; platform-differing root checks in opa).
