## Executive Summary

No framework in this study treats generative planning as mandatory, and only two treat the plan as a durable, typed runtime object. Agent-framework (`7/10`) and CrewAI (`7/10`) both reify plans as Pydantic/dataclass objects (`TodoItem`/`TodoStore` at `python/packages/core/agent_framework/_harness/_todo.py:51`, `TodoList` at `lib/crewai/src/crewai/utilities/planning_types.py:45`) with tool schemas, tests, and checkpoint persistence — but they split the responsibility across two disconnected subsystems (harness todo vs Magentic ledger; crew-level prompt-mutation vs agent-level Flow executor). LangGraph (`6/10`) inverts the model: it owns orchestration planning perfectly via its Pregel BSP `Plan→Execution→Update` scheduler (`libs/langgraph/langgraph/pregel/main.py:464`), yet deliberately owns no task-decomposition planner, outsourcing that to `deepagents` (`README.md:31`). OpenHands (`5/10`) owns planning as a gated UX mode — a markdown file (`PLAN.md` at `openhands/tools/planning_file_editor/definition.py:38`) produced by a read-only `AgentType.PLAN` preset (`openhands/tools/preset/planning.py:94`) — visible but unvalidated prose, not a state machine. The remaining three — Letta, OpenAI Agents SDK, and Pydantic AI core (all `2/10`) — implement no planner at all: planning is model-owned inner monologue (`letta/prompts/system_prompts/memgpt_chat.py:24`), per-turn tool dispatch (`src/agents/run_internal/tool_planning.py:557`), or an external harness capability (`docs/capabilities/overview.md:72`) that never materializes inside the studied repo.

The through-line: where the framework owns the *object* and its lifecycle (Agent-framework harness loop predicate `todos_remaining()` at `python/packages/core/agent_framework/_harness/_loop.py:925`, CrewAI `AgentExecutorState.todos` at `lib/crewai/src/crewai/experimental/agent_executor.py:154`, LangGraph `prepare_next_tasks` at `libs/langgraph/langgraph/pregel/_algo.py:392`), planning is testable, observable, and bounded. Where the model owns the content and the runtime owns nothing (Letta reactive `_step` at `letta/agents/letta_agent_v3.py:894`, OpenAI `AgentRunner._run_impl` loop at `src/agents/run.py:964`, Pydantic AI 3-node `UserPromptNode→ModelRequestNode→CallToolsNode` at `pydantic_ai_slim/pydantic_ai/_agent_graph.py:442`), planning is flexible but invisible, unrepeatable, and silently drift-prone.

## Core Thesis

Planning location predicts every other property of the design.

**When the plan is a runtime object** (typed `TodoItem`/`TaskLedger`/`TodoList`/`PlanStep` with store, events, checkpoint, and tests — Agent-framework `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:272`, CrewAI `lib/crewai/src/crewai/utilities/planning_types.py:14`), responsibility is split but clear: the model authors content, the runtime owns persistence, evaluation, and enforcement. Planning is visible (workflow events, session messages, Flow nodes), reusable within a session via checkpoint, and bounded by explicit caps (`max_stall_count` at `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:472`, `max_replans` at `lib/crewai/src/crewai/agent/planning_config.py:122`).

**When the plan is prose in a prompt** (Letta inner-monologue instruction at `letta/prompts/system_prompts/memgpt_chat.py:24`, OpenAI `Agent.instructions` at `src/agents/agent.py:309`, Pydantic AI `AbstractCapability.get_instructions` at `pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:202`), responsibility collapses onto the model. The runtime merely executes whatever tool call appears next. Planning is optional, invisible beyond reasoning text, not reusable, and unbounded except by `max_steps` or `max_turns`.

**When the plan *is* the graph** (LangGraph `StateGraph` at `libs/langgraph/langgraph/graph/state.py:131`, Agent-framework `WorkflowBuilder` at `python/packages/core/agent_framework/_workflows/_workflow_builder.py:53`), responsibility shifts to the developer. The graph is deterministic, checkpoint-durable, and highly visible (`get_graph()`/`StateSnapshot` at `libs/langgraph/langgraph/pregel/main.py:845`), but static — the LLM cannot author new nodes at runtime, only choose among conditional edges or `Send` packets.

**When the plan is a file** (OpenHands `PLAN.md` at `openhands/app_server/app_conversation/live_status_app_conversation_service.py:1071`), responsibility is tripartite: model authors prose, `PlanningFileEditorTool` gates writes (`openhands/tools/planning_file_editor/impl.py:10`), filesystem persists, human approves via a Build button (`frontend/src/hooks/use-handle-build-plan-click.ts:27`). The result is human-readable and UX-visible, but untyped, unversioned, and disconnected from any execution state machine.

The practical rule: *if planning is enforced by toolset composition or a state-machine predicate, it survives model drift; if it is enforced only by prompt, it does not.* OpenHands stripping executor tools from the planner (`openhands/tools/preset/planning.py:110`) and Agent-framework gating loop continuation on `todos_remaining()` survive drift; CrewAI appending to `task.description` (`lib/crewai/src/crewai/crew.py:1471`) and Letta injecting `<tool_usage_rules>` (`letta/helpers/tool_rule_solver.py:209`) do not.

## Approach Models

Four archetypes emerged; a single source can span two.

### 1. Explicit typed planner with runtime-owned lifecycle

*Sources:* agent-framework (both harness and Magentic), crewai (agent layer).

Planning is a first-class object produced by one LLM call (or a dedicated manager agent) and consumed by a state-machine loop. Agent-framework's harness uses `TodoProvider.before_run` (`python/packages/core/agent_framework/_harness/_todo.py:493`) to inject 5 tools + instructions + current-list message, and `AgentLoopMiddleware` (`python/packages/core/agent_framework/_harness/_loop.py:217`) to loop on the predicate `todos_remaining()` (`python/packages/core/agent_framework/_harness/_loop.py:925`). Magentic uses `StandardMagenticManager` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:514`) wrapping a `SupportsAgentRun` manager agent that authors `TaskLedger`/`ProgressLedger` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:272`/`308`) under orchestrator ownership (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:906`). CrewAI's `AgentReasoning._execute_planning` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:244`) calls the LLM with `FUNCTION_SCHEMA` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:50`) to produce `ReasoningPlan→TodoList` (`lib/crewai/src/crewai/utilities/planning_types.py:45`), then the `AgentExecutor` Flow graph (`lib/crewai/src/crewai/experimental/agent_executor.py:173`) schedules `StepExecutor`/`PlannerObserver` per todo. All artifacts are Pydantic/dataclass-validated, event-emitted (`MagenticPlanCreatedEvent` at `dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticOrchestrator.cs:14`, `AgentReasoningStartedEvent` at `lib/crewai/src/crewai/utilities/reasoning_handler.py:197`), and checkpointed (`OnCheckpointingAsync` at `dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticOrchestrator.cs:357`).

*When it fits:* Multi-agent or long-horizon tasks where plan-vs-actual, approval, and crash-resume matter. *Cost:* Extra LLM call(s) per plan/replan, model-authored content quality variance.

### 2. Workflow graph as the plan

*Sources:* langgraph, agent-framework `WorkflowBuilder`.

The plan *is* the DAG. LangGraph's `StateGraph` (`libs/langgraph/langgraph/graph/state.py:131`) declares `add_node`/`add_edge`/`add_conditional_edges`/`add_sequence` and compiles to `Pregel` with `trigger_to_nodes` (`libs/langgraph/langgraph/graph/state.py:1340`). Each superstep the scheduler calls `prepare_next_tasks()` (`libs/langgraph/langgraph/pregel/_algo.py:392`) to compute the next executable set from `channel_versions` vs `versions_seen`. Agent-framework's `WorkflowBuilder` (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:53`) offers the same static-DAG idiom (`add_fan_out_edges`, `add_switch_case_edge_group`). No LLM decomposition step exists; dynamism comes only from conditional branches and `Send`/`TASKS Topic` fan-out (`libs/langgraph/langgraph/pregel/main.py:804`, `python/packages/core/agent_framework/_harness/_todo.py:505` contrasts with prompt-driven decomposition).

*When it fits:* Production workflows with known topology where determinism, time-travel, and human-interrupt (`PregelLoop.tick` at `libs/langgraph/langgraph/pregel/_loop.py:599`) outweigh open-ended exploration. *Cost:* Plan cannot be rewritten by the model beyond branch choices; long-horizon tasks must be encoded as graph cycles.

### 3. File-artifact gated planning mode

*Source:* openhands.

Planning is a separate conversation with `agent_type="plan"` (`openhands/app_server/app_conversation/app_conversation_models.py:61`) that injects `system_prompt_planning.j2` (`openhands/sdk/agent/prompts/system_prompt_planning.j2:1`) plus `PLANNING_AGENT_INSTRUCTION` (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:185`) and restricts tools to `Glob+Grep+PlanningFileEditor` (`openhands/tools/preset/planning.py:94`). The plan is a markdown file initialized from `PLAN_STRUCTURE` (`openhands/tools/preset/planning.py:12`) at `PLAN.md` on the sandbox workspace (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:1071`). Human approves by clicking Build, which sends `Execute the plan based on the .agents_tmp/PLAN.md file.` (`frontend/src/hooks/use-handle-build-plan-click.ts:27`). A secondary, weaker planner — `task_tracker` writing `TASKS.md` (`openhands/tools/task_tracker/definition.py:38`) — coexists for default-mode ad-hoc decomposition.

*When it fits:* Developer-tools where human-readable prose and readable diffs are more valuable than machine executability. *Cost:* No schema, no versioning, no `Plan` type, no lifecycle; executor must re-parse prose.

### 4. Implicit / absent — model-owned prose

*Sources:* letta, openai-agents-sdk, pydantic-ai (core).

No planner, no plan object, no decomposition code. Letta's loop (`letta/agents/letta_agent_v3.py:328`) is reactive `for i in range(max_steps): response = self._step(...)` — one LLM call, one tool, validation via `ToolRulesSolver.should_force_tool_call` (`letta/helpers/tool_rule_solver.py:273`). The "plan" is the model's `reasoning_content` before each tool call, as instructed by `memgpt_chat.py:24`. OpenAI Agents SDK's `AgentRunner._run_impl` (`src/agents/run.py:964`) loops on `SingleStepResult.next_step` discriminants until `NextStepFinalOutput`; the only object named `*Plan*` is `ToolExecutionPlan` (`src/agents/run_internal/tool_planning.py:557`), which partitions already-returned tool calls by kind/approval before parallel dispatch (`src/agents/run_internal/tool_planning.py:944`). Pydantic AI's `Agent.__init__` (`pydantic_ai_slim/pydantic_ai/agent/__init__.py:487`) exposes no `planner` param; planning is `Planning()` inside `Coder()` from the external `pydantic-ai-harness` (`docs/capabilities/overview.md:72`, `docs/navigation.yml:311`) with a `Cache-safe live reminder` that re-injects instructions via `AbstractCapability.get_instructions` (`pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:202`). All three rely on a declarative adjunct: Letta `ToolRule` subtypes (`letta/schemas/tool_rule.py:360`), OpenAI `Agent.as_tool()`/`handoffs` (`src/agents/agent.py:583`/`331`), Pydantic AI `Toolset` (`docs/toolsets.md:897`).

*When it fits:* Minimal-core libraries that deliberately defer planning until patterns stabilize; teams that prefer prompt iteration over planner maintenance. *Cost:* Non-deterministic, invisible beyond step history, no reuse, no approval surface.

## Pattern Catalog

### Pattern 1 — Prompt+Tools duality with runtime-owned store

*What it solves:* Lets the model decompose work without a separate planner agent, while keeping the ground truth outside the model's context.

*Who demonstrates it:* Agent-framework harness. `DEFAULT_TODO_INSTRUCTIONS` (`python/packages/core/agent_framework/_harness/_todo.py:25`) tells the model when to decompose; `TodoProvider.before_run` (`python/packages/core/agent_framework/_harness/_todo.py:493`) injects tools; `TodoStore` ABC with `TodoSessionStore`/`TodoFileStore` (`python/packages/core/agent_framework/_harness/_todo.py:228`) persists `TodoItem` (`python/packages/core/agent_framework/_harness/_todo.py:51`); `AgentLoopMiddleware` (`python/packages/core/agent_framework/_harness/_loop.py:217`) enforces via `todos_remaining()` (`python/packages/core/agent_framework/_harness/_loop.py:925`).

*Why it works:* Model authors, runtime owns evaluation. Loop predicate reads store, not model self-report.

*Copy when:* Single-agent todos that must survive restarts and bound execution. Add a `min_todos` guard parallel to Magentic's `require_plan_signoff` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:888`) if silent plan-skipping is unacceptable.

*Risk/overkill:* Model can still ignore instructions (approval_mode `never_require` at `python/packages/core/agent_framework/_harness/_todo.py:505`); opt-in wiring (`disable_todo` at `python/packages/core/agent_framework/_harness/_agent.py:318`) is easy to forget, leaving todos decorative.

### Pattern 2 — Manager-agent ledger with stall-aware replanning

*What it solves:* Bounded, auditable multi-agent planning with explicit progress signals.

*Sources:* Agent-framework Magentic. Manager agent (`StandardMagenticManager` at `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:514`) + `ORCHESTRATOR_TASK_LEDGER_*_PROMPT`s (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:108`) produce `TaskLedger` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:272`) + `MagenticProgressLedger` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:308`) with 5-way JSON decision (`ORCHESTRATOR_PROGRESS_LEDGER_PROMPT` at `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:194`). `stallCount`/`max_stall_count` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1117`) triggers `ResetAndReplan`; `progress_ledger_retry_count=3` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:472`) with 250ms backoff handles JSON parse failures; `MagenticPlanCreatedEvent`/`ReplannedEvent` (`dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticOrchestrator.cs:14`) provide visibility; `OnCheckpointingAsync` (`dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticOrchestrator.cs:357`) provides durability.

*Copy when:* Multi-speaker orchestration where per-turn routing depends on plan. *Overkill when:* Single-agent task; costs 2 LLM calls for initial plan + 2 for replan + 1 per progress ledger.

### Pattern 3 — Structured function-calling plan with Pydantic validation

*What it solves:* Machine-parseable decomposition with graceful degradation.

*Source:* CrewAI `AgentReasoning`. `FUNCTION_SCHEMA` for `create_reasoning_plan(plan, steps[{step_number, description, tool_to_use, depends_on}], ready)` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:50`), invoked via `llm.call(..., tools=[FUNCTION_SCHEMA])` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:368`), validated as `TodoList` (`lib/crewai/src/crewai/utilities/planning_types.py:45`). Non-function-calling fallback parses `"READY:"` sentinel (`lib/crewai/src/crewai/utilities/reasoning_handler.py:583`).

*Copy when:* You need dependency-aware scheduling and provider-agnostic LLM support. *Risk:* Fallback path returns zero steps (`lib/crewai/src/crewai/utilities/reasoning_handler.py:270`) — silent degradation to unplanned execution.

### Pattern 4 — Dependency-aware ready-set with parallel fan-out

*What it solves:* Minimal DAG execution without importing a full workflow engine.

*Source:* CrewAI `TodoList.get_ready_todos()` + `can_parallelize` (`lib/crewai/src/crewai/utilities/planning_types.py:133`) + `AgentExecutor.execute_todos_parallel` (`lib/crewai/src/crewai/experimental/agent_executor.py:1068`) routed via Flow `@router decide_next_action` (`lib/crewai/src/crewai/experimental/agent_executor.py:643`). LangGraph's `Send` + `TASKS Topic` (`libs/langgraph/langgraph/pregel/main.py:804`) is the static-graph analogue; Agent-framework's `WorkflowBuilder.add_fan_out_edges` (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:282`) is the developer-authored version.

*Copy when:* Steps have `depends_on` edges and independent ready todos can run concurrently. *Overkill when:* Steps are strictly sequential.

### Pattern 5 — Effort-graded observation pipeline

*What it solves:* Explicit latency/adaptivity tradeoff for per-step replanning.

*Source:* CrewAI `PlanningConfig.reasoning_effort: low/medium/high` (`lib/crewai/src/crewai/agent/planning_config.py:11`), gated by `_should_observe_steps()` (`lib/crewai/src/crewai/experimental/agent_executor.py:518`) and `PlannerObserver.observe()` with `response_model=StepObservation` (`lib/crewai/src/crewai/agents/planner_observer.py:113`) plus heuristic fallback (`lib/crewai/src/crewai/agents/planner_observer.py:88`) when `low`. Yields `StepObservation{step_completed_successfully, remaining_plan_still_valid, suggested_refinements, needs_full_replan, goal_already_achieved}` (`lib/crewai/src/crewai/utilities/planning_types.py:198`).

*Copy when:* You need to let callers choose between zero-token heuristic, failure-triggered replan, and full per-step LLM observation. *Risk:* High-effort mode adds N LLM calls per task (N = plan length); bare `planning=True` maps to `low` effort (`lib/crewai/src/crewai/agent/core.py:396`) and provides no observation.

### Pattern 6 — In-place refinement vs full replan with cap

*What it solves:* Cheap adaptation for small invalidations vs expensive regeneration for drift.

*Source:* CrewAI `PlannerObserver.apply_refinements` (`lib/crewai/src/crewai/agents/planner_observer.py:215`) for `StepRefinement` in-place mutation vs `TodoList.replace_pending_todos()` (`lib/crewai/src/crewai/utilities/planning_types.py:185`) for `needs_full_replan`, bounded by `max_replans` (`lib/crewai/src/crewai/agent/planning_config.py:122`). Agent-framework mirrors with progress-ledger stall count bounding.

*Copy when:* Plans regularly need small fixes without regenerating completed state. *Caution:* Budget exhaustion in CrewAI silently maps to `"all_todos_complete"` (`lib/crewai/src/crewai/experimental/agent_executor.py:1019`) and drops remaining pending todos without marking failed.

### Pattern 7 — Channel-triggered orchestration scheduling

*What it solves:* Deterministic, versioned selection of next actors without a central planner.

*Source:* LangGraph Pregel `prepare_next_tasks()` (`libs/langgraph/langgraph/pregel/_algo.py:392`) comparing `channel_versions` vs `versions_seen`, with `_triggers()` (`libs/langgraph/langgraph/pregel/_algo.py:1260`) and `apply_writes()` (`libs/langgraph/langgraph/pregel/_algo.py:232`) completing the BSP triad. `PregelLoop.tick()` (`libs/langgraph/langgraph/pregel/_loop.py:599`) drives `should_interrupt`/`_put_checkpoint`.

*Copy when:* You need time-travel (`get_state`/`update_state`), interrupts, and hierarchical checkpoint namespaces. *Overkill when:* You need a plan the model can rewrite; this scheduler only reacts to written channels.

### Pattern 8 — Tool-gating by composition (vs prompt-only denial)

*What it solves:* Structural guarantee that the planner cannot execute.

*Source:* OpenHands `get_planning_tools(plan_path)` (`openhands/tools/preset/planning.py:94`) returns only `Glob+Grep+PlanningFileEditor` (editor wrapped with `allowed_edits_files=[plan_path]` at `openhands/tools/planning_file_editor/impl.py:10`); default mode uses `get_default_tools()` (`openhands/tools/preset/default.py:31`) with `Terminal+FileEditor+TaskTracker`. Agent-framework `StandardMagenticManager` wraps a separate `SupportsAgentRun` session (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:592`) with isolated `create_session()` per ledger call.

*Copy when:* Planning and execution have different security contexts or sandboxes. *Risk:* OpenHands still allows unbounded `view` of any file; `PLANNING_AGENT_INSTRUCTION` (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:185`) is defense-in-depth, not primary.

### Pattern 9 — Constraint-solver workflow as planning surrogate

*What it solves:* Deterministic tool sequencing without generative planning.

*Source:* Letta `ToolRulesSolver` (`letta/helpers/tool_rule_solver.py:24`) categorizing `ToolRule` subtypes (`letta/schemas/tool_rule.py:360`) and intersecting via `get_allowed_tool_names()` (`letta/helpers/tool_rule_solver.py:96`), compiled to `<tool_usage_rules>` block (`letta/helpers/tool_rule_solver.py:209`) injected via `Memory.compile()` (`letta/schemas/memory.py:718`).

*Copy when:* Tool order must be human-authored and enforceable, not LLM-invented. *Limitation:* Expressiveness limited to tool-level sequencing; cannot encode subtasks, deadlines, or resource constraints; authoring 8 rule types has high cognitive load.

### Pattern 10 — Cache-safe live reminder

*What it solves:* Keeps the current plan visible across turns without busting provider prompt-cache.

*Source:* Pydantic AI harness descriptor `Planning — Model-owned task plans with a cache-safe live reminder` (`docs/capabilities/overview.md:72`) via `AbstractCapability.get_instructions` (`pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:202`). Re-injects plan as stable-prefix instructions each turn so cache prefix survives.

*Copy when:* Plans are long-lived and token cost matters. *Risk:* Naive re-integration as fresh `UserPromptPart` busts cache every turn; reminder may lag model's internal intent.

## Key Differences

### Who authors vs who owns

Across all sources the split is *model authors, runtime evaluates* — but the evaluation point differs. Agent-framework harness evaluates via store predicate (`todos_remaining`); Magentic evaluates via orchestrator-held `TaskLedger`; CrewAI evaluates via `AgentExecutorState.todos` lifecycle (`lib/crewai/src/crewai/experimental/agent_executor.py:154`); LangGraph evaluates via versioned channels; OpenHands evaluates via filesystem editor boundary; Letta/OpenAI/Pydantic evaluate via single-tool allowlist or not at all. The weakest binding is Letta/OpenAI/Pydantic where evaluation is only "did the returned tool name appear in the allowed list?" (`letta/helpers/tool_rule_solver.py:96`, `src/agents/run_internal/tool_planning.py:339`), not "did the step advance the plan?".

### One plan vs two plans per repo

Agent-framework ships harness todo and Magentic ledger with zero bridge; CrewAI ships crew-level string-append plan (`lib/crewai/src/crewai/crew.py:1471`) and agent-level typed `TodoList` with zero conversion; OpenHands ships gated `PLAN.md` and `task_tracker`'s `TASKS.md` (`openhands/tools/task_tracker/definition.py:38`) as non-interoperating surfaces. Only LangGraph and the 2/10 group avoid the split by not shipping a generative planner at all — a conscious consistency-through-absence choice.

### Visibility axis: events vs prose

Agent-framework and CrewAI emit typed events (`MagenticPlanCreatedEvent` at `dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticOrchestrator.cs:14`, `AgentReasoningStartedEvent` at `lib/crewai/src/crewai/utilities/reasoning_handler.py:197`, `PlanReplanTriggered` at `lib/crewai/src/crewai/experimental/agent_executor.py:409`); LangGraph exposes `StateSnapshot{next, tasks, interrupts}` (`libs/langgraph/langgraph/pregel/main.py:1145`) and `get_graph()`/`debug` streams; OpenHands renders `PlanPreview` (`frontend/src/components/features/chat/plan-preview.tsx:26`) from `PlanningFileEditorObservation`. Letta/OpenAI/Pydantic expose only step history: `Step{stop_reason, provider, tokens}` (`letta/schemas/step.py:16`), `RunItem`/`StreamEvent` (`src/agents/result.py:1`, `src/agents/stream_events.py:1`), `message_history` (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:298`).

### Reusability axis: checkpointed object vs string vs nothing

Agent-framework checkpoints (`TodoFileStore` atomic replace at `python/packages/core/agent_framework/_harness/_todo.py:431`, `MagenticOrchestrator.OnCheckpointingAsync` at `dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticOrchestrator.cs:357`) preserve plans per `session_id`/`source_id`; CrewAI `PlanningConfig` (`lib/crewai/src/crewai/agent/planning_config.py:11`) is reusable as a Pydantic model but generated plans are not cached; LangGraph `CompiledStateGraph` is reusable as a `Runnable` subgraph (`libs/langgraph/langgraph/pregel/main.py:1076`) but exports no `Plan` artifact; OpenHands re-reads `PLAN.md` via the Build prompt (`frontend/src/hooks/use-handle-build-plan-click.ts:27`) — copy-paste is the only cross-conversation reuse; Letta/OpenAI/Pydantic have nothing to reuse.

### Planning as gate vs planning as hint

Agent-framework `AgentLoopMiddleware` looping on `todos_remaining` and Magentic's `max_stall_count`/`max_reset_count`/`max_round_count` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:472`) gate execution hard. CrewAI's `max_replans`/`max_step_iterations`/`step_timeout` (`lib/crewai/src/crewai/agent/planning_config.py:11`) gate soft but observe. OpenHands' `PLANNING_AGENT_INSTRUCTION` (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:185`) forbids execution during planning but is a prompt suffix, not a gate. Letta `max_steps` (`letta/constants.py:74`), OpenAI `max_turns` (`src/agents/run.py:590`), and Pydantic AI `UsageLimits` (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:875`) are not plan completion gates — they are loop truncation limits.

## Tradeoffs

**Model-authored adaptivity vs deterministic static graph.** Harness/Magentic/CrewAI plans adapt per request and per observation; graph plans (LangGraph, `WorkflowBuilder`) never surprise. *Benefit of adaptivity:* Covers open-ended tasks tanpa hand-coded topology. *Cost:* Quality varies by model; empty-plan drift (`todos_remaining==False` on empty list at `python/packages/core/agent_framework/_harness/_loop.py:980` exits silently) and `task.description += plan` accumulation on re-kickoff (`lib/crewai/src/crewai/crew.py:1471`) are real bugs. *Best fit for adaptivity:* Research/assistant tasks; *for determinism:* Production HITL with time-travel.

**Two representations (todo vs ledger) vs no representation.** Agent-framework and CrewAI each pay a conceptual tax — duplicate prompt/ledger concepts and divergent config knobs (`max_stall_count` vs `max_replans`, `observe_steps` vs `reasoning_effort`). *Benefit:* Each representation is optimized for its scale (single-agent todo vs multi-agent team plan). *Alternative seen in LangGraph/Pydantic:* No second representation — cleaner mental model, but user re-implements planning every time.

**Opt-in (default off) vs always-on.** CrewAI `planning=False` (`lib/crewai/src/crewai/crew.py:344`), Agent-framework `disable_todo`/`loop_should_continue=None` (`python/packages/core/agent_framework/_harness/_agent.py:318`/`337`), Magentic `require_plan_signoff=False` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:888`), Letta `tool_rules=None` (`letta/schemas/agent.py:76`), OpenAI/Pydantic no flag at all. *Benefit:* Zero overhead, backward compatible. *Cost:* Easy to forget wiring (Agent-framework loop without `todos_remaining`), discoverability low (CrewAI requires knowing `PlanningConfig()`), and filing-level planning never happens unless user asks.

**Manager agent per-plan LLM cost vs reuse.** Magentic calls the manager LLM twice for initial plan (facts + plan) + twice for replan + once per progress ledger; CrewAI high-effort mode adds one LLM call per step (`PlannerObserver.observe`). *Benefit:* Leverages full agent features (tools, history providers), stateless `create_session()` avoids duplication bug (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:599`). *Cost:* O(rounds) latency/cost; fallback on transient failure aborts workflow (Magentic facts/plan have no retry, only progress ledger does).

**Session-state vs file-state vs memory-state durability.** Session store is zero-config but lost on exit unless checkpointed; `TodoFileStore` atomic replace (`python/packages/core/agent_framework/_harness/_todo.py:431`) is durable but `@experimental` (`python/packages/core/agent_framework/_harness/_todo.py:287`); `PLAN.md` on sandbox is durable only while sandbox lives; `CompiledStateGraph` checkpoint survives failures via `DeltaChannel`; `RunState`/`message_history` survives only as items/approvals without a plan field. *Best fit:* Long-running team plans → checkpoint; simple todos → session; human-readable audit → file + checkpoint.

**Structural tool-gating vs prompt-level denial.** OpenHands stripping executor tools is hard; Letta/OpenAI/Pydantic prompt-plus-allowlist is soft (allowlist can still diverge from prompt, and `ToolRulesSolver.get_allowed_tool_names` intersects to empty set with `ValueError` at `letta/helpers/tool_rule_solver.py:122`). *Benefit of hard:* Fails closed. *Cost:* Planner cannot run scripted checks (`TerminalTool` excluded from OpenHands planning set, forcing slow `GrepTool`/`GlobTool`).

**Cache efficiency vs visibility.** Pydantic AI harness `live reminder` via stable-prefix instructions preserves provider prefix-cache; stuffing plan into fresh `UserPromptPart` busts cache per variant plan length. The tradeoff is history purity: plan as instructions every turn vs plan buried in `message_history`.

## Decision Guide

Choose the approach whose enforcement matches the failure mode you fear most.

**If your model drifts from the plan, you need a predicate, not a prompt.** Use a runtime-owned object with a loop predicate (`todos_remaining`/`stallCount`/`ready-set`) or a scheduler. Agent-framework harness and Magentic, CrewAI agent layer, and LangGraph all qualify; OpenHands file-plus-prompt and the 2/10 group do not.

**If routing among specialists matters, you need a progress ledger, not a todo list.** Agent-framework Magentic's `next_speaker` + `instruction_or_question` decision (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:194`) and CrewAI's `StepObservation.remaining_plan_still_valid` (`lib/crewai/src/crewai/utilities/planning_types.py:198`) both answer "who speaks next?". A flat `TodoList` or `PLAN.md` prose cannot.

**If determinism or time-travel matters more than open-ended decomposition, use the graph.** LangGraph Pregel (`libs/langgraph/langgraph/pregel/main.py:464`) and `WorkflowBuilder` (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:53`) give you `get_state`/`update_state`, `interrupt_before/after`, and hierarchical checkpoints out of the box. Accept that the LLM cannot author new nodes — extend via `Send` or `add_conditional_edges`.

**If human-readable audit is the primary deliverable, use a file.** OpenHands `PLAN.md` with `PLAN_STRUCTURE` (`openhands/tools/preset/planning.py:12`) and `PlanPreview` renders cleanly; promote it to a Pydantic `Plan{steps[{goal, method, status}]}` when you need execution gating.

**If you are a library, ship no planner — ship the substrate.** LangGraph and Pydantic AI made the same choice for opposite operational reasons (LangGraph keeps core small and vendors `deepagents` separately; Pydantic AI keeps `pydantic-ai-slim` provider-agnostic and composes `Capability` at `pydantic_ai_slim/pydantic_ai/capabilities/__init__.py:72`). Follow suit when patterns are still stabilizing.

Flowchart rules:

1. **Do you need HITL signoff on the plan before execution?** Yes → Agent-framework Magentic `require_plan_signoff` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:888`) with `MagenticPlanReviewRequest/Response` (`dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticOrchestrator.cs:105`). No → any approach.
2. **Must the plan survive a crash and resume?** Yes → Agent-framework checkpoint or LangGraph `checkpointer` (`libs/langgraph/langgraph/pregel/_loop.py:1081`); CrewAI only if flow checkpointing is configured (`lib/crewai/src/crewai/crew.py:545`); Pydantic AI only with harness `StepPersistence`. No → file or session store suffices.
3. **Are steps dependent and parallelizable?** Yes → CrewAI `TodoList.get_ready_todos`/`can_parallelize` or LangGraph `Send` fan-out. No → flat todo list or markdown.
4. **Is the planner a different model/session than the executor?** Yes → Magentic manager agent (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:592`) or OpenHands sub-conversation (`frontend/src/hooks/use-handle-plan-click.ts:27`). No → single-agent harness or capability injection.
5. **Does tool order compliance matter more than decomposition quality?** Yes → Letta `ToolRulesSolver` (`letta/helpers/tool_rule_solver.py:24`) or OpenAI `needs_approval` gating (`src/agents/run_state.py:182`). No → generative planner.
6. **Do you need per-step observation with cost control?** Yes → CrewAI `reasoning_effort` (`lib/crewai/src/crewai/agent/planning_config.py:22`) and `step_timeout` (`lib/crewai/src/crewai/agent/planning_config.py:140`); alternatively Magentic progress ledger per round.

## Practical Tips

**Patterns to copy:**

- **Reify the plan as a typed dataclass/Pydantic model with store abstraction** and `to_dict`/`from_dict` — enables tests (`python/packages/core/tests/core/test_harness_todo.py:242`), serialization, and checkpointing. Do this before adding any planner prompt.
- **Gate the loop on the store, not on model self-report.** Wire `todos_remaining()` or `prepare_next_tasks` as the predicate; `loop_should_continue=None` by default (`python/packages/core/agent_framework/_harness/_agent.py:337`) is a footgun — wire it at construction.
- **Atomic persistence for file-backed plans** — write to `*.tmp.{pid}` then `os.replace` (`python/packages/core/agent_framework/_harness/_todo.py:431`) and guard path traversal (`python/packages/core/agent_framework/_harness/_todo.py:344`).
- **Per-session lock with `WeakKeyDictionary`/`ConditionalWeakTable`** (`python/packages/core/agent_framework/_harness/_todo.py:485`, `dotnet/src/Microsoft.Agents.AI/Harness/Loop/TodoCompletionLoopEvaluator.cs:1`) when the same session can be invoked concurrently.
- **Separate facts/plan LLM calls and retry only the structured decision** — Magentic retries progress-ledger JSON 3× (`dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/MagenticManager.cs:67`) but fails fast on facts/plan; mirror this.
- **Effort as a coa rse policy knob** (`reasoning_effort` at `lib/crewai/src/crewai/agent/planning_config.py:22`) when per-step observation cost must be caller-controlled; default `planning=True` → `low` (`lib/crewai/src/crewai/agent/core.py:396`) to avoid surprise latency.
- **Isolate per-step messages** (`StepExecutor._build_isolated_messages` at `lib/crewai/src/crewai/agents/step_executor.py:244`) to prevent prompt bloat — pass only dependency results.
- **Copy don't mutate the task.** Keep `ReasoningPlan` in state, not appended to `task.description` (`lib/crewai/src/crewai/experimental/agent_executor.py:382` comment: `Do NOT mutate task.description`); crew-level string append (`lib/crewai/src/crewai/crew.py:1471`) is the cautionary counterexample.
- **Cache-safe reminder for model-owned plans** — inject via stable-prefix `get_instructions` (`pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:202`) to preserve provider prefix-cache.

**Patterns to avoid or delay until needed:**

- Shipping two disjoint plan representations in one repo (todo vs ledger; `PLAN.md` vs `TASKS.md`) without a bridge or migration guide — doubles learning curve.
- In-place `task.description += plan` mutation — lossy, unversioned, accumulates on re-kickoff.
- Heuristic replan triggers on message string matching (`lib/crewai/src/crewai/experimental/agent_executor.py:2452`) — brittle.
- Observation fallback that defaults to success (`lib/crewai/src/crewai/agents/planner_observer.py:208` returns `success=True` on exception) — masks failures.
- Replan-budget exhaustion that maps to `"all_todos_complete"` — silently drops pending work (`lib/crewai/src/crewai/experimental/agent_executor.py:1019`).
- File-as-plan tied to sandbox lifetime (`PLAN.md`) without durability or versioning — plan disappears when sandbox stops.
- Naming ephemeral dispatch `ToolExecutionPlan` (`src/agents/run_internal/tool_planning.py:557`) alongside conceptual task planning — causes dimension confusion.

**Decision rules:**

- If you cannot name the object that *is* the plan, you have no planner — you have a prompt.
- If the model can mark work complete without doing it and the runtime cannot tell, the plan is advisory — add a verification step or accept the drift.
- If `max_steps` is the only termination signal, you have a loop cap, not a plan-completion gate.

## Anti-Patterns / Caution Signs

- **Decorative todos.** Tools exist (`todos_add` etc.) but no loop predicate enforces them — `loop_should_continue` left `None` (`python/packages/core/agent_framework/_harness/_agent.py:337`). Symptom: empty `TodoList`, one iteration, silent success.
- **String-append crew plan.** `task.description += plan_map[n]` (`lib/crewai/src/crewai/crew.py:1471`) mutates shared state, accumulates on repeated `kickoff()` without `copy()`, and cannot carry `depends_on`. No plan `copy()` preserves it.
- **Advisory timeout.** `StepExecutor.execute(..., step_timeout)` (`lib/crewai/src/crewai/agents/step_executor.py:348`) only checks between iterations — a hung `llm.call` blocks past the deadline. No LLM cancellation wired.
- **Approval deadlock without plan fallback.** Tool `needs_approval` pending leaves `NextStepInterruption` (`src/agents/run_state.py:782`) indefinitely; no `PlanRevision` escapes the blocked tool (`src/agents/run_internal/tool_planning.py:557` has no replanning surface).
- **Stale conditional routing.** `StateGraph.add_conditional_edges` without `path_map` (`libs/langgraph/langgraph/graph/state.py:958`) only warns at `draw_graph`; unknown `Command(goto)` destinations (`libs/langgraph/langgraph/graph/state.py:838`) are silently dropped.
- **Path mismatch between plan creation and consumption.** OpenHands `_compute_plan_path` switches to `agents-tmp-config` for GitLab/Azure (`openhands/app_server/app_conversation/live_status_app_conversation_service.py:1086`) but Build prompt hardcodes `.agents_tmp/PLAN.md` (`frontend/src/hooks/use-handle-build-plan-click.ts:27`).
- **Legacy location divergence.** `PlanningFileEditorTool.create()` prefers legacy `workspace/PLAN.md` (`openhands/tools/planning_file_editor/definition.py:58`) if present — two locations coexist, no dedup, no `mtime`/`hash` freshness check.
- **Constraint deadlock.** Intersecting `Child/Parent/MaxCount` rules yields empty allowlist and `ValueError: No valid tools found` (`letta/helpers/tool_rule_solver.py:122`); `ConditionalToolRule` without `last_function_response` raises separately (`letta/schemas/tool_rule.py:204`).
- **Context overflow mid-plan.** Plan lives only in reasoning history; summarization/compaction (`letta/agents/letta_agent_v3.py:939`, `openhands/tools/preset/planning.py:108` planning condenser `max_size=100`) can evict it; no plan-aware compaction exists.
- **Handoff contention.** Multiple handoff tool calls in one response drop all but first (`src/agents/run_internal/turn_resolution.py:563`) with synthetic message — coordination failure no planner arbitrates.
- **No plan schema, no diff.** None of the seven ships a structured "what changed in this replan" delta or plan-vs-actual audit; the question *Is planning a real runtime object or just prose?* answers "prose" for the bottom four.

## Notable Absences

Shared gaps where evidence in the per-source reports explicitly notes absence, not just silence:

- **No first-class plan diff or audit API in any source.** No source ships a typed `PlanDiff`, `PlanAuditEvent`, or public function that returns planned-vs-actual. Agent-framework notes two plan representations but no comparison; CrewAI notes no planned-versus-actual helper; LangGraph cannot compare because there is no `Plan` channel (`libs/langgraph/langgraph/pregel/main.py:845` only exposes workflow topology, not decomposition); OpenAI/Pydantic/Letta have no plan to diff against.
- **No plan optimizer or alternatives selector.** Searched across Magentic (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1`), CrewAI `utilities/planning*.py`, and LangGraph `pregel` — no A*/cost-based planning, only single plan + reactive replan. The only branched alternative is LangGraph `add_conditional_edges` routing, not plan selection.
- **No cross-run plan reuse library.** No plan registry, template catalog, or cache keyed by `(task hash, tools hash, config hash)`. Agent-framework `Workflow` is reusable as a static graph (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:764`) but not as a learned plan. CrewAI `PlanningConfig` is reusable as config, not as generated plan. Pydantic AI and OpenAI explicitly leave caching to user code.
- **No durable plan transfer between representations.** No bridge `TodoItem ↔ TaskLedger` (agent-framework), no `PlannerTaskPydanticOutput → TodoList` (crewai), no `PLAN.md → TASKS.md` sync (openhands), no declarative YAML planning primitive (`declarative-agents/` search finds none).
- **No unified planning dashboard or visualization** (beyond LangGraph `get_graph()` for topology and OpenHands `PlanPreview` for markdown rendering). CrewAI has no `TodoList` visualizer distinct from Flow viz; Magentic has `WorkflowEvent` streams but no plan-centric UI; Letta `Step`/`StepProgression` (`letta/schemas/step.py:16`/`68`) track execution, not plan.
- **No plan-level HITL beyond Magentic signoff.** Letta `RequiresApprovalToolRule` (`letta/schemas/tool_rule.py:313`) and OpenAI `RunState` approval (`src/agents/run_state.py:182`) gate individual tools, not the plan; CrewAI and LangGraph have no signoff at all; OpenHands Build is a tool-execution toggle, not a plan-review gate.
- **No plan freshness or ground-truth verification.** Stall detection relies on LLM self-assessment (`is_progress_being_made` at `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1117`) or heuristic observation (`PlannerObserver.heuristic_observation` at `lib/crewai/src/crewai/agents/planner_observer.py:88`); no source validates against tool-observation signals (file writes, search results) or human feedback.
