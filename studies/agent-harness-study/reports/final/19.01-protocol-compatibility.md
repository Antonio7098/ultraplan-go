## Executive Summary

Protocol compatibility across the 10 sources converges on two pillars — **JSON Schema as the tool lingua franca** and **OTLP/OpenTelemetry for traces** — but diverges sharply on MCP direction, OpenAPI import, and operational maturity.

*   **JSON Schema is universal where tools exist.** All agent harnesses (agent-framework, crewai, letta, openai-agents-sdk, pydantic-ai, langfuse) generate JSON Schema from Pydantic/Zod and normalize to a canonical `parameters` object. Even non-harnesses (opa, temporal) use it for type-checking or skip it by design.
*   **OTLP is present in 8/10, but ownership differs.** agent-framework, letta, opa, temporal ship both gRPC and HTTP/protobuf exporters with env-var fidelity (`OTEL_EXPORTER_OTLP_ENDPOINT` at `python/packages/core/agent_framework/observability.py:586`, `letta/otel/tracing.py:157`, `internal/distributedtracing/distributedtracing.go:98`). langfuse is the only dual-role (inbound `POST /api/public/otel/v1/traces` at `web/src/pages/api/public/otel/v1/traces/index.ts:27` + outbound `web/src/observability.config.ts:115`). crewai, openai-agents-sdk, openhands deliberately avoid generic export — crewai to a hard-coded vendor endpoint (`lib/crewai/src/crewai/telemetry/telemetry.py:71`), openai-agents-sdk to `https://api.openai.com/v1/traces/ingest` (`src/agents/tracing/processors.py:44`), openhands to PostHog only.
*   **MCP is client-heavy, server-rare, never bidirectional in a single repo.** Five harnesses implement a transport-agnostic client (agent-framework `MCPTool` at `python/packages/core/agent_framework/_mcp.py:424`, crewai `MCPClient` at `lib/crewai/src/crewai/mcp/client.py:59`, letta `AsyncBaseMCPClient` at `letta/services/mcp/base_client.py:41`, pydantic-ai `MCPToolset` at `pydantic_ai_slim/pydantic_ai/mcp.py:715`, openai-agents-sdk `MCPServer` at `src/agents/mcp/server.py:542`). Only langfuse ships a production server (`web/src/features/mcp/server/mcpServer.ts:15` stateless Streamable HTTP 2025-03-26). langgraph and openhands only proxy/expose at deployment edge (`libs/cli/langgraph_cli/schemas.py:471`, `src/api/mcp-service/mcp-service.api.ts:1`). opa/temporal have zero MCP.
*   **OpenAPI import is the unanimous gap.** Every source that *exports* OpenAPI (langfuse via Fern `fern/fern.config.json:1`, letta via FastAPI `letta/fern/openapi.json:2`, temporal via `service/frontend/openapi_http_handler.go:17`, langgraph via `libs/cli/langgraph_cli/schemas.py:235`) has no importer. No source implements `spec → tool` materialization; external REST APIs always require a hand-written adapter.
*   **Tool portability is "canonical schema + per-provider shim," not zero-cost.** The answer to "Can external tools be added without custom adapters?" is **yes only for MCP** (and for pydantic-ai also LangChain via `ext/langchain.py:32`). For OpenAPI it is uniformly **no**.

Maturity correlates with product shape: agent harnesses score 6-8, policy/workflow engines 5 (excellent on their own protocols, absent on agent protocols), and thin frontends 5 (delegated).

## Core Thesis

**The dimension is solved by layering a canonical JSON Schema definition with transport-agnostic MCP client plumbing and delegated OTLP export, not by unifying every protocol into one adapter.**

Sources that score highest (agent-framework 8, langfuse 8, pydantic-ai 8) share three choices: (1) a single `FunctionTool`/`ToolDefinition` holding raw JSON Schema derived from typed code (`agent-framework/_tools.py:890`, `pydantic-ai/tools.py:291`, `langfuse define-tool.ts:127`), (2) a narrow per-provider transformer at request time instead of a universal schema, and (3) OTel as a provider-injected `TracerProvider` rather than a bundled collector. Sources that attempt a universal adapter or bundle every exporter (or hard-code a vendor endpoint) incur coupling or lock-in without improving portability.

Divergence is not primarily quality — it is **role-driven**: observability platforms (langfuse, temporal, opa) optimize for *being* the protocol endpoint (serve OpenAPI, ingest OTLP), while harnesses optimize for *consuming* external protocols (client MCP, provider-agnostic tools). Treating a policy engine's missing MCP as a defect misreads intent; the gap that *is* a defect across roles is the missing OpenAPI→tool importer, which forces custom glue even where the spec is machine-readable.

## Approach Models

Clustered by protocol posture, not by overall quality:

**A. Client-heavy harness (consume external tools) — agent-framework, crewai, letta, pydantic-ai, openai-agents-sdk**
One `MCPTool`/`MCPToolset` base owns `ClientSession`, exposes `FunctionTool`s via `tools/list`, supports at least two transports. JSON Schema is derived from code (Pydantic `model_json_schema()` or Zod `z.toJSONSchema`) and cached. OTLP is either native (agent-framework, letta) or delegated (pydantic-ai) or proprietary (openai-agents-sdk) or stubbed (crewai). These score highest when they add guardrails (sampling deny-by-default at `agent-framework/_mcp.py:130`, schema healing at `letta/functions/schema_generator.py:847`, DoS budgets at `openai-agents-sdk strict_schema.py:21`).

**B. Server-as-product (be the protocol endpoint) — langfuse, temporal (partial), opa (partial)**
Protocol is *served*: langfuse serves MCP (`StreamableHTTPServerTransport` `web/src/features/mcp/server/transport.ts:12`) and ingests OTLP; temporal serves Nexus + OpenAPI and exports OTLP; opa serves policy API and exports OTLP. They prove durability under load (S3 staging `packages/shared/src/server/otel/OtelIngestionProcessor.ts:72`, shared gRPC conns `common/telemetry/config.go:133`, batch processor `internal/distributedtracing/distributedtracing.go:47`) but have no client discovery — langfuse explicitly states server-only (`web/src/features/mcp/server/mcpServer.ts:64` `capabilities: { tools: {} }`).

**C. Orchestration delegator — langgraph**
Graph is protocol-agnostic; all tool/MCP/OpenAPI/OTel decisions are delegated to `langchain-core` (`libs/langgraph/pyproject.toml:27` `langchain-core>=1.4.7`) or platform (`libs/cli/langgraph_cli/schemas.py:471` `disable_mcp`, `libs/sdk-py/langgraph_sdk/runtime.py:87` `execution_runtime`). Strength is portable `BaseTool`/`with_structured_output` (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:292`), weakness is no native wire code — MCP dict at `libs/prebuilt/tests/test_react_agent.py:315` is opaque.

**D. Frontend proxy — openhands**
Owns no protocol runtime; validates config, normalizes transport (`src/utils/mcp-config.ts:60` `normalizeTransport`), probes health (`src/api/mcp-health/probe-mcp-server-health.ts:22`), then delegates to `MCPClient` from `@openhands/typescript-client` (`src/api/mcp-service/mcp-service.api.ts:1`). Patterns are UX-centric (secret redaction `src/api/mcp-service/mcp-service.api.ts:68`, stale-write guard `src/api/mcp-health/mcp-health-store.ts:50`). Scored as fragile because guarantees depend on SDK version pinned at `package.json:27` `1.38.1`.

**E. Non-agent specialist — opa, temporal (when judged as harnesses)**
Their "tool schemas" are `types.Function` (`v1/ast/builtins.go:11`) and Protobuf `Payload` (`common/nexus/payload_serializer.go:15`), not LLM function schemas. Their OTLP and schema maturity is high but misaligned with the dimension's agent-harness questions, hence 5s reflect scope mismatch, not poor engineering.

## Pattern Catalog

**1. Canonical JSON Schema + per-provider transformer**
*Problem:* One tool definition must work across OpenAI strict, Anthropic, Bedrock, Gemini without duplicating authoring.
*Demonstrated by:* pydantic-ai (`ToolDefinition.parameters_json_schema` `pydantic_ai_slim/pydantic_ai/tools.py:291` + `JsonSchemaTransformer` `pydantic_ai_slim/pydantic_ai/_json_schema.py:15` + `ModelProfile.json_schema_transformer` selection `pydantic_ai_slim/pydantic_ai/models/__init__.py:581`), agent-framework (`FunctionTool.parameters()` `python/packages/core/agent_framework/_tools.py:816` + `normalize_tools` `python/packages/core/agent_framework/_tools.py:962`), crewai (`generate_model_description` `lib/crewai/src/crewai/utilities/pydantic_schema_utils.py:648` + sanitizers `lib/crewai/src/crewai/utilities/pydantic_schema_utils.py:615`).
*Why it works:* Single source of truth (Pydantic/Zod) with provider quirks isolated to a walk at `prepare_request` time.
*When to copy:* Any harness supporting >2 LLM providers.
*When overkill/risk:* Single-provider SDKs (openai-agents-sdk leans OpenAI strict `src/agents/strict_schema.py:115` correctly) pay complexity for unused portability; silent constraint stripping (crewai `lib/crewai/src/crewai/utilities/pydantic_schema_utils.py:546` drops `minimum`/`maximum` on Anthropic without warning) is the failure mode.
*Evidence:* `pydantic_ai_slim/pydantic_ai/profiles/google.py:245`, `lib/crewai/src/crewai/llms/providers/anthropic/completion.py:581`, `python/packages/core/agent_framework/_tools.py:1085`.

**2. Transport-agnostic MCP client abstraction**
*Problem:* Support stdio, SSE, Streamable HTTP without duplicating tool discovery/execution.
*Demonstrated by:* agent-framework (`MCPTool` base `python/packages/core/agent_framework/_mcp.py:424` + subclasses `MCPStdioTool`/`MCPStreamableHTTPTool`/`MCPWebsocketTool`), crewai (`BaseTransport` `lib/crewai/src/crewai/mcp/transports/base.py:1` + `MCPClient` `lib/crewai/src/crewai/mcp/client.py:59`), letta (`AsyncBaseMCPClient` `letta/services/mcp/base_client.py:41` + `SSE/Stdio/StreamableHTTP` configs `letta/functions/mcp_client/types.py:222`), pydantic-ai (`MCPToolset` normalizing `MCPToolsetClient` `pydantic_ai_slim/pydantic_ai/mcp.py:27`), openai-agents-sdk (`MCPServer` ABC `src/agents/mcp/server.py:542` + `create_streams` `src/agents/mcp/server.py:1070`).
*Why it works:* One lifecycle (`connect`/`list_tools`/`call_tool`/`cleanup` with `AsyncExitStack`) with transport as factory.
*When to copy:* Always for MCP client; never try per-transport tool wrappers.
*Risk:* Connection-per-call (crewai `lib/crewai/src/crewai/mcp/tool_resolver.py:315`) trades latency for thread safety; shared session (openai-agents-sdk `src/agents/mcp/server.py:952` `_request_lock`) risks races on 5xx.
*Evidence:* `letta/services/mcp/streamable_http_client.py:16`, `lib/crewai/src/crewai/tools/mcp_native_tool.py:17`.

**3. Strict-mode healing and allowlist filtering**
*Problem:* Wild MCP schemas break OpenAI strict mode (`additionalProperties: false`, required/no `anyOf` root).
*Demonstrated by:* letta (`normalize_mcp_schema` adds `additionalProperties: false` `letta/functions/schema_generator.py:608`, `generate_tool_schema_for_mcp` heals `anyOf`/`$ref` `letta/functions/schema_generator.py:586`, `validate_complete_json_schema` `letta/functions/schema_validator.py:1`), agent-framework (`_MCP_FRAMEWORK_DENYLIST` `python/packages/core/agent_framework/_mcp.py:115` + `_prepare_call_kwargs` filtering), openai-agents-sdk (`ensure_strict_json_schema` with budgets `src/agents/strict_schema.py:115`), crewai (`sanitize_tool_params_for_openai_strict` `lib/crewai/src/crewai/utilities/pydantic_schema_utils.py:615`).
*Why it works:* Healing maximizes compatibility (letta promotes optional→required-nullable `letta/functions/schema_generator.py:847`) while denylist prevents arg smuggling.
*When to copy:* Any OpenAI strict integration ingesting third-party schemas.
*Risk:* Semantic drift (optional becomes required), and `anyOf` healing can inject wrong `type: object` on non-object refs (`letta/functions/schema_generator.py:658`).
*Evidence:* `letta/tests/test_schema_validator.py:5`, `web/src/__tests__/server/unit/mcp-define-tool.servertest.ts:6`.

**4. Bring-your-own OTel provider (delegate export)**
*Problem:* Avoid forcing `opentelemetry-sdk` + `exporter-otlp` on every user while still emitting spec-correct spans.
*Demonstrated by:* pydantic-ai (`InstrumentationSettings` takes `tracer_provider` `pydantic_ai_slim/pydantic_ai/models/instrumented.py:82` + docs `docs/logfire.md:170` `OTLPSpanExporter` pattern), crewai (deliberately avoids global provider `lib/crewai/src/crewai/telemetry/telemetry.py:173`), temporal (per-service `TracerProvider` via `fx` `temporal/fx.go:13`, rejecting global), agent-framework (wraps `OpenTelemetryAgent` `docs/decisions/0003-agent-opentelemetry-instrumentation.md:58` keeping it optional).
*Why it works:* Spec-strict modules (`pydantic_ai_slim/pydantic_ai/AGENTS.md:17` "implement only spec-defined features") stay vendor-neutral.
*When to copy:* Libraries (vs. services) where minimal deps matter.
*Risk:* One extra setup step; no exporter bundled means OTLP may never be configured (pydantic-ai gap at `pydantic_ai_slim/pyproject.toml:67`).
*Evidence:* `letta/otel/tracing.py:145` (counter-example: bundled gRPC exporter, heavier but zero-config).

**5. Stateless, per-request MCP server with registry**
*Problem:* Serve many tenants without session leaks, with entitlement gating.
*Demonstrated by:* langfuse (`createMcpServer` fresh `Server` per request `web/src/features/mcp/server/mcpServer.ts:15`, global `ToolRegistry` `web/src/features/mcp/server/registry.ts:72` with 15 feature modules `web/src/features/mcp/server/bootstrap.ts:14`, `InAppAgentMcpRunOverrideSchema` `packages/shared/src/in-app-agent/server/mcpPolicy.ts:386`).
*Why it works:* No coordination, horizontal scale, `enableJsonResponse:true` (`web/src/features/mcp/server/transport.ts:68`) avoids SSE streaming state.
*When to copy:* Multi-tenant SaaS exposing tools over Streamable HTTP.
*Risk:* Loses streaming/subscriptions and stateful prompts/resources (langfuse `capabilities: { tools: {} }` `web/src/features/mcp/server/mcpServer.ts:64`).
*Evidence:* `web/src/pages/api/public/mcp/index.ts:27`, `web/src/__tests__/server/mcp-tools-read.servertest.ts:1`.

**6. Progressive disclosure and permission-tiered tool exposure**
*Problem:* Large MCP surfaces blow up model context.
*Demonstrated by:* agent-framework (`use_progressive_disclosure` `python/packages/core/agent_framework/_mcp.py:520` + loader tools `list_mcp_tools`/`load_tool`/`unload_tool` `python/packages/core/agent_framework/_mcp.py:884` + `tool_name_prefix`), langfuse (`readOnlyHint`/`destructiveHint` `web/src/features/mcp/core/define-tool.ts:39` + `IN_APP_AGENT_LANGFUSE_MCP_TOOL_POLICIES` `packages/shared/src/in-app-agent/server/mcpPolicy.ts:27` auto vs approval).
*Why it works:* Model sees small surface; privileged tools require approval.
*When to copy:* >20 tools per server or sensitive write tools.
*Risk:* Stateful loader (`ctx.add_tools`/`remove_tools` `python/packages/core/agent_framework/_mcp.py:945`) adds operator complexity.
*Evidence:* `docs/decisions/0029-mcp-skill-templates-and-direct-references.md:19`.

**7. Dual-schema validation (wire vs. runtime)**
*Problem:* MCP clients should not see refinement artifacts.
*Demonstrated by:* langfuse (`defineTool` dual `baseSchema` → draft-7 JSON Schema vs `inputSchema` with refinements `web/src/features/mcp/core/define-tool.ts:31`), pydantic-ai (`ToolDefinition` `parameters_json_schema` vs `Tool.from_schema` with `SchemaValidator` `pydantic_ai_slim/pydantic_ai/tools.py:437`).
*Why it works:* Discovery schema stays spec-compliant; runtime validation stays strict.
*When to copy:* Any `defineTool` that supports Zod refinements or Pydantic validators.

## Tradeoffs

**1. Canonical schema vs. per-provider sanitizer**
*Benefit:* Canonical reduces authoring to one Pydantic model; sanitizer ensures provider acceptance (crewai OpenAI strict `lib/crewai/src/crewai/utilities/pydantic_schema_utils.py:615` vs Anthropic `lib/crewai/src/crewai/utilities/pydantic_schema_utils.py:626`).
*Cost:* Silent constraint loss, divergent validation, hard to debug.
*Best fit:* Multi-provider harnesses (pydantic-ai, agent-framework, crewai).
*Failure mode:* Schema valid on OpenAI loses `minimum`/`pattern` on Anthropic without warning (`crewai pydantic_schema_utils.py:546`).
*Alternative:* openai-agents-sdk embraces OpenAI strict as canonical (`src/agents/strict_schema.py:235`) — simpler, but less portable.

**2. Bring-your-own OTel vs. bundled exporter**
*Benefit (BYO):* Minimal deps (`pydantic-ai-slim` only `opentelemetry-api` `pydantic_ai_slim/pyproject.toml:67`), vendor-neutral, per-service providers avoid global contamination (`temporal temporal/fx.go:13`, `crewai telemetry.py:173`).
*Cost (BYO):* Extra setup, no out-of-box OTLP (pydantic-ai requires `OTLPSpanExporter` + `BatchSpanProcessor` `docs/logfire.md:212`), crewai's telemetry remains vendor-locked.
*Benefit (bundled):* Zero-config `setup_tracing(endpoint)` `letta/otel/tracing.py:145`, `agent-framework observability.py:548` honoring `OTEL_*`.
*Failure mode (bundled):* gRPC-only lock-in (letta, temporal `common/telemetry/config.go:403` rejects HTTP), or hard-coded endpoint (crewai `CREWAI_TELEMETRY_BASE_URL` `lib/crewai/src/crewai/telemetry/telemetry.py:71`).
*Alternative seen:* langfuse does both — inbound ingest accepts any content-type (`web/src/pages/api/public/otel/v1/traces/index.ts:27`) but outbound is configurable `OTEL_EXPORTER_OTLP_ENDPOINT` `web/src/env.mjs:305`.

**3. Connection-per-call vs. pooled session**
*Benefit (per-call):* Thread-safe, no shared mutable state (crewai `lib/crewai/src/crewai/mcp/tool_resolver.py:315`, `lib/crewai/src/crewai/tools/mcp_native_tool.py:17`).
*Cost:* TLS handshake per tool call increases P95.
*Benefit (pooled/shared):* Low latency, `list_tools` cache (`pydantic-ai mcp.py:786` TTL, `crewai client.py:51` 300s).
*Failure mode:* Shared session races on 5xx require isolated retry (`openai-agents-sdk streamable_http` `src/agents/mcp/server.py:2325`) and pagination loop detection (`src/agents/mcp/server.py:1444`).
*Best fit:* Per-call for short-lived agents, pooled for long-lived servers.

**4. Healing vs. rejecting invalid schemas**
*Benefit (healing):* 90% of MCP tools become OpenAI-compatible (letta `generate_tool_schema_for_mcp` `letta/functions/schema_generator.py:694` promotes optional→required-nullable).
*Cost:* Mutates upstream intent, can inject wrong types (`letta mcp_client types.py:658` `type: object` on non-object `$ref`).
*Benefit (rejecting):* Fails fast with explicit message (langfuse `define-tool.ts:138` throws on unions/intersections, tested `web/src/__tests__/server/unit/mcp-define-tool.servertest.ts:6`).
*Failure mode (healing):* Healed schema passes `validate_complete_json_schema` but misrepresents optionality; caller sends `null` for truly optional field.
*Alternative:* openai-agents-sdk budgets DoS instead of healing (`src/agents/strict_schema.py:21` 100k nodes).

**5. Stateless server vs. stateful session**
*Benefit (stateless):* Simple horizontal scale, no session leaks (langfuse `web/src/features/mcp/server/mcpServer.ts:57` fresh `Server` per request, `sessionIdGenerator: undefined` `web/src/features/mcp/server/transport.ts:67`).
*Cost:* No streaming/subscriptions, progress notifications unused.
*Alternative:* Stateful servers (not present here) would enable MCP `resources` subscriptions but require sticky sessions and re-auth.
*Best fit:* SaaS tool providers; avoid for agent harnesses needing long-lived sampling.

## Decision Guide

**Choose MCP client depth by agent lifespan:**
- Short-lived/ephemeral agents → per-call client + TTL cache (crewai, pydantic-ai `cache_tools` default `True` `pydantic_ai_slim/pydantic_ai/mcp.py:786`).
- Long-lived server agents → pooled `MCPServerManager` with task-affinity and locks (openai-agents-sdk `src/agents/mcp/manager.py:151`).

**Choose OTel ownership by distribution model:**
- Library/SDK shipped to users → delegate `tracer_provider` (pydantic-ai `models/instrumented.py:82`), document 6-line setup (Logfire 1-line `logfire.configure()` as ergonomic path).
- Deployed service you operate → bundle both transports, honor `OTEL_EXPORTER_OTLP_ENDPOINT` + `OTEL_EXPORTER_OTLP_PROTOCOL` + `HEADERS` with `/v1/{signal}` semantics (agent-framework `observability.py:586`), and support YAML + env with shared connections (temporal `common/telemetry/config.go:57`).

**Choose JSON Schema posture by provider count:**
- 1 provider → enforce its strict subset (openai-agents-sdk `ensure_strict_json_schema` `src/agents/strict_schema.py:115`).
- 2+ providers → canonical + transformer registry keyed by `ProviderType`/`ModelProfile` (pydantic-ai `profiles/google.py:245`, crewai sanitizers). Add warning when constraints are stripped.

**Choose OpenAPI strategy:**
- Today no source provides import — plan to build or adopt one. If you serve an API, export via Fern/FastAPI/served handler (langfuse `fern/fern.config.json:1`, letta `server/rest_api/app.py:136`, temporal `service/frontend/openapi_http_handler.go:17`). For ingestion, create `from_openapi(spec, operationId) → Tool` using `openapi-pydantic` (pydantic-ai `uv.lock:4221` already vendors it) and route through `Tool.from_schema` (`pydantic_ai_slim/pydantic_ai/tools.py:437`).

**Choose MCP direction by role:**
- If you are a tool *provider* for IDE agents, implement stateless Streamable HTTP server with `ToolRegistry` + annotations (langfuse pattern).
- If you are a harness *consuming* tools, implement transport-agnostic client; do not build both unless you bridge (e.g., temporal Nexus↔MCP shim `common/nexus/mcp/` proposed).

## Practical Tips

**Patterns to copy:**
- Derive JSON Schema from typed code (Pydantic/Zod) and expose raw dict escape hatch via `@tool(schema=dict)` (`agent-framework/_tools.py:1135`) or `Tool.from_schema` (`pydantic_ai_slim/pydantic_ai/tools.py:437`) — lets power users supply 2020-12 features without forking.
- Vendor OTLP proto as pre-compiled output to avoid Next.js/bundling issues (langfuse `web/src/pages/api/public/otel/otlp-proto/generated/root.ts:1` + `README.md:3`).
- Expand env vars `${VAR:-default}` at MCP config load (`pydantic_ai_slim/pydantic_ai/mcp.py:642` `_ENV_VAR_PATTERN`, letta `letta/functions/mcp_client/types.py:14`) for secrets without code.
- Wrap `defineTool` with dual validation (`baseSchema` for wire, `inputSchema` refinements for runtime `web/src/features/mcp/core/define-tool.ts:170`) and test union/intersection rejection (`web/src/__tests__/server/unit/mcp-define-tool.servertest.ts:6`).
- Expose `disable_mcp`/`disable_meta` flags in deployment config (`libs/cli/langgraph_cli/schemas.py:471`, `libs/cli/langgraph_cli/schemas.py:484`) to gate protocol surface per env.

**Patterns to delay until needed:**
- Progressive disclosure (`agent-framework _mcp.py:884`) — only after >20 tools or context pressure measured.
- `fastmcp-tasks` extension (`pydantic_ai_slim/pydantic_ai/mcp.py:95`) — only for long-running tools; stateless sessions cannot fire server-initiated handlers (`pydantic_ai_slim/pydantic_ai/mcp.py:1208` warns).
- Multi-transport support — start with Streamable HTTP, add stdio only if spawning subprocesses (letta disables stdio by default `letta/settings.py:45` for multi-tenant safety).

**Caution signs the design is becoming brittle:**
- Two MCP adapters diverge (`crewai mcp_adapter.py:26` legacy `mcpadapt` vs `mcp/client.py:59` native — HTTP missing in legacy).
- `normalize_mcp_schema` depth `max_depth=10` silently returns unresolved `$ref` (`letta/functions/schema_generator.py:790`) — schema appears valid but provider rejects at call time.
- OTLP endpoint hard-coded to vendor (`crewai telemetry.py:71` `CREWAI_TELEMETRY_BASE_URL`) — users cannot ship traces to their collector without forking.
- `additionalProperties:false` by default (`internal/genjsonschema/genjsonschema.go:170`) silences extra fields on nested defs (`internal/genjsonschema/genjsonschema_test.go:429`).
- `Tool` sandbox timeout `180s` vs MCP `30s`/`60s` (`letta/settings.py:36` vs `41`) — inconsistent timeout model.

## Anti-Patterns / Caution Signs

- **Telemetry that swallows errors.** `SafeOTLPSpanExporter.export` returns `FAILURE` silently (`lib/crewai/src/crewai/telemetry/telemetry.py:71`) and `Telemetry._safe_telemetry_operation` swallows (`lib/crewai/src/crewai/telemetry/telemetry.py:267`); operators never learn the collector is down. Mirror is agent-framework's `skipif` when OTLP deps absent (`python/packages/core/tests/core/test_observability.py:1009`) — durability depends on extras.
- **Global `TracerProvider` contamination.** crewai explicitly avoids global install (`lib/crewai/src/crewai/telemetry/telemetry.py:173`), temporal provides per-service providers (`temporal/fx.go:13`); violating this leaks spans between tenants.
- **Deny-by-default sampling as afterthought.** Without `sampling_approval_callback`, MCP `sampling/createMessage` is denied (`python/packages/core/agent_framework/_mcp.py:505`) — but `function_invocation_kwargs` can smuggle secrets to any MCP server declaring that property (`python/packages/core/AGENTS.md` MCPTool notes).
- **Schema healing without audit log.** Stripping `minimum`/`maximum`/`pattern` for Anthropic/Bedrock (`lib/crewai/src/crewai/utilities/pydantic_schema_utils.py:626`) with no warning hides fidelity loss.
- **In-memory tool list without pagination.** `toolRegistry.getToolDefinitions` returns all enabled tools (`web/src/features/mcp/server/registry.ts:117`); beyond 50 tools MCP `ListTools` pagination is missing, risking truncated discovery.
- **Metrics endpoint as empty 200.** `POST /api/public/otel/v1/metrics` returns `fn: async () => {}` (`web/src/pages/api/public/otel/v1/metrics/index.ts:12`) — client believes ingestion succeeded.
- **Auth sniff via substring.** MCP health `AUTH_FAILURE_TEXT` regex (`\b401\b|unauthorized`) (`src/api/mcp-health/probe-mcp-server-health.ts:52`, `letta services/mcp/streamable_http_client.py:63`) retry-classifies incorrectly on novel payloads.
- **`__root__` single-key collapse.** LangGraph `StateGraph._get_json_schema` collapses single `__root__` to `RootModel` (`libs/langgraph/langgraph/graph/state.py:1956`) — OpenAPI validators expecting object get wrapped value schema.

## Notable Absences

- **OpenAPI → tool importer: absent in 10/10.** No `import_openapi`, `OpenAPIToolkit`, `from_openapi` implementation found (negative greps: crewai `lib/crewai/src` zero hits, langgraph `libs/` zero hits, openai-agents-sdk `src/agents` zero hits, temporal `service/frontend/openapi_http_handler.go` is serve-only, langfuse `package.json:41` `openapi:export` is export-only). Every REST integration requires a bespoke `BaseTool`/`Tool` adapter, despite `openapi-pydantic` being available transitively (`pydantic-ai uv.lock:4221`).
- **MCP resources/prompts: present in only 2/10 as runnable code.** Only openai-agents-sdk (`src/agents/mcp/server.py:651`) and pydantic-ai (`pydantic_ai_slim/pydantic_ai/mcp.py:167` `Resource`/`Prompt` wrappers) implement `list_resources`/`read_resource`/`list_prompts`/`get_prompt`; langfuse explicitly `capabilities: { tools: {} }`, crewai lists but never surfaces (`lib/crewai/src/crewai/mcp/client.py:615` exists, `MCPToolResolver` never exposes), langgraph none.
- **MCP server + client in same repo: 0/10.** No source is bidirectional; langfuse is server-only, five harnesses are client-only, langgraph/openhands proxy only, opa/temporal none. No shim translates `tools/list` ↔ `nexus.Service` or `ToolRegistry` ↔ `MCPServer`.
- **OTLP HTTP/protobuf: minority.** Only agent-framework (`observability.py:422` handles both with `/v1/{signal}` auto-append) and opa (`distributedtracing.go:128` both `otlptracegrpc` + `otlptracehttp`) support both; temporal and letta reject HTTP (`common/telemetry/config.go:403`, `letta/otel/tracing.py:14` gRPC only); langfuse worker/web use HTTP only (`web/src/observability.config.ts:115`).
- **Portable `ProtocolAdapter` interface: 0/10.** Letta notes `No generic protocol adapter registry` (`letta/services/tool_executor/mcp_tool_executor.py:5` vs `composio`), temporal suggests `common/nexus/mcp/` shim but not built; each new protocol gets a new executor.
- **JSON Schema Draft alignment:** Opa vendors Draft 4/6/7 (`internal/gojsonschema/draft.go:24`) but generates 2020-12 (`internal/genjsonschema/genjsonschema.go:1`) — generated schemas cannot be validated by own validator; langfuse `z.toJSONSchema({target:"draft-7"})` bans unions (`define-tool.ts:138`) while pydantic-ai `JsonSchemaTransformer` handles `allOf/anyOf/oneOf` with `$defs` inlining — draft mismatches across ecosystem.
