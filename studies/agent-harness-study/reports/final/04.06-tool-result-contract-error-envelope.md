## Executive Summary

Across all seven sources, one convergence is nearly universal: **a failed tool call becomes model-readable feedback rather than a crash**. Every framework catches tool exceptions at an invocation boundary and re-emits them as a tool result the model can act on — agent-framework's central catch in `_auto_invoke_function`, langgraph's `ToolMessage(status="error")`, letta's `get_friendly_error_msg` funnel, pydantic-ai's `RetryPromptPart`, openai-agents-sdk's `failure_error_function`, crewai's i18n error strings, and openhands' MCP `mask_error_details=True`.

What separates the high scorers from the low scorers is *how* that feedback is structured and protected:

- **pydantic-ai (8)** makes failure a distinct message part (`RetryPromptPart`) so success and failure are different types, not different field values.
- **langgraph (8)** keeps one envelope type but gives it a first-class `status="error"` flag, centrally templated messages, and chat-history validation that enforces call/result pairing.
- **openai-agents-sdk (8)** accepts anything stringifiable but pairs it with deep trace/log redaction (exception-graph scrubbing), timeout-as-result defaults, and typed rejection envelopes per tool family.
- **letta (7)** enforces a typed two-layer envelope (executor-internal `ToolExecutionResult` → persisted `ToolReturn` → packaged `{"status": "OK"|"Failed"}` JSON) through a single error-normalization funnel.
- **agent-framework (7)** normalizes everything into a uniform `Content(type="function_result")` envelope with `exception=` as the discriminator, and is the only source shipping default-capable compaction strategies for large results.
- **openhands (6)** owns only the control plane: the tool contract lives in an external SDK, so this repo contributes strong serialization-layer secret redaction and transport-level MCP masking, but no LLM-output safeguards.
- **crewai (4)** reduces everything to a string detected by prefix — workable, but its text path forwards raw `repr(e)` into model-visible observations, has no redaction layer, and discards MCP's `isError` flag at the wrapper boundary.

The weakest capability across the entire cohort is **large-result handling**: only agent-framework ships composable summarization/eviction strategies; letta caps by character count; openai-agents-sdk mandates truncation only in its shell/sandbox stack with everything else opt-in; langgraph, pydantic-ai, crewai, and openhands punt entirely to the application or an external layer.

## Core Thesis

A failed tool call becomes useful feedback rather than a crash when three contracts hold simultaneously:

1. **One funnel** — every failure path flows through a single normalization point, so formatting, capping, and redaction are enforced once instead of hoped for at each raise site.
2. **Dual signaling** — success/failure is conveyed both structurally (a status flag, part kind, or exception field) and textually (an `"Error"`-prefixed message), because models are trained on error-prefixed tool outputs and downstream consumers need non-parseable signals.
3. **Detail separation by construction** — internal detail (tracebacks, chained causes, injected arguments) is kept out of the model-facing envelope by the shape of the code, not by developer discipline.

Sources that enforce all three — pydantic-ai, langgraph, letta, agent-framework, openai-agents-sdk — cluster at 7–8. Sources that rely on convention (crewai's string prefixes) or delegate the contract across an ownership boundary (openhands' external SDK dependency) score 4–6. The pattern holds regardless of product shape: library, server, or platform.

The corollary: **the dimension's biggest unsolved problem is size, not errors.** Error envelopes are comparatively mature everywhere; large results are handled safely almost nowhere by default.

## Approach Models

Three envelope archetypes emerge, plus two boundary-condition variants:

**1. Uniform envelope, error as a field** (langgraph, letta, agent-framework). One result type carries both outcomes; failure is signaled by a field value (`ToolMessage.status`, `ToolExecutionResult.status`, `Content.exception`). This keeps the chat-history schema homogeneous and serialization trivial, at the cost of consumers needing to check a field rather than a type. LangGraph strengthens the field with centralized templates (`TOOL_CALL_ERROR_TEMPLATE = "Error: {error}\n Please fix your mistakes."`, `libs/prebuilt/langgraph/prebuilt/tool_node.py:111`); agent-framework layers a redundant textual prefix onto the `exception=` field (`python/packages/core/agent_framework/_tools.py:1520-1569`); letta packages the whole thing into a model-visible JSON string with an explicit `status` key (`letta/system.py:150-168`).

**2. Distinct error type in a tagged union** (pydantic-ai). Failure gets its own message part — `RetryPromptPart(part_kind='retry-prompt')` — inside a Pydantic discriminated union alongside `ToolReturnPart(part_kind='tool-return')` (`pydantic_ai/messages.py:2036-2044`). The model literally receives a different kind of message asking it to retry, carrying either a plain string or structured validation `ErrorDetails`. This is the strongest form of "model-readable error": the failure channel cannot accidentally carry a traceback because the part's `model_response()` strips context fields by construction (`pydantic_ai/messages.py:1446-1468`).

**3. Errors-as-results over flexible outputs** (openai-agents-sdk). There is no universal envelope; tools may return strings or validated structured outputs (`ToolOutputText/Image/FileContent`), and failures are intercepted by a configurable formatter and returned *as the result* (`src/agents/tool.py:653-667,1863-1872`). Timeouts default to `error_as_result`; approval rejections become realistic typed items (shell rejections synthesize `stderr` + `exit_code: 1` so the provider payload stays valid). The tradeoff is deliberate: maximum authoring ease and provider-shape fidelity, minimum cross-tool uniformity.

**Boundary variants.**

- **String-prefix convention** (crewai): the "envelope" is an i18n template rendered into a plain string (`lib/crewai/src/crewai/translations/en.json:45-56`); the model infers failure from the leading `"Error executing tool:"`. This works until exceptions carry `repr(e)` with chained causes — which the text path forwards verbatim (`lib/crewai/src/crewai/tools/tool_usage.py:428-437`).
- **Delegated contract** (openhands): the app server consumes SDK-defined events and contributes transport-level masking (`FastMCP('mcp', mask_error_details=True)`, `openhands/app_server/mcp/mcp_router.py:43`) plus aggressive outbound secret redaction, but does not own the tool-result schema itself (`openhands/app_server/event_callback/webhook_router.py:56-60`).

## Pattern Catalog

### P1. Centralized error-normalization funnel

- **Problem:** Without a single conversion point, every raise site invents its own model-facing format, and any global policy (capping, redaction, prefixing) must be reimplemented per site.
- **Demonstrated by:** letta (`get_friendly_error_msg`, called from core/sandbox/files/MCP/builtin/composio executors, capped at `MAX_ERROR_MESSAGE_CHAR_LIMIT=1000`, `letta/utils.py:1091-1097`, `letta/constants.py:430`); langgraph (`_handle_tool_error` / `_default_handle_tool_errors` route every failure — direct exception, validation, wrapper failure, invalid tool name — through one template, `libs/prebuilt/langgraph/prebuilt/tool_node.py:383-441`); pydantic-ai (`ToolRetryError` as the single internal control-flow carrier for both tool-validation and output-validation paths, `pydantic_ai/exceptions.py:273-305`).
- **Why it works:** Changes to error formatting, length caps, or redaction happen in one place and are testable with a handful of unit tests (letta pins truncation semantics at `letta/tests/test_utils.py:672-689`; langgraph covers every `handle_tool_errors` branch at `libs/prebuilt/tests/test_tool_node.py:269-602`).
- **Copy when:** You have more than two execution paths producing tool results.
- **Overkill when:** A single tool-invocation site exists (rare outside toy harnesses).

### P2. Dual signaling: structural flag plus textual prefix

- **Problem:** Models parse tool output as text, but programs need non-parseable signals.
- **Demonstrated by:** Nearly everyone, in stronger or weaker forms. langgraph sets `status="error"` *and* renders `"Error: ..."` (`tool_node.py:1007-1012`); letta sets the JSON `"status": "OK"|"Failed"` key *and* prefixes friendly text (`letta/system.py:150-168`, `letta/utils.py:1091-1097`); agent-framework sets `exception=` *and* prefixes `"Error: ..."` (`_tools.py:1476-1569`); crewai has only the prefix.
- **Why it works:** Redundancy survives lossy hops. When a provider adapter drops custom fields (see openai-agents-sdk dropping non-text content on Chat Completions, `src/agents/models/chatcmpl_converter.py:819-855`), the textual cue still reaches the model.
- **Copy when:** Always. The prefix costs nothing; the flag is what generic consumers branch on.
- **Risk:** Prefix-only signaling (crewai) silently degrades if template wording drifts — there is no contract test protecting the vocabulary (`lib/crewai/tests/tools/agent_tools/test_agent_tools.py:112-125` asserts substrings only).

### P3. Redaction-by-default vs leak-by-default

- **Problem:** Exception messages routinely contain paths, tokens, and internal hostnames; tracebacks contain source structure useful to attackers and confusing to models.
- **Demonstrated by:** Three postures. **Safe default:** agent-framework's `include_detailed_errors=False` yields generic `"Error: Function failed."` unless opted in (`_tools.py:1344-1411`, tests at `test_function_invocation_logic.py:1710-1780`); openai-agents-sdk redacts traces/logs deeply — clearing exception args, `__cause__`, and `__context__` at public boundaries — while keeping actionable `str(error)` in the model channel (`src/agents/util/_tool_errors.py:5-14`, `src/agents/exceptions.py:315-405`). **Leak-by-default:** langgraph's default envelope uses `repr(e)` (`tool_node.py:430`) and crewai's text path f-string-formats the raw exception into i18n templates (`tool_usage.py:428-437`).
- **Why safe defaults win:** The detailed path is available for self-correction when needed, and forgetting to configure it fails closed, not open. Agent-framework additionally gates telemetry-side payload capture behind `ENABLE_SENSITIVE_DATA` (`observability.py:1146-1165`).
- **Copy when:** Any multi-tenant, production, or security-sensitive deployment.
- **Tradeoff note:** openai-agents-sdk's split is the most sophisticated — it treats traces/logs and the model as different audiences with different policies — but its model-facing default still embeds raw `str(error)` deliberately for self-correction (`src/agents/tool.py:1872`).

### P4. Large-result management as a separable layer (or an absent one)

- **Problem:** A single verbose tool result can evict useful context or exceed provider limits.
- **Demonstrated by:** agent-framework alone treats this as a framework concern: `ToolResultCompactionStrategy` collapses old tool-call groups into summaries, composed by `ContextWindowCompactionStrategy` under token pressure, on both Python and .NET stacks (`_compaction.py:1314-1419`, `Microsoft.Agents.AI/Compaction/ContextWindowCompactionStrategy.cs:72-108`). openai-agents-sdk mandates truncation in its shell/sandbox stack (token/byte budgets, head+tail preservation, explicit `…N tokens truncated…` markers, `src/agents/sandbox/util/token_truncation.py:89-113`) but makes general trimming an opt-in `call_model_input_filter` (`tool_output_trimmer.py:87-135`). letta caps per-tool with `return_char_limit` (default 50k chars) applied at the manager (`tool_execution_manager.py:124-129`). langgraph, pydantic-ai, crewai, and openhands ship extension points (`pre_model_hook`, `history_processor`, context-overflow-only `summarize_messages`) but no default policy.
- **Why layered wins:** Tools stay ignorant of context pressure; the policy evolves independently and composes (summarize → evict → truncate).
- **Copy when:** Long-running agents with many tool turns.
- **Caution:** Character-based caps (letta's own future-work list notes this) can still admit 12k+ tokens; semantic summarization exists nowhere in this cohort as a default.

### P5. Call-ID binding with pairing enforcement

- **Problem:** A result not bound to its call corrupts protocol state and breaks replay.
- **Demonstrated by:** langgraph raises `INVALID_CHAT_HISTORY` whenever an `AIMessage.tool_calls[id]` lacks its paired `ToolMessage` before the model sees history (`chat_agent_executor.py:243-271`); pydantic-ai generates a `tool_call_id` when the model omits one so retries still match (`messages.py:1123-1127`); openai-agents-sdk prunes orphaned calls on resume so histories stay protocol-valid (`tests/test_run_internal_items.py:64-179`); letta shipped a production-incident migration (`backfill_missing_tool_call_ids`) after real messages lost IDs (`letta/services/message_manager.py:30-114`).
- **Why it works:** Pairing errors are caught at ingestion time, not mid-conversation; letta's migration is direct evidence that this fails in production without enforcement.
- **Copy when:** Always — this is table stakes proven by incident.

### P6. Control flow is not failure

- **Problem:** Interrupts, approvals, cancellations, and user-input pauses must not be converted into error envelopes or retried.
- **Demonstrated by:** langgraph always re-raises the `GraphBubbleUp` family unwrapped (`tool_node.py:973-983`); pydantic-ai documents `ToolRetryError`/`SkipToolValidation` as control-flow exceptions distinct from user-facing errors (`exceptions.py:133-156,273-283`); agent-framework propagates `UserInputRequiredException` request items rather than wrapping them (`_tools.py:1800-1819`); letta gives cancellation and denial their own constructors (`create_tool_returns_for_denials`, `rest_api/utils.py:230-264`).
- **Why it works:** Conflating pause with failure either kills resumability or teaches the model false lessons about the tool.
- **Copy when:** You have any human-in-the-loop or long-running-task feature.

### P7. Dual-audience data separation

- **Problem:** Applications need more context than the model should see (raw payloads, secrets, app state).
- **Demonstrated by:** openai-agents-sdk persists SDK-only `custom_data` on output items that is never replayed to the model (`items.py:430-452`, `run_state.py:1987-1989`); pydantic-ai splits `ToolReturn` into `return_value` / `content` / `metadata` with metadata app-only (`messages.py:891-918`); letta carries `stdout`/`stderr` as first-class side fields whose model visibility depends on the adapter (`letta_message.py:47-48`).
- **Why it works:** Replay stays faithful while the model channel stays clean — provided the side channel genuinely cannot reach the model (see letta's caveat below).
- **Copy when:** Your persisted history doubles as an application database.

## Key Differences

**Where the error type changes.** pydantic-ai is the only source where failure produces a *different type* of model-bound message. langgraph and letta keep the type and flip a field; agent-framework flips a field plus a text prefix; openai-agents-sdk and crewai change only the content. The practical consequence: downstream consumers of pydantic-ai can route on part kind with zero string parsing; consumers of crewai must parse prefixes against templates that have no contract test.

**Where redaction happens.** At construction (pydantic-ai strips `ctx`/`input` in `RetryPromptPart.model_response()`; openai-agents-sdk scrubs exception graphs at public boundaries), at configuration (agent-framework's `include_detailed_errors=False` default), at the transport (openhands' blanket `mask_error_details=True`, too coarse for per-tool nuance), in a side field (letta's stderr, whose model visibility is adapter-dependent — the report explicitly found no central stripper), or nowhere (crewai's text path). Construction-time is the only posture that survives someone forgetting a flag.

**Who handles size.** A strategy layer (agent-framework), a mandatory subsystem (openai-agents-sdk shell/sandbox), a per-tool cap (letta), or nobody (langgraph, pydantic-ai, crewai, openhands). Notably, the sources that handle size best are those operating long-lived sessions where context pressure is guaranteed; the pure-library sources assume the application will compose something.

**MCP `isError` treatment diverges instructively.** agent-framework elevates it to `ToolExecutionException` so the standard catch produces the uniform envelope (`_mcp.py:1690-1739`) — safe, but it breaks pass-through for servers using error-as-data. pydantic-ai converts it to `ModelRetry(str(e))` prefixed `"Error executing tool {name}: ..."` (`toolsets/fastmcp.py:264-271`). crewai's client correctly reads `isError` into `_MCPToolResult(content, is_error)` and then throws the flag away at the wrapper boundary — the model receives the content as if successful (`mcp/client.py:464-495`). openhands masks the details wholesale at the server. langgraph's report found no evidence of MCP mapping in the searched path. Four frameworks, four answers to the same protocol question.

**Replay depth.** All seven persist results keyed by call IDs, but fidelity differs: langgraph checkpoints errors themselves as `(ERROR, exception)` writes that survive resume (`_runner.py:579-603`); openai-agents-sdk persists SDK-only custom data and prunes orphans; pydantic-ai round-trips every part through one canonical `ModelMessagesTypeAdapter`; crewai caches successes only — failures always re-execute, and replay does not reconstruct cache state (`crew.py:1918-1935`). LangGraph's report also flags that checkpoint replay re-executes the tool body rather than replaying recorded output — a correctness hazard for non-idempotent tools that no source fully solves.

## Tradeoffs

**Self-correction vs leakage.** openai-agents-sdk deliberately includes raw `str(error)` in the model-facing default because it maximizes retry quality, accepting an exfiltration surface that apps must close with custom formatters (`src/agents/tool.py:1872`). agent-framework makes the opposite call — generic messages by default — accepting worse self-correction when integrators forget the opt-in flag (`_tools.py:1344-1398`). langgraph and crewai get the worst of both: enough detail to leak (`repr(e)`) without a policy controlling it.

**Uniformity vs authoring ease.** CrewAI's string-everywhere contract lets any result splice into ReAct observations and any provider accept it (`utilities/agent_utils.py:616`), but forces every consumer — LLM, cache, telemetry — onto one lossy representation and pushes all safety burden to tool authors. openai-agents-sdk's strings-first-with-opt-in-structure lands in the middle; pydantic-ai's always-typed parts cost the most authoring ceremony but give the strongest guarantees. Letta shows the platform resolution: enforce the envelope at the executor boundary where the framework, not the tool author, controls the code (`tool_executor_base.py:16-46`).

**Single envelope vs error subtype.** agent-framework's own future-work section argues for promoting a first-class error content type, noting today's scheme means "a typo in the prefix silently degrades observability" (source report, Tradeoffs). pydantic-ai demonstrates the payoff of the subtype — but pays with its own wrinkle: `outcome='failed'` exists on `ToolReturnPart` yet is never set on the main path (failures travel as `RetryPromptPart`s), so consumers filtering on `outcome` alone miss them (`_agent_graph.py:2004-2009`).

**Transport-level masking vs granularity.** openhands' single `mask_error_details=True` toggle guarantees nothing internal reaches MCP clients, but also masks legitimately actionable failures like "missing required arg `path`" identically to stack traces (`mcp_router.py:43`, source report Failure Modes). agent-framework's elevation of `isError` to exception has the same flavor: uniformly safe, occasionally opaque.

**Mutation-based vs view-based compaction.** agent-framework's strategies rewrite `messages` in place, which its own report flags as complicating transactional replay (`_compaction.py:900-903` retains summary keys as partial mitigation). openai-agents-sdk's trimmer operates only at model-call time and never touches persisted items (`tool_output_trimmer.py:136-142`) — cleaner replay semantics, at the cost of re-trimming every call.

**Side channels vs guarantees.** letta preserves tracebacks in `stderr` "demoted to telemetry, not deleted" — valuable for operators, risky because visibility to the model depends on which LLM adapter renders the payload, with no central policy (`e2b_sandbox.py:137`, source report Answers Q3).

## Decision Guide

Choose your envelope archetype by product shape and ownership:

- **You own the full runtime (platform/server):** Follow letta. Define one typed executor-return envelope, force every executor through it, normalize errors through one funnel with a hard cap, and package a model-visible form with an explicit status key at the persistence boundary.
- **Library consumed by unknown applications:** Follow pydantic-ai or langgraph. Make failure a distinct, discriminated part (or a flagged message) produced by a centralized handler, expose knobs (langgraph's `handle_tool_errors` accepting bool/str/callable/tuple-of-types is the most complete knob design seen, `tool_node.py:622-739`), and validate pairing at history-ingestion time.
- **SDK optimized for provider fidelity:** Follow openai-agents-sdk. Accept flexible outputs, convert failures to results through a configurable formatter, keep per-family envelopes type-valid, and invest the savings into redaction depth and replay hygiene.
- **Control plane around someone else's runtime:** Follow openhands' strengths — serialize-and-redact aggressively at your boundary, mask at the transport — but treat the missing tool-output safeguards as a known risk to escalate to the owning team, not a solved problem.
- **Avoid:** Prefix-only string contracts (crewai) unless your execution model is literal ReAct text splicing; even then, sanitize `{error}` substitutions before they enter templates.

If forced to one rule: **make the safe path the default path.** Detailed errors, sensitive telemetry, and raw exception text should all require an explicit opt-in, because the failure of forgetting is silent and asymmetric.

## Practical Tips

- **Route every failure through exactly one function** that formats, prefixes, caps length (letta's 1000-char cap is a good floor, `constants.py:430`), and attaches the structural flag. Test the funnel, not each raise site.
- **Pair every structural signal with an `"Error: ..."` prefix.** The prefix is what survives provider adapters and what models were trained on; the flag is what your code branches on.
- **Strip injected/internal context from validation errors before they reach the model.** LangGraph's `_filter_validation_errors` removes `InjectedState`/`InjectedStore`/`ToolRuntime` errors because they describe values the model doesn't control (`tool_node.py:510-563`) — noise reduction, tested explicitly (`test_tool_node_validation_error_filtering.py:41-470`).
- **Give timeouts and denials their own envelopes**, not generic ones. openai-agents-sdk synthesizes realistic failure shapes (shell rejection = `stderr` + `exit_code: 1`) so provider payloads stay valid (`run_internal/items.py:852-872`); letta distinguishes `[ToolConstraintError]` rule violations from crashes (`helpers.py:501-505`).
- **Bound retries per tool, not globally.** Pydantic-ai's per-tool budget means one bad tool can't poison others (`tests/test_agent.py:11199-11220`); agent-framework adds a consecutive-error circuit breaker forcing `tool_choice="none"` after 3 failures (`_tools.py:2632-2644`).
- **Split large artifacts out of the result body.** Pydantic-ai replaces file bodies with `'See file {identifier}.'` placeholders for text-only providers and sends files as follow-up user content (`messages.py:1271-1297`); agent-framework links hosted files/vector stores by reference (`_types.py:944-982`). Even a crude version beats inlining base64 (crewai's `ReadFileTool`, source report).
- **Persist errors and control-flow distinctly** — langgraph writes `(ERROR, exception)` but saves interrupts as `(INTERRUPT, ...)` (`_runner.py:584-603`) — so resume logic never mistakes a pause for a crash.
- **Add a checksum or framing protocol at sandbox/process boundaries.** Letta's length-prefix + MD5 marker parsing detects corrupted subprocess payloads and degrades to a friendly "output is corrupted" error (`local_sandbox.py:253-275`).

## Anti-Patterns / Caution Signs

- **F-string-formatting raw exceptions into model-visible templates.** CrewAI's `error=e` substitution forwards `repr(e)` with chained causes straight into the next observation (`tool_usage.py:428-437`). If your error path contains `.format(error=e)` or `f"{e!r}"` without a sanitizer, you have leak-by-default.
- **Reading a protocol error flag and dropping it.** CrewAI's MCP client builds `_MCPToolResult(content, is_error)` and returns `content` unconditionally (`mcp/client.py:495`) — the model sees failures as successes. Any wrapper that unwraps a richer result into a narrower one should propagate the discriminator.
- **Two coexisting error conventions.** LangGraph's deprecated validator uses `additional_kwargs["is_error"]` while modern code uses `status="error"` (`tool_validator.py:208-214`); consumers must check both during migration. Letta similarly carries deprecated singular tool-return fields beside the list form. Duplicated envelopes mean duplicated bugs.
- **Console-only truncation.** CrewAI previews `result[:200]` for humans while the model receives the full string (`agent_utils.py:1614`) — a false sense of safety. Truncation that doesn't apply at the model boundary isn't a safeguard.
- **Silent fallbacks that break contracts.** CrewAI falls back from schema-validated JSON to `str(raw_result)` with only a `RuntimeWarning` (`structured_tool.py:73-82`); the model can't tell the structured contract broke. Compare openai-agents-sdk raising `UserError` on schema violations — loud beats silent for contract drift.
- **Blanket toggles where per-tool policy is needed.** OpenHands' server-wide `mask_error_details=True` cannot expose actionable argument errors for one tool while hiding stack traces for another (`mcp_router.py:43`).
- **Side channels without a boundary policy.** Letta's stderr reaches the model depending on adapter rendering, with no central stripper (source report Q2). If visibility of a field is "whatever the renderer does," treat it as exposed.
- **Hook errors swallowed silently.** CrewAI logs hook exceptions and proceeds with the original value (`tool_utils.py:115-141`) — meaning a failing *redaction* hook leaks the very content it was guarding. Security-relevant hooks should fail closed.

## Notable Absences

Gaps confirmed missing across multiple sources by their reports:

- **Default semantic summarization of tool results** exists nowhere. Agent-framework summarizes mechanically (template collapse), letta truncates by character, openai-agents-sdk trims by window — none condense meaning, and four sources do nothing at all.
