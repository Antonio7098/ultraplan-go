## Executive Summary

No studied harness ships a single object called a "scratchpad." A repo-wide search for `scratchpad`/`working_memory` symbols returns nothing meaningful in five of seven sources (the exceptions are langgraph's internal `PregelScratchpad` and incidental docstrings elsewhere). Instead, every harness decomposes working memory into several structures with different lifetimes, audiences, and durability rules — and the decisive design choice is **where each structure sits on the private↔visible axis**, not whether it exists.

Three families emerge. **Infrastructure-hidden scratchpads** (langgraph's per-task `PregelScratchpad`, openai-agents-sdk's `RunContextWrapper`/`RunState`, pydantic-ai's `GraphAgentState`) keep counters, staged input, approval records, and derived sets strictly out of the model's view, exposing only narrow projections (managed values like `RemainingSteps`). **Model-visible task state** (agent-framework's `TodoProvider` + mode provider, crewai's `AgentExecutorState` plan/todos/observations, openhands' `TaskTrackerAction`) gives the model an explicit, injectable task list that may also surface to users. **Shared durable working memory** (letta's memory blocks, partially agent-framework's `FileMemoryProvider`) makes working notes a first-class, user-editable, database-backed artifact rendered into the prompt itself.

The dimension's core question — *can the agent think over multiple steps without confusing working notes with facts?* — is answered by four recurring defenses: (1) typed separation of notes from facts inside one container (`ThinkingPart` vs `TextPart` in pydantic-ai, plan/todos fields vs messages in crewai, `_generated_items` vs `_session_items` in openai-agents-sdk); (2) distill-before-persist gates so only extracted facts reach long-term memory (crewai, agent-framework, letta's sleeptime curation); (3) controlled promotion queues that convert private notes into model-visible content only at declared drain points (agent-framework, pydantic-ai, openai-agents-sdk); and (4) provenance/attribution stamping so injected notes remain distinguishable from genuine user input (agent-framework `_attribution`, pydantic-ai planted-key stamps, openhands planning-agent flags).

Maturity tracks failure engineering, not feature count. Letta (9) wins on write-through durability, change-gated rebuilds, and git-grade audit trails; agent-framework (8) and openai-agents-sdk (8) on atomic writes, versioned snapshot schemas, and tested crash/concurrency matrices. The common weakness across all seven is hygiene enforcement: todo lifecycle, scratch-vs-durable boundaries, and sensitive-content screening are mostly advisory (prompts, conventions, opt-in flags) rather than structurally guaranteed, and no source provides defense-in-depth redaction between scratch content and observability channels.

## Core Thesis

Working memory in agent harnesses is converging on a **layered visibility contract**: each layer of scratch state declares who can see it (nobody / model / user), how long it lives (per tool call / per run / per task / forever), and how it becomes model-visible (never / projection / injection at a drain point / compilation into the prompt). The rubric question "can the agent think without confusing notes with facts?" is answered well only when all three declarations exist and are *enforced* — by types, by serialization boundaries, or by architecture rather than by prompt instructions.

Four quality signals distinguish the top sources:

1. **Notes enter the model only through declared injection points.** Every mature source funnels scratch content into the conversation via a controlled mechanism — `before_run` provider injections stamped with attribution metadata (agent-framework, `python/packages/core/agent_framework/_sessions.py:624-690`), drain-point queues (pydantic-ai, `pydantic_ai_slim/pydantic_ai/capabilities/_pending_messages.py:59-178`), or staged pending input (openai-agents-sdk, `src/agents/run_state.py:941-983`). Where notes leak in sideways — appended to shared task descriptions (crewai legacy path, `lib/crewai/src/crewai/agent/utils.py:55`) — pollution follows.

2. **Durability is a tier decision, not an accident.** The best sources enumerate lifetimes explicitly: per-turn, per-run, per-interruption, cross-process (openai-agents-sdk's layered containers; letta's message-buffer-vs-blocks split, `letta/schemas/agent.py:138-142`). Sources with one undifferentiated blob either lose recoverable work (crewai's per-invoke wipe) or accumulate stale notes indefinitely (advisory-only todo clearing in agent-framework).

3. **Long-term memory is guarded by an explicit promotion gate.** Whether LLM-distilled extraction (crewai `lib/crewai/src/crewai/memory/unified_memory.py:667-679`; agent-framework `python/packages/core/agent_framework/_harness/_memory.py:44-68`), curated background-agent integration (letta sleeptime, `letta/groups/sleeptime_multi_agent_v3.py:205-244`), or structural impossibility of writes (langgraph has no scratchpad→checkpoint path; pydantic-ai has no LTM at all), every source prevents implicit scratch→facts promotion. But most gates are prompt-mediated, not structural — the weakest link everywhere.

4. **Reasoning traces get their own lifecycle.** Chain-of-thought is treated as radioactive in four sources: scrubbed from subsequent context windows (letta, `letta/agents/letta_agent_v2.py:760-792`), parked in `provider_details['raw_content']` away from user-facing `content` (pydantic-ai, `pydantic_ai_slim/pydantic_ai/models/openai.py:2317-2344`), excluded from result assembly as "essentially thoughts" (pydantic-ai, `pydantic_ai_slim/pydantic_ai/_agent_graph.py:1982-1998`), or summarized instead of forwarded across handoffs (openai-agents-sdk, `src/agents/handoffs/history.py:44-49`). This is the clearest operationalized instance of "working notes ≠ facts" in the study.

## Approach Models

### Model A — Infrastructure-hidden scratchpad (engine-owned, projected narrowly)

**Sources:** langgraph, openai-agents-sdk, pydantic-ai (runtime tiers).

Working memory exists as runtime machinery the model never sees directly. LangGraph's `PregelScratchpad` rides under a reserved config key ("a mutable dict for temporary storage scoped to the current task", `libs/langgraph/langgraph/_internal/_constants.py:64-65`), tracking loop position and call/interrupt counters, recreated deterministically from checkpoint metadata on every dispatch (`libs/langgraph/langgraph/pregel/_algo.py:1280-1345`). Facts nodes need — `IsLastStep`, `RemainingSteps` — are exposed as managed-value projections computed as pure functions of scratchpad state (`libs/langgraph/langgraph/managed/is_last_step.py:9-24`). OpenAI Agents SDK documents the boundary bluntly: *"Contexts are not passed to the LLM"* (`src/agents/run_context.py:72-81`); approvals, invocation fingerprints, and pending input live behind underscore fields, while the model-visible history is kept as a separate projection (`_generated_items`) distinct from the full record (`_session_items`, `src/agents/run_state.py:782-786`). Pydantic AI marks its private fields "Private implementation detail — not part of the public API" (`pydantic_ai_slim/pydantic_ai/_run_context.py:157-185`).

The payoff is neutrality: no baked-in planning ideology, minimal durable footprint, and clean reasoning about what survives crashes. The cost is that agents wanting visible plan state must build it themselves from ordinary state channels/tools — langgraph prebuilt contains no todo facility at all (source report searched `todo|todos|write_todos` across `libs/prebuilt`: only lockfile noise).

### Model B — Model-visible structured task state (todo tools and executor state machines)

**Sources:** agent-framework, crewai, openhands.

Here the harness takes a position: the model maintains an explicit task list, and the runtime manages its injection and lifecycle. Agent-framework's `TodoProvider` injects instructions, five `todos_*` tools, and the current list as a user-role message each run (`python/packages/core/agent_framework/_harness/_todo.py:505-615`), backed by a swappable `TodoStore` ABC (session-scoped or atomically-written JSON files, `_todo.py:228-443`). Crewai embeds plan/todos/observations in a pydantic `AgentExecutorState` with a status-machine `TodoList` (`lib/crewai/src/crewai/utilities/planning_types.py:27-195`) and replan-aware `replace_pending_todos` that preserves completed/failed history (`planning_types.py:185-195`). OpenHands defines the todo as a wire protocol artifact: `TaskTrackerAction.command: "view"|"plan"` carrying a full-replacement `task_list` (`src/types/agent-server/core/base/action.ts:127-136`), which the UI derives by backwards-scanning the event stream for the latest `plan` observation (`src/hooks/use-task-list.ts:35-48`).

This model makes planning inspectable and loop-controllable (agent-framework's `todos_remaining` predicate drives loop continuation, `python/packages/core/agent_framework/_harness/_loop.py:925-986`), but transfers correctness onto the model's compliance with advisory instructions — there is no runtime-enforced clearing in any of the three.

### Model C — Shared durable working memory (memory-as-product)

**Source:** letta (with agent-framework's `FileMemoryProvider` as a partial instance).

Letta dissolves the private/public distinction entirely: working memory is a set of labeled `Block`s with character budgets (`letta/schemas/block.py:19-20`), compiled into `<memory_blocks>` XML in the system prompt with usage metadata the model can see (`chars_current`/`chars_limit`, `letta/schemas/memory.py:161-166`). The model edits blocks through typed tools (`core_memory_append/replace`, `memory_insert`, `memory_apply_patch` unified diffs, `memory_rethink` full rewrite; `letta/functions/function_sets/base.py:246-527`), each edit persisted synchronously via `update_memory_if_changed_async` (`letta/services/agent_manager.py:1747-1801`). Users get symmetric access over REST (`letta/server/rest_api/routers/v1/agents.py:1206-1377`) — and, for git-enabled agents, commit-per-edit versioning where git is the source of truth and PostgreSQL is a cache (`letta/services/block_manager_git.py:1-33`). Background "sleeptime" agents curate the same shared blocks out-of-band (`letta/groups/sleeptime_multi_agent_v3.py:127-188`).

This maximizes trust, debuggability, and multi-agent coordination — at the price of having no confidential planning space at all, and concurrency resolved by last-writer-wins outside git mode.

### Cross-cutting: the openhands variant

OpenHands applies Model B's visibility stance to a UI-only vantage point: todos, the `PLAN.md` scratchpad (a real workspace file edited by a dedicated planning sub-conversation, `src/hooks/use-handle-plan-click.ts:57-70`), and logged `ThinkAction` thoughts are all first-class rendered artifacts, while the one invisible mechanism is condensation — `CondensationEvent.forgotten_event_ids` is consumed for token accounting but never shown (`src/hooks/use-await-context-compaction.ts:112-138`). It demonstrates that "user-visible working memory" can be an event-sourced projection rather than locally owned state.

## Pattern Catalog

### P1. Namespaced partitioning of a shared state substrate

- **Problem:** Multiple independent working-memory mechanisms (todos, mode, queued messages, history, task registries) must share one serializable store without colliding, and must be individually swappable.
- **Demonstrated by:** agent-framework — every context provider owns a `source_id` namespace inside `AgentSession.state` (`python/packages/core/agent_framework/_sessions.py:1750`), mirrored by the .NET typed `AgentSessionStateBag` (`dotnet/src/Microsoft.Agents.AI.Abstractions/AgentSessionStateBag.cs:21-145`); openai-agents-sdk achieves similar isolation with random scope ids attached to restored checkpoints (`src/agents/run_context.py:130`); openhands keys all client stores by conversation id.
- **Why it works:** Ownership is explicit at the storage layer, so swapping implementations (e.g., `TodoSessionStore` → `TodoFileStore`, `_todo.py:462-480`) never touches other namespaces, and audit can attribute every entry.
- **Copy when:** Composing more than two stateful mechanisms, or when hosts must choose durability per mechanism.
- **Overkill when:** A single-purpose agent with one ephemeral working set — then a plain dataclass (crewai's `AgentExecutorState`) is simpler.
- **Evidence:** `_todo.py:250-253` (store keyed by `session.state[source_id]`); `tests/core/test_harness_todo.py:322` (concurrent-mutation serialization under per-session locks).

### P2. Injection queues drained at declared points

- **Problem:** Mid-run content (external notifications, tool side-channels, deferred messages) must reach the model without corrupting in-flight request construction or appearing at arbitrary times.
- **Demonstrated by:** agent-framework's `MessageInjectionMiddleware` — `enqueue_messages` appends to session state; the middleware drains and clears on the next model call (`python/packages/core/agent_framework/_sessions.py:1364-1380,1419-1429`). Pydantic AI's `RunContext.enqueue` fills `pending_messages`, drained `'asap'` before each request or `'when_idle'` redirected to end-of-run (`pydantic_ai_slim/pydantic_ai/_run_context.py:413-465`; `pydantic_ai_slim/pydantic_ai/capabilities/_pending_messages.py:59-178`). OpenAI Agents SDK stages resumed input in `RunState._pending_input`, admitted only at defined points and rejected in terminal states (`src/agents/run_state.py:941-983`).
- **Why it works:** Promotion from private to model-visible happens at exactly one code path per framework, making ordering testable and leakage auditable (~20 enqueue tests in pydantic-ai, `tests/test_capabilities.py:16719-17804`).
- **Copy when:** Any external event source (human input, background tasks, timers) must influence a running loop.
- **Risky when:** Drain timing is left to the model or to ad-hoc tool calls instead of the runtime — then delivery order becomes unspecified.

### P3. Recompute-over-persist (derive working state from the durable record)

- **Problem:** Runtime facts the model depends on (loop position, budget remaining, which tools/capabilities were revealed) must survive restarts and failover without bloating checkpoints.
- **Demonstrated by:** langgraph — the scratchpad is rebuilt per dispatch from checkpoint metadata; `step` restores as `metadata["step"] + 1` (`libs/langgraph/langgraph/pregel/_loop.py:1700-1701`), and managed values stay correct because they are pure functions of reconstructed state (`libs/langgraph/langgraph/pregel/_checkpoint.py:246-277` excludes them from hydration). Pydantic AI re-parses `discovered_tool_names`/`loaded_capability_ids` from message history before each request (`pydantic_ai_slim/pydantic_ai/_run_context.py:225-252`) and instructs capability authors to derive state from `post_compaction_window` "rather than remembering it in instance attributes, so it self-heals when compaction replaces the history that carried it" (`messages.py:2782-2787`).
- **Why it works:** There is exactly one source of truth (the durable record); derived caches can be discarded freely, eliminating an entire class of cache-invalidation bugs across compaction and provider fallback.
- **Copy when:** Building engines with checkpoint/replay semantics, or anything that must survive provider failover.
- **Cost:** Parse work per request, and correctness couples to history fidelity — a history processor that drops reveal records silently hides tools again (documented at `pydantic_ai_slim/pydantic_ai/.agents/skills/building-pydantic-ai-agents/references/ON-DEMAND-CAPABILITIES.md:125`).

### P4. Distill-before-persist promotion gate for long-term memory

- **Problem:** Transient scratch work must not silently become durable "facts."
- **Demonstrated by:** crewai extracts discrete memories via LLM analysis before storing, skipping delegation outputs (`lib/crewai/src/crewai/agents/agent_builder/base_agent_executor.py:42-63`). Agent-framework's extraction prompt forbids promoting "transient tasks, temporary reminders, one-off outputs, or tool chatter," and consolidation drops stale/transient items (`python/packages/core/agent_framework/_harness/_memory.py:44-68`). Letta promotes conversation facts only through curated sleeptime-agent edits under its own prompts (`letta/groups/sleeptime_multi_agent_v3.py:205-244`). Langgraph and pydantic-ai make pollution structurally impossible: no scratchpad write path into checkpoints/Store exists (`libs/langgraph/langgraph/pregel/_checkpoint.py:265-277`), and pydantic-ai assigns LTM entirely to application code (`SEMANTIC-GAPS.md:113-120`).
- **Why it works:** Promotion requires deliberate action (an extraction call or explicit tool), creating both a filter and an audit point.
- **Weakness:** In the two frameworks with LLM gates, the filter is a prompt — a misbehaving extractor can promote scratch noise anyway (flagged in both source reports).

### P5. Snapshot-and-restore loop isolation with a continuity log

- **Problem:** Multi-iteration loops need per-iteration freshness (bounded context, retryable steps) without losing overall task continuity.
- **Demonstrated by:** agent-framework's `fresh_context=True` snapshots the session pre-loop and restores it between iterations, carrying continuity solely in an internal progress log injected as `"Progress so far:"` (`python/packages/core/agent_framework/_harness/_loop.py:431-475,724-745`; tested in `tests/core/test_harness_loop.py:454-541`); the .NET `LoopAgent` mirrors this (`dotnet/src/Microsoft.Agents.AI/Harness/Loop/LoopAgent.cs:150-154`). Crewai's StepExecutor builds fresh message lists per step and "never reads or writes the AgentExecutor's state" (`lib/crewai/src/crewai/agents/step_executor.py:64-75`), receiving only distilled dependency results (`experimental/agent_executor.py:610-641`). Openhands replays planning history retaining only the latest file observation, then reads the file once (`src/contexts/conversation-websocket-context.tsx:201-205,477-501`).
- **Why it works:** Iterations become repeatable and bounded; the explicit continuity log makes "what carried over" legible instead of emergent.
- **Copy when:** Running bounded agentic loops over expensive contexts, or isolating untrusted sub-steps.
- **Risk:** If the continuity log is lossy, iterations drift — agent-framework mitigates by handing callbacks defensive copies so the log cannot be mutated (`_loop.py:724-725`).

### P6. Exactly-once consumption semantics for one-shot notifications

- **Problem:** Ephemeral notifications (mode changes, staged attachments, resume values) must be seen once and never replayed.
- **Demonstrated by:** agent-framework records the prior operating mode in state and pops the marker after exactly one injection (`python/packages/core/agent_framework/_harness/_mode.py:186-194,284-287`). Openhands consumes pending attachments exactly once per task id (`src/stores/pending-task-attachments-store.ts:20-40`) and scopes optimistic-message echoes by conversation id so a stale ack pops nothing else (`optimistic-user-message-store.ts:77-84`). Langgraph prevents double-consumption of interrupt resumes across nested tasks by delegating null-resume consumption to the parent scratchpad, with an assertion tying resume-list length to interrupt index (`libs/langgraph/langgraph/pregel/_algo.py:1320-1324`; `libs/langgraph/langgraph/types.py:962`).
- **Why it works:** Each mechanism pairs a consume primitive with a test pinning the exactly-once property — the same discipline applied at three different layers (state, store, engine).
- **Copy when:** Anything delivered "once" — especially across replay/resume boundaries, where duplicate delivery is the default failure.

### P7. Provenance stamping and attribution of injected content

- **Problem:** Once scratch content enters the conversation, consumers (auditors, downstream filters, future turns) must tell injected notes apart from genuine user input.
- **Demonstrated by:** agent-framework stamps every provider-injected message with `_attribution` (`source_id`, `source_type`, cross-session origins), explicitly for governance/audit (`python/packages/core/agent_framework/_sessions.py:636-660`). Pydantic AI plants `STANDING_PROMPT_PLANTED_KEY` only on compaction items its own compact call minted, so foreign items cannot masquerade as trusted standing prompts (`pydantic_ai_slim/pydantic_ai/messages.py:1979-1985`). Openhands tags planning-agent deltas with `isFromPlanningAgent` so streams can never merge across agents (`src/utils/handle-event-for-ui.ts:33-37`).
- **Why it works:** Attribution travels with the data rather than relying on consumers reconstructing provenance from position or role.
- **Copy when:** Any injection mechanism exists; retrofitting attribution after transcripts accumulate is far harder.

### P8. Versioned durable-state contracts for resumable scratch state

- **Problem:** Serialized hidden state that crosses process boundaries becomes an implicit compatibility contract; silent schema drift breaks old snapshots catastrophically.
- **Demonstrated by:** openai-agents-sdk's `RunState` carries `CURRENT_SCHEMA_VERSION = "1.17"` with chronological change summaries enforced by assertion, fail-fast rejection of newer schemas, and a serialized-compatibility corpus test (`src/agents/run_state.py:175-232`; `tests/test_run_state_compatibility_corpus.py`). Pydantic AI's `TemporalRunContext` whitelists serializable fields and raises `UserError` on excluded-field reads so "a field that didn't cross the boundary can't be mistaken for real run state" (`pydantic_ai_slim/pydantic_ai/durable_exec/temporal/_run_context.py:67-93`).
- **Copy when:** Persisting any hidden working state for pause/resume or workflow durability.
- **Skip when:** State is reconstructible (P3) — then versioning burden drops to zero.

## Key Differences

**Private vs. shared is a philosophical fork, not an implementation detail.** Letta states it outright: "Transparency over secrecy" — humans get first-class read/write on the very blocks the model uses (`letta/server/rest_api/routers/v1/agents.py:1206-1377`). Langgraph draws the opposite line: the scratchpad is engine plumbing never surfaced even in `StateSnapshot` (`libs/langgraph/langgraph/types.py:683-701`). Most others sit between: agent-framework exposes scratch state via opt-in console commands only; openai-agents-sdk publishes reasoning items but keeps approvals/pending-input underscore-private; openhands renders everything collapsed-by-default. None of these positions is strictly better — they track product shape (memory server vs. engine vs. SDK vs. UI).

**Default durability diverges with deployment model.** Letta persists every edit synchronously because it is a database-backed service (`core_tool_executor.py:325`). Crewai wipes everything per `invoke()` because it optimizes for repeatable batch runs (`experimental/agent_executor.py:2830-2845`). Langgraph minimizes durable residue because checkpoint-per-superstep already exists — recompute is cheaper than storage (`pregel/_algo.py:1280-1345`). Openai-agents-sdk splits the difference by lifetime layer. The divergence is a rational response to different constraints, not a quality ranking.

**Enforcement strength varies independently of sophistication.** Crewai enforces planner/executor isolation *structurally* with frozen dataclasses (`step_execution_context.py:13-30`) yet leaves its scratch→LTM boundary to an LLM call. Agent-framework engineers crash-safety meticulously (atomic writes, traversal checks, lock GC) yet leaves todo cleanup and scratch-vs-durable separation to prompts (`_todo.py:39-40`; `_memory.py:50-51`). Sophistication in one area does not predict it in another; reviewers should audit enforcement per boundary.

**Where the "notes vs. facts" distinction lives differs fundamentally.** Pydantic AI puts it *inside* the protocol record — `ThinkingPart` vs `TextPart` in one history, with output assembly skipping thinking (`messages.py:1928-1976`; `_agent_graph.py:1997-1998`). Crewai and agent-framework put it in *separate state fields*. Letta dissolves it (everything in blocks is treated as curated fact). Langgraph avoids it (nothing internal reaches the record). This choice determines what third-party consumers (UIs, exporters, eval harnesses) can distinguish without framework cooperation.

**User exposure of reasoning spans the full spectrum.** Verbatim-rendered markdown with no redaction layer (openhands, `collapsible-thinking.tsx:56-58`), public item streams including encrypted-opaque reasoning (openai-agents-sdk, `src/agents/items.py:492-499`), programmatically accessible but presentation-discouraged raw CoT (`provider_details['raw_content']`, pydantic-ai), actively scrubbed from subsequent context windows (letta, `letta_agent_v2.py:760-792`).

## Tradeoffs

**Transparency vs. confidential planning space.**
- Benefit (letta, openhands): users can inspect, correct, and trust working state; background agents can collaborate on shared notes; debuggability is maximal.
- Cost: no private channel exists; letta's `hidden` flag excludes blocks from API listings but *not* from prompt rendering (`letta/services/block_manager.py:349-351` vs `letta/schemas/memory.py:122-130`) — a developer marking secrets "hidden" gets the opposite of what they expect.
- Alternative: agent-framework's opt-in surfaces (`SuppressTodoListMessage` on .NET even suppresses model-side injection, `dotnet/.../Todo/TodoProvider.cs:81`).
- Failure mode: sensitive content verbatim in UI renders (openhands found no redaction utility anywhere in `src/components/conversation-events/**`) or in event payloads (crewai's `MemorySaveStartedEvent(value=content)` carries unredacted content onto the bus, `lib/crewai/src/crewai/memory/unified_memory.py:474-481`).

**Ephemerality vs. resumability.**
- Benefit (crewai): deterministic per-invoke wipe guarantees repeatability and prevents cross-task contamination.
- Cost: a mid-plan crash cannot resume the todo list from process state alone; recovery depends on separately-enabled Flow checkpoints; the in-memory `execution_log` audit trail dies with the run.
- Alternative: letta's write-through (mid-task notes survive crashes between steps) or openai-agents-sdk's versioned `RunState` snapshots.
- Best fit: batch/benchmark harnesses favor ephemerality; interactive long-running agents favor write-through.

**Prompt-enforced hygiene vs. structural guarantees.**
- Benefit: prompt gates (agent-framework's extraction rules, advisory todo-clearing instructions) keep architecture simple and flexible.
- Cost: correctness rests on model compliance; a misbehaving extractor promotes scratch noise into durable memory; stale todos persist indefinitely without runtime enforcement.
- Alternative: structural separation (langgraph's nonexistent write path; pydantic-ai's absent LTM) is immune to compliance failures but forfeits automated memory capture.

**Rich render affordances vs. token cost and injection risk.**
- Benefit (letta): line-number gutters, warning banners, and inline `read_only`/budget metadata give the model precise self-editing targets.
- Cost: doubled surface the model must avoid copying into arguments — hence regex guards hard-rejecting line-number prefixes (`core_tool_executor.py:357-374`), a deliberate context spend.

**Full-fidelity audit copies vs. footprint.**
- Benefit (openai-agents-sdk): keeping `_session_items` alongside the filtered `_generated_items` preserves a complete audit trail while handoff filters reshape what the next agent sees (`src/agents/run_state.py:782-786`).
- Cost: doubled in-memory history during runs; and the include-by-default tracing posture (`trace_include_sensitive_data=true`, `src/agents/run_config.py:53-56`) means audit completeness currently trades against leakage safety.

## Decision Guide

Choose your approach model by primary constraint:

1. **Building an engine/graph runtime with checkpointing?** Adopt langgraph's model: internal scratchpad, recompute-over-persist, narrow typed projections (managed values), and a tiny durable footprint (resume values only). Add what langgraph lacks: a debug hook to serialize scratchpad state for audits.
2. **Shipping a developer SDK where apps compose their own agents?** Follow openai-agents-sdk/pydantic-ai: lifetime-scoped containers, explicit "contexts never reach the LLM" documentation, versioned snapshot schemas if you support pause/resume, and primitives (injection queues) rather than opinionated todo tools. Accept that app authors will hand-roll plan state.
3. **Shipping an end-user product where plans have UX value?** Follow agent-framework/openhands: structured todo tools, full-replacement updates for trivially correct latest-wins derivation, dedicated UI surfaces, and agent-controlled salience. Budget for the advisory-lifecycle weakness with TTL/auto-archive at task boundaries.
4. **Memory itself is the product, or multi-agent curation matters?** Follow letta: shared labeled blocks, write-through persistence, change-gated prompt rebuilds, REST symmetry, and git-versioned audit if compliance demands it. Engineer concurrency (last-writer-wins is a known gap) and fix the `hidden`-from-API-not-model semantics before promising privacy.

Then apply three cross-cutting rules regardless of model:

- **Anything the model must have seen after a restart should be derivable from durable history, not held in attributes** (P3). This is the cheapest reliability win observed in the study.
- **Every path from scratch state to long-term memory must pass an explicit, logged promotion step** (P4). If you cannot name the gate, you have a pollution path.
- **Serialize hidden-state snapshots only behind a versioned schema with a compatibility corpus** (P8), or don't serialize them at all.

## Practical Tips

- **Partition scratch state by owner key from day one** (P1). Retrofitting namespaces onto a shared dict forces migrations; agent-framework's `source_id` scheme costs nothing upfront.
- **Make every injection attributable** (P7). Stamp `source_id`/origin metadata at injection time; downstream redaction, replay filtering, and audit all become queries instead of archaeology.
- **Prefer full-replacement updates for small task lists.** Openhands' whole-list `task_list` replacement makes event-sourced reconstruction trivially correct (`__tests__/hooks/use-task-list.test.ts:55-190`) — worth more than delta-update bandwidth savings below ~dozens of items.
- **Test the clearing matrix, not just happy paths.** Agent-framework's fresh-context/session-reset test matrix (`tests/core/test_harness_loop.py:530-541`) and crewai's sync/async reset blocks (`agent_executor.py:2830-2845,2916-2931`) show boundary clearing is where regressions concentrate.
- **Validate scratch state on load with precise errors.** Strict `from_dict` validation raising descriptive corruption errors (`_todo.py:87-95,256-275`) beats silent resets — corrupted state should fail loudly, not vanish.
- **Use atomic temp-file + rename for any file-backed scratch store**, and clamp restored ID counters above persisted maxima (`_todo.py:223-225,431-443`) — both failure modes (truncated writes, ID collisions after restore) have regression tests worth copying.
- **Pair weakref/GC coupling with scope ids for ephemeral caches** (openai-agents-sdk, `agent_tool_state.py:131-142` + `run_context.py:130`): weakrefs stop leaks, scope ids stop cross-restoration collisions.
- **Give reasoning traces their own lifecycle**: scrub from context windows, exclude from result assembly, park raw CoT outside user-facing fields, summarize across handoffs. Four independent sources converged on variants of this; treat it as table stakes.
- **Cap scratch growth explicitly**: letta caps its memory index at 50 entries and its durable index at 200 lines (`_file_memory.py:78`; `_memory.py:36-37`). Uncapped todo lists and session dicts grow silently until they dominate the prompt.
- **Redact before telemetry, not after**: strip provider-specific fields pre-persistence (openai-agents-sdk, `session_persistence.py:910-930`) rather than trusting downstream sinks.

## Anti-Patterns / Caution Signs

- **Scratch text accumulating in shared domain objects.** Crewai's legacy `handle_reasoning` appends `Planning:` blocks onto the shared `task.description`, contaminating re-invocations and persisted definitions (`lib/crewai/src/crewai/agent/utils.py:55`) — precisely what its own new executor forbids in-code (`experimental/agent_executor.py:382-384`). Two executors disagreeing about a core invariant is a migration smell; audit any duplicated logic for this pattern.
- **Privacy controls that don't cover the actual exposure surface.** Letta's `hidden` flag filters listings, not prompt rendering. Whenever adding a visibility flag, enumerate *all* readers (API, prompt compiler, exports, events) and decide for each.
- **Substring/change heuristics gating persistence decisions.** Letta's skip-rebuild check concedes in-comment that a removed block would slip through ("substring match would still work", `agent_manager.py:1562-1563`). Use hashes or revision counters for change detection.
- **Module-level mutable globals for ephemeral state.** Openai-agents-sdk's nested-agent result maps work but complicate multi-loop embedding and testing (`agent_tool_state.py:35-48`); mitigated by scope ids, still global.
- **Invariants enforced only by comments.** Pydantic AI's shared-by-reference rule — reassignment "would silently break in-step tool reveals" — relies on contributors reading `_agent_graph.py:413-421`. If a broken invariant causes distant failures, it needs type or assertion enforcement.
- **Invisible forgetting.** Openhands consumes condensation events but renders nothing; users cannot see what the model no longer knows (`use-await-context-compaction.ts:112-138`). Any destructive context operation should leave a user-visible trace.
- **Include-sensitive-data-by-default observability.** Openai-agents-sdk traces include sensitive data unless operators flip an env var (`run_config.py:53-56`); voice pipelines default both audio and text tracing on (`pipeline_config.py:26-30`). Defaults should assume publication.
- **Loose path matching for scratch files.** Openhands' `isPlanFilePath()` accepts any `PLAN.MD` suffix, so an unrelated `notes/PLAN.md` would hijack the planner tab (`conversation-websocket-context.tsx:207-208`). Match canonical constants, not suffixes.
- **Unbounded, un-TTL'd scratch stores.** No source enforces todo expiry; crewai finds no retention policy for its replay SQLite store beyond manual reset. Stale working notes are the quiet failure mode of this entire dimension.

## Notable Absences

- **No general-purpose private-notes API for the model in six of seven sources.** Only letta offers the model a writable notes surface, and it is deliberately public. Agent-framework's todos come closest but are task lists, not free-form notes. Openai-agents-sdk explicitly warns custom contexts may not round-trip (`run_state.py:756-762`), leaving agents to abuse the freeform context object.
- **No tagging of model-visible items as provisional vs. factual inside the conversation itself.** The openai-agents-sdk source report states this directly: separation happens only at the runtime/state layer; nothing distinguishes "working notes" from "facts" within model-visible history. Pydantic AI's `ThinkingPart` is the sole partial exception, covering reasoning but not intermediate conclusions written as text.
- **No redaction/PII-screening layer between scratch content and observability anywhere.** Agent-framework found no sensitivity screening in scratchpad stores; crewai emits raw content on its event bus; openhands has no mask/redact utility in rendering; openai-agents-sdk's tracing defaults to inclusion. The closest mechanisms are targeted (reasoning scrubbing, `provider_data` stripping) rather than general.
- **No runtime-enforced task-boundary clearing.** Agent-framework's todo lifecycle is instruction-driven; openai-agents-sdk auto-clears nothing between tasks; letta's autoclear drops messages but preserves blocks by explicit design. Only crewai wipes deterministically, at the cost of resumability.
- **No distributed/multi-process coordination of scratch state.** Agent-framework's locks are in-process (`asyncio.Lock`/`SemaphoreSlim`); letta's concurrent-write story is last-writer-wins with DB-level behavior unconfirmed; langgraph delegates TTL/distributed concerns to custom store implementers.
- **No dedicated audit log of scratch mutations in most sources.** Letta requires opting into git memory for commit-per-edit history; agent-framework auditing means diffing session snapshots; langgraph's raw scratchpad is unauditable by design; crewai's `execution_log` evaporates per invoke.
- **No long-term memory at all in pydantic-ai and langgraph-core** — both assign cross-run memory to application code or opt-in separate mechanisms, making "pollution" structurally impossible but automated memory capture equally absent.

## Per-Source Notes

**agent-framework (8)** — Five coexisting mechanisms (todos, mode, injection queue, loop progress log, file memory) over one provider-partitioned serializable dict, with .NET parity via typed state bags. Strongest engineering floor in the study: atomic writes, strict corruption validation, path-traversal guards, weak-ref lock GC, attribution stamping, fresh-context loop isolation — all regression-tested. Weakest spots are policy, not mechanics: advisory-only todo clearing, prompt-enforced scratch/durable separation, default-on local file memory, and no mutation audit log.

**crewai (7)** — Cleanest expression of the state-machine school: pydantic `AgentExecutorState` with plan/todos/observations/audit-log fields, status-tracked todo lifecycle with dependency tolerance and replan-preserving replacement, frozen-dataclass planner↔executor mediation carrying "no LLM message histories." Deterministic per-invoke wipe and distill-before-persist memory. Held back by dual-generation executors whose legacy path violates the new path's no-pollution rule, raw-content event leakage, and an audit trail that dies with the run.

**langgraph (7)** — The purest infrastructure answer: a private per-task scratchpad recreated from checkpoint metadata on dispatch, read-only managed-value projections (`IsLastStep`, `RemainingSteps`), parent-delegating nested scratchpads preserving exactly-once resume consumption, and a deliberately tiny durable footprint (resume values only). Time-travel correctly drops stale resume writes. Falls short on observability (raw scratchpad uninspectable) and discoverability (undocumented outside code comments); offers no agent-facing notes facility whatsoever.

**letta (9)** — The only source treating working memory as the product: labeled budgeted blocks compiled into the system prompt, model self-edited through a rich tool family (including codex-style multi-block patches), write-through persistence with change-gated prompt rebuilds, REST/git human symmetry, background sleeptime curation, thought scrubbing, and layered compaction with verified thresholds. Kept from 10 by substring rebuild detection, `hidden`-from-API-but-not-model semantics, last-writer-wins shared-block concurrency, and a non-durable voice scratchpad buffer.

**openai-agents-sdk (8)** — The most rigorous lifetime taxonomy: per-turn input reset, per-run private wrapper ("Contexts are not passed to the LLM"), per-interruption versioned `RunState` (schema 1.17 with compatibility corpus), cross-run sessions with decorator composition (compaction/encryption), and weakref+scope-id ephemeral maps. Transactional compaction hardened against cancellation storms; dual model-view/full-record histories preserve audit while reshaping handoff context. Missing: a supported scratchpad concept, inspection of the ephemeral maps, and safe observability defaults.

**openhands (7)** — Studied as the UI vantage point: proves working memory can be a pure event-sourced projection (backwards-scan latest-wins todo derivation, replay-rebuilt plan content, one-shot consume stores, watchdog timers) with full transcript-export auditability including thoughts. Its unique finding is the visibility inversion — everything is shown except condensation, the one thing users arguably most need to see. Server-side scratchpad policy (durability, GC, re-seeding) sits outside the repo and remains unverifiable here.

**pydantic-ai (7)** — The most disciplined "notes ≠ facts" treatment: `ThinkingPart` lives inside durable protocol history (round-tripped with signatures, excluded from result assembly, raw CoT parked in `provider_details`), derived working sets re-parse from history each request so they self-heal across compaction and provider failover, and Temporal serialization fails closed on fields that didn't cross the boundary. The `enqueue`/drain queue is a well-tested injection scratchpad. Gaps: identity-discipline invariants enforced only by prose, all-or-nothing thinking visibility with no harness redaction knob, no first-class todo/plan surface.
