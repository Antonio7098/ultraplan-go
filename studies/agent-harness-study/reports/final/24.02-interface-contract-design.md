## Executive Summary

This dimension could be evaluated against **two of eleven** sources. Only `langfuse` (TypeScript observability platform: Next.js web tier + BullMQ worker + shared packages, **8/10**) and `openhands` (`@openhands/agent-canvas`, a React/TypeScript consumer of a Python agent-server, **7/10**) shipped populated source trees. The other nine returned "absent evidence" reports scoring 1/10: eight upstream repositories (`agent-framework`, `crewai`, `langgraph`, `letta`, `opa`, `openai-agents-sdk`, `pydantic-ai`, `temporal`) were never materialised into their source directories, and the eleventh (`reports`) is an empty report-artifact snapshot holding two bare directories and zero files (audited at `studies/agent-harness-study/reports/source/24.02-interface-contract-design/reports.md:118-123`). These scores grade the *evidence available*, not the upstream projects.

Within the two evaluable sources the convergence is strong enough to state as a model. Both define cross-boundary contracts as **discriminated unions** — langfuse via Zod (`z.discriminatedUnion` over `type`/`actionId`/`role`/`operation`, e.g. `packages/shared/src/server/queues.ts:310-321`; `packages/in-app-agent-sandbox-runtime/src/contracts.ts:8-41`), openhands via literal `kind` tags re-aggregated into one event family (`src/types/agent-server/core/openhands-event.ts:25-46`). Both **validate at every trust boundary**, including boundaries between their own halves — langfuse re-parses queue payloads, sandbox wire ops, and even its own providers' tool results (`packages/shared/src/server/queues.test.ts:53-87`; `packages/in-app-agent-sandbox-runtime/src/server.ts:151`; `worker/src/features/in-app-agent/runtime/sandbox/service.ts:92-125`), openhands re-validates localStorage on read and narrows untyped server JSON before use (`src/api/backend-registry/storage.ts:24-39`; `src/api/agent-server-adapter.ts:153-173`). Both back the declarations with **mechanised enforcement**: CI tests that fail when callers bypass the sanctioned path (`src/api/no-direct-agent-server-calls.test.ts:32-79` in openhands; the client-safe/server-only barrel split with browser-bundle scanning in langfuse). And both encode failure as **typed, discriminated error hierarchies carrying diagnostic payloads** rather than status codes or strings (`packages/shared/src/errors/BaseError.ts:1-39`; `src/api/agent-server-compatibility.ts:41-103`).

They diverge exactly where product shape demands it. Langfuse is a server platform whose infrastructure must be substitutable, so it builds genuinely multi-implementation ports — two sandbox providers behind one consumer-owned interface (`worker/src/features/in-app-agent/runtime/sandbox/types.ts:55-84`), four cloud storage adapters behind one factory (`packages/shared/src/server/services/StorageService.ts:297-348`), six LLM adapters behind one exhaustiveness-checked builder (`packages/shared/src/server/llm/ai-sdk/providers/index.ts:34-124`) — and encodes behavioral semantics as Postgres CAS state machines with race-condition tests (`packages/shared/src/in-app-agent/server/runLifecycle.ts:37-124`, tested at `runLifecycle.test.ts:72-170`). Openhands is a single-purpose UI consumer, so nearly every "interface" has exactly one realization (the SDK class regenerated from the agent-server's OpenAPI) and its contract energy goes into a version-compatibility floor that *throws* typed errors (`src/api/agent-server-compatibility.ts:293-318`), a capability advertisement from the server (`usable_tools`, `:149-155`), and all-or-nothing admission of third-party manifests against host-owned allow-lists (`src/manifests/interface-validation.ts:28-100`).

The dimension's headline question — *"can two independent implementations satisfy the same contract without relying on undocumented behavior?"* — is not answered affirmatively anywhere in the materialized evidence. Langfuse comes closest: its ports have multiple real implementations and boundary validation, but no conformance suite runs an independent implementation through the consumer's scenario matrix (flagged in the langfuse report §Questions/Gaps). Openhands resolves the question by construction: one implementation per contract, parity enforced by regeneration rather than by cross-implementation agreement (openhands report §Answers 3). The nine empty sources add a study-level lesson that several reports stated independently: dispatching contract-analysis tasks against unmaterialised inputs is itself an interface-contract failure of the orchestration layer, and empty sources should be a hard pre-condition failure rather than a fleet of no-evidence reports.

## Core Thesis

> A contract is not the type declaration; it is the enforcement machinery wrapped around the declaration. Both evaluable sources spend most of their contract-design effort not on defining interfaces but on deciding what happens when interfaces are violated or evolve: parse everything crossing a process or trust boundary, make violations typed exceptions with diagnostic payloads, gate compatibility explicitly (version floors, optional-field rules, capability advertisements), and use CI to prevent callers from bypassing the sanctioned path. Where that machinery exists, contracts hold across adapters and versions; where it thins out — doc-comment-only merge semantics in openhands' settings path, `Record<string, unknown>` AG-UI handlers in langfuse, suspend semantics that differ between sandbox adapters — shape still compiles but guarantees silently evaporate. The corollary from the nine absent sources: before asking whether a contract is well designed, verify there is a contract; an unmaterialised source converts every downstream question into a logistics answer.

## Approach Models

Clustering by how contracts are defined, validated, and evolved yields two substantive models and one non-model.

**Model A — Shared-schema platform contracts (langfuse).** The unit of contract is a Zod schema published from `packages/shared` and imported by both the Next.js web tier and the BullMQ worker, eliminating producer/consumer drift at the source (`packages/shared/src/server/queues.ts:1-12`). Three mechanisms carry the model:

- *Routing envelopes are discriminated unions.* Queue payloads (`IngestionEvent` at `queues.ts:23-48`), outbound webhooks (`WebhookOutboundEnvelopeSchema` at `queues.ts:310-321`), batch actions (`BatchActionProcessingEventSchema` with 9+ actionIds at `queues.ts:180-265`), AG-UI messages keyed by role (`packages/shared/src/in-app-agent/schema.ts:158-197`), and sandbox operations keyed by operation name (`contracts.ts:8-41`) all route on a literal discriminator. A mapped type `TQueueJobTypes` ties queue names to validated job shapes at compile time (`queues.ts:476-667`).
- *Infrastructure sits behind small consumer-owned ports.* `SandboxProvider` (4 methods, optional lifecycle extensions) is declared in the worker runtime, not by either adapter (`worker/src/features/in-app-agent/runtime/sandbox/types.ts:55-84`); both the Docker and Lambda MicroVM adapters conform, and the worker validates every tool result against `InAppAgentSandbox*ResultSchema` before returning, so a misbehaving provider fails loudly (`service.ts:92-125`). `StorageService` has four real implementations selected by env-flagged factory (`StorageService.ts:235-272`, `297-348`). `ManagedCredentialProvider` is a 3-property port whose refresh semantics are supplied once by a shared `RefreshingTokenManager` (`packages/shared/src/server/auth/credentials/types.ts:8-12`; `RefreshingTokenManager.ts:19-99`).
- *Behavioral guarantees are executable, not prose.* The run lifecycle is a CAS state machine — `claimQueuedRun` claims by filtering on `status: QUEUED` (`runLifecycle.ts:37-58`), heartbeats return fenced/unfenced verdicts (`:60-84`), terminal writes return false if ownership was lost (`:93-124`) — with dedicated race tests (`runLifecycle.test.ts:72-170`). A pure classifier `classifyStaleRun` maps stuck runs onto four named failure verdicts (`runLifecycle.ts:696-747`). Delivery guarantees are assigned per tier: BullMQ is delivery-only (`attempts: 1`, `packages/shared/src/server/redis/inAppAgentRunQueue.ts:30-39`); Postgres owns correctness.

Supporting mechanisms: a closed MCP-tool policy registry typed with `satisfies Record<string, InAppAgentMcpToolPolicy>` so a new tool cannot ship without a policy entry (`packages/shared/src/in-app-agent/server/mcpPolicy.ts:27-360`); provider-option translation that fails closed with `{ok: false, unknownKeys}` (`packages/shared/src/server/llm/ai-sdk/providers/types.ts:7-9`); `Symbol.for(...)` error markers so `LLMValidationError` survives bundling realms (`packages/shared/src/server/llm/errors.ts:7-40`); and an explicit backward-compatibility rule for rolling deploys — new payload fields ship `.optional()` with comments plus regression tests proving old shapes still parse (`queues.ts:30-78`; `queues.test.ts:53-87`).

**Model B — Generated-client consumer contracts (openhands).** The frontend owns the wire types it consumes and treats everything else as untrusted input. Four mechanisms carry the model:

- *Type families sealed by literal discriminators.* Every event extends `BaseEvent {id, timestamp, source}` and adds a literal `kind` (`src/types/agent-server/core/base/event.ts:10-25`); the full union is re-aggregated in one file (`src/types/agent-server/core/openhands-event.ts:25-46`) and narrowed by documented type guards (`src/types/agent-server/type-guards.ts:45-122`). Closed literal unions bound the space: `EventType`/`ActionOnlyType`/`ObservationOnlyType` (`base/base.ts:4-53`), `SecurityRisk`/`ExecutionStatus` (`base/common.ts:59-75`).
- *One sanctioned path per transport.* A CI test scans the source tree and fails on any raw `axios`/`fetch`/`HttpClient` usage toward the agent-server, with an allow-list of exactly three files (`src/api/no-direct-agent-server-calls.test.ts:32-79`); all calls flow through typed SDK clients assembled by one options helper that throws `NoBackendAvailableError` when unconfigured (`src/api/agent-server-client-options.ts:52-69`). Cloud-vs-local is a uniform envelope (`callCloudProxy<T>`, `src/api/cloud/proxy.ts:5-39`) plus a repeated per-call branch on `active.kind`.
- *Compatibility failures throw, early.* A minimum-version floor with a full-semver parser gates startup; too-old servers raise `AgentServerUnsupportedVersionError`, unknown versions `AgentServerUnknownVersionError`, unreachable ones `AgentServerUnavailableError` — each carrying `code`/`actualVersion`/`requiredVersion` (`src/api/agent-server-compatibility.ts:18-19`, `243-291`, `41-103`, `293-318`), with probe tests covering every branch (`src/__tests__/api/agent-server-compatibility-bundled-pin.test.ts:69-141`). Runtime capability advertisement arrives via the server's `usable_tools` field, defaulting to allow when absent (`:149-155`).
- *Third-party surface is admitted, never trusted.* Externally authored catalog/interface manifests pass an all-or-nothing validator: regex-pinned endpoints, `{id}` substitution shape, attribute names/types matched against what the host dialog actually implements (`HOST_ATTRIBUTES`), enum values checked against closed lookup tables (`src/manifests/interface-validation.ts:28-100`, `49-58`; `src/manifests/manifest-validation.ts:93-99`).

Supporting mechanisms: adapter functions normalizing wire shapes to consumer shapes (`toAppConversation`, `src/api/agent-server-adapter.ts:317-402`); discriminator constants kept in one module so SDK-generated names never leak (`src/constants/canvas-ui.ts:1-10`); legacy/new coexistence handled inside the type system (`StrReplaceEditorObservation` retained beside `FileEditorObservation`, `src/types/agent-server/core/base/observation.ts:148-184`; tool-name vs action-kind decoupling at `base/action.ts:317-323`); and localStorage treated as hostile input, re-validated entry-by-entry on read with guards tuned to specific tampering vectors (`src/api/backend-registry/storage.ts:24-40`; `health-storage.ts:24-39`).

**Non-model — absent evidence (nine sources).** Eight repositories were never cloned into their source directories and the `reports` snapshot contains zero files; each report documents exhaustive negative searches and scores the rubric floor. Several reports additionally sketch verification checklists for a re-run — e.g., whether temporal's persistence drivers share one conformance rig, whether opa fences unstable APIs behind a v0/v1 import blocker, whether pydantic-ai ships a `TestModel`/`FunctionModel` harness — but all of these are explicitly labeled speculation pending materialisation, not findings (see Open Questions).

## Pattern Catalog

Patterns appear below only if demonstrated by both sources or shown unusually clearly by one.

**P1. Discriminated unions as the universal routing contract.**
*Problem:* consumers must dispatch heterogeneous payloads (queue jobs, webhook deliveries, stream events, tool operations) without fragile string sniffing.
*Demonstrated by:* langfuse — five separate `z.discriminatedUnion` families covering queues, webhooks, notifications, AG-UI messages, and sandbox ops (`queues.ts:180-265, 310-321`; `schema.ts:158-197`; `contracts.ts:8-41`). Openhands — every event, action, and observation carries a literal `kind` participating in exhaustive narrowing (`openhands-event.ts:25-46`; `base/base.ts:55-63`).
*Why it works:* adding a variant is additive; narrowing is compiler-checked; validation rejects unknown discriminators outright (tested at `queues.test.ts:29-51`).
*Copy when:* any payload crosses a process, package, or trust boundary and needs routing.
*Overkill/risky when:* the variant set churns constantly across independently deployed producers — every new variant forces coordinated consumer updates unless consumers handle unknown tags deliberately.
*Evidence:* both reports §Architectural Decisions.

**P2. Validate at every boundary — including between your own halves.**
*Problem:* types guarantee nothing at runtime; drift enters wherever data crosses serialization, storage, or package realms.
*Demonstrated by:* langfuse parses inbound queue payloads in the worker (`worker/src/queues/inAppAgentRunQueue.ts:9-13`), parses sandbox HTTP bodies (`packages/in-app-agent-sandbox-runtime/src/server.ts:151`), validates inbound tool-call files (`server.ts:95`), and — most tellingly — validates results returned by *its own* first-party sandbox providers (`worker/src/features/in-app-agent/runtime/sandbox/service.ts:92-125`). Openhands re-validates localStorage entries and health counters on read, with a guard specifically shaped to reject tampered `-1` failure counts that would defeat auto-disable (`src/api/backend-registry/storage.ts:24-40`; `health-storage.ts:10-39`), and narrows untyped `/server_info` JSON before downstream use (`agent-server-adapter.ts:153-173`).
*Why it works:* the schema becomes the executable statement of the contract; corruption, tampering, and producer regressions fail at the door instead of propagating as undefined behavior.
*Copy when:* always, for anything crossing a boundary you do not fully control — including your own persisted state.
*Cost:* parse overhead on hot paths; mitigated in langfuse by dev-only response validation on some routes and by cheap structural guards in openhands.
*Evidence:* langfuse report §Answer 4; openhands report §Answers 2 and §Failure Modes.

**P3. Consumer-owned narrow ports with factory-selected adapters.**
*Problem:* infrastructure substitution (sandboxes, object storage, LLM providers, credential brokers) without letting provider concerns leak into business logic.
*Demonstrated by:* langfuse — `SandboxProvider` declared next to its consumer with two conforming adapters (`sandbox/types.ts:55-84`; `providers/docker.ts:28-231`; `providers/lambdaMicrovm.ts:74-456`) selected by an env-driven factory that uses `assertUnreachable` for exhaustiveness (`config.ts:24-67`); four storage adapters behind `StorageServiceFactory` (`StorageService.ts:297-348`); six LLM builders behind one `never`-checked dispatcher (`providers/index.ts:34-124`). Openhands shows the structural form without the multiplicity: `Backend {id, name, host, apiKey, kind, ...}` is a clean 5+1-field port (`backend-registry/types.ts:4-23`), but only one implementation exists per client contract.
*Why it works:* the consumer defines the minimum surface it needs; providers stay replaceable; the factory centralizes selection policy.
*Copy when:* you anticipate more than one real implementation, or want test doubles to satisfy the same seam.
*Overkill when:* single-implementation forever — then a generated client (Model B) gives shape parity for less ceremony.
*Evidence:* langfuse report §Answers 1–3; openhands report §Answers 1–3.

**P4. Mechanised boundary enforcement in CI.**
*Problem:* access rules ("use the typed client", "don't import server-only modules into the browser") decay under contributor pressure unless a machine checks them.
*Demonstrated by:* openhands — the no-direct-calls test enumerates forbidden import shapes and raw HTTP patterns with a three-file allow-list (`no-direct-agent-server-calls.test.ts:32-79`). Langfuse — the client-safe barrel exports only runtime-neutral modules while server-only contracts require explicit subpaths, enforced by a browser-bundle scan in CI (langfuse report §Architectural Decisions, final bullet).
*Why it works:* the rule becomes a failing test instead of a review comment; violations surface at PR time.
*Copy when:* any rule whose violation is detectable by grep/import analysis.
*Risk:* allow-list rot — entries accrete and each one is a standing exception nobody remembers approving.
*Evidence:* both reports §Architectural Decisions.

**P5. Typed compatibility failures carrying diagnostic payloads.**
*Problem:* version skew between independently deployed components produces mysterious runtime breaks.
*Demonstrated by:* openhands most explicitly — a version floor, a prerelease-aware semver parser, and an error hierarchy distinguishing unavailable / unsupported / unknown with machine-readable fields (`agent-server-compatibility.ts:41-103`, `243-318`); identification works via both `instanceof` and a structural `name`/`code` check so cross-realm errors still narrow (`:61-121`). Langfuse's analog is evolutionary rather than gating: `.optional()` fields plus inline warnings plus regression tests prove old payloads keep flowing during rolling deploys (`queues.ts:30-48, 50-78`; `queues.test.ts:53-87`).
*Why it works:* callers program against the failure (`error.code === ...`) instead of parsing messages; support can read `actualVersion` vs `requiredVersion` straight off the thrown object.
*Copy when:* your components deploy on independent clocks (client/server, worker/web, plugin/host).
*Complementary move:* pair a hard floor with soft capability discovery (openhands' `usable_tools`) so minor skew degrades gracefully (`:149-155`).
*Evidence:* openhands report §Answers 4, §Architectural Decisions; langfuse report §Notable Patterns.

**P6. Closed registries with compile-time exhaustiveness.**
*Problem:* enumerated universes (tool names, queue names, action ids, host-known identifiers) silently grow without the corresponding handling or policy.
*Demonstrated by:* langfuse — the MCP policy registry uses `satisfies Record<string, Policy>` and derives the tool-name type via `keyof typeof`, so an unpolicied tool cannot compile (`mcpPolicy.ts:27-360`, `366-367`); queue factories switch on `QueueName` with `_exhaustiveCheckDefault: never` (`getQueue.ts:36-116`). Openhands — closed `LOOKUP_TABLES` constrain externally submitted manifest identifiers, and SDK-generated discriminator names live once in constants modules (`src/manifests/types.ts`; `src/constants/canvas-ui.ts:1-10`).
*Why it works:* the registry *is* the type; addition without handling is a compile error, not a production surprise.
*Copy when:* a set of named things each requires associated metadata or behavior.
*Watch out:* big unions with thin per-variant test coverage — langfuse's own batch-action union covers 9 actionIds but its regression tests exercise only a few (`queues.ts:180-265` vs `queues.test.ts` coverage noted in §Tradeoffs).
*Evidence:* langfuse report §Notable Patterns; openhands report §Architectural Decisions 5–6.

**P7. Explicit assignment of correctness between tiers.**
*Problem:* distributed queues and proxies blur who guarantees delivery, ordering, and exactly-once behavior.
*Demonstrated by:* langfuse — the in-app-agent queue is deliberately delivery-only (`attempts: 1` with an inline comment naming Postgres CAS + reconcile-on-read as the correctness owner, `inAppAgentRunQueue.ts:30-39`), which turns duplicate redeliveries into harmless CAS no-ops. Openhands assigns shape-parity duty to regeneration: the SDK mirrors the server's OpenAPI, so the "contract test" is the generator itself, and the repo's dual transports (local SDK, cloud proxy) route to the same backend by design (openhands report §Answers 3, §Tradeoffs).
*Why it works:* stating who owns which guarantee removes the classic double-checkpointing/lost-update bugs; reviewers can audit one mechanism instead of three overlapping ones.
*Copy when:* combining at-least-once transports with durable state stores, or shipping generated clients.
*Failure mode when implicit:* redelivery handlers that retry side effects because nobody wrote down that the queue is delivery-only.
*Evidence:* langfuse report §Architectural Decisions bullet 2 and §Tradeoffs last bullet; openhands report §Questions/Gaps bullet 2.

**P8. Identity markers that survive realms and refactors.**
*Problem:* JavaScript's `instanceof` breaks across bundler realms, duplicated packages, and serialized boundaries — so error and capability checks quietly stop matching.
*Demonstrated by:* langfuse — `LLMValidationError` registers a `Symbol.for(...)` marker so detection survives bundling (`llm/errors.ts:7-40`), and Mastra tools are detected structurally (`execute` + `inputSchema` present) precisely because `instanceof Tool` is unreliable across package versions (`worker/src/features/in-app-agent/runtime/tools.ts:109-118, 132-135`). Openhands — error guards check both `instanceof` and structural `name`/`code` (`agent-server-compatibility.ts:61-121`).
*Why it works:* identity is decoupled from constructor lineage, which is the only portable notion in a multi-realm runtime.
*Copy when:* libraries are duplicated across bundles (monorepos with shared packages, embedded UI kits, plugin systems).
*Risk:* structural checks match look-alikes — a tool with the right shape but wrong `execute` signature slips through (langfuse flags exactly this, §Tradeoffs).
*Evidence:* langfuse report §Rating rationale and §Notable Patterns; openhands report §Architectural Decisions 4.

**P9. Admission pipelines for third-party contract artifacts.**
*Problem:* external contributors submit manifests/tools/configs that the host must accept without trusting them.
*Demonstrated by:* openhands — manifests are validated all-or-nothing against regex-pinned endpoint shapes, closed lookup tables, and `HOST_ATTRIBUTES` mirroring what the host edit-dialog actually implements, collecting structured errors rather than failing on first fault (`interface-validation.ts:28-100, 83-86`; `manifest-validation.ts:67-70, 93-99`); admission suites exercise well-formed acceptance and per-invariance rejection (`__tests__/manifests/interface-validation.test.ts:38-100+`). Langfuse's internal analog is the MCP approval registry pairing every tool name with `approval` mode and RBAC scope, with availability re-derived from roles at decision time so stored grants cannot outlive role changes (`mcpPolicy.ts:477-510`; tested at `worker/src/features/in-app-agent/runtime/sandbox/../tools.test.ts:5-24`).
*Why it works:* the host's own implemented behavior becomes the validation reference; external artifacts can neither exceed nor diverge from it.
*Copy when:* plugins, marketplace items, or user-authored automation target your host.
*Evidence:* openhands report §Architectural Decisions 5 and §Notable Patterns; langfuse report §Failure Modes bullet 7.

## Key Differences

The interesting differences track product shape and operational constraints, not quality.

- **Multi-implementation ports vs regeneration-enforced parity.** Langfuse needs interchangeable infrastructure because it is deployed across heterogeneous environments (Docker dev sandboxes vs Lambda MicroVMs in prod; S3/Azure/GCS/OCI storage), so it pays for ports, factories, and per-result validation. Openhands embeds one server's API, so every contract has exactly one implementation and the interesting invariant is shape parity with that server — enforced by regenerating the SDK from OpenAPI rather than by testing a second implementation (openhands report §Answers 3). Neither approach is "more correct": substitution pressure is a deployment property, not a design virtue.
- **Behavioral encoding depth.** Langfuse encodes semantics as executable state machines: claim/heartbeat/finish CAS transitions, a pure stale-run classifier with four named verdicts, and race tests (`runLifecycle.ts:37-124, 696-747`; `runLifecycle.test.ts:72-170`). Openhands' contracts are mostly structural; where behavior matters it appears as point guards (version floor, auth-error detection requiring *both* a flag and status 401, `:132-133`) while other semantics live in doc comments — the settings deep-merge/list-replacement rules are documented at `settings-service.api.ts:25-49, 67-76` but asserted by no test (openhands report §Questions/Gaps bullet 3).
- **Evolution strategy follows deploy topology.** Langfuse upgrades web and worker independently against shared queues, so its compatibility instrument is the *payload*: new fields optional, old shapes regression-tested (`queues.test.ts:53-87`). Openhands pairs an independently released UI with an independently released server, so its instruments are a *handshake*: minimum-version floor, typed rejection, capability advertisement defaulting to allow (`agent-server-compatibility.ts:149-155, 293-318`). Same underlying problem — skew — answered at different layers.
- **Fail-open vs fail-closed defaults.** Openhands' capability detection fails open: a server that omits `usable_tools` gets everything through (`:34-39, 149-155`), a deliberate availability-over-safety choice. Langfuse's config translation fails closed: unknown provider keys produce `{ok: false, unknownKeys}` and unresolved configs wrap into `LLMValidationError` (`providers/types.ts:7-9`; `resolveAiSdkModelConfig.ts:103-115`). The pattern: *capability* negotiation tolerates absence; *configuration* validation rejects it.
- **Absorbing upstream contract mismatches.** Langfuse duplicates AG-UI schemas locally because upstream ships Zod-v3-shaped declarations incompatible with Zod v4 (`schema.ts:7-15`), and monkey-patches the Mastra chunk processor to surface approval/error events upstream swallows (`worker/src/features/in-app-agent/runtime/agent.ts:1348-1456`) — pragmatic bridges documented inline. Openhands insulates rather than patches: SDK-generated discriminator names are captured once in constants modules and type guards key on stable consumer-side names (`constants/canvas-ui.ts:1-10`; `type-guards.ts:183-200`). Both accumulate maintenance debt; langfuse's sits in runtime patching, openhands' in hand-mirrored shapes like `ConfiguredAgentSettings`, written by hand rather than derived from a schema (`agent-server-adapter.ts:817-947`).
- **Where each leaks shape-only contracts.** Langfuse: some AG-UI handlers accept `Record<string, unknown>` and lose exhaustiveness (`persistence.ts:1438-1453`); `SandboxProvider.suspendSession` means "leave the container running" for Docker but a real microvm suspend for Lambda — a semantic difference carried by comments and log lines, not types (`providers/docker.ts:211-219`; `config.ts:15-19`). Openhands: `SettingsUpdateRequest`'s index-signature escape hatch lets unknown keys through to the server (`settings-service.api.ts:77-85`), and `WorkspaceMode` is a bare literal union with no helper binding UI intent to payload (`conversation-metadata-store.ts:6`). In both, the leak is the same species: structure verified, semantics delegated to humans.

## Tradeoffs

**Hand-authored multi-implementation schemas (langfuse) vs generated single-implementation client (openhands).**
Benefit (langfuse): many real implementations prove the port is satisfiable; schemas express exactly the domain's constraints; validation is explicit. Cost: every contract needs tests, factories, and drift vigilance; upstream type mismatches force duplication or patching. Best-fit: platforms with genuine infra variance. Failure mode: ports that exist but were never proven substitutable — precisely langfuse's flagged conformance gap. Alternative observed (openhands): generation buys guaranteed parity and deletes whole categories of drift, at the price of hypothetical-only substitutability and a hard coupling to the generator's output (`agent-server-adapter.ts:817-947` hand-writes what the schema could derive).

**Narrow ports vs broad service interfaces (within langfuse).**
`SandboxProvider` (four methods, optional extras, result-validated at call time) demonstrates the narrow end: both adapters conform, a third would be caught at the boundary. `StorageService` (ten methods, three upload strategies, buffer/signed-URL paths returning `undefined` on non-S3 adapters) demonstrates the broad end: capability differences are documented inline but invisible to the type system (`StorageService.ts:235-272, 240-242`). Lesson: interface size is a substitutability budget — every method that not all implementations honor converts a compile-time guarantee into a runtime maybe.

**Fail-open capability defaults (openhands `usable_tools`) vs fail-closed config translation (langfuse `TranslatedProviderOptions`).**
Benefit of fail-open: older or minimal servers keep working; features degrade in instead of breaking. Cost: a server that forgets to advertise gets capabilities it may not support — the asymmetry is documented but real (`agent-server-compatibility.ts:149-155`). Benefit of fail-closed: misconfiguration surfaces at setup with actionable detail (`unknownKeys` list). Cost: stricter upgrades break previously-tolerated configs. Best-fit: fail-open for *feature presence*, fail-closed for *identity and credentials*.

**Gradual payload evolution (langfuse optional fields) vs handshake gating (openhands version floor).**
Optional-fields-plus-tests keeps mixed-version fleets flowing but slows feature velocity — required fields demand staged migrations, visible in the four optional attribution fields on `OtelIngestionEvent` (`queues.ts:50-78`). Version floors give clean semantics and loud failures but draw a cliff: below the floor nothing works, so the floor must be chosen conservatively and the rejection must be diagnosable (openhands' error payloads exist exactly for this). Best-fit: queues/shared stores → gradualism; direct client↔server → gating.

**Structural escape hatches (both).**
Langfuse's `Record<string, unknown>` AG-UI handlers survive upstream churn but forfeit exhaustiveness checks at the consumer (`persistence.ts:1438-1453`); openhands' `[key: string]: unknown` on settings diffs forwards arbitrary keys for server-side validation (`settings-service.api.ts:77-85`). Benefit: forward compatibility without lockstep releases. Cost: silent fallthrough — a wrongly-shaped tool passes langfuse's structural check (`tools.ts:109-118`), and undocumented settings keys ship undetected past openhands' compiler. The escape hatch should be a marked, bounded region, not a habit.

**In-process bridging of upstream gaps (langfuse) vs insulation layers (openhands).**
Patching the Mastra chunk stream (`agent.ts:1348-1456`) keeps product moving today and creates a pin to upstream internals tomorrow. Duplicating AG-UI schemas (`schema.ts:7-15`) is the same trade in data form. Openhands avoids runtime patching but pays with hand-synced constants and adapters. There is no free option for depending on imperfect upstreams — pick the debt whose expiry (upstream fix landing) is most predictable.

## Decision Guide

Rules of thumb grounded in the observed models:

- **If both sides of the contract deploy independently against shared state** (queues, databases) → adopt langfuse's Model A: shared-package schemas, discriminated routing unions, validate-on-ingress, and the optional-field evolution rule with regression tests for old shapes. Write down which tier owns correctness (delivery-only queue + durable CAS owner) before the first redelivery happens, not after.
- **If one side consumes the other's generated API surface** → adopt openhands' Model B: own narrowed type families on the consumer, regenerate the client from the server contract, ban raw transports by CI test, and gate startup on an explicit version floor whose failures are typed and diagnostic. Accept that substitutability is out of scope; invest the saved effort in early-failure detection instead.
- **If substitution is a real requirement** (multiple plausible backends) → declare the port next to the consumer, keep it under ~5 core methods, validate adapter outputs at the boundary, and — the step both sources skipped — add a conformance suite running every implementation through the consumer's scenario matrix before counting on it.
- **When a set of named things each need attached policy or behavior** → use a closed registry typed with `satisfies`/`keyof` (or a constants module + closed lookup table) so additions without handling fail compilation.
- **When `instanceof` must cross bundles or duplicated packages** → switch to registered symbols (`Symbol.for`) or dual checks (structural + instanceof). Never rely on constructor identity across realms.
- **Choosing defaults:** fail open for capability advertisement, fail closed for configuration and credential resolution, and say which policy each field uses — the dangerous cases observed were the undocumented middle (undefined returns meaning "unsupported", `:240-242` in langfuse's StorageService).
- **When an upstream dependency's types don't fit your stack** → prefer duplicating its schemas locally behind a TODO-and-tracking-link (revertible) over runtime patching (sticky), and isolate any unavoidable patch in one named function with a comment explaining the upstream gap.

## Practical Tips

**Copy these.**

- Discriminated unions with literal discriminators for every routed payload; reject unknown discriminators in validation (both sources).
- Re-validate at every boundary — including reads of your own persisted/local state and results from your own first-party adapters (langfuse `service.ts:92-125`; openhands `storage.ts:24-40`).
- Typed error hierarchies whose instances carry the diagnostics a support engineer needs (`actualVersion`, `requiredVersion`, `code`), identified via realm-safe checks (both sources).
- A CI test that enforces the sanctioned transport/import path with an explicit, short allow-list (openhands `no-direct-agent-server-calls.test.ts:32-79`; langfuse barrel-split bundle scan).
- Rolling-deploy discipline: new payload fields optional, comment at the field, regression test parsing the old shape (langfuse `queues.ts:30-48` + `queues.test.ts:53-87`).
- Pure classifiers mapping messy runtime states onto named verdicts, unit-tested without I/O (langfuse `classifyStaleRun`, `runLifecycle.ts:696-747`).
- Constants modules capturing externally generated names/discriminators so they are named once and never string-matched ad hoc (openhands `constants/canvas-ui.ts:1-10`).
- All-or-nothing admission of third-party manifests/configs with structured error collection, validated against what the host actually implements (openhands `interface-validation.ts:83-86`).

**Avoid or delay until needed.**

- Ten-method service interfaces where some methods silently don't apply to some adapters — split capability-specific methods into narrower interfaces until the second adapter forces the issue (langfuse `StorageService`).
- Structural duck-typing as a *primary* identity mechanism; keep it as a documented fallback with a comment explaining why `instanceof` failed (langfuse `tools.ts:132-135`).
- Index-signature escape hatches (`[key: string]: unknown`) on contracts whose semantics live only in doc comments — either encode the invariant in the type or add a test that executes it (openhands settings diff).
- Runtime monkey-patching of upstream libraries beyond one isolated, commented bridge function (langfuse Mastra chunk patch).
- Big discriminated unions whose variants lack per-variant parse-regression tests (langfuse batch-action coverage gap).

## Anti-Patterns / Caution Signs

Signs the contract layer is going brittle, drawn strictly from observed evidence:

- **Semantics migrating into prose.** Deep-merge rules, suspension-vs-termination differences, and secret-stripping conventions living in comments or log lines rather than types or tests (openhands settings docs; langfuse Docker-vs-Lambda suspend; `conversation-metadata-store.ts:38`). Comments document intent; nothing enforces it — the next implementer will read the type and skip the prose.
- **Identity checks quietly degrading to shape checks.** When `instanceof` starts failing across packages and teams respond by spreading structural fallbacks, the contract has lost its ability to say *which* implementation it is talking to (langfuse `withOptionalSilentMcpOutput`).
- **Duplicated upstream contracts without an expiry plan.** Local copies of third-party schemas are fine with a TODO and tracking link; they rot when the upstream fixes itself and nobody notices (langfuse AG-UI duplication).
- **Undefined-as-capability-bit.** Methods returning `undefined` to mean "not supported by this adapter" turn the type system into documentation (`StorageService.ts:240-242`).
- **Capability flags that default to allow.** Absence of information resolving to "permitted" is safe only until the first provider that forgets to advertise (openhands `usable_tools`, acknowledged asymmetry).
- **Untested union arms.** Nine batch-action ids, two exercised paths — the union compiles, the tests pass, the untested arm drifts (langfuse §Tradeoffs).
- **Single-implementation contracts marketed as abstraction.** An interface with exactly one realization and no conformance test is a naming convention, not a seam; fine if acknowledged (openhands does), corrosive if relied upon for substitution that was never exercised.
- **Orchestration-level (study) anti-pattern:** dispatching analysis/consumers against inputs that were never materialised, with no fail-fast gate — nine of eleven sources produced no-evidence reports measuring logistics instead of architecture (flagged independently by the agent-framework, crewai, langgraph, letta, opa, pydantic-ai, and reports analyses).
