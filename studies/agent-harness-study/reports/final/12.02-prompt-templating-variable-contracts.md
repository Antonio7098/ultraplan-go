## Executive Summary

None of the eight sources ships a conventional, general-purpose template engine for LLM prompts. No active Jinja2, Mako, or Handlebars-in-the-large exists anywhere in the studied trees: letta's three Jinja2-syntax files are dead artifacts with no loader (`letta/templates/summary_request_text.j2`, reimplemented as a Python function at `letta/services/summarizer/summarizer.py:436-457`); langgraph's core library contains zero prompt-related code and delegates classical templating to the external langchain-core library; openai-agents-sdk contains no template dependency at all and forwards variables as structured JSON to the server. What exists instead is a spectrum of deliberately minimal mechanisms — hand-rolled regex substitution (agent-framework .NET Magentic at `dotnet/src/Microsoft.Agents.AI.Workflows/Specialized/Magentic/PromptTemplates.cs:12-31`, crewai's ~70-line `interpolate_only` at `lib/crewai/src/crewai/utilities/string_utils.py:79-150`, langfuse's mustache compiler at `packages/shared/src/utils/prompts.ts:14-28`), single-variable retreats (letta's `{CORE_MEMORY}`), expression languages scoped to structured workflows (Power Fx in agent-framework declarative, CEL in crewai Flows), and one genuine external engine adopted behind a typed wrapper (pydantic-ai's Handlebars via `pydantic-handlebars`).

The dimension's central question — *can a prompt template be reused with different variables safely?* — splits cleanly along where validation happens. The sources that check template variables against an explicit contract **before rendering** answer yes emphatically: pydantic-ai fails construction on unknown names against `deps_type`/`deps_schema` (`pydantic_ai_slim/pydantic_ai/template.py:63-68`, tested at `tests/test_template.py:73-80`); crewai's Flow layer rejects unknown CEL roots at declaration load (`lib/crewai/src/crewai/flow/expressions.py:195-227`); openhands rejects manifests whose placeholders fall outside published namespaces at admission (`src/manifests/manifest-validation.ts:46-49`). The sources that defer checking to render time or skip it entirely answer "sometimes": crewai's classic crews surface typos only mid-kickoff as raw `KeyError`s (`lib/crewai/src/crewai/agents/agent_builder/base_agent.py:794-802`), langfuse's shared compiler silently preserves unfilled placeholders (`packages/shared/src/utils/prompts.ts:20`), and agent-framework's Python interpolation replaces well-formed-but-typo'd tokens with empty strings and no diagnostic (`python/packages/declarative/agent_framework_declarative/_workflows/_declarative_base.py:927`).

Escaping interpolated **values** into prompts is absent in all eight sources — universally accepted as inherent to LLM prompting. Where escaping-like machinery does exist, it guards resolvers and non-LLM surfaces: path-traversal resistance in agent-framework's state interpolator (`_declarative_base.py:391-399`), regex metacharacter escaping in langfuse's prompt-composition resolver (`packages/shared/src/server/services/PromptService/utils.ts:1-3`), markup bans in openhands manifests (`src/manifests/manifest-validation.ts:27-28`), and HTML escaping delegated to React or UI layers.

## Core Thesis

**Prompt templating maturity is determined not by which engine is chosen but by when variable contracts are enforced and whether that enforcement is honest about what it covers.** Three findings anchor this thesis across the corpus:

1. **Enforcement timing is the real design axis.** Every source can substitute text; they differ sharply on whether an unknown variable is caught at construction (pydantic-ai, openhands admission, crewai Flow declarations, agent-framework skills probe at `python/packages/core/agent_framework/_skills.py:2324-2343`), at kickoff/render time (crewai tasks, langgraph framework paths), or never (silent empty-string/preserve paths in agent-framework Python, letta, langfuse batch workers). The 7-scoring sources are exactly those with early enforcement; the 5–6 scorers tolerate multiple silent regimes within one codebase.

2. **Every source is internally inconsistent about missing variables.** Not one source has a single missing-variable policy. agent-framework alone exhibits leave-literal (.NET regex), `KeyError` (Python `str.format`), empty-string (Python interpolation), exception (declarative malformed segments), and fail-fast-probe (skills) behaviors across five subsystems; crewai ranges from field-contextualized `ValueError`s to silent no-op marker replacement. This is the strongest cross-corpus signal: fragmentation happens *within* products, not just between them, because each feature adopts whatever mechanism was nearest at hand.

3. **The value-escaping question is settled by consensus — and the resolver-escaping question is not.** All eight sources insert substituted values verbatim into LLM-bound text; none treats indirect prompt injection through values as a solved or even addressed problem (explicitly documented as a trust decision only in openhands, `src/manifests/manifest-validation.ts:4-8`, and crewai flow scripts, `lib/crewai/src/crewai/flow/runtime/_actions.py:268-273`). But the *mechanical* integrity of substitution — no re-expansion of inserted content, safe path resolution, regex-safe names — is engineered seriously where tested: agent-framework pins a no-re-expansion guarantee with adversarial input (`dotnet/tests/Microsoft.Agents.AI.Workflows.UnitTests/PromptTemplatesTests.cs:209-232`), while crewai's iterated replace leaks nested expansion (`string_utils.py:135-148`) and openai-agents-sdk's chained `.replace()` calls have an order-dependent hazard (`src/agents/sandbox/memory/prompts.py:64-68`). Single-pass substitution with a regression test is the differentiator between trustworthy and merely functional engines.

## Approach Models

Clustering the corpus yields four approach models, ordered by how much templating work the framework itself owns:

**Model A — Composition over templating (langgraph, partially openai-agents-sdk).** The framework defines no string-interpolation engine. langgraph's `Prompt` union type (`SystemMessage | str | Callable[[StateSchema], LanguageModelInput] | Runnable`, `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:121-126`) treats plain strings as static content that is never interpolated (`chat_agent_executor.py:143-148`); dynamic prompts are user functions receiving the full typed graph state, with runtime context injected via the signature-inspected `KWARGS_CONFIG_KEYS` table (`libs/langgraph/langgraph/_internal/_runnable.py:168-229`). Variables become ordinary typed code; missing-variable errors become Python errors inside user logic. openai-agents-sdk applies the same philosophy at the boundary: its `Agent.prompt` carries `{id, version?, variables?}` to the Responses API and substitution happens platform-side (`src/agents/prompts.py:23-33`, forwarded at `src/agents/models/openai_responses.py:980`).

**Model B — Minimal hand-rolled substitution (crewai core, langfuse, openhands manifests, agent-framework Magentic, letta).** Each implements a tiny custom engine tuned to one constraint: crewai's identifier-only regex deliberately ignores JSON braces so embedded examples survive task descriptions (`string_utils.py:83-85`, proven at `lib/crewai/tests/utilities/test_string_utils.py:33-76`); langfuse's ~20-line mustache compiler shares exported regexes (`MUSTACHE_REGEX`, `VARIABLE_REGEX`) as a common vocabulary for editors, previews, and workers (`packages/shared/src/utils/stringChecks.ts:7-18`); openhands' dotted-path engine explicitly refuses any expression language ("a setup block cannot express behavior here", `src/manifests/manifest-template.ts:4-8`); agent-framework's .NET regex substitutes only documented tokens so literal braces need no escaping (`MagenticPromptOverrides.cs:15-19`); letta reduced its runtime surface to one reserved token, `{CORE_MEMORY}` (`letta/constants.py:64`).

**Model C — Expression-language templating for structured workflows (agent-framework declarative, crewai Flows).** When templates must compute rather than interpolate, both sources adopt sandboxed expression engines with scoped symbol tables: Power Fx segment trees evaluated against `WorkflowFormulaState` scopes (`dotnet/src/Microsoft.Agents.AI.Workflows.Declarative/PowerFx/WorkflowFormulaState.cs:19-147`) and CEL expressions validated against allowed roots at declaration time (`expressions.py:195-227`). These are the only two subsystems in the corpus where templates contain executable logic, and both pair the engine with explicit scope governance (unknown-scope rejection, root allowlists).

**Model D — External engine behind a typed contract wrapper (pydantic-ai).** Handlebars is adopted wholesale via `pydantic-handlebars`, but wrapped so tightly that the engine becomes invisible: `TemplateStr` compiles once in `__init__`, validates every placeholder name against `deps_type` or `deps_schema` at that moment (`template.py:63-68`), exposes `__call__(ctx)` so the existing dynamic-prompt pipeline consumes it with zero special cases (`template.py:85-87`), and round-trips through YAML specs by re-validating during Pydantic parsing (`template.py:100-108`). This model gets full template expressiveness *and* early contract checks, at the cost of depending on external render semantics.

## Pattern Catalog

### P1. Compile-once / validate-at-construction contracts

- **Problem:** template variable mistakes discovered at render time surface far from authoring, sometimes mid-run after expensive upstream work.
- **Demonstrated by:** pydantic-ai (construction-time `ValueError` on unknown names, `tests/test_template.py:73-80`); agent-framework skills provider (probe-formatting a candidate template with sentinels before accepting it, `_skills.py:2326-2343`); crewai Flow layer (declaration-time CEL root allowlist wired at `flow_definition.py:928-967`); openhands (whole-manifest admission rejection, `manifest-validation.ts:15-17`).
- **Why it works:** compilation already parses the template; comparing parsed placeholder names against a declared contract is nearly free, and failures land where developers are looking.
- **When to copy:** whenever templates cross an API boundary — constructor arguments, YAML/spec files, third-party submissions.
- **When overkill/risky:** internal developer-owned constants where a mistake is a trivially debugged crash (langgraph's tool-node error templates are fine unvalidated, `tool_node.py:108-121`).
- **Evidence quality:** strong — negative tests pin the behavior in pydantic-ai and openhands admission tests (`__tests__/manifests/manifest-validation.test.ts:80`).

### P2. Contract-as-test: documentation that cannot drift

- **Problem:** placeholder contracts written only in docs rot silently.
- **Demonstrated by:** agent-framework pairs XML-doc placeholder lists with a theory test asserting published defaults retain those placeholders (`MagenticPromptOverrides.cs:24-72` + `PromptTemplatesTests.cs:250-261`); openhands pins rendered request bodies to fixtures "verified against the live service" so a template-engine change fails CI as a would-be production 422 (`__tests__/manifests/automation-setup.test.ts:62-96,225-241`); openhands also test-enforces placeholder parity across all 15 i18n locales (`__tests__/i18n/translation-completeness.test.ts:118-135`).
- **Why it works:** the contract becomes an executable artifact; CI, not reviewers, catches drift.
- **When to copy:** any template whose output shape another system depends on.
- **When overkill:** throwaway or fully internal strings.
- **Evidence quality:** strong; the fixture approach even catches divergence from a mirrored implementation in another repo.

### P3. Literal-preserving conservative grammars

- **Problem:** LLM prompts legitimately contain braces — JSON schemas, code samples, `${...}`-style text — that naive formatters mangle.
- **Demonstrated by:** crewai's identifier-only pattern leaves `{123}`, `{!var}`, and whole JSON objects untouched (tested at `test_string_utils.py:133-146`); agent-framework .NET leaves unmatched tokens verbatim (`PromptTemplates.cs:29-30`); letta's `PreserveMapping.__missing__` returns `"{"+key+"}"` so unknown placeholders survive (`letta/prompts/prompt_generator.py:15-19`, tested at `tests/test_utils.py:437-467`); langfuse documents triple-brace escape hatching (`{{{name}}}` renders `{value}`, `stringChecks.ts:10-12`); crewai CEL supports `${'${'}` for literals (`tests/test_flow_from_definition.py:932-941`).
- **Why it works:** making the grammar strict enough to exclude prose means authors never learn escaping rules.
- **When to copy:** always, for prompt surfaces. This is arguably the single most transferable pattern in the study.
- **Risk:** literal-preservation plus silent-missing combines into invisible degradation — a typo'd `{Local.UserNamme}` renders as an empty hole in agent-framework Python precisely because the grammar accepted it (`_declarative_base.py:927`).

### P4. Single-pass substitution with adversarial-value regression tests

- **Problem:** if replacement output is re-scanned for later placeholders, attacker- or accident-controlled values can rewrite other parts of the prompt (second-order injection).
- **Demonstrated positively:** agent-framework substitutes in one pass and never re-scans inserted values, with a test feeding task text containing `{schema}`/`{team}` and asserting verbatim survival (`PromptTemplatesTests.cs:209-232`).
- **Demonstrated negatively:** crewai's loop iterates original-template variables but replaces against the mutated string, so an input containing `{b}` expands again if `{b}` appears later (`string_utils.py:135-148`); openai-agents-sdk chains sequential whole-document `.replace()` calls where an earlier value containing a later placeholder gets rewritten (`src/agents/sandbox/memory/prompts.py:64-68`); langfuse hardens this seam explicitly by doubling `$` in replacement strings (`PromptService/index.ts:375-377`).
- **Why it matters:** single-pass is a one-line implementation decision that eliminates an entire bug class; the test proves it stays eliminated.

### P5. Shift-left validation into editors and admission gates

- **Problem:** server-side or render-time validation reaches users too late.
- **Demonstrated by:** langfuse runs live CodeMirror diagnostics for multiline, unclosed, empty, and invalid-name variables (`web/src/components/editor/CodeMirrorEditor.tsx:73-115`) and blocks playground submission naming unset variables (`web/src/features/playground/page/context/index.tsx:958-965`); openhands rejects manifests at admission before any UI or request exists (`manifest-validation.ts:15-17`); openhands additionally maps server 422 errors back to exact form fields by rebuilding payloads with `{{form.<name>}}` stand-ins (`deriveErrorMap`, `src/manifests/automation-setup.ts:387-434`).
- **Why it works:** authoring-time feedback converts contract violations from runtime incidents into editing nudges.
- **Caveat:** shift-left only helps surfaces it covers — programmatically assembled payloads bypass local validation entirely (openhands tradeoff note), and langfuse's public create API validates structure but not variable syntax (`packages/shared/src/features/prompts/types.ts:28-61`).

### P6. Templates-as-callables / composition normalization

- **Problem:** supporting both static strings and dynamic prompt producers fragments the execution path.
- **Demonstrated by:** pydantic-ai makes `TemplateStr.__call__(ctx)` match the existing callable contract so `SystemPromptRunner` handles it uniformly (`template.py:85-87`, consumed at `pydantic_ai_slim/pydantic_ai/agent/__init__.py:3013-3020`); langgraph normalizes every prompt form once in `_get_prompt_runnable` then composes `prompt_runnable | model` (`chat_agent_executor.py:137-170`); openai-agents-sdk resolves static and dynamic prompts concurrently each turn with deterministic sibling cancellation (`run_internal/run_loop.py:2097-2100`, tested at `tests/test_agent_prompt.py:153-221`).
- **Why it works:** one downstream pipeline means one place to add tracing, caching, or validation.
- **Observability bonus:** langgraph names the prompt step `PROMPT_RUNNABLE_NAME = "Prompt"` so it appears as a distinct trace span (`chat_agent_executor.py:119`); pydantic-ai emits rendered descriptions into OTel span attributes (`capabilities/instrumentation.py:178-181`); langfuse tags compile stages in eval spans (`worker/src/features/evaluation/evalService.ts:1018-1020`).

### P7. Explicit degradation tiers for auxiliary injections

- **Problem:** some substitutions are nice-to-have; failing a run over them is wrong, but failing silently forever is also wrong.
- **Demonstrated by:** crewai drops invalid date-format injections with a logged warning instead of failing (`utilities/prompts.py:153-161`); openhands omits optional suffix lines structurally and emits an explicit "Automation backend: not running" sentence rather than blank space (`src/api/agent-server-adapter.ts:239-279`); langfuse degrades unmapped eval variables to `""` with logs while throwing with remediation guidance for deleted dataset items (`evalService.ts:1516-1541,1557-1566`).
- **Why it works:** availability-vs-correctness is decided per data class, not globally — and the degrade paths log.
- **Contrast:** letta performs the same append-if-missing maneuver for `{CORE_MEMORY}` but commented out the warning log (`prompt_generator.py:156-162`), turning a reasonable tier into an invisible one.

## Key Differences

**Where substitution happens.** Platform-shaped sources move it off-repo: openai-agents-sdk transports variables as JSON fields so client-side escaping is moot by construction (`openai_responses.py:980`), and langfuse stores templates verbatim while each consumer compiles them (`CreatePromptSchema`, `packages/shared/src/features/prompts/types.ts:28-56`). Framework-shaped sources own substitution because they execute prompts. This is product shape, not quality: the SDK cannot validate variables client-side without fetching template metadata it deliberately doesn't mirror.

**Strings-as-static vs strings-as-template.** langgraph treats every plain string as complete, immutable content (`chat_agent_executor.py:143-148`) — eliminating the entire format-bug class by refusing interpolation. pydantic-ai takes the opposite stance on its spec path: any YAML string containing `{{` is auto-compiled (`template.py:100-102`), meaning the same literal behaves differently in Python (stored verbatim, `agent/__init__.py:651`) versus YAML (compiled). Both are coherent answers to "what does a string mean," but they make migration between entry points hazardous in pydantic-ai's case and impossible-to-break in langgraph's.

**Expression languages: embraced vs refused.** agent-framework and crewai give structured workflows real computation (scoped Power Fx, rooted CEL), accepting evaluator complexity and fallback ladders (agent-framework degrades PowerFx → `_eval_simple` → return-original, `python/packages/declarative/agent_framework_declarative/_workflows/_state.py:376-386`). openhands refuses expression evaluation outright and pushes logic into skills, keeping the template language "trivially auditable" (`src/manifests/manifest-template.ts:4-8`). The refusal is a security posture: no expression engine means no expression-injection class at all.

**Error enrichment discipline.** crewai's task layer translates internal `KeyError`s into `ValueError`s naming both variable and field (`task.py:1084-1089`) — while its own agent layer propagates bare `KeyError`s (`base_agent.py:794-802`), showing enrichment applied unevenly within one repo. langgraph consistently names key and runnable in framework errors ("Missing required config key '<key>' for '<name>'", `_runnable.py:413-418`). openai-agents-sdk under-enriches: a malformed prompt dict raises bare `KeyError('id')` rather than its existing `UserError` type (`src/agents/prompts.py:79`).

**Silent-degradation tolerance.** letta and agent-framework Python accept invisible holes as the price of uptime; langfuse accepts them only in batch contexts while interactive surfaces fail fast; langgraph confines silence to helper defaults (`_get_state_value(..., default=None)`, `chat_agent_executor.py:129-134`) while framework paths raise. The difference tracks operational context: chat UX favors continuity; eval pipelines favor throughput; graph frameworks can afford strictness because errors are cheap to attribute.

## Tradeoffs

- **Fail-fast construction vs flexibility.** pydantic-ai's compile-once validation catches typos early but forbids dynamically-shaped deps unless users skip the contract entirely — there is no warn-on-unknown middle ground (`pydantic_ai_slim/pydantic_ai/template.py:57-70`; gap noted in its report). openhands solves this differently: lenient `""` substitution at render, backed by required-field validation, defaults, and a server-side preflight of rendered drafts (`manifest-local-validation.ts:116-164`, `automation-setup.ts:353-365`). Best-fit: strict construction for API-crossing templates; lenient-plus-preflight for user-authored ones.
- **One engine vs many idioms.** crewai matches syntax to community expectation — Modelfile markers for Ollama porters, f-string-style `{name}` for Python users, CEL for typed flows — at the cost of five maintenance surfaces and non-uniform behavior (`utilities/prompts.py:230-251`, `flow/expressions.py`). letta shows the opposite extreme: one token, bulletproof common case, but user-defined variables permanently `NotImplementedError` (`prompt_generator.py:128-130`).
- **Delegation vs integration.** langgraph leaning on langchain-core avoids a second implementation but forfeits integration-level validation — LangGraph never knows what variables a composed `ChatPromptTemplate` requires (`test_pregel.py:3796-3801` shows the delegation pattern). pydantic-ai wrapping handlebars keeps integration (validation, typing) while delegating rendering — but then inherits undocumented render semantics for untyped templates.
- **Availability vs diagnosability.** agent-framework's graceful degradation ladder keeps declarative workflows running when `powerfx` is absent, but the same YAML can evaluate differently per environment and raw `=...` residue can leak into rendered prompts (`_state.py:448-509,560-561`). Silence buys uptime and costs truth.
- **Re-scanning vs declaring variables.** langfuse derives variables from current content at each surface — always consistent with edits, but it prevents type/default/required metadata and leaves the public API unable to reject bad templates (`web/src/features/playground/page/context/index.tsx:242`). Declared schemas (pydantic-ai's `deps_schema`, openhands' `SetupFieldConstraints`) enable richer checks but require authors to maintain them.
- **Raw fidelity vs structural safety in structured prompts.** letta writes memory-block labels and values raw into XML-ish tags (`f"<{label}>"`, `letta/schemas/memory.py:150-173`) for renderer speed; a label like `my block>` corrupts markup that `ContextWindowCalculator` parsing depends on. openhands bans markup characters at the source for host-rendered copy while correctly exempting transport-only request bodies (`manifest-validation.ts:27-28,124-133`) — the same distinction letta hasn't drawn.

## Decision Guide

Choosing a prompt-parameterization strategy, based on what the corpus demonstrates:

1. **Variables come from typed application state, IDE support matters → composition/callable model (langgraph, pydantic-ai-preferred-path).** Make the prompt producer a function over typed inputs; the type system becomes the variable contract. langgraph's signature-injected kwargs table (`_runnable.py:168-229`) shows how to keep hidden data flow visible in signatures.
2. **Templates embed JSON/code examples authored by end users → conservative hand-rolled substitution (crewai, agent-framework .NET).** An identifier-only grammar plus single-pass replacement preserves prose fidelity without teaching escaping. Adopt agent-framework's adversarial regression test (`PromptTemplatesTests.cs:209-232`) the day you write the engine.
3. **Templates arrive from third parties → admission-gate them (openhands).** Publish allowed namespaces/constants, reject everything else at intake, pin rendered outputs to fixtures verified against the consuming service. Do not rely on downstream tolerance.
4. **Reusable managed templates across SDKs/languages → delegate to a platform (openai-agents-sdk).** Transport variables as structured fields; accept that client-side validation requires fetching template metadata, and plan for it (the SDK currently doesn't, `src/agents/prompts.py:32-33`).
5. **Templates need conditionals/computation in declarative configs → scoped expression language with allowlisted roots (crewai CEL, agent-framework Power Fx)** — and only then. Both sources confine expressions to structured workflow layers, never free-form prompt strings.
6. **Batch pipelines over many items → decide the missing-variable policy explicitly and instrument it (langfuse).** Interactive surfaces throw with named variables; batch degrades to `""` with logs — the split is deliberate (`evalService.ts:1510-1541`). Copy the split, not the absence of telemetry.

A composite recommendation emerges directly: **use Model A/B mechanics, Model D validation timing, and openhands admission discipline wherever templates cross a trust boundary.**

## Practical Tips

- **Write the no-re-expansion test first.** One test — value containing a valid-looking placeholder must survive verbatim — pins the most important engine property (agent-framework `PromptTemplatesTests.cs:209-232`). If your engine fails it, fix the engine, not the test.
- **Prefer leaving unmatched tokens literal over substituting empty strings**, but pair it with a lint/diagnostic pass. Literal preservation keeps debugging possible (you can see `{UserNamme}` in the prompt); empty-string substitution destroys the evidence (agent-framework Python path, `_declarative_base.py:927`).
- **Validate caller-supplied templates at construction with a probe**: format the candidate against sentinel values and verify the sentinels come back out (agent-framework skills, `_skills.py:2326-2343`). It catches both syntax errors and missing-required-placeholder mistakes in ~10 lines.
- **Publish placeholder contracts next to defaults, and test them together.** Expose default templates publicly so overrides can build on them (agent-framework `MagenticDefaultPrompts.cs:9-30`), document per-prompt placeholders in the override API (`MagenticPromptOverrides.cs:11-72`), and assert the pairing in CI.
- **Serialize non-string values through one choke point.** langfuse's `[object Object]` bug exists because two sibling compilers serialize differently (`String(value)` vs JSON, `prompts.test.ts:14-32`); route all coercion through one `parseUnknownToString`-style function.
- **Escape regex metacharacters anywhere a name enters `new RegExp(...)`**, even when upstream validation currently guarantees safety — langfuse flags its own unescaped case as latent debt (`compileChatMessages.ts:28`) and already owns the helper (`escapeRegex`, `PromptService/utils.ts:1-3`).
- **Keep volatile blocks at the tail of assembled prompts** so stable prefixes stay cache-friendly (crewai appends date/skill catalogs last, `utilities/prompts.py:144-171`); letta goes further with persisted compiled prompts rebuilt only on memory change, guarded by diff (`letta/services/agent_manager.py:1465-1517`).
- **Name the prompt step in traces** (langgraph's `"Prompt"` span, pydantic-ai's OTel description attributes) — prompt assembly becomes observable without changing any template.
- **Delete dead template machinery.** letta's orphaned `.j2` files, deprecated-but-present `prompt_template` fields, and duplicated `safe_format` are exactly how future maintainers edit the wrong artifact (`letta/templates/summary_request_text.j2` vs `summarizer.py:436-457`). Inert flags (agent-framework's unconsumed `Format.strict`, `_models.py:488-499`) invite false confidence; enforce or remove.

## Anti-Patterns / Caution Signs

- **Inert contract surfaces.** Schema fields that promise validation the runtime never performs: agent-framework's `Format.strict` defined but never read outside tests (`_models.py:494`); letta's `"mustache"` enum member that always raises (`prompt_generator.py:173-175`) and `user_defined_variables` raising `NotImplementedError` while a protected-name check above it can never fire (`prompt_generator.py:128-136`). Caution sign: grep finds schema definitions with zero consumers.
- **Chained or iterated replacement.** Sequential `.replace()` passes make output depend on value content and call order (openai-agents-sdk ordering hazard, `prompts.py:64-68`); iterated loops enable second-order expansion (crewai, `string_utils.py:135-148`). Any multi-pass substitution should be treated as a defect unless proven otherwise.
- **Missing-variable silence without diagnostics.** Empty-string fills with no logging (agent-framework interpolation; openhands `toText()`, `manifest-template.ts:35-37`; langfuse eval worker), or warnings written then commented out (letta, `prompt_generator.py:161`). The failure signature: plausible-looking outputs built on incomplete prompts, discoverable only by diffing rendered text.
- **Unescaped structural grammar.** Interpolating raw user-controlled labels/values into markup the system itself parses (letta XML-ish tags consumed by `ContextWindowCalculator`) lets content corrupt structure. If a parser reads the prompt's skeleton, the skeleton needs the escaping budget.
- **Duplicated substitution logic.** Two implementations of the same conceptual operation with diverging edge-case semantics (letta's twin `safe_format`; langfuse's two compilers differing on whitespace handling, pinned by their own test at `worker/src/__tests__/evalService.test.ts:184-188`) guarantee eventual behavioral drift.
- **Contract enforcement that varies by layer within one product.** crewai enriches errors in the task layer but not the agent layer; agent-framework's behaviors change per subsystem. Developers crossing boundaries get surprised; the predictability hazard is the inconsistency itself, not any single behavior.
- **Latent injection in helpers.** Exported functions that interpolate parameters into `RegExp` or interpreters without defensive escaping, relying on today's callers for safety (langfuse `replaceTextVariables`, `compileChatMessages.ts:28`). Helpers should carry their own defenses because call-site discipline decays.

## Notable Absences

Consistently absent across all eight sources (each verified by targeted searches in the per-source reports):

- **No value escaping/sanitization for LLM-bound text anywhere.** Substituted task text, tool results, memory values, and dataset fields flow verbatim into prompts in every source. Only agent-framework XML-escapes injected *metadata* (skill names/descriptions, `_skills.py:2352-2353`) — and nothing escapes narrative content.
- **No typed variable schemas binding types/defaults to template variables** in most sources. Contracts are name-based throughout; langfuse states explicitly that no `Record<var, type>` evidence was found; pydantic-ai's `deps_type` comes closest but its schema check remains name-level only (`docs/agent-spec.md:143`).
- **No prompt-content escaping utilities in langgraph, openai-agents-sdk, pydantic-ai, or crewai** — searches for escape/sanitize/redact found only SQL-pattern escaping, OTel exception escaping, and display-layer HTML escaping.
- **No observability on degraded substitutions in batch paths** beyond debug/error logs (langfuse recommends counters; letta disabled its one warning).
- **No aggregate size limits on rendered prompts** in openhands (per-field `maxLength` only; `MAX_MESSAGE_LENGTH` caps manifest-authored messages, not user-entered values) — a gap likely shared elsewhere since no source mentions one.
- **No documented threat model for indirect prompt injection through interpolated values**, except code-comment-level trust statements in openhands (`manifest-validation.ts:4-8`) and crewai flow scripts (`_actions.py:268-273`). langgraph feeds LLM-generated tool names and exception reprs back into `ToolMessage`s by design with neither sanitization nor risk documentation (`tool_node.py:430,1272-1275`).

## Per-Source Notes

Brief normalized summaries; details live in the per-source reports.

- **agent-framework (6):** Five coexisting templating subsystems with distinct syntaxes and failure modes; the .NET Magentic surface (documented contract + no-re-expansion test) is the corpus's best-engineered classical template; Power Fx declarative adds scoped expressions with a fallback ladder; Python sides lack upfront validation and resolve typos to empty strings.
- **crewai (6):** User-facing inputs use a brace-conservative `interpolate_only` with loud contextual errors and snapshot-based re-interpolation; framework slices fill via `str.format` over `en.json`; Ollama-marker templates silently no-op; the newer Flow layer's CEL system (declaration-time root allowlists, structured errors) is the mature subsystem pointing at where the project is heading.
- **langfuse (6):** Prompt-management platform with a shared mustache lexical core reused by editors, previews, and workers; enforcement is strongest where money is at stake (evaluator v2 server-side equality checks) and weakest at the public API boundary; preserve-vs-throw is decided per surface rather than by the compiler.
- **langgraph (7):** No engine, by design — a typed `Prompt` union plus callables over state makes variables ordinary code; framework paths fail fast with precise errors while helper paths default silently; classical templating is delegated opaquely to langchain-core.
- **letta (5):** Deliberate performance-driven retreat to one reserved `{CORE_MEMORY}` token with imperative prompt assembly and persisted compiled prompts; correct-but-lenient semantics undermined by dead Jinja2 artifacts, duplicated substitution logic, unreachable safety checks, and raw XML-tag rendering without escaping.
- **openai-agents-sdk (6):** Templating owned by the server; the SDK transports `{id, version, variables}` with clean structural validation and capability gating on unsupported backends; internal renderers mix three ad-hoc styles; client-side feedback for variable mistakes requires a network round trip.
- **openhands (7):** Frontend composes prompts through three surface-scoped mechanisms; the manifest subsystem is the corpus's most complete trust-boundary treatment — published namespaces, admission rejection, markup bans, opt-in expression-literal guards, live-service fixture pinning, and error-to-field mapping — weakened mainly by silent blanks with no observability.
- **pydantic-ai (7):** Full Handlebars adoption disciplined by compile-once validation against `deps_type`/`deps_schema`, threaded through Pydantic validation contexts so YAML specs and Python constructors share one contract bus; gaps concentrate in untyped-template render semantics delegated to the external library and the spec-path auto-compilation asymmetry.
