## Executive Summary

Ten sources were scheduled for this dimension, but only two delivered an inspectable code payload: **langfuse** and **openhands**, each rated **8/10** ("clear model with tests, explicit interfaces, and operational safeguards"). The other eight — agent-framework, crewai, langgraph, letta, opa, openai-agents-sdk, pydantic-ai, and temporal — had empty source directories on disk; the only artifact for each was its UltraPlan descriptor YAML naming the upstream repository and applicable dimensions. Their per-source reports correctly recorded "no clear evidence found" across every rubric row and scored the floor of the band rather than fabricating findings. Every comparative claim in this report therefore rests on exactly two evidence-backed sources; nothing about the unmaterialized upstreams can be affirmed or refuted.

Despite radically different product shapes — langfuse is a multi-runtime TypeScript platform monorepo (Next.js web + Express/BullMQ worker + Prisma/ClickHouse data layer), while openhands is a single React SPA that doubles as an embeddable npm library (`@openhands/agent-canvas`) plus an Electron wrapper — the two converge on the same boundary vocabulary:

- An **explicit export surface** (`package.json#exports` maps with named subpaths) as the de facto public API contract.
- A **machine-checked dependency direction**: an ESLint restricted-import rule plus either file-walking boundary tests (openhands) or a dependency-cruiser rule set with a ratcheting violation baseline (langfuse).
- A **regression-tested public surface** so internal modules cannot silently leak into the published artifact.
- **Colocated docs-as-contract** (per-workspace `AGENTS.md` files kept in lock-step with the manifests).

They diverge where their constraints differ: langfuse enforces boundaries *between deployable packages* with a warn-and-ratchet migration posture over 2,710 known legacy violations, while openhands enforces boundaries *inside one package* with hard-failing CI tests over a much younger codebase. Neither reaches the 9–10 band: langfuse carries heavy migration debt behind warn-only graph rules; openhands concentrates its cloud/local seam in hand-written per-service branches and a single 1,297-line adapter.

The eight empty-payload reports are themselves a material finding: this dimension is uniquely sensitive to source materialization because every artifact it inspects — manifests, imports, visibility markers, separation tests — lives in code. A missing checkout collapses all five analysis steps to "nothing to inspect" regardless of upstream quality, which argues for a pre-flight emptiness check before spending compute on this dimension.

## Core Thesis

Module-boundary quality in agent harnesses is produced by **mechanical artifacts, not folder layout**. Both high-scoring sources express boundaries as four reinforcing layers: (1) an exports map that makes the public surface a build-time fact, (2) a lint or graph rule that catches what the exports map cannot (intra-package deep imports, transport bypasses), (3) regression tests that fail CI when the surface drifts, and (4) prose documentation kept adjacent to the manifest so the rules survive personnel changes. Where legacy debt exists, a committed baseline that can only shrink (langfuse's `.structure-baseline.json`, `web/scripts/structure/stats.mjs:233-252`) converts an impossible big-bang cleanup into a monotonic improvement process.

The corollary answers the dimension's headline question — *"Can you use the tool system without pulling in the entire runtime?"* — affirmatively in both populated sources, but through opposite mechanisms: langfuse achieves independence by **splitting into separately installable workspace packages** with narrowed subpaths (`packages/shared/package.json:17-114`), while openhands achieves it by **excluding everything non-public from the library build** (`tsconfig.lib.json:1-34` + Vite `preserveModules`, `vite.config.ts:215-244`). Independence is a property you build and test for, not one that emerges from tidy directories.

## Approach Models

**Model A — Workspace federation with a written dependency DAG (langfuse).**
Four runtime packages (`web`, `worker`, `packages/*`, `ee`) declared in `pnpm-workspace.yaml:1-6` and orchestrated by a turbo task graph (`turbo.json:11-122`). The dependency direction is stated as a hard rule in root documentation — `web → shared,ee; worker → shared; ee → shared; shared → none` (`sources/langfuse/AGENTS.md:30-36`) — and `@langfuse/shared` empirically imports no `@langfuse/*` sibling. Each package exposes its surface through named `package.json#exports` subpaths rather than one barrel: `@langfuse/shared` alone ships a client-safe root (`packages/shared/src/index.ts:1-137`), a server-only barrel (`packages/shared/src/server/index.ts:1-212`), a Prisma-only `/src/db` entrypoint (`packages/shared/package.json:22-25`), and nine feature-narrowed in-app-agent subpaths (`packages/shared/package.json:74-113`). Structural hygiene is governed by a 20-rule project-structure RFC instrumented in `web/scripts/structure/` and ratcheted through a committed `.structure-baseline.json`. This is an *operational* boundary model: packages map to deployment units and execution contexts (browser vs Node, OSS vs EE).

**Model B — Single-package app/library duality (openhands).**
One React/TypeScript codebase (~135k LoC) whose boundaries are organized along three axes: feature domain × architectural role (`api/`, `hooks/`, `stores/`, `services/`, `components/`) × backend kind (`Backend { kind: "local" | "cloud" }`, `src/api/backend-registry/types.ts:4-13`). The public surface is a hand-curated ship-list barrel (`src/lib/index.ts:1-57`) mapped to eight typed `package.json#exports` subpaths with no wildcard entry (`package.json:206-248`), mechanically bounded by a `tsconfig.lib.json` allowlist that excludes `api/`, `stores/`, `hooks/`, and `utils/` from declaration emit. The only sanctioned route to the agent-server is SDK-typed clients constructed through one options helper (`src/api/agent-server-client-options.ts:52-79`); raw `fetch`/`axios` against `/api/*` is banned by a file-walking test (`src/api/no-direct-agent-server-calls.test.ts:32-79`) mirrored in ESLint (`eslint.config.js:252-271`). This is a *packaging* boundary model: the boundary separates what ships to embedders from what powers the app, inside a single repo.

**Model C — Unassessable (eight sources).**
agent-framework, crewai, langgraph, letta, opa, openai-agents-sdk, pydantic-ai, and temporal all present an empty inspection target. Their descriptors exist (e.g. `sources/letta.ultraplan-source.yml:1-75`, `sources/temporal.ultraplan-source.yml:57`), but no manifest, import graph, visibility marker, or separation test exists to evaluate. Per the isolation rules, none of these reports borrowed evidence from siblings — correctly, since that would have contaminated per-source attribution.

## Pattern Catalog

### P1. The exports map is the public API contract

- **Problem:** Without a build-enforceable surface, internal helpers leak into consumer code and become de facto API.
- **Demonstrated by:** langfuse (`packages/shared/package.json:17-114`, `ee/package.json:7-15`) and openhands (`package.json:206-248`).
- **Why it works:** Subpath entries with explicit `types`/`import`/`require` conditions make deep imports resolvable only through sanctioned entrypoints; openhands additionally ships **no wildcard** `./*` entry, so `import "@openhands/agent-canvas/api/skills-service"` is impossible by construction. Langfuse narrows further per concern — e.g. `./instrumentation/bootstrap` exists solely because OTel initializers must load before `sdk.start()` without dragging in the server barrel (`packages/shared/package.json:42-44`, `packages/shared/AGENTS.md:60-64`).
- **Copy when:** You publish any consumable package, or your monorepo has more than one consumer of shared code.
- **Overkill when:** A single-app repo with no external consumers — there an internal barrel convention suffices.
- **Evidence:** langfuse's exports map spans ~98 lines of deliberate subpaths; openhands pins five subpaths against accidental change in `__tests__/package-library.test.ts:34-60`.

### P2. Machine-checked dependency direction, with a real incident as motivation

- **Problem:** Documented direction decays unless something fails when violated.
- **Demonstrated by:** langfuse — eslint `no-restricted-imports` on `^(\.\./)+(packages|ee|worker)/` blocks relative escapes past the exports map (`web/eslint.config.mjs:33`), with the rule comment citing PR #15031, a production-deploy-breaking relative deep import (`web/eslint.config.mjs:23-36`). openhands — a file-walking test bans raw HTTP clients against `/api/*` across every `.ts`/`.tsx` file (`src/api/no-direct-agent-server-calls.test.ts:32-79`).
- **Why it works:** Both mechanisms convert an architectural preference into a red build. The incident citation matters: it teaches *why* the rule exists, which sustains compliance better than abstract policy.
- **Copy when:** Always, for any multi-package or layered codebase. Prefer pairing a lint rule (fast, precise) with a test (catches shapes lint misses).
- **Overkill when:** A tiny library with one import direction and no internal layers.
- **Caveat:** langfuse notes static-import linting does not cover dynamic `import()` (`web/eslint.config.mjs:27-32`) — a coverage gap worth assuming in any similar rule.

### P3. Regression tests pinning the public surface

- **Problem:** Surfaces drift silently — symbols get added, removed, or renamed without anyone deciding.
- **Demonstrated by:** openhands most explicitly: `__tests__/library-entrypoints.test.ts:1-49` asserts key exports exist as functions *and* that a deliberately removed symbol stays gone (`:44-48`); `__tests__/package-library.test.ts:1-158` asserts the exports shape, rejects git dependencies, and requires exact semver pins. Langfuse's analogue is indirect: the structure-stats snapshot and `pnpm structure:stats --diff` make drift visible (`web/scripts/structure/stats.mjs:233-252`).
- **Why it works:** A failing test forces the surface change to be a reviewed event rather than an accident.
- **Copy when:** Anything publishable. OpenHands' own gap analysis names the next step: a *positive* exhaustive snapshot ("only these names") instead of negative assertions, plus a built-dist `.d.ts` round-trip typecheck to catch prop renames.
- **Overkill when:** Pre-1.0 experimental packages churning daily.

### P4. Multi-surface barrels separating execution contexts

- **Problem:** One barrel per package lets server-only or heavy code (Prisma, ClickHouse drivers, megabyte-scale JSON) leak into bundles that must not carry it.
- **Demonstrated by:** langfuse's three-surface split — client-safe root (server-free, no Prisma among ~137 re-export lines, `packages/shared/src/index.ts:1-137`), server barrel, Prisma-only db entrypoint — with the invariant "mixing them would ship Prisma into browser bundles; nothing crashes when that happens, which is exactly why it has to be structural" (`packages/shared/AGENTS.md:163-167`, `web/scripts/structure/README.md:160-167`); enforced by rule `rfc10-no-client-to-server` (`web/.dependency-cruiser.js:48-64`). openhands' analogue is lib-vs-app: internals excluded from `dist/`, and the ~1 MB `translation.json` isolated behind a `/* @__PURE__ */` re-export so the app build drops it (chunk fell 909 KB → 74 KB after the split) (`src/i18n/resources.ts:43-44`).
- **Why it works:** Execution-context violations fail loudly in bundle scans or rule checks rather than silently inflating artifacts.
- **Copy when:** Your package serves more than one runtime context (browser+server, host-app+bundle).
- **Overkill when:** Pure server-side libraries.

### P5. Ratchet baselines for inherited debt

- **Problem:** Big-bang cleanups stall; warn-only rules normalize violations.
- **Demonstrated by:** langfuse's committed `.structure-baseline.json` (2,710 known violations across 17 rules) that only shrinks, regenerated solely via `--baseline`, with `--diff` showing progress (`web/scripts/structure/stats.mjs:233-252`, `web/scripts/structure/README.md:28-32`), supported by an import-rewriting move tool (`README.md:43-119`). openhands uses micro-versions of the same idea: a three-file allowlist in its boundary test (`src/api/no-direct-agent-server-calls.test.ts:7-11`).
- **Why it works:** It converts "the codebase violates our own rules" from hypocrisy into a tracked migration plan; each PR must be neutral-or-better.
- **Copy when:** Adopting structure rules onto an existing codebase.
- **Overkill/risky when:** The baseline becomes a dumping ground — langfuse's shrinkage rate is bounded by reviewer attention, and top contributors (rule 8: 1,214 cross-feature deep imports; rule 10: 97 client→server hits) are real coupling, not cosmetics (`web/.structure-baseline.json`).

### P6. Cross-cutting contracts owned centrally at the seam

- **Problem:** When two sides of a seam (producer/consumer, UI/service) each define the contract, they drift.
- **Demonstrated by:** langfuse owns queue names and zod payload schemas once, in shared (`packages/shared/AGENTS.md:13-15`), so web producers and worker consumers cannot diverge. openhands centralizes client-option construction (`getAgentServerClientOptions`, `src/api/agent-server-client-options.ts:52-79`) and query-key families in one helpers file guarded by an ESLint literal ban (`src/hooks/query/query-keys.ts:8-73`, `eslint.config.js:351-358`).
- **Why it works:** One definition point means the compiler/tests catch mismatches at the seam instead of at runtime.
- **Copy when:** Any message, queue, RPC, or cache-key contract crosses a module or process boundary.
- **Counter-example:** langfuse's worker↔sandbox contract is validated only at runtime in `contracts.ts` because the sandbox is a separate Docker artifact (`packages/in-app-agent-sandbox-runtime/src/contracts.ts`); the langfuse report itself flags generated shared types as the fix.

### P7. Non-package boundaries for heavyweight runtimes

- **Problem:** Some components (sandboxed code execution, desktop shell, mock servers) would pollute the dependency graph if expressed as normal packages.
- **Demonstrated by:** langfuse isolates the in-app-agent sandbox as a sibling package whose only JS dep is `zod`, built into a Docker image string-referenced by the worker (`packages/in-app-agent-sandbox-runtime/package.json:20-31`, `worker/src/features/in-app-agent/runtime/sandbox/config.ts:6`). openhands keeps Electron packaging in a separate folder with its own manifest, lazy-loads embed-only surfaces (`React.lazy` for Terminal/SettingsModal/etc.), and excludes `src/mocks/` from the library build while gating the mock worker behind `VITE_MOCK_API`.
- **Why it works:** Process/container/image boundaries are stricter than import boundaries — nothing transitive leaks.
- **Cost:** Contracts across such seams lose type-checking (see P6 counter-example) and become invisible to graph tools (string-referenced image names and vi-mock paths are blind spots for dep-cruiser and even langfuse's move tool, `web/scripts/structure/README.md:111-116`).
- **Copy when:** The component brings OS-level or container-level dependencies.
- **Avoid when:** The contract between sides changes frequently without a schema discipline.

### P8. Docs-as-contract, colocated with the manifest

- **Problem:** Boundary rules that live only in tribal memory die with reorgs.
- **Demonstrated by:** Both sources maintain per-directory `AGENTS.md` files kept in lock-step with the code they govern: langfuse's root file states the dependency DAG (`AGENTS.md:30-36`) and its shared-package file mirrors the exports map section-by-section (`packages/shared/AGENTS.md:51-113`); openhands' documents the layering mandate ("hooks wrap services, never the other way around", `src/api/README.md:64-89`) and barrel hygiene ("internal callers use deep paths" so dev-graph fan-out stays small).
- **Why it works:** Adjacency creates maintenance pressure — when the manifest changes, the doc next to it is in the same diff.
- **Copy when:** Everywhere; but treat it as documentation *of* enforcement (P1–P3), never as a substitute for it.

## Key Differences

The interesting comparison is langfuse vs openhands, since the other eight sources offer no evidence to compare.

**Topology: many packages vs one package.** Langfuse splits by deployment unit and execution context (web service, worker service, shared library, EE overlay) because its product *is* several runtimes cooperating through queues and a database (`pnpm-workspace.yaml:1-6`, `turbo.json:11-122`). OpenHands splits nothing because it ships one distributable; its boundaries are intra-package and exist to protect the published library surface from app internals (`tsconfig.lib.json:1-34`). These are responses to different constraints — independent deployability vs embeddability — not quality differences.

**Enforcement posture: warn-and-ratchet vs hard-fail.** Langfuse runs its dependency-cruiser rules at `severity: "warn"` (`web/.dependency-cruiser.js:3-10`) and leans on the ratchet plus the eslint error for real enforcement; openhands' boundary tests fail CI outright. Langfuse's choice reflects a mature codebase with 2,710 inherited violations — hard-failing those rules today would freeze all work; openhands' reflects a young codebase that could adopt strict rules from birth. Same goal, different starting points.

**Surface governance: implicit vs asserted.** In langfuse the exports map *is* the contract, with traditional visibility annotations nearly absent (three `/** @internal */` tags total, e.g. `packages/shared/src/server/services/DatasetService/DatasetItemValidator.ts:31`); in openhands the contract is *tested* (`library-entrypoints`, `package-library`) but only negatively — neither source yet has a positive exhaustive snapshot of the public surface, a gap both reports acknowledge independently.

**Where the "runtime" sits relative to consumers.** OpenHands physically removes the runtime from the published artifact (api/stores/hooks excluded from `dist/`, verified by `preserveModules` builds, `vite.config.ts:215-244`). Langfuse keeps everything reachable but gates reachability by subpath and direction rules — its equivalent of "don't pull the whole runtime" is "import `@langfuse/shared/in-app-agent/toolResults`, not the server barrel."

**Cycle policy.** Langfuse encodes one explicitly: runtime cycles forbidden, type-only edges exempt but tracked (`web/.dependency-cruiser.js:21-29`), with the caveat that lifting a type into a runtime value turns a tolerated cycle into a hazard visible only in a survey metric. OpenHands observed no cycles and has thin leaf barrels (`src/components/terminal/index.ts:1`), so its policy is implicit in structure rather than encoded as a rule.

## Tradeoffs

**Workspace split (langfuse) vs single-package ship-list (openhands).**
Benefit (split): independently installable/buildable packages; forced directionality; deployment alignment. Cost: exports-map bureaucracy, multi-manifest versioning (release-it bumps `VERSION.ts` in three packages, `package.json:75-95`), risk of package sprawl. Benefit (single): zero publishing overhead, refactor freedom internally. Cost: the boundary is only as strong as the allowlist and tests; adding a public route means editing `tsconfig.lib.json` by hand (`tsconfig.lib.json:13-17`). Best-fit: split for multi-runtime products; ship-list for embeddable UI. Failure modes: split → consumers bypass via relative paths (which is why the eslint rule exists); single → a fat `src/lib/index.ts` nobody curates.

**Warn-severity rules + ratchet (langfuse) vs hard-fail tests (openhands).**
Benefit of warn+ratchet: migration proceeds while rules exist; no all-hands freeze. Cost: depends on process discipline — the baseline moves only when someone cares, and the cheap regex detectors can drift from the canonical TS-parse detectors (`web/scripts/structure/README.md:142-145`). Benefit of hard-fail: violations cannot land, ever. Cost: every legitimate exception needs an allowlist edit; rules written early may be wrong. Failure mode (langfuse): a 2,710-entry baseline where real coupling (rules 8/10) hides among cosmetic counts. Failure mode (openhands): allowlist creep.

**Explicit repeated dispatch (openhands cloud/local branches) vs centralized contract (langfuse queue schemas).** OpenHands writes `if (active.kind === "cloud") return callCloudProxy(...)` per method (`src/api/event-service/event-service.api.ts:40-69`), choosing readability over DRY — the seam is visible everywhere it applies, and the team has declined a dispatcher helper so far. Langfuse puts the contract in one place and both sides consume it. Explicit dispatch scales poorly (twelve cloud `.api.ts` files mirror local services); central contracts scale poorly when contracts multiply without governance. Each source implies the alternative for the other: openhands' report suggests a `dispatchByBackend` helper; langfuse's suggests promoting runtime-validated sandbox payloads to generated types.

**Centralized cross-cutting adapter vs distributed mappers (openhands).** `agent-server-adapter.ts` concentrates 1,297 lines of DTO translation, encrypted settings, and suffix injection in one file — one place to refactor on an SDK bump, but also a single point of merge conflict and review bottleneck, mitigated by 1,776 lines of adapter tests (`__tests__/api/agent-server-adapter.test.ts:1-1776`). Distributed mappers would localize diffs but scatter the seam.

**Non-package isolation (P7) vs in-graph dependency.** Docker/Electron/string-reference boundaries keep graphs clean but forfeit compile-time checking and tool visibility; both sources pay this price knowingly (runtime-validated sandbox contracts; string-referenced image names invisible to dep-cruiser).

## Decision Guide

- **Publishing anything? Make the exports map mandatory first** (both sources). If consumers can only reach sanctioned subpaths, half your boundary problems are already structural facts.
- **Choose topology by deployment shape, not aesthetics.** Multiple deployables/execution contexts → workspace packages with a written DAG (langfuse). One distributable with embedded reuse → single package + ship-list barrel + build allowlist (openhands).
- **Greenfield: hard-fail from day one.** OpenHands demonstrates that boundary tests written before debt accumulates stay cheap. Brownfield: adopt warn + ratchet, and budget recurring "shrink the baseline" PRs — otherwise the ratchet ossifies (langfuse's rule 8 at 1,214).
- **Enforce direction at two layers minimum:** a fast lint rule for the common case, a walking test or graph check for what lint misses (dynamic imports, string-built specifiers — both flagged as gaps).
- **Pin cross-process/cross-container contracts in schemas owned by the lower layer,** and generate types across non-JS seams; do not leave them to runtime validation alone.
- **When a capability spans contexts** (like langfuse's in-app-agent across shared/web/worker/sandbox), define durable contracts in the shared package and keep runtime logic out of it — the shared `runLifecycle.ts` reaching back into `../../server` (`packages/shared/src/in-app-agent/server/runLifecycle.ts:9`) shows how easily "shared" erodes.
- **Answer "can I use X without Y?" with a test, not a claim.** OpenHands' library-entrypoints test imports domain barrels in plain Vitest with no server, no mocks, no Playwright — that test *is* the yes.

## Practical Tips

- Add a no-wildcard `package.json#exports` map with explicit `types`/`import`/`require` triplets; forbid `"./*"`.
- Write one file-walking boundary test early (ban raw transports, banned importers, or forbidden directories); keep its allowlist under ten entries and reviewed.
- Mirror the exports map in a colocated `AGENTS.md`/README section so doc and manifest change in the same PR.
- Split barrels by execution context (client-safe root / server / db) the moment one package serves two runtimes; state the failure scenario ("Prisma in the browser bundle") in the rule comment, with an incident link if one exists.
- Commit a violation baseline when adopting structure rules; regenerate only deliberately; show `--diff` in PRs.
- Keep per-domain barrels for the *published* surface but require deep imports internally (openhands) — dev-graph fan-out stays small and the public surface stays curated.
- Use lazy chunks and `/* @__PURE__ */` annotations to keep heavy optional assets (megabyte i18n JSON, terminal emulator) out of eager graphs; verify with bundle-size numbers in the PR (909 KB → 74 KB in openhands).
- Put queue/cache/RPC key vocabulary in one constants/schema module and ban raw literals via lint (the `SETTINGS_QUERY_KEYS` pattern).
- For embeddable UI, namespace CSS at build time (`postcss-prefix-selector` under `[data-agent-server-ui]`) and export the scope constants as part of the public API.

## Anti-Patterns / Caution Signs

- **A baseline that never shrinks.** 2,710 entries with the top contributor being genuine cross-feature coupling means the ratchet is documenting debt, not retiring it.
- **Warn-only graph rules paired with disabled hygiene tooling.** Langfuse runs dep-cruiser at warn and ignores knip `files`/`exports`/`types` issues (`knip.jsonc:4-11`) — dead-code and unused-export signals are effectively off.
- **Two implementations of the same rule.** Regex approximations in CI alongside canonical TS-parse detectors will drift (`web/scripts/structure/README.md:142-145`).
- **Dynamic `import()` outside lint coverage.** The restriction mechanisms examined police static imports only; the escape hatch is documented but unguarded.
- **String-referenced seams.** Image names, mock paths, and route strings are invisible to graph tools; migrations stop and ask a human (langfuse `structure:move` behavior).
- **Shared modules that reach back into infrastructure.** One `../../server` import in a supposedly context-free shared module quietly invalidates the "server-free" promise of the whole subtree (`runLifecycle.ts:9`).
- **Cross-cutting god-adapters.** A 1,297-line translation module is manageable only while its test suite (1,776 lines) grows with it.
- **Negative-only surface tests.** Asserting a removed symbol stays gone does not prevent a *new* internal from leaking; you also need the positive set.
- **Docs asserting direction the tooling doesn't check.** Any `AGENTS.md` rule with no corresponding lint/test/baseline entry should be treated as aspirational.
