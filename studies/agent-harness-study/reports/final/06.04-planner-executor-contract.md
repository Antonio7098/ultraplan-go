## Executive Summary

No source ships a standalone, versioned `Plan` contract that survives across subsystems. The field converges on one principle — **never trust the LLM plan without validation before a side effect** — but diverges on how to enforce it.

- **Hardened turn validators** (openai-agents-sdk 8/10, pydantic-ai 8/10) treat every `ModelResponse`/`ToolCallPart` as untrusted, validate Pydantic schemas, fingerprint `call_id`s, enforce retry budgets, and synthesize `RetryPromptPart`/`ToolCallOutputItem` errors before the planner's next turn. Bad plans cannot trigger double execution; they are forced into LLM-visible correction loops.
- **Event-sourced tool contracts** (openhands 7/10) and **deterministic schedulers** (langgraph 7/10) enforce typing at the tool/channel boundary (`Schema(extra="forbid")`, `PregelExecutableTask`, `Send`/`Command`) but rely on silent warn-and-drop for unknown writes and on `EventLog` replay for feedback — safe against crashes, weak against semantic hallucinations.
- **Structured plan executors** (crewai 7/10) are the only source with a typed multi-step plan (`ReasoningPlan → PlanStep → TodoList` with `depends_on` DAG, `StepExecutionContext`, `StepResult`) plus per-step LLM observation (`StepObservation`) and bounded refinement/replan. The contract is strong in-process but ephemeral (cleared on `invoke()`) and has a dual untyped `CrewPlanner` path that pollutes `task.description`.
- **Fragmented multi-contract** (agent-framework 5/10) exposes three disjoint contracts — free-text `TodoItem` list (harness), immutable typed DAG (`WorkflowBuilder+Executor+Edge`), and LLM-judged `MagenticProgressLedger` — with no bridge. Workflow DAG alone would score 7-8 for `WorkflowGraphValidator` (`python/packages/core/agent_framework/_workflows/_validation.py:101-163`) and `WorkflowContext[OutT,W_OutT]` typing, but the dominant harness path registers todo tools with `approval_mode="never_require"` (`python/packages/core/agent_framework/_harness/_todo.py:505`) and trusts model output for shape only.

Cross-agent planning is absent or nascent everywhere: handoffs and nested `Agent.as_tool`/`DelegateTool` re-enter the same turn loop rather than share a plan DAG. The central lesson: **if you need execution to be safe when the planner is bad, add explicit validation, fingerprint dedup, interruption budgets, and typed failure feedback before any `executor.__call__`** — do not rely on prompt compliance or on `max_iterations` as the only guard.

## Core Thesis

**Where the planner is an LLM, the executor's job is not to be clever — it is to be a strict, observable validator with cheap correction loops.** Sources that achieve this (openai-agents-sdk, pydantic-ai) decompose the boundary into three typed stages — `ProcessedResponse`/`ToolCallPart` normalization, `ToolExecutionPlan`/`ValidatedToolCall` authorization with `call_id` fingerprints and `ToolVisibility` gates, and `ToolCallOutputItem`/`RetryPromptPart` feedback re-fed to the next model turn — and make every rejection durable via `RunState`/`DeferredToolRequests` or `AgentErrorEvent` + `RetryPromptPart`. Sources that blur the boundary (agent-framework todos, crewai crew planner) push validation into prompt instructions (`"adjust your todos accordingly"` `python/packages/core/agent_framework/_harness/_todo.py:35-40`) or into a single `max_iterations`/`max_replans` cap, which does not prevent a hallucinated plan from executing to completion.

**Where the planner is deterministic (langgraph Pregel), the invariant flips:** trust is cheap at compile (`validate_graph` `libs/langgraph/langgraph/pregel/_validate.py:13-107`) and expensive at runtime, where `apply_writes` warn-and-drops unknown channels (`libs/langgraph/langgraph/pregel/_algo.py:310-313`) and `prepare_push_task_send` silently ignores unknown `Send.node`s (`libs/langgraph/langgraph/pregel/_algo.py:972-979`). Availability is favored over fail-closed, which is correct for long-running threaded graphs but wrong for LLM-generated `Send`/`Command` where silent shrinking is a safety hole.

Both convergences point to the same failure mode: **execution is safe only if the executor can reject structurally valid but semantically wrong plans before side effects, and if failure is fed back as a typed, model-visible signal the planner must handle next turn.** No source fully types `Plan` as `Plan{id, revision, steps:[{id, tool, depends_on, status}]}` with a lintable diff; the best approximations are crewai `TodoList` (typed but ephemeral) and Temporal-style `HistoryBuilder` (durable but not in this sample).

## Approach Models

Sources cluster into four models. Langgraph is engine-as-planner; the other five are LLM-as-planner with different executor hardening.

### A. Hardened Single-Turn Validator (LLM plans, SDK hardens before side effect)

**openai-agents-sdk, pydantic-ai, openhands** — planner output is one `ModelResponse`/`Message` worth of tool calls. Executor is not a scheduler but a gate: normalize, fingerprint, schema-validate, check `needs_approval`/`is_tool_available`, enforce retry budgets, then fan out.

- OpenAI SDK: `ModelResponse` → `ProcessedResponse{functions, handoffs, computer_actions, interruptions, function_tools_not_found}` (`src/agents/run_internal/run_steps.py:116-148`) → `_dedupe_processed_response_invocations` → `ToolExecutionPlan{pending_interruptions, approved_mcp_responses}` (`src/agents/run_internal/tool_planning.py:557-682`) → `gather_with_cancel`.
- Pydantic-AI: `ModelResponse{ToolCallPart}` → `ToolManager.validate_tool_call` → `ValidatedToolCall{args_valid, validation_error, deferral}` (`pydantic_ai_slim/pydantic_ai/tool_manager.py:56-95`) → `process_tool_calls` with `Early/Graceful/Exhaustive` strategies (`pydantic_ai_slim/pydantic_ai/_tool_execution.py:254-322`) → `RetryPromptPart` or `ToolReturnPart`.
- OpenHands: `Message{tool_calls} → normalize_tool_call (aliases) → fix_malformed_tool_arguments → _extract_security_risk/_summary → model_validate → _ActionBatch → ParallelToolExecutor` with `DeclaredResources` locking (`_sdk_inspect/sdk/agent/utils.py:68-442`, `_sdk_inspect/sdk/agent/agent.py:767-903`).

Best-fit: general-purpose chat/tool harnesses where every turn could emit any tool; safety must be per-call, not per-DAG.

### B. Typed Multi-Step Plan with Observer (LLM plans a DAG, executor observes each step)

**crewai** — the only source where the planner produces an explicit multi-step structure.

Planner: `AgentReasoning.handle_agent_reasoning` with `FUNCTION_SCHEMA` strict JSON + retry loop `while not ready and attempt < max_attempts` (`lib/crewai/src/crewai/utilities/reasoning_handler.py:244-408`) → `ReasoningPlan{plan:str, steps:list[PlanStep{step_number, description, tool_to_use, depends_on}}, ready:bool}` → `TodoList` of `TodoItem{status:pending/running/completed/failed}` (`lib/crewai/src/crewai/utilities/planning_types.py:45-196`). Executor: `StepExecutor.execute(todo, StepExecutionContext{task_description, task_goal, dependency_results}) → StepResult` (`lib/crewai/src/crewai/agents/agents/step_executor.py:64-127`) with fresh `messages` per todo (`lib/crewai/src/crewai/agents/agents/step_executor.py:244`), then `PlannerObserver.observe → StepObservation{suggested_refinements, needs_full_replan, goal_already_achieved}` (`lib/crewai/src/crewai/agents/agents/planner_observer.py:113-304`) routing via `reasoning_effort` tiers (`lib/crewai/src/crewai/experimental/agent_executor.py:555-1013`).

Best-fit: task decomposition where parallel steps with dependencies matter and per-step semantic feedback is affordable (medium/high effort).

### C. Deterministic Channel-Driven Scheduler (no LLM plan; topology is the plan)

**langgraph** — planner is `PregelLoop.tick` comparing `channel_versions > versions_seen[INTERRUPT]` and `trigger_to_nodes` (`libs/langgraph/langgraph/pregel/_algo.py:1260-1277`), emitting `PregelTask` or `PregelExecutableTask{input, proc, writes, config, retry_policy, cache_key, writers, subgraphs, timeout}` for `PregelRunner.tick` (`libs/langgraph/langgraph/pregel/_runner.py:176-573`). Dynamic planning via `Send(node,arg)` on `TASKS:Topic[Send]` (`libs/langgraph/langgraph/pregel/main.py:809`, `libs/langgraph/langgraph/pregel/_algo.py:938-1005`) and `Command(update,resume,goto)` (`libs/langgraph/langgraph/types.py:798-848`) with `map_command` (`libs/langgraph/langgraph/pregel/_loop.py:903-931`). Feedback is checkpointer `pending_writes` (`ERROR/INTERRUPT/RESUME/TASKS` — `libs/langgraph/langgraph/pregel/_loop.py:415-508`) and retry/timeout policies.

Best-fit: durable DAG/state-machine workloads where planning must be deterministic, replayable, and testable without LLM nondeterminism.

### D. Fragmented Multi-Contract (three coexisting, incompatible plans)

**agent-framework** — a catalog of valid choices with no unified surface.

- Harness Todo: `TodoItem{id,title,description,is_complete}` (`python/packages/core/agent_framework/_harness/_todo.py:51-96`) via LLM tool surface `todos_add/complete/remove` looping on `todos_remaining(provider)` (`python/packages/core/agent_framework/_harness/_loop.py:925-973`).
- Workflow DAG: `WorkflowBuilder.add_edge/add_fan_out/add_switch_case → Workflow{executors, edge_groups, start_executor, output_from}` (`python/packages/core/agent_framework/_workflows/_workflow_builder.py:53-882`) with `Executor.@handler + WorkflowContext[OutT,W_OutT]` (`python/packages/core/agent_framework/_workflows/_executor.py:31-478`).
- Magentic: `_MagenticTaskLedger{facts, plan}` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:272-286`) + `MagenticProgressLedger{is_request_satisfied,is_in_loop,is_progress_being_made,next_speaker}` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:290-334`) routed by `MagenticOrchestrator`.

Best-fit analysis: workflow DAG is the durable pick for developer-authored graphs; todos are the ergonomic pick for LLM planning; Magentic is the only closed-loop replanner — but requiring three mental models for one dimension is the core fragility.

## Pattern Catalog

### 1. Single-source Pydantic tool schema generating both prompt and validator

**Problem:** Prompt schema and runtime validator drift.
**Sources:** openhands (`ToolDefinition.to_openai_tool`/`to_mcp_schema` from `Action` model `_sdk_inspect/sdk/tool/tool.py:379-497`), openai-agents-sdk (`function_schema()` → `ensure_strict_json_schema` `src/agents/function_schema.py:290-491` + `src/agents/strict_schema.py`), pydantic-ai (`ToolDefinition.parameters_json_schema` `pydantic_ai_slim/pydantic_ai/tools.py:544-748` + `ToolManager._validate_tool_args` `pydantic_ai_slim/pydantic_ai/tool_manager.py:307-349`).
**Why it works:** One `extra="forbid"` Pydantic model is the single source for OpenAI/MCP JSON and for `model_validate`; mismatch becomes a type error, not a runtime surprise.
**When to copy:** Any LLM tool surface.
**When overkill:** Never — cost is one `TypeAdapter` at registration.
**Evidence:** `_sdk_inspect/sdk/tool/schema.py:172-240`; `src/agents/tool.py:441-615`; `pydantic_ai_slim/pydantic_ai/messages.py:2769`.

### 2. Zero-trust `call_id` fingerprint + dedup before side effects

**Problem:** Model reuses or mutates a `call_id` to double-execute or poison an approval.
**Sources:** openai-agents-sdk `_dedupe_processed_response_invocations` + `_tool_invocation_status` fingerprint (`src/agents/run_internal/tool_planning.py:339-554`, `src/agents/run_context.py:304-355`) raising `ModelBehaviorError("Model reused a tool call ID for a different invocation")`; pydantic-ai `ModelMessagesTypeAdapter` + `_clean_message_history` sanitizing `ToolCallPart.tool_call_id` (`pydantic_ai_slim/pydantic_ai/messages.py:2954-3010`); agent-framework `_safe_next_id` clamping (`python/packages/core/agent_framework/_harness/_todo.py:223-225`).
**Why it works:** Identity is hashed over `type+name+args+call_id`; duplicates coalesce, mutations hard-fail, completed keys are skipped — idempotency without distributed locks.
**When to copy:** Any harness persisting `RunState`/conversation history or resuming from a checkpointer.
**Evidence:** `src/agents/run_internal/tool_planning.py:245-391`; `pydantic_ai_slim/pydantic_ai/_agent_graph.py:2964-2990`.

### 3. Structured failure-as-tool-output correction loop

**Problem:** Validation or execution failures must be LLM-visible without crashing the run.
**Sources:** All LLM-planner sources converge: openai-agents-sdk `ToolCallOutputItem` via `_output_item_to_input_item` (`src/agents/items.py:221-491`) looped by `while True` in `run.py:967`; pydantic-ai `ModelRetry → ToolRetryError(RetryPromptPart)` (`pydantic_ai_slim/pydantic_ai/exceptions.py:616-649`, `pydantic_ai_slim/pydantic_ai/_tool_execution.py:884-915`); openhands `AgentErrorEvent`/`UserRejectObservation` → `View.events_to_messages` (`_sdk_inspect/sdk/event/llm_convertible/observation.py:51-149`, `_sdk_inspect/sdk/event/base.py:91-126`); crewai `StepObservation` with `suggested_refinements` (`lib/crewai/src/crewai/utilities/planning_types.py:198-271`).
**Why it works:** Every failure becomes a `tool`-role message or structured part for the next `model.request`, so the model self-corrects without human intervention; budgets (`max_retries`, `max_replans`) bound the loop.
**When to copy:** Always when the planner is an LLM.
**When risky:** If structured output co-emits with retry — pydantic-ai `retry_wins` invariant suppresses winning output (`pydantic_ai_slim/pydantic_ai/_tool_execution.py:881-909`), openai-agents-sdk `check_for_final_output_from_tools` short-circuits differently (`src/agents/run_internal/turn_resolution.py:753`).
**Evidence:** `src/agents/run_internal/turn_resolution.py:784-911`; `_sdk_inspect/sdk/agent/response_dispatch.py:239-308`.

### 4. Interruption / deferral as durable first-class plan rejection

**Problem:** A plan needs approval or human data without being marked "failed".
**Sources:** openai-agents-sdk `ToolExecutionPlan{pending_interruptions}` + `RunState{CurrentStep: NextStepInterruption, _tool_invocations}` (`src/agents/run_internal/tool_planning.py:557-682`, `src/agents/run_state.py:761-875`); pydantic-ai `CallDeferred/ApprovalRequired → DeferredToolRequests` resumable via `DeferredToolResults` (`pydantic_ai_slim/pydantic_ai/tools.py:15-22`, `pydantic_ai_slim/pydantic_ai/_tool_execution.py:964-1010`); openhands `_requires_user_confirmation → WAITING_FOR_CONFIRMATION` (`_sdk_inspect/sdk/agent/agent.py:605-647`) and `HookEventProcessor.block_action → UserRejectObservation(rejection_source="hook")` (`_sdk_inspect/sdk/hooks/conversation_hooks.py:123-173`); langgraph `interrupt(value) → GraphInterrupt` + `RESUME` writes (`libs/langgraph/langgraph/types.py:851-974`, `libs/langgraph/langgraph/pregel/_loop.py:818-846`).
**Why it works:** Rejection is persisted, not ephemeral; resume can deduplicate via `output_exists_checker`/`approval_items_by_call_id` (`src/agents/run_internal/turn_resolution.py:1134-`).
**When to copy:** Any hosted multi-tenant or regulated harness.
**Evidence:** `src/agents/run_state.py:846`; `pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:1098-1124`.

### 5. Bounded adaptivity with explicit budgets per level

**Problem:** Unbounded observation/retry loops diverge or explode cost.
**Sources:** crewai `PlanningConfig{max_steps=20, max_replans=3, max_step_iterations=15, reasoning_effort}` (`lib/crewai/src/crewai/agent/planning_config.py:11`, `lib/crewai/src/crewai/experimental/agent_executor.py:555-1013`); pydantic-ai `max_retries=1/max_output_retries=1` + `UsageLimits` (`pydantic_ai_slim/pydantic_ai/agent/__init__.py:658`); langgraph `RetryPolicy{initial_interval, backoff_factor, max_attempts, jitter}` + `TimeoutPolicy` (`libs/langgraph/langgraph/types.py:418-514`); openai-agents-sdk `MaxTurnsExceeded` (`src/agents/run.py:554`); agent-framework Magentic `max_stall_count=3/max_reset_count` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:338-393`).
**Why it works:** Each loop tier (step iterations, replan count, turn count, stall count) has an independent cap; low/medium/high effort selects which tiers run.
**When to copy:** Always — set at least one hard cap (`max_turns`/`recursion_limit`) plus one advisory stall budget.
**Evidence:** `lib/crewai/src/crewai/experimental/agent_executor.py:747-1058`; `libs/langgraph/langgraph/pregel/_retry.py:573-838`.

### 6. Stall-counter drift detector with LLM progress ledger

**Problem:** Detect semantic drift or looping without a numeric metric.
**Sources:** agent-framework Magentic `is_in_loop/is_progress_being_made/is_request_satisfied + reason` → `stall_count` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:290-393,1109-1120`); crewai `PlannerObserver` `remaining_plan_still_valid/needs_full_replan/goal_already_achieved` (`lib/crewai/src/crewai/utilities/planning_types.py:212`, `lib/crewai/src/crewai/experimental/agent_executor.py:885-1022`).
**Why it works:** Model self-assesses per step/ledger with `reason` text; counter debounces transient misjudgments and emits `REPLANNED`/`PlanReplanTriggeredEvent`.
**When to copy:** Multi-step loops where one extra LLM call per step or per batch is affordable.
**When risky:** False-positive `is_in_loop` clears `chat_history` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:385-393`); heuristic fallback masks real failures.
**Evidence:** `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:300-334,699-733`.

### 7. Isolated execution context (dependency_results only)

**Problem:** Parallel steps leak full history and bloat context.
**Sources:** crewai `StepExecutionContext(task_description, task_goal, dependency_results:dict[int,str])` frozen dataclass (`lib/crewai/src/crewai/utilities/step_execution_context.py:14`) built from `get_dependency_result` (`lib/crewai/src/crewai/experimental/agent_executor.py:647`); openhands `DeclaredResources+ParallelToolExecutor` locking (`_sdk_inspect/sdk/agent/parallel_executor.py:54-162`); pydantic-ai `ToolManager.for_run_step` with `prepare_tools` scoping (`pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:438-476`).
**Why it works:** Each step gets only predecessor outputs wired by `depends_on`, enabling safe `asyncio.gather`/`execute_todos_parallel` (`lib/crewai/src/crewai/experimental/agent_executor.py:1257`) without prompt pollution.
**When to copy:** Any DAG-parallel plan.
**When gaps appear:** Forgetting a `depends_on` edge drops transitive context — the constraint must be planner-visible.
**Evidence:** `lib/crewai/src/crewai/utilities/step_execution_context.py:44`; `lib/crewai/src/crewai/agents/agents/step_executor.py:244`.

### 8. Prepare/hook rewriting before execution

**Problem:** Advertise a different tool set than is executable, or rewrite args without forking the agent.
**Sources:** pydantic-ai `Tool.prepare(ctx,ToolDefinition)→ToolDefinition|None` + `prepare_tools/prepare_output_tools` per `run_step` + `before_/wrap_/after_tool_validate/execute` (`pydantic_ai_slim/pydantic_ai/tools.py:104-132`, `pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:748-936`); openai-agents-sdk `_collect_runs_by_approval` + `tool_guardrails` (`src/agents/tool_guardrails.py:18-118`); openhands `PreToolUse` hook `block_action` (`_sdk_inspect/sdk/hooks/conversation_hooks.py:123-173`).
**Why it works:** Mutability is scoped (per-step, per-tool) and observable via OTel/event bus rather than ad-hoc filtering inside the executor.
**When risky:** Composition order matters — `CombinedCapability` topological sort cannot eliminate subtle bypass if a validator is assumed outermost.
**Evidence:** `pydantic_ai_slim/pydantic_ai/tools.py:486`; `src/agents/run_internal/tool_planning.py:759-840`.

## Key Differences

| Concern | Choice A | Choice B | Why they differ |
|---------|----------|----------|-----------------|
| What is stored / planned | Typed step DAG (`PlanStep/TodoItem/Writes`) — crewai, langgraph, agent-framework workflow | Untyped tool-call set (`ModelResponse`/`ProcessedResponse`/`ActionEvent` batch) — openai-sdk, pydantic-ai, openhands, agent-framework harness | DAG suits task decomposition & parallel scheduling; set suits free-form chat where decomposition is prompt-dependent |
| Who plans | LLM invents steps (crewai `AgentReasoning`, openai/pydantic/openhands `ModelResponse`, agent-framework todos+Magentic) | Deterministic engine derives tasks from `channel_versions` vs `versions_seen` + `trigger_to_nodes` (langgraph) | Langgraph defers semantic planning to user `StateGraph` topology; LLM harnesses delegate decomposition to the model |
| Trust posture | Zero-trust per-call validation (openai-sdk fingerprint, pydantic-ai `validate_tool_call`, openhands `model_validate`) | Shape-only or lenient validation (agent-framework todos `from_dict` + `never_require`, langgraph warn-and-drop `libs/langgraph/langgraph/pregel/_algo.py:310-313`) | Application harnesses can afford to fail-closed per turn; engine harnesses favor availability across long threaded runs |
| Can executor reject? | Explicit pause (`NextStepInterruption`/`DeferredToolRequests`/`WAITING_FOR_CONFIRMATION`) or `ModelBehaviorError` hard fail | Implicit `StepResult(success=False)`/`ToolReturnPart(failed)` retried as `RetryPromptPart` with budget, or silently dropped | Explicit pause serves HITL/durable resume; implicit retry serves autonomous self-correction |
| Can executor modify? | Filter/rewrite individual calls (`prepare`/`Hook`/`apply_refinements`) without replanning whole plan | Full regeneration (`replace_pending_todos`, `StandardMagenticManager.replan`, `_trigger_replan`) preserving completed/failed | Cheap refinement handles description tweaks; regeneration needed when `tool_to_use`/`depends_on` or ledger facts are wrong |
| How failure fed back | Typed `StepObservation`/`RetryPromptPart`/`AgentErrorEvent` + stall ledger (`crewai`, `pydantic-ai`, `openhands`, `agent-framework` Magentic) | Durable `pending_writes {ERROR, INTERRUPT}` + `retry/timeout` policy (`langgraph`) vs `ToolCallOutputItem` string re-fed in next loop (`openai-sdk`) | Typed feedback enables refinement routing; durable writes enable cross-restart replay; string feedback is simplest LLM correction |
| Is contract typed? | Strongly typed all the way to execution (`PregelExecutableTask`, `WorkflowContext[OutT,W_OutT]`, `ToolDefinition`, `Schema extra="forbid"`) | Typed at code, untyped at persistence/history (`PendingWrite tuple[str,str,Any]`, `TodoItem.title: str` free text, `task.description += plan` string append) | In-memory typing is cheap; persisting generic `Any` payloads and human-readable titles erases invariants needed for plan linting |
| Cross-agent planning | Native scheduler primitives (`Command.PARENT`, `Send` fan-out, `PregelNode.subgraphs` langgraph; `Handoff`/`Agent.as_tool` openai-sdk; `DelegateTool`/`AgentDefinition` openhands; pydantic `Graph→Agent.tool`) | None — per-agent `TodoList` only (crewai), per-session `TodoStore` (agent-framework harness) | Distributed execution exists; declarative cross-agent *planning* (planner agent → executor agents on a shared DAG) does not — delegation is prompt text over isolated conversations |

## Tradeoffs

### Strict per-call validation vs LLM ergonomics & throughput

- **Strict (openai-sdk, pydantic-ai, openhands):** Benefit — bad plans never reach side effects; `strict_json_schema` + Pydantic + fingerprint makes contract tests deterministic. Cost — rejects loose but harmless schemas; requires `strict_json_schema=False` opt-in and burns `max_retries=1` quickly on chatty validators. Best-fit: hosted, multi-tenant, regulated.
- **Lenient (langgraph runtime, agent-framework todos):** Benefit — `TOOL_NAME_ALIASES` + `fix_malformed_tool_arguments` + warn-and-drop keep long runs alive through transient checkpoint staleness or model sloppiness. Cost — hallucinated `Send.node` silently shrinks fan-out; bad todo list runs to completion. Best-fit: durable DAGs where availability > strict correctness.

### Explicit multi-step plan vs implicit next-tool set

- **Explicit DAG (crewai):** Benefit — `depends_on` enables `can_parallelize`/`execute_todos_parallel`, `StepExecutionContext` isolation, and synthesis validation. Cost — planner must emit `step_number/depends_on/tool_to_use` correctly; circular/missing deps deadlock to bounded replans then abandon remaining work (`lib/crewai/src/crewai/experimental/agent_executor.py:1119-1128`, `max_replans=3`). Best-fit: research→synthesize workflows.
- **Implicit set (openai-sdk, pydantic-ai, openhands):** Benefit — zero plan authoring, immediate OpenAI/Anthropic compat. Cost — no step dependency metadata means no DAG parallelism beyond `gather_with_cancel` per turn; prompt tokens carry ordering. Best-fit: chat, single-turn tool use.

### Isolation vs context richness

- **Frozen minimal context (crewai `StepExecutionContext` with `dependency_results` only):** Benefit — prevents prompt pollution, enables parallel scheduling. Cost — forgetting a `depends_on` edge drops transitive signal (e.g., web-search result). Alternative is `parallel_executor` with `DeclaredResources` coarse lock (`tool:<name>` by default) where context is full but parallelism limited.

### Heuristic observe vs LLM observe vs no observe

- **LLM observe (crewai medium/high, Magentic progress ledger):** Catches semantic failures, drives `refine_and_continue` vs `replan_now` vs `goal_achieved`. Cost — extra LLM call per step/batch; doubles/triples cost. `high` is only mode that evaluates `goal_already_achieved` early-exit.
- **Heuristic observe (crewai low, openhands stuck detector):** Fast (`heuristic_observation` `lib/crewai/src/crewai/agents/agents/planner_observer.py:88`), but `needs_full_replan` detection delayed until error `StepResult`.
- **No per-step observe (openai-sdk, pydantic-ai, langgraph):** Defers judgment to next LLM turn or retry policy — cheaper, less sensitive to semantic drift.

### Durability vs inspectability

- **Durable engine history (langgraph checkpointer `pending_writes`, openai-sdk `RunState` 17 migrations):** Survives crashes and interrupts, enables `fork`/`fork`-style resets; but `PendingWrite tuple` and `task.description += plan` mutate history in lossy ways.
- **Ephemeral typed plan (crewai `AgentExecutorState` cleared on `invoke()`, agent-framework harness session store):** Rich semantics but `invoke()` wiping `plan, todos, observations, execution_log` (`lib/crewai/src/crewai/experimental/agent_executor.py:2879`) and `fresh_context=True` discarding todo mutations (`python/packages/core/agent_framework/_harness/_loop.py:436-586`) lose lineage for HITL loops.

### Mutable `writes:deque` vs immutable plan

- Langgraph shares `writes.extend` via `CONFIG_KEY_SEND` (`libs/langgraph/langgraph/pregel/_algo.py:722-735`) so nodes/commands can append without returning. Enables `Command`/`Send` ergonomics but makes plan immutability unverifiable and introduces a `threading.Lock`-only data-race surface.

## Decision Guide

**Do you need execution to be safe if the planner hallucinates?**
- Yes → Choose **Hardened Validator** (openai-agents-sdk or pydantic-ai). Require `ModelResponse → ValidatedToolCall` with `call_id` dedup, strict JSON, `needs_approval`/`is_tool_available` gates, and `max_retries`/`UsageLimits` before any `executor.__call__`. OpenAI SDK if you target OpenAI Responses API; Pydantic-AI if you need multi-provider, incremental tool `search`/`load_capability`, or deferred HITL.

**Do you need a multi-step plan with dependencies and parallel steps?**
- Yes → Copy **crewai's `TodoList` contract** (`TodoItem`+`TodoList.get_ready_todos`+`StepExecutionContext`) — or promote it to a versioned `PlanRevision{version, parent, reason, diff}` store because crewai itself overwrites history. Set `reasoning_effort=high` if early `goal_already_achieved` termination matters; `medium` is the default even when unset (`lib/crewai/src/crewai/experimental/agent_executor.py:564`).

**Do you need deterministic, replayable, interruptible workflows independent of LLM nondeterminism?**
- → Choose **langgraph**. Compile `StateGraph`/`MessageGraph`, enable `durability="sync"` (not `"exit"` which stages in `_exit_delta_writes` until exit) and `RetryPolicy`. Add a strict mode that promotes `logger.warning` on unknown channel/`Send.node` to `InvalidUpdateError` for tester/planner-generated plans.

**Do you need per-tool-call audit and interactive confirmation?**
- → Choose **openhands** pattern: `Schema(extra="forbid")` + 5-stage normalization + dual gates (security analyzer + `PreToolUse` hooks partitioning `_ActionBatch.blocked_reasons`). Default `tool_concurrency_limit=1` (`_sdk_inspect/sdk/agent/base.py:338`); implement `declared_resources` to earn parallelism.

**Do you need cross-agent delegation today?**
- No framework provides a shared DAG with typed merge — all delegation re-enters a new conversation (`Agent.as_tool`, `DelegateTool` spawning `LocalConversation`, `Handoff`, `Agent.tool` wrapping `Agent.run`). Treat cross-agent planning as application-level: define a `CrewPlan{tasks:[{agent_role, todos:TodoList}]}` or `PlanDefinition` file (`AgentDefinition` frontmatter `_sdk_inspect/sdk/subagent/schema.py:151-305`) with input/output schemas, progress events, and cancellation — do not store todos per session only.

**How to set bounds (always two layers):**
- Hard cap — `max_replans`/`max_turns`/`recursion_limit`/`max_stall_count`/`max_reset_count` (never leave one as `None`=unlimited, e.g., Magentic `max_reset_count` default `None`). Advisory budget — `RemainingSteps`/`IsLastStep`, stall counter with decrement on progress, `PlannerObserver` remaining-plan check.

## Practical Tips

### Patterns to copy

- **Generate JSON schema from the same Pydantic model that validates.** Enforces `extra="forbid"` once (`_sdk_inspect/sdk/tool/schema.py:172-240`) — add `TestFunctionSchema` round-trip tests (`lib/crewai/tests/utilities/test_planning_types.py:331`).
- **Fingerprint every `call_id` and dedup before execution.** Copy `tool_invocation_identity` + `completed_output_keys` pattern (`src/agents/run_internal/tool_planning.py:348-391`) and `sanitize_messages` forgery stripping (`pydantic_ai_slim/pydantic_ai/messages.py:2954-3010`) for any resumable history.
- **Add `reason` to every state-changing mutation and persist it.** `TodoCompleteInput(reason)` validated non-empty (`python/packages/core/agent_framework/_harness/_todo.py:152-157`) and `TodoItem` should store it; crewai `PlanReplanTriggeredEvent.replan_reason` and Magentic `reason` show the value for post-hoc diff.
- **Separate lightweight `apply_refinements` from full `replace_pending_todos`.** Zero-LLM-call description tweak (`lib/crewai/src/crewai/agents/planner_observer.py:215`) vs bounded regeneration (`lib/crewai/src/crewai/utilities/planning_types.py:185`) saves tokens while preserving `completed/failed`.
- **Use `get_ready_todos` + `can_parallelize` + frozen `StepExecutionContext(dependency_results)`.** Isolate each `StepExecutor`'s message window (`lib/crewai/src/crewai/agents/step_executor.py:244`) so parallel steps don't leak — but remember to wire `depends_on` explicitly or transitive answers are dropped.
- **Make interruption a typed `RunState`/`DeferredToolRequests` artifact, not a string.** Check `output_exists_checker`/`approval_items_by_call_id` on resume (`src/agents/run_internal/turn_resolution.py:1134-`) to avoid re-execution and to keep `UsageLimits` coherent.
- **Guard stores with per-session locks + atomic replace.** `WeakKeyDictionary[AgentSession, asyncio.Lock]` plus `tmp.<pid> → os.replace` (`python/packages/core/agent_framework/_harness/_todo.py:280-443`) with `test_harness_todo.py:322-379` concurrency regression.
- **Normalize before validating.** Crewai `reasoning_handler` FUNCTION_SCHEMA + fallback `"READY: …"` sentinel handling (`lib/crewai/src/crewai/utilities/reasoning_handler.py:351-408`), openhands `parse_tool_call_arguments → normalize_tool_call → fix_malformed_tool_arguments → model_validate` (`_sdk_inspect/sdk/agent/utils.py:68-442`) — but test both paths; sentinel string matching is brittle.
- **Apply stall-counter with decrement on progress** (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1118`) rather than monotonically incrementing; debounces flapping.
- **Re-derive `pending_writes` deterministically per superstep** (`libs/langgraph/langgraph/pregel/_algo.py:233-345` `apply_writes` grouping by `task_path_str(t.path[:3])`) for replay — but surface `REPLANNED`/`PlanReplanTriggered` as distinct events, not as extra `pending_writes` entries.

### Patterns to avoid or delay until needed

- **Don't use `after_content` injection like `task.description += plan` for crew-level planning** (`lib/crewai/src/crewai/crew.py:1472`) — it erases the boundary between intent and plan and `task.description` is shared/mutable.
- **Don't register todo/plan mutation tools with `never_require` approval** (`python/packages/core/agent_framework/_harness/_todo.py:505`) in hosted settings — gate behind `ToolApprovalMiddleware` where `plan→execute` mode switch is an observable contract edge.
- **Don't rely on `is_complete:bool` alone.** `TodoItem.is_complete` (`python/packages/core/agent_framework/_harness/_todo.py:51-96`) lacks `blocked/abandoned` and audit. Prefer `TodoStatus=Literal["pending","running","completed","failed"]` (`lib/crewai/src/crewai/utilities/planning_types.py:11`) with `status` + `reason`.
- **Don't need a plan validator? Delay it — but not forever.** History-as-plan harnesses can defer declarative `Plan` until audit is required; once needed, start with `OutputSchema` capturing `list[Step{tool, args, depends_on}]` and a `PlanExecutor` dry-run lint rather than a full engine.
- **Don't set `sequential=True` on one tool without auditing the whole batch** (`pydantic_ai_slim/pydantic_ai/tools.py:544` `ToolDefinition.sequential` creates a barrier that constrains `process_tool_calls` ordering non-locally).
- **Don't over-promise heuristic observation.** `heuristic_observation(success=True)` on exception (`lib/crewai/src/crewai/agents/planner_observer.py:88-208`) hides failures — unify to explicit `failed` even at `low` effort.

## Anti-Patterns / Caution Signs

- **Free-text plan bottleneck:** `TodoItem.title: str` or `task.description += plan` passes shape validation with hallucinated file paths/DB names. Signal: executed tool calls diverge from todo titles with no validator comparing them. Mitigate: compile-time `is_type_compatible` edge checks (`python/packages/core/agent_framework/_workflows/_validation.py:211-284`), tool-expectation checks (`lib/crewai/src/crewai/agents/agents/step_executor.py:515` `ValueError` if `tool_to_use` not called), or `PlanValidator` comparing remaining todos to recent observations before next `tick`.
- **Silent warn-and-drop shrinking the plan:** `apply_writes` or `prepare_push_task_send` logging and ignoring unknown writes/nodes instead of rejecting. Signal: fan-out shrinks, downstream reducer waits until `GraphRecursionError`/`MaxTurnsExceeded` with no error. Mitigate: `strict: bool` flag promoting warnings to `InvalidUpdateError`/`ModelBehaviorError`.
- **Lost justification / non-auditable mutations:** `todos_complete(reason)` not persisted (`python/packages/core/agent_framework/_harness/_todo.py:544-561`); `WorkflowCheckpoint` restores executor state but not harness todos (`python/packages/core/agent_framework/_workflows/_checkpoint.py` vs `python/packages/core/agent_framework/_harness/_todo.py:245-285`). Signal: "why was item 7 closed?" requires transcript scrape.
- **Fresh-context or `invoke()` lineage loss:** `AgentLoopMiddleware(fresh_context=True)` restoring baseline each iteration (`python/packages/core/agent_framework/_harness/_loop.py:436-586`) and `AgentExecutor.invoke()` wiping `plan/todos/observations/execution_log` (`lib/crewai/src/crewai/experimental/agent_executor.py:2879`). Signal: plan edits/observations vanish inside the loop or on resume.
- **Failed-as-satisfied masking downstream errors:** `TodoList._dependencies_satisfied` treating `failed` as satisfied (`lib/crewai/src/crewai/utilities/planning_types.py:112`) plus `continue_plan` even when `step_completed_successfully==False && needs_full_replan==False` (`lib/crewai/src/crewai/experimental/agent_executor.py:769-819`). Signal: downstream steps execute on garbage `result` from failed dependency.
- **Stall oscillation / premature reset:** Magentic decrementing `stall_count` on progress caps at 0 (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1118`) can prevent reaching `max_stall_count`; transient `is_in_loop` false positive triggers costly `reset()` clearing `chat_history` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:385-393`).
- **Sibling cancellation non-determinism:** `sibling_category_failure` cancel + `gather_with_cancel` (`src/agents/run_internal/tool_planning.py:984`) and `execute_todos_parallel` `asyncio.gather` sharing pre-observation state cause winner-dependent output ordering that affects prompt determinism; mitigate via `ordered_done_tasks` sorting (`src/agents/run_internal/tool_execution.py:337`) or explicit ordering knob.
- **Coarse resource locking throttling throughput:** `DeclaredResources(declared=False)` default causing `tool:<name>` mutex serialization (`_sdk_inspect/sdk/tool/tool.py:99-332`) even for independent file keys; any multi-agent plan will bottleneck unless tools declare `keys`.
- **Deprecated delegate with inherited workspace race:** `DelegateTool` spawning `LocalConversation`s sharing workspace (`_sdk_inspect/tools/delegate/impl.py:153-224`) deprecated since 1.16.0 without typed successor — any current cross-agent plan risks file races and free-text `DelegateObservation` concatenation.
- **String sentinel brittleness:** `"READY: I am ready to execute the task."` substring check (`lib/crewai/src/crewai/utilities/reasoning_handler.py:596`) and `VERDICT: DONE/MORE` markers (`python/packages/core/agent_framework/_harness/_loop.py:188-199`) fragile to LLM phrasing.

## Notable Absences

- **Versioned, lintable `Plan` artifact.** No source emits `Plan{id, revision, parent, steps:[{id, tool, depends_on, status, owner}], diff}` with `PlanValidator` honoring `depends_on`/`tool_to_use`. Closest are crewai ephemeral `TodoList` and openai-sdk ephemeral `ToolExecutionPlan` — both per-turn, not cross-run.
- **Shared plan versioning and revision history.** Agent-framework todo overwrites snapshots (`python/packages/core/agent_framework/_harness/_todo.py:265`); crewai `execution_log/observations` wiped on `invoke()`; langgraph `PendingWrite tuple[Any]` not schema-versioned; openai-sdk `RunState` versions `generated_items` but not plan diffs; openhands `EventLog` appends `PlanningFileEditorObservation` but groups to last edit per phase in preview.
- **Semantic plan verifier before execution.** Todo/plan channels validated for type/shape only; no source validates that the plan covers the request, has no duplicates, or is correctly ordered before looping. Pydantic/strict JSON helps per-tool args, not plan coverage.
- **Cross-agent shared plan DAG.** No shared `TodoList`/`Plan` mutex or partition — `Crew._execute_tasks` is sequential per `Task` (`lib/crewai/src/crewai/crew.py:1558`), `TodoStore` is per `AgentSession.source_id` (`python/packages/core/agent_framework/_harness/_todo.py:232-242`), `magentic` ledger is single-manager only. A `CrewPlan{tasks:[{agent_role, todos:TodoList}]}` with delegation edges is missing.
- **Typed plan lifecycle events.** No `plan_changed/plan_invalidated/plan_abandoned` stream — only Magentic `REPLANNED` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:786-800`), crewai `PlanReplanTriggeredEvent/PlanRefinementEvent`, and langgraph `channel_versions` drift. `on_output_validate_error`/`on_tool_validate_error` hooks exist but are per-tool, not per-plan.
- **Formal protocol contract artifact.** No protobuf/OpenAPI/IDL for `ToolRun*/ProcessedResponse/PregelExecutableTask/ModelRequestParameters` — contracts are Python dataclass + JSON schema generated at runtime; cross-language executors cannot contract-test from an exported spec.
- **Static cross-agent goto/route checks.** Langgraph statically checks `Command(goto=Literal["node"])` annotations (`libs/langgraph/langgraph/graph/state.py:812-858`) but not `Command.PARENT` namespace resolution (`libs/langgraph/langgraph/pregel/_retry.py:544-571` numeric-strip heuristic) or `Send` node existence until runtime.
- **Compaction-aware plan anchoring.** No source re-anchors a committed plan before context-window condensation/summarization — the plan block can be evicted from the LLM window even when it is the contract under execution.
