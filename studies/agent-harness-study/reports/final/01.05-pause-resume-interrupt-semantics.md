## Executive Summary

Six per-source studies of dimension 01.05 asked one question in five variants: can execution stop safely and resume later without losing meaning? Five sources contain substantive design evidence — three workflow/graph runtimes (agent-framework, langgraph, temporal), one server-backed chat-agent product (letta), and one sandboxed execution host (openhands). The sixth (`reports`) is an empty directory tree whose study is explicitly vacuous: zero files means zero interrupt points, checkpoints, or resume inputs to inspect (source report: `reports/source/01.05-pause-resume-interrupt-semantics/reports.md:18-23`).

Across the five substantive sources, the convergent finding is that **safe pausability comes from committing the pause itself as durable state at an architecturally-defined boundary before control returns to the caller**. LangGraph writes `INTERRUPT`/`RESUME` pending writes through its checkpointer (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:795`, `langgraph/pregel/_runner.py:585-591`). Temporal records pause as a history event through the same atomic transaction path as every other state mutation (`service/history/api/update_workflow_util.go:14-125`). Agent-framework snapshots state + messages + pending requests into a `WorkflowCheckpoint` at every superstep boundary (`agent_framework/_workflows/_checkpoint.py:30-89`). Letta commits the approval request message, step row, and run status in one transaction (`letta/agents/letta_agent_v3.py:1402-1410`). OpenHands is the deliberate outlier: it refuses to cache pause state at all after its `is_paused` column produced stale reads, and now treats the runtime as the sole source of truth (`alembic/versions/012.py:19-29`).

The divergent axis is *where the interrupt boundary sits and who honors it*: superstep boundaries plus arbitrary in-node `interrupt()` calls (langgraph), `request_info` pauses shaped as request/response pairs (agent-framework), step boundaries polled cooperatively (letta), OS-level container suspension that knows nothing of the agent inside it (openhands), and server-side pause enforced by stamp checks and event buffering with heartbeat-driven in-flight stop (temporal).

On the headline question — *"can a user approve a pending action tomorrow and continue from the exact same state?"* — the answer is yes-with-caveats for langgraph, agent-framework, and temporal (9/10 each), yes-for-practical-purposes-but-coarse for letta (7/10), and only-at-the-container-boundary for openhands (6/10). No source implements true multi-party resume arbitration; every system answers "can two actors resume the same run?" with some form of first-writer-wins.

## Core Thesis

> **A pause is safe exactly when it is committed like any other state transition — typed, persisted, correlated by a deterministic key, and validated on restore — and resume is safe exactly when the system has an explicit story for what changed in the world while execution was suspended.**

The evidence splits the sources into three durability postures. Event-sourced or checkpoint-committed pause (temporal's history events rebuilt by `mutable_state_rebuilder.go:671-678`; langgraph's checkpointer round-trip proven across memory/SQLite/Postgres savers; agent-framework's atomic `tmp + os.replace` file checkpoints at `_checkpoint.py:317-321`) survives crashes by construction. Transactionally-committed row state (letta's `Run`/`Step`/`Message` writes) survives crashes but leaves the resume contract implicit — there is no `POST /v1/runs/{id}/resume`; the client re-sends a message and the loop discovers the prior run (`letta/services/run_manager.py` vs. the docstring-only resume path, `letta_agent_v3.py:973-1023`). Externalized pause state (openhands) is correct-by-skepticism but makes the agent's own resumability someone else's problem, acknowledged in a single comment about ACP sessions self-resuming from `base_state.json` (`live_status_app_conversation_service.py:1875-1877`).

The second half of the thesis is what separates 9/10 systems from 7/10 ones: the world-changed problem. Temporal buffers signals, timers, cancels, and retries during pause and drains them in order on unpause (`event_store.go:352-356`, `tests/pause_workflow_execution_test.go:1159-1272`). Agent-framework states its contract bluntly — "the framework remembers what it knew; you remember what the world knows" — and offers executor hooks rather than automatic revalidation. LangGraph re-executes the interrupted node so application code can re-inspect the world. Letta handles the narrow case it models well (approval responses validated against persisted tool-call IDs even after context compaction, `helpers.py:230-310`, summarizer protection at `summarizer.py:295-304`) but does not model external change generally. Systems that lack both buffering and validation helpers push staleness onto callers silently.

## Approach Models

**temporal — pause as an event-sourced state-machine transition.** Pause is not a flag on a row; it is `EVENT_TYPE_WORKFLOW_EXECUTION_PAUSED` in replicated history plus `PauseInfo` metadata (identity, reason, request id) on mutable state (`service/history/historybuilder/event_factory.go:1052-1082`, `api/persistence/v1/executions.pb.go:4330-4402`). Enforcement is distributed: `UpdateWorkflowWithNew` refuses to schedule workflow tasks while paused (`update_workflow_util.go:80-90`), the transfer queue drops activity dispatches when `ai.Paused || ai.Stamp != task.Stamp` (`transfer_queue_active_task_executor.go:259-262`), and heartbeats carry the paused flag back to workers holding in-flight activities (`recordactivitytaskheartbeat/api.go:82-105`). Unpause regenerates the scheduled workflow task and pending activity work (`mutable_state_impl.go:3280-3302`). Workflow-level and activity-level pause are separate primitives.

**langgraph — checkpointer-centric interrupts in a BSP loop.** Two interrupt flavors with distinct semantics: static `interrupt_before`/`interrupt_after` evaluated against channel versions at compile time, and dynamic `interrupt(value)` raised mid-node, surfaced as an `Interrupt(value, id)` payload, and resumed with `Command(resume=...)` (`langgraph/types.py:811-934`, `graph/state.py:1170-1254`). Everything needed to resume lives in the checkpointer: the checkpoint plus reserved negative-index pending-write keys `INTERRUPT=-3, RESUME=-4` (`checkpoint/base/__init__.py:795`). Resume determinism comes from binding values to task ids and an interrupt counter, with xxh3-derived namespace hashes disambiguating identical interrupts across subgraphs (`types.py:559-578`). A fourth mechanism, cooperative drain via `RunControl.request_drain()`, stops at the next superstep boundary while persisting the checkpoint (`runtime.py:79-104`).

**agent-framework — layered pause over superstep checkpoints.** The only in-process pause is HITL-shaped: `WorkflowContext.request_info(...)` emits a typed event and settles the run into `IDLE_WITH_PENDING_REQUESTS` (`_events.py:58-67`, `_workflow_context.py:393-424`); the functional API raises `WorkflowInterrupted` (a `BaseException`, `_functional.py:83-99`). Checkpoints are written automatically at every superstep boundary and threaded into a `previous_checkpoint_id` chain (`_runner.py:84-144`). Restore validates a SHA-256 graph-signature hash and refuses mismatches (`_runner.py:274-279`). A third layer translates the identical model onto Azure Durable Task Scheduler, where .NET uses `TaskOrchestrationContext.WaitForExternalEvent` (`DurableExecutorDispatcher.cs:104-130`) — the same semantics ported across languages and hosts.

**letta — the run as a database lifecycle.** Pause states are rows: an `ApprovalRequestMessage` persisted with `stop_reason=requires_approval` mapping to `RunStatus.completed` (`schemas/letta_stop_reason.py:24-49`), or `RunStatus.cancelled` flipped by an API call and observed by a per-step DB poll (`agents/letta_agent_v2.py:749-757`). Client-side tool execution reuses the approval machinery. Long-running background runs persist SSE chunks to Redis streams with cursor-based reattachment (`redis_stream_manager.py:199-526`), so clients detach and reattach — even across restarts — without the run knowing.

**openhands — freeze the world, not the agent.** Pause/resume are properties of the runtime container: `container.pause()`, `psutil.suspend()`, or remote `POST /pause` (`sandbox_router.py:84-105`). Security is the standout concern: the session API key hash is nulled on pause and a fresh key issued on resume (`remote_sandbox_service.py:501-540`), and key auth is rejected for non-running sandboxes (`session_auth.py:73-87`). After migration 012 dropped the stale-prone `is_paused` column, the app server never trusts local pause state — every read queries the runtime (`remote_sandbox_service.py:188-206`). Whether the agent inside resumes meaningfully is delegated entirely to the embedded SDK.

**reports — no approach model.** The source contains only empty directories; the study documents absence rather than design and contributes no architectural evidence to this synthesis.

## Pattern Catalog

### 1. Commit the pause itself as durable state before yielding

- **Problem:** if the pause record lives only in process memory, a crash during the pause destroys the very state needed to resume.
- **Demonstrated by:** temporal (`AddWorkflowExecutionPausedEvent` appended in the standard update transaction, `mutable_state_impl.go:3196-3247`); langgraph (runner `commit()` writes `INTERRUPT` pending writes and explicitly does not treat interrupt as failure, `pregel/_runner.py:574-613`); agent-framework (`_create_checkpoint_if_enabled` at every superstep boundary, `_runner.py:212-238`); letta (`_step_checkpoint_finish` → message checkpoint → run status update, `agents/letta_agent_v2.py:988-1029`).
- **Why it works:** resume then reduces to loading persisted state plus presenting a validated input — no hidden in-process precondition. LangGraph's tests assert exact checkpoint counts after pause and resume across three saver implementations.
- **When to copy:** always. This is the load-bearing pattern of the dimension; every 7+ scorer does it.
- **When it is overkill:** never for anything resumable; for purely ephemeral interactive sessions where losing the run is acceptable, in-memory interruption suffices — but then do not advertise resumability.
- **Evidence:** see citations above; openhands supplies the contrast case (migration `011.py`→`012.py` shows DB-cached pause flags failing when external terminations go stale).

### 2. Typed, id-correlated resume inputs validated against persisted state

- **Problem:** "resume" must land on the exact pending decision, even with multiple interrupts outstanding, duplicate submissions, or compacted context.
- **Demonstrated by:** langgraph (`Command(resume={interrupt_id: value})` targeting xxh3-hash-keyed ids, multi-interrupt validation raising otherwise, `_loop.py:891-919`); agent-framework (`responses={request_id: value}` validated against actually-pending requests, `workflow.py:912-960`, with deterministic `auto::<index>` fallback ids, `_functional.py:229-234`); letta (`validate_approval_tool_call_ids` requires the response to reference every pending tool call, `helpers.py:121-148`, and an idempotency check searches full history so retries after summarization dedupe, `helpers.py:230-310`); temporal (`RequestId` idempotency on pause — same id is a no-op — and precondition guards on unpause, `pauseworkflow/api.go:61-67`, `unpauseworkflow/api.go:58-62`).
- **Why it works:** correlation ids turn resume from "continue somehow" into a lookup, making duplicates harmless and misdirected responses detectable errors rather than silent corruption.
- **When to copy:** whenever more than one pause point can be outstanding, or when resume crosses a network/process boundary (i.e., almost always in production).
- **When risky:** auto-generated sequential ids (agent-framework's `auto::<index>`) are stable only within replaying the same run; callers must not treat them as globally unique.
- **Evidence:** citations above; letta additionally protects the trailing approval pair from summarizer eviction so the correlation target cannot be compacted away (`services/summarizer/summarizer.py:295-304`).

### 3. Restore-time validation guards against a changed program

- **Problem:** a checkpoint saved by version A of the code must not be silently restored by structurally different version B.
- **Demonstrated by:** agent-framework (SHA-256 graph signature over executors/edges checked on restore, raising `WorkflowCheckpointException("Workflow graph has changed")`, `_runner.py:274-279`; functional API mixes step bytecode digest into the hash, `_functional.py:1144+`; both covered by `test_resume_fails_when_graph_mismatch`); temporal (mutable state rebuilt strictly by replaying history events, so code changes surface as replay divergence rather than silent state mismatch, `mutable_state_rebuilder.go:671-678`).
- **Why it works:** fail-fast beats corrupted continuation; the error names the mismatch instead of producing undefined behavior steps later.
- **When to copy:** any system whose persisted pause outlives deploys — which is the entire point of long-lived HITL pauses.
- **Cost/risk:** strict hashing turns benign refactors into restore failures; teams need a documented migration story (langgraph demonstrates one: legacy pre-v1 interrupt payloads round-trip through modern serializers with dedicated migration tests, `tests/test_interrupt_migration.py:11-49`).
- **Evidence:** citations above.

### 4. Cooperative stop at architecturally-defined boundaries

- **Problem:** preemptive kills corrupt state; systems need sanctioned points where stopping is safe.
- **Demonstrated by:** langgraph (`RunControl.request_drain()` sets a flag checked at the top of `tick()`; checkpoint still persists; sub-superstep cancellation deliberately unsafe and not attempted, `runtime.py:95`, `tests/test_runtime.py:170-246`); letta (per-step `_check_run_cancellation` DB poll plus a 0.5 s poll wrapper on SSE streams, `agents/letta_agent_v3.py:1029-1035`, `streaming_response.py:153-229`); temporal (heartbeat returns `ActivityPaused` and the worker stops itself; completed-anyway activity results are rejected by stamp check, `isactivitytaskvalid/api.go:60-63`).
- **Why it works:** bounded, testable interruption semantics; every system can state exactly how long a stop may take (one superstep / one step / one heartbeat interval) — though letta's honest answer is "one LLM call plus tool execution," which can be minutes.
- **When to copy:** universally; pair with a deadline-aware escalation (none of the three has one yet — langgraph lists a drain timeout as future work).
- **Counter-example:** openhands suspends the container mid-instruction with no handshake; whatever the agent was doing simply halts at the OS level, and whether that state is coherent is invisible to the app server.
- **Evidence:** citations above.

### 5. Control-flow signals that cannot be swallowed by user error handling

- **Problem:** if pause/cancel travels as a normal exception, application `except Exception:` blocks absorb it and the run silently continues or dies wrong.
- **Demonstrated by:** langgraph (`GraphBubbleUp` superclass short-circuits the retry layer so interrupts skip retry handling, `pregel/_retry.py:632-634`; user `asyncio.CancelledError` wrapped in `NodeCancelledError` to prevent masquerade, `errors.py:168-186`); agent-framework (`WorkflowInterrupted` extends `BaseException` precisely so user handlers cannot catch it, `_functional.py:83-99`).
- **Why it works:** it encodes "this is not an error" in the type system rather than in documentation.
- **When to copy:** any embeddable runtime where users write the code being interrupted.
- **When risky:** `BaseException` escapes naive `except:` too; document it loudly (agent-framework catches it in `_run_core` so authors never see it).
- **Evidence:** citations above.

### 6. Buffer or protect the world's inputs during pause

- **Problem:** events arriving during suspension must neither vanish nor arrive out of order on resume.
- **Demonstrated by:** temporal — the deepest treatment: signals received while paused are recorded to history but buffered without scheduling a workflow task, drained in order in a single task on unpause (`TestSignalBufferingOrderWhilePaused`, `tests/pause_workflow_execution_test.go:1159-1272`); fired timers record events but defer their task; cancels requested during pause take effect only after unpause (`tests:1505-1578`); activity retry counters freeze (`mutable_state_impl.go:6803-6819`); pause/unpause events themselves buffer behind in-flight workflow tasks to avoid races (`event_store.go:302-360`). Letta — narrower but real: stale approval responses fail tool-call-id validation, retried approvals dedupe via full-history search, and the summarizer refuses to evict pending approvals (`helpers.py:121-148,230-310`, `summarizer.py:295-304`).
- **Why it works:** ordering guarantees convert "what happened while I was away" from data loss into a deterministic queue.
- **When to copy:** whenever external parties can send inputs to a paused run (chat platforms, webhooks).
- **When overkill:** single-user local tools where the human is also the only input source.
- **Evidence:** citations above; langgraph's partial analog reapplies succeeded siblings' writes from the checkpoint rather than re-running them (`_loop.py:724-737`).

### 7. Rotate credentials across the pause boundary

- **Problem:** long pauses extend the lifetime of any credential captured at start; a leaked key should die at pause.
- **Demonstrated by:** openhands alone — `session_api_key_hash = None` before pausing; resume mints and stores a new key (`remote_sandbox_service.py:501-540,542-570`); auth rejects non-running sandboxes outright (`session_auth.py:73-87`); the resume endpoint is rate-limit-exempt because it is the critical recovery path (`middleware.py:18`).
- **Why it works:** invalidation is enforced by authentication failure rather than by trusting a paused flag.
- **When to copy:** hosted products where sandboxes/sessions hold user secrets and pause windows are unbounded.
- **Cost:** every resume churns secret lookups; long-lived integrations caching the old key break until they observe rotation (a sharp edge openhands notes for third parties).
- **Evidence:** citations above; absent from all other four sources' designs.

## Key Differences

**Granularity of interrupt points.** LangGraph offers the finest: static node-boundary breakpoints plus arbitrary `interrupt()` calls inside a node body (`types.py:811-934`), with multiple interrupts per node matched by counter index. Temporal operates at workflow-task granularity with heartbeat-mediated stops for activities. Letta pauses only between steps — an in-flight LLM call or tool always completes (`agents/letta_agent_v3.py:1511-1540`). Agent-framework pauses at `request_info` call sites and superstep boundaries, and intentionally offers no plain "sleep until X" for the graph API because a pause without an expected response lacks a deterministic resume trigger. OpenHands pauses everywhere and nowhere: OS suspension can strike mid-instruction, which is maximum availability of interrupt with minimum semantic content.

**Who interprets the pause.** In temporal and langgraph, the runtime enforces pause mechanically (no task scheduling; no task dispatch past stamps). In agent-framework, the framework persists but the executor owns revalidation ("you remember what the world knows"). In letta, the loop interprets only its own status enums. In openhands, nobody in the studied repo interprets the agent's pause — the SDK is a black box, which is why its rating rests on operational safeguards rather than semantic guarantees.

**Pause vs. cancel vs. terminate separation.** Temporal keeps them crisply distinct and composable: cancel-during-pause is recorded and delivered on unpause, terminate works while paused, reset spawns a fresh RUNNING run (`tests:1347-1755`). LangGraph separates dynamic interrupt, drain, and error writes with reserved indices. Agent-framework's .NET side has an explicit halt primitive (`DurableHaltRequestedEvent.cs:10-16`) the Python side lacks. Letta conflates: cancelling an approval-paused run materializes denial tool-returns, so "user cancelled" and "user denied" leave identical trails (`run_manager.py:705-777`) — operationally simple, forensically lossy.

**Resume branch semantics.** LangGraph is the only source where resuming an arbitrary historical checkpoint creates an explicit fork (`source="fork"` checkpoints prevent subsequent resumes loading wrong state, `_loop.py:940-959`). Temporal's reset-while-paused starts a new run — pause is per-run, never inherited by ContinueAsNew or reset. Agent-framework's checkpoint chain supports branching structurally but exposes no fork API (`CheckpointStorage` has no branch method, `_checkpoint.py:119-189`), so recovery is single-branch. Letta and openhands continue the same entity by construction (same `conversation_id` / sandbox row reused).

**Multi-party resume posture.** Temporal is strongest: per-shard workflow leases serialize simultaneous unpause RPCs, and the second fails a precondition cleanly (`consistency_checker.go:114-122`). Agent-framework serializes per instance via `_ensure_not_running` (`workflow.py:379-383`) but has no cross-process claim. LangGraph declares single-writer per thread id with first-write-wins and no optimistic concurrency. Letta permits org-wide read fan-out via shared streams but write races are unresolved (first writer wins; `ConcurrentUpdateError` timing-dependent). OpenHands has no ownership check beyond creation and no idempotency token, so duplicate resumes each mint fresh keys.

## Tradeoffs

**Re-execution vs. cached replay on resume.**
LangGraph re-runs the interrupted node from its top, exposing pre-`interrupt()` logic to the resume value and offering no built-in idempotency — simple runtime, side-effect burden on authors (`func/__init__.py:479-525` offers memoization help). Agent-framework caches per-step results so resume skips completed steps entirely — fast and inherently idempotent, demonstrated by `test_per_step_checkpoint_enables_crash_recovery` (`test_functional_workflow.py:592-635`) — at the cost of larger checkpoints carrying `_step_cache`. Best-fit: re-execution where nodes wrap idempotent APIs; caching where steps are expensive or non-idempotent. Failure modes: silent duplicate side effects (re-execution) vs. checkpoint bloat and staleness of cached results (caching).

**Event-sourced enforcement vs. row-state enforcement.**
Temporal's history-event pause buys auditability, replication to passive clusters via stamp bumps (`mutable_state_impl.go:3229-3244`), and crash-proof rebuilds; it costs an event log, buffering machinery, and a documented race window against in-flight tasks requiring regression tests (`tests:853-983`). Letta's row flip buys transactional simplicity and SQL queryability; it costs a scattered status model — four overlapping enums (`RunStatus`, `StepStatus`, `StopReasonType`, `JobStatus`) that must be reconciled, with only `RunStatus` consulted for cancellation.

**Always-ask-runtime vs. cached pause state (openhands).**
Dropping the `is_paused` column eliminated a class of stale-cache bugs (external terminations leaving phantom "paused" rows) at the price of a runtime API call on every sandbox read and slower queries. Correctness-for-latency trades rarely appear this explicitly in a schema migration; it is a textbook receipt (`011.py:19-38` → `012.py:19-29`).

**Cooperative vs. preemptive interruption.**
Every substantive source chose cooperative. Benefit: no torn state, testable bounds. Cost: a non-cooperating unit blocks everything — a busy node defeats langgraph's drain, a hung LLM provider stalls a letta run indefinitely (tests sidestep this with short prompts, `integration_test_cancellation.py:179-188`), a non-heartbeating worker keeps a paused temporal activity alive. No source ships deadline-aware escalation.

**HITL-shaped pause vs. general-purpose pause.**
Agent-framework's choice that all in-process pause is request/response-shaped gives every pause a deterministic resume trigger, but forces "wait for a queue/timestamp" patterns into the durable-task tier. Temporal's admin-facing pause has no expected response at all — it is an operational brake, not a conversation turn — which suits its operator audience. Same word, different products, both valid.

## Decision Guide

- **Building a workflow engine or orchestrator where pause must survive infra failure, replication, and audits?** Copy temporal: pause as history event, stamps for dispatch gating, buffered external inputs, lease-serialized transitions. Accept the cost of an append-only log and race-regression testing.
- **Embedding pause/resume in an in-process graph library with pluggable persistence?** Copy langgraph: reserved control-write keys, resume values bound to task + counter + namespace hash, explicit `Command` resume, cooperative drain. Require idempotent node bodies by contract, since you will re-execute them.
- **Need both lightweight local iteration and production-grade durability from one model?** Copy agent-framework's layering: one pause semantic (`request_info`), swappable `CheckpointStorage` Protocol (in-memory/file now, remote later), signature-checked restore, optional durable-host translation layer.
- **Building a product API where runs are resources customers poll and approve over HTTP?** Copy letta's shape — typed stop reasons mapped to run status, approval payloads validated against persisted tool-call ids, stream reattachment via cursors — but fix its gaps: add a first-class resume endpoint, an owner/lease field, and a version column before allowing concurrent writers.
- **The agent internals are a black box you cannot change?** OpenHands' posture is the honest fallback: pause the environment, rotate credentials, treat the runtime as truth, refuse operations needing a live agent. Do not claim semantic resumability you cannot verify.
- **Choosing between re-execution and cache-replay:** default to re-execution (langgraph-style) unless steps are expensive or non-idempotent; then adopt agent-framework-style step caches and pay the checkpoint-size cost.
- **If your pause can outlive a deploy,** you need restore-time structural validation (signature hash or replay) before anything else; without it, tomorrow's approval lands in yesterday's topology.

## Practical Tips

- Persist the pause atomically with the state it freezes. Every high scorer ties the pause record into the same transaction/write path as normal state (`update_workflow_util.go:14-125`; `letta_agent_v3.py:1402-1410`).
- Make resume input small, typed, and id-correlated. Validate it against persisted state on arrival (pending-request existence checks in agent-framework `workflow.py:936-960`; tool-call-id validation in letta `helpers.py:121-148`).
- Reserve distinct persistence keys for control signals so they cannot collide with data writes (langgraph `WRITES_IDX_MAP` with negative indices, `checkpoint/base/__init__.py:795`).
- Model "stopped waiting for a human," "operator braked the run," and "killed" as different states. Letta's cancel/deny conflation shows the forensic cost of merging them.
- Protect pending-approval context from compaction/eviction, or make correlation survive it (letta searches full history for the matching tool message, `helpers.py:248-265`).
- Buffer inbound events during pause and drain in order; assert the order in tests like temporal's `TestSignalBufferingOrderWhilePaused`.
- State the worst-case stop latency honestly in docs: "one superstep" (langgraph), "one heartbeat interval" (temporal), or letta's uncomfortable "one full LLM call plus tool."
- Expose pause/resume as observable events — lifecycle callbacks (`on_interrupt`/`on_resume` in langgraph `callbacks.py:42-77`), webhook firing on pause/resume (openhands `webhook_router.py:339`), search attributes for paused entities (temporal `TemporalPauseInfo`, `mutable_state_impl.go:6979-6995`).
- Rate-limit-exempt the resume path deliberately (openhands `middleware.py:18`) — it is the recovery route users hammer during incidents — but add an idempotency token so retries do not churn keys.
- Test pause under adverse interleavings explicitly: pause-during-in-flight-task, cancel-while-paused, retry-while-paused, resume-after-graph-change. All three 9/10 sources have named tests for exactly these.

## Anti-Patterns / Caution Signs

- **Caching pause state that another actor can change underneath you.** OpenHands added `is_paused` in migration 011 and dropped it in 012 after external terminations made it lie. If you cache, you must own invalidation.
- **Multiple overlapping lifecycle enums requiring reconciliation.** Letta's `RunStatus`/`StepStatus`/`JobStatus`/`StopReasonType` quadruplicate phase semantics; "is this paused?" requires reading `Run.stop_reason`, not the step's own status.
- **Cancellation that only samples at coarse boundaries with no escalation.** A stuck LLM HTTP call or a hung tool makes "cancel" advisory (letta); a busy node blocks drain (langgraph); a silent worker ignores pause (temporal). Caution sign: tests that use artificially short prompts/timeouts to make cancellation observable.
- **Conflating terminal reasons.** When cancel and deny produce byte-identical trails, incident review cannot distinguish user intent (letta `run_manager.py:705-777`).
- **Resume discoverable only by reading docstrings.** If there is no endpoint/method named "resume," every client reimplements the protocol and some get it wrong (letta's implicit pick-up; openhands' V1 endpoints missing from generated OpenAPI, `scripts/update_openapi.py:19-20`).
- **Swallowable control-flow exceptions.** If user `except Exception:` can eat your interrupt, pause becomes probabilistic. Both mature runtimes encode the exception hierarchy defensively.
- **No ownership or lease on resumable entities.** Every source exhibits some variant: any org member can cancel a letta run; anyone with a `sandbox_id` can resume an openhands sandbox; langgraph threads have no claim primitive. The caution sign is answering concurrency questions with "the event loop serializes it."
- **Black-box boundaries without contracts.** OpenHands triggers resume but cannot verify the agent server recovered; a single comment acknowledges the SDK's role. If component A claims resumability that component B must deliver, the contract needs a test, not a comment.

## Notable Absences

- **Optimistic concurrency on resume everywhere.** No source implements CAS-style resume (e.g., `expected_parent_checkpoint_id`), listed explicitly as future work in langgraph; letta lacks a version column on run updates; openhands mints a new key per duplicate resume.
- **Checkpoint forking as an API.** LangGraph achieves forks via time-travel (`get_state_history` + explicit checkpoint config), but agent-framework's chain structure — which could support it — exposes no fork/branch method, so parallel exploration of a paused run requires restore-then-manually-repause.
- **Approval gates at the app-server layer in openhands.** No router exposes list/approve/reject of pending actions; `confirmation_mode` is forwarded as a policy hint and enforced invisibly inside the SDK. No interrupt API is proxied either.
- **Mid-flight interruption primitives generally.** Temporal has no force-stop for a single activity (heartbeat only) and stubs `PauseActivityExecution`/`UnpauseActivityExecution` as `Unimplemented` (`workflow_handler.go:7306-7317`); letta has no tool-call cancel; langgraph offers no way to resume a node from *after* the interrupted statement rather than the node top.
- **Retention/TTL policies for checkpoints.** Agent-framework's storage protocol has delete but no garbage-collection story; letta's Redis SSE streams expire after 3 hours (`redis_stream_manager.py:42-44`), bounding reattachment windows arbitrarily.
- **Any evidence at all from `reports`.** The source tree contained zero files — only an empty staging directory named for a different dimension slug (`07.04-timeouts-and-cancellation`). Its study contributes a process lesson, not design evidence: staging scaffolding without manifests lets vacuous corpora pass silently through a pipeline, and a preflight emptiness check would have caught it.

## Per-Source Notes

- **temporal (9/10):** The most complete treatment of "world changed while paused": signals, timers, cancels, and retries each have defined deferral semantics with named regression tests, including an issue-linked race test iterating 200 times. Deductions center on the acknowledged in-flight-task race window and heartbeat-only activity interruption. Pause is per-run — ContinueAsNew and reset escape it by design.
- **langgraph (9/10):** Richest interrupt taxonomy (static breakpoints, dynamic value-bearing interrupts, cooperative drain, time-travel forks) with the strongest cross-backend persistence proof (memory/SQLite/Postgres) and legacy-payload migration tests. Weakest links: whole-node re-execution pushes idempotency to authors; exit-mode checkpoint logic carries a flagged identity-check hack (`_loop.py:1075`).
- **agent-framework (9/10):** Only source spanning two languages with identical semantics (.NET `WaitForExternalEvent` mirror), and the only one validating program structure at restore time via graph-signature hash. Gaps: no Python halt primitive to match .NET's; parent-workflow restoration from sub-workflow-bearing checkpoints is a tracked TODO (`_workflow_executor.py:525-526`).
- **letta (7/10):** Strongest productized HITL ergonomics — approval requests are first-class messages with validation and summarization-proof idempotency, and background streams reattach across restarts. Loses points to step-granularity-only cancellation, enum sprawl, implicit resume, and unowned concurrent writes.
- **openhands (6/10):** Best operational-security story (key rotation, rate-limit-exempt resume, runtime-as-truth after a measured rollback of cached pause state). Semantically thinnest: no approval API, no interrupt proxy, agent internals opaque; resume determinism holds only at the sandbox boundary.
- **reports (1/10):** Vacuous by construction — an empty corpus studied exhaustively. Valuable only as pipeline hygiene evidence: its report self-documents every search performed and recommends a `SKIPPED_EMPTY_SOURCE` preflight guard plus artifact manifests so partial population becomes detectable.

## Open Questions

- **Cross-process coordination:** can multiple workers safely share one resumable thread/run anywhere? LangGraph says no lock exists; letta's conversation lock covers new requests but not resumes; openhands has none. Nobody answered yes with evidence.
- **Propagation latency of pause to in-flight work:** temporal documents the mechanism (heartbeat round-trip) but no SLA; letta's upper bound is "one full step"; no source publishes a number.
- **Sub-workflow/sub-agent attribution:** how do interrupts from parallel subgraphs surface deterministically and identifiably? LangGraph flattens to one merged tuple with namespace-hash-only attribution; letta delegates multi-agent loops opaquely; agent-framework's cross-workflow restore is unfinished (issue #1614).
- **Corrupted-state recovery:** what happens when a checkpoint file or mutable-state blob is damaged mid-pause? LangGraph found no detection/repair path; agent-framework's atomic writes bound the window but define no recovery; temporal relies on history replay but does not address corrupt history.
- **Child-workflow pause composition:** temporal found no parent-command pause for child workflows — pause is API-driven only. Is that a gap or a principle?
- **Does `confirmation_mode` in openhands constitute a real gate?** The repo evidence supports only "hint forwarded to the SDK"; verifying actual approval behavior requires studying the external agent server, outside this study's boundary.
- **What populated `sources/reports` supposed to contain, and did its producer crash or was it cleaned?** Undeterminable from the empty tree; the per-source report recommends manifests and checksums to make this diagnosable next time.
