## Executive Summary

The four sources represent four distinct answers to "where does durable knowledge live?" Microsoft Agent Framework treats memory as a **pluggable context-engineering pipeline**: one two-phase SPI (`ContextProvider`) with five swappable backends and unusually deliberate scoping/governance safeguards. CrewAI implements a **single unified LLM-curated store**: one `Memory` class with hierarchical path scopes, an LLM-in-the-loop encoding/recall flow, composite ranking with recency decay, and local-first LanceDB persistence. Letta makes tiered memory the **product architecture itself**: core/archival/recall/git-backed tiers as database entities, org-enforced multi-tenancy in the ORM base class, blocks shared via pivot tables, and actor-attributed undo/redo history. OpenHands' frontend is a **control plane only**: it owns a memory toggle, a project/personal/public skill taxonomy, and deny-list disabling, while all memory content lives server-side outside this source.

Scores cluster at 7–8 for the three systems that own memory end-to-end, with openhands at 6 because its layer cannot inspect or correct the memory content it switches on. The deepest convergence is a negative result: **no source implements TTL or expiry** — staleness is managed by decay ranking (crewai), consolidation cadence (agent-framework harness), prompt instructions (letta), or is simply accepted (openhands build-time catalog, agent-framework Mem0). Correction is the second universal weak leg: strong only where memory is a first-class edited artifact (letta's surgical tools + undo stack; agent-framework's harness topic files), LLM-dependent in crewai (consolidation falls back to insert), absent in Python Mem0, and impossible from openhands' UI.

## Core Thesis

Long-term memory maturity tracks how many of these five properties a system treats as first-class: **scoped writes, partitioned reads, attributed mutations, correctable records, and mechanical freshness.** All four sources persist knowledge durably; none enforces freshness mechanically; correction quality spans from letta's verbatim-uniqueness edits with undo/redo to openhands having no memory-content surface at all. The decisive architectural choice is not which vector store to use but **who is trusted to write, who can read, and whether scope is enforced by structure (paths, directories, ORM tenancy) or by convention (strings, flags, heuristics)** — sources that enforce by structure (letta org predicates, agent-framework non-inheriting retrieval scopes) score their safety guarantees in tests; sources that enforce by convention (crewai path prefixes, openhands filesystem heuristics) document the fragility themselves.

> Can useful knowledge persist without becoming creepy or wrong? Only partially: every source can persist usefully, but "not wrong" depends on correction surfaces that exist in just two of four sources, and "not creepy" depends on identity binding that only the platform-shaped sources (letta, hosted agent-framework) actually enforce.

## Approach Models

Four approach models emerged, one per source:

1. **Extension-point pipeline (agent-framework).** Memory is whatever plugs into a two-phase hook — retrieve/inject before the run, extract/write after (`python/packages/core/agent_framework/_sessions.py:793`; .NET mirror at `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:42`). Five concrete stores (Mem0, Foundry, Cosmos toolkit, Redis, file-based harness memory) share one contract. Scope is explicit and layered: Mem0 separates *storage* scope from a *retrieval* scope that never inherits by default (`python/packages/mem0/agent_framework_mem0/_context_provider.py:50-62`). The framework deliberately refuses to be the memory service.
2. **Unified curated service (crewai).** One `Memory` class replaced the legacy short/long/entity/external split (deprecated aliases remain at `lib/cli/src/crewai_cli/cli.py:430-451`). Every write passes through an LLM EncodingFlow that infers scope/category/importance and plans keep/update/delete consolidations (`lib/crewai/src/crewai/memory/encoding_flow.py:112-222`); every read passes through an adaptive-depth RecallFlow with composite semantic+recency+importance scoring (`lib/crewai/src/crewai/memory/types.py:345-380`). Tenancy is hierarchical string scopes like `/company/team/user` (`lib/crewai/src/crewai/memory/types.py:28-31`).
3. **Tiered platform data model (letta).** Memory is the product: always-in-context core blocks, unbounded archival passages, searchable recall history, and an opt-in git repository giving blocks full commit history (`letta/services/block_manager_git.py:1-50`). Blocks are first-class shared objects linked to agents/groups/identities via pivot tables (`letta/orm/blocks_agents.py`, `identities_blocks.py`), and organization tenancy is applied in the ORM base class so every read is filtered by default (`letta/orm/sqlalchemy_base.py:116-118, 265-267`).
4. **Control plane (openhands).** The frontend owns no memory content. It persists a `load_memory` opt-in flag (`src/mocks/settings-handlers.ts:357-369`), classifies skills into project/personal/public scopes from filesystem paths (`src/utils/skill-scope.ts:3-9`), merges skills into conversation launch contexts with deny-list filtering (`src/api/agent-server-adapter.ts:749-788`), and keeps disposable device-local state in localStorage. Retrieval machinery (keyword triggers) lives entirely in the agent-server.

Clustering note: models 1–2 are library-shaped (memory is opt-in wiring, identity is caller-supplied), model 3 is application/platform-shaped (memory is server state with enforced tenancy), model 4 shows what a memory system looks like from the client slice of a multi-repo product. These are responses to different constraints, not quality ranks.

## Pattern Catalog

### P1. Two-phase memory hooks around the agent loop
- **Problem:** memory retrieval/extraction must not tangle with the core agent loop.
- **Demonstrated by:** agent-framework (`ContextProvider.before_run/after_run`, `_sessions.py:793-828`; .NET `InvokingAsync/InvokedAsync`, `AIContextProvider.cs:42-91`); crewai achieves the same effect with EncodingFlow/RecallFlow invoked around task execution (`agent/core.py:619-682`).
- **Why it works:** any backend (vector DB, SaaS, filesystem) plugs in without loop changes; providers compose with per-source attribution (`_sessions.py:757-790`).
- **Copy when:** building a framework or harness where users bring their own stores.
- **Overkill when:** a single fixed backend suffices — then it is indirection without payoff.
- **Evidence:** agent-framework report, Core SPI rows; crewai report, auto context injection row.

### P2. Storage scope decoupled from retrieval scope, with non-inheritance
- **Problem:** memories written under a shared `agent_id` leaking to unrelated users.
- **Demonstrated by:** agent-framework Python Mem0 — `search_*` scopes never inherit storage scopes, nothing is retrieved until explicitly configured, proven by dedicated tests (`python/packages/mem0/tests/test_mem0_context_provider.py:372,449,500`); samples stress that agent-wide retrieval returns memories written by *any* user (`python/samples/02-agents/context_providers/mem0/mem0_sessions.py:29-166`).
- **Why it works:** read authorization is a separate decision from write routing; defaults fail closed.
- **Copy when:** multi-user deployments share any agent or application namespace.
- **Risky when:** copied inconsistently — .NET defaults `SearchScope = storageScope` (`dotnet/src/Microsoft.Agents.AI.Mem0/Mem0Provider.cs:284-287`), and the cross-language divergence is flagged as a migration leak hazard.
- **Evidence:** agent-framework report, Architectural Decision 2 and Tradeoffs.

### P3. Structural partitioning of physical storage by owner
- **Problem:** tenant isolation must not depend solely on query filters.
- **Demonstrated by:** agent-framework harness memory encodes source+owner into directory paths with traversal rejection (`python/packages/core/agent_framework/_harness/_memory.py:700-745`) and hosted Foundry partitions `{root}/a-{agent}/u-{user}/c-{context}.json` as defense-in-depth beyond identity checks (`docs/decisions/0031-hosted-per-user-session-storage-isolation.md`); letta namespaces Turbopuffer vectors per archive/org and prefixes git repo paths with the org (`letta/helpers/tpuf_client.py:312-346`; `git_operations.py:91-95`).
- **Why it works:** a forged identifier cannot even resolve into another tenant's physical location.
- **Copy when:** hosting untrusted identifiers or storing per-user artifacts on shared infrastructure.
- **Overkill when:** single-tenant local-first tools (crewai's project-keyed disk store, `paths.py:16-26`).

### P4. Attribution metadata as a governance primitive
- **Problem:** blended memory origins make audit, debugging, and attack detection impossible.
- **Demonstrated by:** agent-framework stamps `_attribution.origin_session_ids` on injected cross-session content and ships an observer sample defending against chained sub-backdoor attacks (`python/packages/core/agent_framework/_sessions.py:624-698`); letta checkpoints record `actor_type`/`actor_id` (`letta/services/block_manager.py:898-899`) and git commits record author type/id (`letta/schemas/memory_repo.py:19-44`); crewai keeps `MemoryRecord.source` provenance — though unauthenticated free text (`types.py:60-66`).
- **Why it works:** provenance turns "the agent said" into a queryable fact.
- **Copy when:** memory crosses session, user, or agent boundaries in any direction.
- **Caveat:** attribution without authentication (crewai `source`) is documentation, not enforcement.

### P5. LLM-in-the-loop write curation with safe fallbacks
- **Problem:** raw transcript dumps rot; extraction adds cost and its own failure modes.
- **Demonstrated by:** crewai's EncodingFlow dedupes (≥0.98 cosine), analyzes overlap, and executes keep/update/delete plans — defaulting to plain insert on analysis failure (`encoding_flow.py:224-347`; fallback at `analyze.py:309-315`); agent-framework's Cosmos provider runs cadence-throttled fact extraction drained on exit (`packages/azure-cosmos-memory/.../_context_provider.py:262-280, 313-332`) and harness extraction caps at ~5 durable facts per pass with 24h/5-session consolidation gates (`_harness/_memory.py:39-68, 1505-1573`); letta's sleeptime agent is instructed to clean "redundant and outdate information" (`letta/prompts/system_prompts/sleeptime_v2.py:16-28`).
- **Why it works:** writes become distillation events, not accumulation events.
- **Copy when:** conversation volume exceeds what raw recall can rank usefully.
- **Risky when:** curation failures are silent — crewai's availability-over-accuracy fallback means bloated/mis-scoped records accumulate rather than get lost.

### P6. Progressive disclosure with index sidecars
- **Problem:** unbounded context injection vs. completeness.
- **Demonstrated by:** agent-framework harness memory loads a `MEMORY.md` table of contents plus ≤3 keyword-scored topic files per turn, with tools to pull more (`_harness/_memory.py:38, 1079-1098, 1292-1313`); indexes are rebuilt atomically after mutations and hidden from the agent's own grep surface (`_harness/_file_memory.py:76-99, 280-299`). Contrast: letta compiles full core memory into every system prompt within a char limit (`letta/constants.py:435`).
- **Copy when:** memory corpora grow past prompt budget.
- **Overkill when:** memory fits comfortably in-context — progressive disclosure adds tool-call latency.

### P7. Edit-safety ergonomics for model-writable memory
- **Problem:** letting an LLM mutate persistent state invites corruption.
- **Demonstrated by:** letta most thoroughly — `read_only` block flags enforced in every mutating tool (`core_tool_executor.py:319-321`), line-number display prefixes validated away so display artifacts never corrupt stored values (`:357-374`), verbatim-uniqueness required for replace (`:380-391`), optimistic-locking version column (`orm/block.py:56-58`), and a linear undo/redo checkpoint stack with actor attribution (`block_manager.py:859-909`). agent-framework instructs the model to read a topic before editing and registers write tools with `approval_mode="never_require"` (`_harness/_memory.py:1223-1313`) — the approval default is a conscious tradeoff hosts may tighten.
- **Copy when:** the model, not just the user, can write memory.
- **Skip when:** writes are application-controlled only.

### P8. Soft-disable (deny-list) instead of deletion
- **Problem:** users want knowledge off without destroying it.
- **Demonstrated by:** openhands `disabled_skills` filtered at launch time on both OpenHands and ACP paths, tested (`src/api/agent-server-adapter.ts:763-767`; tests `__tests__/api/agent-server-adapter.test.ts:131-178`); crewai offers `read_only=True` making writes silent no-ops (`unified_memory.py:165-171`).
- **Why it works:** reversible, auditable, no destructive operations in the happy path.
- **Failure mode:** orphaned names accumulate — openhands replaces the list wholesale and keys by name, so renamed skills leave stale entries forever (`settings-service.api.ts:70-75`).

### P9. Serialized background writes with drain-before-read barriers
- **Problem:** LLM-curated writes are slow; blocking the agent on them is unacceptable, but unordered async writes corrupt read-your-writes expectations.
- **Demonstrated by:** crewai's single-worker save pool plus mandatory `drain_writes()` inside `recall()` (`unified_memory.py:148-151, 350-363`); agent-framework Cosmos drains scheduled extractions via `flush()` on exit (`_context_provider.py:313-332`). Counter-example: Foundry fire-and-forget updates only log failed writes (`_memory_provider.py:262-263`).
- **Copy when:** write latency would otherwise stall turns.
- **Watch for:** interpreter-shutdown races — crewai documents saves silently abandoned at exit (`unified_memory.py:641-650`).

## Key Differences

**Enforcement mechanism for isolation.** Letta enforces tenancy structurally in the ORM base class with security warnings when reads bypass filtering (`sqlalchemy_base.py:256-258, 499-504`); agent-framework enforces it by API contract and tests (non-inheriting scopes, physical partitioning); crewai and openhands rely on conventions — sanitized path strings sharing one table (`memory/utils.py:8-36`) and home-directory regexes (`skill-scope.ts:35-106`) respectively. Both convention-based sources name their own fragility: colliding crew names share a namespace, and a project checked out under `$HOME` misclassifies skills.

**Identity binding.** Letta links blocks to identities as external end-user keys (`identity_manager.py:419-452`) and derives hosted scopes from trusted `UserId` (agent-framework: `HostedFoundryMemoryProviderScopes.cs:28-31`). CrewAI's `source` is claimable free text; openhands has no multi-user model in this layer and hard-disables org skills (`skills-service.ts:54`). This is the sharpest library-vs-platform divergence: products that bill per user must bind memory to authenticated identity; libraries legitimately punt.

**Correction surfaces.** Ranked strongest to weakest: letta (surgical replace/patch/rethink + undo/redo + REST PATCH + hard delete with vector mirroring), agent-framework harness file memory (read-before-edit, replace, delete topic, consolidate) but asymmetric elsewhere (Python Mem0 has no delete/update at all — verified by grep), crewai (`update()` re-embeds, consolidation corrects near-duplicates, but all paths fall back to insert on LLM failure), openhands (none for memory notes; toggle-off is the only remedy).

**Freshness strategy.** Four different bets: crewai ranks recency with a 30-day half-life decay but never deletes (and scores on `created_at`, leaving `last_accessed` written-but-unused — `lancedb_storage.py:339-359`); agent-framework ages content only through gated LLM consolidation and debounced incremental sync cursors; letta decorates search results with `time_ago` strings and forbids relative dates in persisted memory (`core_tool_executor.py:186-227`; `sleeptime_v2.py:17-20`); openhands freezes the public catalog at build time (`skills-service.ts:26-33`). None expires mechanically.

**Where memory physically lives.** Local-first project disk (crewai LanceDB/Qdrant Edge), server databases as canonical state (letta PostgreSQL+pgvector with optional Turbopuffer/Git mirrors), external SaaS services behind adapters (agent-framework Mem0/Foundry/Cosmos/Redis), and browser/server split with content server-side (openhands). Each matches deployment shape: CLI/dev-tool, hosted product, framework integrators, web IDE.

## Tradeoffs

- **Uniform SPI vs backend depth.** Agent-framework's common contract keeps agents portable, but correction semantics fragment per backend (rich in harness/file memory, nonexistent in Python Mem0) and Python/.NET disagree on retrieval-scope defaults — porting becomes a leak risk. CrewAI's opposite bet (one unified memory) buys consistent semantics and introspection at the cost of specialized retrieval behavior per memory type.
- **Fail-open retrieval vs fail-loud corruption.** Agent-framework logs memory-retrieval errors and continues ("non-critical", `_memory_provider.py:181-183`) while quarantining unreadable snapshots (`_sessions.py:1955-1978`); crewai emits `MemorySaveFailedEvent` instead of raising (`unified_memory.py:324-363`). Agents never die from memory hiccups, but total retrieval outages degrade silently — Mem0 logs "unable to verify memory state" when *all* partition searches fail yet still proceeds (`_context_provider.py:227-228`). Letta takes the opposite bet exactly once and it hurts: non-strict Turbopuffer write failures leave passages invisible to vector search indefinitely, with no reconciliation job (`passage_manager.py:629-632`).
- **Model-writable memory vs approval friction.** Agent-framework registers `write_memory`/`delete_memory_topic` with `approval_mode="never_require"` for speed, trading away a HITL checkpoint on persistent-state mutation; letta gates the same capability with read-only flags and structural guards instead of approvals. Both are coherent; mixing them carelessly is not.
- **Sharing vs lifecycle coupling.** Letta blocks survive detachment as org-visible objects (`core_tool_executor.py:778-806`) — reuse wins, but "delete my memory" from one agent removes nothing others reference. CrewAI's `/crew/{name}` auto-namespacing has the same shape one level down: convenient, collision-prone.
- **Opt-in privacy vs learning value.** OpenHands defaults memory off (`default: false`) — maximally non-creepy, but enabled users cannot audit what was remembered. CrewAI's `private` flag is filter-only after fetch: private records stay fully readable to anyone opening the store (`unified_memory.py:746-751`), and the recall-filter path lacks dedicated tests.
- **Availability-over-accuracy on curation.** CrewAI persists even when analysis fails, storing the raw blob if extraction breaks (`analyze.py:159-162, 191-197`); memory never blocks work, but mis-scoped bloat accumulates and correctness is LLM-dependent everywhere it matters.

## Decision Guide

Choose an approach model by constraint, not preference:

- **Building a framework/harness where users bring their own stores** → agent-framework's extension-point pipeline. Define one narrow two-phase contract, make retrieval scopes explicit and non-inheriting, stamp attribution on injected content. Do not ship a canonical store.
- **Building a dev-tool/CLI where one team owns both code and storage** → crewai's unified curated store with hierarchical path scopes. Accept convention-based tenancy; add identity binding before multi-user use.
- **Building a hosted multi-tenant product** → letta's platform model: memory as DB entities, tenancy enforced in the data-access layer by default, identities bound to memory objects, per-tenant physical namespaces in every backing store including vector and object storage.
- **Owning only a control-plane layer over someone else's memory service** → openhands' pattern: typed clients only, schema-driven settings, opt-in default-off flag, deny-list soft-disable, regression-test the secret channels. Demand a memory-content CRUD API from the owning team early.

Decision rules within a chosen model:

1. **If more than one principal can write under one namespace**, adopt P2 (storage/retrieval scope separation) regardless of stack — and test non-inheritance explicitly, as agent-framework does.
2. **If the model can write memory**, adopt P7 guards (read-only flags, uniqueness-checked replacement, attribution) before shipping; decide the approval policy consciously rather than inheriting a default.
3. **If memory volume exceeds prompt budget**, choose between letta-style bounded in-context tiers and agent-framework-style progressive disclosure; do not mix unbounded injection with a large corpus.
4. **If you dual-write SQL + vector stores**, either make strict-mode the default for interactive writes (letta's lesson) or schedule reconciliation — log-and-continue guarantees invisible drift.
5. **If you need erasure (GDPR-style)**, verify a real delete path exists end-to-end first: agent-framework's managed-store erasure depends entirely on backing services; crewai has `forget()`/`reset()`; letta has cascading hard deletes with known uneven edges (dangling block-history actors, `block_history.py:34-37`); openhands' layer has none.

## Practical Tips

- **Make the safe thing the default.** Agent-framework's no-default-retrieval scope costs a little setup friction and buys categorical cross-user leak prevention; .NET's inherit-by-default is simpler and is exactly the divergence flagged as a porting hazard.
- **Persist attribution, not just content.** Origin session ids (agent-framework), actor-attributed checkpoints and git authorship (letta) cost one column each and enable audit, undo, and attack forensics later.
- **Gate durability behind your egress policy.** Treating memory writes as data egress (agent-framework `_RunPersistenceGate`, `_sessions.py:1078-1085`) closes the "denied content became durable" hole that most designs never consider.
- **Frame retrieved memory as untrusted input.** Cosmos injects LLM-generated summaries as delimited untrusted reference information specifically to close stored-prompt-injection (`_context_provider.py:385-412`); crewAI concatenates recalled records straight into prompts with no sanitization (`lite_agent.py:616-625`) — do the former.
- **Write freshness metadata even without expiry.** `updated_at` + contributing session ids on topics (agent-framework), `time_ago` decoration (letta), `last_accessed` touching (crewai) are cheap now and are prerequisites for any future TTL policy. Note crewai's cautionary tale: it touches `last_accessed` but nothing consumes it for scoring.
- **Test the scoping negatives, not just positives.** Agent-framework's `test_other_users_memories_are_not_retrieved` style assertions (`test_mem0_context_provider.py:449`) are what turn a scoping design into a guarantee. CrewAI's untested private-flag filter shows how enforcement code without CI coverage stays unverified.
- **Quarantine, don't trust, corrupted persistence.** Atomic writes + `.corrupt` quarantine + version validation (agent-framework `FileSessionStore`) beat both silent truncation and crash-on-load.
- **Give installs/updates visible seams.** OpenHands detects skill installs by pattern-matching bash output — clever but brittle against installer wording changes; prefer server acks where available.

## Anti-Patterns / Caution Signs

- **Convention-only tenancy at multi-user scale.** Path-string scopes sharing one physical table (crewai), home-dir regex classification (openhands `skill-scope.ts:21-77`), or flat scope strings with no org hierarchy (all four sources lack a first-class organization tier except letta) — each source documents its own misclassification scenarios. Caution sign: scoping logic that grows regexes to compensate for missing structure.
- **Correction asymmetry across backends.** If deleting a fact requires different mechanisms per store — or out-of-band console access, as with Python Mem0 — the memory system will accumulate wrong facts. Caution sign: "you can clear it via the vendor dashboard" appearing in docs.
- **Prompt-driven hygiene.** Letta's staleness control is instructions to the sleeptime agent ("do not write 'today'", cleanup directives); correctness now depends on model compliance with zero mechanical backup. Caution sign: freshness policies living only in prompt text.
- **Log-and-continue dual-writes.** Silent partial indexing (letta Turbopuffer failures, `passage_manager.py:629-632`; agent-framework Foundry fire-and-forget updates) produces memories that exist canonically but can't be found semantically. Caution sign: no reconciliation story mentioned anywhere in the repo.
- **Filter-after-fetch privacy.** Private records remaining plaintext and serialization-visible (crewai) means "privacy" is one missed filter away from exposure. Caution sign: privacy implemented exclusively as post-query predicate.
- **All-or-nothing memory controls.** OpenHands' only remedy for poisoned memory notes is disabling memory globally — users rationally respond by leaving it off. Caution sign: a memory system whose only off-switch is also its only steering wheel.
- **Build-time knowledge snapshots.** Frozen public catalogs require release cycles for knowledge updates (openhands `skills-service.ts:26-33`) and mid-conversation installs stay inert (`skill-install-events.ts:22-28`). Caution sign: "requires rebuild" as the documented update path for knowledge.
- **Unbounded per-record limits without lifecycle.** Letta's 100k-char default block limit plus embedding padding to dim 4096 simplifies schemas while allowing single records to dominate context and storage (`constants.py:435`; `passage.py:49-77`).

## Notable Absences

Evidence-backed absences that held across multiple sources:

- **No TTL/expiry mechanism anywhere.** Agent-framework: "no provider implements TTL or expiry"; crewai: decay sinks ranking but removal requires manual `forget(older_than=...)`; letta: searched for TTL/cron/decay patterns, only sleeptime scheduling exists; openhands: localStorage blobs have no GC beyond explicit removal calls. Staleness is possible everywhere and guaranteed absent active maintenance.
- **No first-class organization/global scope in the library-shaped sources.** Agent-framework explicitly searched and found none beyond flat application tagging; crewAI's `/company/*` examples are doc-level conventions; openhands has org skills server-side but hard-disabled client-side. Only letta models organizations as data.
- **No automated PII handling in memory pipelines.** Letta searched redact/anonymize/pii across services — none; crewai disclaims encryption/redaction; agent-framework relies on backend controls and documents plaintext posture in-code (`_sessions.py:1886-1898`).
- **No memory-quality evaluation.** Nothing in letta measures whether persisted memories stay accurate; crewAI's consolidation outcomes are transient counters not observable records; no source ships accuracy benchmarks.
- **No reconciliation for dual-store drift.** Letta's SQL↔Turbopuffer gap has no repair job; agent-framework's Mem0 eventual-consistency window is handled by a hardcoded sleep in samples (`mem0_basic.py:64-69`).
- **No encryption-at-rest owned by the frameworks themselves** — delegated to OS permissions (agent-framework file stores), backend services (.NET XML docs), or absent (crewai).
- **No cross-device continuity for client-tier memory** (openhands localStorage is explicitly device-local and labeled disposable).

## Per-Source Notes

- **agent-framework (7/10):** The most governance-conscious source. One SPI (`ContextProvider`), five backends, explicit non-inheriting retrieval scopes with 48 focused scoping tests, origin attribution, egress-gated durability, corrupt-snapshot quarantine, and consolidation windows that refuse to advance on failure. Held back by missing Python-Mem0 delete/update, absent TTL, experimental markers, and the Python/.NET scope-default divergence.
- **crewai (8/10):** The most complete write/read *pipeline*. Unified `Memory` with LLM-analyzed encoding (dedup ≥0.98, consolidation plans), adaptive-depth recall with confidence routing and evidence-gap propagation, composite scoring with 30-day recency half-life, cross-process file locks and commit-conflict retries — all tested, including a ~40-case root-scope suite. Held back by shallow filter-only privacy, claimable `source` identity, untested private-flag recall, and O(table) scans capped at 50k rows.
- **letta (8/10):** The most mature *data model*. Four tiers with schemas and REST surfaces, org tenancy in the ORM base, blocks as shared pivot-table objects, edit-safety guards (read-only, uniqueness, line-number stripping, version column), actor-attributed undo/redo, optional git-as-source-of-truth. Held back by prompt-only freshness, log-and-continue vector drift with no reconciliation, a multi-archive search limitation, mid-deprecation scope fields, and warning-only actor-less read bypass.
- **openhands (6/10):** A clean control-plane slice: opt-in default-off memory toggle with pinned persistence diffs, typed-client discipline enforced by CI guard, project/personal/public skill scopes, tested deny-list enforcement on two launch paths, actively-tested secret-channel isolation. Scored lowest because the layer cannot list, view, edit, or delete the `.openhands/memory/` content it enables, and scope classification rests on fragile path heuristics.
