## Executive Summary

Nine sources spanning agent libraries (agent-framework, crewai, langgraph, pydantic-ai, openai-agents-sdk), an agent server (letta), an agent frontend (openhands), a policy engine designed for unattended operation (opa), and a workflow orchestration server (temporal) were compared on when each system retries, asks the user, escalates to a human, or stops.

The convergent core model is remarkably consistent: **automatic retry is reserved for provably transient transport faults under bounded budgets; tool-level failures are converted into model-visible content so the LLM self-corrects instead of the framework blindly re-invoking; escalation to humans is a first-class control-flow category that is structurally distinct from failure; and stopping is engineered as a graceful outcome rather than a crash**. Equally consistent is what nobody builds: not one source ships push-based human notification (email/chat/pager). Escalation delivery is always delegated outward — to orchestrators (opa, temporal), embedding applications (the libraries), event-bus consumers (crewai), or webhook receivers whose failures letta deliberately swallows (`letta:letta/services/run_manager.py:504-508`).

The sources diverge most on three axes, and the divergence tracks product shape rather than quality: (1) **durability of escalation state** — temporal, langgraph, agent-framework, and crewai flows persist pending human decisions across crashes, while in-process libraries hand serializable state objects to the app; (2) **classification discipline** — temporal and openai-agents-sdk make retry-vs-stop an explicit typed decision, while crewai's agent layer retries any non-litellm exception including programming bugs (`crewai:lib/crewai/src/crewai/agent/core.py:731-747`) and langgraph's default retries *unknown* exceptions broadly (`langgraph:libs/langgraph/langgraph/_internal/_retry.py:28-29`); (3) **auditability** — temporal gets it for free from event sourcing (`temporal:service/history/historybuilder/event_factory.go:351-374`), while openhands relies on consent-gated telemetry and openhands/agent-framework keep audit structures in memory or localStorage.

Ratings cluster in the 7–9 band. The two 9s (openai-agents-sdk, pydantic-ai) win on taxonomy clarity and fail-closed replay safety, not retry sophistication.

## Core Thesis

Recovery-vs-escalation maturity is not a property of having a good retry helper — every source has one. It is a property of three discipline choices:

1. **A strict taxonomy that keeps four categories separate**: retryable transient faults, model-correctable faults, decisions requiring a human, and termination. The strongest sources encode this in types, not conventions: temporal's `RetryState` enum distinguishes "stopped because non-retryable" from "stopped because budget exhausted" from "stopped because deadline passed" (`temporal:service/history/workflow/retry.go:41-111`); pydantic-ai gives recovery, terminal reporting, and escalation distinct exception classes with different routing (`pydantic-ai:pydantic_ai_slim/pydantic_ai/exceptions.py:57-183`); langgraph's `GraphBubbleUp` base makes interrupts/drains structurally unable to enter the retry or error-handler paths (`langgraph:libs/langgraph/langgraph/pregel/_runner.py:224-226`).
2. **Every loop bounded, every exhaustion defined.** The failure mode is never "retry forever" by accident — even systems that retry indefinitely by default (opa, temporal, openhands websockets) do so as a documented design stance with external escalation surfaces, and the weakest spots in strong sources are exactly where a bound or an exhaustion semantic is missing (temporal's ambiguous `MaximumAttempts=0`, flagged by TODO at `temporal:service/history/workflow/retry.go:29`; openhands' WS reconnect defaulting to `Infinity` attempts, `openhands:src/hooks/use-websocket.ts:113-114`).
3. **Escalation state is durable state.** A pause-for-human must survive process death like any other checkpoint: agent-framework checkpoints pending HITL requests (`agent-framework:python/packages/core/agent_framework/_workflows/_agent_executor.py:320-337`), langgraph persists INTERRUPT writes (`langgraph:libs/langgraph/langgraph/pregel/_runner.py:574-613`), openai-agents-sdk serializes the entire run into `RunState` (`openai-agents-sdk:src/agents/run_state.py:1704`), crewai auto-persists pending flow feedback to SQLite (`crewai:lib/crewai/src/crewai/flow/persistence/sqlite.py:31-51`). Systems that treat escalation as ephemeral (or as a blocking modal) cap out at interactive-only use.

The corollary: **auditability of recovery decisions is best achieved architecturally, not by adding an audit log**. Temporal stamps the retry decision into immutable history events; langgraph writes errors/interrupts as checkpointed pending writes retrievable via `CheckpointTuple.pending_writes`; pydantic-ai makes the transcript itself the audit log via `RetryPromptPart` and typed tool outcomes. Bolt-on audit lists (agent-framework's in-memory `security.py` audit log) are the weak form of the same idea.

## Approach Models

**agent-framework — layered decision ladder keyed by failure class.** Tool exceptions become `function_result` contents with `exception=` set so the LLM decides whether to correct arguments (`agent-framework:python/packages/core/agent_framework/_tools.py:1412-1434`); consecutive-error (default 3) and iteration (default 40) caps end in one final text-only generation with `tool_choice="none"` instead of crashing (`_tools.py:3307-3313`); approval requests are content types that park workflows in `IDLE_WITH_PENDING_REQUESTS`; ordinary middleware exceptions fail open into model-visible results while `MiddlewareFailure` is the single fail-closed escape that cancels sibling calls (`_middleware.py:85-114`).

**crewai — stack of independent retry loops with no central engine.** Provider clients own transport retries (`max_retries=2` defaults, `crewai:lib/crewai/src/crewai/llms/providers/openai/completion.py:223`); the agent layer re-executes whole tasks up to `max_retry_limit` (default 2) for anything not explicitly excluded; guardrails get their own budget (default 3) that re-prompts with validation errors; context overflow is recovered by summarization. Escalation exists only implicitly — "raise to caller" or "ask a human via a `HumanInputProvider`"; the word escalation appears nowhere in the codebase.

**langgraph — recovery compiled into the graph.** Per-node `RetryPolicy` (backoff, jitter, ordered first-match chains) wraps task execution (`langgraph:libs/langgraph/langgraph/pregel/_retry.py:573-683`); exhausted retries escalate in-process to developer-authored error-handler nodes compiled as hidden graph nodes that survive resume via persisted `ERROR_SOURCE_NODE` markers (`_loop.py:751-812`); humans are reached through `interrupt()` or static breakpoints; cooperative drain stops at superstep boundaries with the checkpoint saved (`runtime.py:95-104`).

**letta — exception-typed layers beneath a mandatory stop-reason taxonomy.** Every exit declares one of 12 stop reasons deterministically mapped to run statuses — notably `requires_approval` maps to *completed*, making pause-for-human look successful to schedulers (`letta:letta/schemas/letta_stop_reason.py:9-49`). Below that, provider errors normalize into a typed hierarchy via `handle_llm_error` so loops decide retry purely by `isinstance` (`letta:letta/llm_api/openai_client.py:1216-1420`); context overflow triggers compaction-and-retry up to a configurable ceiling; the v3 loop can fail over to fallback models via a circuit-breakered router.

**opa — unattended-service contract: absorb, preserve, externalize.** All remote interactions retry forever with jittered exponential backoff from one shared primitive (`opa:v1/util/backoff.go:14-43`); failed activations abort their storage transaction leaving last-known-good policy serving, with the previous ETag restored so re-sync works (`v1/plugins/bundle/plugin.go:516-519`, `v1/storage/storage.go:95-108`); process exit (or deliberate panic) is reserved for boot failures and consistency-invariant violations (`v1/runtime/runtime.go:651-689`, `v1/plugins/bundle/plugin.go:220-224`); humans are reached through status snapshots, health endpoints, and metrics consumed by orchestrators.

**openai-agents-sdk — centralized decision gate with composable policies and hard vetoes.** One function, `_evaluate_retry`, decides all transport retry with three deliberately separate fail-closed replay vetoes (abort-like errors, already-emitted stream output, replay-unsafe/stateful requests) that application policy cannot override (`openai-agents-sdk:src/agents/run_internal/model_retry.py:419-479`); tool failures are never retried programmatically but formatted into model-visible messages via `failure_error_function`; authorization-driven pauses surface as `NextStepInterruption` with full `RunState` serialization and approve/reject APIs.

**openhands — two-tier error lifecycle in the UI.** Connection errors auto-clear on recovery and are backed by bounded/unbounded automatic retry (backoff+jitter, watchdogs); conversation errors are sticky until an explicit human action (`openhands:src/stores/error-message-store.ts:4-9,62-65`). Auth failures skip probe retries specifically so the escalation UI appears faster ("a decided server response, not a transient miss", `src/hooks/query/use-backends-health.ts:160-171`). Human gating is an execution status (`WAITING_FOR_CONFIRMATION`) rendered inline, with the actual policy computed client-side but enforced server-side (`NeverConfirm`/`AlwaysConfirm`/`ConfirmRisky(HIGH)`, `src/api/agent-server-adapter.ts:593-605`).

**pydantic-ai — five independent budgets navigated by exception type.** Docs map transport, model-fallback, tool, output, and hook retry layers that "don't share budgets" (`pydantic-ai:docs/retries.md:5-15`). `ModelRetry` asks the model to correct; `ToolFailed` reports terminally without consuming budget; `ApprovalRequired`/`CallDeferred` end the run with a `DeferredToolRequests` output resolved in a later run; `UsageLimitExceeded`/`UnexpectedModelBehavior` stop. Deterministic failures are injected into Temporal's `non_retryable_error_types` so engine retries cannot mask permanent bugs (`pydantic-ai:pydantic_ai_slim/pydantic_ai/durable_exec/temporal/_toolset.py:156-170`).

**temporal — typed decision machine with application-code escalation.** One canonical function returns a `RetryState` enum, never a boolean (`temporal:service/history/workflow/retry.go:31-112`); exhaustion appends a terminal history event stamped with the retry state and wakes the owning workflow so *application code* chooses remediation (`service/history/api/respondactivitytaskfailed/api.go:105-121`). Human controls are separate, idempotent operator APIs — pause/unpause/reset/terminate — plus visibility queries over `FailedWorkflowStatuses`. Internal RPC uses a second regime where `ResourceExhausted` retries indefinitely under a slow throttle lane without counting against caller policies (`common/backoff/retry.go:15-60`).

## Pattern Catalog

### P1. Model-visible failure feedback (self-correction instead of tool retry)

- **Problem:** Automatically retrying a failed tool risks duplicating side effects and bypasses the entity that can actually fix bad arguments.
- **Sources:** agent-framework (`_tools.py:1412-1434`, stated intent at `python/samples/02-agents/tools/function_tool_recover_from_failures.py:17`), pydantic-ai (`ModelRetry` → `RetryPromptPart`, `exceptions.py:57-97`), openai-agents-sdk (`failure_error_function`, `tool.py:1863-1872`), letta (error-status tool returns, `tool_execution_manager.py:143-155`), langgraph prebuilt (`ToolNode.handle_tool_errors` → `ToolMessage`, `tool_node.py:674-687`), crewai (parse errors appended to history, `agent_utils.py:763-778`).
- **Why it works:** the failure becomes conversational data; the model can adjust arguments, choose another tool, or give up — and the framework's budget counters bound how long it may try.
- **Copy when:** failures are argument-shaped, validation-shaped, or otherwise interpretable by the model.
- **Risky when:** failures are infra-transient (flaky network) — then model-mediated "retry" burns expensive round-trips; openai-agents-sdk notes applications wanting cheap programmatic tool retry must implement it inside the tool. Also gate detailed error text (agent-framework defaults detail off to resist prompt injection via error content, `_tools.py:1426-1428`).

### P2. Typed control-flow category separate from failure

- **Problem:** If "pause and ask a human" travels the exception path, it gets retried, logged as an error, or swallowed by generic handlers.
- **Sources:** langgraph (`GraphBubbleUp` bypasses retry and error handlers, `_runner.py:224-226,299-300`), pydantic-ai (`ApprovalRequired`/`CallDeferred` treated as neither errors nor retries, `tool_manager.py:466-490`), crewai (`HumanFeedbackPending` documented "not an error, a control flow signal", returned as a value, `async_feedback/types.py:148-172`), letta (`requires_approval` → completed status, `letta_stop_reason.py:30-32`), openhands (`WAITING_FOR_CONFIRMATION` execution status, `use-agent-state.ts:24-25`), openai-agents-sdk (`NextStepInterruption`, not an exception), agent-framework (approval content types flow through the normal Content pipeline).
- **Why it works:** schedulers, UIs, and retry engines can treat waiting-for-human as healthy; crewai even emits `MethodExecutionPausedEvent` instead of `MethodExecutionFailedEvent` (`flow/runtime/__init__.py:2948-2987`).
- **Copy when:** always, for any human-in-the-loop mechanism.
- **Risky when:** the distinction erodes — e.g., temporal currently reports paused activities as `RETRY_STATE_IN_PROGRESS`, blurring "human-frozen" from "actively backing off" (`mutable_state_impl.go:6925-6927`).

### P3. Bounded loops with graceful degradation to a final answer

- **Problem:** Runaway agents burn money; crashing on a budget denies the user any output.
- **Sources:** agent-framework (error/iteration/call budgets each force one final tool-free response, `_tools.py:3299-3313`), crewai (`max_iter` → forced final answer, `agent_utils.py:363-433`), letta (`max_steps` stop reason → completed, `letta_agent_v2.py:408-409`), openai-agents-sdk (`max_turns` + pluggable error handlers converting terminal errors into schema-*validated* fallback outputs, `run_error_handlers.py:36-55`), langgraph (recursion limit sets `out_of_steps` before raising, `_loop.py:606-609`), pydantic-ai (usage limits checked before requests, after responses, and before tool calls, `usage.py:492-560`).
- **Why it works:** the user gets an answer plus an explanation; the run ends in a defined state.
- **Copy when:** any autonomous loop. openai-agents-sdk's variant — validating handler-produced fallbacks against `output_type` and running output guardrails — is the most rigorous form (`error_handlers.py:170-205`).
- **Risky when:** degradation masks root causes; pair with visible diagnostics (langgraph attaches a troubleshooting link to `GraphRecursionError`).

### P4. Durable persistence of pending escalations

- **Problem:** A process restart must not orphan an open question to a human.
- **Sources:** agent-framework (pending HITL requests inside workflow checkpoints, `_agent_executor.py:320-337`), langgraph (INTERRUPT pending writes, `_runner.py:585-591`), openai-agents-sdk (`RunState.to_json/from_string` with sticky approval decisions surviving serialization, `run_state.py:1704,1300-1314`), crewai (SQLite-backed pending feedback with regression-tested resumption, `persistence/sqlite.py:31-51`), letta (approval message persisted immediately "to prevent agent from getting into a bad state", `letta_agent_v2.py:636-646`), pydantic-ai (resume keyed by message history + `DeferredToolResults` matched by `tool_call_id`).
- **Why it works:** escalation latency becomes unbounded-by-design; the system tolerates hours-long human response times.
- **Copy when:** any HITL beyond a synchronous CLI.
- **Risky when:** resume matching is fragile — langgraph's nested interrupts match positionally (`types.py:866-868`), which breaks if node code changes between interrupt and resume; pydantic-ai rejects duplicate IDs and marks already-executed calls to prevent ambiguity (`_agent_graph.py:660-705`).

### P5. Replay-safety vetoes around side effects

- **Problem:** Retrying a request whose side effects may have landed duplicates work.
- **Sources:** openai-agents-sdk (three separate fail-closed vetoes + distinct `approve_unsafe_replay` consent channel, `model_retry.py:442-479`, `retry.py:116-133`), agent-framework (lost MCP task-create before task-id known is *never* re-sent, tested at `tests/core/test_mcp.py:7148-7177`; indeterminate AG-UI occurrences retained for a safety window), langgraph (`task.writes.clear()` per attempt so partial updates never leak into retries, `_retry.py:613-615`; failed tasks excluded from cache, `_loop.py:1864-1884`), temporal (stale-attempt guards drop superseded timers, `timer_queue_active_task_executor.go:297-300`), crewai (dedicated test proving deliberate aborts survive `max_retry_limit`, `test_tool_failure.py:689-704`).
- **Why it works:** idempotency is treated as evidence-based (provider marks safe / task acknowledged) rather than assumed.
- **Copy when:** any retry crossing a side-effectful boundary.
- **Risky when:** veto logic sprawls — openai-agents-sdk needs dense comments explaining why the three vetoes stay unfused.

### P6. Externalized escalation via observability surfaces

- **Problem:** Unattended services cannot ask a human directly.
- **Sources:** opa (status service POSTs, `/health?plugins` probes, custom Rego health policies, Prometheus drop counters — `status/plugin.go:497-509`, `server/server.go:1299-1416`), temporal (visibility queries over `FailedWorkflowStatuses` + metrics; explicitly no paging, searched case-insensitively for pager/oncall/alert — zero functional hits).
- **Why it works:** keeps the core clean and lets orchestrators own restart/page decisions; OPA's readiness latch ("ready = has been healthy at least once", `server/server.go:1363-1378`) prevents readiness flapping.
- **Copy when:** building a daemon/platform.
- **Risky when:** nobody consumes the surfaces — both reports flag that out-of-the-box failure→human latency is effectively unbounded.

### P7. Classify-before-retry (decided failures never retried)

- **Problem:** Retrying permanent failures delays the inevitable and hides bugs.
- **Sources:** openhands (auth errors skip probe retries so recovery UI shows sooner, `use-backends-health.ts:160-171`), temporal (`NonRetryableErrorTypes`, canceled/terminated and schedule-timeouts never retried, `retry_policy.go:27-64`), langgraph (`default_retry_on` refuses ValueError/TypeError-class errors, `_internal/_retry.py:1-29`), letta (`LLMError` subclasses other than overflow re-raised immediately, `letta_agent_v2.py:559-561`), pydantic-ai (Temporal integration marks `UserError`/`UnexpectedModelBehavior` non-retryable), agent-framework (`MiddlewareFailure` never becomes a tool result).
- **Why it works:** fast, truthful escalation beats hopeful retries; crewai's inverse shows the cost — coding errors in callbacks consume the full retry budget silently (`agent/core.py:731-747`).
- **Copy when:** always define the non-retryable set explicitly.
- **Risky when:** classification relies on string matching against provider messages — letta's centralized substring heuristics are tested but inherently fragile against wording changes (`error_utils.py:16-41`).

### P8. Counter accounting that resets and stays observable

- **Problem:** Cumulative counters false-trip on long healthy runs; invisible counters hide spend.
- **Sources:** agent-framework (consecutive-error counter resets on success, tested at `test_function_invocation_logic.py:3798-3850`), pydantic-ai (per-tool-name reset-on-success budgets; hallucinated tool names get their *own* budget so one bad name can't exhaust another tool's allowance, `tool_manager.py:496-517`), openai-agents-sdk (failed attempts recorded as zero-token usage entries so retry counts appear in usage, `model_retry.py:338-350`), temporal (attempt tracking with stale-fire dropping), crewai (per-attempt event scoping keeping traces balanced, `agent/core.py:733-734`).
- **Copy when:** any retry budget longer than one attempt.
- **Watch:** pydantic-ai documents the flip side — a tool failing intermittently can fail unboundedly within the run-level request limit since its counter keeps resetting (`docs/retries.md:35`).

### P9. Watchdogs and circuit breakers converting hangs into decisions

- **Problem:** Timeouts that never fire leave runs stuck invisibly; infinite polling hammers dead infrastructure.
- **Sources:** openhands (10s handshake watchdog force-closing stuck sockets, `websocket-handshake.ts:17-25`; 150s pending-message watchdog flipping bubbles to retryable errors; persisted 5-failure circuit breaker, `health-storage.ts:10`), langgraph (run/idle timeout watchdogs refreshed by token streaming, `_retry.py:422-517`), letta (event-loop hang watchdog with self-validation script and multi-source readiness gating, `event_loop_watchdog.py:26-206`, `readiness_state.py:63-84`), temporal (workflow-task start-to-close deadline self-widening after 3 failures to avoid thrashing, `workflow_task_state_machine.go:1465-1489`).
- **Copy when:** any component can hang without raising.
- **Risky when:** watchdog conversion produces false positives — openhands' 150s flip can mark a still-processing send as errored, inviting double delivery (mitigated by echo-content dedup).

### P10. Substitution as recovery (fallback models)

- **Problem:** A degraded provider shouldn't fail the run if an equivalent exists.
- **Sources:** pydantic-ai (`FallbackModel` walks configured models while `_should_fallback(exc)` holds, aggregating all failures into `FallbackExceptionGroup`; rejected-response costs accumulate onto the winner so spend stays observable — `models/fallback.py:229-318,296-307`), letta (v3 loop consults a fallback-handle router recording circuit-breaker success/failure signals, `letta_agent_v3.py:1171-1211`).
- **Copy when:** multi-provider setups exist and failure classification can distinguish provider-wide faults.
- **Risky when:** fallback masks systematic issues (e.g., a malformed request that will fail everywhere); pydantic-ai handles this by letting `fallback_on` include response-quality handlers, not just exceptions.

## Key Differences

**Central decision gate vs layered autonomy.** openai-agents-sdk funnels all transport retry through `_evaluate_retry` and coordinates with hidden SDK retries so budgets don't multiply invisibly (`model_retry.py:516-554`); temporal likewise funnels through one function returning a typed state. By contrast, crewai and letta distribute budgets across layers that don't coordinate: crewai's worst case is `guardrail_max_retries × (max_retry_limit + 1)` full task executions for one user-visible failure; letta's overflow defense spans four levels with triplicated implementations drifting between loop generations. The central-gate design costs complexity up front (three coexisting retry layers in openai-agents-sdk) but prevents compounding; the layered design is easier to reason about locally and harder globally.

**What gets retried by default.** This is the sharpest divergence. langgraph's `default_retry_on` returns True for *unknown* exceptions (availability-first, can mask bugs); crewai retries everything except litellm-originated errors and declared aborts (bugs included); temporal defaults to *unlimited* attempts (`MaximumAttempts=0`); opa retries remote I/O forever by design. Against these, pydantic-ai defaults tool retries to **1**, openai-agents-sdk makes runner-managed retry strictly opt-in, and letta fail-fasts on most `LLMError` subclasses. The pattern: platforms optimizing for liveness of long-lived services retry generously; libraries closer to developer iteration loops default conservatively so bugs surface immediately.

**Where the human sits.** Interactive harnesses put the human in the process (openhands' inline confirm buttons with keyboard shortcuts; crewai's console-default stdin providers — ideal for CLIs, useless for servers). Libraries emit protocol objects and trust the app (pydantic-ai `DeferredToolRequests`, openai-agents-sdk `result.interruptions`). Platforms push structured signals outward and pull decisions back through APIs (letta's REST approval toggle per agent+tool; temporal's pause/reset/terminate endpoints; opa's health/status read by Kubernetes). None of the nine notifies proactively; the closest is openhands' local sound/tab-title attention notification (`use-agent-notification.ts:6-10`).

**Audit architecture.** Temporal derives an append-only audit trail from event sourcing — the retry decision and the retry-run lineage (`NewExecutionRunId`) are history facts (`event_factory.go:351-374`). langgraph checkpoints `(ERROR, exc)`/`(INTERRUPT, ...)` writes. pydantic-ai persists decisions as transcript parts. letta combines named OTEL events, stop reasons, run metadata, and callback-delivery columns. The weaker forms: agent-framework's security audit log is a plain in-memory list with no sink (`security.py:1698`); crewai's decisions live only in the event stream; openhands depends on consent-gated PostHog events plus validated localStorage; opa counts dropped log/status payloads but doesn't preserve them — "a burst of drops can lose the very evidence needed to audit them."

**Graceful-stop vocabulary.** agent-framework and crewai converge on "one more model call with tools disabled." letta formalizes it as a stop-reason enum. openai-agents-sdk adds recoverable terminal errors via validated handler outputs. langgraph offers drain-at-boundary semantics safe from any thread. opa traps SIGTERM with configurable shutdown periods. These are complementary responses to the same requirement; the enum-based version (letta, temporal's RetryState) is the most operationally legible because downstream consumers can branch on declared outcomes.

## Tradeoffs

- **Model-driven recovery vs deterministic retry.** agent-framework/pydantic-ai/openai-agents-sdk delegate tool-failure handling to the LLM, gaining flexibility at the cost of guaranteed pacing: a model stuck in an argument loop burns paid round-trips until the iteration cap (agent-framework default 40, `_tools.py:95`). CrewAI takes the opposite extreme — blind whole-task re-execution with no backoff — trading token cost and latency predictability for implementation simplicity. Temporal sits between: automatic retries with exponential curves, but only for infrastructure faults classified retryable.
- **Fail-open error surfacing vs debuggability.** agent-framework hides tool-error detail unless `include_detailed_errors=True` (`_tools.py:1426-1428`) — safer against prompt injection, harder to debug. Letta embeds full tracebacks and even full in-context message text in fatal compaction errors (`agent.py:1060-1067`) — maximally debuggable, potentially huge in logs. OpenAI Agents SDK redacts exception payloads at public boundaries unless sensitive tracing is on (`exceptions.py:159-215`).
- **Unbounded availability vs bounded correctness.** opa's retry-forever and temporal's unlimited-default keep services alive through prolonged outages but mean some failures never escalate beyond telemetry; langgraph's permissive unknown-exception retry favors availability but a persistent bug is retried `max_attempts` times before surfacing. pydantic-ai/openai-agents-sdk take the opposite bet: exhaust fast, terminate loudly.
- **Pause-as-success vs pause-as-pending.** Letta classifying `requires_approval` as `completed` makes schedulers happy but widens the state machine (completed runs can flip to cancelled, allowed explicitly, `run_manager.py:342-352`). LangGraph/openhands model pausing as a distinct status — more truthful, more states to handle.
- **Silent notification swallowing vs run integrity.** Letta deliberately swallows callback/webhook failures so notifications never affect run completion — protecting the run while leaving a human who depends on webhooks uninformed unless they poll (`run_manager.py:508`). OpenHands made the opposite call for auth failures: fail the retry fast to surface the escalation UI sooner.
- **Consistency vs availability at the invariant boundary.** OPA panics on deactivation that would leave inconsistent state, acknowledging in-code it "shouldn't panic" but continuing is worse (`plugin.go:220-224`); crewai's `SystemExit` on context overflow is the unconsidered version of the same trade — it kills embedding interpreters and bypasses telemetry (`agent_utils.py:824-832`).
- **Durable-first recovery vs serializable-state portability.** LangGraph/temporal/agent-framework persist recovery state server-side (works across processes, requires infrastructure); openai-agents-sdk/pydantic-ai serialize state objects the app must keep alive (portable, but the host owns durability — openai-agents-sdk mitigates with full `RunState.to_json`, pydantic-ai with message-history-keyed resume).

## Decision Guide

**Choosing a retry default posture:**
- Long-running unattended service → generous bounded retry + externalized escalation (opa/temporal model): classify failures, retry transient classes indefinitely at capped delay, expose status/health/metrics, and reserve process death for boot/invariant failures.
- Developer-facing library → conservative opt-in retry (openai-agents-sdk/pydantic-ai model): narrow default budgets (1–3), explicit non-retryable sets, loud terminal exceptions with remediation text.
- Either way: never retry unknown/unclassified exceptions by default — that is the specific weakness both langgraph (`default_retry_on`) and crewai exhibit.

**When to retry vs ask the model vs ask a human vs stop:**
- Transport/infra fault with proof of transience (connection reset, 429/5xx before any output emitted) → automatic retry with backoff+jitter, bounded budget, and replay vetoes.
- Argument/validation/parse failure → model-visible feedback with a guided correction prompt (enumerate valid alternatives — pydantic-ai's pattern at `_agent_graph.py:2026-2060`).
- Authorization, high-risk side effects, irreversible actions → human escalation, modeled as a distinct control-flow category, persisted durably.
- Budget exhaustion, usage-limit breach, refusal, invalid structured output → typed termination; optionally offer a validated fallback-output handler (openai-agents-sdk) or a forced final answer (agent-framework/crewai).

**Configuring escalation thresholds:**
- Prefer one policy object per layer over scattered constants (openai-agents-sdk's `ModelRetrySettings`, temporal's `RetryPolicy` proto validated at start time) over openhands-style scattered module constants or letta's mix of env vars and hardcoded function defaults.
- Make thresholds validated and namespace/scoped where multi-tenant (temporal's dynamic-config defaults with `retrypolicy.Validate` rejecting malformed policies at start time).

**Making recovery auditable:**
- If you have an event log/checkpoint store, write the decision there (langgraph/temporal) — do not maintain a parallel in-memory list (agent-framework's gap).
- Stamp *why* a retry stopped (non-retryable vs exhausted vs deadline), not just *that* it stopped — temporal's RetryState-in-events is the reference implementation.
- Persist notification delivery outcomes even if delivery itself is fire-and-forget (letta's `callback_status_code`/`callback_error` columns).

**Preserving escalation across crashes:**
- Checkpoint pending human-input requests atomically with conversation state (agent-framework), or serialize the whole resumable run (openai-agents-sdk), and add resume-integrity checks (reject duplicate/stale tool-call IDs — pydantic-ai).

## Practical Tips

**Patterns to copy:**
1. Give every failure site exactly one of four dispositions — retry, model-feedback, human-deferral, terminate — expressed in types (distinct exceptions/content types/enums), not string flags.
2. End every budget with a defined terminal behavior, ideally a graceful one (final answer, validated fallback, declared stop reason).
3. Add a reset-on-success semantic to cumulative error counters, and give hallucinated/dynamic entities their own budget keys (pydantic-ai).
4. Write replay vetoes as fail-closed defaults with a separate explicit consent channel for unsafe replay (openai-agents-sdk's `approve_unsafe_replay`).
5. Emit distinct paused vs failed signals everywhere humans wait; never route waiting through the error path.
6. Convert hangs into decisions with watchdogs, and persist circuit-breaker state across restarts (openhands).
7. Document what is *never* retried alongside what is (pydantic-ai's `docs/retries.md:127-132` closes the intuition/implementation gap).
8. Test the negative space: deliberate aborts must survive retry limits (crewai's `test_retry_limit_does_not_swallow_the_abort`), malformed approvals must re-pause rather than execute (openai-agents-sdk `test_hitl_error_scenarios.py:536-583`).

**Patterns to delay until needed:**
- Model-failover routing with circuit breakers (letta/pydantic-ai) — valuable only with real multi-provider deployments.
- Structured attempt-lifecycle observers (langgraph's internal timed-attempt observer) — start with logs plus usage-accounting tricks (zero-token entries).
- Rego/custom-policy health gates (opa) — plain `/health?plugins` suffices until fleet-scale.
- Approval lifecycle machines with retention windows and idempotency keys (agent-framework's AG-UI eight-state occurrence machine) — needed only for hosted/multi-client approval flows.

**Caution signs that the recovery design is going brittle:**
- Retry logic duplicated in multiple places (openhands' byte-identical `withRetry` copies; letta's v1/v2/v3 drift with a known "should be removed" hack).
- Distinct states collapsing in display layers (`STUCK` → `ERROR` in openhands; paused reported as in-progress in temporal).
- Thresholds living as unlabeled constants across files instead of one config surface.
- Exhaustion paths raising bare `Exception` or `SystemExit` (crewai guardrails/context-overflow) — unhandleable downstream.
- Audit trails that only exist behind consent flags, in-memory lists, or lossy buffers.
- Compounding budgets no one can compute (crewai's guardrail×agent multiplication).
- Notification paths whose failures are swallowed with no retry and no surfaced record.

## Anti-Patterns / Caution Signs

- **Blind whole-task retry without classification** (crewai): any non-litellm exception — including programming bugs — consumes the full `max_retry_limit`, with no backoff, because classification excludes only two classes (`agent/core.py:731-747`).
- **Permissive default retry of unknown exceptions** (langgraph `default_retry_on`, `_internal/_retry.py:28-29`): availability-first, but persistent bugs get masked for `max_attempts` rounds before surfacing.
- **Ambiguous unlimited defaults**: temporal's `MaximumAttempts=0` meaning infinity, flagged by standing TODO ("treat 0 as 0, not infinite", `retry.go:29`); opa's unconditional retry-forever; openhands' WS `maxAttempts` defaulting to Infinity while every other path is bounded.
- **Silent state collapse**: openhands mapping `STUCK` to `ERROR` with only an inline comment (`use-agent-state.ts:30-31`) removes the trigger for a distinct recovery affordance.
- **Notification paths that fail silently** (letta webhooks/callbacks swallowed, `webhook_service.py:48-55`): the escalation channel itself has no recovery path.
- **Graceless stop edges**: `SystemExit` on context overflow and bare `Exception` from exhausted guardrails (crewai) sacrifice programmatic handleability; contrast letta/openai-agents-sdk where every exit carries a typed reason and remediation text.
- **String-heuristic failure classification** (letta's substring matching for overflow/credit detection, `error_utils.py:16-41`): centralized and tested, but a provider wording change converts recoverable overflows into fatal errors.
- **Positional/fragile resume matching** (langgraph nested interrupts matched by call order, `types.py:866-866` region): node edits between interrupt and resume silently misroute human answers; pydantic-ai's ID-matched results with duplicate rejection is the robust variant.
- **Auto-approval rules with collision risk** (agent-framework name-matching auto-approval can approve an unrelated same-named tool, warned at `_tool_approval.py:365-376`): configuration mistakes silently bypass the human gate.
- **Misconfiguration disabling enforcement** (agent-framework policy checks skipped with a warning when the label-tracking middleware didn't run, `security.py:1969-1976`): should fail closed.

## Notable Absences

Consistent across all nine sources (verified by targeted searches reported in each analysis):

- **Push-based human notification** (email/chat/pager/webhook-on-failure): none ships it. agent-framework found notification only in sample business logic; langgraph/temporal/opa/pydantic-ai/openai-agents-sdk/crewai/openhands each report zero hits for notification/pager/webhook escalation machinery; letta's callback/webhook channels are client-configured, fire-once, and swallow failures.
- **A central registry ranking failure severity across subsystems** (agent-framework searched explicitly): each layer owns its own constants and enums.
- **A durable, framework-owned recovery-audit store**: temporal achieves it via event sourcing and langgraph via checkpointed writes, but as library features; pydantic-ai, crewai, agent-framework, openhands require consumers to assemble audit trails from history/events/spans/logs themselves.
- **Automatic re-drive of failed runs** (letta explicitly delegates retry-from-failure to clients).
- **Backoff/jitter at the agent/task layer** outside dedicated transport stacks (crewai has none between task retries; only provider clients own backoff strategies).

Source-specific absences worth knowing: agent-framework has no core-loop provider-rate-limit retry (samples fill the gap, streaming unsupported, `auto_retry.py:82-84`); langgraph exposes its structured attempt telemetry only via an internal config key reserved for its server product; temporal's `RETRY_STATE_PAUSED` propagation is unfinished (TODO sites); letta's legacy backoff decorator is dead code on modern async paths (`llm_api_tools.py:64` catches only sync `requests` errors); opa's discovery reconfiguration is non-transactional mid-plugin-set; openhands cannot observe whether its `ConfirmRisky` policy is honored server-side.

## Per-Source Notes

- **agent-framework (8):** Most complete interactive-loop ladder: model-retry, three graceful caps, content-typed escalation, fail-closed `MiddlewareFailure`, checkpoints carrying pending HITL. Weakest at cross-layer audit (in-memory list) and provider-error retry (sample-only). Python/.NET parity suggests spec-driven design; Go is a placeholder.
- **crewai (7):** Simplest mental model — three independent retry loops plus pluggable human input — with genuinely excellent event-bus observability and declarative tool-failure policies. Loses points for blind retry, compounding budgets, `SystemExit`, and bare-Exception edges. Flow-level HITL pause/resume with SQLite persistence is the standout subsystem.
- **langgraph (8):** Recovery is a graph concept: retry wrappers around tasks, error handlers as hidden nodes that survive restarts, interrupts as durable pending writes, drain as a first-class control signal. Taxonomy choices actively serve policy (NodeTimeoutError deliberately not subclassing TimeoutError to remain retryable). Gaps: permissive defaults, server-gated metrics, no after-N-failures escalation hook.
- **letta (8):** The stop-reason enum is the most operationally legible terminal vocabulary studied; four-layer context-overflow defense is deep but triplicated across loop generations with drift. Typed provider-error normalization enables clean isinstance-based loop decisions. Webhook silence and hardcoded aggressive backoff are the main operational risks.
- **opa (8):** The purest unattended-service model: retry-forever, transactional last-known-good, ETag restoration, panic only on invariant risk, orchestrator-owned escalation. Readiness latching and shared backoff primitives show platform discipline. Costs: some failures never escalate past telemetry, and buffered drops can destroy audit evidence.
- **openai-agents-sdk (9):** Highest rigor: centralized `_evaluate_retry`, three deliberate fail-closed replay vetoes with a separate consent channel, coordination preventing hidden retry stacking, fully serializable interruption state, validated fallback outputs, careful cancellation hygiene (drained/scrubbed tasks). Cost: intricate three-layer retry story; observability limited to debug logs + usage deltas.
- **openhands (7):** Demonstrates that a frontend is a legitimate escalation surface: two-tier sticky/transient error lifecycle, watchdogs, persisted circuit breaker, keyboard-first confirmation UX, and settings-derived server-enforced confirmation policies. Held back by scattered constants, duplicated helpers, STUCK collapse, and consent-gated auditing.
- **pydantic-ai (9):** Cleanest taxonomy: five documented non-shared budgets, exception-per-disposition, transcript-as-audit-log, pause/resume deferral with integrity checks, cancellation terminal by contract, and durable-exec-aware non-retryable classification. Weaknesses: terminal-not-degrading exhaustion, intermittent-tool unboundedness within request limits, no queryable audit store, realtime-session asymmetry.
- **temporal (8):** Reference implementation for auditable retry decisions (typed RetryState stamped into immutable events with retry-run lineage) and for separating user-facing expiring policies from internal throttle lanes. Application-code-as-escalation-target plus explicit idempotent operator APIs. Gaps: unlimited default, no push escalation, unfinished paused-state semantics.
