## Executive Summary

The evidence base for this dimension is severely skewed: **8 of 10 source directories were empty at study time**. Only two sources produced analyzable implementation evidence — **langfuse** (8/10), a TypeScript monorepo spanning web, worker, and shared packages, and **openhands** (7/10), a React/TypeScript frontend consuming a typed SDK from an agent-server backend. The eight empty payloads each contain only a `.ultraplan-source.yml` descriptor; their 1/10 scores record absence of evidence, not evidence of bad design, and no comparative claim about them is supportable. Every empty-source report documents its search boundary explicitly and refuses to speculate about the upstream project — the correct posture.

Within that constraint, the two substantive sources converge on a recognizable model of what an error taxonomy in an agent harness is *for*:

- **Federated taxonomies, not one tree.** Langfuse runs at least nine parallel classifications (HTTP-coded `BaseError` subclasses, LLM stack-layer kinds, ClickHouse resource types, code-eval dispatcher codes with `retryable`, outbound-URL security classes, Slack provider codes, an MCP user-vs-server split, a worker retryability marker, in-app-agent run error codes) (langfuse: `packages/shared/src/errors/BaseError.ts:1-40`, `packages/shared/src/server/llm/errors.ts:43`, `worker/src/errors/UnrecoverableError.ts:3-17`). OpenHands layers one server-owned canonical classification (`ErrorClassification.kind`) under at least six subsystem-local vocabularies: ACP codes, MCP test-failure kinds, sandbox issues, backend-health sentinels, availability error classes, and transient-vs-sticky banner types (openhands: `src/utils/error-handler.ts:2`, `src/utils/acp-error-codes.ts:8-18`, `src/hooks/query/use-bash-command-logs.ts:16-21`).
- **Classification drives concrete sinks.** In both systems the point of the taxonomy is to answer three questions mechanically: retry or stop, what do we tell the user, and how do we log/measure it. Langfuse short-circuits BullMQ retries on `UnrecoverableError` and pauses evaluators on terminal block reasons; OpenHands switches banner icons, shows/hides retry and reauth buttons, and routes telemetry to `diagnostic` vs `outcome` buckets by kind (langfuse: `worker/src/features/integrations/bullmqAttempts.ts:8-32`; openhands: `src/components/features/chat/error-message-banner.tsx:103-120`, `src/utils/error-handler.ts:44-46`).
- **Defensive classification is mandatory.** Both walk `cause` chains (langfuse with cycle-protection sets, openhands with a 4-hop cap) and both avoid raw `instanceof` where module boundaries, bundling, or mocking can break prototype identity (langfuse: `packages/shared/src/server/llm/errors.ts:159-177`, `web/src/features/public-api/server/withMiddlewares.ts:208-210`; openhands: `src/utils/user-facing-error.ts:13-41`).
- **Unknown-safe degradation is the extensibility contract.** New categories must degrade gracefully: langfuse persists run error codes as free-form strings that readers must tolerate (`packages/shared/src/features/inAppAgent/types.ts:25-29`); openhands defaults missing kinds to `"unknown"` and treats unknown as diagnostic telemetry (`src/utils/error-handler.ts:27,44-46`).

The shared weaknesses are equally consistent: neither system has a central prose document of its taxonomy, both couple parts of classification to fragile string matching against upstream error text, and neither unifies its several retryability flags behind one predicate.

The dimension's headline question — *"Can you tell from the error type whether to retry, escalate, or stop?"* — is answerable **yes** for both populated sources via explicit retryability markers, terminal markers, and probe-retry predicates. It is unanswerable for the eight empty sources.

## Core Thesis

Mature error taxonomies in agent-facing systems are not single hierarchies but **federated per-subsystem vocabularies that converge on a small number of dispatch sinks** — retry-or-stop decisions, user-facing copy, severity/log level, and telemetry dimensions. What separates a 7–8 score from ad-hoc handling is not having one grand error tree but three properties visible independently in langfuse and openhands:

1. **Retryability is a first-class property of the classification itself**, not inferred at each call site (langfuse's `retryable` flags and `UnrecoverableError` marker; openhands' server-supplied `retryable` field and `isRetryableProbeError` over health sentinels).
2. **Unknown categories degrade safely**: fallback buckets, default switch arms, forward-compatible persisted enums — so adding a category never breaks existing handlers.
3. **Classification logic is defensive**: cause-chain walking, non-instanceof identity checks, reserved telemetry keys — because real errors arrive wrapped, re-bundled, and mislabeled by upstream text.

Both systems lose points on exactly the same axes — distributed documentation and string-matching adapters to upstream errors — which suggests these are the systemic bottlenecks for reaching 9–10 maturity, independent of product shape.

## Approach Models

**Langfuse — producer-side federated taxonomy with three convergence sinks.** Langfuse owns its throw sites across shared packages, web, and worker, so it defines named error classes carrying policy metadata (`name`, `httpCode`, `isOperational`, `isUserError()`) and lets every consumer surface fall back to generic `BaseError` handling (`packages/shared/src/errors/BaseError.ts:1-40`). Around that base it adds source-specific classifications wherever a failure domain has its own vocabulary: LLM stack-layer `kind` (`provider | validation | ai-sdk | timeout | abort`) (`packages/shared/src/server/llm/errors.ts:43`), ClickHouse resource failure modes keyed off message discriminators (`packages/shared/src/server/repositories/clickhouse.ts:47-110`), a `z.enum` dispatcher-code taxonomy with explicit `retryable` (`packages/shared/src/server/evals/codeEvalDispatcherTypes.ts:144-182`), a worker-only terminal marker (`UnrecoverableError`) duck-typed by name (`worker/src/features/integrations/bullmqAttempts.ts:8-32`), outbound-URL security classes classified by name across module boundaries (`worker/src/errors/findOutboundUrlValidationError.ts:17-90`), Slack provider codes (`packages/shared/src/server/services/SlackService.ts:21-29`), an MCP user-vs-server split (`web/src/features/mcp/core/errors.ts:19-49`), and a 14-value persisted enum for in-app-agent runs with an explicit "readers must tolerate unknown strings" contract (`packages/shared/src/features/inAppAgent/types.ts:25-29`). Everything eventually maps onto one of three sinks: an HTTP/tRPC/MCP wire code, a BullMQ retry-or-persist decision, or a user-facing copy decision.

**OpenHands — consumer-side layered taxonomy around a server-owned core.** The studied surface is a frontend, so the canonical classification arrives over the wire: `ErrorClassification` with `kind`, `retryable`, `user_action`, `error_id` imported from the backend SDK (`src/utils/error-handler.ts:2`, `__tests__/utils/error-handler.test.ts:61-79`). The frontend does not invent core kinds; instead it enriches with local vocabularies where the server has none — ACP agent codes including a distinct `UsagePolicyRefusal` (`src/utils/acp-error-codes.ts:8-18`), MCP probe kinds extended locally with `"credentials"` (`src/types/mcp-server.ts:34`), sandbox issue states (`src/hooks/query/use-bash-command-logs.ts:16-21`), backend-health sentinel strings (`src/hooks/query/use-backends-health.ts:36-40`), an availability class hierarchy with stable codes (`src/api/agent-server-compatibility.ts:41-103`), and a transient-vs-sticky banner split (`src/stores/error-message-store.ts:9`). Dispatch targets are UI affordances (retry button iff connection error, reauth button iff `ACPAuthRequired`), root-level routing (auth screen vs missing-server screen), and a privacy-aware telemetry split (`src/root.tsx:354-372`, `src/components/features/chat/chat-interface.tsx:589-598`, `src/utils/error-handler.ts:44-46`).

**The empty cluster.** Eight sources share the same "model": none observable. Each per-source report documents its search boundary (directory listings returning zero files), cites only its descriptor YAML, and explicitly refuses to speculate about the upstream repository's design. Mapping to the dimension's reference categories is therefore only assessable for langfuse (broad coverage except context/user) and openhands (provider→auth/credentials, tool→ACP spawn/init/prompt errors, policy→`UsagePolicyRefusal`, timeout→explicit kinds; model and context unmapped).

## Pattern Catalog

### P1. Retryability as a first-class property of the classification
- **Problem:** Handlers must decide retry vs escalate vs stop without embedding provider knowledge at every call site.
- **Sources:** Both. Langfuse (`CodeEvalDispatcherError.retryable`, `LLMErrorInfo.isRetryable`, `UnrecoverableError` vs plain `Error`); openhands (`ErrorClassification.retryable` field; `isRetryableProbeError` skips retry on auth/missing-key sentinels).
- **Why it works:** The decision travels with the error, so queue processors and probes reduce to one branch. Langfuse's processor persists terminal ERROR or rethrows purely on `isUnrecoverableError(e)` (`worker/src/queues/codeEvalQueue.ts:43-88`); openhands surfaces auth failures immediately because they are classified non-retryable (`src/hooks/query/use-backends-health.ts:164-171`).
- **When to copy:** Always, wherever automated retry exists. This is the single strongest predictor of being able to answer the dimension's headline question.
- **When risky:** Multiple independent boolean flags for the same concept (langfuse has four) invite divergence; centralize into one predicate once more than two exist.
- **Evidence:** `packages/shared/src/server/evals/awsLambdaCodeEvalDispatcher.ts:35-94`, `worker/src/features/in-app-agent/executeInAppAgentRun.ts:603-633`, `src/hooks/query/use-backends-health.ts:164-171`.

### P2. Federated taxonomies converging on few dispatch sinks
- **Problem:** One hierarchy cannot express provider quirks, infra failure modes, and policy outcomes without becoming a grab-bag.
- **Sources:** Both. Langfuse: nine classifications → HTTP code / retry decision / copy. OpenHands: seven taxonomies → UI affordances / routing / telemetry.
- **Why it works:** Subsystem vocabularies stay precise and close to their failure domain, while the small sink count keeps global behavior coherent.
- **When to copy:** Any multi-surface system (API + worker + UI).
- **When risky:** When the federation grows past discoverability — openhands flags that a new contributor must learn which taxonomy governs each subsystem before writing any handler.
- **Evidence:** `packages/shared/src/errors/index.ts:1-13`, `web/src/features/mcp/core/error-formatting.ts:27-115`, `src/stores/error-message-store.ts:9`.

### P3. Defensive classification: cause-chain walking with bounded depth
- **Problem:** Actionable signal hides under wrappers (`RetryError`, SDK wraps, CORS-normalized network failures).
- **Sources:** Both. Langfuse (`findInCauseChain` with a `visited` set against cycles, `unwrapRetryError`, `packages/shared/src/server/llm/errors.ts:159-177`; same technique in the outbound-URL classifier, `worker/src/errors/findOutboundUrlValidationError.ts:48-71`); openhands (`collectErrorMessages` walks `cause` up to 4 hops, `src/utils/user-facing-error.ts:13-41`).
- **Why it works:** Wrapped errors are the norm in layered stacks; classifiers that unwrap find the real source category.
- **When to copy:** Anywhere errors pass through middleware, SDKs, or job queues.
- **When risky:** Hard caps silently misclassify deep chains (openhands flags its magic number 4 as load-bearing and undocumented elsewhere); chain walkers must defend against cycles.
- **Evidence:** as cited above.

### P4. Non-instanceof identity checks
- **Problem:** `instanceof` breaks across duplicated modules, bundle boundaries, and test mocks.
- **Sources:** Langfuse, unusually thoroughly: duck-typing on `.name === "UnrecoverableError"` to survive module boundaries (`worker/src/features/integrations/bullmqAttempts.ts:11-13`), a `Symbol.for("langfuse.error.LLMValidationError")` marker for cross-package identity (`packages/shared/src/server/llm/errors.ts:3-5`), `error.constructor.name === "ZodError"` where zod may be double-bundled (`web/src/features/public-api/server/withMiddlewares.ts:208-210`), and name-based outbound-URL validation (`worker/src/errors/findOutboundUrlValidationError.ts:17-90`). OpenHands uses hand-written type-guard predicates (`isAgentServerAuthError`, `isSdkHttpStatusError`) instead (`src/api/agent-server-compatibility.ts:157-174`).
- **Why it works:** Identity survives boundaries that prototypes do not.
- **When to copy:** Monorepos with multiple bundles, plugin systems, or mocked tests.
- **When risky:** Name collisions — a foreign error setting `this.name = "UnrecoverableError"` would be treated as terminal; langfuse accepts this risk because it owns the throw sites.
- **Evidence:** as cited above.

### P5. Unknown-safe fallback buckets and forward-compatible persistence
- **Problem:** Taxonomies evolve; readers deployed older than writers must not crash or misbehave on new categories.
- **Sources:** Both. Langfuse persists `InAppAgentRunErrorCode` as a free-form string column whose comment mandates tolerance of unknown values (`packages/shared/src/features/inAppAgent/types.ts:25-29`) and collapses internal Lambda codes into a generic `INTERNAL_ERROR` for users while preserving detail in traces (`packages/shared/src/server/evals/codeEvalExecution.ts:174-204`). OpenHands defaults missing/null kind to `"unknown"` → diagnostic telemetry bucket and gives every switch a `default:` arm (`src/utils/error-handler.ts:27`, `src/utils/mcp-test-error-message.ts:15-24`).
- **Why it works:** Additive evolution becomes non-breaking by construction — new error types can be added without breaking existing handling.
- **When to copy:** Every persisted enum and every wire-contract union.
- **When risky:** Silent wrong-but-non-crashing output (openhands notes a forgotten switch arm yields the generic message indefinitely).
- **Evidence:** as cited above.

### P6. Closed unions as deliberate evolution friction
- **Problem:** Uncontrolled category sprawl makes dispatch untestable.
- **Sources:** Both. Langfuse's `CodeEvalDispatcherErrorCode` is a `z.enum` and `LLMErrorInfo.kind` a closed TS union, so additions force updates to message maps, retry sets, and APM builders (`packages/shared/src/server/evals/codeEvalDispatcherTypes.ts:144-160`, `packages/shared/src/server/llm/errors.ts:43`). OpenHands' `ExtendedMCPTestFailureKind` is closed and requires a new switch arm (`src/types/mcp-server.ts:34`).
- **Why it works:** The compiler/schema forces coordinated review when semantics must stay tight.
- **When to copy:** Wire contracts and money/policy-adjacent classifications.
- **When risky:** High-churn exploratory domains where coordination cost slows iteration; pair with P5 defaults.
- **Evidence:** as cited above.

### P7. Severity, icons, and copy derived from the type, not the call site
- **Problem:** Log levels and user messages drift when decided ad hoc at throw/catch sites.
- **Sources:** Both. Langfuse computes log severity from `isUserError()` with downgrades for NOT_FOUND/UNAUTHORIZED (`web/src/features/public-api/server/withMiddlewares.ts:67-82`) and maps run error codes to UI copy tables (`web/src/features/in-app-agent/lib/backgroundExecutionSession.ts:573-599`). OpenHands picks banner icon color from kind (`src/components/features/chat/error-message-banner.tsx:103-120`), i18n headers from code tables (`src/utils/acp-error-codes.ts:10-18`), and localized toast rewrites from message classifiers (`src/utils/custom-toast-handlers.tsx:96-108`).
- **Why it works:** One classification, many consistent renderings; call sites stay dumb.
- **When to copy:** Everywhere user-visible or operator-visible output depends on error category.
- **When risky:** Only if the mapping tables themselves lack tests (langfuse notes its Slack switch has no dedicated unit test per branch).
- **Evidence:** as cited above.

### P8. Privacy-aware observability cards built from classification
- **Problem:** Rich errors leak secrets into logs/APM; poor ones starve dashboards.
- **Sources:** Convergent independent invention. Langfuse exports low-cardinality span attributes (`eval.llm.error.kind`, `retryable`, `status_code`, `block.reason`) while deliberately excluding provider response bodies (`worker/src/features/evaluation/evalSpanAttributes.ts:84-117`). OpenHands routes `internal`/`unknown` kinds to full-payload diagnostic telemetry and everything else to lighter outcome telemetry, protected by `RESERVED_ERROR_KEYS` so callers cannot spoof the classification (`src/utils/error-handler.ts:10-15,44-46`).
- **Why it works:** The taxonomy becomes the redaction boundary — classification granularity defines observability granularity.
- **When to copy:** Any system shipping error data to third-party observability backends.
- **When risky:** Reserved-key lists are static; new analytic dimensions require editing the guard list.
- **Evidence:** as cited above.

### P9. String-matching adapters to upstream errors (necessary hazard)
- **Problem:** Upstream providers (OpenAI/Anthropic, ClickHouse, Slack, hosted MCP servers) return untyped text; classification still needs a source category.
- **Sources:** Both. Langfuse's `BLOCK_REASON_PATTERNS` substrings, ClickHouse message discriminators, and Slack `switch(slackErrorCode)` (`packages/shared/src/server/evals/classifyEvaluatorLlmError.ts:5-42`, `packages/shared/src/server/repositories/clickhouse.ts:53-62`, `web/src/features/slack/server/router.ts:367-389`). OpenHands' regex upgrade of `connection`→`credentials` when auth-failure text matches (`src/api/mcp-health/probe-mcp-server-health.ts:51-59`).
- **Why it works anyway:** It is often the only handle available, and openhands shows the safe shape: *conservative upgrade* — start from a coarse safe bucket and refine on strong textual evidence.
- **When to copy:** With version-pinned fixture tests per provider so drift fails CI, not production (both reports recommend adapter layers; neither fully has one).
- **When risky:** Silently misclassifying billing/auth outages as "internal" when upstream wording changes.
- **Evidence:** as cited above.

### P10. Classification driving durable side effects, not just logs
- **Problem:** Some categories demand state change (pause a broken evaluator, disable a dead backend), which logging cannot express.
- **Sources:** Both. Langfuse pauses an evaluator at the DB layer when the block reason is terminal (`worker/src/features/evaluation/evalService.ts:1102-1109`). OpenHands persists consecutive-failure counts and flips `disabled: true` after five failures, surviving reloads via localStorage write-through (`src/api/backend-registry/health-storage.ts:10-39`, `src/api/backend-registry/health-store.ts:46-63`).
- **Why it works:** The taxonomy becomes an operational control plane; incident response is pre-encoded.
- **When to copy:** Recurring-failure domains with cheap, reversible state transitions.
- **When risky:** Misclassification now causes actions, not just wrong labels — pair with P9 pinned tests. Note also langfuse's deliberate refusal to auto-retry `OUTCOME_UNKNOWN` during the durability window (`worker/src/features/in-app-agent/executeInAppAgentRun.ts:611-625`): some states must escalate to verification, never retry.

## Key Differences

The deepest difference between the two analyzable sources is **ownership position**, and most other differences follow from it:

- **Producer vs consumer.** Langfuse owns throw sites, so it can afford named classes with enforced metadata and exhaustive dispatch tests (`worker/src/features/integrations/bullmqAttempts.test.ts:41-66` asserts terminal behavior across six flows). OpenHands consumes a server's kinds, so its design center is *graceful consumption*: default-to-unknown, local enrichment vocabularies, conservative upgrades — and it structurally cannot add a canonical kind without a backend release (openhands tradeoffs section). Neither choice is better; they are responses to who controls the error's birthplace.
- **Classes+flags vs unions+tables.** Langfuse leans on class hierarchies with behavior (`httpCode`, `isUserError()`) plus scattered boolean flags; openhands leans on discriminated unions and mapping tables (`SANDBOX_ISSUE_I18N`, `ACP_ERROR_HEADER_KEYS`). The table style gets compile-time exhaustiveness if switches are checked; the class style gets generic fallbacks for free via the base class. Langfuse's own future-work notes suggest registry-style mappings to get the best of both (`web/src/features/public-api/server/unstable-public-api-error-contract.ts:160-262`).
- **Where retry lives.** Langfuse encodes retry in the error object and durable queue processor; openhands splits it — probe-level automated retries for transient sentinels (`src/hooks/query/use-backends-health.ts:164-171`), human-in-the-loop retry buttons for conversation-level failures (`src/components/features/chat/chat-interface.tsx:589-592`). An agent harness doing both automated and interactive recovery needs both layers. This divergence tracks operational reality: langfuse runs background evaluation pipelines where duplicate side effects cost money; openhands runs an interactive UI where retry means reconnect/refetch.
- **Escalation semantics.** Langfuse escalates operationally (DB-level evaluator pause; unknown outcomes require verification, not retry). OpenHands escalates to humans (reauth button, dedicated screens, sticky banners). Same taxonomy concept, different escalation channel, driven by product shape.
- **Test strategy.** Langfuse tests dispatch exhaustively but leaves string-matching ladders thinly covered; openhands tests each subsystem in isolation but has no end-to-end test proving server event → extraction → banner → telemetry handles new kinds (both reports' gaps sections agree on this complementary blind spot).
- **Documentation posture.** Identical weakness from opposite directions: langfuse distributes JSDoc + AGENTS.md playbooks with no central doc (`web/AGENTS.md:264-270`); openhands has TSDoc everywhere and nothing in `docs/` except a 401 note (`AGENTS.md:549-553`). Divergent products, same gap.

Against the empty cluster, no comparison is possible — the differences there are study-infrastructure failures (missing payloads), not design differences, and treating them as quality signals would be a category error.

## Tradeoffs

- **Single canonical taxonomy vs federated vocabularies.** Federation keeps subsystem semantics precise (langfuse's ClickHouse resource codes mean something HTTP codes cannot) at the cost of discoverability and cross-subsystem consistency; a canonical type (what openhands wishes for) simplifies onboarding but would either bloat into meaninglessness or strip subsystem nuance. Both sources chose federation; both pay for it in documentation debt.
- **Closed unions vs open extension.** Closed unions (langfuse `z.enum`, openhands MCP kinds) buy compile-time discipline and testable dispatch but require coordinated multi-file changes for every addition (langfuse enumerates five call sites for one new dispatcher code). Open string codes (openhands ACP `string | null`, langfuse persisted run codes) allow additive growth but push correctness onto conventions like default arms and reader tolerance. Best-fit: closed for wire/policy contracts, open-with-defaults for persisted/UI categories.
- **instanceof purity vs boundary-proof identity checks.** Strict `instanceof` is semantically cleanest but demonstrably breaks under double bundling and mocks — langfuse's ZodError workaround and symbol markers exist precisely because of this. Name/marker duck-typing survives boundaries but admits collision risk. Copy langfuse's approach only where you own all throw sites.
- **Server-owned kinds vs client-invented kinds.** Server ownership guarantees consistency and single-sourced semantics (openhands), but couples UI capability to release cadence and pushes clients toward regex-based inference as a workaround — which reintroduces P9 fragility. Client-side taxonomies (langfuse's whole stack) keep autonomy but multiply the vocabularies operators must learn.
- **Rich internal codes vs collapsed user-facing codes.** Langfuse's two-step normalization preserves diagnostic fidelity in traces while giving users honest generic messages (`getCodeEvalUserVisibleError`), at the cost of users seeing less than operators do. The alternative — surfacing everything — leaks internals; collapsing too early loses debuggability.
- **Retry encoded in the error vs retry encoded at the boundary.** Error-carried retryability (both sources) scales across many producers but risks divergent flags; boundary-owned policies (a single `isRetryable(error)` registry, listed as future work by both) centralize but become a bottleneck file. Evidence supports starting with error-carried flags and consolidating once the flag count grows — langfuse reached four independent booleans and is now paying the consolidation cost.
- **Auto-retry vs verify-after-unknown.** Aggressive retry buys liveness and risks duplicate side effects; verification-on-unknown buys safety and costs latency plus state-machine complexity. Langfuse encodes the safety side explicitly: `OUTCOME_UNKNOWN` (an approved mutation may have applied but its result may not have persisted) is never auto-retried (`worker/src/features/in-app-agent/executeInAppAgentRun.ts:160-167`). For side-effecting agent steps the evidence favors never auto-retrying unknown-outcome windows.

## Decision Guide

Choose your taxonomy architecture by answering these questions in order:

1. **Do you own the throw sites?**
   - Yes → build a base error class carrying policy metadata (`httpCode`/`code`, `isOperational`, user-vs-system) with generic fallback handling in middlewares, then add source-specific subclasses or kind discriminators per failure domain (langfuse model).
   - No (you consume someone else's service) → treat the incoming classification as canonical, default unknown kinds to a safe bucket, and grow local vocabularies only for subsystems the producer does not classify (openhands model).
2. **Does the error cross package, bundle, or process boundaries?** If yes, plan identity checks that survive boundaries (markers, name duck-typing, predicate guards) from day one; retrofitting them after a bundler change is how langfuse ended up with three different identity mechanisms in one middleware file.
3. **Is the category set stable or exploratory?** Stable/wire-facing → closed unions with exhaustive tests (P6). Exploratory/persisted → open strings with mandated reader tolerance and default arms (P5).
4. **Do errors wrap other errors?** Then cause-chain walking with cycle protection and a documented depth cap is mandatory infrastructure, not a utility (P3).
5. **Do you have automated retries?** Then retryability must be part of the classification itself (P1), and unknown-outcome windows must route to verification, not retry.
6. **Do you ship error data to third-party observability?** Derive a low-cardinality attribute card from the classification and protect it with reserved keys (P8); let classification granularity define your redaction boundary.
7. **When to refactor toward one unified taxonomy:** when handlers in different subsystems start making contradictory decisions for the same underlying category (openhands' warning sign: seven taxonomies, no single `ErrorKind`), or when your retryability flags exceed ~three and disagree (langfuse's four booleans).

## Practical Tips

- Put a `retryable` (or its inverse, terminal) marker on the classification itself before writing any handler; every later decision reduces to one branch.
- Give every dispatch switch a tested default arm, and persist enums as strings that readers must tolerate — this is the cheapest insurance for schema evolution.
- Build the cause-chain walker once, centrally, with cycle protection; ban ad-hoc `err.cause?.message` digging.
- Derive log severity and UI copy from the classification via lookup tables; forbid per-call-site severity decisions for classified categories.
- When you must parse upstream text, do it as a conservative *upgrade* (coarse safe bucket first, refine on match) and pin the expected upstream strings in fixtures so drift fails CI (openhands' probe pattern is the safest observed variant).
- Keep an internal-code ↔ user-facing-code translation step so traces stay rich while users get honest generic messages (langfuse `getCodeEvalUserVisibleError`).
- Reserve analytics keys (`error_kind`, `error_id`, …) so caller metadata cannot spoof the classification, and promote caller event IDs only as fallback correlation keys (openhands `RESERVED_ERROR_KEYS` + `eventId` fallback).
- Encode operational reflexes in the taxonomy: pause-on-terminal-block, disable-after-N-consecutive-failures — with the state persisted, not just logged.
- Document the playbook even if you skip the encyclopedia: a short "throw X, let it bubble, extend here" note (langfuse `web/AGENTS.md:264-270`) captures most of the practical value of a taxonomy doc.

## Anti-Patterns / Caution Signs

- **Stringly-classified core paths.** If billing/auth/timeout detection rests on substring matches against live upstream messages with no pinned fixtures, you have a silent-misclassification clock ticking (langfuse flags exactly this for `BLOCK_REASON_PATTERNS` and ClickHouse discriminators).
- **Parallel unbridged wire contracts.** Two public vocabularies for the same errors (legacy HTTP codes vs stable `code` enums) joined by a hand-maintained instanceof ladder means every new error class risks forgetting one bridge (langfuse `toUnstablePublicApiError`).
- **Mixed identity paradigms in one file.** If a middleware needs `instanceof`, `.constructor.name`, `.name`, and symbol markers simultaneously, the module-boundary strategy is undefined and each new error type forces an archaeology exercise.
- **Taxonomy count exceeding handler-author awareness.** Caution sign from openhands: when contributors must first ask "which of seven vocabularies applies here?", wrong-but-silent handling follows (the stdio `ENOENT` reported as `connection` with URL-fix advice).
- **Default arms without exhaustiveness checks.** A closed union plus a `default:` arm gives you crashes-never and correctness-untested; missing switch arms go unnoticed forever (openhands MCP kinds).
- **Retry flags multiplying unchecked.** Three or more independent `retryable`-ish booleans in one codebase (langfuse reached four) is the leading indicator that handlers already disagree about escalation.
- **Classification that stops at logging.** If the only consumer of your kinds is a logger line, the taxonomy is documentation, not mechanism — expect it to rot.
- **Duck-typing on names without collision review.** Any error that happens to set `name = "UnrecoverableError"` becomes terminal; acceptable only while you own every throw site.
- **Silent-empty study inputs.** Harness-level caution from the empty-source cluster: fetch steps can fail silently while descriptor metadata remains, leaving vacuous targets; pipelines should fail fast on zero-file sources rather than emit null reports (echoed by every empty-source report recommending SHA pinning and fetch-manifest entries).
