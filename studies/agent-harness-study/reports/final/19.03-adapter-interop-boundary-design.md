## Executive Summary

This dimension answers: are standards core abstractions, optional adapters, or afterthoughts — and can a new protocol be added without modifying core?

No source treats every standard identically; each separates a small set of *canonical* protocols to core and pushes the rest to adapters, but where the cut is drawn and how the boundary is enforced varies dramatically.

- **The top tier (opa 8, openai-agents-sdk 8, pydantic-ai 8) proves the mature form:** narrow `ABC`/`Protocol` contracts owned by core (`plugins.Factory`/`Plugin` in `v1/plugins/plugins.go:89`, `Model`/`ModelProvider` in `src/agents/models/interface.py:37`, `AbstractModel`/`Provider`/`ModelProfile` in `pydantic_ai_slim/pydantic_ai/models/__init__.py:366` / `pydantic_ai_slim/pydantic_ai/providers/__init__.py:42`) with all wire formats in isolated adapter packages. New adapters require zero core edits when the contract exists; adding a *new contract* is the only core change.
- **The middle tier (agent-framework 7, crewai 7, langgraph 7, temporal 7) is architecturally clear but leaks.** agent-framework's `SupportsChatGetResponse`/`BaseChatClient` (`python/packages/core/agent_framework/_clients.py:84`, `217`) and langgraph's `BaseCheckpointSaver`/`BaseChannel` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:176`, `libs/langgraph/langgraph/channels/base.py:19`) are exemplary dependency-inversion boundaries. But agent-framework lacks a cross-protocol conformance harness, langgraph only harnesses checkpoints (not Store/Cache/Channel/Serde), temporal's SQL plugin map is global `init()` mutable state (`common/persistence/sql/store.go:18`), and crewai's `LLM.__new__` routing (`lib/crewai/src/crewai/llm.py:393`) hard-codes `SUPPORTED_NATIVE_PROVIDERS`.
- **The lower tier (langfuse 5, letta 5, openhands 6) is correctly diagnosed as "present but fragile."** langfuse's `LLMAdapter` closed enum (`packages/shared/src/server/llm/types.ts:246`) with exhaustive `switch` (`packages/shared/src/server/llm/llmText.ts:545`) and monolithic `OtelIngestionProcessor` (`packages/shared/src/server/otel/OtelIngestionProcessor.ts:241`), and letta's `ProviderType` enum (`letta/schemas/enums.py:53`) with `LLMClient.create` `match/case` (`letta/llm_api/llm_client.py:32`), force every new provider through core edits. OpenHands is a special case: its adapter model is sound for a frontend (`src/api/no-direct-agent-server-calls.test.ts:7` guard), but Skills/MCP catalog are build-time snapshots requiring rebuilds.

**Convergence:** All 10 sources externalize at least one major interop family to adapters behind typed contracts; all provide per-adapter tests; all document boundaries in code (godoc/docstrings/Pydantic unions). Six sources (agent-framework, openai-agents-sdk, pydantic-ai, opa, temporal, langgraph-core) allow new adapters of an *existing* family without core edits.

**Divergence:** Whether *new families* are open (registry/Protocol pass-through) or closed (enum + factory branch), whether runtime swappability is true DI or build-time `init()` registration, and whether conformance is a reusable harness or ad-hoc per-adapter tests. These are not pure quality gaps — they reflect product shape: Langfuse is a SaaS observability platform where ingestion is the product; OPA is a Go binary where static linking is the deployment model; OpenHands is a frontend where the backend owns protocol reality.

**The universal gap is conformance as a first-class artifact.** Only langgraph's `langgraph-checkpoint-conformance` package (`libs/checkpoint-conformance/langgraph/checkpoint/conformance/validate.py:32`) approaches a durable, capability-aware harness. No source provides a single harness covering all adapter families with failure injection and version negotiation.

## Core Thesis

Adapter and interop boundary maturity is not binary (core vs adapter) but a four-level ladder, and a source's position is determined by three linked decisions: **contract narrowness**, **discovery mechanism**, and **conformance investment**.

1. **Level 1 — Afterthought integration:** Protocols leak into core logic, new providers require core branches, tests are end-to-end only. None of the studied sources is here today, but early-stage projects default here.

2. **Level 2 — Adapter-layer with closed registry (langfuse, letta, crewai):** Core defines typed configs/ABCs, adapters are isolated files, but `enum` + exhaustive `switch`/`match` + hard-coded `SUPPORTED_*` constants force core edits for every new provider/transport/signal. This is the correct tradeoff for products that value static exhaustiveness and correctness over community extensibility.

3. **Level 3 — Adapter-layer with open DI/structural typing (agent-framework structural `Protocol`, openai-agents-sdk `Protocol` Sessions, pydantic-ai `Model`/`Provider` + instance passthrough, langgraph-core `ABC` + DI, temporal `CustomDatastoreConfig` escape hatch):** Any object satisfying `SupportsChatGetResponse` (`python/packages/core/agent_framework/_clients.py:84`) or `Session` Protocol (`src/agents/memory/session.py:16`) is accepted without registration. New adapters are a new class + injection (`Pregel(checkpointer=...)` at `libs/langgraph/langgraph/pregel/main.py:798`, `RunConfig(model_provider=Custom)` at `src/agents/run_config.py:358`, `Agent(model=my_model)` at `pydantic_ai_slim/pydantic_ai/models/__init__.py:1540`). Cost is discoverability and late error detection.

4. **Level 4 — Durable, observable, extensible boundary (opa 8, openai-agents-sdk 8, pydantic-ai 8; aspirational for others):** Level 3 plus a versioned capability model, a reusable conformance suite (langgraph's `Capability` enum at `libs/checkpoint-conformance/langgraph/checkpoint/conformance/capabilities.py:15` is the closest), operational safeguards (status state machine at `v1/plugins/plugins.go:127`, credential-safe redaction at `src/agents/mcp/server.py:249`, `ArraySlotBudget` at `packages/shared/src/server/otel/OtelIngestionProcessor.ts:112`), and explicit extension documentation. OPA's global `RegisterPlugin` (`v1/runtime/runtime.go:95`) and Temporal's `supportedPlugins` map (`common/persistence/sql/store.go:18`) show Level 4 is still build-time, not hot-swappable — indicating the ladder's top is not "hot reload" but "no core file edited, rebuild is declarative."

Sources diverge because they optimize for different constraints: **correctness** (Langfuse/Letta closed enums deliberately prevent silent passthrough via `_exhaustiveCheck: never` at `packages/shared/src/server/llm/llmText.ts:599`), **deployment model** (OPA/Temporal static binary → `init()` registries), **deployment surface** (OpenHands frontend → typed-client proxy), and **API surface breadth** (LangGraph/Pydantic-AI many interchangeable families → need generic conformance; CrewAI three families → ad-hoc tests scale).

Therefore the actionable lesson is not "make everything Level 4" but: **choose the right level per boundary, make the choice explicit and documented, and invest conformance harness effort proportional to how many third parties will implement adapters.**

## Approach Models

Four archetypes emerged; each appears in at least two sources and each is a valid response to distinct constraints.

### Model A — Open DI / Structural Typing (Runtime-Swappable, Zero Registration)

**Describe:** Core defines a minimal narrow contract (`Protocol` or `ABC` with few methods). Any object satisfying the shape is accepted via constructor/DI injection; no global registry, no enum, no decorator needed. Factory functions short-circuit on `isinstance`/`runtime_checkable`.

**Members:** agent-framework (`SupportsChatGetResponse` at `python/packages/core/agent_framework/_clients.py:84`, `SupportsAgentRun` at `python/packages/core/agent_framework/_agents.py:233`, proven via `test_plain_class_satisfies_protocol` at `python/packages/core/tests/core/test_clients.py:33`), openai-agents-sdk `Session(Protocol)` at `src/agents/memory/session.py:16`, pydantic-ai `Model` instance passthrough at `pydantic_ai_slim/pydantic_ai/models/__init__.py:1540`, langgraph `Pregel(checkpointer=...)` injection at `libs/langgraph/langgraph/pregel/main.py:798`.

**When this model is chosen:** The team expects community/out-of-tree adapters, values minimal boilerplate, and accepts late (runtime) interface errors in exchange for zero-core-change extensibility.

### Model B — Global Build-Time Registry (`init()` + String Key)

**Describe:** Core defines stable `Go`/`Python` interfaces. Adapters self-register in a process-wide map during `init()`/import (`RegisterPlugin`, `RegisterStorageBackend`, `RegisterDefaultBundleActivator`). Selection is via config string (`PluginName`, `PluginName` + `DataStore` discriminant, URI scheme). No code reflection discovery; the binary is the unit of extension.

**Members:** opa (`registeredPlugins map[string]Factory` at `v1/runtime/runtime.go:68`, `RegisterPlugin` at `v1/runtime/runtime.go:95`, `RegisterStorageBackend` at `v1/runtime/runtime.go:101`, `rego.RegisterPlugin` at `v1/rego/plugins.go:36`), temporal (`supportedPlugins map[string]sqlplugin.Plugin` at `common/persistence/sql/store.go:18`, `RegisterPlugin` at `common/persistence/sql/store.go:21` from `common/persistence/sql/sqlplugin/mysql/plugin.go:27` etc.), langfuse MCP `ToolRegistry` with static `bootstrapMcpFeatures()` at `web/src/features/mcp/server/bootstrap.ts:30` (same shape minus Go `init()`), crewai `LLM.__new__` + `SUPPORTED_NATIVE_PROVIDERS` (Python variant of global registry at `lib/crewai/src/crewai/llm.py:478`).

**When this model is chosen:** Deployment is a statically linked binary or bundled server where rebuild is the normal upgrade path, and correctness/static analysis is valued over hot-reload. Test isolation and hot-swap are sacrificed.

### Model C — Closed Enum / Exhaustive Switch (Core-Guarded Adapter Set)

**Describe:** Supported protocols are enumerated as a closed `enum`/`Literal`/`Literal union`. Dispatch is an exhaustive `switch`/`match` with a `never`/`ValueError` default that forces compile-time or startup failure on unknown values. Adding a provider means editing the enum, the switch, and often supporting tables.

**Members:** langfuse `LLMAdapter` enum (`packages/shared/src/server/llm/types.ts:246`) + `translateLegacyProviderOptions` exhaustive switch (`packages/shared/src/server/llm/llmText.ts:545` with `_exhaustiveCheck: never` at `599`), letta `ProviderType` (22 values at `letta/schemas/enums.py:53`) + `LLMClient.create` `match/case` (`letta/llm_api/llm_client.py:32` + streaming hard-code at `letta/adapters/letta_llm_stream_adapter.py:97`), pydantic-ai `KnownModelName` literal (500+ values at `pydantic_ai_slim/pydantic_ai/models/_known_model_names.py:13`) + `infer_provider_class` map (`pydantic_ai_slim/pydantic_ai/providers/__init__.py:142`), crewai `SUPPORTED_NATIVE_PROVIDERS` constant (`lib/crewai/src/crewai/llm.py:327`) + `provider_mapping` dict (`lib/crewai/src/crewai/llm.py:432`).

**When this model is chosen:** The team prioritizes exhaustive type-checking, friendly `Did you mean ...?` suggestions, and prevention of silent passthrough over community self-registration. Appropriate for Tier-1 provider lists where every entry needs curated docs, rate limits, and telemetry.

### Model D — Gateway / Proxy Adapter (Frontend or Edge Facade)

**Describe:** Interop is not protocol translation but typed-client + proxy forwarding. Core enforces *how* to call the backend (centralized client options, proxy envelope, version floor), not *how* to translate wire formats. Extension is via config/catalog data at runtime, but new protocol *kinds* require SDK + proxy changes.

**Members:** openhands (`getAgentServerClientOptions` at `src/api/agent-server-client-options.ts:52`, CI guard at `src/api/no-direct-agent-server-calls.test.ts:32`, `callCloudProxy` at `src/api/cloud/proxy.ts:18`), temporal Nexus as core HTTP (`service/frontend/nexus_handler.go:418`, `docs/architecture/nexus.md:22`) — gateway is core, not adapter, langfuse legacy `POST /api/public/ingestion` (`web/src/pages/api/public/ingestion.ts:55`) vs OTel `POST /api/public/otel/v1/traces` (`web/src/pages/api/public/otel/v1/traces/index.ts:27`) which are both core routes, not pluggable transports.

**When this model is chosen:** The adapter lives at a process boundary (browser, edge, frontend) where the real protocol handling is owned by another repo/service. The proxy pattern trades deep extensibility for CORS/secret-isolation and version-pinning discipline.

## Pattern Catalog

### Pattern 1 — Narrow Core Contract with Structural Acceptance

- **Problem:** How to allow out-of-tree adapters without forcing inheritance or registry edits, while keeping core small.
- **Demonstrated by:** agent-framework (`SupportsChatGetResponse` `runtime_checkable Protocol` at `python/packages/core/agent_framework/_clients.py:84`, validated by `test_mock_client_satisfies_protocol` at `python/packages/core/tests/core/test_clients.py:33`), openai-agents-sdk `Session(Protocol)` at `src/agents/memory/session.py:16` + `SessionABC` fallback, pydantic-ai `infer_model(Model|str)` instance short-circuit at `pydantic_ai_slim/pydantic_ai/models/__init__.py:1540`.
- **Why it works:** Structural typing decouples the contract from the type hierarchy; tests prove a plain class with `get_response` satisfies the protocol without subclassing, eliminating boilerplate for BYO adapters.
- **When to copy:** You expect plugins from users who should not depend on your base class, you are in Python/TypeScript, and you can tolerate late discovery of missing methods.
- **When it is overkill/risky:** In Go/static languages where compile-time exhaustiveness is desired, or where missing-method errors would be silent in production. In Python, typos surface late (agent-framework tradeoff explicitly noted).
- **Evidence:** `python/packages/core/agent_framework/_clients.py:84-201` (protocol) + `python/packages/core/tests/core/test_clients.py:33-52` (duck-typing proof); `src/agents/memory/session.py:15` (structural session).

### Pattern 2 — Monorepo Leaf Adapters (One Package Per Protocol)

- **Problem:** How to keep dependency weight and blast radius low when supporting many protocols.
- **Demonstrated by:** agent-framework 20+ `python/packages/` dirs (`python/packages/openai/`, `anthropic/`, `a2a/`, `ag-ui/`, `hosting-mcp/`), langgraph `libs/checkpoint*` + `libs/checkpoint-postgres`/`sqlite` leaf packages (`libs/langgraph/pyproject.toml:28`), pydantic-ai per-file provider isolation (`pydantic_ai_slim/pydantic_ai/models/AGENTS.md:3` rule: "Place provider-specific code in `models/{provider}.py`"), temporal per-dialect `sqlplugin` packages (`common/persistence/sql/sqlplugin/mysql/plugin.go:15`, `postgresql/plugin.go:20`, `sqlite/plugin.go:22`).
- **Why it works:** Each adapter owns its SDK dependency, telemetry name (`OTEL_PROVIDER_NAME` in agent-framework), and version floor; core stays dependency-free and install cost stays minimal.
- **When to copy:** You ship a framework with many optional integrations and consumers should pay only for what they import.
- **When overkill:** Small codebases with 1–2 protocols where monorepo overhead exceeds isolation benefit; CI complexity grows with per-package `pyproject.toml` / `go.mod` discipline.
- **Evidence:** `python/packages/core/agent_framework/_clients.py:217` (`BaseChatClient` minimal) vs `python/packages/ag-ui/agent_framework_ag_ui/_client.py:115` (`AGUIChatClient` subclass); `libs/checkpoint/langgraph/checkpoint/memory/__init__.py:33` reference adapter downstream of `libs/checkpoint/.../base/__init__.py:176`.

### Pattern 3 — Capability-Negotiated Conformance Harness

- **Problem:** How to test adapters that only support a subset of operations without requiring every adapter to implement everything.
- **Demonstrated by:** langgraph-checkpoint-conformance: `Capability` enum (9 values) at `libs/checkpoint-conformance/langgraph/checkpoint/conformance/capabilities.py:15`, auto-detection via `__dict__` override check (`libs/checkpoint-conformance/.../capabilities.py:90-96`), decorator-registered factories (`@checkpointer_test` at `libs/checkpoint-conformance/.../initializer.py:59`), `validate()` dispatch to 9 spec modules (`libs/checkpoint-conformance/.../validate.py:32`, suite at `libs/checkpoint-conformance/.../spec/test_put.py:11`). Temporal mirrors the pattern informally with shared persistence suites (`common/persistence/tests/history_store.go` instantiated per `mysql_test.go:86`, `postgresql_test.go`, `sqlite_test.go:46`).
- **Why it works:** Optional methods are explicit capabilities, not nullable flags; harness skips unsupported capabilities rather than failing, while `DetectedCapabilities.from_instance` proves implementation coverage. Add `readCapability` → `copy_thread` without versioned interfaces.
- **When to copy:** You have persistence/queue/search boundaries where adapters legitimately subset features (time-travel fork, TTL, vector search) and you want third-party implementers to self-validate.
- **When overkill:** Single-protocol products or when only one production adapter exists; the harness pays off when you maintain Postgres vs SQLite vs in-memory vs Cassandra equivalently.
- **Evidence:** `libs/checkpoint-conformance/langgraph/checkpoint/conformance/validate.py:32-128` (runner) + `libs/checkpoint-conformance/README.md:64-124` (spec doc); temporal counterpart `common/persistence/tests/mysql_test.go:86` + `common/persistence/visibility/store/sql/query_converter_test.go`.

### Pattern 4 — Converter-Pair / Pure Translation Layer

- **Problem:** How to keep transport lifecycle separate from wire-format mapping so translation is testable without network.
- **Demonstrated by:** agent-framework `mcp_to_run`/`mcp_from_run` (`python/packages/hosting-mcp/agent_framework_hosting_mcp/_conversion.py:19`) + `AGUIEventConverter` (`python/packages/ag-ui/agent_framework_ag_ui/_event_converters.py:1`), pydantic-ai `map_from_mcp_params` / `map_from_pai_messages` (`pydantic_ai_slim/pydantic_ai/_mcp.py:22`), `AGUIAdapter` / `VercelAIAdapter` message mapping (`pydantic_ai_slim/pydantic_ai/ui/ag_ui/_adapter.py:232`, `vercel_ai/_adapter.py:145`), openai-agents-sdk `Converter.items_to_messages` + `ChatCmplHelpers`/`OpenAIResponsesConverter` pattern, opa `DataRequestV1`/`DataResponseV1` `Metadata` passthrough via `RegisterJSONFields` (`v1/server/types/types.go:240`).
- **Why it works:** Side-effect-free helpers are cheap to unit-test, version-gate, and compose; transport ownership (server/route/auth/session) stays with the application.
- **When to copy:** Any interop where retries, backpressure, and auth are the app's responsibility and translation correctness is the framework's burden.
- **Evidence:** `python/packages/hosting-mcp/AGENTS.md:1-45` (explicit "does not provide server/routes/transport lifecycle/auth"); `pydantic_ai_slim/pydantic_ai/ui/_adapter.py:207-438` (shared `sanitize_messages` security policy across diverging `load_messages`/`dump_messages`).

### Pattern 5 — Middleware/Pipeline Extension (Stackable Interop Concerns)

- **Problem:** How to let users inject retry, telemetry, compaction, auth, filtering without forking adapters.
- **Demonstrated by:** agent-framework three pipelines `AgentMiddlewarePipeline`/`ChatMiddlewarePipeline`/`FunctionMiddlewarePipeline` + `MiddlewareBundle` atomic grouping (`python/packages/core/agent_framework/_middleware.py:1006`, `745`), pydantic-ai `WrapperModel`/`InstrumentedModel`/`FallbackModel` decorator chain (`pydantic_ai_slim/pydantic_ai/models/wrapper.py:32`, `instrumented.py:52`), openai-agents-sdk streaming/tool transformation layers + `BaseToolAdapter`, temporal decorator stack `TaskManager → RateLimited → Metrics → Retryable` (`common/persistence/client/factory.go:109-122`), opa `Manager.ExtraRoute`/`ExtraMiddleware`/`ExtraAuthorizerRoute` late binding consumed in `Server.initRouters` (`v1/plugins/plugins.go:764`, `v1/server/server.go:888`).
- **Why it works:** Interop concerns compose orthogonally to wire adapters; ordering is the only coupling (agent-framework `MiddlewareBundle` explicitly addresses atomic installation).
- **When to copy:** Your adapters share cross-cutting needs (logging, retry, auth injection, state mutation hooks) that users should toggle per call.
- **Evidence:** `python/packages/core/agent_framework/_middleware.py:745-828` (bundle); `pydantic_ai_slim/pydantic_ai/models/wrapper.py:32-158` (`__getattr__` forwarding `profile`/`base_url`); `common/persistence/client/factory.go:54-64` (metric/rate-limit/health decorators).

### Pattern 6 — Feature-Module / Tool Registry with Self-Registration

- **Problem:** How to let domain teams contribute tools/endpoints to a platform server without editing the server handler.
- **Demonstrated by:** langfuse MCP `McpFeatureModule` (`web/src/features/mcp/server/registry.ts:49`) + singleton `ToolRegistry` with duplicate detection (`web/src/features/mcp/server/registry.ts:72`) + `defineTool<TInput,TName>` enforcing draft-7 JSON Schema (`web/src/features/mcp/core/define-tool.ts:112`) + static `bootstrap.ts:30` wiring (and policy exhaustiveness test at `web/src/__tests__/server/unit/in-app-agent-mcp-policy.servertest.ts:13`); opa `Manager.ExtraRoute` (`v1/plugins/plugins.go:788`) + `hooks.Hook` dispatch (`v1/hooks/hooks.go:32`) as registry analogs; temporal `supportedPlugins` self-registration (`common/persistence/sql/store.go:21`).
- **Why it works:** Duplicate detection fail-fast (`if (this.features.has(...)) throw` at `web/src/features/mcp/server/registry.ts:83`, `panic("already registered")` at `v1/rego/plugins.go:40` / `common/persistence/sql/store.go:23`) prevents silent collision; enablement filtering (`getToolDefinitions` gated by `isEnabled`) allows per-tenant gating.
- **When to copy:** A multi-team monolith where each domain contributes an adapter/toolsurface to a shared server boundary.
- **When risky:** Static wiring (langfuse `bootstrap.ts:13` 15-feature array, OPA global map) makes incremental rollout and test isolation harder; no lazy load.
- **Evidence:** `web/src/features/mcp/server/registry.ts:49-108` (contract + uniqueness); `v1/hooks/hooks.go:32-112` (type-asserted hook dispatch); `common/persistence/sql/store.go:18-26` (plugin map).

### Pattern 7 — Prefix/URI-Scheme Router with Generic Escape Hatch

- **Problem:** How to allow out-of-tree backends without making core enumerate every kind.
- **Demonstrated by:** temporal `DataStores map[string]DataStore` discriminant + `CustomDatastoreConfig{Name, Options}` (`common/config/config.go:268`, `467`) + `AbstractDataStoreFactory` (`common/persistence/client/abstract_data_store_factory.go:16`) dispatched in `DataStoreFactoryProvider` (`common/persistence/client/fx.go:204` `case CustomDataStoreConfig`), and `ArchiverProvider` scheme dispatch + `CustomHistoryArchiverFactory` fallback (`common/archiver/provider/provider.go:123,54`); openai-agents-sdk `MultiProviderMap.add_provider(prefix, provider)` (`src/agents/models/multi_provider.py:44`) + `prefix/model` partition (`src/agents/models/multi_provider.py:199`) with `unknown_prefix_mode`; pydantic-ai `Model` instance passthrough that bypasses `provider:model` string parsing entirely (`pydantic_ai_slim/pydantic_ai/models/__init__.py:1540`).
- **Why it works:** The generic bag is the Open/Closed safety valve: a new kind that fits `AbstractDataStoreFactory` or `UIAdapter` requires no `switch` edit; only truly novel *families* touch core.
- **When to copy:** You operate infrastructure with operator-provided backends (databases, blob stores, model endpoints) where forking core per backend is unacceptable.
- **Evidence:** `common/config/config.go:156-174` (exactly-one validation) + `common/persistence/client/fx.go:187-219` (factory provider); `src/agents/models/multi_provider.py:18-44` (prefix map).

### Pattern 8 — Shared Adapter-Local Conformance (Rendering Assertions / Snapshot Tests)

- **Problem:** How to verify wire correctness without a full harness, keeping tests valid across SDK bumps.
- **Demonstrated by:** pydantic-ai `tests/AGENTS.md:153` + `tests/test_tool_availability_portability.py:1449` ("capture the render … and assert against that"), `tests/profiles/test_resolution_matrix.py:114-1900` snapshot matrix for `Model.profile` resolution; crewai A2UI `test_a2ui_schema_conformance.py:206` cross-validating Pydantic vs vendored JSON schema; agent-framework per-adapter rendering suites (`python/packages/ag-ui/tests/ag_ui/test_message_adapters.py:3`, `python/packages/a2a/tests/test_a2a_agent.py:719`, `python/packages/core/tests/core/test_mcp.py` 5286 lines).
- **Why it works:** Asserting against rendered requests/schemas rather than SDK internals survives SDK major bumps; snapshot matrices catch profile-vs-wire drift as a single registry.
- **When to copy:** When you cannot invest in a full harness but need per-adapter confidence and a culture rule that every adapter owns its translation tests.
- **Evidence:** `pydantic_ai_slim/pydantic_ai/models/AGENTS.md:31` ("every forwarded `ModelSettings` field must get a case in `test_model_settings_support.py`"); `lib/crewai/tests/a2a/extensions/test_a2ui_schema_conformance.py:206` (strongest crewai conformance example).

## Tradeoffs

### 1. Exhaustiveness vs Extensibility (closed enum vs open DI)

- **Benefit of closed enum + exhaustive switch:** `langfuse` (`packages/shared/src/server/llm/llmText.ts:545` → `_exhaustiveCheck: never` at `599`), `letta` (`letta/schemas/enums.py:53` + `letta/llm_api/llm_client.py:32`), and `crewai` (`lib/crewai/src/crewai/llm.py:327`) guarantee a new provider cannot silently fall through to wrong behavior, enable `Did you mean ...?` suggestions, and keep telemetry/docs/rate-limits curated. The `default: never` pattern is enforced by the compiler.
- **Cost:** Every new protocol (LLM provider, MCP transport at `lib/crewai/src/crewai/mcp/tool_resolver.py:281`, OTel signal in `OtelIngestionProcessor.ts:241`) requires a core PR and redeploy, blocking organizational forks and community `pip install provider-foo`.
- **Alternative:** agent-framework `runtime_checkable Protocol` (`python/packages/core/agent_framework/_agents.py:233`), pydantic-ai instance passthrough (`pydantic_ai_slim/pydantic_ai/models/__init__.py:1540`), openai-agents-sdk `MultiProviderMap.add_provider` (`src/agents/models/multi_provider.py:44`) allow zero-core-change adapters but trade late error detection and lack curated prefix suggestions.
- **Best-fit:** Closed enum when the boundary is user-facing SaaS with managed auth/telemetry; open DI when the product is an embeddable SDK where operators supply backends.

### 2. Global Registry vs Constructor Injection

- **Benefit of global registry:** opa `RegisterPlugin` (`v1/runtime/runtime.go:95`) and temporal `RegisterPlugin` (`common/persistence/sql/store.go:21`) make built-ins self-register with zero config indirection and straightforward static linking. Factory receives `*Manager` dependency injection (`v1/plugins/plugins.go:89-92`) through the manager, not globals.
- **Cost:** Process-wide singleton with `sync.Mutex` (`v1/runtime/runtime.go:68`, `common/persistence/sql/store.go:18`) requires rebuild to swap, panics on duplicate (`v1/rego/plugins.go:40`, `common/persistence/sql/store.go:23`), and hampers test isolation (only `rego.ResetTargetPlugins` at `v1/rego/plugins.go:45` as escape hatch). No hot-swap via `Reconfigure` (config blob only).
- **Alternative:** `Pregel(store=...)` (`libs/langgraph/langgraph/pregel/main.py:737`), `RunConfig(model_provider=...)` (`src/agents/run_config.py:358`), `Session` structural (`src/agents/memory/session.py:16`) pass adapters per-run with hermetic test isolation (fresh instance per `RegisteredCheckpointer.create()` at `libs/checkpoint-conformance/.../initializer.py:59`).
- **Best-fit:** Registry for static-binary distribution (`go:embed`); DI for Python/TypeScript SDKs and for boundaries where per-run isolation matters (checkpoint, store, session).

### 3. Monolithic Processor vs Pluggable Mapper Chain

- **Benefit of monolith:** langfuse `OtelIngestionProcessor` (3636 lines, `otel/OtelIngestionProcessor.ts:241`) centralizes GenAI/OpenInference/`langfuse.observation.*` priority, `ArraySlotBudget` backpressure (`otel/OtelIngestionProcessor.ts:112`), and conversion-failure accounting in one observable place.
- **Cost:** Adding `logs`/`metrics` signal or a new semconv (`web/src/pages/api/public/otel/v1/metrics/index.ts:16` stub) bloats the god class; no shared `OtelAttributeExtractor` interface.
- **Alternative:** agent-framework converter-pair and pydantic-ai `Model`/`Provider` split + `resolve_request_tools` centralized visibility table (`pydantic_ai_slim/pydantic_ai/models/__init__.py:1890`) keep translation per-adapter and cap monolith growth.
- **Best-fit:** Monolith when one team owns the write path and observability across semconv dialects matters most; mapper chain when the interop surface is many vendors that evolve independently.

### 4. Fresh-Client-Per-Call vs Pooling

- **Benefit of fresh:** crewai `MCPToolResolver._resolve_native` → `MCPNativeTool` closure-captured `_client_factory` (`lib/crewai/src/crewai/mcp/tool_resolver.py:417`) + `MCPClient` (`lib/crewai/src/crewai/mcp/client.py:44`) eliminates transport-level races, proven by `test_each_invocation_gets_fresh_client` at `lib/crewai/tests/mcp/test_mcp_config.py:187`. agent-framework `BaseChatClient` wrapping similarly avoids shared mutable session.
- **Cost:** TLS/handshake overhead for high-churn tools; `cache_tools_list` (`lib/crewai/src/crewai/mcp/client.py:44`) only mitigates discovery. openai-agents-sdk mitigates via shared `http_client` pool (`src/agents/models/openai_provider.py:38`) and per-loop WS cache (`src/agents/models/openai_provider.py:127`).
- **Best-fit:** Fresh-client default for correctness; opt-in pooling with bounded reconnect for hot paths.

### 5. Typed Pydantic/ABC Contracts vs Lightweight Dynamic Config

- **Benefit of heavy typing:** crewai `MCPServerStdio | MCPServerHTTP | MCPServerSSE` discriminated union (`lib/crewai/src/crewai/mcp/config.py:12`), pydantic-ai `ModelProfile` TypedDict (`pydantic_ai_slim/pydantic_ai/profiles/__init__.py:47`) and `ModelSettingsUnion` (`letta/schemas/model.py:550` analogue) give editor support, static validation, and version-pinned docs.
- **Cost:** Verbosity and merge/validation complexity (`pydantic_ai_slim/pydantic_ai/models/__init__.py:864` three-layer merge + `supported_native_tools` intersection; temporal `DataStore.Validate()` exactly-one check at `common/config/persistence.go:170`). Adding a field touches many `validate`/`register` sites.
- **Alternative:** temporal `CustomDatastoreConfig.Options map[string]any` (`common/config/config.go:467`) maximizes flexibility but defers validation to runtime/factory implementation.
- **Best-fit:** Strong typing for public SDK surfaces; untyped bag for operator-provided escape hatches where schema cannot be known ahead.

### 6. Bundle-Size/Eager Import vs Lazy/Dynamic Discovery

- **Benefit of eager/static:** langfuse `bootstrapMcpFeatures()` at import time (`web/src/features/mcp/server/bootstrap.ts:70`) and upfront `MCP_FEATURES` array (`web/src/features/mcp/server/bootstrap.ts:13`) guarantee tree-shaking visibility, TypeScript exhaustiveness, and duplicate detection at startup. opa `init()` registration is analogous.
- **Cost:** Fat bundle (15 features always loaded), no incremental rollout behind flag without rebuild, fragile import side-effect ordering (noted at `web/src/features/mcp/server/registry.ts:83` guard).
- **Alternative:** `importlib` entry-points / file-system glob discovery (proposed in future considerations for all three) would enable third-party feature packages without core edits, at cost of sandboxing and version coordination.

## Decision Guide

### When to make protocols core abstractions

- Your product *is* the protocol (observability ingestion, workflow persistence, policy engine REST API). If clients must speak `DataStoreFactory` (`common/persistence/persistence_interface.go:32`) or `OtelIngestionQueue` (`packages/shared/src/server/queues.ts:405`) to be useful, own the contract and version it.
- You maintain multiple production backends that must be interchangeable (SQLite/Postgres/Cassandra in temporal; in-memory/Postgres/SQLite checkpoints in langgraph). Harness investment pays off.
- Reference: langgraph checkpoint (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:176`) vs langfuse queue contracts (`packages/shared/src/server/queues.ts:405`) — both correctly core-owned but only langgraph is adapter-interchangeable.

### When to make protocols adapters

- A family of interchangeable providers exists (LLMs, tool servers, transports) behind a single capability surface. Define the narrow `ABC`/`Protocol` once (`Model` at `pydantic_ai_slim/pydantic_ai/models/__init__.py:366`, `MCPServer` at `src/agents/mcp/server.py:542`, `BaseChannel` at `libs/langgraph/langgraph/channels/base.py:19`) and put every wire format in a leaf package/module.
- Consumers should pay only for adapters they use (monorepo leaf pattern, `python/packages/*` in agent-framework).
- Reference: agent-framework `BaseChatClient` + 20 provider packages (`python/packages/openai/`, `anthropic/`, etc.) — zero core edit to add `bedrock` or `ollama`.

### Choosing between the four models

| Situation | Choose | Key mechanism to adopt |
|-----------|--------|------------------------|
| Embeddable Python/TS SDK where community supplies adapters | Model A — Open DI / Structural | `Protocol` or `runtime_checkable` + `infer_model(Model|str)` instance passthrough (`pydantic_ai_slim/pydantic_ai/models/__init__.py:1540`) |
| Static Go binary, operator config selects built-ins | Model B — Global build-time registry | `RegisterPlugin`/`RegisterStorageBackend` + `PluginName` string key (`v1/runtime/runtime.go:95`, `common/persistence/sql/store.go:21`) plus `Abstract*Factory` escape hatch for out-of-tree |
| SaaS platform with curated Tier-1 vendors and managed telemetry/auth | Model C — Closed enum | Closed `enum`/`Literal` + exhaustive switch with `never` check (`packages/shared/src/server/llm/llmText.ts:545-599`) but expose at least one generic escape (custom `baseURL`, `Model` instance) |
| Frontend/edge that proxies to a service owning protocol reality | Model D — Gateway | Centralized client-options factory + typed-client guard (`src/api/agent-server-client-options.ts:52`, `src/api/no-direct-agent-server-calls.test.ts:32`) + per-service `backend.kind` branching (`src/api/mcp-service/mcp-service.api.ts:193`) |

### Whether adapters should be runtime-swappable

- **If the boundary is per-request** (model, store, session, compaction, auth on redirect via `createSecureLlmFetch` at `packages/shared/src/server/llm/secureLlmFetch.ts:1`): Yes — make it DI-injectable and avoid `init()` global state. Agent-framework and openai-agents-sdk are exemplars.
- **If the boundary is per-deployment** (database engine, object store, FHIR terminology server): Build-time registration is fine; invest instead in config validation (`DataStore.Validate()` at `common/config/persistence.go:170`, `ExtraRoute` duplicate panic at `v1/plugins/plugins.go:790`) and startup `StateErr` reporting (`v1/plugins/plugins.go:127`), not hot-reload.

### How far to invest in conformance

- **One primary backend + few adapters:** Adapter-local rendering/assertion tests suffice (pydantic-ai `tests/AGENTS.md:153` pattern, agent-framework per-package suites). Add a policy exhaustiveness test (langfuse `in-app-agent-mcp-policy.servertest.ts:13`) if your adapter catalog must stay classified.
- **Multiple production backends for same contract:** Invest in a harness with capability detection (langgraph `libs/checkpoint-conformance/.../validate.py:32`, temporal shared persistence suites at `common/persistence/tests/*.go`). Budget for it early; retrofitting `Store`/`Cache`/`Channel` harnesses (noted gaps at `libs/checkpoint/langgraph/store/memory/__init__.py:1` absence) is the most common missed deadline in this study.

## Practical Tips

### Patterns to copy

- **Adopt the "converter-pair without transport" rule** (`python/packages/hosting-mcp/AGENTS.md:18` `"does not provide server/routes/transport"`). Isolate `mcp_to_run`/`mcp_from_run` (`python/packages/hosting-mcp/.../_conversion.py:19`), `AGUIEventConverter`, or `map_from_mcp_params` (`pydantic_ai_slim/pydantic_ai/_mcp.py:22`) as pure functions testable without network. Copy this any time the app owns SSE/auth/lifecycle.
- **Make `*Store`/`*Channel`/`*Serde` boundaries `ABC` for gradual optional-method adoption** (`BaseCheckpointSaver` at `libs/checkpoint/langgraph/checkpoint/base/__init__.py:176` documents `DeltaChannel` warnings inline) but keep `SerializerProtocol`/`ChannelProtocol`/`Session` as `Protocol` for structural flexibility (`libs/checkpoint/langgraph/checkpoint/serde/base.py:6`, `src/agents/memory/session.py:16`). Copy the mixed strategy, not one or the other.
- **Standardize on per-adapter rendering assertions and a profile-resolution snapshot** (pydantic-ai `tests/test_tool_availability_portability.py:1449`, `tests/profiles/test_resolution_matrix.py:114`). Copy the rule: every forwarded `ModelSettings`/`ModelProfile` field gets a case in its support test (`pydantic_ai_slim/pydantic_ai/models/AGENTS.md:31`). This catches wire-vs-profile drift faster than generic integration tests.
- **Implement the generic `Custom*Config` escape hatch alongside your closed switches** (temporal `CustomDatastoreConfig` at `common/config/config.go:467`, openai-agents-sdk `MultiProviderMap` at `src/agents/models/multi_provider.py:44`). Even if 99% of users use built-ins, the one team with an internal fork needs the hatch to avoid forking core.
- **Add a policy/classification exhaustiveness test** like langfuse `web/src/__tests__/server/unit/in-app-agent-mcp-policy.servertest.ts:13` ("every registry tool classified exactly once") and openhands' architectural guard (`src/api/no-direct-agent-server-calls.test.ts:32`). These are the cheapest durable gates the study found.
- **Expose capability-gated, capability-detected harness** from day one for persistence/queue/search families (langgraph `Capability` enum at `libs/checkpoint-conformance/.../capabilities.py:15`, `validate` runner at `.../validate.py:32`). Even if only one adapter ships, the harness prevents capability mismatch later (`acopy_thread` forgetting at `libs/checkpoint/.../validate.py:82` silent-pass noted).

### Patterns to avoid or delay

- **Do not introduce a closed provider/transport enum unless you also provide an instance-escape hatch.** The recurring failure — letta `ProviderType` (22 values) without registry (gap at `letta/settings.py:496` only `summarizer`/`experimental_check` slots) and langfuse `LLMAdapter` closed switch — forces every new provider through a core PR. Delay the enum until you need exhaustive telemetry/docs; start with the instance path.
- **Do not build a single monolithic processor for a new signal.** Langfuse's `OtelIngestionProcessor.ts:241` (3636 lines) and pydantic-ai's `resolve_request_tools` table (`pydantic_ai_slim/pydantic_ai/models/__init__.py:1890`) show the cost of central visibility logic. Prefer mapper-per-semconv decomposition from the start; the monolith rarely decomposes without a migration.
- **Do not hide static wiring behind "registry" terminology.** Langfuse `ToolRegistry` (`web/src/features/mcp/server/registry.ts:72` enforcing uniqueness) is called a registry but is statically populated at import (`bootstrap.ts:30`). If discovery is not dynamic, call it a manifest and document that adding a feature requires `bootstrap.ts` edit plus `mcpPolicy.ts:27` entry — otherwise contributors mis-expect plugin scanning.
- **Do not multi-wrap via monkey-patching.** Crewai `wrap_agent_with_a2a_instance` (`lib/crewai/src/crewai/a2a/wrapper.py:97` with `MethodType` replacement at `166`) keeps agent hierarchy stable but buries interception order and makes double-wrap fragile. Prefer composition/decorator (`WrapperModel` at `pydantic_ai_slim/pydantic_ai/models/wrapper.py:32`, `InstrumentedModel`) where stacking semantics are explicit.

### Decision rules for choosing between main approaches

- **"Will a third party implement this boundary?"** → If yes, pick Model A (open DI) + narrow contract + typed but non-exhaustive `ModelSettingsUnion`-style bag. If no (SaaS-managed), Model C (closed enum) is cheaper and more correct.
- **"Is the adapter selected per request or per deployment?"** → Per request → DI (langgraph `Pregel(checkpointer=...)`, openai-agents-sdk `RunConfig(model_provider=...)`). Per deployment → global registry is acceptable if you add a harness and startup validation.
- **"Does the family have a subset-capable surface (prune/copy/Delta, vector search, TTL)?"** → Add `Capability` detection immediately (`libs/checkpoint-conformance/.../capabilities.py:15`) rather than versioning the interface.
- **"Is there a 'which protocol are we speaking' string on the wire (OTel semconv, A2A `X-A2A-Extensions` at `lib/crewai/src/crewai/a2a/extensions/registry.py:51`, MCP schema `v0_8`/`v0_9` at `lib/crewai/src/crewai/a2a/extensions/a2ui/schema/...`)?"** → Version-gate the adapter (`AGUIAdapter.ag_ui_version` at `pydantic_ai_slim/pydantic_ai/ui/ag_ui/_adapter.py:237`, `VercelAIAdapter.sdk_version` at `pydantic_ai_slim/pydantic_ai/ui/vercel_ai/_adapter.py:149`) and implement `skip_unknown_tagged_items` forward-compat.

### Caution signs that the boundary is becoming brittle

- `validate`/`register` functions gain a new `case`/`branch` for every feature (`resolve_request_tools` at `pydantic_ai_slim/pydantic_ai/models/__init__.py:1890` table growth; `llmText.ts:545` switch growth) rather than delegating to adapter-supplied strategy/resolver.
- Adapter capability omission silently degrades: temporal `archiverProvider` caching forever (`common/archiver/provider/provider.go:69`) so config changes are invisible, or langgraph `prune` causing `DeltaChannel` to `from_checkpoint(MISSING)` (`libs/langgraph/langgraph/channels/delta.py:131`) and reconstruct as empty with no error.
- Interop docs scatter across `AGENTS.md` shards with no single `docs/interop-boundaries.md` (noted as gap in 8 of 10 sources). When newcomers ask "how do I add a provider?" and the answer cites 4 files/3 registries, specification debt has arrived.
- Error mapping relies on substring matching (`letta/adapters/anthropic`: `tests/adapters/test_letta_llm_stream_adapter_error_handling.py:209` keyword checks for `"tokens allowed"` / `"context exceeded"`) rather than structured codes.
- Runtime swappability tested only via constructor (`Agent(client=...)` at `python/packages/core/agent_framework/_agents.py:813`) and never via config reload/discovery (observed in letta `MCPToolResolver` at `lib/crewai/src/crewai/mcp/tool_resolver.py:59`, agent-framework factory tests at `python/packages/core/tests/core/test_clients.py:59`).

## Anti-Patterns / Caution Signs

- **Exhaustive hard-coded fallback that silently poisons.** Crewai's `_LEARNED_RESPONSES_ONLY_MODELS` set (`lib/crewai/src/crewai/llms/providers/openai/completion.py:65`) retaining 404 state per process for the session, and `opneai/` typofallthrough to LiteLLM (`lib/crewai/src/crewai/llm.py:468`), hide routing errors as remote API failures. Signal: provider dispatch state is process-global and learned, not declared.
- **Transport negotiation fallback that masks misconfiguration.** Agent-framework A2A `minimal_agent_card(url)` fallback (`python/packages/a2a/agent_framework_a2a/_agent.py:303`) improves demo success but succeeds silently when binding mismatches should surface as warnings. Signal: fallback path logged but not surfaced to caller.
- **Silent drop on unknown tag with forward-compat flag.** Pydantic-ai `AGUIAdapter` `skip_unknown_tagged_items` swallow (`pydantic_ai_slim/pydantic_ai/ui/ag_ui/_adapter.py:276`) can hide genuinely malformed items that coincidentally carry unknown tags. Signal: `UserWarning` rather than structured telemetry.
- **Hard-coded streaming dispatch as second registry.** Letta's `SimpleLLMStreamAdapter`/`LettaLLMStreamAdapter` `if provider_type in [...]` (`letta/adapters/letta_llm_stream_adapter.py:81`, `letta_llm_stream_adapter.py:97`) duplicating the factory's `match` means adding a `ProviderType` without updating two files yields `ValueError` at invocation, not at config validation. Signal: same enum dispatched in multiple exhaustive lists.
- **Per-call isolation paying reconnect on hot paths without pooling option.** Crewai fresh-client-per-invocation (`lib/crewai/src/crewai/mcp/tool_resolver.py:417`) and agent-framework layered wrapping (`ChatTelemetryLayer → FunctionInvocationLayer → ChatMiddlewareLayer` at `python/packages/ag-ui/agent_framework_ag_ui/_client.py:115`) are correct defaults, but the study finds no source offering an opt-in pool/batched alternative. Signal: TLS/handshake cost on high-churn tool observably added but not tunable.
- **Intercept via `MethodType` monkey-patch.** Crewai A2A wrapper (`lib/crewai/src/crewai/a2a/wrapper.py:166`) replacing `execute_task`/`kickoff` and restoring in `finally` entangles interception order. Signal: wrapper stacking or re-entry tests missing.
- **Global mutable `init()` map without hermetic test helper.** OPA `registeredPlugins` (`v1/runtime/runtime.go:68` `sync.Mutex`) / Temporal `supportedPlugins` (`common/persistence/sql/store.go:18`) with `panic("already registered")` (`common/persistence/sql/store.go:23`) collide across parallel tests. Signal: `grep RegisterPlugin` → multiple parallel tests without `ResetTargetPlugins`-style reset.
- **Auth split contract (`NewClient` once, `Prepare` per request) not as testable invariant.** OPA `rest.HTTPAuthPlugin` (`v1/plugins/rest/rest.go:41` doc `"MUST NOT perform per-request"` vs `"MUST be in Prepare"` clarified in `CHANGELOG.md:735`) and langfuse `createSecureLlmFetch` stripping on cross-origin redirect (`packages/shared/src/server/llm/secureLlmFetch.ts:1` via `llmText.ts:306`) are correctness-critical but have no reusable conformance helper. Signal: plugin authors copy-paste sample but never validate the two-phase invariant.

## Per-Source Notes

- **agent-framework (7):** Reference implementation for Python adapter-layer design. Core `BaseChatClient` requires only `_inner_get_response` (`python/packages/core/agent_framework/_clients.py:217`) so every protocol (A2A `agent_framework_a2a/_agent.py:209`, AG-UI `_client.py:115`, MCP `_mcp.py:424`, 20 provider packages) is a symmetrical `BaseChatClient` subclass. Static `import` is replaced by structural typing for extensibility; tradeoff is `MonoRepo` CI cost and middleware ordering sensitivity (`MiddlewareBundle` at `_middleware.py:745` as safeguard). Key evidence for "instance-addable without core edits" thesis. Isolated weakness is lack of harness (`test_checkpoint_storage_protocol_compliance` at `test_checkpoint.py:137` is only storage-level).

- **crewai (7):** The clearest example of dual-layer correctness: typed `MCPServerStdio | HTTP | SSE` union (`lib/crewai/src/crewai/mcp/config.py:12`) and `BaseTransport(ABC)` (`lib/crewai/src/crewai/mcp/transports/base.py:37`) on one side, hard-coded `SUPPORTED_NATIVE_PROVIDERS` (`lib/crewai/src/crewai/llm.py:327`) + `provider_mapping` (`lib/crewai/src/crewai/llm.py:432`) on the other. ## Open Questions

- **Do closed enums want instance-escape hatches in every surface?** Pydantic-ai proves `infer_model(Model|str)` (`pydantic_ai_slim/pydantic_ai/models/__init__.py:1540`) preserves extensibility alongside `KnownModelName` (`.../_known_model_names.py:13`), and temporal proves `CustomDatastoreConfig` (`common/config/config.go:467`) preserves it alongside string-keyed factories. Crewai, letta, and langfuse have only the closed side — is the absence deliberate (correctness over forklift) or deferred? No ADR was found in any of the three except `lib/crewai/src/crewai/a2a/extensions/base.py:1` code-level docs distinguishing `A2AExtension` hooks from `X-A2A-Extensions` header. (Sources: crewai `lib/crewai/src/crewai/llm.py:327`, letta `letta/schemas/enums.py:53`, langfuse `packages/shared/src/server/llm/types.ts:246`; gap noted in all three per-source gaps.)

- **Is runtime hot-swap ever a real requirement?** No source demonstrates swapping code without rebuild. OPA and temporal both confirmed restart-required; agent-framework, openai-agents-sdk, pydantic-ai swap per-request instances via DI but not via config-driven plugin reload. If your dimension requires "swappable at runtime via config," every studied source would score lower — the question needs operational refinement (instance per-run vs code hot-reload).

- **What is the boundary versioning story?** Only langgraph `Checkpoint.v` (`LATEST_VERSION 4` at `libs/langgraph/langgraph/pregel/_checkpoint.py:23` + `LATEST_VERSION 2` legacy at `libs/checkpoint/.../base/__init__.py:811`), langfuse Fern versions (`fern/apis/...` spec history), and temporal bundle manifest dual-format (`RegoVersion` + `FileRegoVersions` at `v1/bundle/bundle.go:147`, proto vs JSON at `756`) document versioning. None exposes capability negotiation (compare `ModelProfile` flags in pydantic-ai `.../profiles/__init__.py:47` vs OPA `ast.Capabilities` not in adapter interfaces). How a vNext client avoids breaking a v1 adapter is unresolved.

- **Where is the single "adding a protocol" checklist?** Per-source `AGENTS.md` shards tell `where` to put provider code (pydantic-ai `models/{provider}.py` rule at `.../models/AGENTS.md:3`, agent-framework `python/AGENTS.md:50`, langgraph `AGENTS.md` dependency map) but not the `steps + tests + docs + telemetry + deprecation` lifecycle. No source ships the central interop spec proposed in 7 of 10 future-considerations lists (e.g., crewai `docs/edge/en/interop-boundaries.mdx`, agent-framework consolidated diagram, temporal `docs/architecture/persistence-adapter.md`). Is this intentionally distributed?

- **Dormant intent on community providers?** Lettas `settings.plugin_register_dict` (`letta/settings.py:496` only two slots) and crewais `SUPPORTED_NATIVE_PROVIDERS` (`lib/crewai/src/crewai/llm.py:327`) versus MCP/A2A proper registries (crewai `A2AExtension` at `lib/crewai/src/crewai/a2a/extensions/base.py:57`, langfuse MCP registry at `web/src/features/mcp/server/registry.ts:72`) suggest LLM boundaries were intentionally kept closed. Searched `AGENTS.md`, `Plugin` RFCs, and extension guides in each — no design doc found stating why LLM provider extension is not registry-driven while MCP/tool extension is. (Sources: letta `grep plugin_register`, crewai `grep entry_points/pluggy` → none; noted as question in both.)
