## Executive Summary

Seven systems answer "keep trying or hand off?" with a shared skeleton — persist inside explicit budgets, degrade before failing, make every stop typed and observable — but they implement that skeleton at three different architectural layers depending on product shape. **Library harnesses** (agent-framework, crewai, openai-agents-sdk, letta) put budgets in the run loop and resolve exhaustion in-band: force a final answer, synthesize a handler output, or fail fast. **Infrastructure platforms** (temporal, langgraph) move persistence into a durable substrate (history events, checkpoints) so that exhaustion, pauses, and operator stops become *resumable states* rather than losses. **Client surfaces** (openhands' frontend) neither retry the loop nor replan; they configure server-side budgets, render outcomes like `capped`/`interrupted`, and convert every give-up into an explicit human decision.

Scores span 7–10: temporal earns 10 for durable, failover-safe, fully observable retry semantics; openai-agents-sdk earns 9 for fail-closed replay governance and validated escalation handlers; agent-framework, crewai, langgraph, and letta each earn 8 with different residual gaps (log-string stop reasons, uncoordinated retry knobs, static policies, missing transient-retry fallbacks); openhands earns 7 because the core loop lives in a sibling repo and several client-side decisions contradict its own bounded-retry discipline. The strongest convergence: nobody lets an agent loop forever by accident — six of seven bound loops by default and require explicit opt-in to unbounded operation. The deepest divergence is not *how hard* agents try but *where the reason for stopping lives*: as a queryable typed datum (temporal's `RetryState`, letta's `StopReasonType`, langgraph's state history), or as a log string humans must grep (agent-framework, openai-agents-sdk at DEBUG).

## Core Thesis

Persistence-vs-escalation philosophy splits along one axis: **is persistence a policy executed by a loop, or a property guaranteed by a substrate?**

Loop-policy systems (agent-framework, crewai, letta, openai-agents-sdk) treat each failure as a decision the harness makes now: count it, classify it, either feed it back to the model or stop, and record why. Their signature move is **graceful degradation at budget exhaustion** — spending one more LLM call to force a usable answer (`python/packages/core/agent_framework/_tools.py:3307-3325`; `lib/crewai/src/crewai/utilities/agent_utils.py:376-433`) rather than raising. This optimizes for returning *something*, at the risk of laundering incomplete work into confident output.

Substrate-guarantee systems (temporal, langgraph) invert the problem: they checkpoint everything first (`libs/langgraph/langgraph/pregel/_loop.py:1132-1148`; `service/history/historybuilder/event_factory.go:293-380`), so retries become time-shifted timer tasks instead of busy loops, pauses survive process death by default, and "why did it stop?" is a first-class enum persisted into history (`service/history/workflow/retry.go:44`). This optimizes for durability and auditability, at the cost of machinery complexity and defaults biased toward unlimited retrying that can mask systemic bugs (`common/retrypolicy/retry_policy.go:76-81`).

Surface-escalation clients (openhands frontend) complete the spectrum: they refuse to persist silently on the user's behalf (`src/stores/error-message-store.ts:4-9`) and invest instead in *classified non-retry paths* and recovery affordances — the recognition that in a UI, an unexplained infinite spinner is worse than a fast, actionable failure.

All three layers converge on the same terminal contract: **a stop must be typed, attributed, and visible**. Where sources diverge is who holds the continuation decision — deterministic harness code (letta v3 removed model-controlled heartbeats entirely, `letta/agents/letta_agent_v3.py:105`), the model reacting to fed-back errors (letta, crewai, openai-agents-sdk tool failures), configured predicates (langgraph `should_continue`-style handlers, openai-agents-sdk retry policies), or operators and rules engines (temporal pause/reset/DLQ). The dimension's driving question — can persistence be tuned per task? — is answered yes by all seven, but only via composition of primitives everywhere except openhands' explicit confirmation ladder (`NeverConfirm`/`AlwaysConfirm`/`ConfirmRisky`, `src/api/agent-server-adapter.ts:593-605`) and agent-framework's mode-gated autonomy (`_mode.py:15-71`); no source ships a single named autonomy dial spanning retries + approvals + budgets.

## Approach Models

Each source's approach model, expressed in this dimension's vocabulary (retry / replan / ask-for-help / delegate / pause / stop):

**temporal — infrastructure-managed time-shifted retry with operator escalation.** The server evaluates a validated `RetryPolicy` in one place (`RetryActivity`, `service/history/workflow/mutable_state_impl.go:6878-6963`) and materializes retries as future timer tasks, never held goroutines (`mutable_state_impl.go:6957-6963`). Exhaustion flips a typed terminal cause and routes internal tasks to a DLQ (`service/history/queues/executable.go:605-620`). Humans enter through operator APIs (PauseActivity/PauseWorkflow/ResetWorkflow, `service/frontend/workflow_handler.go:7166-7230`) and namespace rules that auto-pause misbehaving activities (`mutable_state_impl.go:10029-10085`). Replanning is deliberately absent — strategy belongs to workflow code.

**openai-agents-sdk — opt-in runner-managed retry with fail-closed replay governance.** Default persistence comes from provider transport retries; runner-managed retries require explicit `ModelSettings.retry` (`src/agents/model_settings.py:188`). A composable policy DSL (`src/agents/retry.py:304-461`) decides, gated by three hard vetoes protecting stateful/streaming requests from blind replay (`src/agents/run_internal/model_retry.py:440-479`). Tool failures persist by default as model-visible error outputs (`src/agents/tool.py:1863-1872`). Loop exhaustion escalates via `MaxTurnsExceeded` unless a keyed handler synthesizes a validated final output (`src/agents/run_error_handlers.py:50-55`). HITL pauses freeze into serializable `RunState` snapshots (`src/agents/run_state.py:749-851`).

**agent-framework — layered caps with graceful degradation and a typed human control plane.** Each nesting level carries its own cap: 40 tool iterations (`python/packages/core/agent_framework/_tools.py:95`), 10 harness-loop iterations (`_harness/_loop.py:122-127`), 100 workflow supersteps (`_workflows/_const.py:4`). Caps degrade gracefully — tools disabled, one final answer forced (`_tools.py:3307-3325`) — while multi-agent Magentic adds genuine stall-detection replanning via progress ledgers (`_orchestrations/_magentic.py:1116-1125,1156-1192`). Humans escalate through three typed channels: session-backed tool approvals, workflow `request_info` with checkpoint-based resume, and plan sign-off review (`_harness/_tool_approval.py:343-418`; `_magentic.py:956-958`).

**crewai — four-scope budgeted persistence with corrective feedback.** Distinct counters govern the ReAct loop (`max_iter=25`), whole-task retries (`max_retry_limit=2`), guardrail re-execution (`guardrail_max_retries=3`), and provider HTTP retries (`lib/crewai/src/crewai/agents/agent_builder/base_agent.py:304-306`; `lib/crewai/src/crewai/agent/core.py:255-258`; `lib/crewai/src/crewai/task.py:275-280`). Guardrail and parse violations become conversational context so the next attempt can fix the cause (`task.py:1394-1408`). A three-value `ToolFailurePolicy` (IGNORE/WARN/RAISE) resolves down a tool→task→agent→crew chain (`lib/crewai/src/crewai/tools/tool_failure.py:57-68,177-208`); deliberate aborts bypass retries via a passthrough exception tuple (`core.py:139-141`). Escalation to humans is pre-configured HITL loops plus durable flow pause/resume (`lib/crewai/src/crewai/flow/runtime/__init__.py:1524-1557`).

**langgraph — durable-substrate engine where escalation is configuration.** The engine refuses to choose a persistence strategy; it persists every superstep (`libs/langgraph/langgraph/pregel/_loop.py:1132-1148`) and exposes a tiered ladder: node-level `RetryPolicy` with backoff (`libs/langgraph/langgraph/pregel/_retry.py:573-683`) → graph-level error handlers converting failures into recovery tasks (`libs/langgraph/langgraph/pregel/_runner.py:222-239`) → hard stop on `recursion_limit` (`libs/langgraph/langgraph/pregel/main.py:3002-3011`) → cooperative drain (`libs/langgraph/langgraph/runtime.py:79-104`) → timeouts (`types.py:451-514`) → dynamic `interrupt()` for HITL (`types.py:851-974`). Exception subclasses route each path distinctly (`errors.py:148-199`).

**letta — harness-owned continuation with class-aware fail-fast.** All continue/stop logic concentrates in `_decide_continuation` (`letta/agents/letta_agent_v3.py:1967-2036`): tool calls continue the loop, plain responses end it, declarative tool rules override both. Failure handling is asymmetric by design — tool errors feed back for self-correction (`letta/services/tool_executor/tool_execution_manager.py:131-155`), context overflow triggers compaction-and-retry (`letta_agent_v3.py:1218-1294`), provider outages route through a circuit breaker to fallback models (`letta_agent_v3.py:1183-1213`), but unknown exceptions stop immediately ("prevent wasteful retry loops", `letta_agent_v3.py:1519-1521`). Dangerous actions escalate as persisted approval messages that survive restarts (`letta_agent_v3.py:1681-1709`). A credit gate stops runs with `insufficient_credits` before each paid step (`letta_agent_v3.py:333-339`).

**openhands (frontend) — configure budgets, observe outcomes, escalate to humans.** The client sends `max_iterations` (fallback 500) and enables server-side stuck detection at conversation start (`src/api/agent-server-adapter.ts:1122-1126`), then renders terminal states including `capped` and resumable `interrupted` goal loops (`src/types/agent-server/core/events/conversation-state-event.ts:82-97`). Transport persistence is automatic but classified: auth errors, 404s, and unsupported filters never retry (`src/hooks/query/use-settings.ts:145`; `src/hooks/query/use-backends-health.ts:160-171`); five consecutive health failures trip a persisted circuit breaker (`use-backends-health.ts:220-227`). Delegation failures return corrective `guidance` telling the agent how to recover rather than rejecting (`src/services/child-conversation-launch.ts:499-536`). Mid-run human escalation has a dedicated state, UI, and shortcuts (`AWAITING_USER_CONFIRMATION`, `src/components/shared/buttons/conversation-confirmation-buttons.tsx:16-135`).

## Pattern Catalog

### P1. Bounded-by-default with explicit unbounded opt-in
- **Problem:** runaway agents burning unbounded cost.
- **Demonstrated by:** agent-framework (40/10/100 caps; `None` requires deliberate opt-in, `python/packages/core/agent_framework/_tools.py:95`; `_harness/_loop.py:260-262`), crewai (`max_iter=25`), langgraph (`recursion_limit`, env-overridable default, `libs/langgraph/langgraph/_internal/_config.py:32`), letta (`DEFAULT_MAX_STEPS=50`, `letta/constants.py:75`), openai-agents-sdk (`DEFAULT_MAX_TURNS=10`, `src/agents/run_config.py:45`), temporal (defaults bounded by schedule-to-close deadlines even when attempts are unlimited, `common/retrypolicy/retry_policy.go:76-81`).
- **Why it works:** makes a runaway agent a *misconfiguration*, not an accident; validation rejects bad caps up front (agent-framework `_tools.py:1389-1409`; temporal admission validation `common/retrypolicy/retry_policy.go:103-141`).
- **Copy when:** building any autonomous loop. It is the closest thing the field has to a universal rule.
- **Overkill/risk when:** never really — but note the escape hatches differ in danger. `max_turns=None` (openai-agents-sdk `run_config.py:578-582`) removes the only loop-level stop with no compensating circuit breaker, which that source itself flags.
- **Evidence of strain:** openhands' WebSocket reconnect defaults to `maxAttempts ?? Infinity` (`src/hooks/use-websocket.ts:113-114`), internally contradicting its otherwise strict bounded discipline — mitigated only by delay-capping and jitter.

### P2. Graceful degradation at the cap: force a final answer instead of crashing
- **Problem:** budget exhaustion mid-task would otherwise discard all accumulated work.
- **Demonstrated by:** agent-framework sets `tool_choice="none"` and demands one final response without tools, falling back to literal text if even that fails (`_tools.py:3307-3325`); crewai appends a `force_final_answer` error and spends exactly one more LLM call (`lib/crewai/src/crewai/utilities/agent_utils.py:376-433`).
- **Related variants:** openai-agents-sdk error handlers synthesize outputs that pass the same guardrails/validation as organic finals (`src/agents/run_internal/run_loop.py:742-786`); letta's forced continuation injects "you must call X" heartbeats for required-before-exit rules (`letta/agents/letta_agent_v3.py:1624-1642`).
- **Why it works:** users get a usable artifact plus evidence rather than an exception; the caller distinguishes forced from natural completion only if the system says so.
- **Copy when:** user-facing products where partial answers beat errors.
- **Risk:** incomplete investigations get laundered into confident-looking output. CrewAI's own analysis warns there is no structured signal distinguishing forced answers beyond verbose logs; pair this pattern with typed stop reasons (P4).

### P3. Errors-as-feedback: self-correction over mechanical retry
- **Problem:** blind retries repeat identical failing calls.
- **Demonstrated by:** letta converts every tool exception into an `"error"` tool result placed back in context (`letta/services/tool_executor/tool_execution_manager.py:131-155`); crewai feeds parser and guardrail errors into messages/retry context (`lib/crewai/src/crewai/utilities/agent_utils.py:743-778`; `task.py:1394-1408`); openai-agents-sdk's `default_tool_error_function` does the same (`src/agents/tool.py:1863-1872`); langgraph error handlers turn failed tasks into normal state transitions handled by recovery nodes (`libs/langgraph/langgraph/errors.py:156-158`).
- **Why it works:** the LLM can fix bad arguments or violated constraints on the next attempt — replanning without a planner.
- **Copy when:** failures are argument- or constraint-shaped (schema violations, guardrail blocks).
- **Risk:** costs a full LLM step per mistake and cannot repair non-semantic faults (network, permissions). Temporal solves the same problem differently: application workers embed `NextRetryDelay` so the *expert* controls pacing while the server keeps accounting (`service/history/workflow/retry.go:48-67`).

### P4. Typed stop reasons as first-class data
- **Problem:** "why did it stop?" must be machine-queryable for operations and analytics.
- **Demonstrated by:** temporal persists a `RetryState` enum (`MAXIMUM_ATTEMPTS_REACHED`, `NON_RETRYABLE_FAILURE`, …) inside history events (`service/history/workflow/retry.go:44,96-110`; `event_factory.go:293-380`); letta shares one `StopReasonType` across loop, streaming wire, step table, and run-status derivation (`letta/schemas/letta_stop_reason.py:10-49`); langgraph gives each escalation path a dedicated exception type (`libs/langgraph/langgraph/errors.py:54-199`) and queryable `get_state_history()` (`main.py:1480-1531`); crewai emits typed events carrying `retry_count` and attempt numbers (`lib/crewai/src/crewai/events/types/llm_guardrail_events.py:34,70`).
- **Why it works:** fleet-wide questions ("how many runs died on budget?") become queries, not log greps.
- **Copy when:** anything operated at scale.
- **Counter-examples worth heeding:** agent-framework records stop reasons as log strings with an explicitly acknowledged gap (`_tools.py:3309-3312`, gap noted in its report); openai-agents-sdk logs retries at DEBUG behind default-on redaction (`model_retry.py:669-676`; `src/agents/_debug.py:13-20`). Both rank observability as their main deduction.

### P5. Durable human escalation as a resumable pause, not a crash
- **Problem:** asking a human takes hours or days; the run must not die waiting.
- **Demonstrated by:** all seven, in escalating durability. openai-agents-sdk freezes interruptions into versioned serializable `RunState` with an approval ledger (`run_state.py:749-851`); letta persists approval requests as transcript messages resumable after restarts (`letta/server/rest_api/utils.py:304-340`); langgraph's `interrupt()` persists position as a pending write requiring a checkpointer (`types.py:851-974`); agent-framework checkpoints workflows across process restarts (`_workflow_context.py:403-434`); crewai saves full flow state on `HumanFeedbackPending` (`flow/runtime/__init__.py:1524-1557`); openhands dedicates a UI state with duplicate-submission guards (`conversation-confirmation-buttons.tsx:16-135`); temporal records pause identity/reason/idempotency IDs in history (`pauseactivity/api.go:54-66`).
- **Why it works:** escalation becomes a state transition, so the persistence effort lands exactly where waits are longest.
- **Copy when:** always. The differentiator among mature systems is whether the *pending request itself* survives process death — the weaker versions (in-memory queues) break here.

### P6. Replay-safety and idempotency governance before any retry
- **Problem:** retrying non-idempotent work corrupts state or double-spends.
- **Demonstrated by:** openai-agents-sdk fails closed — stateful and already-streaming requests are hard-vetoed from replay without explicit approval (`model_retry.py:440-479`) and rewind sessions before each replay (`run_loop.py:2591-2600`); langgraph clears prior-attempt writes before every retry for at-most-once commit semantics (`_retry.py:614-615`); openhands claims delegation launches by `toolCallId` before network work so socket replays cannot double-launch billable conversations (`child-conversation-launch.ts:196-227`); temporal ignores stale-attempt timeouts by comparing attempt numbers (`timer_queue_active_task_executor.go:290-294`).
- **Why it works:** separates "keep trying" from "keep hammering/duplicating"; makes retry cost predictable.
- **Copy when:** any side-effectful tool or stateful conversation. This is the single biggest maturity marker separating the 9–10 scores from the 8s.
- **Risk:** ceremony — legitimate stateful retries need explicit approvals, friction by design (openai-agents-sdk's own tradeoff note).

### P7. Classify failures: transient vs decided/deliberate
- **Problem:** retrying decided failures wastes money; failing transient ones wastes availability.
- **Demonstrated by:** crewai's passthrough tuple keeps deliberate `ToolExecutionFailedError` out of the retry loop (`core.py:139-141`); langgraph's default predicate retries connection/5xx only (`_internal/_retry.py:1-29`); openai-agents-sdk's DSL encodes classification as composable policies (`retry.py:304-461`); openhands excludes invalid-key/logged-out/unsupported-filter errors (`use-backends-health.ts:160-171`); temporal validates non-retryable lists at admission (`common/retrypolicy/retry_policy.go:27-64`).
- **Why it works:** encodes operational scar tissue into code (openhands' git-sync comment explains why three retries once sat the page in a skeleton for two minutes, `use-git-sync.ts:24-29`).
- **Fragility warning:** crewai sniffs `litellm` by module-name prefix (`core.py:743`) — vendored/wrapped clients would silently change retry behavior. Prefer exception-type allowlists.

### P8. Circuit breakers and blast-radius limits over infinite persistence
- **Problem:** repeated futile attempts harm the system being retried against.
- **Demonstrated by:** openhands disables polling after 5 consecutive failures and persists the disabled state across refreshes (`use-backends-health.ts:220-227`); letta's circuit breaker reroutes providers to fallbacks with Redis-backed failure counting (`letta/services/llm_router/llm_router_client_base.py:42-47`); temporal enforces minimum continue-as-new spacing and slower resource-exhaustion policies (`mutable_state_impl.go:2974-2997`; `executable.go:94-101`); openhands' parallel sockets jitter to avoid lockstep retries (`use-websocket.ts:125-136`); openai-agents-sdk suppresses hidden provider retries whenever runner-managed retries own the attempt (`model_retry.py:516-554`).
- **Why it works:** distinguishes liveness (keep the session) from pressure (protect the backend).
- **Copy when:** multiple concurrent agents or flaky dependencies. Jitter-under-contention is cheap and universally applicable.

## Key Differences

**Where retries live.** Temporal centralizes retry decisions server-side in pure functions of persisted state (`retry.go:31-112`), so any server resumes another's loop after failover. LangGraph pushes policy to node declarations (`add_node(..., retry_policy=...)`, `state.py:275-332`). openai-agents-sdk makes runner-level retry strictly opt-in and coordinates exactly one retry owner per attempt (`model_retry.py:539-554`). crewai scatters four independent counters across scopes. letta largely refuses mechanical retry, delegating transport resilience to SDK configs and the router breaker (`anthropic_client.py:440-483`). Same vocabulary, four different owners.

**Who decides to keep going.** Deterministic harness logic (letta v3 explicitly removed model-controlled heartbeats: "No heartbeats (loops happen on tool calls)", `letta_agent_v3.py:105`) versus model-driven continuation (judge verdicts keep agent-framework loops alive, with ambiguity deliberately biasing toward MORE, `_loop.py:192-199`) versus operator/config-driven (temporal's conditional retry policies flipped by dynamic config during overload windows, `common/util.go:194-210`). Letta's v1/v2→v3 evolution is the clearest evidence this is a live debate: model flexibility was traded for determinism guarantees.

**What happens at exhaustion.** Force-a-final-answer (agent-framework, crewai) vs raise a typed exception with optional handler synthesis (openai-agents-sdk `MaxTurnsExceeded` + handlers) vs emit a terminal stop reason and mark the run (letta `max_steps`) vs start a fresh run with attempt+1 (temporal workflow retries, `workflow_task_completed_handler.go:888-921`) vs surface `capped` to a human in the UI (openhands). These are genuinely different products of the same budget concept.

**Replanning support.** Only agent-framework implements automated replan machinery: LLM-produced progress ledgers detect stalls, then reset context and regenerate plans with typed events (`_magentic.py:1116-1125,1156-1192`). CrewAI bounds a planning refine loop but falls back to proceeding with the current plan to avoid deadlock (`reasoning_handler.py:438-444`). LangGraph provides the *hooks* (error handlers, `Command`) but no primitive. Everyone else delegates replanning to the model reacting to error feedback (P3) or to graph/application authors — three sources independently list "no first-class replanning" as their top-band blocker.

**Autonomy dials.** OpenHands exposes the most explicit ladder: confirmation mode selecting NeverConfirm / AlwaysConfirm / risk-threshold ConfirmRisky, plus sub-agent gating (`agent-server-adapter.ts:593-644`). Agent-framework gates looping by operating mode (plan = interactive, execute = autonomous, `_mode.py:15-71`) and hands off with per-agent turn limits (`_handoff.py:819-848`). Temporal's rule engine auto-pauses matched activities — an autonomy dial operators control post-deployment (`mutable_state_impl.go:10029-10085`). The other four explicitly lack a single dial; their reports recommend composing primitives manually or adding presets.

**Default posture.** Temporal defaults to effectively-unlimited retries within deadlines (durability-first); letta defaults to fail-fast on unknown errors (cost-first, with an in-code rationale comment); openai-agents-sdk defaults retries off at the runner (app-developer-sovereignty). This split tracks product shape: a workflow platform selling durability, a hosted service controlling spend, and a library refusing to surprise its embedders.

## Tradeoffs

- **Graceful degradation vs honest signals.** agent-framework and crewai buy termination-with-artifact at the cost of ambiguous completions (`_tools.py:3307-3325`; `agent_utils.py:376-433`), while letta's typed stop reasons make forced vs natural endings queryable (`letta_stop_reason.py:26-49`) but its forced continuations still explain themselves in message text rather than telemetry (`letta_agent_v3.py:2006-2032`). Best-fit: degradation for consumer products, typed reasons everywhere regardless.
- **Fail-fast vs always-retry defaults.** letta's refusal to blind-retry prevents runaway spend but leaves transient DB/provider faults fatal outside the narrow fallback path (`letta_agent_v3.py:1519-1521` vs `1212-1213`); temporal's unlimited default maximizes completion but "can mask systemic bugs for a long time" (`common/retrypolicy/retry_policy.go:76-81`). openai-agents-sdk sidesteps by making it a documented choice (`model_settings.py:188`). Failure modes are mirror images: silent degradation vs silent masking.
- **Substrate durability vs complexity.** LangGraph's checkpoint-per-superstep makes every policy recoverable but correctness depends on subtle invariants across ~2000-line loop files (`_loop.py`), and exit-mode durability intentionally loses crashes (`types.py:89-95`); loop-policy systems are simpler but lose mid-run state on death (letta rolls back partial steps on exception, `letta_agent_v3.py:1513`). Choose by MTBF of your host and value of partial progress.
- **Centralized policy vs per-site tuning.** OpenHands' dozens of per-hook `retry:` values give precise local control yet make global posture unauditable; temporal's single shared retry vocabulary (`common/backoff/retrypolicy.go:34-79`) makes system-wide questions answerable but needs dynamic config for local overrides. crewai shows the failure endpoint of scattering: five counters with no documented interaction order (does a provider retry consume a `max_iter` iteration? No evidence found).
- **Safety vetoes vs retry agility.** openai-agents-sdk's three-veto replay governance prevents corrupting server-side conversation state (`model_retry.py:443-479`) but makes legitimate stateful retries require explicit approvals; langgraph's aggressive default predicate (unknown exceptions retry, `_internal/_retry.py:28-29`) favors liveness but is risky around non-idempotent tool nodes. Both positions are defensible; mixing them unknowingly is not.
- **Budget accounting subtleties.** agent-framework persists function-call budgets across approval pauses specifically so HITL round-trips can't evade caps (`_tools.py:101,3193`) but accepts best-effort overshoot on parallel batches (`_tools.py:1348-1351`); crewai's never-reset `_times_executed` turns task retries into an agent-lifetime budget — cheap, surprising, invisible (`core.py:208,745-746`). Budgets need stated scope and reset semantics more than they need particular numbers.
- **Escalation ergonomics vs mechanism stability.** LangGraph owns the interrupt *mechanism* while agent-level HITL vocabulary recently migrated to another package (`prebuilt/interrupt.py:7-10` deprecation), creating version-skew risk; openai-agents-sdk keeps mechanism and policy together but nested-agent approvals bubble to outer runs, surprising callers (`docs/human_in_the_loop.md:5-7`).

## Decision Guide

**Choosing a persistence architecture:**
- Building a library/embeddable harness → follow openai-agents-sdk: bounded loops by default, retries opt-in via policy objects, typed escalation handlers whose outputs pass the same validation as finals, and fail-closed governance around any stateful replay.
- Building a long-running/multi-day product → follow temporal or langgraph: persist first (checkpoints/history), then express retry/pause/stop as recoverable states. If you cannot build the substrate, use one — mid-run pausability is not retrofit-friendly.
- Building a consumer-facing surface over someone else's loop → follow openhands: classify failures, escalate every give-up to an actionable human decision, and never retry silently on the user's behalf.
- Building multi-agent orchestration → agent-framework's Magentic is currently the only studied source with genuine automated stall-detection replanning; otherwise budget a planning refine loop (crewai-style, with anti-deadlock fallback) or accept model-in-loop self-correction (P3).

**Choosing a default posture:**
- Side-effectful tools or non-idempotent writes → fail-closed (openai-agents-sdk vetoes; openhands idempotency ledger) and classify aggressively.
- Pure/read-mostly LLM calls → retry-with-backoff defaults are fine (langgraph's predicate; temporal deadlines).
- Cost-sensitive hosted service → letta's stance: reserve mechanical persistence for understood-recoverable classes (context overflow, provider blips), fail fast otherwise, add budget gates (`insufficient_credits`, `letta_agent_v3.py:333-339`).

**Choosing where humans enter:**
- Pre-configured gates (approvals per tool/task) when actions are predictably dangerous — letta `default_requires_approval`, openhands `ConfirmRisky`.
- Operator-initiated controls when the system outlives individual requests — temporal pause/reset/DLQ.
- Rule-triggered suspension when volume makes manual watching impossible — temporal namespace rules auto-pausing matched activities.
- What nobody does yet: runtime promotion of a task to HITL *after N failures* (crewai explicitly confirms HITL is strictly pre-configured, `task.py:233`). If you need adaptive supervision today, build it on rule engines or event streams.

## Practical Tips

- **Give every loop a number and a terminal action.** Every studied system pairs ceilings with defined exits (force answer / raise / stop reason / new run). An unpaired counter is a hang.
- **Spend one extra call on degradation.** The force-final-answer move (`_tools.py:3307-3325`; `agent_utils.py:384-415`) is cheap, test-covered in both sources, and dramatically improves perceived reliability. Test that no orphaned function calls leak when tools get disabled (agent-framework does exactly this, `test_function_invocation_logic.py:1574-1637`).
- **Make stop reasons enums, not log lines.** Copy letta's single taxonomy shared across API, stream, DB, and status derivation (`letta_stop_reason.py:10-49`) or temporal's `RetryState` in history. Retrofitting this later means parsing message text (the regret both agent-framework and letta report for continuation reasons).
- **Clear or claim state before retrying.** Write-clearing (langgraph `_retry.py:614-615`), session rewind (openai-agents-sdk), idempotency claims (openhands), or attempt-number comparison (temporal) — pick one per side-effect boundary.
- **Jitter and desynchronize concurrent retries**, especially multiple sockets/agents hitting one backend (`use-websocket.ts:125-127`).
- **Separate per-attempt metrics from whole-life metrics.** temporal's `activity_task_fail` vs `activity_fail` and single-attempt vs schedule-to-close latency split (`common/metrics/metric_defs.go:968-982`) is the reference shape for answering "is it failing often?" separately from "is it failing forever?".
- **Persist escalation requests, not just flags.** Approval state should survive restarts (P5); in-memory pending queues are the most common maturity cliff.
- **Record usage truthfully across retries.** openai-agents-sdk surfaces failed attempts as zero-token usage entries (`model_retry.py:338-350`) so cost dashboards don't lie about attempts.
- **Document knob interactions.** The recurring audit finding across crewai, openai-agents-sdk, and letta is not missing knobs but unstated ordering between them (provider retries vs iterations vs turn budgets). Publish an effective-config view or preset bundles.

## Anti-Patterns / Caution Signs

- **Unbounded defaults hiding in corners.** openhands' `Infinity` reconnect and openai-agents-sdk's `max_turns=None` show that one unbounded path undermines an otherwise disciplined story. Audit for them.
- **Counters that never reset.** crewai's `_times_executed` bleeds a lifetime budget across tasks (`core.py:208,745-746`); temporal notes failover resetting attempt counts restarts DLQ budgets (`executable.go:388-397`). Any cross-scope counter sharing needs explicit semantics and tests.
- **Classification by string sniffing.** Module-prefix checks for provider errors (`core.py:743`) and regex-per-error DLQ patterns with documented perf warnings (`docs/admin/dlq.md:16-19`) couple behavior to package layout or cost you throughput.
- **Conflating distinct terminal states.** openhands mapping `STUCK`→`ERROR` "for now" destroys the stuck-but-alive signal in the UI (`use-agent-state.ts:30-35`); temporal works in the opposite direction, splitting timeout-vs-non-retryable causality explicitly (`mutable_state_impl.go:6896-6907`). Losing distinctions is easy; recovering them is not.
- **Silent degradation of config.** Invalid tool-failure policies quietly behaving as WARN (`tool_failure.py:200-207`) and dead settings like letta's unreferenced `multi_agent_send_message_max_retries` (`settings.py:350`) make deployments mean something other than what operators wrote. Reject or implement.
- **Schema/test drift on defaults.** letta's stale test asserting `max_steps == 10` against a code default of 50 (`tests/test_letta_request_schema.py:19` vs `constants.py:75`) plus silently accepted zero/negative step counts (`test_letta_request_schema.py:33-45`) — validate budgets and pin defaults in tests.
- **Handler/escape-hatch subtleties nobody reads.** openai-agents-sdk handlers returning `None` fall through to raising anyway (`run.py:1489-1490`); agent-framework unbounded loops rely entirely on the predicate terminating (`_loop.py:260-262`). Document the fall-through loudly or assert on it.
- **Brittleness signs overall:** retry behavior changing when dependencies are vendored (string sniffing), persistence questions unanswerable from telemetry (DEBUG-only logging behind redaction), HITL reachable only if configured before launch, and error handlers that can form ping-pong cycles bounded only by the global step budget (langgraph's handler-loop caveat, `_runner.py:171-174`).

## Notable Absences

- **No unified autonomy abstraction.** Six of seven sources answer the driving question ("can persistence be tuned per task?") yes-but-through-composition; only openhands ships a named ladder (confirmation modes) and only agent-framework gates by operating mode. Three reports independently recommend preset bundles (e.g., cautious/balanced/aggressive) as the missing dial.
- **No runtime-triggered human escalation.** Nothing promotes a task to HITL after N failures anywhere in the corpus; escalation is exclusively pre-configured (crewai evidence) or operator-initiated (temporal).
- **Little loop-level backoff in agent frameworks.** crewai retries immediately with no backoff; agent-framework's consecutive-error limit stops rather than retries; letta's backoff exists only in SDK clients and the DB layer. Mature exponential backoff appears only at the infra/SDK tiers (temporal, langgraph, openai-agents-sdk) — a clear layer-boundary artifact.
- **Cost/token-budget circuit breakers are rare.** letta's credit gate is the only implemented budget stop found; openai-agents-sdk lists a usage ceiling as future work and openhands has a budget type with no client wiring.
- **Structured persistence-decision telemetry is the minority position.** Typed, queryable stop reasons exist in temporal, letta (steps table), and langgraph (state history); agent-framework and openai-agents-sdk consciously defer to logs/traces, and openhands instruments outcomes but not individual retry attempts.
- **Cross-attempt historical memory.** Nothing tracks "this task failed N times across resumes/runs" durably except temporal's attempt counters in mutable state; langgraph explicitly notes checkpoint metadata carries no attempt counters.
- **Replanning remains bespoke.** Outside Magentic, every system either punted to graph authors, model feedback, or workflow code — and said so.

## Per-Source Notes

Brief orientation; details above carry the citations.

- **agent-framework (8/10):** Layered caps (40 tool iterations / 10 loop / 100 supersteps) each degrading gracefully; Magentic replans on ledger-detected stalls; three typed human channels (approvals, `request_info`, plan sign-off). Gaps: string-only stop reasons, no transient-error retry, best-effort budget overshoot.
- **crewai (8/10):** Four budgeted scopes with corrective-feedback retries; `ToolFailurePolicy` chain; deliberate-vs-transient passthrough; strong event-bus observability. Gaps: never-reset lifetime retry counter, no backoff, five uncoordinated knobs, module-sniffed escalations.
- **langgraph (8/10):** Checkpoint-per-superstep substrate with a tiered escalation ladder (retry → error-handler node → recursion limit → drain → timeout → interrupt); exceptional replay/query observability. Gaps: static policies, no built-in replanning, aggressive unknown-exception retry default, HITL ergonomics partially moved to a sibling package.
- **letta (8/10):** Harness-owned continuation via `_decide_continuation` plus declarative tool rules; class-aware failure handling (feedback for tools, compaction for overflow, breaker for providers, fail-fast for unknowns); one stop-reason taxonomy end-to-end; durable approvals. Gaps: no generic transient retry without fallback, dead retry setting, textual continuation reasons.
- **openai-agents-sdk (9/10):** Opt-in policy-driven retries with composable DSL; fail-closed three-veto replay governance with session rewind; typed handlers producing validated finals; serializable `RunState` pauses; truthful usage accounting. Gaps: DEBUG-only retry logging behind redaction, no aggregate autonomy view, implicit legacy conversation-lock retries.
- **openhands (7/10):** Frontend half of a two-repo contract: configures server budgets (`max_iterations`, stuck detection), classifies transport failures, trips persisted circuit breakers, converts delegation failures into guidance, renders `capped`/`interrupted` goal loops. Gaps: core loop out of scope, `STUCK`→`ERROR` conflation, unbounded WS reconnect default, per-hook retry scatter.
- **temporal (10/10):** Server-evaluated `RetryPolicy` as pure functions over persisted state; time-shifted timer-driven retries; typed `RetryState` in history events; DLQ with operator merge/purge; pause/unpause/reset plus rule-driven auto-pause; application-steered `NextRetryDelay`. Caveats: unlimited-by-default retries, Cassandra-only DLQ, some hardcoded thresholds, `RETRY_STATE_PAUSED` unfinished.

## Open Questions

- **Budget interaction ordering.** Do provider-level HTTP retries consume executor iterations (`max_iter`)? CrewAI searched and unresolved (`core.py`, provider clients); similar composition questions shadow openai-agents-sdk's hidden-provider-retry suppression. No source documents a canonical precedence model.
- **Provider adapter parity for replay-safety advice.** openai-agents-sdk evidence covers the OpenAI adapter; third-party adapters were not audited for populating `ModelRetryAdvice.replay_safety`.
- **Multi-agent delegation reliability.** letta's only related setting is dead code (`settings.py:350`); whether supervisor/sleeptime group send-message retries exist at all is unevidenced.
- **Retry accounting across cluster failover (temporal).** Attempt counts reset on regime switch (`executable.go:388-397`); standby-cluster replication-task retry behavior was traced only partially.
- **LangGraph JS parity.** Only REST client bindings are in-repo; whether LangGraph.js implements equivalent retry/interrupt semantics could not be verified.
- **Who judges "capped vs complete" (openhands)?** The judge and acceptance threshold run server-side; the client renders verdicts it cannot explain (`conversation-state-event.ts:66-75`).
- **Does any system close the loop from persistence telemetry back into autonomy?** Temporal's rules engine is the nearest (auto-pause on matched failures), but no source demonstrated feedback-driven adjustment of retry aggressiveness based on observed success rates — all such adaptation is aspirational or hand-wired.
