## Executive Summary

Seven sources split cleanly into two camps on the dimension's core question — *"Can you answer 'what did this run cost?' in under a minute?"* — and the split is positional, not qualitative.

**Camp 1: token truth in-process, pricing deferred outward** (agent-framework, crewai, openai-agents-sdk, plus langgraph at the extreme). These normalize provider-reported usage into one canonical typed shape, sum it through a single combiner at every re-invocation boundary, and emit it via telemetry — but none contains a price table or dollar calculation (openai-agents-sdk: only docstrings stating `request_usage_entries` exists to *enable* downstream cost calc, `src/agents/usage.py:219,228`; agent-framework: repo-wide searches for `cost|price|pricing|dollar` return only incidental hits, per-source report §Questions; langgraph: "cost lookup" appears solely as a hypothetical custom-transformer example, `libs/langgraph/langgraph/stream/_types.py:70-74`). They answer the question in tokens instantly; dollars require joining their output with an external price sheet or observability backend.

**Camp 2: currency answers shipped** (pydantic-ai, langfuse, and openhands as a display consumer of server-computed dollars). pydantic-ai prices every model call in-process via the dedicated `genai-prices` dependency with Decimal math (`pydantic_ai_slim/pydantic_ai/_cost.py:29-59`) and is the only source enforcing monetary run limits (`UsageLimits.cost_limit`, `pydantic_ai_slim/pydantic_ai/usage.py:417-472`). langfuse computes real dollar costs server-side at ingestion time with tiered pricing and persists them for read-time rollups (`worker/src/services/IngestionService/index.ts:1617-1689`). openhands renders server-provided `accumulated_cost` with budget progress in a dedicated Usage tab (`src/components/features/conversation/usage-panel/usage-panel.tsx:22-86`).

Two findings hold across all seven: **tool-execution monetary cost is tracked by no one** (counts only, everywhere), and **retry-cost accounting is universally implicit or structural rather than a first-class ledger** — with openai-agents-sdk's zero-token retry entries (`src/agents/run_internal/model_retry.py:338-350`) and pydantic-ai's natural request-flow accumulation as the strongest treatments. Ratings span 3–9, but the spread measures scope ownership, not care: even the lowest scorer (langgraph) transports per-message usage faithfully with tested wire reconstruction (`libs/sdk-py/tests/streaming/test_messages_projection.py:39-75`).

## Core Thesis

Token-and-cost accounting maturity is not about *whether* a system computes dollars — it is about **who owns which half of the problem and how honestly each layer handles missing data, retries, and boundaries**.

Every source that counts tokens converges on the same three-part discipline despite zero coordination: (1) **normalize once** at the provider boundary into a canonical typed usage shape; (2) **aggregate through one combiner primitive** at each point where a logical run re-invokes an inner call; (3) **treat "not reported" as distinct from zero**. This convergence suggests these are the load-bearing invariants of the domain — break any one and totals drift or lie.

The divergence is all in the *last mile*. General-purpose frameworks deliberately stop at tokens because price tables rot (langfuse freezes costs at ingest and has no repricing path even as a dedicated platform — searched `backfill.*cost`, `recalc`, `reprice`, no evidence found), because cached-token discount semantics differ per provider (agent-framework notes raw summation preserves volume but not blended cost), and because billing policy belongs to the deployer. The two sources that do compute currency do so only after solving the ownership problem explicitly: pydantic-ai outsources rates to a same-org dedicated library and wraps it in a "never fail the run" contract (`pydantic_ai_slim/pydantic_ai/_cost.py:62-95`); langfuse makes client-provided figures strictly authoritative over computed ones ("Provided costs are authoritative", `worker/src/services/IngestionService/index.ts:1407-1419`). The lesson for harness builders: **the hard part is not multiplying tokens by prices — it is preserving enough per-call structure, provenance, and null-semantics that any pricer, present or future, can be correct.**

## Approach Models

The seven sources cluster into four approach models, with two hybrid variants:

**Model A — Normalize-once, aggregate-everywhere framework** (agent-framework). A canonical usage type (`UsageDetails` in Python, M.E.AI's in .NET) is populated at the provider boundary and every higher layer composes with one combiner (`add_usage_details`; `UsageAggregator.Combine/Accumulate`, `dotnet/src/Shared/Usage/UsageAggregator.cs:17-67`). Each new re-invocation site — function-calling loop, approval auto-approval chain, message injection, agent loop, workflow branch merge — adds one aggregation line, and the run total *replaces* last-call usage on the final response so callers get whole-run numbers without knowing internal call counts (`dotnet/src/Shared/Usage/UsageAggregationExtensions.cs:25-41`). Monetary cost is delegated entirely to observability: GenAI semconv attributes plus the `gen_ai.client.token.usage` histogram push pricing to backends (`python/packages/core/agent_framework/observability.py:381-396,1511-1517`).

**Model B — Lifetime accumulator + delta views + event bus** (crewai). Each LLM instance keeps monotonically increasing counters (`_token_usage`, `lib/crewai/src/crewai/llms/base_llm.py:955-986`); per-run attribution is derived by snapshotting before execution and reporting `delta_since(baseline)` afterward (`lib/crewai/src/crewai/types/usage_metrics.py:79-109`). Flow-level totals come from event-bus listeners correlated by a `current_flow_id` contextvar under a lock (`lib/crewai/src/crewai/flow/runtime/__init__.py:879-911`), allowing measurement of LLM calls made outside crew machinery. One normalizer (`from_provider_dict`) backs all three layers with a documented promise they agree (`lib/crewai/src/crewai/types/usage_metrics.py:142-155`).

**Model C — Mutable run-context aggregate + per-request ledger substrate** (openai-agents-sdk). One public `Usage` instance lives on `RunContextWrapper` and is mutated via `.add()` after every model response (`src/agents/run_context.py:83`; `src/agents/run_internal/run_loop.py:2306,2636`). Alongside totals, an auto-populated `request_usage_entries` list preserves per-request splits — explicitly motivated as the substrate "for accurate per-request cost calculation" (`src/agents/usage.py:218-229`) — making this the purest expression of *deferred pricing done right*: cost policy stays outside the library, but the exact granularity needed for tiered pricing survives.

**Model D — Embedded pricer with guardrails** (pydantic-ai). Pricing is outsourced to `genai-prices` (hard dependency, `pydantic_ai_slim/pyproject.toml:69`), wrapped in `best_effort_price`: known failures → `None` cost, unexpected exceptions → warning, run continues (`pydantic_ai_slim/pydantic_ai/_cost.py:62-95`). All usage enters one choke point — `_append_response` fills cost and increments `RunUsage` (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:1779-1795`) — which makes double-counting the primary correctness risk, addressed with explicit commit-exactly-once designs. `UsageLimits` checks cost/tokens/requests/tool-calls at five lifecycle points including pre-request counted-token projection (`pydantic_ai_slim/pydantic_ai/usage.py:492-572`).

**Model E — Ingestion-time enrichment platform** (langfuse). Costs are computed once during ingestion enrichment — model resolved by regex against a 167-model seeded catalog, pricing tier selected by priority-ordered usage-shape conditions, `Decimal(price) × units` per usage bucket — and stamped onto ClickHouse observation rows (`worker/src/services/IngestionService/index.ts:1658-1688`); trace/user/daily/experiment summaries are read-time `sum()` queries over those stamps (`packages/shared/src/server/repositories/traces.ts:1285`). Client-supplied usage/cost always beats computed values; matched-tier id/name are persisted per row for audit (`packages/shared/clickhouse/migrations/clustered/0031_add_usage_pricing_tier_columns.up.sql:1-2`).

**Model F — Transport-only delegation** (langgraph). Usage rides inside `AIMessage.usage_metadata` produced upstream by langchain-core; LangGraph streams messages faithfully (v1 messages mode, v3 `ChatModelStream.usage` projections, SDK wire protocol) and never inspects them (`libs/langgraph/langgraph/pregel/_messages.py:49-256`; `libs/langgraph/langgraph/stream/transformers.py:155-197`). Observability is positioned as a LangSmith product capability, not a framework feature (`README.md:42,56`). Its contribution to the pattern language is negative-space: what a transport layer must still get right — stable message identities, dedupe-before-emit, per-handle correlation — for anyone aggregating downstream.

**Model G — Server-authoritative consumption/display** (openhands). Counting and dollar computation happen in the agent-server; the frontend ingests through dual redundant channels (live WebSocket stats events preferred over a 30-second REST poll, precedence documented at `src/hooks/use-live-conversation-metrics.ts:6-21`), merges per-usage-id buckets with `combineUsageMetrics` (a port of the Python SDK's `get_combined_metrics`, `src/utils/conversation-metrics.ts:8-12`), and renders budget/context-fill/provider-credit surfaces. Additive fields sum; state-like fields (`context_window`, `per_turn_token`) merge via `Math.max` (`src/utils/conversation-metrics.ts:55-62`).

## Pattern Catalog

**P1. Canonical usage type + single combiner primitive.**
- *Problem:* Multiple providers report usage in different shapes across multiple loop levels; naive per-site summing drifts.
- *Demonstrated by:* All six counting sources — agent-framework `add_usage_details` (`python/packages/core/agent_framework/_types.py:430-468`); openai-agents-sdk `Usage.add()` (`src/agents/usage.py:257-312`); crewai `add_usage_metrics` (`lib/crewai/src/crewai/types/usage_metrics.py:32-77`); pydantic-ai `RunUsage.incr` (`pydantic_ai_slim/pydantic_ai/usage.py:371-390`); openhands `combineUsageMetrics` (`src/utils/conversation-metrics.ts:12-73`); langfuse's usage-type-keyed Map columns (`packages/shared/clickhouse/migrations/clustered/0002_observations.up.sql:19-23`).
- *Why it works:* One place to fix rounding/null/coercion semantics; every new aggregation site inherits correctness.
- *Copy when:* Any multi-provider or multi-loop system. *Risky when:* You need provider-specific economics that don't survive normalization (see P4's counterpoint).

**P2. Aggregate at every re-invocation boundary; run-total replaces last-call usage.**
- *Problem:* A logical "run" hides N model calls behind tool loops, approvals, injections, retries; reading the last response undercounts massively.
- *Demonstrated by:* agent-framework aggregates in function loops, approval chains, message-injection loops, agent loops, and workflow merges, with comments that hitting a cap must not "discard every prior turn's cost" (`dotnet/src/Microsoft.Agents.AI/Harness/ToolApproval/ToolApprovalAgent.cs:148-174`; `dotnet/src/Microsoft.Agents.AI/Harness/Loop/LoopAgent.cs:166-212`); openai-agents-sdk folds after each turn (`run_loop.py:2306,2636`).
- *Why it works:* Callers read `response.usage` once and get whole-run truth regardless of internal complexity.
- *Copy when:* Your harness has hidden inner loops. *Risky when:* Consumers also need per-call attribution without a ledger (then combine with P4).

**P3. "Unknown ≠ zero" null semantics everywhere.**
- *Problem:* Providers omit usage payloads, counters reset mid-run, wire data arrives malformed; treating absence as zero fabricates free work.
- *Demonstrated by:* agent-framework skips non-int values with a warning and .NET returns the surviving side on one-sided nulls (`_types.py:462-467`; `dotnet/tests/Microsoft.Agents.AI.UnitTests/Shared/UsageAggregatorTests.cs:89-134`); openai-agents-sdk marks requests-without-usage and converts to `Usage(requests=N)` rather than fake zeros (`src/agents/usage.py:315-343`); pydantic-ai keeps `Decimal | None` so budgets distinguish "free" from "unpriceable" and warn (`usage.py:130-135,528-535`); openhands coerces malformed wire values to zero/null and renders genuine `$0.0000` differently from unknown-null (`src/api/conversation-service/agent-server-conversation-service.api.ts:96-148`; `activity-log-item.tsx:41-52`); langfuse explicitly refuses byte-based estimation fallback, skipping counts and emitting a metric instead (`index.ts:1441-1466`).
- *Why it works:* Preserves the distinction between measured-zero, unreported, and unmeasurable — the difference between an honest bill and a silently wrong one.
- *Copy when:* Always. This is the most universal pattern in the study.

**P4. Per-request entry ledger as deferred-pricing substrate.**
- *Problem:* You don't want to own a price table, but callers eventually need tiered, cache-aware dollar figures.
- *Demonstrated by:* openai-agents-sdk's `request_usage_entries` preserves `[100K, 150K, 80K]`-style splits with cache-read/write detail, with a test sketching exactly how Anthropic tiered math would consume them (`tests/test_usage.py:427-488`); langfuse stores `provided_*` alongside computed maps so provenance is queryable; openhands' server ships a per-call `costs[]` ledger with model+timestamp (`src/types/agent-server/core/events/conversation-state-event.ts:30-34`) — though its UI never consumes it (see Caution Signs).
- *Why it works:* Decouples capture fidelity from pricing policy; a later pricer needs no new instrumentation.
- *Copy when:* Building a library/framework. *Overkill when:* A platform already prices at ingest (langfuse) — there, stamp-and-aggregate wins.

**P5. Stamp-at-ingest, aggregate-at-read (platform pattern).**
- *Demonstrated by:* langfuse computes costs once during ingestion and derives all summaries as read-time sums over stamped rows — the traces table deliberately holds no cost column (`packages/shared/src/server/repositories/traces.ts:1080-1145`).
- *Why it works:* Cheap queries, auditability, immunity of history to code changes; materialized ClickHouse projections accelerate hot paths (`0040_create_events_core.up.sql:43-48`).
- *Cost:* Price corrections never restate history; no backfill pipeline found (per-source report §Gaps).
- *Copy when:* You operate the storage layer. *Avoid when:* Users expect retroactive repricing.

**P6. Snapshot/delta scoping over lifetime counters.**
- *Problem:* Instance-level accumulators are cheap but conflate runs.
- *Demonstrated by:* crewai snapshots before kickoff and reports `delta_since(baseline)` with negative clamping (`lib/crewai/src/crewai/agent/core.py:1655,1830-1832`); openai-agents-sdk computes task/turn span usage as start-snapshot minus end-snapshot so spans reconcile with the run total (`src/agents/run_internal/agent_runner_helpers.py:76-160`); agent-framework accumulates inner-chat usage in a ContextVar and stamps the summed total onto the agent span without re-walking responses (`observability.py:128,3078-3103`).
- *Why it works:* Run attribution without per-event plumbing. *Fragility:* Every entry point must remember to snapshot (crewai flags this itself as fragile for new entry points).

**P7. Structural retry accounting — attempts countable, tokens honest.**
- *Problem:* Retried/failed attempts burn money but often yield no parseable usage.
- *Demonstrated by:* openai-agents-sdk prepends zero-token `RequestUsage` entries for failed attempts so attempt counts survive without inventing tokens and `sum(entries) == top-level tokens` holds (`src/agents/run_internal/model_retry.py:338-350`, tested at `tests/models/test_model_retry.py:514-555`); pydantic-ai lets retries flow through the same accumulation path as normal billed requests, including rejected fallback-model candidates (`models/fallback.py:297-306`); langfuse makes ingestion replay structurally non-additive via Redis seen-keys plus last-write-wins merges (`worker/src/queues/ingestionQueue.ts:87-109`; `index.ts:1760-1768`); langgraph exposes `node_attempt` as the join key it never uses (`libs/langgraph/langgraph/pregel/_retry.py:600-612`).
- *Why it works:* Distinguishes "attempt happened" from "tokens fabricated."
- *Copy when:* You have any retry/fallback machinery. *Gap to accept:* pre-failure partial-stream tokens remain unknowable (openai-agents-sdk says so explicitly).

**P8. Tiered-pricing-aware ordering: price before merge.**
- *Demonstrated by:* pydantic-ai prices Anthropic continuation segments individually *before* merging token counts, because merged 300k tokens priced at tier-1 rates would understate cost (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:1021-1023`, test comment at `tests/models/test_streamed_continuation.py:405`); langfuse's tier matcher evaluates regex thresholds over usage buckets (cached-input, batch discounts) per observation (`packages/shared/src/server/pricing-tiers/matcher.ts:116-154`).
- *Copy when:* Any provider applies volume/cache tiers. *Irrelevant when:* Flat pricing.

## Key Differences

- **Where pricing lives.** agent-framework emits model attribution and expects external backends to price (`observability.py:3147-3150`), while pydantic-ai embeds a live pricer behind a never-fail contract (`_cost.py:62-95`) — same token substrate, opposite last-mile philosophy, driven by product shape (multi-vendor framework vs opinionated library with a sister pricing lib).
- **Accumulation topology.** agent-framework composes immutable combiner results up a tree of loops; openai-agents-sdk mutates one shared object in place (hooks/tools see live totals, but streaming reads are stale until the terminal chunk, `src/agents/run_context.py:84-86`); crewai accumulates lifetime counters on LLM instances and reconstructs runs via deltas. Same invariant — every inner call lands in the total — different concurrency/staleness tradeoffs.
- **Replay and retry semantics.** langfuse makes retries *overwrite* (idempotent last-write-wins), openai-agents-sdk makes retries *count without tokens*, pydantic-ai makes retries *bill normally*, and langgraph makes retried attempts *invisible* (cleared writes wipe any usage-bearing messages, `libs/langgraph/langgraph/pregel/_retry.py:615,738`). Four coherent answers to one question; only the first three preserve spend truth.
- **Enforcement vs display vs nothing.** Only pydantic-ai halts runs on `cost_limit` (with explicit best-effort caveats, `docs/agent.md:1009`); openhands displays budget progress but shows no evidence of enforcement and asks whether the server enforces it (§Open Questions); agent-framework substitutes call-count caps framed as "the primary knob for controlling cost" (`python/packages/core/agent_framework/_tools.py:1342-1395`); langfuse confines budget alerting to cloud-EE code outside OSS core.
- **Normalization vs raw fidelity.** openai-agents-sdk normalizes by default with opt-in `preserve_raw_usage` for exact field-presence semantics (`docs/usage.md:55-76`); agent-framework's open-ended int-valued dicts let unknown provider counters flow through untouched — which is precisely how Copilot smuggles a cost figure, truncated double→long (`dotnet/src/Microsoft.Agents.AI.GitHub.Copilot/GitHubCopilotAgent.cs:505-508`); langfuse stores provided and computed maps side-by-side, preserving both.
- **Attribution depth vs presentation clarity.** openhands receives per-usage-id buckets (agent vs condenser vs profile) and per-call ledgers on the wire but collapses everything to one scalar for display (`conversation-state-event.ts:44-47` vs `src/utils/conversation-metrics.ts:23,30`); langfuse keeps per-observation granularity forever and aggregates only at query time. Opposite resolutions of the same tension.

## Tradeoffs

**In-process pricing (pydantic-ai) vs deferred pricing (openai-agents-sdk, agent-framework).**
Benefit (in-process): instant dollar answers, enforceable limits, mid-stream live cost. Cost: pricing freshness is hostage to the `genai-prices` snapshot — new models are unpriced until the library updates, and `cost_limit` silently degrades exactly then (benign `None` + `CostNotFoundWarning`). Benefit (deferred): no stale rate tables in-library; pricing policy stays with the deployer. Cost: the "$ per run" question requires external joins, and hosts without caps have no framework-level spend ceiling (agent-framework §Failure Modes: unpriced runaway risk).

**Stamp-at-ingest (langfuse) vs accumulate-in-run (frameworks).**
Benefit (ingest): history is frozen and auditable; reads are cheap sums; provenance per row. Cost: a wrong price poisons records permanently absent backfill; a mid-retry price edit silently reprices a record. Benefit (in-run): totals reflect current knowledge; nothing persists to misprice. Cost: nothing durable survives the process unless separately exported (pydantic-ai's summary is in-memory only; crewai's cross-process pause/resume restarts at zero, `flow/runtime/__init__.py:934-939`).

**Mutable shared aggregate (openai-agents-sdk) vs immutable combiners (agent-framework).**
Benefit (mutable): hooks and tools read live totals trivially; nested agent-as-tool runs share the parent object so outer totals stay correct (`src/agents/agent.py:720-730`). Cost: manual snapshotting needed for history; checkpoint boundaries need deepcopy isolation to avoid cross-contamination (`src/agents/run_context.py:117-131`). Immutable combiners invert this: safer composition, but every site must remember to thread the result.

**Lifetime counters + deltas (crewai) vs per-event emission.**
Benefit: cheap, no event storm; one normalizer guarantees layer agreement. Cost: granularity bounded by who remembers to snapshot; failed attempts that never complete emit `LLMCallFailedEvent` with no usage at all (`lib/crewai/src/crewai/events/types/llm_events.py:117-121`); parallel siblings sharing a parent contextvar may over-count each other — acknowledged in the API docs themselves (`flow/runtime/__init__.py:918-926`).

**Trust-the-server (openhands) vs verify-the-client.**
Benefit: no tokenizer/pricing maintenance client-side; single honest number fast. Cost: server-side errors propagate silently; "why did this conversation cost $5?" is unanswerable from the UI because the drill-down ledger goes unconsumed.

**Faithful passthrough (langgraph) vs aggregation.**
Benefit: tiny provider-neutral core; usage piggybacks on content pathways that already exist. Cost: the studied failure mode verbatim — the run-cost question cannot be answered without external tooling, and subgraph messages are excluded from the `.messages` projection so naive sums understate hierarchical spend (`stream/transformers.py:184-191`).

## Decision Guide

Choose your position on the ownership spectrum by product shape, not ambition:

1. **Building a general-purpose framework/library** → Do what agent-framework and openai-agents-sdk do: canonical typed usage, one combiner, aggregation at every hidden re-invocation boundary, telemetry export, and a per-request ledger explicitly designed as a pricing substrate. Do *not* ship a price table — the maintenance liability is permanent and both 8-score frameworks declined it. If you want a seam, add an optional pluggable calculator consuming your ledger (both reports' Future Considerations sketch exactly this; crewai's dead `completion_cost` field shows what an unplumbed seam looks like).
2. **Building an application that must show users dollars now** → Adopt a maintained pricer dependency (pydantic-ai/genai-prices pattern: registry-owned rates, best-effort degradation, `None` ≠ zero) or delegate to an observability platform (langfuse pattern: authoritative client overrides, ingest-time stamping). Pair either with spend controls at the provider, because pydantic-ai's docs themselves warn `cost_limit` is best-effort, not a billing guarantee (`docs/agent.md:1009`).
3. **Building a low-level orchestration/graph layer below the concern** → langgraph's model is legitimate, but its obligations are: stable identities for replayed content (`pregel/_messages.py:426-461`), dedupe-before-emit so usage surfaces once (`_messages.py:97-104`), and attempt metadata (`node_attempt`) as a join key for whoever aggregates later. Ship the reference aggregator you refuse to force on everyone — langgraph's own "cost lookup" transformer example (`stream/_types.py:70-74`) remains hypothetical.
4. **Building a UI/consumer over a server that meters** → openhands' model: trust server numbers, merge defensively (coerce malformed values, reset state on context switch, hide unavailable features gracefully), be scrupulous about null-vs-zero and estimates-vs-bills. But consume the attribution depth you're shipped — flattening per-id/per-call data into one scalar forfeits debuggability you already paid for on the wire.
5. **Budget enforcement is a requirement?** Only pydantic-ai demonstrates in-library enforcement worth copying: checks before request (with optional counted-token lower bound), after response, before tool batches (projected deep-copy), and at completion; warn loudly when limits are unenforceable due to missing prices. Everyone else either displays (openhands), proxies via call caps (agent-framework), or defers to cloud tiers (langfuse OSS).

## Practical Tips

- **Make the combiner the only place arithmetic happens.** Every source with trustworthy totals funnels all summation through one function with pinned edge-case tests (agent-framework's combiner test suite covers non-int skipping and iadd edge cases, `tests/core/test_types.py:636-697,3285-3333`; openai-agents-sdk's 668-line `test_usage.py`).
- **Convert cumulative streams to increments at the boundary.** Anthropic sends cumulative snapshots; agent-framework's `_incremental_usage` normalizes to deltas so downstream additive merges stay correct (`python/packages/anthropic/agent_framework_anthropic/_chat_client.py:1189-1192`); crewai reconciles raw Anthropic cache keys so cached workloads don't undercount billed prompt tokens (`usage_metrics.py:111-136`). Decide cumulative-vs-incremental explicitly per provider; mixing them silently corrupts totals.
- **Record span/metric usage before early exits.** openai-agents-sdk sets chat-completions span usage *before* validation branches so truncated completions still record tokens, and streaming responses record before yielding the terminal event since consumers may close immediately (`models/openai_chatcompletions.py:303-313`; `models/openai_responses.py:686-689`).
- **Test the failure-shaped cases, not just happy sums:** zero-usage responses still emit metrics (agent-framework `test_capture_response_records_zero_token_usage`, `test_observability.py:4381`); cap exhaustion still aggregates (`test_observability.py:5735-5740`); retry-inflated request counts (openai-agents-sdk `test_model_retry.py:514-555`); tiered continuation math (pydantic-ai `test_streamed_continuation.py:403-482`); exact Decimal pins per provider (pydantic-ai VCR snapshots, e.g. gpt-4o = 0.00075, `test_cost.py:127`).
- **Guard against double-counting at telemetry seams.** pydantic-ai drops OTel attribute keys colliding with first-class fields because aggregators like Langfuse sum both (`usage.py:244-252`), records metrics after span close (`_instrumentation.py:457-459,543-544`), and langgraph dedupes finalized messages between stream and node output (`_messages.py:398-406`). Any number emitted on two channels will be added twice by someone.
- **Preserve pricing provenance.** langfuse stamps the matched tier id/name onto every row, enabling post-hoc audits and a future backfill join key (`index.ts:1347-1358`); pydantic-ai returns full `PriceCalculation` objects, not just totals (`messages.py:2688-2700`).
- **Serialize usage with your checkpoints/state.** openai-agents-sdk round-trips usage including request entries and deep-copies at checkpoint boundaries so resumed branches don't cross-contaminate (`usage.py:405-431`; `run_context.py:117-131`); pydantic-ai carries usage across Temporal/DBOS/Prefect boundaries. Runs outlive processes more often than you think.

## Anti-Patterns / Caution Signs

- **Dead cost scaffolding.** crewai declares `LLM.completion_cost: float | None` and nothing in the repo ever reads or writes it (`lib/crewai/src/crewai/llm.py:370`) — planned-but-unrealized support that misleads readers. openhands ships orphaned "Input Cost Per Token" i18n strings and a dead `parseMaxBudgetPerTask` parser (`translation.json:3335,3845`; `settings-utils.ts:18-27`). Caution sign: cost-shaped symbols with zero consumers.
- **Typed-but-unconsumed ledgers.** openhands' wire format includes per-call `costs[]` with model+timestamp, `response_latencies[]`, and `token_usages[]` — grep finds only type declarations, no consumers (`agent-server-conversation-service.types.ts:268-288`). Attribution depth paid for but never rendered makes cost debugging impossible from the UI.
- **Duplicated reduce logic.** openhands hand-writes the identical metrics reduce twice (WS context reducer vs `combineUsageMetrics`); they currently agree but can silently diverge (`conversation-websocket-context.tsx:227-267` vs `conversation-metrics.ts:28-66`).
- **Warn-only consistency checks that never correct.** langfuse's usage-total mismatch detector logs a rate-limited metric but never auto-corrects, so corrupt instrumentor payloads persist (`index.ts:1557-1615`).
- **Silent zero on catalog miss.** langfuse's regex model matching means unmatched models yield zero cost silently — a tested expectation, not an error (`calculateTokenCost.unit.test.ts:1122`). Freshness-dependent catalogs need a loud miss signal.
- **Lossy economic passthroughs.** agent-framework truncates Copilot's fractional-dollar `Cost` into a long and drops MCP `_meta.cost` outright during conversion (`GitHubCopilotAgent.cs:505-508`; `test_mcp.py:1193-1213`). When provider economics only survive if they fit your counter mold, you're discarding bills.
- **Correlation keys that leak across units of work.** crewai's contextvar-based flow correlation can over-count parallel sibling flows sharing a parent — documented in its own API docs (`flow/runtime/__init__.py:918-926`); shared LLM instances double-count when crew roll-up iterates agents (`crew.py:2205-2209`). Caution sign: aggregation keyed on ambient context rather than explicit run handles.
- **Clamping that launders anomalies.** crewai's `delta_since` clamps negative deltas to zero, converting a mid-run counter reset into an undercount instead of an error (`usage_metrics.py:93-108`).
- **Frozen pricing with no restatement path.** langfuse lacks any backfill/reprice job; combined with silent catalog misses, a stale price list quietly misprices everything ingested while looking healthy.

## Notable Absences

Across all seven sources, checked against each report's explicit search evidence:

- **Monetary cost computation** is absent from four of seven (agent-framework, crewai, langgraph, openai-agents-sdk) — deliberate design, confirmed by negative searches in each report.
- **Tool-execution monetary cost** is absent from *all seven*. Counts exist (agent-framework `max_function_calls`; pydantic-ai `RunUsage.tool_calls`; crewai `run_attempts`), but no source prices a local, hosted, or MCP tool execution. Hosted-tool charges surface only inside response-level token aggregates (openai-agents-sdk §Q3); OpenRouter-reported upstream tool costs land unmerged in `provider_details` (pydantic-ai `models/openrouter.py:567-573`).
- **First-class retry-cost line items** exist nowhere; the best treatments are structural (P7), and provider-managed transport retries remain unobservable even in the strongest implementation (openai-agents-sdk toggles but does not itemize them).
- **Cross-run/historical spend aggregation** appears only in langfuse (daily metrics API, dashboards) and weakly in openhands (automation CSV export). Frameworks keep run summaries in memory at most.
- **Multi-currency support**: none. langfuse's prices and columns are implicitly USD with no currency field found; no other source has currency at all.
- **Vendor-neutral observability hooks in-core** are rare: agent-framework (OTel semconv) and pydantic-ai (OTel attributes + histograms) ship them; langgraph offers none (LangSmith-oriented README only); crewai exports usage via its own tracing listener.
- **Persistence of run summaries**: pydantic-ai explicitly in-memory only; crewai loses totals across pause/resume; openai-agents-sdk offers session-level persistence only as an extension (`advanced_sqlite_session.py:618-654`).

## Per-Source Notes

- **agent-framework (7)** — Token accounting as a first-class typed end-to-end concern in both Python and .NET, aggregated at every loop boundary with null-safe semantics and semconv-aligned OTel; cost deliberately excluded except lossy passthroughs. Strongest evidence of aggregation-under-failure (cap exhaustion, approval pauses, zero-token captures all tested).
- **crewai (7)** — Three coordinated layers (instance counters, event-bus flow aggregation, legacy callbacks) sharing one provider normalizer, with strong defensive engineering; undermined by invisible failed-call tokens, opt-in snapshot fragility, and documented sibling-flow over-counting.
- **langfuse (8)** — The reference ingestion-enrichment design: ~1,772-line dedicated cost-calculation suite, tiered pricing with persisted provenance, tokenizer isolation with skip-not-estimate policy, structural replay idempotency. Weakened by frozen history and the absent tool-cost dimension.
- **langgraph (3)** — Pure transport delegation to langchain-core/LangSmith with excellent message-fidelity mechanics (dedupe, stable IDs, tested wire reconstruction) and zero aggregation; the clearest demonstration that passthrough alone fails the dimension's one-minute test.
- **openai-agents-sdk (8)** — Centralized mutable `Usage` on the run context plus the study's best per-request ledger and the only explicit failed-retry accounting; docs-as-contract matches implementation. Conditional third-party accuracy (LiteLLM warnings, `include_usage` requirements) is the main softness.
- **openhands (7)** — Frontend consumption/display layer with unusually mature UX safeguards (reset-on-switch regression tests, null-vs-zero honesty, estimate labeling, graceful endpoint degradation); capped by being display-only over an out-of-boundary server, leaving its richest data unconsumed.
- **pydantic-ai (9)** — End-to-end subsystem: typed request/run usage with inclusive-bucket semantics, outsourced-but-integrated pricing with never-fail degradation, single accumulation choke point, five-point limit enforcement, OTel double-count guards, durable-execution serialization, and exact Decimal test pins. The study's benchmark; docked for unpriced tools and snapshot-freshness dependence.
