## Pattern Catalog

No code-level patterns exist for this dimension — zero test files means zero patterns of any kind (`reports.md:99-101`). What the source does demonstrate unusually clearly are two **negative patterns** in study/pipeline infrastructure, recorded here because they are transferable and evidence-backed:

### 1. Silent-empty propagation through a staged-snapshot pipeline
- **Problem**: A harness stages per-dimension inputs as directory snapshots; consumers assume a resolvable path implies readable content.
- **Demonstrated in**: reports — directories exist and pass existence checks, but any content read fails; a downstream validator attempting to read this dimension's generated report before it was written hit exactly this class of failure (`content.read ... file does not exist`) (`reports.md:112-115`).
- **Why it matters**: Empty inputs do not produce errors at the boundary where they occur; they produce failures (or silently empty outputs) far downstream, at the point of consumption.
- **When the underlying concern applies**: Any pipeline built on staged artifacts, cached snapshots, or convention-over-content layouts. Presence-of-path does not imply availability-of-data (`reports.md:113`).
- **Mitigation seen recommended**: A harness-level preflight check that fails fast when a selected source directory contains zero files (`reports.md:120`).

### 2. Convention-over-content masking
- **Problem**: A rigid, well-formed layout (`<NN.NN>-<dimension-slug>/`) communicates expected structure even when content is missing.
- **Demonstrated in**: reports — the nested `source/07.04-timeouts-and-cancellation/` slot encodes intent while carrying no executable behavior (`reports.md:42`, `reports.md:61`).
- **Why it matters**: A well-formed path may be mistaken for substance by humans scanning trees and by tooling doing existence checks (`reports.md:108`).
- **When it bites**: Whenever layout conventions are treated as progress indicators; the structure signals "this will be filled," not "this is filled."
- **Evidence**: `reports.md:97`, `reports.md:101`, `reports.md:108`.

Neither pattern says anything about lifecycle or concurrency semantics in agent runtimes; both concern the reliability of the study apparatus itself.

## Tradeoffs

Both tradeoffs below come from the source report's boundary observations (`reports.md:103-108`) and describe the study setup rather than any runtime design.

- **Snapshot vs. live tree.** If the directory was meant to snapshot prior study outputs as evaluation inputs, the isolation/reproducibility tradeoff was paid for but the payload never landed — consumers get isolation guarantees over an empty set (`reports.md:107`). Benefit of the chosen design: reproducible, bounded inputs. Cost observed here: isolation over nothing, plus late failure discovery. An alternative — letting analysts read live sibling trees — would have provided content but violated the study's isolation rules (`reports.md:27`).
- **Convention-over-content vs. explicit contracts.** A fixed `<NN.NN>-slug/` layout makes expected structure legible without documentation (`reports.md:61`). Cost: structure persists even when substance is missing, masking emptiness (`reports.md:108`). An alternative — emitting an explicit manifest of staged files (or an explicit "EMPTY" marker) — would make absence machine-visible at the same cost as the convention.

## Practical Tips

- **Fail fast on zero-file sources.** Add a harness-level preflight that converts silent-empty snapshots into explicit errors (`reports.md:120`). This turns a downstream `content.read ... file does not exist` surprise into an immediate, attributable failure (`reports.md:115`).
- **Document staging contracts.** If a per-dimension layout convention is load-bearing, document who writes into it and what filenames are expected once content exists; otherwise readers cannot distinguish cosmetic scaffolding from a working contract (`reports.md:121`).
- **Anchor negative results with an audit trail.** When reporting that something is absent, record the exact commands, their scope, and their outputs (as done at `reports.md:132-136`) so reviewers can verify the search was exhaustive and correctly scoped.
- **Respect isolation boundaries during diagnosis.** The reason the emptiness cause (skipped generation? moved data? deleted?) could not be determined is that inspecting sibling sources is banned by the study's isolation rules (`reports.md:27`, `reports.md:127`). Diagnose provisioning gaps through harness metadata, not by breaking study boundaries.
- **Once populated, instrument the full verification stack before trusting lifecycle claims.** The absent artifact classes enumerated in the source report — invariant definitions, forbidden-transition generators, deterministic schedulers/barriers/fake clocks, trajectory comparators, leak detectors, race/sanitizer CI, seed capture, release gates (`reports.md:52-60`) — form a checklist of what "lifecycle semantics verified" minimally requires.
