## Executive Summary

Of ten sources enumerated for this dimension, **eight have no observable evidence** because their source directories are empty in the local checkout (agent-framework, crewai, langgraph, letta, opa, openai-agents-sdk, pydantic-ai, temporal). Each scored `1 / 10` for "absent," not because the frameworks lack event schemas, but because the study was dispatched against a vendored checkout that does not exist on disk. Hard rule #1 forbids compensating with evidence from sibling sources or from public knowledge of the upstream repositories, so all eight reports collapse to "no evidence found" with the same search boundary.

The two sources with real evidence — **langfuse (8 / 10)** and **openhands (7 / 10)** — are the only data points available for synthesis. They represent two distinct agent-runtime product shapes:

- **langfuse** is a managed-observability product with its own in-app agent runtime (AG-UI protocol). It uses a typed enum (`EventType`) for events, a Postgres-owned CAS state machine for run lifecycle, a monotonic per-conversation `sequenceNumber` for ordering, and a typed terminal-state vocabulary (`InAppAgentRunErrorCode`) covering creation/completion/failure/cancellation/timeout. It can reconstruct the full lifecycle of any run from events alone.
- **openhands** is an agent orchestration product with a Python server emitting a wire-protocol event stream consumed by a TypeScript frontend. It uses a discriminated union with 16 variants (`OpenHandsEvent`), ISO-8601 `timestamp` for ordering, and a `ConversationStateUpdateEvent` envelope that carries `full_state | execution_status | stats | goal` snapshots. It is comprehensive for tool-call, error, hook, condensation, goal, and ACP sub-agent lifecycles but has no explicit `schema_version` field, no conversation-start/conversation-finish event, and no dedicated cancellation event.

The synthesis below works with the **convergent patterns, divergent design choices, and notable absences** observable across these two full-evidence sources, plus the study-wide operational lesson about how many sources failed to surface evidence.

## Core Thesis

Across the two observable sources, lifecycle events converge on three patterns — **typed discriminated events, durable ordered storage, and parent-ID linkage** — but diverge on whether ordering is enforced server-side via monotonic cursors (langfuse) or client-side via ISO timestamp sort with deduplication (openhands). Both can reconstruct run lifecycles from events alone, but with different reconstruction guarantees: langfuse guarantees strict per-conversation ordering and gap-free replay through `sequenceNumber` plus a typed terminal-error vocabulary, while openhands achieves reconstruction through discriminators, paired action→observation events, and a generic `ConversationStateUpdateEvent` envelope that bundles state snapshots onto the same channel as raw events.

The eight sources scored 1 / 10 are not evidence of weak event design; they are evidence of an **operational failure** in the study pipeline (no vendored checkout). Any practitioner reading this report should treat the 1 / 10 ratings as a signal that the dimension cannot be evaluated for those frameworks under the current study bootstrap, not as a verdict on their actual design.

## Approach Models

The dimension surfaced two distinct approach models across the two sources with evidence. The eight sources with no evidence cannot contribute approach models under the isolation rules.

### Model A — Typed enum + Postgres-owned CAS + monotonic per-conversation cursor (langfuse)

**Where implemented.** Langfuse's in-app agent runtime, which drives AG-UI streams inside the Langfuse product itself. The schema lives in `packages/shared/src/in-app-agent/`, the runtime lifecycle lives in `packages/shared/src/in-app-agent/server/runLifecycle.ts`, and the persistence seam lives in `packages/shared/src/in-app-agent/server/persistence.ts`.

**Main mechanism.** A `EventType` enum from `@ag-ui/core` provides per-event typing; a Postgres `InAppAgentEvent` table assigns a `sequenceNumber` per conversation under a `lockConversation` row lock; a `InAppAgentRun` row tracks `status`, `createdAt`, `claimedAt`, `heartbeatAt`, `cancelRequestedAt`, and `finishedAt` with state transitions guarded by fenced CAS updates; a typed terminal-error vocabulary (`InAppAgentRunErrorCode`) names the specific failure reason (`WORKER_LOST`, `RUN_TIMEOUT`, `STEP_LIMIT`, `APPROVAL_EXPIRED`, etc.).

**Supporting mechanisms.** A whitelist `toPersistableAgentEvent` (`persistence.ts:739-932`) projects each known `EventType` into a persistable shape; a compaction pass (`eventCompaction.ts:35-62`) merges consecutive `TEXT_MESSAGE_CHUNK`/`REASONING_*_CHUNK` deltas before persistence; a reconciler (`runLifecycle.ts:688-747`) classifies stale runs and CAS-transitions them to `FAILED` with a typed error code.

**Standout patterns worth copying.**
- Per-conversation monotonic `sequenceNumber` rather than wall-clock timestamp for the watch cursor (`persistence.ts:75-83`). The cursor is gap-free by construction; the snapshot's high-water mark is the max over the returned rows.
- Fenced CAS returning `{count: 0}` semantics (`runLifecycle.ts:37-58,64-84,93-124`). The worker detects lost-ownership without inspecting the row.
- `OUTCOME_UNKNOWN` for cancellation windows where a tool mutation may have started but its result did not persist (`executeInAppAgentRun.ts:160-167`). Distinguishes "we cancelled cleanly" from "we cancelled but state is uncertain."

**Tradeoffs.** Database-clock `createdAt` is authoritative (no producer-clock skew), but the AG-UI optional `timestamp` is silently dropped — the producer cannot signal clock anomalies through the event stream. Per-conversation `lockConversation` serializes throughput. Stored-as-`String` columns for `status`/`error_code` give forward compatibility but force every consumer through `safeParse`. See `packages/shared/src/features/inAppAgent/types.ts:5-11,23-29`.

**Where the lifecycle model would not fit.** Lightweight streaming-only runtimes that don't need durable replay, terminal-error codes, or approval continuations. Per-conversation row locking adds latency that a single-shot stateless API would not tolerate.

### Model B — Discriminated union + ISO timestamp ordering + state-snapshot envelope (openhands)

**Where implemented.** OpenHands' agent-server wire protocol, which is mirrored in TypeScript under `src/types/agent-server/core/`. The store is `src/stores/use-event-store.ts`, the WebSocket bridge is `src/contexts/conversation-websocket-context.tsx`, and the UI projection layer is `src/utils/handle-event-for-ui.ts`.

**Main mechanism.** A discriminated `OpenHandsEvent` union (`openhands-event.ts:25-46`) with 16 variants tagged by `kind`. Every event extends `BaseEvent` (`event.ts:10-25`) carrying `id`, `timestamp` (ISO 8601), and a `source` union (`agent | user | environment | hook`). The store sorts by ISO lexicographic timestamp and dedups by `id`. Actions and observations pair via `action_id`; hook events carry six lifecycle discriminators; conversation state changes ride on a single `ConversationStateUpdateEvent` envelope with `key: "full_state" | "execution_status" | "stats" | "goal"`.

**Supporting mechanisms.** Two-tier streaming-delta handling (`streaming-delta-batcher.ts:21-49`) coalesces per-token deltas into a single persisted bubble per frame and excludes them from the dedup `Set`. Action→observation supersede (`handle-event-for-ui.ts:418-441`) replaces `ActionEvent` in place by id when its matching `ObservationEvent` arrives. ACP tool-call lifecycle collapses into two events per `tool_call_id` (started, terminal) with a `status` union.

**Standout patterns worth copying.**
- Pure runtime validation at the wire boundary: `isBaseEvent` and `isAgentServerEvent` (`type-guards.ts:45-62,299-301`) drop anything that fails shape validation before it touches state. The chokepoint is small, testable, and explicit.
- Strict pagination mode (`event-service.api.ts:144-163`): callers like transcript export pass `strictPagination: true` so incomplete pages surface as errors instead of silent gaps.
- Defensive dedup of replayed events on WebSocket reconnect with `since`-replay (`conversation-websocket-context.tsx:559-568`): side-effects are gated on `eventIds.has` to remain idempotent across reconnects.

**Tradeoffs.** No `schema_version`/`event_version` field — additive-only evolution, no way for old clients to detect a wire schema they don't understand (`type-guards.ts` returns false, events are dropped silently). No monotonic `seq` — two events with identical ISO timestamps are non-deterministic (`use-event-store.ts:28-31`). Pause and cancellation ride on a generic `PauseEvent` + `ExecutionStatus.PAUSED` channel rather than a typed `CancelEvent`, so user-pause is indistinguishable from auto-pause without cross-referencing the `source` field. Cloud sandbox pause/resume leaves no event at all; the WS is just suppressed (`AGENTS.md` "Cloud conversation resume gating").

**Where the lifecycle model would not fit.** Systems requiring strict gap-free replay guarantees, durable terminal-error codes, or auditable state machines. OpenHands' timestamp-only ordering makes deterministic reconstruction possible but not guaranteed; langfuse's monotonic cursor makes it guaranteed.

## Pattern Catalog

The following patterns appear in both langfuse and openhands (or are otherwise load-bearing for the dimension). Each is annotated with the evidence that supports it and the contexts where it should or should not be applied.

### Pattern 1 — Typed event discrimination via enum or union

**Problem.** A stream of untyped events forces every consumer to validate shapes ad-hoc, leading to brittle consumer code and silent drops on malformed events.

**Where demonstrated.** langfuse uses the `EventType` enum imported from `@ag-ui/core` (`schema.ts:7`, re-exported at `openhands-event.ts`-equivalent references in `schema.ts:208-219`). openhands uses the discriminated `OpenHandsEvent` union of 16 variants (`openhands-event.ts:25-46`) with `kind: "<string-literal>"` discriminators on each variant.

**Why it works.** Enums and discriminated unions narrow types in `if`/`switch` branches at compile time, and runtime type-guards (`type-guards.ts:45-62,299-301` for openhands; `toPersistableAgentEvent` in `persistence.ts:739-932` for langfuse) provide a single chokepoint to reject malformed events.

**When to copy.** Any system where a stable wire format is published to third-party consumers. Either enum or discriminated union is appropriate.

**When it is overkill or risky.** Single-process runtimes where the producer and consumer are always the same version. In that case, a struct or named tuple can be simpler.

**Evidence.** langfuse `packages/shared/src/in-app-agent/server/persistence.ts:739-932`, `packages/shared/src/in-app-agent/schema.ts:208-219`; openhands `src/types/agent-server/core/openhands-event.ts:25-46`, `src/types/agent-server/type-guards.ts:45-62,299-301`.

### Pattern 2 — Per-conversation monotonic cursor (langfuse) vs ISO timestamp + dedup (openhands)

**Problem.** Replay must be gap-free to avoid missing lifecycle transitions on reconnect or partial load.

**Where demonstrated.** langfuse assigns `sequenceNumber = (latestEvent?.sequenceNumber ?? -1) + 1` under `lockConversation` (`runLifecycle.ts:850-882`) with composite PK `(projectId, conversationId, sequenceNumber)` (`schema.prisma:275`). openhands uses ISO lexicographic `compareEventsByTimestamp` (`use-event-store.ts:24-35`) with an `eventIds: Set<string|number>` for O(1) dedup (`use-event-store.ts:100-107`).

**Why it works.** langfuse's cursor is gap-free by construction because the database serializes appends. openhands' cursor is gap-tolerant because dedup by `id` plus timestamp sort is sufficient when the producer assigns stable ids.

**When to copy.** Per-conversation monotonic cursor is the right pattern when strict replay guarantees are required (e.g., financial workflows, regulated environments). ISO timestamp + dedup is the right pattern when clients tolerate eventual consistency and the producer can guarantee monotonic clock advance per conversation.

**When it is overkill or risky.** Per-conversation row locking adds latency and serializes throughput; ISO timestamp alone is non-deterministic for identical timestamps (`use-event-store.ts:28-31`).

**Evidence.** langfuse `packages/shared/src/in-app-agent/server/runLifecycle.ts:850-882`, `packages/shared/prisma/schema.prisma:263-278`; openhands `src/stores/use-event-store.ts:24-35,100-107`.

### Pattern 3 — Parent ID linkage via typed fields

**Problem.** Tool-call, observation, hook, and approval events must link to the action or span that triggered them for forensic reconstruction.

**Where demonstrated.** langfuse's `InAppAgentEvent` row carries `projectId`, `conversationId`, `runId` plus the JSON `event` body embedding `toolCallId`, `messageId`, `threadId`, `parentRunId` (`schema.prisma:264-272`). openhands' `ActionEvent` carries `tool_call_id`, `llm_response_id`, `security_risk`, `critic_result` (`action-event.ts:11-72`); `ObservationEvent` carries `tool_call_id` and `action_id` to back-link (`observation-event.ts:36-39`); `HookExecutionEvent` carries `action_id`/`message_id` (`hook-execution-event.ts:66-99`); `ACPToolCallEvent` carries `tool_call_id` to pair started/terminal (`acp-tool-call-event.ts:50-67`).

**Why it works.** Strong typing forces every producer to set the parent field; the union narrows in consumers. Both sources attach parent IDs at write time rather than inferring them at read time.

**When to copy.** Any system where multiple event kinds interact (actions call tools, tools return observations, hooks wrap actions).

**When it is overkill or risky.** Simple single-event-per-conversation streams don't need cross-linkage.

**Evidence.** langfuse `packages/shared/prisma/schema.prisma:263-278`, `packages/shared/src/features/inAppAgent/types.ts:85-101`; openhands `src/types/agent-server/core/events/action-event.ts:11-72`, `src/types/agent-server/core/events/observation-event.ts:9-52`, `src/types/agent-server/core/events/hook-execution-event.ts:6-99`.

### Pattern 4 — Terminal-error vocabulary as a typed enum (langfuse)

**Problem.** When a run fails, the consumer needs to know whether it was cancelled, timed out, lost a worker, exhausted steps, or encountered an agent error — each has a different remediation.

**Where demonstrated.** langfuse's `InAppAgentRunErrorCode` (`types.ts:30-69`) enumerates `STALE, CANCELLED, AGENT_ERROR, INIT_FAILED, WORKER_SHUTDOWN, OUTCOME_UNKNOWN, ENQUEUE_FAILED, QUEUE_TIMEOUT, WORKER_LOST, RUN_TIMEOUT, APPROVAL_EXPIRED, APPROVAL_SUPERSEDED, APPROVAL_CANCELLED, STEP_LIMIT`. Each is paired with a specific CAS transition (`runLifecycle.ts:696-747`).

**Why it works.** Typed codes let downstream dashboards and metrics distinguish failure modes without parsing error messages. Reconciliation logic is pure (`classifyStaleRun` is a pure function), so read paths and write paths cannot diverge.

**When to copy.** Any durable workflow runtime where distinguishing cancellation from timeout from worker-loss matters operationally.

**When it is overkill or risky.** Short-lived streaming pipelines where errors are reported and forgotten. A typed enum is overhead when a single `error: string` would suffice.

**Evidence.** langfuse `packages/shared/src/features/inAppAgent/types.ts:30-69`, `packages/shared/src/in-app-agent/server/runLifecycle.ts:696-747`.

### Pattern 5 — Fenced CAS state transitions (langfuse)

**Problem.** Concurrent workers must not corrupt run state when claim/heartbeat/finish transitions race.

**Where demonstrated.** langfuse's `claimQueuedRun`, `heartbeatClaimedRun`, `finishClaimedRun` all return `{count: 0}` semantics (`runLifecycle.ts:37-58,64-84,93-124`). Approval-decision CAS is exactly-once (`runLifecycle.ts:283-297`). The reconciler's CAS guards the prior `heartbeatAt` value so a renewing worker cannot be killed (`runLifecycle.test.ts:128-170`).

**Why it works.** `updateMany` + `count`-based fencing is a database-side primitive that doesn't require application-level mutexes. The worker can detect lost-ownership without re-reading the row.

**When to copy.** Any system with multiple workers (or replicas) competing for the same run.

**When it is overkill or risky.** Single-writer systems. CAS adds a round-trip per transition.

**Evidence.** langfuse `packages/shared/src/in-app-agent/server/runLifecycle.ts:37-58,64-84,93-124,283-297`.

### Pattern 6 — State-snapshot envelope (openhands)

**Problem.** When state changes (execution_status, goal status, conversation stats), the consumer needs a single channel to receive the update without flooding the event stream with per-field events.

**Where demonstrated.** openhands' `ConversationStateUpdateEvent` (`conversation-state-event.ts:99-151`) carries `key: "full_state" | "execution_status" | "stats" | "goal"` and a typed `value` union.

**Why it works.** One event envelope with a discriminator avoids emitting many single-purpose state events. Consumers gate on `key` to handle each variant. The frontend persists goal status into a per-conversation store on arrival (`conversation-websocket-context.tsx:652-654`).

**When to copy.** When state and events share a wire channel and a single envelope reduces consumer complexity.

**When it is overkill or risky.** When state changes are rare and could ride on dedicated lifecycle events with explicit start/finish markers. The envelope model blurs the line between "event happened" and "state snapshot," which complicates gap detection.

**Evidence.** openhands `src/types/agent-server/core/events/conversation-state-event.ts:99-151`, `src/contexts/conversation-websocket-context.tsx:643-654`.

### Pattern 7 — Event-type whitelist at persistence seam (langfuse)

**Problem.** Some upstream event types should be persisted; others (e.g., transient deltas, deprecated types) should be dropped. Without a whitelist, silent drops or surprise persists cause confusion.

**Where demonstrated.** langfuse's `toPersistableAgentEvent` (`persistence.ts:739-932`) lists every persisted event type by hand and returns `null` for explicit non-persisted types (`persistence.ts:907-928`), including deprecated `THINKING_*`, `STATE_SNAPSHOT`/`STATE_DELTA`/`ACTIVITY_DELTA`/`RAW`/`STEP_*`/`TOOL_CALL_CHUNK`/`REASONING_ENCRYPTED_VALUE`. The companion `dropRedirectToolCallEvents` (`persistence.ts:1346-1396`) collapses redirect tool-call scaffolding.

**Why it works.** The whitelist is a single audit point. Unknown types are logged and dropped. Redirect artifacts don't pollute the conversation history.

**When to copy.** Any system with a noisy upstream event vocabulary where some events are intermediate or transient.

**When it is overkill or risky.** Small stable vocabularies where every event should be persisted.

**Evidence.** langfuse `packages/shared/src/in-app-agent/server/persistence.ts:739-932,1346-1396,907-928`.

### Pattern 8 — Two-tier streaming-delta handling (openhands)

**Problem.** Per-token streaming deltas create noise that must be coalesced into a single persisted bubble per frame, without losing content when the final message arrives.

**Where demonstrated.** openhands' `StreamingDeltaBatcher` (`streaming-delta-batcher.ts:21-49`) coalesces `StreamingDeltaEvent`s; the store excludes them from the dedup `Set` (`use-event-store.ts:95-107`). Final `FinishAction`/`MessageEvent` reconciles streamed text via `mergeStreamingDeltaEvent` (`handle-event-for-ui.ts:20-29`) and the `StreamedSegments` matcher explicitly tolerates supersets (`handle-event-for-ui.ts:287-300`).

**Why it works.** Per-frame coalescing keeps the dedup `Set` O(1); the superset matcher preserves content even when a final token arrives after the action has reconciled.

**When to copy.** Any LLM streaming surface where per-token events would dominate the event volume.

**When it is overkill or risky.** Non-streaming event streams where deltas are already batched upstream.

**Evidence.** openhands `src/utils/streaming-delta-batcher.ts:21-49`, `src/stores/use-event-store.ts:95-107`, `src/utils/handle-event-for-ui.ts:20-29,215-301,374-385`.

### Pattern 9 — Compact-then-persist compaction (langfuse)

**Problem.** Storage grows linearly with turns if every `TEXT_MESSAGE_CHUNK` is persisted individually.

**Where demonstrated.** langfuse's `compactTextMessageChunks` (`eventCompaction.ts:5-33`) and `compactPersistedEventDeltas` (`eventCompaction.ts:35-62`) collapse consecutive deltas before they hit `InAppAgentEvent`.

**Why it works.** Compaction at the persistence seam keeps the runtime simple and the storage shape bounded. Activity deltas and full-message snapshots are not yet compacted — see "Notable Absences" below.

**When to copy.** Storage-bound runtimes where deltas dominate.

**When it is overkill or risky.** Read-heavy workloads that need every delta.

**Evidence.** langfuse `packages/shared/src/in-app-agent/server/eventCompaction.ts:5-33,35-62`.

## Key Differences

### Ordering guarantees

- **langfuse** enforces strict per-conversation ordering via a monotonic `sequenceNumber` assigned under a row lock. The watch cursor is gap-free by construction (`persistence.ts:75-83`). Database-clock `createdAt` is authoritative for display, but the wire `timestamp` from `@ag-ui/core` is not relied upon for ordering.
- **openhands** relies on ISO lexicographic timestamp sort plus dedup by `id`. Two events with identical timestamps are non-deterministic (`use-event-store.ts:28-31`); the transcript export relies on stable `Array.prototype.sort` to preserve server-side causal order from the response.

**Why they diverge.** Langfuse is a managed-observability product where strict replay correctness is a contractual requirement. OpenHands' agent-server prioritizes low-overhead streaming and tolerates eventual consistency for the UI; the transcript export adds a `strictPagination` mode to fail loud when completeness matters (`event-service.api.ts:144-163`).

### Versioning strategy

- **langfuse** has no `schema_version` field on events but ships a typed terminal-state vocabulary (`InAppAgentRunStatus`, `InAppAgentRunErrorCode`) that constitutes a versioned lifecycle vocabulary. Forward compatibility is achieved via `safeParse` readers that tolerate unknown values (`runLifecycle.ts:431-435,483-486,584-590`).
- **openhands** has no `schema_version` field either (`grep` for `event_version`/`schema_version` in `src/types/agent-server/` returned zero hits). Additive evolution is handled via optional fields and explicit comments (`dynamic_context?: TextContent` marked "Optional for older persisted events" — `system-event.ts:21-25`). `ACPToolCallEvent.status` tolerates `null` for legacy builds (`acp-tool-call-event.ts:65-66`).

**Why they diverge (or converge).** Both treat version compatibility as a concern but solve it via type-tolerant readers rather than explicit version fields. Langfuse's lifecycle vocabulary is more elaborate because the runtime has more terminal states (queued, running, awaiting_approval, succeeded, failed, cancelled). OpenHands relies on additive optional fields because the wire format is simpler.

### Lifecycle breadth

- **langfuse** covers creation (`RUN_STARTED`), enqueue (`QUEUED`), claim (`claimedAt` + `RUNNING`), steady-state (`heartbeatAt`), parking (`AWAITING_APPROVAL`), approval decision, success (`SUCCEEDED`), failure (`FAILED`), cancellation (`CANCELLED`), and timeout via reconciliation (`QUEUE_TIMEOUT`, `WORKER_LOST`, `RUN_TIMEOUT`, `APPROVAL_EXPIRED`), step exhaustion (`STEP_LIMIT`). The terminal-state vocabulary is explicit and exhaustive.
- **openhands** covers tool-call (action→observation), Finish (action+observation), Pause, Hooks (six types), Condensation (request+summary), Goal (running/complete/capped/interrupted), ConversationError, ServerError, AgentError. **Gaps:** no dedicated `ConversationStarted`/`RunStarted` event, no dedicated `Cancel` event (Pause + ExecutionStatus.PAUSED carry the signal), no cloud sandbox pause/resume event.

**Why they diverge.** Langfuse is built around durable workflows that must terminate in well-defined terminal states. OpenHands is built around a streaming UI where finish is inferred from `FinishAction` and pause is inferred from `ExecutionStatus` — the UI surfaces the inference rather than recording explicit lifecycle markers.

### Parent ID model

- **langfuse** threads `parentRunId`, `rootRunId`, `traceStartedAt`, `approvalRequestedAt`, `continuationNumber` (`types.ts:85-101`) so approval continuations form a lineage chain. ClickHouse-side events carry `parent_span_id`, `is_app_root`, `trace_id` for hierarchical reconstruction.
- **openhands** carries `action_id`, `tool_call_id`, `message_id`, `llm_response_id` on individual events but has **no run/span ID in the event payload** — `conversation_id` is inferred from the WebSocket URL (`websocket-url.ts:120-134`). Goal verdict `event_ids` lists `string[]` for per-event traceability but not a hierarchical run/span model.

**Why they diverge.** Langfuse supports nested runs (root + continuations + approval chains) and surfaces them to a public observability surface (ClickHouse). OpenHands treats the conversation as the unit of work and ties events to the conversation by URL, not by payload field.

### Storage and transport

- **langfuse** persists events to Postgres (durable, transactional) and projects a columnar copy to ClickHouse (analytical). The two surfaces are deliberately separate; AG-UI is the canonical conversation history, ClickHouse is the public observability surface.
- **openhands** ships events over WebSocket (`resend_mode='since'`) with REST preload (`sortOrder: "TIMESTAMP_DESC"`) for initial load (`use-conversation-history.ts:30-72`, `conversation-websocket-context.tsx:368-373,971-973`). The cloud backend may not support timestamp cursors; the API gracefully degrades to "no more pages" unless `strictPagination: true` is set.

**Why they diverge.** Langfuse owns the database. OpenHands treats the agent-server as an external service with REST+WS as the only transport.

## Tradeoffs

| Choice | Benefit | Cost | Best-fit context | Failure mode | Alternative |
|--------|---------|------|------------------|--------------|-------------|
| Per-conversation monotonic cursor | Gap-free replay guaranteed; deterministic reconstruction | Row-locking serializes throughput per conversation; latency per append | Durable workflows, replay correctness contracts, regulated environments | Hot conversation bottlenecks all appends | ISO timestamp + dedup; opens path to non-determinism |
| ISO timestamp + dedup | Low overhead; works across heterogeneous transports; no per-conversation lock | Non-deterministic for identical timestamps; relies on producer clock monotonicity | Streaming UIs, eventual-consistency consumers | Two simultaneous events with identical timestamps appear in either order | Per-conversation monotonic cursor; adds DB overhead |
| Typed terminal-error vocabulary | Dashboard segmentation; precise remediation guidance | Requires consensus on vocabulary; new error codes require coordination | Production runtimes with metrics and alerting | Unknown error codes surface as `null` and lose classification | Free-form `error: string`; loses structure |
| Fenced CAS state transitions | Safe under concurrency; no app-level mutex needed | Round-trip per transition; requires DB support for `updateMany` count | Multi-worker / multi-replica deployments | Application assumes success without checking `count === 0`; silently corrupts state | Optimistic concurrency with version fields |
| State-snapshot envelope | Single channel for all state changes; reduces event count | Blurs "event happened" vs "state snapshot"; complicates gap detection | Mixed event+state streams where consumers want both on one channel | Replay can't distinguish "snapshot at time T" from "event at time T" | Dedicated lifecycle events (langfuse model) |
| Event-type whitelist at persistence seam | Single audit point; explicit non-persisted types | Maintenance burden; new types must be added to the whitelist | Large upstream vocabularies with transient/intermediate types | Unknown types silently dropped without surfacing in tests | Persist-everything model; bloats storage |
| Schema duplication (langfuse `schema.ts:9-14`) | Decouples from upstream Zod version mismatch | Drift risk when upstream changes | Cross-package Zod compatibility issues | Future schema change in `@ag-ui/core` requires manual sync | Direct import; breaks on version skew |

## Decision Guide

**Choose per-conversation monotonic cursor (langfuse pattern) when:**
- The runtime must guarantee strict replay correctness (durable workflows, regulated environments, multi-worker fan-out).
- The product exposes lifecycle events to consumers who will treat missed events as bugs.
- Operational metrics distinguish terminal states (cancellation vs timeout vs worker-loss vs step-limit).
- The DB supports `updateMany` count-based fencing and per-row locking without significant throughput cost.

**Choose ISO timestamp + dedup (openhands pattern) when:**
- The runtime is single-writer per conversation and tolerates eventual consistency.
- Consumers are streaming UIs that coalesce events into bubbles, not audit logs that need every delta.
- The wire crosses an HTTP/WS boundary where row-locking is not feasible.
- Operational metrics are coarse (success vs failure vs error) rather than fine-grained per terminal state.

**Choose typed terminal-error vocabulary when:**
- The runtime has more than 3 distinct terminal states (e.g., succeeded, failed, cancelled, timed out, lost worker).
- Dashboards need to segment failures by type.
- A reconciler is the authoritative writer for timeout-derived failures.

**Choose state-snapshot envelope when:**
- State changes (execution_status, goal status, conversation stats) share a wire channel with raw events.
- Consumers want both state and events on one transport.
- The distinction between "event happened" and "state snapshot" is unimportant for downstream consumers.

**Choose event-type whitelist at persistence seam when:**
- The upstream vocabulary is large or evolving.
- Some events are intermediate/transient and should be dropped.
- A single audit point for what gets persisted is operationally valuable.

**Choose schema duplication when:**
- Upstream library version skew (e.g., Zod v3 vs v4) prevents direct import.
- The cost of drift is lower than the cost of breaking on every upstream change.

**Choose compact-then-persist compaction when:**
- Storage grows linearly with turns (text/reasoning deltas dominate).
- Read-heavy workloads don't need every delta.
- The compaction logic is pure and testable.

## Practical Tips

### Patterns to copy

1. **Per-conversation monotonic cursor for replay-critical runtimes.** Pair it with a row lock and a `(conversationId, sequenceNumber)` composite primary key.
2. **Typed terminal-state vocabulary.** Enumerate every way a run can fail or terminate; don't rely on error message parsing.
3. **Fenced CAS with `{count: 0}` semantics.** Detect lost-ownership without re-reading the row.
4. **Runtime type guards at the wire boundary.** A single `isBaseEvent`/`isAgentServerEvent` chokepoint drops malformed events before they touch state.
5. **Per-conversation lock + per-row lock.** Compose them when both correctness and isolation matter.
6. **Action→observation supersede in UI.** Replace `ActionEvent` by id when its matching `ObservationEvent` arrives; reduces visual noise without losing data.
7. **Defensive dedup of replayed events.** Side-effects in WS handlers must be idempotent across reconnects; gate them on `eventIds.has`.
8. **Reconciliation as the source of truth for timeouts.** `classifyStaleRun` is pure; reconcilers and read paths cannot diverge.
9. **Compact-then-persist for high-volume deltas.** Coalesce text/reasoning chunks before they hit durable storage.

### Patterns to avoid or delay until needed

1. **Per-conversation row locking** for single-writer systems. The latency is unjustified if only one process ever appends.
2. **Typed terminal-error vocabulary** for short-lived streaming pipelines. A single `error: string` is sufficient when errors are reported and forgotten.
3. **Event-type whitelist at persistence seam** for small stable vocabularies. The maintenance cost outweighs the audit benefit.
4. **State-snapshot envelope** when events and state should be on separate transports. Mixing them complicates gap detection.
5. **Schema duplication** unless upstream version skew forces it. Direct import is simpler.

### Decision rules

- **Strict replay required?** → Per-conversation monotonic cursor (langfuse).
- **Streaming UI with eventual consistency?** → ISO timestamp + dedup (openhands).
- **More than 3 terminal states?** → Typed vocabulary.
- **Multi-worker or multi-replica?** → Fenced CAS.
- **Wire crosses HTTP/WS boundary?** → Prefer ISO timestamp; row-locking is not available.
- **Per-token events would dominate volume?** → Compact-then-persist.

### Caution signs

- **Two events with identical ISO timestamps and non-deterministic order.** Indicates ISO-timestamp-only ordering without a tiebreaker.
- **Silent drops of unknown event types.** Indicates a whitelist without logging or alerting.
- **Cancellation indistinguishable from pause.** Indicates `PauseEvent` carrying the cancellation signal without a typed `CancelEvent`.
- **Cloud sandbox lifecycle invisible to events.** Indicates infrastructure lifecycle separated from event stream.
- **Schema changes shipped without version field.** Indicates additive-only evolution that old clients can't detect.
- **Reconciliation writes and reads diverge.** Indicates reconciler not the sole authority for timeout-derived transitions.
- **Per-conversation lock held during long-running operations.** Indicates throughput bottleneck risk.

## Anti-Patterns / Caution Signs

| Anti-pattern | Symptom | Why it's bad | Where seen (or avoided) |
|--------------|---------|--------------|-------------------------|
| ISO timestamp-only ordering | `compareEventsByTimestamp` with no monotonic `seq` | Two events with identical timestamps are non-deterministic | openhands acknowledges this in `use-event-store.ts:28-31` and adds `strictPagination` mode for completeness-sensitive callers |
| No `schema_version` field | `grep` for `event_version`/`schema_version` returns zero hits | Old clients can't detect a wire schema they don't understand; silently ignore unknown kinds | Both sources; mitigated by type-tolerant readers and additive optional fields |
| Pause and cancellation on the same channel | `PauseEvent` + `ExecutionStatus.PAUSED` without typed `CancelEvent` | User-pause indistinguishable from auto-pause | openhands — gap surfaced in `pause-event.ts:4-8` and `common.ts:67-75` |
| Cloud lifecycle outside event stream | Sandbox pause/resume suppresses WS URL but emits no event | Pause/resume invisible to event-log observers | openhands — documented in `AGENTS.md` "Cloud conversation resume gating" |
| Schema duplication debt | Zod v3/v4 mismatch forces manual copy | Drift risk when upstream changes | langfuse `schema.ts:9-14` — tracked upgrade path exists |
| Per-conversation lock serializing throughput | Every event append holds `lockConversation` | Hot conversation bottlenecks all appends | langfuse — accepted for correctness; read-side cursor streams without locking |
| Free-form error message parsing | `error: string` without typed codes | Loses classification; downstream dashboards can't segment | Avoided by langfuse via `InAppAgentRunErrorCode`; openhands carries `code` + `classification` on error events |
| Duplicate event writes from two paths | `RUN_STARTED` skipped in runtime `onEvent` because `createQueuedRun` already wrote it | Type-level duplication prevention, not constraint-level | langfuse `executeInAppAgentRun.ts:461-463` — works today; could break with multi-writer |

- **No retention / archival policy for `InAppAgentEvent`.** No retention migrations found under `packages/shared/prisma/migrations/`. Runtime has no built-in eviction.

### OpenHands

- **No `ConversationStarted` / `RunStarted` event.** Conversation creation is metadata on `AppConversation.created_at` (`agent-server-conversation-service.types.ts:200-215`), not an event-stream record.

- **No machine-readable schema artifact** (OpenAPI/JSON-Schema) in the frontend repo. The canonical schema lives in `software-agent-sdk` (Python, Pydantic); frontend type module re-declares events as TypeScript.
