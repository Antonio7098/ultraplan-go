## Executive Summary

Seven sources spanning agent libraries, a multi-tenant observability platform, an agent server, two infrastructure engines, and a frontend converge on one structural answer: keep secrets out of every surface the model, policy, or client can see, and inject them through ambient channels resolved at execution time. They diverge sharply on the dimension's guiding question — *can a trace be shared without leaking credentials?* Only agent-framework answers "yes by default" for its own telemetry (`observability.py:768-780`, whitelist at `observability.py:2631-2680`). openai-agents-sdk answers "no by default" because `trace_include_sensitive_data` defaults to True (`run_config.py:53-56`), and letta answers "no" outright: E2B execution-start events carry full decrypted sandbox env vars (`e2b_sandbox.py:90-99`). The rest are partial — gated by license (langfuse EE masking), opt-in policy that fails soft (opa), curated surfaces only (openhands), or excluded-payload discipline left to operators (temporal).

Scores cluster tightly (6–8, mean ≈7). The spread is explained less by storage sophistication than by egress discipline: letta has the most elaborate crypto stack of the group (AES-256-GCM + PBKDF2 per value, `crypto_utils.py:104-150`) yet scores lowest because its observability plane publishes what its storage plane protects. openhands ships no client-side crypto at all yet scores 7 because its wire protocol carries only `LookupSecret` references and regression tests pin that channel as sole (`__tests__/api/agent-server-adapter.test.ts:561-656`). The strongest convergent mechanisms are allowlist-by-construction egress filtering, typed secret wrappers with masked reprs, inject-at-execution indirection, and negative tests codified as security invariants.

## Core Thesis

**Secret safety in agent harnesses is decided at the egress boundaries — telemetry, serialization, logs, wire payloads — not at storage.** Sources that treat every egress point as a gated, allowlisted, tested surface score higher regardless of whether they have a vault integration or encryption-at-rest; sources that invest in storage while leaving one ungated channel open leak anyway.

Three observations support this across sources:

- **Encryption quality did not predict rating.** letta (6/10) encrypts everything at rest with per-value salts and has dedicated crypto tests (`tests/test_crypto_utils.py:16-373`), yet a single unfiltered OTEL event defeats it (`e2b_sandbox.py:90-99`). langfuse (8/10) wins not on cipher strength (same AES-256-GCM family, single global key, `encryption.ts:18-34`) but because its data layer strips secrets from every read path by default via Prisma-wide column omission and allowlist schemas (`db.ts:32-39`; `automations.ts:218-229`).
- **Indirection beat protection.** openhands never holds values in the conversation wire — secrets travel as URL lookups the server dereferences at spawn (`agent-server-adapter.ts:1203-1228`) — which is a stronger guarantee than any post-hoc masking of values that were already transported.
- **Defaults decided outcomes more than mechanisms.** agent-framework's deny-by-default content capture plus a sticky disable switch (`observability.py:1238-1261`) makes its traces shareable out of the box; openai-agents-sdk has comparable gating machinery but flips the trace default to include-sensitive (`run_config.py:53-56` vs `_debug.py:12-27` for logs), producing the sharpest safety cliff in the study.

## Approach Models

- **agent-framework — construction-time credentials, gated telemetry.** Secrets resolve during chat-client instantiation through a layered loader (override → `.env` → env var → default, `_settings.py:199-292`) wrapped in `SecretString`; Azure paths use `TokenCredential` objects rather than string keys (`_chat_client.py:226-230`). Tool credentials flow through per-request `header_provider` callbacks origin-scoped against redirects (`_mcp.py:3159-3175`), ContextVar-sourced providers kept out of arguments (test `test_mcp.py:7967-8027`), or stdio `env` maps (`_mcp.py:2893-2914`). Telemetry emits metadata always but content only behind `ENABLE_SENSITIVE_DATA`, with whitelist-only OTel tool-definition serialization (`observability.py:2666-2680`).

- **langfuse — platform vault with capability lifecycle.** Three credential classes (customer provider credentials, Langfuse API keys, ephemeral agent identities) under one model: AES-256-GCM seal at write (`router.ts:270`), masked display twins (`displaySecretKey`), strip-on-read projections, bcrypt+fast-hash API keys never stored in plaintext (`apiKeys.ts:14-40`), decrypt only inside job handlers (`webhooks.ts:538`), and a fresh project-scoped read-only MCP key minted in-transaction per agent run and deleted at terminal states (`executeInAppAgentRun.ts:381-399`).

- **letta — encrypted columns + layered sandbox injection.** A first-class `Secret` pydantic type (encrypted in memory, masked repr, `secret.py:13-32`) backs provider keys, MCP tokens, and org/agent-scoped env vars in Postgres. Injection follows strict precedence OS env → org-global → provided → agent-scoped → runtime (`base.py:476-517`), decrypted as late as possible before subprocess/E2B launch (`sandbox_config_manager.py:322-340`). An optional webhook brokers per-(user/org/tool/agent) credentials (`sandbox_credentials_service.py:45-59`).

- **opa — declarative service credentials, infrastructure-held secrets.** Each outbound `services[_]` entry selects exactly one credential method (bearer/OAuth2/mTLS/SigV4/GCP/Azure/custom plugin, enforced at `rest.go:104-115`); tokens are read from files per request (`auth.go:99-124`) or fetched from cloud metadata/KMS/KeyVault so key material never enters config (`auth.go:377-428`). Redaction is layered: hardcoded debug-log header redaction (`rest.go:36-39`), purge-at-read for `opa.runtime().config` (`topdown/runtime.go:52-111`), and Rego-authored decision-log mask/drop policies (`plugin.go:1048-1141`).

- **openai-agents-sdk — exposure control without a secret store.** No unified vault; credentials arrive via host env, programmatic setters, or inline mount entries, with `EnvValue.resolve()` as an extension point still TODO (`manifest.py:84-110`). Instead, four egress channels are controlled: logs default-redacted (`_debug.py:12-27`), exception chains rebuilt frame-by-frame to drop payloads (`exceptions.py:140-178`), serialized state stripped of mount authority and re-bound only against a current trusted manifest (`_mount_security.py:1751-1813`), and span payloads gated behind `trace_include_sensitive_data`.

- **openhands — transport indirection with explicit exposure tri-state.** The frontend stores secrets server-side and launches conversations with `LookupSecret` URL references the server resolves at spawn (`agent-server-adapter.ts:1203-1228`); settings reads distinguish redacted display / Fernet ciphertext / backend-only plaintext via `X-Expose-Secrets` (`settings-service.api.ts:115-122`); UI re-masking of `<CUSTOM_SECRETS>` blocks acts as a defensive backstop against backend regressions (`redact-custom-secrets.ts:1-32`).

- **temporal — config-as-code with refresh boundaries and layered identity.** YAML config optionally template-rendered from env vars via sprig (`loader.go:226-252`); database passwords can come entirely from an external `passwordCommand` designed for short-lived IAM tokens (`persistence.go:299-323`) refreshed per connection by a `RefreshingConnector` (`connector.go:8-39`). Identity is normalized once in a gRPC interceptor into claims with per-namespace roles (`interceptor.go:251-299`, `roles.go:25-36`), with mTLS cert groups per relationship and hot reload.

## Pattern Catalog

### P1. Masking-by-type (typed secret wrappers)

- **Problem:** accidental leaks through logging, reprs, and serialization.
- **Demonstrated by:** agent-framework (`SecretString` masking `repr()`, `_settings.py:52-82`); letta (`<Secret: ****>` repr asserted by regression test, `secret.py:271-279`, `tests/test_secret.py:121-140`).
- **Why it works:** preserves normal string ergonomics and framework compatibility (pydantic) while making the accidental path (repr/debug print) safe; cheap to adopt incrementally.
- **Copy when:** your language supports str subclasses/value types and you have many secret-shaped fields converging on one type.
- **Risky/overkill when:** treated as the sole control. agent-framework documents that f-string interpolation still prints the value by design (`_settings.py:62-69`); letta silently degrades to plaintext in the `_enc` column without a master key (`secret.py:55-69`). Masking-by-type is ergonomics hardening, not secrecy.
- **Evidence:** both reports rate this pattern positively but explicitly caveat its limits.

### P2. Allowlist-by-construction at egress layers

- **Problem:** new fields silently carry secrets into responses, traces, and exports as schemas evolve.
- **Demonstrated by:** langfuse (Prisma client-wide `omit` of secret columns plus `Safe*Schema.omit({secrets})`, `db.ts:32-39`, `automations.ts:87,123`); agent-framework (OTel tool definitions keep only type/name/description/parameters, dropping `authorization`/`headers`, `observability.py:2666-2680`); opa (request-context headers enter decision logs only when explicitly configured, `plugin.go:745-759`); openai-agents-sdk (authority-field tables per mount type, `_mount_security.py:57-107`).
- **Why it works:** unknown fields are dropped by default, so the control survives schema growth; each source pairs it with named negative tests.
- **Copy when:** building any serialization toward a less-trusted plane (UI, telemetry backend, export files, audit logs).
- **Overkill when:** purely internal debug tooling where fidelity outranks leakage risk — though even there, gate by flag rather than omitting the mechanism (see agent-framework's opt-in sensitive capture).

### P3. Inject-at-execution via indirect channels

- **Problem:** model-supplied tool arguments or prompts must never become the credential transport.
- **Demonstrated by:** agent-framework (`header_provider` + ContextVar proven by test to keep credentials out of arguments, `test_mcp.py:7967-8027`); letta (sandbox env-var layering, `base.py:476-517`; MCP `{{ VAR }}` templating, `types.py:194-202`); openhands (`LookupSecret` URLs resolved server-side, `agent-server-adapter.ts:1203-1228`); langfuse (decrypt inside the job handler immediately before use, `llmText.ts:301-304`); temporal (`passwordCommand` + `RefreshingConnector` resolving fresh DSN per connection, `connector.go:29-39`).
- **Why it works:** the credential stays ambient (process env, callback, server-side lookup) so the LLM-visible surface never carries it; several sources prove this property with tests rather than asserting it.
- **Copy:** essentially always, for any tool/MCP credential path.
- **Risky when:** the indirect channel itself becomes an egress. Letta is the cautionary case: env-var injection worked, then the execution-start OTEL event published the whole resolved dict (`e2b_sandbox.py:90-99`). Also note agent-framework serializes calls when a `header_provider` is set to prevent wrong-credential races (`_mcp.py:3123-3130`) — correctness bought with concurrency.

### P4. Durable state never grants authority

- **Problem:** serialized runs, sessions, and exports resurrect credentials after theft or sharing.
- **Demonstrated by:** openai-agents-sdk (session-state serialization sanitizes mount authority and sets a REDACTED marker; resume requires exact-match rebind against a current trusted manifest, `_mount_security.py:1723-1813`, `sandbox_session_state.py:300-347`); openhands (wire payloads carry lookups, not values); langfuse (API keys stored hash-only, `apiKeys.ts:14-40`); openai-agents-sdk again for tracing keys (SHA-256 fingerprint persisted instead of the key, `traces.py:171-192`).
- **Why it works:** a stolen snapshot can be inspected but cannot act; re-binding forces the thief to also possess current trusted configuration.
- **Copy when:** runs pause/resume/export, or state crosses trust domains (browser ↔ server, worker ↔ queue).
- **Cost:** resume flows get stricter and can fail closed on topology mismatch — openai-agents-sdk accepts this deliberately (`test_mount_authority_rebind_requires_exact_credential_free_topology`).

### P5. Ephemeral capability keys scoped per task/run

- **Problem:** long-lived broad-scope keys turn one conversation compromise into a vault compromise.
- **Demonstrated by:** langfuse (per-run project-scoped MCP key minted in the same transaction that links it to the run row, flagged read-only by default, deleted on finish/error/cancel with a reconcile sweep for crashed workers, `executeInAppAgentRun.ts:381-399,130-137`); temporal (Nexus completion tokens bound to component ref + request ID, `callback_token.go:22-33` — though unsigned).
- **Why it works:** blast radius shrinks to a single run's lifetime; audit logs attribute actions back to the human creator (`auditLog.ts:96-122`).
- **Copy when:** an autonomous agent needs platform API access. This is the study's clearest differentiator between langfuse (8) and openhands (7), whose launcher attaches *every* saved secret to *every* conversation start (`agent-server-adapter.ts:1269-1274`).
- **Risky when:** cleanup correctness is assumed rather than engineered — langfuse needed deletion guards preventing the cleanup path from eating user keys (`apiKeys.ts:124-134`) plus crash reconciliation.

### P6. Fail-closed gates at trust boundaries (vs fail-open peers)

- **Problem:** degraded modes quietly ship secrets or accept forged state.
- **Demonstrated (fail-closed):** temporal boots reject token-required-without-provider and provider-without-TLS pairings (`fx.go:300-308`); openhands aborts conversation launch rather than starting with redacted/broken credentials (`settings-service.api.ts:500-511`); openai-agents-sdk rejects credentialed in-container mounts unless runtime-only acknowledged code opts in (`manifest.py:296-351`); agent-framework makes `disable_instrumentation()` sticky against library re-enable attempts (`observability.py:1238-1261`).
- **Counter-examples (fail-open):** letta writes plaintext into `_enc` columns when no key is set (`secret.py:55-69`); opa uploads decision-log events *unmasked* if the mask rule errors (`plugin.go:785-788`); langfuse ingestion masking defaults fail-open (`applyIngestionMasking.ts:210-215`).
- **Why it works:** security posture becomes a startup-time invariant instead of a runtime hope.
- **Copy when:** the failure mode is silent credential exposure; degrade availability, not confidentiality.

### P7. Negative tests as security invariants

- **Demonstrated by:** langfuse (VIEWER-role reads assert `not.toHaveProperty("secretKey")` across list and detail routes, `automations-trpc.servertest.ts:2896+`); agent-framework (dedicated OTel secret-leak tests, `test_observability.py:4166-4340`); openhands ("request.secrets is the sole channel" regression tests forbidding context mirroring, `agent-server-adapter.test.ts:561-656`); openai-agents-sdk (132 mount-security tests including provenance forgery and serialization redaction); letta (`tests/test_mcp_encryption.py:69-90` verifying ciphertext written, plaintext NULL).
- **Why it works:** absence-of-property and channel-uniqueness assertions encode the threat model so refactors cannot silently regress them; langfuse even codifies the doctrine itself in-repo (`.agents/skills/security-review/references/secret-read-paths.md`).
- **Copy:** universally. Every source scoring ≥7 has this; it is the cheapest high-yield practice in the study.

### P8. Redirect/origin hygiene for credentialed requests

- **Demonstrated by:** agent-framework (origin-scoped header injection comparing scheme/host/port before attaching, `_mcp.py:3159-3175`); langfuse (`createSecureLlmFetch` strips provider auth + gateway headers when origin changes, `llmText.ts:306-318`); opa (no `Authorization` on 307/308, AWS signing skipped on host change, `auth.go:117-122,866-872`).
- **Why it works:** redirect-based exfiltration is a cross-cutting hazard independent of where secrets are stored; three independent implementations converge on the same check.
- **Copy:** whenever code attaches credentials to HTTP requests dynamically. Caveat from agent-framework: custom `http_client`s bypass the guarantee (`_mcp.py:3045-3053`).

## Key Differences

**Where secrets live.** Config/env-first (opa, temporal) suits engines deployed by operators who already run k8s secret mounts and instance profiles — opa treats "the environment is the secret store" explicitly (`aws.go:31-59`, metadata endpoints). Database-encrypted-columns (langfuse, letta) suit multi-tenant platforms whose users submit credentials at runtime. Client-construction (agent-framework) and remote-store-with-lookup (openhands) suit libraries and frontends that should hold nothing durable themselves. These are constraint-driven choices, not quality rankings: opa's lack of a vault SPI is a real gap for enterprise users (`rest.go:90-102` custom plugins are the only escape hatch), but building one would add dependencies to a zero-dependency engine.

**Who enforces redaction, and at what layer.** agent-framework gates inside the instrumentation library (every content-bearing span write checks a settings object, `observability.py:1655` et al.). langfuse pushes sanitization into the data layer so every route inherits it (`db.ts:32-39`) — the repo doctrine argues routes are too numerous to sanitize individually (`secret-read-paths.md:44-67`). opa externalizes it to policy authors (Rego mask/drop). openhands duplicates it deliberately at the UI as a backstop (`redact-custom-secrets.ts:3-7`). letta and temporal have no general mechanism at all. The lesson: centralizing enforcement at one choke point beats distributing discipline across call sites, but the choke point must cover the actual egress planes — langfuse's own logger lacks a redact filter despite its data-layer rigor.

**Identity granularity.** Per-run ephemeral capabilities exist only in langfuse among the agent-facing sources. temporal offers strong per-user/per-namespace scoping (JWT claims re-authorized per target namespace, `interceptor.go:347-417`) but process-wide outbound identity. letta has structural task granularity (agent-scoped env vars override org ones) undermined by a weak runtime anchor: actor identity comes from an unauthenticated client header with a shared default fallback unless a flag is flipped (`user_manager.py:113-133`). openai-agents-sdk and opa have essentially no per-task identity concept — scoping is delegated to the embedding application.

**Sandbox environment handling spans the full spectrum.** Most restrictive: langfuse injects *zero* env vars into sandboxes — only tool-call file contents (`docker.ts:77-85`). Restrictive-by-default with escape hatch: agent-framework shell tools' `clean_env=True` stops inheriting `os.environ` entirely (`shell/_tool.py:113-118`), and .NET's `EnvironmentSanitizer` keeps only PATH/HOME/USER-class variables (`EnvironmentSanitizer.cs:20-60`). Manifest-confined: openai-agents-sdk Docker backend resolves container env only from the manifest (`docker.py:1736-1744`) — but its unix-local backend copies the entire host environment (`unix_local.py:442-451`). Legacy-hazardous: letta's direct mode temporarily swaps the whole server-process `os.environ` mid-request (`tool_execution_sandbox.py:114-122`).

## Tradeoffs

- **Operational simplicity vs blast radius (single master key).** langfuse runs every integration secret under one global `ENCRYPTION_KEY` (`encryption.ts:4`) and acknowledges the concentration in its own doctrine (`secret-read-paths.md:14-17`); letta does the same with `LETTA_ENCRYPTION_KEY` plus per-value PBKDF2. Both favor self-host friendliness over per-tenant envelopes; neither shows a rotation path in code (langfuse's only remediation is a legacy-plaintext migration, `encryptBlobStorageSecrets.ts:74-107`). Alternative seen: opa/temporal push custody to infrastructure (file mounts, metadata services, KMS signing), trading centralized auditability for distributed trust.

- **Availability vs confidentiality in failure modes.** letta chose plaintext fallback over refusing writes without a key (`secret.py:55-69`) — desktop-friendly, silently insecure. openhands chose the opposite for a narrower moment: launching with redacted credentials throws (`settings-service.api.ts:500-511`). opa's mask-failure behavior (`plugin.go:785-788`) and langfuse's fail-open masking show the same axis in log pipelines: keeping ingestion alive means shipping unmasked content by default.

- **Debuggability vs shareability in telemetry defaults.** agent-framework ships content-off by default (metadata telemetry always, payload opt-in, `observability.py:777-780`); openai-agents-sdk ships logs-off but traces-on (`_debug.py:12-17` vs `run_config.py:53-56`), maximizing new-user debuggability at the cost of "just share this trace" being dangerous. Both document the flags; only agent-framework adds a sticky kill switch so user intent outranks library auto-setup (`observability.py:1238-1261`).

- **Global attachment vs least privilege.** openhands attaches all secrets to every run for client simplicity (`agent-server-adapter.ts:1269-1274`), explicitly noted as violating minimal exposure; langfuse pays the complexity cost of per-run mint/delete (row churn, reconcile sweeps) for run-scoped capability. The tradeoff is operational machinery versus incident blast radius.

- **Rich tracing vs secret-free backends.** letta persists full provider request/response JSON by default (`settings.py:387`) and logs complete sandbox env dicts — turning OTLP collectors and ClickHouse into secret stores. langfuse's sandbox providers log summarized payloads (byte counts, truncated previews) instead of content (`docker.ts:537-599`). Same observability goal, opposite retention posture.

- **Usability affordances vs enforcement.** agent-framework keeps the convenient shared `function_invocation_kwargs` dict and merely documents the cross-server forwarding hazard (`_mcp.py:3089-3094`); openai-agents-sdk rejects the analogous situation outright — credentialed mounts fail closed until trusted code acknowledges (`manifest.py:296-351`). Library ergonomics pull toward warn-and-document; application/platform code pulls toward refuse-and-explain.

## Decision Guide

Choose a primary approach by product shape:

1. **Library/SDK embedded in others' apps** (agent-framework, openai-agents-sdk shape): do not build a vault. Provide typed settings with precedence rules, ambient credential channels (callbacks/ContextVar/env maps), deny-by-default telemetry with a sticky kill switch, and whitelist-based serialization. Delegate custody to the host (platform credentials, `TokenCredential`, `EnvValue` extension points). Accept that per-user identity propagation belongs to the host.
2. **Multi-tenant platform holding user secrets** (langfuse shape): encrypt-at-rest with a validated master key, store API keys hash-only, make the data layer strip secrets by default (client-wide omission + derived Safe schemas), mint ephemeral per-task capability keys in-transaction with teardown reconciliation, and enforce with least-privilege negative tests. Add envelope key rotation earlier than either studied source managed.
3. **Engine/service operated by admins** (opa, temporal shape): declarative per-service credential blocks selecting exactly one method, per-request resolution so mounted/short-lived credentials rotate without restart, boot-time validation of auth/TLS pairing, field-level config masking for dumps, and policy-controlled (auditable) log sanitization. Treat the deployment environment as the secret store rather than embedding provider SDKs.
4. **Client/frontend talking to an agent server** (openhands shape): never hold or transmit values — carry lookup references the server dereferences in its own trust domain, split display vs launch vs round-trip exposures into explicit modes, fail closed when integrity is uncertain, and pin the sole-channel contract with regression tests.

Cross-cutting decision rules:

- If a credential must reach a tool, prefer the channel the model cannot author: env mapping > ambient callback > argument-side kwarg. Never pass credentials through model-visible kwargs (the documented agent-framework hazard).
- If you cannot enumerate what leaves the process, invert to allowlists at each serializer rather than trying to scrub patterns afterward.
- If a feature degrades when its security prerequisite is missing (encryption key absent, TLS absent, trusted manifest stale), decide explicitly whether it fails open or closed — three of seven sources leaked precisely because this was implicit.

## Practical Tips

- **Gate content, not instrumentation.** Ship telemetry metadata always and payloads behind an opt-in flag (agent-framework model). Pair it with a sticky disable so a user's off decision survives library auto-setup.
- **Derive safe views from unsafe ones.** langfuse's `Safe*Schema = FullSchema.omit({secrets})` and Prisma-wide `omit` mean one declaration controls every read path; openai-agents-sdk derives authority tables per mount type the same way. Hand-written sanitizers drift; derived ones don't.
- **Mask at the type, test the mask.** Adopt a `Secret`/`SecretString` wrapper with masked repr *and* a regression test asserting the plaintext never appears in string output (letta `tests/test_secret.py:121-140`).
- **Resolve credentials per request, not per process.** opa's `token_path` read-per-request enables k8s secret-mount rotation with zero restarts (`auth.go:99-124`); temporal's `RefreshingConnector` does the same for DB connections (`connector.go:8-27`). Design the seam once and short-lived credentials work everywhere.
- **Mint-and-delete capability keys for autonomous access.** Copy langfuse's transactional link of key→run row, read-only default, deletion guards, and crash reconcile sweep — all four pieces are load-bearing.
- **Serialize nothing that grants authority.** Strip credentials from persisted state, persist a fingerprint (SHA-256) where identity verification is needed, and require re-binding against current trusted config on resume (openai-agents-sdk).
- **Add absence assertions to your test suite.** `expect(row).not.toHaveProperty('secretKey')` on least-privileged paths, and "sole channel" tests asserting secrets never mirror into prompt-facing context, catch the most common regression class observed across these reports.
- **Check origins before attaching credentials to redirects.** Three independent implementations converged on scheme/host/port comparison; reuse one of them rather than inventing policy.

## Anti-Patterns / Caution Signs

- **Logging the injection payload.** The single worst finding in the study: letta's E2B execution-start event records the entire decrypted env-var dict (`e2b_sandbox.py:90-99`), converting its strongest mechanism (late decryption) into its largest leak. Any time a "started X with Y" debug event includes resolved credentials, assume the trace backend is now a secret store.
- **Sensitive-data defaults that differ per channel.** openai-agents-sdk's logs-safe/traces-unsafe asymmetry means teams that verified their logs will still leak via traces. Caution sign: any security default that must be memorized per-output-plane.
- **Fail-soft redaction.** opa's mask-rule error path returns nil and uploads the event unmasked (`plugin.go:785-788`); langfuse's masking fails open by default. A redaction pipeline that can silently degrade to full fidelity is not a control.
- **Fixed-name masking lists.** temporal masks exactly `Password`/`KeyData` (`masker.go:11-14`) — renamed or new secret-bearing fields escape silently; opa's debug-log denylist covers two headers, missing anything like `X-Vault-Token`. Caution sign: denylists that require editing source to extend.
- **Blanket attachment of credentials.** Every secret on every run (openhands) collapses per-conversation blast radius to the whole vault. Caution sign: no API to say "this run needs only these two secrets."
- **Plaintext fallbacks and dual columns.** letta retains NOT NULL legacy plaintext columns alongside `_enc` ones (`sandbox_config.py:49-53`, OAuth tables `mcp_oauth.py:21-59`) and falls back to cleartext without a key — migration-friendliness preserving attack surface indefinitely.
- **Convenience kwarg channels.** Shared kwargs forwarded to every server whose schema declares the name (agent-framework `_mcp.py:3084-3094`) are documented hazards; the framework warns but doesn't block. Caution sign: credential transport reachable through the same interface the model influences.
- **Full host-env inheritance in dev/local modes.** openai-agents-sdk's unix-local sandbox (`unix_local.py:442-451`) and letta's legacy process-env swap put host secrets one `env` command away from the transcript; the Docker/subprocess counterparts avoid this, showing the constraint is choice, not necessity.
- **Unsigned or weakly-held capability tokens.** temporal's Nexus callback tokens are plain base64 (`callback_token.go:28`); anyone capturing one can post a completion until namespace-match validation stops them. Caution sign: capability envelopes with "encryption later" comments shipping in production paths.

## Notable Absences

Across all seven sources, the following were repeatedly absent — useful signal about what the industry does *not* yet standardize:

- **No universal secret scrubber for arbitrary log output.** agent-framework found no redaction for user-provided log statements or middleware output; temporal searched `redact|scrub|sanitiz|mask` repo-wide and found only four narrow sites; letta and langfuse's winston logger have no redact filter; openhands has none over terminal/event streams. Content redaction is everywhere channel-specific, nowhere systemic.
- **No generic vault/secret-provider SPI in the engines.** opa's only extension is custom Go auth plugins (`plugins.go:740-749`); temporal uses an exec-command shim (`passwordCommand`) where a `SecretProvider` interface would sit; openai-agents-sdk's `EnvValue` secret-store implementation is an open TODO (`manifest.py:84`).
- **Per-tool ACLs binding identities to specific tools** — agent-framework explicitly found none; openai-agents-sdk's domain-scoped secrets are hosted-shell-only (`tool.py:1219-1232`).
- **CI secret scanning** — not located within langfuse's inspected workflows; openai-agents-sdk found none; unverified elsewhere. Given how many sources committed dev credentials or shipped placeholder keys (temporal's `"temporal"` passwords in `development-mysql8.yaml:17`, langfuse compose's all-zeros `ENCRYPTION_KEY` at `docker-compose.yml:24-25`), this gap is conspicuous.
- **TTL backstops for cleanup-dependent lifecycles.** langfuse suggests TTL expiry behind its reconcile sweep as future work; openai-agents-sdk has no rotation handling for inline mount credentials.
- **Data-plane payload encryption in-repo.** temporal ships codec plumbing only and delegates encrypted payloads to external codec servers; letta cannot confirm whether stored LLM traces ever carry credential material.

## Per-Source Notes

- **agent-framework (7):** Strongest telemetry posture of the group — deny-by-default content, sticky disable, whitelisted OTel attributes with named leak tests. Origin-scoped `header_provider` injection and clean-env shell modes are best-in-class mechanisms. Held back by the documented `function_invocation_kwargs` forwarding hazard, repr-only masking, per-provider (not pipeline-wide) .NET redaction, and experimental FIDES information-flow labeling.
- **langfuse (8):** Highest score. The data-layer enforcement model (encrypt-on-write, mask-for-display twins, strip-on-read via client-wide omission, decrypt-in-handler) plus per-run ephemeral agent keys with transactional lifecycle is the most complete design studied. Gaps are operational: no log-redaction mechanism, EE-gated fail-open masking, all-zeros compose defaults, and ciphertext embedded in delete-audit payloads.
- **letta (6):** Best-in-group crypto ergonomics (typed `Secret`, async-first PBKDF2 batching, export scrubbing, prefix heuristics) undermined by the observability plane: raw env dicts in OTEL events, unfiltered `log_event`, decrypted MCP tokens in API responses, silent plaintext fallback, and residual plaintext OAuth columns.
- **opa (7):** Most mature *outbound* credential machinery — six declarable methods, single-method enforcement, per-request file reads, KMS/KeyVault sign-in-place, redirect hygiene. Decision-log mask/drop is uniquely auditable (applied pointers recorded on events) but opt-in and fail-soft; `opa.runtime().env` exposes the whole process environment to every policy by design.
- **openai-agents-sdk (7):** Deepest treatment of durable-state authority: 132-test mount-security module, sanitized session state, exact-topology rebind, runtime-only exposure acknowledgements, fingerprint-not-secret persistence. The trace-default cliff and full-host-env local sandbox are the two deliberate-but-costly choices.
- **openhands (7):** Cleanest *transport* story — LookupSecret indirection, tri-state exposure header, fail-closed launch, sole-channel regression tests, layered UI backstop masking with longest-first replacement ordering. Weakest *scoping* story: all secrets on every run, browser-held plaintext for renames, shared HOME race tracked as TODO #1019, and server-side enforcement unverifiable from this repo.
- **temporal (7):** Strongest identity architecture (spoof-resistant principal headers, per-namespace claims re-authorized per target, mTLS cert groups with expiry telemetry) and clever credential-refresh boundaries. Secret handling itself is ad hoc: two-field config masking, JWKS over plain http accepted, initial key-fetch failure non-fatal, unsigned callback tokens, committed dev passwords.
