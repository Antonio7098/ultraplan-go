## Executive Summary

Seven systems spanning an observability platform (langfuse), an inline policy engine (opa), a durable workflow engine (temporal), three agent libraries/frameworks (letta, openai-agents-sdk, agent-framework), and one harness frontend (openhands). Every one of them persists security-relevant facts as structured records — events, rows, or serialized state — but they diverge sharply on *where that record lives*, *who is bound to it*, and *whether it survives failure*.

What converges: all seven implement explicit human-approval trails or their closest equivalent; five of seven stitch correlation IDs across subsystems (decision IDs, trace/span IDs, run lineage); all seven treat redaction of sensitive payloads as a first-class concern. What diverges: only langfuse writes a dedicated security audit ledger through a single central writer with authorization-context snapshots frozen into each row. The others embed audit data into their primary domain substrate — workflow history (temporal), conversation messages (letta), resumable run state (openai-agents-sdk), outbound decision events (opa), wire-protocol content delegated to hosts (agent-framework), a server-owned stream viewed thinly by the frontend (openhands).

The recurring weakness is identical everywhere: **action traceability is strong, decision traceability is weak**. Six of seven sources report no policy-decision identifier bound to executed actions (the sole partial exception is OPA's `decision_id`, which correlates a request to its log event but not to the rule that decided it); none provides tamper evidence (no hash chains, signatures, or WORM sinks were found in any source); and attribution of *who approved* ranges from solid (langfuse's `decidedByUserId`) to structurally absent (openai-agents-sdk's actor-less approval records, agent-framework's unlogged approvals).

Ratings span 5–8: productized audit surfaces score highest (langfuse 8); purpose-built pipelines with real gaps score mid (opa 7, temporal 7, openai-agents-sdk 7); libraries that design enforcement well but skip the historical record score lowest (letta 5, openhands 5, agent-framework 5).

## Core Thesis

Across all seven sources, auditability splits cleanly into two problems that get very different levels of investment:

1. **"What happened?" — largely solved.** Every source durably records tool calls, arguments/results (modulo redaction), lifecycle state, and timestamps, usually via append-only event streams or relational rows (e.g., langfuse's sequence-numbered agent event stream at `packages/shared/src/in-app-agent/server/persistence.ts:158-294`; temporal's transaction-chained history table at `schema/cassandra/temporal/schema.cql:58-70`; OPA's schema-versioned `EventV1` at `v1/plugins/logs/plugin.go:49-76`).
2. **"Who authorized it, under what policy, and can we prove it later?" — unsolved everywhere to some degree.** Approval decisions exist as records in six sources, but the *policy context* of those decisions is almost never persisted: policy lives in code version (langfuse, per-run recomputation at `worker/src/features/in-app-agent/executeInAppAgentRun.ts:330-348`), in mutable agent-row state (letta, mutated with the acting actor discarded at `letta/services/agent_manager.py:3064-3088`), in conversation-start payloads (openhands, `src/api/agent-server-adapter.ts:1118-1121`), or nowhere at all (temporal's authorizer denials leave only a metric counter, `common/authorization/interceptor.go:304-331`).

A second-order finding: **audit depth tracks product shape, not engineering quality.** Systems whose core value proposition is durable execution or decision-making (temporal, opa, langfuse) build audit infrastructure because the audit trail *is* part of the product. Libraries and frameworks (letta, openai-agents-sdk, agent-framework) invest heavily in tamper-resistant *live enforcement* — approval binding, replay protection, fail-closed gates — but push historical durability onto hosts, and that delegation is where the trail breaks (agent-framework's ADR promises approval logging that the shipped middleware never implements: `docs/decisions/0006-userapproval.md:95` vs. no logging calls in `_harness/_tool_approval.py`). The lesson is not "libraries are lazy"; it is that without an owned substrate, audit guarantees cannot be enforced, only requested.

## Approach Models

Clustering the seven reports yields seven distinct models, which reduce to four archetypes when grouped by *where the ledger lives and who owns it*.

### Archetype A — The dedicated security ledger (langfuse)

A purpose-built store (`AuditLog` Prisma model, `packages/shared/prisma/schema.prisma:852-876`) written through exactly one typed choke point (`auditLog()` at `web/src/features/audit-logs/auditLog.ts:86-155`) from 100+ mutation sites, backed by a second append-only event stream for the agent harness (`persistence.ts:158-294`). Supporting mechanisms: role snapshots frozen into rows, an exhaustive per-tool policy map recomputed per run (`packages/shared/src/in-app-agent/server/mcpPolicy.ts:27-360`), CAS-based exactly-once approvals with TTL (`runLifecycle.ts:222-397`), and two independent enforcement points (worker + MCP HTTP boundary, `web/src/features/mcp/server/registry.ts:170-189`). This is the only model that treats audit as a product feature with its own read APIs, RBAC scopes, and export path.

### Archetype B — Domain history as the audit log (temporal; openhands server-side by proxy)

The system's own immutable execution record doubles as the audit trail. Temporal appends every workflow mutation as a chained `HistoryEvent` (`schema/cassandra/temporal/schema.cql:58-70`) with caller `Identity` threaded into event attributes (`service/history/workflow/mutable_state_impl.go:4604-4610`), bulk-operator attribution encoded as indexed search attributes (`service/frontend/workflow_handler.go:5917-5953`, `common/searchattribute/sadefs/constants.go:29`), and archival to object storage (`service/history/archival/archiver.go:30-86`). OpenHands' frontend consumes the same shape: every security-relevant fact is a typed event with id/timestamp/source over a server-persisted stream (`src/types/agent-server/core/base/event.ts:8-27`). Strength: logs and behavior can never diverge because the log *is* the behavior. Weakness: non-domain actions (authz denials, namespace CRUD, failed logins) live outside the history in weaker, optional channels.

### Archetype C — Ship the decision out (opa)

Audit records are generated per request and delivered to external infrastructure: buffered upload with retries to remote sinks, console, or plugins (`v1/plugins/logs/plugin.go:902-961`, fan-out at `790-819`). Redaction is itself policy-governed and self-describing — mask/drop Rego policies run over each event and record applied paths in `erased`/`masked` arrays (`v1/plugins/logs/mask.go:178`, `mask.go:197`). Correlation is contractual: the crypto-random `decision_id` is returned synchronously in the API response (`v1/server/server.go:1644-1646`) and stamped into OTel spans. Weakness: delivery is at-least-effort — rate-limit and buffer-overflow drops vanish leaving only Prometheus counters (`eventBuffer.go:161-171`), and buffers are memory-only.

### Archetype D — Decisions as checkpointed state, durability delegated (openai-agents-sdk, letta, agent-framework, openhands-frontend)

All four library-tier sources model human decisions as structured data owned by a run/conversation rather than appended to a security log:

- **openai-agents-sdk**: approve/reject decisions live in `_ApprovalRecord` structures serialized into versioned `RunState` snapshots (`src/agents/run_context.py:56-68`, `run_state.py:1300-1339`), protected against approval replay by canonical invocation fingerprints (`src/agents/_tool_invocation.py:155-219`). The sandbox layer alone gets a true event pipeline with UUID ids and durable JSONL sinks (`src/agents/sandbox/session/events.py:32-89`, `sinks.py:97-342`).
- **letta**: approvals are first-class `role="approval"` rows in the same `messages` table as chat (`letta/schemas/enums.py:116`, `letta/orm/message.py:75-83`), validated against pending state and made idempotent by scanning recent tool returns (`letta/agents/helpers.py:287-294`, `234-266`).
- **agent-framework**: approvals travel as protocol content types (`function_approval_request/response`, `python/packages/core/agent_framework/_types.py:1273-1307`) with session-persisted state (`_harness/_tool_approval.py:248-275`); FIDES policy violations go to an in-memory list (`security.py:1698`) with no timestamps or actor ("there is no separate user identity here", `security.py:1631`).
- **openhands frontend** (thin-client variant): renders and exports the server's stream but keeps nothing itself — browser store is memory-only Zustand wiped on conversation switch (`src/stores/use-event-store.ts:153-223`).

Common property: enforcement integrity is high (binding, validation, fail-closed coercion), historical integrity is whatever the host's storage happens to provide.

## Pattern Catalog

Patterns below appear in multiple sources, or in one source unusually clearly.

### P1. Single choke-point writer/emitter

- **Problem:** scattered ad-hoc logging produces inconsistent, incomplete trails.
- **Demonstrated by:** langfuse routes all audit rows through one union-typed helper (`web/src/features/audit-logs/auditLog.ts:54-155`); OPA funnels every decision through the plugin logger with a stable extension interface (`v1/plugins/logs/plugin.go:39-43`); temporal forces all traffic through one authz interceptor pair (`common/authorization/interceptor.go:83-127`).
- **Why it works:** one place to enforce schema, redaction, and failure policy; the surface is enumerable and testable.
- **Copy when:** you have many mutation sites across routers/services.
- **Risky when:** the choke point becomes a write-amplification bottleneck or a single point of failure without a defined failure mode (see langfuse's mixed fail-open/fail-closed behavior under audit-write errors, `web/src/__tests__/server/mcp-public-api-tools.servertest.ts:400-413` vs. fire-and-forget Stripe paths at `web/src/ee/features/billing/server/stripe/stripeWebhookHandler.ts:680,729`).

### P2. Correlation-first identifiers echoed to callers

- **Problem:** auditors must join async logs to synchronous outcomes.
- **Demonstrated by:** OPA mints a per-request UUID decision ID, returns it in the response body, and stamps it into OTel spans (`v1/runtime/runtime.go:1152-1158`; `v1/server/server.go:1644-1646`, `3212-3216`); langfuse uses monotonic per-conversation sequence numbers plus run lineage (`parentRunId`/`rootRunId`/`continuationNumber`, `packages/shared/src/in-app-agent/server/runLifecycle.ts:359-378`); openai-agents-sdk copies active `span_id`/`trace_id` into sandbox audit events (`src/agents/sandbox/session/sandbox_session.py:163-175`); letta propagates `x-api-request-log-id` for step↔log joins (`letta/server/rest_api/middleware/request_id.py:32-64`).
- **Why it works:** makes response↔log↔trace joins a first-class contract instead of timestamp archaeology.
- **Copy when:** any asynchronous delivery of audit data exists.
- **Note:** identifiers must be globally unique — OPA's auxiliary `req_id` is a per-process counter that collides across replicas (`v1/runtime/logging.go:68`), unlike its UUID decision IDs.

### P3. Attribution bridges for non-human actors

- **Problem:** "the agent did it" destroys accountability.
- **Demonstrated by:** langfuse resolves in-app-agent API keys back to their human creator and writes that userId into audit rows (`web/src/features/audit-logs/auditLog.ts:96-122`, pinned by tests at `web/src/__tests__/server/audit-log-in-app-agent.servertest.ts:40-88`); temporal tags system-initiated mutations with reserved identities (`history-service`, `history-resetter`, `service/history/consts/const.go:13-14`) and substitutes `"frontend-service"` rather than leaving terminate events anonymous (`service/frontend/workflow_handler.go:113,2493`); letta records `actor_type` (LETTA_AGENT vs LETTA_USER) on memory checkpoints (`letta/orm/block_history.py:36-37`); openai-agents-sdk distinguishes programmatic callbacks from human interruption points (`docs/human_in_the_loop.md:89-97`).
- **Why it works:** preserves both the machine provenance and a responsible human without conflating them.
- **Copy when:** agents hold credentials or act semi-autonomously. This is arguably the single most transferable pattern in the study.

### P4. Fail-closed audit coupling

- **Problem:** best-effort auditing silently loses entries exactly when things go wrong.
- **Demonstrated by:** langfuse performs one MCP mutation path's audit write inside the same transaction as the mutation and tests that audit failure rejects the tool call (`web/src/__tests__/server/mcp-public-api-tools.servertest.ts:400-413`); it also aborts agent runs whose triggering user is missing ("a missing user must never implicitly mean 'trusted system'", `worker/src/features/in-app-agent/executeInAppAgentRun.ts:241-245`); openai-agents-sdk forces manual approval when a callable `needs_approval` policy cannot be evaluated on unparseable arguments (`src/agents/run_internal/tool_execution.py:1300-1318`); agent-framework coerces malformed (non-boolean) approval responses to denial (`_types.py:1460-1461`).
- **Why it works:** converts silent evidence loss into visible operation failure.
- **Cost:** couples availability to audit-store health; apply selectively on the riskiest paths, as langfuse does rather than uniformly.

### P5. Exactly-once / replay-proof decision application

- **Problem:** duplicate or replayed approvals double-execute or authorize unintended payloads.
- **Demonstrated by:** langfuse applies approval decisions via conditional-update CAS on the parked run with TTL expiry (`packages/shared/src/in-app-agent/server/runLifecycle.ts:283-297`, TTL at `tunables.ts:17`); openai-agents-sdk fingerprints invocations so a reused provider call ID with different arguments raises `ModelBehaviorError` (`src/agents/run_context.py:327-352`) and scopes hosted-MCP stickiness by `(server_label, tool_name)` (`run_context.py:446-452`); openhands guards duplicate confirmation POSTs client-side (`submittedEventIds`, `conversation-confirmation-buttons.tsx:16-47`); letta detects retry duplicates by scanning recent tool returns (`letta/agents/helpers.py:234-266`); agent-framework binds responses to immutable pending-request snapshots and rejects unknown/duplicate ids (`python/packages/core/agent_framework/_tools.py:2109-2213`).
- **Why it works:** approval integrity is a precondition for audit meaning — a forgeable decision record poisons everything downstream.
- **Strongest variant:** openai-agents-sdk's semantic fingerprint, because it defeats payload-substitution replays, not just duplicates.

### P6. Context snapshotting at write time

- **Problem:** later RBAC changes rewrite history retroactively.
- **Demonstrated by:** langfuse stores the actor's org/project roles inside each audit row (`packages/shared/prisma/schema.prisma:860,862`), so revocation cannot change what the log says they could do; OPA stamps bundle revisions and evaluated-rule labels onto events (`v1/plugins/logs/plugin.go:56,71`).
- **Copy when:** your authorization model evolves faster than your retention period.
- **Counterexample:** letta mutates `requires_approval` rules in place with no versioning, so past policy states are unrecoverable (`letta/services/agent_manager.py:3085-3086`).

### P7. Auditable redaction

- **Problem:** privacy scrubbing usually leaves no trace of what was removed, making logs unverifiable.
- **Demonstrated by:** OPA's mask/drop policies append applied operations to the event itself (`erased`/`masked`, `v1/plugins/logs/mask.go:178,197`, surfaced at `plugin.go:1328-1329`); openai-agents-sdk applies per-sink payload policies by cloning events, so one event fans out at different redaction levels (`src/agents/sandbox/session/manager.py:76-99`); langfuse pairs unconditional row-writing with entitlement-gated reading (`web/src/server/api/routers/auditLogs.ts:86-99` vs. `web/src/features/entitlements/constants/entitlements.ts:30-34`).
- **Limit:** disclosure lists show *that* values were removed, not what they were, and unsigned events mean an upstream actor could still alter history undetected (OPA report, tradeoffs section).

### P8. Symmetric decision records — and the asymmetry trap

- **Problem:** recording only one branch of a binary human decision misleads reconstructors.
- **Positive examples:** langfuse persists superseded approvals distinctly (`APPROVAL_SUPERSEDED`, `runLifecycle.ts:163-174`) and materializes automated denials on cancellation (letta parallel: `letta/services/run_manager.py:671-679`); openhands persists rejections with structured reasons (`UserRejectObservation`, `src/types/agent-server/core/events/observation-event.ts:42-51`).
- **Negative example:** openhands has no first-class artifact for *accepted* confirmations — after `{accept:true}` the action executes indistinguishably from an auto-approved run (`src/hooks/mutation/use-respond-to-confirmation.ts:19-22` sends no reason; `should-render-event.ts:143-144` filters unmatched kinds, hiding even rejections from rendered transcripts). An auditor watching the transcript sees risky commands run with no sign a human vetoed others.
- **Rule:** every approval state transition — request, accept, reject, expire, supersede, timeout — needs its own record type.

### P9. Export hygiene: treat exports as an attack surface and as evidence

- **Problem:** audit artifacts leak data or mislead by incompleteness.
- **Demonstrated by:** openhands whitelists exportable detail kinds, sanitizes markdown, ships HTML with a `default-src 'none'` CSP, and sets `strictPagination` so partial histories cannot masquerade as complete ones (`src/utils/transcript-export/index.ts:72-110,642`; `src/api/event-service/event-service.types.ts:26-33`); langfuse gates batch export behind RBAC+entitlement with explicit combination tests (`web/src/__tests__/server/batchExport-trpc.servertest.ts:89-166`).
- **Copy when:** humans will consume audit artifacts outside the primary UI.

## Key Differences

**Ledger placement.** Langfuse runs a separate security-specific table alongside its domain event stream, so audit retention can be reasoned about independently — while letta embeds approvals in chat messages, sharing retention/deletion semantics with summarizable, compactable conversation data (letta report, tradeoffs: "an auditor's record can shrink with the context window"). Temporal fuses them entirely: the workflow history is the audit log, guaranteeing zero divergence between behavior and record but leaving non-workflow actions in weaker optional channels. These are constraint-driven choices: a SaaS analytics platform needs queryable compliance data; a chat-agent server optimizes for conversational coherence; a workflow engine needs replay fidelity above all.

**Attribution strength.** Four distinct tiers emerge:

1. Verified-principal plumbing that reaches stored records — nobody fully achieves this.
2. Strong convention with snapshotting — langfuse (roles frozen into rows; agent keys bridged to humans).
3. Plumbing exists but doesn't reach the record — temporal computes a server-side `Principal` from JWT/TLS (`common/authorization/interceptor.go:156-158`) yet stores caller-*asserted* `Identity` strings; OPA computes identity for authorization input (`authorizer.go:216-219`) but omits it from `EventV1` entirely, recording only `requested_by` socket address (`plugin.go:67,737`) — and capturing the Authorization header to compensate would log raw bearer tokens (`v1/server/identifier/token.go:28`).
4. Structurally absent — openai-agents-sdk approval records have no actor field; agent-framework states "there is no separate user identity here" (`security.py:1631`); openhands events carry only a four-value `source` role (`common.ts:56`); letta trusts a self-asserted header that falls back to a shared default actor (`dependencies.py:39`, `user_manager.py:122-135`).

**Denial/failure symmetry.** Openhands records human rejections but not accepts; temporal and OPA record neither allow nor deny authorization decisions persistently (metric counters only: `common/authorization/interceptor.go:304-331`, drop counters at `v1/plugins/logs/plugin.go:274-277`); letta logs nothing on 401 (`check_password.py:29-31`); langfuse is again the partial exception, distinguishing expired/superseded approvals in run status though not as first-class decision events.

**Default-on vs opt-in.** Langfuse writes audit rows unconditionally and gates *reading*; OPA generates no decision IDs at all unless a logger is configured (`v1/runtime/runtime.go:959-962`); temporal's lifecycle wide events are doubly disabled by default (noop provider + dynamic-config gate, `temporal/fx.go:222-224`, `common/dynamicconfig/constants.go:239-242`) and its authz defaults to allow-all/admin-for-everyone (`claim_mapper.go:52-54`); letta's detailed tool telemetry defaults off (`letta/settings.py:529`). Opt-in auditing means most real deployments run with weaker trails than the code supports.

**Redaction direction.** Openai-agents-sdk shows the sharpest internal asymmetry: logs suppress payloads by default (`src/agents/_debug.py:12-28`) while traces include sensitive data by default (`run_config.py:404-410`) — two subsystems answering the same question oppositely. Everyone else picks one direction per subsystem and stays consistent.

## Tradeoffs

**Dedicated ledger vs embedded substrate.** A separate audit table (langfuse) costs an extra write path and dual-bookkeeping discipline but buys independent retention, RBAC, and export semantics. Embedding in domain storage (letta messages, temporal history) eliminates divergence-by-construction but chains the audit trail's lifetime to domain retention — cascade deletes on langfuse's own `audit_logs.user_id/project_id` FKs show that even a dedicated table degrades if entity lifetime governs trail lifetime (`packages/shared/prisma/migrations/20240212175433_add_audit_log_table/migration.sql:25,28`).

**Opt-in auditing vs hot-path cost.** OPA and temporal keep the eval/serve path lean by making audit configuration-dependent; the bill arrives as forensic blindness in default deployments. Temporal explicitly chose counters over persisted decisions for latency reasons (temporal report, tradeoffs). Langfuse pays unconditional write cost for universal coverage — viable because its write volume is business mutations, not per-request policy evaluation like OPA's.

**Privacy-by-default vs forensics.** All seven redact something by default: agent-framework excludes tool args from spans unless sensitive-data mode is on (`_tools.py:749-762`); openai-agents-sdk strips exec output from sandbox events (`events.py:18-29`); letta's verbose tool-arg logging defaults off. Benefit is leakage control; cost is that an auditor often cannot see *what arguments* a dangerous tool received. OpenAI-SDK's asymmetric trace default (sensitive-on) shows how easily these drift.

**Convenience grants vs blast radius.** Sticky/approval-scope shortcuts improve usability and shrink friction: langfuse's per-conversation "always allow" (`runLifecycle.ts:318-343`), openai-agents-sdk's sticky scopes overridden by exact-call decisions (`run_context.py:649-661`), agent-framework's auto-approval rules — the last carrying a documented risk that same-name tools get silently auto-approved across features, removing the human from the loop with only a normal success span as trace (`_harness/_tool_approval.py:365-376`). Mitigations converge on scoping (per-conversation, per-server-label, per-disclosed-violation-set) plus per-run revalidation.

**Buffered delivery vs completeness.** OPA trades completeness for bounded memory (drop-oldest buffers, `buffer.go:32-56`); openai-agents-sdk drops spans when its 8192-item queue fills (`processors.py:618-621`); temporal's noop default silently discards wide events. The alternative — synchronous durable writes — is what lets langfuse offer fail-closed coupling, at the price of coupling availability to the audit store.

**Verified principals vs adoption friction.** Temporal keeps `Identity` free-form precisely because requiring authenticated principals for every SDK would break compatibility; trust is an operator upgrade path (JWT claim mapper over mTLS, `default_jwt_claim_mapper.go:78-110`). Letta's shared password optimizes local dev simplicity at the cost of multi-human attribution. Both are deliberate product-shape tradeoffs, not oversights.

## Decision Guide

Choosing an auditability model based on your context:

- **You operate a multi-tenant SaaS with compliance obligations** → Archetype A (langfuse): dedicated ledger, single writer, roles snapshotted into rows, RBAC-gated reads, tested export path. Add what langfuse lacks: decouple trail lifetime from entity lifetime (no cascade deletes) and stamp a policy-version hash per row.
- **You build a durable execution engine where history already must be append-only** → Archetype B (temporal): make the domain history the audit log and spend remaining effort on the edges — persist authz decisions, thread the verified principal into stored identity, default-on a minimal security event set.
- **You are an inline policy engine whose entire value is decisions** → Archetype C (OPA): decision logs as a shipped pipeline with schema-versioned events, correlation IDs echoed to callers, and policy-governed redaction. Fix OPA's gaps before copying blindly: put authenticated identity in the event, emit tombstones on drops, add a durable spool option.
- **You ship a library/framework that cannot own storage** → Archetype D, but avoid its documented failure mode: define a typed decision-record interface with mandatory actor/timestamp/policy-ref fields and a pluggable sink (openai-agents-sdk's sandbox `EventSink` + JSONL outbox is the right shape, `src/agents/sandbox/session/sinks.py:97-342`); do not repeat agent-framework's gap of promising approval logging in an ADR while shipping middleware with no logger.
- **You build a frontend/UI tier** → openhands' thin-client posture: server owns the ledger; the client renders, exports safely (whitelists, CSP, strict pagination), and never becomes a shadow audit copy.

Cross-cutting rule of thumb: **if a reviewer would ask "who approved this?" six months later, that answer must be a stored field, not a derivation.** If your only mechanism is "correlate three stores and hope," you are below the letta/agent-framework line, not above it.

## Practical Tips

- **Bridge agent identities to humans at the credential layer** (langfuse): keys minted by/for agents carry their creator, and the audit writer attributes actions accordingly (`web/src/features/audit-logs/auditLog.ts:96-122`). Cheapest fix for the attribution gap in any agentic product.
- **Snapshot authorization context into each record** (langfuse role columns; OPA bundle revisions): future RBAC changes then cannot falsify history.
- **Make the risk assessment itself a recorded field on the action** (openhands' `security_risk` enum persisted per `ActionEvent`, `action-event.ts:42-61`): auditors see not just what ran but what the system thought of it beforehand.
- **Fingerprint invocations, not just IDs** (openai-agents-sdk): prevents stale approvals from being replayed against changed payloads (`src/agents/_tool_invocation.py:199-219`).
- **Record every branch of human decisions**, including expiry, supersession, timeout, and machine-denial (langfuse's `APPROVAL_SUPERSEDED`; letta synthesizing denial tool-returns on cancellation, `run_manager.py:671-679`).
- **Give loss a ledger, not just a gauge**: OPA's counters reveal *that* events were lost but never *which*. Even a coarse tombstone (time window + count + boundary decision IDs) upgrades reconstruction materially.
- **Separate analytics from audit deliberately** (openhands): consent-gated PostHog funnel events never carry conversation content (`src/services/telemetry.ts:1-30`), preventing the telemetry channel from becoming an ungoverned shadow audit log.
- **Test the audit path like production code**: langfuse pins fail-closed behavior, agent-key attribution, and export authorization in integration tests; openai-agents-sdk maintains ~26k lines covering approval edge cases. Untested audit code rots invisibly — openhands' untested confirmation submission path is the cautionary case.
- **When delegating durability to hosts, define the contract in writing and enforce it in types** (agent-framework's spec language "history providers may retain approval contents for audit", `docs/specs/004-python-function-calling-loop.md:408-409`, is a hope; openai-agents-sdk's versioned `RunState` schema changelog, `run_state.py:186-217`, is a contract).

## Anti-Patterns / Caution Signs

- **In-memory audit stores** (agent-framework's `audit_log: list[dict]`, wiped on restart and clearable via `clear_audit_log()`, `security.py:1698,2169-2184`): any audit surface without a flush path is a demo, not a control.
- **Designed-but-unimplemented logging** (agent-framework ADR 0006 commits to logging approvals; the middleware contains none): enforcement without a historical record means live tamper-resistance masks a dead audit trail.
- **Self-asserted identity with fallback defaults** (letta's `user_id` header falling back to a shared default actor unless operators opt into `no_default_actor`; temporal's admin-for-everyone claim mapper): attribution collapses silently, and attackers can act under any name.
- **One-sided decision records** (openhands accepts invisible, rejections filtered from render and export by `should-render-event.ts:143-144`): reviewers draw wrong conclusions from systematically incomplete streams.
- **Cascade deletes touching audit tables** (langfuse `migration.sql:25,28`): deleting a user or project destroys evidence about actions taken while it existed.
- **Unlogged authentication failures** (letta 401s return with zero logging): brute-force against the single shared password leaves no trace.
- **Denial storms invisible forensically** (temporal/OPA metric-only denials): repeated unauthorized probing produces aggregate blips, no sources, claims, or targets.
- **Read access unaudited** (temporal history/visibility reads carry no caller-attributed record at default levels): exfiltration via reads is untraceable — a blind spot unique to history-as-audit-log architectures.
- **Silent exception swallowing on evidence retrieval** (letta returning `None` on trace-read failures, `routers/v1/steps.py:109-110`; openhands cloud pagination degrading to empty pages with a console warning, `event-service.api.ts:149-163`): storage failures masquerade as clean logs.
- **History rewriting through normal operations** (letta checkpoint undo deletes later block-history entries, `block_manager.py:874-883`): good-faith recorded states become unrecoverable through ordinary use.
- **Caution signs your design area is going brittle**: audit writes sometimes awaited and sometimes fire-and-forget within one codebase (langfuse's tRPC vs Stripe paths); two subsystems disagreeing on sensitive-data defaults (openai-agents-sdk logs-vs-traces); synthetic agent turns indistinguishable from real user input in the record (openhands' reprompt prefix-matching, `should-render-event.ts:15-26`); policy state mutable with the acting actor discarded (letta `agent_manager.py:3064-3088`).

## Notable Absences

Absences confirmed by explicit searches in the source reports; none of the seven has:

- **Tamper evidence.** No hash chaining, signing, or WORM export found in any source. Langfuse, letta, openhands, and OPA reports each document targeted searches that came up empty; temporal's CRC32 checksums are sampled durability guards explicitly "not a tamper-control" (`service/history/workflow/checksum.go:15-36`, mismatches logged and ignored at `mutable_state_impl.go:562-569`).
- **Policy-decision IDs bound to executed actions.** OPA's `decision_id` correlates request↔event but records neither the deciding rule expression nor the authenticated principal; langfuse explicitly lacks any decision-ID store ("policy is implicit in code version"); openai-agents-sdk found none anywhere in source.
- **Authentication/login auditing** where auth exists (langfuse: no `auditLog` usage under auth features; letta: unlogged 401s).
- **Approval-decision timestamps and actors together.** openai-agents-sdk records decisions without either; agent-framework without either; langfuse records the decider but not a standalone decision-ID; letta binds neither cryptographically.
- **Unified cross-system audit correlation** where harnesses compose with governance tooling — openhands defers its Agent Server→external-audit bridge to future work (`docs/DefenseClaw.md:280-282`).
- **Loss tombstones** identifying which specific events were dropped (OPA, openai-agents-sdk, temporal all signal loss only via counters/warnings).

## Per-Source Notes

Brief recaps; the synthesis above carries the analysis.

- **agent-framework (5)** — Three incomplete layers: protocol-level approvals (tamper-resistant binding, disclosure-bound waivers, session persistence), FIDES violation records in process memory without timestamps/actors, OTel spans gated for sensitive data. The ADR-promised approval logging is absent; .NET shell-policy and Purview verdicts are unpersisted. Reconstruction requires joining ephemeral memory, session snapshots, and exported traces.
- **langfuse (8)** — The study's reference implementation: centralized typed writer over a 45+-resource auditable union, roles frozen into rows, agent-key→human attribution, fail-closed transactional auditing on the riskiest path, exhaustive per-tool policy map recomputed per run, CAS+TTL exactly-once approvals with full run lineage. Held back from 9–10 by cascade deletes, no tamper evidence, unaudited auth events, and entitlement-gated visibility for OSS/self-hosted operators.
- **letta (5)** — Genuinely well-engineered HITL approval messages (validated, idempotent, denial-reasoned, compaction-protected) atop excellent what-happened observability (steps/runs/provider_traces/OTEL correlation). Undermined by shared-password auth, self-asserted headers with default-actor fallback, unlogged auth failures, unversioned policy mutation, undo-rewritten checkpoints, and OSS/cloud auth-code drift.
- **opa (7)** — Decision logging as designed-in product: schema-versioned `EventV1`, crypto-random decision IDs echoed to callers, policy-governed mask/drop with audited redaction arrays, prepared-query caching, status/metrics surfacing of delivery health. Gaps: identity never lands in events, `system.authz` denials bypass the pipeline, memory-only buffers lose events silently, shutdown flush is best-effort.
- **openai-agents-sdk (7)** — Approvals as first-class, schema-versioned, serialization-durable run state with invocation fingerprinting and fail-closed policy evaluation; a real audit-event pipeline (UUID events, seq numbers, per-sink redaction policies, durable JSONL sinks) reserved for the sandbox; deep test culture. Gaps: no actor/timestamp on decisions, no policy-decision IDs, lossy default trace exporter, vendor-coupled default backend unavailable under ZDR.
- **openhands (5, frontend-scoped)** — Clean typed event vocabulary with per-action risk levels, named confirmation policies compiled at conversation start (enforcement server-side, un-bypassable by the client), persisted rejection records, hook-execution records capturing policy-enforcement outcomes, and disciplined exports. Acceptances vanish post-hoc, no actor identity, untested submission path, and durable audit explicitly deferred to unbuilt external tooling. Server-side truth not inspectable from this source.
- **temporal (7)** — Event sourcing as audit substrate done right: append-only chained history, identity threading, reserved system identities, batch-operator search attributes with reason memos, anti-spoofing interceptors, cross-namespace re-authz, archival. Security layers lag the core: metric-only denials, disabled-by-default actor-less lifecycle events, open defaults, debug-gated access logs, unaudited reads, no approval machinery.
