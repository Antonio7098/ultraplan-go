## Executive Summary

No source treats hierarchical, typed, reorderable task decomposition as a mature first-class primitive. All six converge on the same pragmatic answer — let the LLM invent subtasks in free-form text, then persist them in whatever substrate already exists (a flat list, a state channel, or an ephemeral turn struct). Only **crewai** demonstrates a complete plan-scheduling loop with explicit `depends_on`, four-state status, and dependency-aware parallel dispatch; **langgraph** and **pydantic-ai** demonstrate powerful graph substrates where dependencies are structural edges between actors, not fields on a plan. The remaining three — **agent-framework**, **openhands**, and **openai-agents-sdk** — use disjoint or absent representations: flat binary/ternary lists with no edges, prose markdown, or a per-turn transient grouping that is discarded after execution. The invariant question "which subtask is blocking progress?" is answerable only where a scheduler computes a ready-set (crewai via `get_ready_todos` in `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:133`, langgraph via `StateSnapshot.tasks` in `libs/langgraph/langgraph/types.py:683` and `tasks_w_writes` in `libs/langgraph/langgraph/pregel/debug.py:209`, pydantic-ai graph via `_GraphIterator.active_tasks` in `pydantic_graph/pydantic_graph/graph_builder.py:661`); in the flat-list and ephemeral models the answer is "no signal."

## Core Thesis

Task decomposition across modern agent harnesses is **substrate-driven, not plan-driven**. Frameworks with a graph/BSP engine (langgraph, pydantic_graph, agent-framework workflows) encode decomposition as wiring between actors and therefore get dependencies, barriers, and fan-out for free — but lose a queryable plan artifact. Frameworks with a todo/tool surface (crewai, agent-framework harness, openhands) encode decomposition as an LLM-authored list and therefore get human-readable plans with trivial persistence — but lose dependency semantics, typing, and blocking analysis unless they add them explicitly, which only crewai does. The deepest divergence is not code quality but constraint choice: stateful graph platforms optimize for static verification and replay; session-oriented agent SDKs optimize for minimal DSL tax. Convergence appears in the shared floor — flat `title/description` subtasks, prose decomposition guidance, and whole-list or per-item tool mutations — and in the shared failure mode: no hierarchical nesting, no reorder without lossy rebuild, and evaluation that is either a heuristic LLM judge or a trivial `any(not done)` predicate.

## Approach Models

Three approach models emerge when normalizing the per-source reports by what the framework treats as the decomposition atom.

### Model 1 — Flat LLM-Authored List (agent-framework todos, openhands TaskTracker/PLAN.md, crewai TodoList)

- **Vocabulary:** `TodoItem`/`TaskItem` with `title`/`description`/`notes`, binary/ternary status, optional `tool_to_use`, stored in `TodoList`/`TodoState` or `TASKS.json` or `PLAN.md`.
- **Where implemented:** `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:47-101`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:45-196`, `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:29-52`, `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/preset/planning.py:14-88`.
- **Main mechanism:** Expose `todos_add`/`todos_complete`/ `task_tracker plan|view` tools; LLM decides granularity guided by prose (`DEFAULT_TODO_INSTRUCTIONS` in `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:22-40`, `TASK_TRACKER_DESCRIPTION` in `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:270-400`, `FUNCTION_SCHEMA` in `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:50-104`).
- **Variants:** agent-framework adds atomic `TodoFileStore` and per-session `WeakKeyDictionary` locks; crewai adds `depends_on` and `TodoStatus=pending|running|completed|failed`; openhands adds a parallel markdown artifact `PLAN.md` gated by `PlanningFileEditorExecutor(allowed_edits_files=[plan_path])` (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/planning_file_editor/impl.py:28-30`).

### Model 2 — Graph/BSP Actor Wiring (langgraph Pregel, pydantic_graph, agent-framework Workflow)

- **Vocabulary:** `PregelNode`/`Executor`/`BaseNode`/`Step` + `Edge`/`BranchSpec`/`Fork`/`Join`/`Decision` + `Send`/`Command`/`Call`, scheduled as `PregelExecutableTask`/`GraphTask` supersteps.
- **Where implemented:** `libs/langgraph/langgraph/pregel/main.py:464-478`, `libs/langgraph/langgraph/graph/state.py:667`, `libs/langgraph/langgraph/types.py:704`, `pydantic_graph/pydantic_graph/graph_builder.py:673`, `pydantic_graph/pydantic_graph/node.py:60`, `sources/agent-framework/python/packages/core/agent_framework/_workflows/_executor.py:30-120`.
- **Main mechanism:** Developer declares nodes/channels/edges; compiler builds `trigger_to_nodes`/`edges_by_source`/`parent_forks`; `prepare_next_tasks` / `iter_graph` yields PUSH (Send/Call) + PULL (channel-triggered) batches each superstep (`libs/langgraph/langgraph/pregel/_algo.py:391-513`, `pydantic_graph/pydantic_graph/graph_builder.py:673-841`).
- **Variants:** langgraph adds `waiting_edges` barriers (`libs/langgraph/langgraph/graph/state.py:209`), `TASKS=Topic(Send)` isolation (`libs/langgraph/langgraph/pregel/main.py:806-809`), functional `@task` futures; pydantic_graph adds `ReducerFunction` pluggability (`pydantic_graph/pydantic_graph/join.py:91`) and early-stop `cancel_sibling_tasks` (`pydantic_graph/pydantic_graph/join.py:73`); agent-framework adds `Edge.condition` predicates and `FanOutEdgeGroup`/`FanInEdgeGroup` (`sources/agent-framework/python/packages/core/agent_framework/_workflows/_edge.py:80-160`).

### Model 3 — Ephemeral Turn Grouping (openai-agents-sdk, pydantic-ai agent FSM, agent-framework Magentic ledger)

- **Vocabulary:** `ToolExecutionPlan`/`ProcessedResponse`/`SingleStepResult.next_step`, `GraphAgentState` with `message_history`/`run_step`, `MagenticProgressLedger`/`_MagenticTaskLedger`.
- **Where implemented:** `src/agents/run_internal/tool_planning.py:558-573`, `src/agents/run_internal/run_steps.py:116-199`, `pydantic_ai_slim/pydantic_ai/_agent_graph.py:299-343`, `sources/agent-framework/python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:340-400`.
- **Main mechanism:** Model output for one turn is classified and grouped by tool kind, executed via `gather_with_cancel`, then dropped; next turn rebuilds a fresh plan (`src/agents/run_internal/tool_planning.py:619-646`, `src/agents/run_internal/tool_planning.py:944-1101`); Magentic stores `facts`/`plan` as opaque `Message` payloads.
- **Why it diverges:** Valid response to SDK-vs-platform constraints — openai-agents-sdk and pydantic_ai_slim are thin runtimes over provider APIs where a durable plan graph would be DSL tax; evaluation is via turn bounds (`MaxTurnsExceeded` at `src/agents/run.py:1058`) or LLM-judged heuristics (`is_request_satisfied` at `sources/agent-framework/python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:340`).

**What converges:** All three models agree that decomposition is **imperative and LLM-authored** unless the developer pre-wires a graph. Even the strongest structured case (crewai) uses `FUNCTION_SCHEMA` function-calling to let the model emit `PlanStep` rather than framework-generated plans.

**Why they diverge:** Product shape and maturity drive the split. Graph platforms (langgraph, pydantic_graph) sell deterministic orchestration — hence structural edges. Agent SDKs (openai-agents-sdk, pydantic_ai slim, openhands DEFAULT mode) sell minimal integration — hence ephemeral or flat prose. Crewai and agent-framework straddle both worlds, which explains their fragmented dual-track findings (crewai crew-planner vs agent-executor; agent-framework todos vs workflows).

## Pattern Catalog

### Pattern 1 — Flat Todo Collection with Per-Session Durability

- **Problem:** LLM-authored subtasks must survive across turns without teaching a complex plan DSL.
- **Sources:** agent-framework (`sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:227-370`), openhands (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:148-266`), crewai (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:45-196`).
- **How it works:** Expose 2–5 narrow tools (`todos_add/complete/remove/get_*`, `task_tracker view|plan`, `FUNCTION_SCHEMA create_reasoning_plan`) over a `list[TodoItem]` held in session state or `TASKS.json`. Persistence is atomic write-then-rename (`os.replace` in `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:280-310`) with ID clamping (`_safe_next_id` in `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:190-210`) and per-session locks (`WeakKeyDictionary`/`ConditionalWeakTable`).
- **When to copy:** Session-oriented assistants, single-agent loops, human-in-the-loop todo review.
- **When overkill/risky:** When subtasks have ordering constraints — flat lists silently accept contradictory ordering and require whole-list resend for reorder (openhands `self._task_list = action.task_list` in `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:176`).
- **Evidence:** `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:447-620`, `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:42-145`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:384-444`.

### Pattern 2 — Dependency-Aware Ready-Set Scheduler

- **Problem:** Parallel subtasks must not run before their prerequisites.
- **Sources:** crewai (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:112-154`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1106-1321`), langgraph (`libs/langgraph/langgraph/pregel/_algo.py:475-482`, `libs/langgraph/langgraph/graph/state.py:202-209`, `libs/langgraph/langgraph/pregel/_algo.py:1260-1277`), pydantic-ai (`pydantic_graph/pydantic_graph/graph_builder.py:193`, `pydantic_graph/pydantic_graph/graph_builder.py:1084`).
- **How it works:** Each subtask declares `depends_on: list[int]` (crewai), or each node declares `triggers: list[str]` / `waiting_edges` (langgraph), or each node participates in `parent_forks`/`intermediate_join_nodes` (pydantic_graph). Scheduler computes ready set: crewai `get_ready_todos` requires `_dependencies_satisfied` with terminal `completed|failed` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:112-131`), langgraph `prepare_next_tasks` uses `updated_channels ∩ trigger_to_nodes` fast path, pydantic_graph `iter_graph` enforces join barriers via `_is_fork_run_completed`.
- **Why it works:** Decouples authoring (model writes edges) from execution (engine enforces DAG), enabling `can_parallelize` fan-out (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:133-154`) and `execute_todos_parallel` via `asyncio.gather` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1257-1321`) or `Send` fan-out (`libs/langgraph/langgraph/types.py:737`).
- **When to copy:** Any multi-step plan with ordering; mandatory for parallel dispatch.
- **When overkill:** Single-threaded sequential agents — sequential builder (`sources/agent-framework/python/packages/orchestrations/agent_framework_orchestrations/_sequential.py:50-180`) suffices.
- **Failure mode if copied poorly:** Circular `depends_on` → deadlock → `needs_replan` → `max_replans` exhaustion and silent `all_todos_complete` drop (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1056-1064`).

### Pattern 3 — Dual PUSH/PULL Superstep Scheduling

- **Problem:** Support both data-parallel fan-out and data-driven triggering in one tick.
- **Sources:** langgraph (`libs/langgraph/langgraph/pregel/_algo.py:437-513`, `libs/langgraph/langgraph/types.py:704-792`), pydantic-ai (`pydantic_graph/pydantic_graph/graph_builder.py:673-841`, `pydantic_graph/pydantic_graph/graph_builder.py:800-936`).
- **How it works:** Reserve a `TASKS=Topic(Send)` channel for PUSH tasks created by `Send`/`Call` (`libs/langgraph/langgraph/pregel/main.py:806-809`) merged with PULL tasks triggered by channel version bumps (`libs/langgraph/langgraph/pregel/_algo.py:1260-1277`) into a single `dict[str, PregelExecutableTask]`. Task IDs are deterministic `xxhash/uuid5(checkpoint_id + ns + step + name)` (`libs/langgraph/langgraph/pregel/_algo.py:1395-1410`) for idempotent replay.
- **When to copy:** Workflows with map-reduce or dynamic worker dispatch.
- **Cost:** Two overlapping dispatch APIs (`Send` vs `Command` in `libs/langgraph/langgraph/types.py:798-849`) complicate static analysis; unknown-target `Send` is silently dropped with a warning (`libs/langgraph/langgraph/pregel/_algo.py:977-978`).

### Pattern 4 — Fork/Join Barrier with Pluggable Reducer

- **Problem:** Fan-out into N parallel subtasks and fan-in once all complete (or first-wins).
- **Sources:** pydantic-ai (`pydantic_graph/pydantic_graph/node.py:60-80`, `pydantic_graph/pydantic_graph/join.py:30-199`), langgraph (`libs/langgraph/langgraph/graph/state.py:338-341`, `libs/langgraph/langgraph/pregel/_algo.py:253-256`), crewai (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:133-154`), agent-framework (`sources/agent-framework/python/packages/core/agent_framework/_workflows/_edge.py:80-160`).
- **How it works:** `Fork(is_map)` broadcasts or maps an iterable; `Join(reducer, initial_factory, parent_fork_id)` reduces branch results via `reduce_list_append`/`reduce_first_value`; `_is_fork_run_completed` gates finalization until `active_tasks` for that fork is empty (`pydantic_graph/pydantic_graph/graph_builder.py:1084`). Langgraph `waiting_edges: set[tuple[tuple[str,...], str]]` encodes barrier declaratively; crewai `execute_todos_parallel` uses `asyncio.gather` + `zip(ready, gathered)`.
- **When to copy:** Parallel research, critique loops, map over file lists.
- **Caution:** Pydantic_graph empty-iterable edge creates join state eagerly (`pydantic_graph/pydantic_graph/graph_builder.py:1044`); langgraph apply-writes sort is deterministic by `task_path_str(path[:3])` (`libs/langgraph/langgraph/pregel/_algo.py:253`) — no priority hook.

### Pattern 5 — Per-Turn Tool-Kind Grouping (Ephemeral Plan)

- **Problem:** Execute heterogeneous tool calls emitted in one model turn without a persistent plan.
- **Sources:** openai-agents-sdk (`src/agents/run_internal/tool_planning.py:558-573`, `src/agents/run_internal/tool_planning.py:985-1034`), pydantic-ai `CallToolsNode` (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:1100` region), agent-framework `WorkflowEvent` grouping.
- **How it works:** `ProcessedResponse{new_items, handoffs, functions, shell_calls, ...}` (`src/agents/run_internal/run_steps.py:116-152`) → `_build_plan_for_fresh_turn` copies buckets into `ToolExecutionPlan{function_runs, shell_calls, computer_actions, ...}` (`src/agents/run_internal/tool_planning.py:619-646`) → `_execute_tool_plan` fans out to 6 executors via `gather_with_cancel` (`src/agents/run_internal/tool_planning.py:984-1036`).
- **When to copy:** Simple ReAct loops where plan identity across turns is unnecessary.
- **When risky:** Cross-turn dependencies cannot be expressed; crash loses in-flight `ToolExecutionPlan` — history is `RunItem`s not plan (`src/agents/items.py:686-740`).

### Pattern 6 — Isolated Step Context with Result-Only Propagation

- **Problem:** Prevent prompt bloat and cross-step contamination when executing plan steps.
- **Sources:** crewai (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:244-326`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/step_execution_context.py:13-64`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:647-678`), langgraph channels.
- **How it works:** `StepExecutionContext{task_description, task_goal, dependency_results: dict[int,str]}` passes only terminal dependency outputs to `StepExecutor._build_isolated_messages`; crewai validates `tool_to_use` via `_validate_expected_tool_usage` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:515-538`).
- **When to copy:** Plans with >10 steps or expensive tool traces.
- **Cost:** Loses off-dependency conversational memory — requires replanning to surface new history; observation must then `apply_refinements` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:215-242`) or `replace_pending_todos` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:185-196`).

### Pattern 7 — Observation Pipeline for Plan Adaptation (Heuristic + LLM)

- **Problem:** Detect invalidated plans without a structural verifier.
- **Sources:** crewai (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:88-242`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:198-278`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:680-1089`), agent-framework (`sources/agent-framework/python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:340-400`, `sources/agent-framework/python/packages/core/agent_framework/_harness/_loop.py:520-560`).
- **How it works:** After each step, `PlannerObserver.observe` calls LLM (medium/high effort) or `heuristic_observation` (low) to produce `StepObservation{step_completed_successfully, remaining_plan_still_valid, needs_full_replan, goal_already_achieved}`; `decide_next_action` → `refine_and_continue` (in-place `StepRefinement`) or `replan_now` (`replace_pending_todos`) bounded by `PlanningConfig.max_replans` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agent/planning_config.py:11-151`). Agent-framework `todos_remaining` predicates re-invoke while `any(not is_complete)` (`sources/agent-framework/python/packages/core/agent_framework/_harness/_loop.py:526-532`).
- **When to copy:** Long-horizon tasks where model may learn `goal_already_achieved` mid-plan.
- **Cost:** N extra LLM calls per task; inconsistent fallback defaults (outer exception returns `success=True` vs parse failure returns `success=False` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:208-352`).

## Key Differences

**Explicit vs implicit dependency representation.** Crewai stores `depends_on: list[int]` on `TodoItem`/`PlanStep` with `_dependencies_satisfied` requiring terminal status (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:112-145`) and computes `get_ready_todos` directly. Langgraph and pydantic_graph store no `depends_on` on subtasks — ordering is emergent from `PregelNode.triggers` + `waiting_edges` (`libs/langgraph/langgraph/graph/state.py:202-209`) or `edges_by_source` + `parent_forks` (`pydantic_graph/pydantic_graph/graph_builder.py:193`). Agent-framework workflows encode `Edge{source_id, target_id, condition?}` (`sources/agent-framework/python/packages/core/agent_framework/_workflows/_edge.py:80-160`) but todos have no `blocked_by`; openhands and openai-agents-sdk encode no ordering at all. The consequence is that only crewai and the graph engines can answer "what is ready?"; the flat lists answer only "what is done?"

**Status granularity and queryability.** Crewai uses four-state `pending|running|completed|failed` plus `get_completed/failed/pending_todos` counts (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:50-183`) and `PlanStepStarted/Completed` events. Agent-framework `TodoItem.is_complete: bool` (`sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:53-60`) plus `BackgroundTaskStatus RUNNING|COMPLETED|FAILED|LOST` (`sources/agent-framework/python/packages/core/agent_framework/_harness/_background_agents.py:28-65`) — but the two lifecycles are not joined. Openhands `TaskItem` uses `todo|in_progress|done` (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:29-39`) and `Task` uses `running|completed|error` — fragmented. Langgraph `PregelTask{error, interrupts, result}` in `libs/langgraph/langgraph/types.py:637-646` folds `pending_writes` channels `RETURN/ERROR/INTERRUPT` via `tasks_w_writes` (`libs/langgraph/langgraph/pregel/debug.py:209-279`); status is checkpoint-derived, not field-mutated. Openai-agents-sdk has no plan status — turn-level `NextStepRunAgain|Handoff|FinalOutput|Interruption` (`src/agents/run_internal/run_steps.py:155-199`) and binary `TodoItem.completed` only for Codex bridge (`src/agents/extensions/experimental/codex/items.py:98-107`) — so blocking is only `NextStepInterruption`.

**Durability and replay.** Agent-framework offers the strongest todo durability: atomic `os.replace` file store + `TodoSessionStore` + per-session locks, tested for corruption/path-traversal/concurrent clamping (`sources/agent-framework/python/packages/core/tests/core/test_harness_todo.py:15-350`). Openhands persists `TASKS.json` (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:252-266`) but with no lock and doc/code drift (`TASKS.md` docstring vs `TASKS.json` code). Crewai `AgentExecutorState.todos` is memory-only Flow state, not checkpoint-persisted, and crew-level `task.description += plan` is string-append not versioned (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:57-78`) — re-kickoff accumulates. Langgraph persists `CheckpointTask` + `PendingWrite` per tick (`libs/langgraph/langgraph/types.py:182-220`, `libs/langgraph/langgraph/pregel/_loop.py:415-546`) with time-travel `update_state` (`libs/langgraph/langgraph/pregel/main.py:1392-1435`). Openai-agents-sdk drops `ToolExecutionPlan` after execution — `RunState` persists only `RunItem` history and `_current_step: NextStepInterruption` (`src/agents/run_state.py:254`). Pydantic-ai core persists only `GraphAgentState` + message history (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:299-343`) — todos, if any, live in external `pydantic-ai-todo` Postgres/Capability stores cited at `docs/capabilities/third-party.md:9`.

**Typed subtask taxonomy.** Only crewai's `tool_to_use: str|None` on `PlanStep`/`TodoItem` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:22-39`) acts as a type proxy validated by `_validate_expected_tool_usage` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:515-538`). Agent-framework executors have typed `input_types`/`output_types` (`sources/agent-framework/python/packages/core/agent_framework/_workflows/_executor.py:30-80`) but todos have no `kind`. Openhands `TaskAction.subagent_type` types the executor not the subtask (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task/definition.py:37-62`). Openai-agents-sdk groups by tool kind (`function_runs`, `shell_calls` in `src/agents/run_internal/tool_planning.py:558-573`) — implementation kind, not plan semantics. Langgraph/pydantic_ai subtask kind is node name string + free-form `metadata` (`libs/langgraph/langgraph/graph/state.py:381`) — low taxonomy signal.

**Update granularity.** Agent-framework: per-item tools `todos_add` returns items, `todos_complete/remove` return counts (`sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:506-600`). Crewai: `replace_pending_todos` + in-place `apply_refinements` for surgical edits vs full replan (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:185-196`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:215-242`). Openhands: whole-list replacement only (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:174-176`) or markdown `str_replace`. Langgraph/pydantic_ai: add node/edge requires graph rebuild; runtime path uses `Command(update={"plan": ...})` ad-hoc dict patch (`libs/langgraph/tests/test_pregel.py:5165-5220`). Openai-agents-sdk: no update — next turn's model output is the plan.

## Tradeoffs

**Flat todo minimalism vs typed dependency taxonomy.** Benefit: minimal LLM DSL, any model can author `title` strings; trivial persistence (`TodoItem{id,title,description,is_complete}` at `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:47-60` and `TaskItem{title,notes,status}` at `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:32-39`). Cost: no `depends_on`/`priority`/`blocked` — system cannot derive critical path or answer blocking; reordering requires `remove+add` lossy remint. Best-fit: single-agent short tasks. Crewai pays the opposite cost: explicit `depends_on` + `tool_to_use` enables `can_parallelize` but adds function-calling tax and risks deadlock if LLM emits unsatisfiable edges.

**Graph structural edges vs plan-level `depends_on` field.** Benefit of graph edges (langgraph, pydantic_graph, agent-framework workflows): compile-time validation (`validate_workflow_graph` at `sources/agent-framework/python/packages/core/agent_framework/_workflows/_validation.py:1-60`, `StateGraph.validate` at `libs/langgraph/langgraph/graph/state.py:1129-1175`), deterministic superstep ordering, barrier fan-in for free. Cost: implicit dependencies distributed across `triggers`/`waiting_edges`/`BranchSpec`/`Fork`/`Join` — no single DAG artifact to lint or reorder offline; dynamic `Send` fan-out is best-effort warning on unknown target (`libs/langgraph/langgraph/pregel/_algo.py:977-979`). Field-level `depends_on` (crewai) is inspectable as data but requires runtime topological reasoning and `max_replans` guard.

**Ephemeral turn grouping vs durable plan registry.** Benefit ephemeral (openai `ToolExecutionPlan`): minimal state, clean `gather_with_cancel` per turn (`src/agents/run_internal/tool_planning.py:984-1036`), no plan store to version. Cost: crash loses plan; no cross-turn blocking query; handoffs/agents-as-tools are control flow not tracked subtasks (`src/agents/run_internal/run_steps.py:155-157`). Benefit durable (agent-framework `TodoFileStore`, openhands `TASKS.json`, langgraph `CheckpointPayload`): survives restart, queryable via `todos_get_all`/`get_state`/`get_state_history`. Cost: I/O overhead (`checkpointer.put_writes` + `put_after_previous` in `libs/langgraph/langgraph/pregel/_loop.py:415-546`) and locking complexity.

**Whole-list replacement vs surgical patch vs graph rebuild.** Whole-list (`task_tracker plan`): conflict-free save but high token overhead and silent clobber race (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:174-176` with no optimistic concurrency). Per-item tools (agent-framework): precise but five tools to learn; batch reorder still requires `remove+add` losing `id`. Patch (`replace_pending_todos`/`apply_refinements`): cheap adaptation but refinement limited to description mutation. Graph rebuild: type-safe but requires `build()->Workflow` (`sources/agent-framework/python/packages/core/agent_framework/_workflows/_workflow_builder.py:53-300`) or `compile` (`libs/langgraph/langgraph/graph/state.py:982-1176`) — not suitable for LLM-authored runtime reordering.

**Isolated step context vs shared history.** Isolated (crewai): predictable tokens, contamination-free, but loses off-dependency memory — observer must replan. Shared (implicit in flat lists where each `view` returns full list): maximal context but bloat and cross-step leakage.

**Heuristic LLM evaluation vs structural coverage check.** Heuristic (MagenticProgressLedger `is_request_satisfied/is_in_loop/is_progress_being_made` at `sources/agent-framework/python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:340`, PlannerObserver `StepObservation` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:198-278`, openai guardrails/max-turns): lightweight, no formal verifier, but false positives/negatives and extra LLM latency. Structural (`todos_remaining` `any(not is_complete)` at `sources/agent-framework/python/packages/core/agent_framework/_harness/_loop.py:526-532`, `_dependencies_satisfied` terminal check): deterministic but cannot judge coverage or minimality — "all todos done" ≠ "task complete."

## Decision Guide

Choose based on whether your agents need a plan that outlives a single model turn.

**If you run a fixed workflow orchestrated by code, not by model improvisation:**
- Pick graph/BSP wiring. Use **langgraph StateGraph** (`libs/langgraph/langgraph/graph/state.py:667`) or **pydantic_graph GraphBuilder** (`pydantic_graph/pydantic_graph/graph_builder.py:1139`) or **agent-framework WorkflowBuilder** (`sources/agent-framework/python/packages/core/agent_framework/_workflows/_workflow_builder.py:53`). Declare `add_edge`/`waiting_edges`/`Fork`/`Join` declaratively; fan-out via `Send`/`Fork(is_map=True)`; persist via `checkpointer`/`GraphRun` state. Do not add a separate todo list — your graph *is* the decomposition artifact.

**If you run a single ReAct agent that needs human-visible progress:**
- Pick flat todo with per-item tools. Copy **agent-framework** pattern (`sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:447-620`) if you need atomic durability and concurrent safety; copy **openhands** markdown (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/preset/planning.py:14-88`) only if plans must render in UI. Add `depends_on` yourself if tasks can block.

**If you need dependency-aware parallelism with runtime replanning:**
- Pick **crewai** as the only out-of-the-box LLM-plan scheduler. Copy `PlanStep → TodoItem` conversion (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:384-444`), `get_ready_todos`/`can_parallelize` gating (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:133-154`), and the Observe→Decide loop (`PlannerObserver` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:88-242` with `PlanningConfig.max_replans` at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agent/planning_config.py:11-151`). Do not copy the crew-level string-append planner (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:57-78`) without fixing fragmentation.

**If you are a thin SDK over a provider API and want zero plan tax:**
- Stay ephemeral like **openai-agents-sdk** (`src/agents/run_internal/tool_planning.py:558-646`). Document "break down via prompts" (`examples/agent_patterns/README.md:11`, `docs/multi_agent.md:29`) and delegate structured planning to an optional capability (like `pydantic-ai-todo` at `docs/capabilities/third-party.md:9`). Do not invent a durable plan graph unless you also add concurrency control over its external store.

**When to bridge flat todos ↔ graph:** If your system has both (agent-framework, openhands sub-agents, pydantic_ai), build an adapter that materializes `list[TodoItem(depends_on)]` into workflow edges rather than letting the two layers drift. None of the studied sources do this today — the gap is documented in every "fragmentation" tradeoff row.

## Practical Tips

**Patterns to copy now:**

- **Per-session serialized RMW with monotonic clamped IDs.** Implement `WeakKeyDictionary[Session, Lock]` mutation serialization + `_safe_next_id = max(ids)+1` (seen in `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:190-210` and mirrored in `dotnet/src/Microsoft.Agents.AI/Harness/Todo/TodoProvider.cs:80-130`). Prevents duplicate IDs under `asyncio.gather` without a DB transaction.
- **Deterministic task IDs for idempotent replay.** Hash `checkpoint_id + namespace + step + name + trigger` (langgraph at `libs/langgraph/langgraph/pregel/_algo.py:1395-1410`, pydantic_graph `replace_placeholder_id` at `pydantic_graph/pydantic_graph/graph_builder.py:50`) so resume/time-travel does not duplicate subtasks.
- **Ready-set extraction as the single blocking oracle.** Expose `get_ready_todos` (crewai), `StateSnapshot.next` + `tasks_w_writes` (langgraph), or `active_tasks`/`active_reducers` (pydantic_graph) as the answer to "what is blocking?" Do not rely on status enum alone — compute `pending - ready` as the blocked set.
- **Typed `tool_to_use` hint on subtasks.** Even if you keep titles free-form, add `tool_to_use: str|None` (crewai at `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:22-39`) so the scheduler can validate via `_validate_expected_tool_usage` and the executor can build an isolated context.
- **Atomic write-then-rename for file-backed todos.** `TodoFileStore` pattern (`sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:280-310`) with sanitized segments (`_ENCODED_SEGMENT_PREFIX`, `WINDOWS_RESERVED_FILE_STEMS`) avoids corruption and path traversal.

**Patterns to avoid or delay:**

- **Do not create a second plan surface alongside todos.** Openhands `TASKS.json` + `PLAN.md` (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:238-263` vs `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/preset/planning.py:14-53`) and agent-framework todos+workflows and pydantic_ai slim+external todos bifurcate responsibility. One plan registry per run is enough; add the second only when you have a proven bridge.
- **Do not use string-append plan mutation.** Crewai `task.description += plan` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_handler.py:57-78`) is lossy, accumulates on re-kickoff, and breaks structured queries. Keep description immutable and store plans as versioned artifacts.
- **Do not rely on non-function-calling fallback that silently drops plans.** Guard `_create_initial_plan` empty-steps path (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/reasoning_handler.py:270-276`) — surface a warning or fall back to sequential unplanned execution explicitly.
- **Do not fan-out via `Send`/`Command` without validating targets.** Langgraph silently drops unknown nodes (`libs/langgraph/langgraph/pregel/_algo.py:977-978`); fail-closed validation at graph compile or surface as a `PregelTask.error` visible in snapshots.
- **Do not store `reason` separately from `TodoItem`.** Agent-framework `todos_complete` accepts `{id, reason}` but reconstructs `TodoItem(is_complete=True)` without persisting it (`sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:536-560`); audit trails vanish after the call.

**Caution signs that decomposition is becoming brittle:**

- Titles parsed to infer `kind`/`priority` because no typed field exists — signals taxonomy debt.
- `any(not is_complete)` used as the sole loop predicate (`sources/agent-framework/python/packages/core/agent_framework/_harness/_loop.py:526-532`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:50`) — no progress made inside the loop is visible beyond "still has work."
- Whole-list `plan` calls growing with `TodoList` size — token cost and silent clobber risk rise linearly.
- `max_replans` hitting its cap and execution finalizing with partial results (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/experimental/agent_executor.py:1056-1064`) or `MaxTurnsExceeded` aborting with lost plan (`src/agents/run.py:1058-1144`) — indicates deadlock or invalid plan that no validator caught.

## Anti-Patterns / Caution Signs

- **Lost reason / no completion audit.** `TodoCompleteInput.reason` not persisted, justification vanishes after tool call — breaks compliance/replay. Seen in `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:536-560`; mirrored as missing `completed_reason` in all flat lists.
- **No blocked detection → silent stall.** Two todos with logical dependency but no edge cause outer loop to reprompt generically ("Continue working on the task" at `sources/agent-framework/python/packages/core/agent_framework/_harness/_loop.py:40`) rather than targeting blocker. Documented for agent-framework, openhands (`Todo:2` count at `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:94-99`), and openai-agents-sdk parallel group (`src/agents/run_internal/tool_planning.py:984-1036`).
- **Whole-list reseal for reordering.** Moving a todo earlier requires `remove+add` (new ID) or resending entire array — loses stable refs. Seen in agent-framework (no `reorder` field in `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:320-350`, `dotnet/src/Microsoft.Agents.AI/Harness/Todo/TodoState.cs:12-24`), openhands (`self._task_list = action.task_list` at `studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:176`), and pydantic_ai rebuild requirement (`pydantic_graph/pydantic_graph/graph_builder.py:850` insertion order).
- **Silent drop of unknown fan-out target.** `Send(node="unknown")` → warning + `None` → execution proceeds (`libs/langgraph/langgraph/pregel/_algo.py:977-978`); no `PregelTask.error` seeded, no hard fail — parallel work silently lost.
- **Prose plan as the only artifact.** `PLAN.md` 5-tuple headers (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/preset/planning.py:14-88`) with free-form bullets not queryable; Build is a hard-coded prompt (`frontend/src/hooks/use-handle-build-plan-click.ts:27`) mismatching `agents-tmp-config` path for GitLab/Azure — stale plans execute vacuous.
- **Tool enforcement aborting semantic success.** `_validate_expected_tool_usage` raising `ValueError` if `tool_to_use` not called (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/step_executor.py:515-538`) converts a correct text answer into `StepResult(success=False)`.
- **Orphaned sub-agents on crash.** `TaskManager` temp dirs leaked (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task/manager.py:117-142`, `391-407`); `BackgroundAgentsProvider` Runtime `asyncio.Task` marked `LOST` on provider loss (`sources/agent-framework/python/packages/core/agent_framework/_harness/_background_agents.py:180-220`) — decomposition not durably resumable.
- **Inconsistent observation failure defaults.** `PlannerObserver.observe` outer exception returns `success=True, remaining_valid=True` vs parse fallback `success=False, valid=False` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:208-352`) — masking vs spurious replan in the same component.

## Notable Absences

- **Hierarchical decomposition** — No source supports `children: list[Subtask]` or `parent_step_number` nesting. All plan artifacts are flat: `list[TodoItem]` (`sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:320-350`), `TodoList.items` (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:45-196`), `list[TaskItem]` (`studies/agent-harness-study/sources/openhands/_sdk_inspect/tools/task_tracker/definition.py:49-52`), ad-hoc `list[str|list[str]]` in langgraph test (`libs/langgraph/tests/test_pregel.py:5165-5188`). Graph engines support nominal nesting via subgraphs/namespace (`libs/langgraph/langgraph/pregel/_algo.py:624-625`, `pydantic_graph/pydantic_graph/id_types.py:50`) but not plan-step nesting.

- **First-class reorder/prioritize API.** No `todos_reorder(ids)` / `todos_update(id, patch)` / `todos_reorder` preserving identity. Agent-framework has no reorder field (`dotnet/src/Microsoft.Agents.AI/Harness/Todo/TodoState.cs:12-24`); openhands requires whole-list resend; langgraph reorder is `update_state` on channel state not a plan API (`libs/langgraph/langgraph/pregel/_checkpoint.py:117`); openai-agents-sdk and pydantic_ai core have no update API.

- **Typed subtask taxonomy with routing.** No `kind: Literal["research","code","review"]` or `priority`/`effort`/`owner` enum on plan items; only crewai `tool_to_use: str|None` proxies type. Developer must parse `title`/`description` strings to route subtasks to specialist agents.

- **Explicit `blocked`/`waiting_on` status.** Closest is langgraph `PregelTask.interrupts`/`error` (`libs/langgraph/langgraph/types.py:637-646`) or crewai `get_ready_todos` derived set; but no source exposes `blocked_by: list[int]` or `BlockedTask{task_id, blocked_by[], reason}` as a typed view. Flat lists collapse to `todo`/`pending` vs `done`/`completed`.

- **Plan validation and coverage metrics.** No `validate_plan` checking dependency cycles, duplicate/contradictory subtasks, or coverage; only graph edge/type validation exists (`validate_workflow_graph` at `sources/agent-framework/python/packages/core/agent_framework/_workflows/_validation.py:1-60`, `StateGraph.validate` at `libs/langgraph/langgraph/graph/state.py:1129`). No `is_plan_complete`/`plan_score`/`minimality` check — completion is `is_complete` or `EndMarker` reachability.

- **Unified plan registry bridging LLM todos ↔ graph tasks.** No `TodoWorkflowAdapter` / `TodoGraphAdapter` materializing `list[TodoItem(depends_on)]` into `WorkflowBuilder.add_edge` or `StateGraph.add_edge`. Every source with both layers documents fragmentation: agent-framework todos vs workflows, openhands TaskTracker vs TaskManager, crewai crew-planner vs AgentExecutor, pydantic_ai core graph vs external TodoCapability.

## Per-Source Notes

**agent-framework (6/10):** Dual durable todo + compiled DAG but deliberately disconnected. Copy its `TodoStore` persistence and lock pattern; avoid replicating the missing `depends_on`/`reorder` gaps and the `reason`-not-persisted audit hole. Workflow side is production-grade (typed handlers, fan-out/in groups, validation) — use it for developer-declared decomposition, not for LLM-authored plans. Evidence: `sources/agent-framework/python/packages/core/agent_framework/_harness/_todo.py:47-620`, `sources/agent-framework/python/packages/core/agent_framework/_workflows/_workflow_builder.py:53-300`.

**crewai (7/10):** Most complete LLM-plan loop in the cohort. Copy its dependency-aware scheduler (`get_ready_todos`/`can_parallelize`), four-state lifecycle, and refinement-vs-replan policy (`studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/agents/planner_observer.py:215-242`, `studies/agent-harness-study/sources/crewai/lib/crewai/src/crewai/utilities/planning_types.py:185-196`). Compensate for flat-only structure, disconnected crew-planner, and memory-only state; add persistence and hierarchical phases before claiming production readiness.

**langgraph (7/10):** The reference for graph decomposition without a plan object. Copy its PUSH/PULL superstep merge, barrier `waiting_edges`, deterministic `TASKS` Topic, and snapshot blocking surface (`StateSnapshot.tasks/next/interrupts`). Accept that plan concerns must be built atop channels — there is no `Subtask` kind, no plan-update tool, and silent unknown-`Send` drops need hardening.

**openai-agents-sdk (2/10):** Explicitly chooses absence. Its `ToolExecutionPlan` is a clean ephemeral grouping primitive (`src/agents/run_internal/tool_planning.py:558-646`) and useful to study as the minimal floor, but it contributes no decomposition representation to copy if you need cross-turn plans, status, dependencies, or reorder.

**openhands (4/10):** Two human-oriented surfaces (`TASKS.json` + `PLAN.md`) plus isolated delegated `Task` sub-conversations. Useful to study the human-readability vs machine-queryability tradeoff; the markdown artifact previews well in `PlanPreview` (`studies/agent-harness-study/sources/openhands/frontend/src/components/features/chat/plan-preview.tsx:26-80`) but pays whole-list mutation and fragmentation. The per-source documented path mismatch and doc/code drift (`TASKS.md` vs `TASKS.json`) make it the cautionary example for plan persistence hygiene.

**pydantic-ai (3/10):** A generic graph engine posing as absence for plan concerns. Its `pydantic_graph` decomposition (`Fork`/`Join`/`Decision`/`Reducer` at `pydantic_graph/pydantic_graph/node.py:60`, `pydantic_graph/pydantic_graph/join.py:150`, `pydantic_graph/pydantic_graph/decision.py:41`) is the most typed parallel substrate after langgraph; the agent-loop usage (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:2574-2603`) shows how a 4-node FSM avoids plan semantics entirely. Copy the reducer/early-stop pattern and superstep barrier, but bring your own plan layer (extending `AbstractCapability` at `pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:1`).

## Open Questions

- No source proves large fan-out under load (e.g., `max_steps=20` with fan-out `depends_on`) beyond unit tests (`lib/crewai/tests/utilities/test_structured_planning.py:572-644`, `libs/langgraph/tests/test_pregel.py:5165`) — missing latency, cycle-detection, and idempotency metrics at scale.
- External `pydantic-ai-todo` / `TodoCapability` claims subtask dependencies + Postgres persistence (`docs/capabilities/third-party.md:9-11`, `docs/toolsets.md:895`) are out-of-scope per study isolation — unverified atomicity, replay semantics, and blocking query performance.
- Whether Langgraph `Send.timeout` per-fan-out (`libs/langgraph/langgraph/types.py:755`) interacting with `interrupt_before/after` distinguishes timeout-blocked vs human-interrupt in `StateSnapshot` — docs leave the error-type discrimination ambiguous.
- Relationship between crewai deprecated `max_reasoning_attempts` and the `max_attempts`/`max_replans`/`max_step_iterations` triad is implicit and mixed in tests — migration semantics unclear.
- Unified persistence for crewai `AgentExecutorState.todos` into `RuntimeState` checkpoint is suggested but not implemented; whether Flow rebound of memory views survives resume remains untested.
