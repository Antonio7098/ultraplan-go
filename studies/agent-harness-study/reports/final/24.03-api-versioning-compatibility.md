## Executive Summary

All ten systems version *something*, but none version everything the same way. The only surface where most achieve executable safety is **persisted state**: langgraph (checkpoint `v=4`), openai-agents-sdk (`RunState $schemaVersion 1.17`), pydantic-ai (`ModelMessagesTypeAdapter` aliases), and temporal (schema `curr_version`/`min_compatible_version`) all carry an explicit version field, test migration against frozen fixtures, and either migrate on read or fail closed. Every other surface — REST APIs, SDK exports, tool schemas, traces, prompts — relies disproportionately on **policy and convention**.

Mean rating is 6.1/10 (range 4–7). The four 7s (langfuse, langgraph, openai-agents-sdk, pydantic-ai, opa at 7) share a deliberate enforcement mechanism beyond docs: Fern-stamped deprecation envelopes, fixture-backed checkpoint migrations, or a griffe break-detector in CI. The three 4–5s (letta 4, crewai 5) demonstrate the failure mode of "additive forever on a single prefix" — `deprecated=True` without removal, mono-version pins, and thin checkpoint shims — which keeps old clients alive but accumulates fallback spaghetti and hides when removal is safe. Agent-framework (6) and temporal (6) and openhands (6) occupy the middle: a clear version gate exists (floor, header semver, or two-level lifecycle) yet coverage is spotty — e.g., only a subset of .NET projects validate API compat, only ingestion has header negotiation, only history has capability flags.

Central finding: **upgrading safely without auditing every internal change is only plausible when the deployer pins a version range and the project ships executable compatibility tests for the exact artifact being persisted or consumed** (checkpoints, message histories, queue payloads). Where such tests exist, upgrade is drained-read-migrated. Where only changelogs and `FutureWarning` exist, upgrade is audit-and-hope.

## Core Thesis

Compatibility is not a single version number but a **product of three independent choices** that every source mixes differently:

1. **What is versioned explicitly** (package semver vs. persisted `v` vs. path `/v2` vs. capability string).
2. **How breaking is communicated** (typed warning with removal tuple vs. body `_deprecation` envelope vs. changelog prose vs. silence).
3. **How compatibility is proven** (frozen corpus and signature snapshot vs. manual `CHANGELOG.md` review).

Sources that score highest decouple (1) so that persisted contracts can evolve without bumping the public API, couple (2) to (1) so warnings carry the target version, and automate (3) so CI fails on accidental breakage. Langgraph's integer `v` + typed `LangGraphDeprecatedSinceV10(since=(1,0), expected_removal=(2,0))` + fixture test; openai-agents-sdk's `CURRENT_SCHEMA_VERSION=1.17` + `SCHEMA_VERSION_SUMMARIES` + `historical corpus from git archive`; pydantic-ai's Pep440 git-tag + `PydanticAIDeprecationWarning(UserWarning)` + griffe fingerprint waiver; langfuse's Fern `availability: deprecated` + `V3_SUNSET_DATE=2026-11-16` single source + `deprecation-signal.servertest.ts` drift test — each illustrates the pattern.

Sources that score lowest collapse (1) into a single mono-version (`crewai 1.15.17` everywhere, `letta 0.16.8`), leave (2) as `deprecated=True` or docstring with no sunset, and leave (3) to a handful of unit tests on the happy path. The resulting cost is not immediate breakage — additive `optional()` and fallback `old or new` keep clients green — but **permanent dual-path maintenance, silent cache/fleet staleness, and no machine-readable signal for when the old path can be removed**.

## Approach Models

Clustered by dimension-relevant approach rather than by implementation language:

### Cluster A — Executable Persisted-Contract Versioning
**Members:** langgraph, openai-agents-sdk, pydantic-ai (messages), temporal (schema), agent-framework (checkpoints/sessions)

Writes always emit `LATEST`/`CURRENT`; reads tolerate any supported `v` and migrate in place or fail closed; a frozen corpus or proto round-trip suite pins compatibility. Common mechanism: `v: int` or `$schemaVersion: "1.17"` or `curr_version` with `LATEST_VERSION = 4` (`libs/langgraph/langgraph/pregel/_checkpoint.py:23`), `CURRENT_SCHEMA_VERSION="1.17"` (`src/agents/run_state.py:182`), `curr_version/min_compatible_version` manifest (`tools/common/schema/updatetask.go:38`). Best-fit when persisted artifacts outlive code deploys by days–months (checkpoints, message history, DB schema). Cost: migration code is permanent and corpus maintenance is real (openai-agents-sdk retains `baseline v0.19.4` writer; langgraph embeds v1/v2/v3 blobs).

### Cluster B — Path- and Header-Versioned Public API with Explicit Sunset
**Members:** langfuse, opa, temporal (REST)

Routing carries version: `GET /api/public/v2/observations` vs `legacy/observations-v1` (`fern/apis/server/definition/observations.yml:36` vs `legacy/observations-v1.yml:11`), `POST /v0/data` vs `POST /v1/data` (`v1/server/server.go:83-94`), `Accept: application/vnd.opa.ucast.all+json` (`v1/server/compile_handler.go:44`). Sunset is a single date or `SupportedClients` range with a machine-readable signal (`_deprecation: {message,replacement,docsUrl,sunsetAt}` gated on `NEXT_PUBLIC_LANGFUSE_CLOUD_REGION` at `web/src/features/public-api/server/createAuthedProjectAPIRoute.ts:316`; `SupportedServerVersions=">=1.0.0 <2.0.0"` at `common/headers/version_checker.go:29`). Best-fit for server/CLI fleets where clients can switch URLs or headers. Cost: doubles route surface, big-bang sunset pressure, and header `parseInt("4.1",10)==4` class bugs.

### Cluster C — Additive Monolith (Mono-Version + Thin Migration)
**Members:** crewai, letta, partially agent-framework

Single `__version__ = "1.15.17"` (`lib/crewai/src/crewai/__init__.py:51`) or `0.16.8` (`pyproject.toml:3`) for the whole workspace; evolution is "add optional field, keep old field `deprecated=True`, fallback `old or new`" (`letta/server/rest_api/routers/v1/agents.py:540-557`, `lib/crewai/src/crewai/state/runtime.py:89-175`). Migration is thin: crewai `_migrate` only handles `<1.14.6` `memory_kind`/`source_type`; agent-framework enforces `snapshot.version == _SESSION_SNAPSHOT_VERSION` or raise (`python/packages/core/agent_framework/_sessions.py:1974`). Best-fit for early-stage monorepos or Cloud-managed backends where server and SDK ship together. Cost: no removal window, perpetual fallback spaghetti, `FutureWarning` silent by default (`lib/crewai/src/crewai/a2a/config.py:310`).

### Cluster D — Capability / Feature-Flag Negotiation Islands
**Members:** crewai (A2A), openhands, temporal, langfuse (ingestion), opa (capabilities), pydantic-ai (ModelProfile/Instrumentation)

Instead of version numbers, peers exchange sets: `usable_tools: string[]` (`src/api/agent-server-compatibility.ts:27`), `supported-features: follows-next-run-id` (`common/headers/version_checker.go:31`), `WasmABIVersions[]` (`v1/ast/capabilities.go:84`), `ProtocolVersion = Literal["0.3.0","0.4.0"]` (`lib/crewai/src/crewai/a2a/types.py:38`). negotiation is three-step priority matching (`negotiate_transport()` at `lib/crewai/src/crewai/a2a/utils/transport.py:109`) or boolean advertisement (`GetSystemInfo.Capabilities` at `service/frontend/workflow_handler.go:3506`). Exists only on sub-surfaces; never generalized — every report notes "no generic capability negotiation beyond X". Best-fit for heterogeneous fleets where feature rollout is incremental. Cost: set-membership is typo-sensitive and invisible until a feature silently disappears (openhands defaults to `true` when `usable_tools` absent).

### Cluster E — Staged Maturity Lifecycle
**Members:** agent-framework, pydantic-ai, langgraph, openhands

An orthogonal overlay: `alpha→beta→rc→released→deprecated` (`python/PACKAGE_STATUS.md:14-52`) or `Stable / Deprecated (next major) / Beta (may break in minor) / Internal (__repr__ churn permitted)` (`docs/version-policy.md:11-25`). Enforced by decorator (`@experimental(feature_id=ExperimentalFeature.HARNESS)` at `python/packages/core/agent_framework/_feature_stage.py:52`), `PydanticAIDeprecationWarning(UserWarning)` visible by default, or `@beta`/`!!! warning "Beta"` prose (`libs/langgraph/langgraph/pregel/main.py:3504`). Best-fit for frameworks that incubate features inside a stable package. Cost: beta promise is policy-only unless paired with Cluster A/B enforcement; many betas never graduate.

## Pattern Catalog

**1. Single-writer LATEST + lazy migrate-on-read**
- *Problem:* Persisted artifacts must survive code upgrades without a migration job.
- *Sources:* langgraph (`create_checkpoint` always `v=LATEST_VERSION` at `libs/langgraph/langgraph/pregel/_checkpoint.py:207`, `_migrate_checkpoint` at `libs/langgraph/langgraph/pregel/main.py:1136`), openai-agents-sdk (`to_json` always `1.17` at `src/agents/run_state.py:179`), temporal schema (`executeUpdates`→`updateSchemaVersion` at `tools/common/schema/updatetask.go:108`), pydantic-ai additive messages.
- *Why works:* No need to rewrite old rows eagerly; old threads upgrade when touched.
- *Copy when:* checkpoint, message history, or DB rows outlive deploys.
- *Overkill when:* ephemeral state (stream frames) — there `v3` literal dispatch suffices.
- *Evidence:* `libs/langgraph/langgraph/pregel/main.py:1136`, `src/agents/run_state.py:182`, `tools/common/schema/updatetask.go:38`.

**2. Frozen historical corpus generated from real writers**
- *Problem:* Hand-edited version labels give false confidence.
- *Sources:* openai-agents-sdk (`tests/fixtures/run_state/` per-version writers via `git archive` + `sources.json:44`, validated by `tests/test_run_state_compatibility_corpus.py:178`), langgraph (`SAVED_CHECKPOINTS` v1/v2/v3 blobs + `test_checkpoint_migration.py:272` masking non-deterministic fields), temporal less mature (only scheduler `replay_test.go`).
- *Why works:* Proves old bytes actually parse, not just that new code thinks it would.
- *Copy when:* durable resume boundary (HITL, long-running workflows).
- *Risk:* High maintenance; openai-agents-sdk documents `canonical_compatibility` exceptions for versions without writers.
- *Evidence:* `tests/fixtures/run_state/README.md:1`, `tests/test_run_state_compatibility_corpus.py:141`, `libs/langgraph/tests/test_checkpoint_migration.py:1475`.

**3. Griffe / API-snapshot break detector with fingerprinted waiver**
- *Problem:* Prevent accidental public API removal without a migration note.
- *Sources:* pydantic-ai (`.github/scripts/check_api_compatibility.py:106` `griffecli check --against <tag>` with `SHA256(package\0path\0message)` at `:46` + `api-compatibility-allowlist.json:2` empty), openai-agents-sdk (`tests/fixtures/released_api_contract.json` + `released_api_contract_policy.json` + `tests/test_released_api_contract.py:42`), agent-framework .NET (`PackageValidationBaselineVersion` at `dotnet/src/Microsoft.Agents.AI.Foundry.Hosting/Microsoft.Agents.AI.Foundry.Hosting.csproj:6`) and temporal missing.
- *Why works:* CI fails closed on any signature/field change; waiver is tag-scoped and reviewable.
- *Copy when:* SDK/library with many re-exports; pair with `__all__` contract.
- *Risk:* Only syntactic; semantic flips like `end_strategy: early→graceful` not caught.
- *Evidence:* `.github/scripts/check_api_compatibility.py:68`, `tests/test_released_api_contract.py:82`, `dotnet/Directory.Packages.props:2`.

**4. Typed deprecation hierarchy with removal SemVer baked in**
- *Problem:* Free-form deprecation messages cannot be linted or filtered.
- *Sources:* langgraph (`LangGraphDeprecationWarning(since, expected_removal)` at `libs/langgraph/langgraph/warnings.py:13` with `SinceV05→(2,0)` etc., 15 `pytest.warns` tests at `tests/test_deprecation.py:28`), pydantic-ai (`PydanticAIDeprecationWarning(UserWarning)` at `pydantic_ai_slim/pydantic_ai/_warnings.py:4`), agent-framework (`ExperimentalWarning` once per `feature_id` via `(_WARNED_FEATURES: set[tuple[type[Warning], str]])` at `python/packages/core/agent_framework/_feature_stage.py:28`).
- *Why works:* Consumers can `filterwarnings` by subclass; CI can assert removal deadlines.
- *Copy when:* framework with staged deprecations; make warning visible by default (`UserWarning` not `DeprecationWarning`).
- *Risk:* Coarse buckets (three subclasses for many deprecations) and `warnings.warn` default invisibility for `FutureWarning` (`lib/crewai/src/crewai/a2a/config.py:310` silent).
- *Evidence:* `libs/langgraph/langgraph/warnings.py:28`, `pydantic_ai_slim/pydantic_ai/_warnings.py:4`, `python/packages/core/agent_framework/_feature_stage.py:202`.

**5. Validation-alias preservation for renamed fields**
- *Problem:* Renaming a field must not break stored JSON.
- *Sources:* pydantic-ai (`AliasChoices('provider_details','vendor_details')` at `messages.py:2577` + `request_tokens→input_tokens` at `usage.py:91` + regression `tests/test_messages.py:575`), crewai backfills `memory_kind`/`source_type` (`lib/crewai/src/crewai/state/runtime.py:115`), letta bare-UUID rewriting (`letta/schemas/letta_base.py:79`) but less typed.
- *Why works:* Old bytes deserialize into new model; write emits canonical name (observable churn but not breakage).
- *Copy when:* persisted message/usage/schema with external storage (DB JSON columns).
- *Risk:* String-compare of raw JSON histories now shows churn; combine with `__get_pydantic_core_schema__` to preserve unknown fields (`usage.py:143`).
- *Evidence:* `pydantic_ai_slim/pydantic_ai/messages.py:2577`, `pydantic_ai_slim/pydantic_ai/usage.py:88`, `lib/crewai/src/crewai/state/runtime.py:106`.

**6. Path-versioned successors with field-group opt-in**
- *Problem:* Additive expansion without breaking existing callers.
- *Sources:* langfuse (`/api/public/v2/observations` cursor+field-groups at `fern/apis/server/definition/observations.yml:36`, `/v3/scores` polymorphic `BOOLEAN 0|1 double → boolean` at `scores-v3.yml:199`, `/otel/v1/traces` OTLP), opa `v0+v1/data` (`v1/server/server.go:83`), pydantic-ai field groups implicitly.
- *Why works:* Minimal core returned unless `fields=` lists groups; new groups added safely.
- *Copy when:* REST surface with many optional expansions and a big-bang migration budget.
- *Risk:* Doubles route surface; clients must change URLs, not just headers.
- *Evidence:* `fern/apis/server/definition/observations.yml:30`, `v1/server/server.go:904`.

**7. Body `_deprecation` envelope + OpenAPI stamping from single source**
- *Problem:* Runtime clients and docs must agree on sunset.
- *Sources:* langfuse (`V3_SUNSET_DATE="2026-11-16"` at `web/src/features/public-api/server/deprecations.ts:11`, `attachDeprecation()` at `:102` adding `{...body, _deprecation}` only on Cloud, `stamp-deprecations.ts:64` + `fern-deprecations.ts:71` + `deprecation-signal.servertest.ts:40` drift tests).
- *Why works:* One constant fans out to runtime JSON, OpenAPI `deprecated:true`, and docs upgrade guide; tests prove parity.
- *Copy when:* hosted + self-hosted split; supplement with standard `Deprecation`/`Sunset` headers.
- *Risk:* Array bodies passthrough (`deprecations.ts:107`), Cloud-only gate hides warnings from self-hosted until upgrade.
- *Evidence:* `web/src/features/public-api/server/deprecations.ts:11`, `web/scripts/openapi/stamp-deprecations.ts:29`, `web/src/__tests__/server/deprecation-signal.servertest.ts:40`.

**8. Bidirectional semver header negotiation**
- *Problem:* Prevent old SDK talking to new server and vice versa.
- *Sources:* temporal (`ServerVersion="1.32.0"` + `SupportedServerVersions=">=1.0.0 <2.0.0"` + `SupportedClients map` at `common/headers/version_checker.go:26` + `ClientSupported` bidirectional check at `:116` + `SDKVersionInterceptor` at `common/rpc/interceptor/sdk_version.go:31`), langfuse ingestion (`x-langfuse-ingestion-version` reject `>4` at `web/src/pages/api/public/otel/v1/traces/index.ts:270`), openhands (`X-OpenHands-Client-Version` telemetry at `src/api/client-source.ts:12`).
- *Why works:* Fail fast with typed `ClientVersionNotSupported`/`ServerVersionNotSupported` before handler logic.
- *Copy when:* gRPC/HTTP edge where SDK fleet is heterogeneous; unknown clients bypass (`version_checker.go:124`).
- *Risk:* Missing headers treated as compatible (`version_checker_test.go:38`), hardcoded `ServerVersion` drifts from `go.mod` tag.
- *Evidence:* `common/headers/version_checker.go:44`, `common/rpc/interceptor/sdk_version.go:40`, `web/src/pages/api/public/otel/v1/traces/index.ts:261`.

**9. Set-membership capability discovery (degrade-to-unknown)**
- *Problem:* Rolling deploy must not hard-fail when a new capability is absent.
- *Sources:* openhands (`usable_tools` string set at `src/api/agent-server-compatibility.ts:27`, `isAgentServerToolAvailable` defaults `true` when absent at `:149`; `DeploymentCapabilities` set at `src/manifests/manifest-capabilities.ts:7`), temporal (`GetSystemInfo.Capabilities` booleans missing→`false` at `service/frontend/workflow_handler.go:3509`; `ClientSupportsFeature` splits `supported-features` at `common/headers/version_checker.go:150`), langfuse (`areLegacyWritesActive`/`areEnrichedWritesActive` from `LANGFUSE_MIGRATION_V4_WRITE_MODE` at `packages/shared/src/env.ts:328`).
- *Why works:* Old servers render with defaults; new servers advertise; no version bump needed per feature.
- *Copy when:* many independent feature flags and mixed-version fleets.
- *Risk:* Typo-sensitive, silently drops feature if misspelled; requires discipline to add `rejectInEventsOnlyMode` where needed (langfuse 20+ routes manually flagged).
- *Evidence:* `src/api/agent-server-compatibility.ts:149`, `service/frontend/workflow_handler.go:3506`, `packages/shared/src/features/analytics-integrations/export-source-policy.ts:202`.

**10. Single numeric floor as compatibility gate**
- *Problem:* Simple "you must be at least this version" for tightly coupled frontend+backend.
- *Sources:* openhands (`config/defaults.json:9` `compatibility.minimumAgentServer:"1.28.0"` consumed by `loadAgentServerInfo()` with 5s timeout at `src/api/agent-server-compatibility.ts:15` + `compareAgentServerVersions` at `:243` + 6 vitest cases at `compatibility.test.ts:14`), letta implicit (`letta-client>=1.7.12` vs server `0.16.8`), crewai freshness check.
- *Why works:* Easy to reason about, enforce at startup (`root.tsx:22`), health-poll every 10s.
- *Copy when:* frontend and backend release in lockstep and you can afford to block render.
- *Risk:* Coarse — breaking change that keeps same major slips through; prerelease `localeCompare` lexicographic misorders `rc.2` vs `rc.10`.
- *Evidence:* `config/defaults.json:9`, `src/api/agent-server-compatibility.ts:293`, `src/api/agent-server-compatibility.test.ts:14`.

## Key Differences

- **Persisted-version strictness.** Langgraph and openai-agents-sdk are strict-forward (unknown `v`/`$schemaVersion` raises `UserError` listing `SUPPORTED_SCHEMA_VERSIONS` at `src/agents/run_state.py:3842`). Pydantic-ai is lenient-forward via `AliasChoices` (old `vendor_details` still validates). Temporal schema is lenient-backward (installed `> expected` allowed because changes are "backwards-compatible" at `common/persistence/schema/version.go:21`). Crewai is lenient with warning (`missing version → 0.0.0` at `lib/crewai/src/crewai/state/runtime.py:106`). Agent-framework hard-fails (`version != _SESSION_SNAPSHOT_VERSION` raise at `python/packages/core/agent_framework/_sessions.py:1974`). Choice reflects durability horizon: long-paused HITL favors lenient read + corpus; short-lived workflow favors fail-closed.

- **API versioning axis.** Langfuse and OPA choose path versioning (`/v2/`, `/v1/`), Temporal chooses header semver negotiation, Pydantic-ai/openai-agents-sdk choose package semver + isolated persisted version, Letta/Crewai choose no axis (single `/v1`). Path versioning gives explicit migration checklist but doubles handlers; header negotiation enables incremental rollout but every capability needs client opt-in and server fallback (temporal's `FixFollowEvents` hack exists for that); mono-version avoids matrix but forces perpetual dual code paths.

- **Deprecation observability.** Pydantic-ai deliberately uses `UserWarning` so warnings are visible by default (`_warnings.py:4`); langgraph bakes removal version into type (`SinceV10→(2,0)`) enabling `filterwarnings` by subclass; langfuse stamps `_deprecation` into body JSON agently readable but Cloud-only; agent-framework deduplicates `ExperimentalWarning` once per `feature_id` with caller-frame attribution (`_feature_stage.py:202`); letta/crewai use `FutureWarning` which is silent by default and `logger.warning` only when `settings.debug` (`letta/helpers/decorators.py:70`), so most users never see it. The difference is not taste — it determines whether deprecation is discovered in CI or only in docs.

- **Proof strength.** Pydantic-ai and openai-agents-sdk gate PRs on executable API/credential corpus tests (griffe + corpus + redaction); langfuse gates on `openapi-deprecations.servertest.ts` drift + `deprecation-signal.servertest.ts`; langgraph gates on `test_checkpoint_migration.py` + `test_deprecation.py` + `test_delta_channel_migration.py`. Letta/crewai gate only on unit tests for the single migrated path (`test_checkpoint.py:212` for `<1.14.6`, `tests/test_agent_serialization_v2.py:1036` for revision tag). Agent-framework validates only subset of .NET projects; temporal tests semver headers but not proto field removal.

- **Beta vs stable promise.** Pydantic-ai policy explicitly states `beta` may break in minors (`docs/version-policy.md:22`) yet no `beta/` code namespace was observed — policy-only. Langgraph marks `DeltaChannel` and `stream v3` as `!!! warning "Beta"` with readability-only guarantee (`channels/delta.py:34`). Agent-framework's `ExperimentalFeature` inventory (`PACKAGE_STATUS.md:64`) is the most concrete beta registry. Correlation with score: sources with a concrete registry and warning machinery score higher.

## Tradeoffs

- **Unified sunset vs per-endpoint sunset (langfuse).** One date `2026-11-16` for all v3 deprecations simplifies communication (`web/src/features/public-api/server/deprecations.ts:11`) but forces big-bang migration; per-endpoint sunset would allow early removal of `metrics-v1` without holding `ingestion` — seen as future consideration across reports.

- **Cloud-only runtime signal vs self-hosted noise (langfuse).** Gating `_deprecation` on `NEXT_PUBLIC_LANGFUSE_CLOUD_REGION` avoids spamming self-hosters who set their own cadence, at cost that self-hosted outdated SDKs get no in-band warning until upgrade breaks. Alternative seen in `openhands` (always-checked floor) and `temporal` (always-checked header).

- **Body envelope vs standard headers (langfuse vs opa/temporal).** Body `_deprecation` survives SDK deserialization that drops headers and is LLM-agent-readable, but violates IETF `Deprecation`/`Sunset` and cannot be added to array responses (`deprecations.ts:107`). Header negotiation (`Deprecation: true`, `Sunset:`) is proxy-visible but requires client to inspect headers — complementary, not competing.

- **Additive optional fields vs versioned queue schema (langfuse, letta).** Marking every new queue field `.optional()` keeps rolling deploys green without draining (`packages/shared/src/server/queues.ts:30` comment "Optional for rolling deploy compatibility"), but accumulates `undefined` handling forever; a `schemaVersion` discriminator would permit deprecation/removal with coordinated drain — proposed for langfuse `version: z.literal(1).default(1)`.

- **Pre-1.0 `0.Y.Z` with breaking on `Y` (openai-agents-sdk, openhands) vs `1.x` stable (langgraph, pydantic-ai).** `0.Y.Z` isolates breaking to minor while signaling instability, allowing patch to carry non-breaking feature/beta/bugfix (`docs/release.md:11`). Cost is that consumers cannot use `~=`/`^` and must pin `0.Y`, shifting audit burden to integrator; `1.x` with conventional pins (`langgraph 1.2.11` + `langgraph-checkpoint>=4.1.0,<5.0.0` at `libs/langgraph/pyproject.toml:20`) is familiar but every checkpoint major requires coordinated bump.

- **Coexistence of three versioning generations (temporal) vs hard break.** Temporal keeps `use_compatible_version` (v1) + `BuildId` sets (v2) + `WorkerDeploymentVersion` (v3) simultaneously (`proto/internal/temporal/server/api/persistence/v1/executions.proto:632`), plus `v0+v1` data handlers. Enables zero-downtime rolling upgrades; cost is persistence bloat, `oneof build_id_info` branching forever, and `MaxSets` limit (`service/matching/version_sets.go:48`).

- **Lenient forward read vs fail-closed (crewai/temporal vs openai-agents-sdk/langgraph).** Lenient (missing version → `0.0.0`, installed > expected allowed) favors forward progress and rollback; fail-closed (unknown `$schemaVersion` → `UserError` listing supported) prevents mis-resume of new invariants (e.g., `invocation identity/scope`). Best-fit depends on whether silent loss of new invariants is worse than blocked resume.

- **Broad allow-range `<2.0.0` (temporal) vs tight `>=x,<y` (langgraph, crewai).** `SupportedClients: "<2.0.0"` maximizes window but defers major negotiation to future 2.0 (untested). Tight pins (`langgraph-sdk>=0.4.2,<0.5.0`) avoid accidental major but withhold security fixes across majors.

## Decision Guide

Choose your primary compatibility mechanism by the dominant artifact lifetime and fleet shape:

- **If persisted HITL/workflows outlive deploys by hours–days** (agent checkpoints, runs): use **Cluster A**. Emit `CURRENT` on every write, tolerate `N` prior `v` on read with deterministic `_migrate_*`, freeze a per-version corpus from real writers, and fail closed on unknown future `v`. Copy langgraph/openai-agents-sdk verbatim; do not hand-edit fixture labels.

- **If you run a public REST/HTTP API with external SDKs across orgs**: use **Cluster B** with Fern/OpenAPI as source of truth. Declare `availability: deprecated` with `sunsetAt + replacement + docsUrl`, stamp `deprecated:true` into OpenAPI and `_deprecation` into JSON (and `Deprecation`/`Sunset` headers), and test drift (`openapi-deprecations.servertest.ts`). Provide path-versioned successors (`/v2/`) for type-breaking changes and keep header negotiation (`x-langfuse-ingestion-version`) only for wire-level toggles.

- **If you control server and SDK and ship together (monorepo, Cloud) and can enforce mono-version pins**: use **Cluster C** but impose a **removal SLA** from day one (e.g., "deprecated for 2 minors then removed, tracked in `DEPRECATED.md`"). Without SLA you will replicate letta/crewai — `deprecated=True` forever and no signal for when `source_ids` can be deleted.

- **If fleet is heterogeneous and rolling upgrades are frequent**: add **Cluster D** capabilities. Advertise booleans via `GetSystemInfo`/`usable_tools`/`supported-features`; never gate on version number alone. Implement the three-step negotiation (`client preferred → server preferred → fallback`) like crewai `negotiate_transport()` and degrade to `unknown` rather than hard-fail when discovery 404s (openhands). Enforce that every legacy-table read has `rejectInEventsOnlyMode` or equivalent.

- **If you incubate features inside a stable package**: layer **Cluster E**. Inventory every experimental surface in one manifest (`PACKAGE_STATUS.md`), require `@experimental(feature_id=...)` with `ExperimentalWarning` once per `feature_id` and caller attribution, and promote via `rc` stage with versioned wire `type` discriminator before `released`. Do not rely on docstring-only deprecation.

General rules distilled from the ten:

1. **One version per concern** — package, persisted, and protocol each need their own counter. Crewai's single `1.15.17` for all packages forces unrelated CLI fixes to rev the SDK.
2. **Warning must carry its removal version and be visible by default** — `UserWarning` or `LangGraphDeprecationWarning(since, expected_removal)`; never `FutureWarning` alone, never `settings.debug` gate, never docstring-only.
3. **Add a machine-readable signal wherever humans read the docs** — header + body + OpenAPI description from one constant (`V3_SUNSET_DATE`); otherwise self-hosted or header-dropping SDKs miss it.
4. **Fail closed for durable, degrade for discovery** — unknown checkpoint `v` → typed error; unknown `usable_tools` → `true`/`unknown` with degraded UX. Inverting this (as letta `Version("future")` silent) yields silent mis-resume.

## Practical Tips

**Patterns to copy:**

- **Freeze a corpus from real historical writers.** Use `git archive` per tag as openai-agents-sdk does; store `sources.json` provenance; note `canonical_compatibility` exceptions explicitly. Run field-preservation + idempotence + type-strictness tests (`_find_subset_errors`, `test_historical_state_comparison_preserves_json_scalar_types` at `tests/test_run_state_compatibility_corpus.py:153`).

- **Enforce public API with griffe or signature snapshot.** Pin `against latest tag`, SHA256 fingerprint `(package\0path\0message)` (`check_api_compatibility.py:46`), require `pull_request` URL in waiver, fail on unused waivers. Pair with `__all__` membership and positional-constructor guard (`tests/test_source_compat_constructors.py:34`).

- **Stamp deprecations from one Fern/OpenAPI source.** Single `V3_SUNSET_DATE` + `V3_NOTICE` + `REPLACEMENT` map (`web/src/features/public-api/server/deprecations.ts:11`) fanned to runtime `attachDeprecation`, OpenAPI `deprecated:true`, and docs. Test human/machine date round-trip and message containment.

- **Make deprecation visible.** In Python prefer `class PydanticAIDeprecationWarning(UserWarning)` over `DeprecationWarning`; in JS/Go emit `Warning: 299` plus body field; deduplicate per feature with caller frame.

- **Use AliasChoices for renamed persisted fields, not migration scripts.** `AliasChoices('provider_details','vendor_details')` + custom `__get_pydantic_core_schema__` to preserve unknown fields (`usage.py:143`) keeps old DB rows readable and round-trippable.

- **Advertise capabilities, not just versions.** `GET /server_info` returning `usable_tools` and `GET /v1/capabilities` returning `DeploymentCapabilities` allow set-matched negotiation without bumping `/v1`.

**Patterns to avoid or delay until needed:**

- **Single-date big-bang sunset** — delay per-endpoint sunset until after current wave; premature granularity doubles coordination cost.

- **`optional()` everywhere without `schemaVersion`** — cheap now, permanent `undefined` handling later. Add `schemaVersion` only when you need to remove a field.

- **`0.Y.Z` wildcard pins (`>=0.Y`)** — pin `0.Y` exactly; treat `Y` as major.

- **Embedding all historic `capabilities/*.json` into binary** (opa) — bloats binary; generate `version_index.json` and serve via `LoadCapabilitiesVersion` lookup.

- **Per-file glob `file_rego_versions`** — powerful but `undefined` overlap semantics surprise; prefer longest-prefix or explicit precedence and warn on overlap.

**Decision rules for choosing between main approaches:**

- Persisted state that must survive upgrade? → integer `v` + corpus (Cluster A).
- External HTTP clients you don't control? → path versioning + body/header deprecation (Cluster B).
- Rolling deploy with in-flight queue jobs? → additive `optional()` + `schemaVersion` discriminator (hybrid A+D).
- Tightly coupled frontend+backend with fast iteration? → numeric floor + capability sets (Cluster D+E) but document N-1 window.

**Caution signs that the design is becoming brittle:**

- `CHANGELOG.md` has empty `Unreleased` while GitHub Releases is the real changelog (openhands) — offline auditability lost.
- `PackageValidationBaselineVersion` set on only subset of projects (agent-framework) — silent drift risk.
- `deprecated=True` count grows but no removal issue links with `[cleanup-old-wv]` aging (temporal) — tech-debt accumulation metric.
- `unsupported version` errors appear only via 422 or opaque `ClientToolSchemaConflictError` rather than typed `ClientVersionNotSupported` — version gate is bypassable.
- Cache files (`~/.cache/crewai/version_cache.json` 24h) and `getCachedAgentServerInfo` host-mismatch — staleness masks yank/mismatch for up to a day.

## Anti-Patterns / Caution Signs

- **Additive-forever without removal.** Letta carries `deprecated=True` on ~80 routes/fields (`letta/server/rest_api/routers/v1/sources.py:49`, `letta/schemas/agent.py:87`) with `TODO`/`cleanup-old-wv` comments but no sunset; dual handling (`folder_ids or source_ids` at `letta/server/server.py:648`) persists indefinitely. Signal: `grep -r "deprecated.*True" | wc -l` trending up while no removal PR lands.

- **Silent FutureWarning / debug-gated deprecation.** Crewai `FutureWarning` (`lib/crewai/src/crewai/a2a/config.py:310`) and letta `logger.warning if settings.debug` (`letta/helpers/decorators.py:70`) are invisible to most users; CI with `-W ignore` doubly silences. Signal: users report breakage at major bump despite "we warned."

- **Mono-version forcing unrelated revs.** Crewai exact pin `crewai-core==1.15.17` (`lib/crewai/pyproject.toml:11`) means a CLI typo fix produces a new SDK version; operators cannot reason about impact. Signal: `pyproject.toml` `version=` identical across all workspace packages and `__version__` hard-pinned in three places.

- **Stale version cache hiding yank.** Crewai 24h `version_cache.json` (`lib/crewai-core/src/crewai_core/version.py:56`) plus `CI=true` banner suppression (`lib/crewai/src/crewai/events/utils/console_formatter.py:68`) means CI may run yanked code silently for a day.

- **Missing coverage for protocol negotiation.** Every report flags "no generic capability negotiation beyond X" and "no dedicated unit tests for negotiation utilities." Signal: `negotiate_transport` exists but no test file was discovered; `langfuse` queue evolution relies on comment "Optional for rolling deploy compatibility" not contract test.

- **Overlapping version selectors with undefined behavior.** OPA's sorted-key glob order (`v1/bundle/bundle.go:1352` "undefined") and pydantic-ai's cross-class `ModelProfile` field preservation make evaluation order surprising.

- **Hardcoded ServerVersion drift.** Temporal `ServerVersion="1.32.0"` comment "can be changed by the create-tag Github workflow" (`common/headers/version_checker.go:26`) decoupled from `go.mod` module version; local builds misreport.

- **Mixed fleet codec flip.** Agent-framework ADR 0034 warns newer writer defaulting to `*.msgpack` while older fleet globs `*.json` resumes stateless without error (`docs/decisions/0034-python-session-store-serialization.md:294`).

## Notable Absences

Across ten sources, the following were sought but not found (or found in only one island):

- **Formal deprecation/migration policy with sunset SLA** — no `DEPRECATED.md`, `MIGRATION.md`, or `docs/versioning.md` in any repo except pydantic-ai's `docs/version-policy.md:3` (≥3mo before next major, 6mo security) and langfuse's `V3_SUNSET_DATE`. Six reports explicitly state "no formal LTS or deprecation window."

- **Breaking-change detection in CI for proto/OpenAPI** — only pydantic-ai (griffe), openai-agents-sdk (signature contract), and agent-framework .NET (ApiCompat) automate it. No source runs `buf breaking`, `openapi-diff`, or `schemathesis` as a gate.

- **Persisted-trace / prompt / tool-schema versioning with migration tests** — message histories are versioned, but tool JSONSchema, prompt templates, and OTel trace schemas are versionless lists or additive by policy. `ModelMessagesTypeAdapter` is the exception, not the rule; instrumentation attributes explicitly allowed to churn in minors (`docs/version-policy.md:15`).

- **Version negotiation beyond ingestion/A2A islands** — every report except temporal's header flags "no generic capability/version negotiation." No `Accept-Version`, `X-Langfuse-Api-Version`, or SDK↔server capability handshake generalizes.

- **Backwards-compatibility matrix testing old client↔new server (or reverse)** — only openai-agents-sdk corpus and langgraph fixture matrix approximate it; no source runs golden `N-1` integration harness, Pact contract tests, or pinned old-image replay.

- **In-repo CHANGELOG with BREAKING markers** — langfuse externalizes to `langfuse/langfuse-docs`, letta/temporal have no file, langgraph points to GitHub Releases (`libs/langgraph/pyproject.toml:32`), crewai freezes `docs/v*/en/changelog.mdx` snapshots post-hoc. Offline `git log --follow CHANGELOG.md` workflow is broken everywhere.

- **Machine-readable stability matrix (`STABLE/EXPERIMENTAL/INTERNAL`)** — no `STABILITY.md` or `__stability__` markers enforced by linter; status must be inferred from `experimental/` prefix, `@deprecated`, or `x-fern-availability: deprecated`.
