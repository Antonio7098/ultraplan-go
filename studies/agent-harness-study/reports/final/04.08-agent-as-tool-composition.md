## Executive Summary

All six sources can expose a higher-level capability (another agent, a workflow, a remote peer) as a callable tool, but they reach that capability through four distinct mechanism families: explicit wrapper APIs (`openai-agents-sdk`'s `Agent.as_tool()`, `agent-framework`'s `as_tool()`/`AsAIFunction()`), language-primitive delegation (`pydantic-ai`'s "await the child's `run()` inside your tool", `langgraph`'s any-`Runnable`-as-node uniformity), domain-specific delegation tools holding live peer references (`crewai`'s `DelegateWorkTool`), and conversation/process-level spawning where the tool creates an independent child run rather than a nested one (`openhands`' browser-executed `launch_child_conversation`).

Two findings converge across every source despite these different mechanisms. First, **the model-facing contract is almost universally a string**: whatever structure exists inside the child is flattened to text before it reaches the parent LLM in five of six sources, with rich typed results preserved only for programmatic/harness consumers (`openai-agents-sdk: src/agents/tool.py:374-392`, `pydantic-ai: pydantic_ai_slim/pydantic_ai/run.py:593-743`, `langgraph: libs/langgraph/langgraph/graph/state.py:1456-1481`, `agent-framework: python/packages/core/agent_framework/_agents.py:714`, `crewai: lib/crewai/src/crewai/tools/agent_tools/delegate_work_tool.py:22-30`). Second, **no source has a structural recursion or cycle guard for agent-as-tool composition**; every source terminates cyclic compositions only through per-level budgets that multiply rather than constrain across depth (verified by targeted searches in each report).

Where sources genuinely differ is in what crosses the boundary *besides* text: human-in-the-loop approvals (`openai-agents-sdk` routes nested interruptions to arbitrary depth and survives serialization; `langgraph` aggregates sibling interrupts and resumes them durably), cost attribution (`openai-agents-sdk` shares the parent's usage object automatically; `pydantic-ai` makes it opt-in via `usage=ctx.usage`; `langgraph`, `crewai`, and `openhands` attribute nothing per child), and cancellation semantics (`pydantic-ai` isolates child cancellation as a failed tool return by default — the inverse of most frameworks — while `openai-agents-sdk` propagates deterministically through both streaming and non-streaming paths).

## Core Thesis

Composition scales not by adding a new execution concept but by refusing to add one. The strongest designs in this study make an agent *literally be* a tool — same schema machinery, same approval gates, same tracing, same error policy — so that every safeguard built for flat tool calls applies to nested runs for free (`openai-agents-sdk`: an agent tool is a plain `FunctionTool` flagged `_is_agent_tool`, `src/agents/agent.py:1015-1040`; `agent-framework`: `as_tool()` returns an ordinary `FunctionTool` closure reusing approval/middleware/OTel plumbing, `python/packages/core/agent_framework/_agents.py:608-724`; `langgraph`: any compiled graph is a node because it is a `Runnable`, `libs/langgraph/langgraph/graph/state.py:778-787`). The recurring weakness is the mirror image of that strength: because nested runs reuse the flat-call pipeline, concerns that only exist at depth — cumulative budget, cycle detection, per-child cost, child trace identity — have no natural home and were absent in all six sources. The dimension question "can composition scale without creating invisible nested loops?" is answered **no** everywhere: loops are bounded per level but never globally, and no source detects a cycle before burning its budgets.

## Approach Models

**Explicit wrapper API (openai-agents-sdk).** `Agent.as_tool()` converts an agent into a strict-schema `FunctionTool` whose invocation starts a full nested `Runner.run` (`src/agents/agent.py:583-605`, `src/agents/agent.py:961-976`). The wrapper carries machine-readable provenance (`ToolOrigin(type=AGENT_AS_TOOL)`, `src/agents/tool.py:285-337`) that downstream tracing, approval routing, and state serialization consume. Child bounds are mandatory: passing `max_turns=None` still resolves to the default of 10 (`src/agents/agent.py:713`, `src/agents/run_config.py:45`). This is the most opinionated model: composition is a product feature with its own input types, output extractor chain, streaming callback option, and dedicated ~3,700-line test suite.

**Primitive-first delegation (pydantic-ai).** Deliberately *no* `as_tool` wrapper exists in this revision (repo-wide search returned no definition); the sanctioned pattern is an async tool body awaiting another agent's `run()` (`docs/multi-agent-applications.md:13-97`). The framework instead guarantees the cross-cutting concerns around that call: shared usage accumulation, run-scoped cancellation with isolation-by-default, OTel span nesting via baggage, and typed child results (`pydantic_ai_slim/pydantic_ai/agent/abstract.py:469-544`). The docs codify five composition levels from tool delegation up through graph control flow (`docs/multi-agent-applications.md:3-11`), and the agent loop itself is a `pydantic_graph` state machine, so workflow-as-tool composes at two levels (`_agent_graph.py:2580`).

**Uniform substrate (langgraph).** Composition reduces to "`Runnable` in graph node": a compiled graph, a prebuilt ReAct agent shaped for embedding (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:466-468`), or a plain tool all compose identically (`libs/langgraph/langgraph/graph/state.py:778-787`). Nested graphs are discovered by bytecode/closure introspection rather than registration (`libs/langgraph/langgraph/pregel/_utils.py:45-73`) — zero boilerplate, but detection failure is silent by design (`libs/langgraph/libs/langgraph/tests/test_subgraph_detection.py:1-9`). A distinctive extra: children can steer parents upward via `Command(graph=Command.PARENT)` (`libs/langgraph/langgraph/types.py:799-848`).

**Adapter family (agent-framework).** One adapter pattern replicated across surfaces: `BaseAgent.as_tool()` (Python), `AIAgentExtensions.AsAIFunction()` (.NET), `Workflow.as_agent()` (graph becomes an agent, which is itself `.as_tool()`-able), and `RawAgent.as_mcp_server()` (agent published as a single MCP tool) (`python/packages/core/agent_framework/_agents.py:608-724, :1653-1699`; `_workflows/_workflow.py:1195-1236`). Uniformity comes from requiring only `SupportsAgentRun`; the deliberate price is a string-in/string-out contract at every boundary.

**Named delegation tools (crewai).** Instead of generic wrapping, hierarchy is expressed as two ordinary tools — `DelegateWorkTool`/`AskQuestionTool` — holding direct references to peer agents and synthesizing an ad-hoc `Task` executed synchronously inside the caller's tool step (`lib/crewai/src/crewai/tools/agent_tools/base_agent_tools.py:112-120`). The LLM picks targets by role name from rosters interpolated into tool descriptions, with defensive sanitization for fragile outputs. Workflow-as-tool is one-directional: flows orchestrate crews (`docs/edge/en/concepts/flows.mdx:846-878`), but no `Crew.as_tool()`/`Flow.as_tool()` exists.

**Conversation-spawning client tool (openhands).** Because this source is a frontend, its most interesting mechanism makes the *browser* the tool executor: `launch_child_conversation` is a JSON-schema client tool the LLM calls, the WebSocket handler intercepts, and the UI validates and executes — creating a genuinely independent child conversation (local git-worktree isolated or cloud) and posting a structured result envelope back into the parent (`src/api/launch-child-conversation-client-tool.ts:61-112`, `src/services/child-conversation-launch.ts:272-497`). Server-side `task` tool delegation is gated behind `enable_sub_agents` (`src/api/agent-server-adapter.ts:636-641`), default off (`src/services/settings.ts:50`).

## Pattern Catalog

### 1. Adapter-over-platform: wrap, don't invent
- **Problem:** nested runs need schemas, approvals, limits, tracing, error policy without building a parallel nested-run protocol.
- **Demonstrated by:** openai-agents-sdk (agent tool inherits the whole function pipeline, `src/agents/agent.py:1015-1040`), agent-framework (closure returns plain `FunctionTool`, `_agents.py:718-724`), langgraph (uniform `Runnable` node acceptance, `state.py:778-787`).
- **Why it works:** every safeguard written once for flat calls composes to depth N unchanged.
- **Copy when:** you already have a solid function-tool pipeline. **Overkill/risky when:** nested-specific needs (per-child budgets, interruption replay) then leak into generic modules — visible in openai-agents-sdk, where nested logic spreads across `tool_execution.py`, `turn_resolution.py`, `tool_context.py`, and `agent_tool_state.py`.
- **Evidence:** openai-agents-sdk Architectural Decisions #1; agent-framework Architectural Decisions #1–2.

### 2. Mandatory/defaulted child budgets
- **Problem:** an unbounded child is a footgun users will eventually trigger.
- **Demonstrated by:** openai-agents-sdk collapsing `max_turns=None` to the default 10 (`src/agents/agent.py:713`) — unbounded children are unrepresentable at this layer; langgraph rejecting `recursion_limit < 1` at entry (`pregel/main.py:2563-2564`).
- **Why it works:** removes a whole class of misconfiguration without needing cycle detection.
- **Copy when:** exposing any nesting API. **Risky when:** legitimate long-running children exist — then provide explicit override, as langgraph does via config merge preserving caller values (`_internal/_config.py:184-186`).
- **Evidence:** openai-agents-sdk Q2 answer; langgraph Evidence "Recursion limit config".

### 3. Two-tier bounding: hard engine limit + soft agent-visible degradation
- **Problem:** crashing the run on budget exhaustion wastes work the model could have wrapped up.
- **Demonstrated by:** langgraph — `GraphRecursionError` protects the engine (`errors.py:67-87`) while managed `RemainingSteps` lets the react agent answer "Sorry, need more steps..." instead of raising (`managed/is_last_step.py:18-21`, `chat_agent_executor.py:620-634`).
- **Why it works:** separates invariant enforcement (engine) from policy (agent UX).
- **Copy when:** your loop has a model in it that can degrade gracefully. **Overkill for:** pure mechanical loops.
- **Evidence:** langgraph Architectural Decisions "Two-tier step limiting".

### 4. Shared-mutable usage accumulator threaded through context
- **Problem:** who pays for the child's tokens?
- **Demonstrated by:** openai-agents-sdk automatically (`usage=context.usage`, `src/agents/agent.py:720-730`, with resume-path rebinding regression-tested at `tests/test_agent_as_tool.py:1545-1619`); pydantic-ai opt-in via `usage=ctx.usage` (`agent/__init__.py:1480-1487`), pinned by tests proving both attributed and unattributed outcomes (`tests/test_usage_limits.py:209-336`).
- **Why it works:** exact roll-up totals with near-zero code.
- **Failure mode:** silent under-counting when omitted — pydantic-ai's own shipped subagent tools skip it (`common_tools/image_generation.py:104-105`), and durable-execution engines structurally lose it because activities see copied contexts (`docs/durable_execution/temporal.md:223`, issue #6886).
- **Alternative seen:** aggregate-after-the-fact summation (crewai `calculate_usage_metrics`, `crew.py:2201-2228`) or deferral to the tracing backend (langgraph).

### 5. HITL/approvals as the privileged signal that crosses boundaries
- **Problem:** if a nested agent needs human input, someone three levels up must hear about it.
- **Demonstrated by:** openai-agents-sdk collecting nested interruptions onto the outer step and routing decisions back down by invocation identity, failing closed on ambiguity (`run_internal/tool_planning.py:697-704`, `tool_context.py:178-191`), surviving serialization through arbitrary depth (`tests/test_run_state.py:11673-11750`); langgraph merging simultaneous sibling interrupts into one (`pregel/_runner.py:690`) with interrupt/resume durability tested across subgraphs (`test_time_travel.py:1323, 1416`); agent-framework rethrowing `UserInputRequiredException` as call-id-bound contents (`_tools.py:1706-1722`).
- **Why it works:** treats approval as control flow, not data, so it cannot be flattened away by text contracts.
- **Copy when:** any nested capability can block on humans. **Risky when:** routing identity is ambiguous — fail closed, as openai-agents-sdk does.

### 6. Corrective-guidance error envelopes instead of thrown failures
- **Problem:** a failed child shouldn't kill the parent when the server already acknowledged the call.
- **Demonstrated by:** openhands — the launcher "never rejects"; every failure becomes `{status:"error", error, guidance}` fed back to the LLM (`child-conversation-launch.ts:499-528`); relatedly, openai-agents-sdk's configurable `failure_error_function` defaults to model-visible strings with `None` opting into reraise (`src/agents/agent.py:599`, tested `tests/test_agent_as_tool.py:3335-3427`), and langgraph's `handle_tool_errors` converts invocation errors into error-text `ToolMessage`s (`prebuilt/tool_node.py:674-694`).
- **Why it works:** the calling agent is itself a recovery loop.
- **Cost:** diagnosability — crewai shows the degenerate end where *all* exceptions become prose strings and callers cannot branch on failure (`base_agent_tools.py:121-124`). Offer a typed side channel if programs, not just models, consume results.

### 7. Idempotency ledger for side-effectful composition over unreliable transports
- **Problem:** reconnecting sockets replay actions; a duplicated child launch is a billable duplicate.
- **Demonstrated by:** openhands claiming each `tool_call_id` in localStorage *before* any network work, dropping mid-flight replays, degrading gracefully when storage is unavailable (`child-conversation-launch.ts:196-227`, tested at `__tests__/services/child-conversation-launch.test.ts:490-506`).
- **Copy when:** tool execution happens outside the process that acknowledged the request. **Overkill for:** in-process nested calls with transactional acknowledgment.

### 8. Ambient-context tracing instead of child-run handles
- **Problem:** nested runs need parent linkage without inventing a child-run API.
- **Demonstrated by:** four independent implementations — crewai's contextvar event-scope stack stamping `parent_event_id`/`emission_sequence` on every event with a hard depth cap of 100 (`events/event_bus.py:543-568`, `event_context.py:22-32`); agent-framework parenting each run's `invoke_agent` OTel span in the async context (`observability.py:2409-2412`); pydantic-ai baggage propagation onto descendant spans (`capabilities/instrumentation.py:183-190`); langgraph callback managers propagated through config with per-task checkpoint namespaces (`pregel/_loop.py:1640-1650`).
- **Why it works:** zero composer effort; traces come out right by default.
- **Cost identified identically in two sources:** no first-class handle to attach budgets, cancellation tokens, or per-delegation cost to (crewai Tradeoffs; agent-framework Tradeoffs). Ambient tracing observes nesting; it cannot govern it.

### 9. Provenance stamping on child artifacts
- **Problem:** in shared state or merged transcripts, which child produced this output?
- **Demonstrated by:** openai-agents-sdk persisting `ToolOrigin(AGENT_AS_TOOL, agent_name, agent_tool_name)` through RunState serialization (`src/agents/tool.py:293-337`); langgraph stamping the producing agent's `name` onto every `AIMessage` (`chat_agent_executor.py:681-682`); openhands tagging planning events `isFromPlanningAgent` and filtering hidden protocol messages by the `[child-conversation] ` prefix constant (`conversation-websocket-context.tsx:793-801`, `constants/child-conversation.ts:20`).
- **Copy when:** children write into shared channels or streams.

### 10. Isolation-by-default cancellation with opt-in propagation
- **Problem:** should cancelling the child kill the parent?
- **Demonstrated by:** pydantic-ai inverts the common pattern — a sub-agent's self-cancel surfacing in a tool body converts to a failed `ToolReturnPart` the parent can react to (`_tool_execution.py:41-62`), while whole-tree teardown requires sharing a `CancellationToken` (`_cancel.py:42-90`); contrast openai-agents-sdk, where parent cancellation deterministically tears down children on both streaming and non-streaming paths (`run_internal/tool_execution.py:2168-2203`, `util/_asyncio_tasks.py:117-152`).
- **Why isolation works:** lets a parent try-and-fallback across delegates (pydantic-ai's own fallback-via-subagent tools rely on it, `common_tools/x_search.py:54-78`).
- **Risk:** surprising semantics — the isolation rule applies specifically in tool bodies, not other await sites, and must be documented and tested (`tests/test_run_cancellation.py:1786-1847`).

### 11. Upward control-flow primitive
- **Problem:** sometimes the child knows best that the *parent* should go somewhere else.
- **Demonstrated by:** langgraph's `Command(graph=Command.PARENT)` carrying `goto`/`update`/`resume` upward, honored by the parent's write mapper, failing fast at root ("There is no parent graph"), and pinned by a nested-subgraph jump test (`types.py:799-848`, `pregel/_io.py:56-59`, `test_parent_command.py:9-53`).
- **Copy when:** children participate in navigation/routing decisions. **Avoid when:** it would let untrusted children mutate parent state arbitrarily — scope what `update` may touch.

### 12. Post-hoc cycle detection via evaluation spans
- **Problem:** with no runtime guard, how do you even *know* delegation went circular?
- **Demonstrated by:** pydantic-ai evals asserting span-tree ancestry ("no circular delegation" sample) and counting nested sub-agent tool calls (`docs/evals/evaluators/span-based.md:541-549`, `pydantic_evals/evaluators/agentic.py:28-36`).
- **Why it matters:** the only cycle-detection mechanism found anywhere in this study — detection after the fact, in CI rather than at runtime.
- **Copy when:** you cannot change the runtime but can instrument it.

## Key Differences

**In-process nesting vs. independent child runs.** Five sources nest execution inside the parent process; openhands spawns *independent conversations* whose lifecycle, cost, and history are opaque to the parent ("does not block you... cannot see this conversation's history", `launch-child-conversation-client-tool.ts:16-17`). This is a valid response to product shape, not a quality gap: a browser frontend cannot share a Python run loop with a cloud sandbox, so it buys parallelism and fault isolation at the price of observability (no streamed progress, cost, or completion notification reaches the parent — only an id/url/status snapshot, `child-conversation-launch.ts:42-66`). CrewAI's A2A module and agent-framework's A2A samples make the same trade at network granularity.

**Wrapper ergonomics vs. primitive purity.** openai-agents-sdk invests in a discoverable, metadata-rich wrapper; pydantic-ai deliberately removed/never ships one, betting that "strong primitives over opinionated batteries" keeps the public surface small while hand-rolling name/description/schema derivation onto users (pydantic-ai Architectural Decisions #1; its Questions/Gaps note even historical `as_tool()` is gone without a migration entry). LangGraph effectively outsources the ergonomic to langchain-core — repo-wide searches found zero in-repo `as_tool` definitions. The consequence for users differs: SDK users get schema derivation and collision policies (`_tool_identity.py:431-538` catches `Refund`/`refund` name collisions at planning time) for free; primitive users get none of those guarantees and nothing statically prevents forgetting `usage=ctx.usage`.

**Result-contract richness tracks the consumer, not the framework.** Wherever a programmatic harness consumes nested results, structure survives: `FunctionToolResult.agent_run_result` carries the complete nested `RunResult` including interruptions (openai-agents-sdk), `AgentRunResult[T]` delivers validated typed output plus messages and ids (pydantic-ai), state-shaped dicts filtered to declared output keys plus `Command` objects serve langgraph parents (`state.py:1456-1468`), `CrewOutput` is a fully typed Pydantic model for Flow consumers (crewai), and typed events + merged usage cross agent-framework's `WorkflowAgent` boundary (`_workflows/_agent.py:509-585`). But the *model-facing* leg converges on text everywhere except langgraph's shared-state subgraphs — and agent-framework is the purest expression of that choice: string-in/string-out even though its own workflow path proves richer transport was feasible.

**Bounding philosophy.** openai-agents-sdk mandates a per-child turn count; pydantic-ai bounds economically via usage limits that children do *not* inherit unless passed (`agent/__init__.py:1516`); langgraph inherits the numeric `recursion_limit` but restarts the counter per level; agent-framework layers multiple caps (40 iterations/run, 100 supersteps/workflow, 10/harness loop) yet defaults cumulative `max_function_calls` to unlimited and enforces it best-effort after batches (`_tools.py:1342-1351`); crewai inherits per-agent `max_iter` (25) with the delegation layer unable to pass child-specific limits at all (`base_agent_tools.py:46-48`); openhands gives each conversation its own 500-iteration bound with nothing capping fan-out or depth. Same destination — worst case grows with depth × breadth — reached through five different philosophies.

**Cancellation direction.** pydantic-ai is the outlier with isolation-by-default; openai-agents-sdk propagates deterministically downward; langgraph converts user-raised cancels into honest `NodeCancelledError` failures and offers cooperative drain at superstep boundaries but cannot cancel sync nodes at all ("sync nodes cannot be safely cancelled in-process", `graph/state.py:715-722`); crewai has no propagation whatsoever, only a `TimeoutError` (`agent/core.py:816-839`). These reflect architecture: task-structured async runtimes propagate naturally; synchronous executor loops cannot.

## Tradeoffs

**Dedicated wrapper API vs. bare primitives.**
Benefit: discoverability, auto-derived schemas, enforced coupling points (openai-agents-sdk's structured-input options, `agent.py:650-668`). Cost: API surface to maintain and nested-specific logic smeared across generic modules (openai-agents-sdk Future Considerations). Best fit: SDKs with many naive users. Failure mode of the primitive alternative: silent omission of critical keywords — pydantic-ai's unattributed child spend is exactly this bug, committed by its maintainers. Alternative seen: langgraph's reliance on an external dependency for the ergonomic.

**Text-only boundary vs. structured child results.**
Benefit: universal provider compatibility and maximal simplicity (agent-framework decision #3). Cost: parents can't validate child outputs, make usage-aware decisions, or branch on failure; openai-agents-sdk explicitly lacks a typed output contract analogous to function tools' `output_json_schema` (`tool.py:521-522`). Best fit: LLM-mediated delegation. Failure mode: guardrails/evaluators that inspect structured failures miss everything (crewai exception-masking). Alternative seen: dual contract — text to the model, full result objects to the harness (openai-agents-sdk, pydantic-ai).

**Shared usage object vs. per-child ledgers vs. none.**
Benefit of sharing: exact aggregate totals nearly free (openai-agents-sdk, pydantic-ai). Cost: no attribution ("what did the cardiology agent cost?" is unanswerable from `result.usage` alone, pydantic-ai Tradeoffs) and lossy under serialization (Temporal gap, `temporal.md:223`). Per-request entry retention (openai-agents-sdk `usage.py:218-229`) enables post-hoc reconstruction but nobody ships it per-child today.

**Per-level bounds vs. global tree budget.**
Benefit: composability without hidden cross-layer coupling; each level independently tunable (agent-framework decision #5, langgraph Tradeoffs). Cost: total work scales multiplicatively; a buggy cycle burns bounded-but-large compute everywhere. Nobody ships the global budget; both langgraph and agent-framework list it as future work. Best fit for per-level only: trusted, shallow compositions. Failure mode: A↔B mutual delegation detected by no one (crewai Failure Modes; openai-agents-sdk Q4).

**Ambient-context observability vs. child-run handles.**
Benefit: zero-API-cost tracing that is correct by construction (Pattern 8). Cost: forecloses attaching budgets/cancellation/per-delegation costs (crewai, agent-framework Tradeoffs) and leaves parents without programmatically accessible child trace IDs (agent-framework Gaps; openhands has only `parent_conversation_id`, silently dropped below agent-server 1.37.1 — honestly reported as `parent_link: false`, `constants/child-conversation.ts:30-37`).

**Error swallowing vs. typed failure propagation.**
Spectrum observed: always-swallow-with-prose (crewai) → guidance envelopes, never reject (openhands) → configurable model-visible strings with reraise opt-out (openai-agents-sdk, langgraph) → typed exceptions crossing as call-id-bound contents for the one privileged signal, HITL (agent-framework). Benefit of swallowing: conversation survives. Failure mode: Python-side callers can't branch on failure except by parsing text.

## Decision Guide

Choose your composition mechanism by answering, in order:

1. **Does the child need to share the parent's process state (memory, session, checkpoints)?**
   Yes → in-process nesting. Prefer a wrapper API if your stack has one (openai-agents-sdk-style `as_tool`), otherwise delegate via awaited `run()` and *manually thread* the coupling points (`usage=ctx.usage`, deps, cancellation token) as pydantic-ai requires.
   No → consider independent child runs/conversations (openhands model) for parallelism and blast-radius isolation, accepting that you must build idempotency (replay ledgers) and report status snapshots rather than streams.

2. **Do humans approve things inside the child?**
   Then pick a mechanism where approvals are control flow that crosses boundaries: verify nested interruptions surface at the top and survive pause/resume (openai-agents-sdk's serialized multi-level resume tests are the reference standard, `test_run_state.py:11673-11750`; langgraph's aggregated, resumable interrupts are second).

3. **Is cost per child a requirement?**
   If yes, none of the six satisfies you out of the box. Closest bases: automatic shared usage (openai-agents-sdk) for tree totals; per-request entries for post-hoc reconstruction; OTel per-invocation histograms (agent-framework, pydantic-ai) for external correlation. Plan to build a keyed ledger yourself.

4. **Is unbounded recursion a realistic risk in your domain?**
   Assume yes if users compose agents freely. No source protects you: combine mandatory per-child turn defaults (openai-agents-sdk style), a soft-budget degradation path (langgraph style), and post-hoc span-ancestry assertions in CI (pydantic-ai evals style).

5. **Does the child ever need to redirect the parent?**
   Only langgraph offers a first-class upward channel (`Command.PARENT`). Without one, children influence parents solely through their string payloads.

6. **Composing workflows, not just agents?**
   Check bidirectionality: agent-framework (workflow→agent→tool, plus MCP publishing) and langgraph/pydantic-ai (graphs host agents; agents embed graphs) support both directions; crewai is flows-down-crews-up-only; openai-agents-sdk has no separate workflow abstraction at all.

## Practical Tips

- **Make the agent-tool indistinguishable from a function tool at the schema layer**, then flag it with provenance metadata for downstream consumers — you inherit validation, approvals, timeouts, and tracing wholesale (openai-agents-sdk `_is_agent_tool` + `ToolOrigin`; agent-framework's entire adapter family).
- **Collapse "unbounded" configurations to safe defaults silently** (`max_turns=None → 10`); it is one line that eliminates the worst misconfiguration class.
- **Give agents a soft signal before the hard wall**: expose remaining budget to the model so it can conclude gracefully instead of dying mid-plan (langgraph `RemainingSteps`).
- **Never let a child's failure crash the parent by default; never hide it either.** Return a structured envelope with an actionable `guidance` field (openhands), and offer an explicit escape hatch to reraise for callers who want fail-fast (openai-agents-sdk `failure_error_function=None`).
- **Claim side-effect identities before doing network work** if acknowledgments and execution happen in different processes — replay-safe composition is a transport problem, not a model problem (openhands `claimToolCall`).
- **Stamp provenance on everything a child emits into shared channels** (agent names on messages, origin metadata on items, prefix constants on protocol messages) so transcripts stay attributable without envelopes.
- **Test composition at depth ≥ 3 with serialization round-trips in between**; openai-agents-sdk's parametrized `nesting_edges` suite is the study's benchmark for this. Single-level tests miss routing, usage-rebinding, and resume bugs that only appear at depth (e.g., the cached-resume usage detachment fixed at `src/agents/agent.py:879-884`).
- **Fail closed on ambiguous nested identity** — when two pending nested invocations match one approval decision, raise rather than guess (openai-agents-sdk `tool_context.py:179-191`).
- **Report capability degradation honestly in results**: openhands' `parent_link: false` + explanatory note beats a silently missing relationship the agent will act on wrongly.
- **Add span-ancestry assertions to your eval suite** even without runtime guards; circular delegation is detectable in CI from traces alone (pydantic-ai).

## Anti-Patterns / Caution Signs

- **Delegation layers that cannot pass child-specific limits.** CrewAI's `_execute` accepts only `(agent_name, task, context)` — no timeout/budget/depth parameter survives the delegation boundary (`base_agent_tools.py:46-48`). If your delegation seam can't carry constraints, every child inherits whatever defaults its class happens to have.
- **Errors converted to prose strings with no typed residue.** Once exceptions become `"Error executing tool..."` text, evaluators and guardrails are blind (crewai). Caution sign: your failure-handling story requires parsing English.
- **Recursion defense consisting of prompt advice.** "Do NOT call this tool twice for the same task" is advisory, not enforced (openhands `launch-child-conversation-client-tool.ts:38`); children inheriting the launch/delegation tool with no depth counter means the tree grows until resources stop it. Any design whose last line of defense is a sentence in a tool description is brittle.
- **Best-effort global caps checked after the fact.** agent-framework checks `max_function_calls` after each parallel batch completes — overshoot up to full batch size is accepted by design (`_tools.py:1342-1351`). Caution sign: cost caps documented as approximations.
- **Silent feature loss at integration seams.** LangGraph's introspective subgraph detection "failing is silent" (`test_subgraph_detection.py:1-9`): missed subgraphs quietly lose checkpoint/stream integration. Any discovery-by-magic mechanism needs a loud diagnostic mode.
- **Concurrency hazards documented instead of prevented.** .NET's `AsAIFunction` warns about undefined behavior under concurrent use of a shared session rather than enforcing serialization (`AgentExtensions.cs:61-65`) — contrast Python's race-aware session clone (`_agents.py:684-692`).
- **Duplicate role/name resolution ambiguity.** CrewAI resolves coworker matches to `agent[0]` after sanitization, so two agents sharing a role silently collapse to one (`base_agent_tools.py:80-110`). Name-derived targeting needs collision policies (see openai-agents-sdk's derived-name `collision_policy="error"`).
- **Hidden protocol traffic invisible in transcripts.** OpenHands filters the `[child-conversation] ` result message from display (`should-render-event.ts:105-112`); debugging suffers when the JSON the agent acted on isn't in the visible history unless exported.
- **Attribution that depends on remembering a keyword.** If correctness of cost accounting hinges on developers passing `usage=ctx.usage` — and even the framework's own tools forget — expect silent under-counting in production (pydantic-ai).

## Notable Absences

Absences verified across all six reports:

- **No structural recursion or cycle guard for agent-as-tool anywhere.** Every report searched for depth counters, cycle detectors, or ancestor sets over composition graphs and found none; termination everywhere rests on per-level budgets plus model behavior (openai-agents-sdk Q4; langgraph Q4; pydantic-ai Q4; agent-framework Q4; crewai Q4; openhands Q4). The nearest neighbors are adjacent guards: crewai's event-stack depth cap (100) and flow-runtime `max_method_calls` `RecursionError`, langgraph's per-loop `GraphRecursionError` and `MULTIPLE_SUBGRAPHS` error, agent-framework's workflow self-loop *warnings*, and openai-agents-sdk's cycle-safe BFS over handoff graphs — which pointedly does not traverse agent tools.
- **No per-child cost attribution in any source.** Best cases are automatic aggregation into one shared counter (openai-agents-sdk), opt-in sharing (pydantic-ai), path-dependent merging (agent-framework workflow route only), or aggregate-after-the-fact sums (crewai). Nothing tags tokens to a specific delegation invocation.
- **No cross-level/tree-global budget anywhere** — every bound (turn counts, iteration caps, superstep limits, conversation iteration ceilings) restarts per nesting level or per conversation.
- **No typed output schema for agent tools** comparable to function tools' output validation; child outputs are strings to the parent model in five of six sources (langgraph's shared-state subgraphs being the partial exception).
- **Child trace identifiers rarely surface programmatically to parents** — ambient span/callback/contextvar hierarchies exist in four sources, but a parent cannot read "which child run produced this" from a result object; openhands has only a version-gated `parent_conversation_id`.
- **Workflow-as-tool is asymmetric or absent**: no reverse `Crew.as_tool()`/`Flow.as_tool()` in crewai; no workflow abstraction at all in openai-agents-sdk; openhands composes conversations, not declarative workflows.
- **Sync-node cancellability gap** in langgraph and **no cancellation propagation to delegated children** in crewai — cancellation maturity lags far behind flat tool calls in half the sources.

## Per-Source Notes

**openai-agents-sdk (8/10)** — The reference implementation for operational completeness: mandatory child turn bounds, interruptions routed across arbitrary nesting depth with serialization survival, deterministic cancellation on streaming and non-streaming paths, provenance persisted through RunState, and a scope-qualified process-local registry with weakref leak protection (`agent_tool_state.py:35-48, :131-142`). Deductions: no recursion guard, aggregate-only cost, in-process-only durability, no tool-guardrail parameters on `as_tool` (`docs/guardrails.md:65`).

**pydantic-ai (7/10)** — The primitives-first counterpoint: no wrapper, just `await child.run()` with the framework guaranteeing usage sharing, cancellation scoping, and OTel nesting. Unique contributions: isolation-by-default cancellation with binding hygiene (`take_run_binding` consumed once, `_cancel.py:285-293`), and the only cycle-detection story in the study (eval span ancestry queries). Deductions: opt-in attribution skipped even by first-party tools, child limit inheritance absent, durable-execution attribution structurally broken (#6886).

**langgraph (7/10)** — The uniform-substrate play with the strongest bounding story: hard `GraphRecursionError` plus soft `RemainingSteps` degradation, validated limits, durable interrupts resuming across subgraph boundaries, and the only upward-control primitive (`Command.PARENT`). Deductions: budgets restart per level (~depth × limit worst case), introspective subgraph discovery fails silently, no core cost attribution, and the flagship prebuilt agent factory is deprecated toward an out-of-repo API.

**agent-framework (7/10)** — The widest adapter surface: agent→tool (Python + .NET), workflow→agent→tool, agent→MCP-server, A2A skills→tools, with kwargs verbatim forwarding proven through A→B→C chains (`test_as_tool_kwargs_propagation.py:111`) and race-aware session cloning. Deductions: the primary boundaries discard usage and structure (text-only), cumulative call caps default unlimited and enforce late, no depth guard beyond advisory workflow self-loop warnings.

**openhands (7/10)** — The application-layer outlier proving composition semantics can live client-side: JSON-schema'd browser-executed launch tool, replay-idempotency ledger, bounded cloud polling (180 s), corrective-guidance envelopes, version-gated honesty, and worktree/shared isolation with graceful downgrade. Deductions: recursion prevented only by prose, child costs invisible, no trace IDs beyond parent links, and subagent execution internals live outside the audited boundary.

**crewai (6/10)** — Domain-shaped delegation: roster-interpolated delegation tools with LLM-defensive role normalization, manager exclusivity structurally enforced, ambient event-parent-chain tracing capped at depth 100, and the loudest recursion guard in the study (flow `RecursionError` naming the self-listening footgun). Deductions: plain-string results with swallowed exceptions, aggregate-only costs, no delegation-cycle detection, no way to pass child-scoped limits, and one-directional workflow composition.
