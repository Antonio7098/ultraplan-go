## Executive Summary

The five sources span the full design spectrum for compressing long histories into summaries. At one end, **langgraph** ships no summarization at all — only precise, tested substrate primitives (`RemoveMessage`, the `REMOVE_ALL_MESSAGES` atomic-replace sentinel, a sanctioned `pre_model_hook` seam) with all policy delegated to user code. **openhands** is a thin frontend that owns configuration, manual triggering, and observation of a server-side condenser it cannot inspect. **crewai** runs two unconnected mechanisms: destructive reactive conversation summarization plus durable statement-level memory extraction. At the other end, **agent-framework** and **letta** are full in-process compaction engines — pluggable strategies with layered triggers, failure rollback/fallback chains, and provenance-bearing summary records.

Three findings dominate. First, every source converges on separating *what the model sees* from *what is stored*: compression is a projection, not an erasure, in four of five sources (crewai's conversation path is the lone destructive outlier). Second, no source evaluates whether its summaries actually preserve decisions, facts, or uncertainty — drift detection is structural or mechanical everywhere, making prompt-mandated coverage sections the entire quality mechanism industry-wide. Third, token math is heuristic in every implementation that estimates it (chars/4, bytes/4 × 1.3 safety margins), and trigger models range from proactive thresholds (letta's 90% rule) to purely reactive exception handling (crewai) to none (langgraph).

## Core Thesis

Mature memory compression is fundamentally an exercise in keeping raw history immutable and treating summaries as projections that carry their own provenance. Every source that retains raw history alongside compressed views gains the ability to audit, compensate for, or eventually regenerate what was lost; the one source that destructively clears conversation history (crewai) permanently forfeits verification, diffing, and regeneration, and survives only because a parallel SQLite store happens to retain raw task outputs. Yet even the most mature engines stop at structural guarantees: across all five sources there is no semantic evaluation of summary fidelity anywhere — the answer to "does compression preserve decisions, facts, and uncertainty?" is "only because the prompts ask for it."

## Approach Models

**agent-framework — strategy-pluggable compaction over annotated groups.** Messages are partitioned into atomic groups (system / user / assistant-text / tool-call, including non-contiguous call/result pairs via union-find), strategies annotate groups with `_excluded` flags rather than deleting them, and a projection step decides what the model sees (`python/packages/core/agent_framework/_compaction.py:200-325,705-737`). LLM `SummarizationStrategy` is one composable strategy among deterministic ones (`ToolResultCompactionStrategy`, truncation), strictly opt-in with an explicitly-injected summarizer client (`_compaction.py:1197`). The same model exists in .NET with predicate-driven triggers and transactional rollback (`dotnet/src/Microsoft.Agents.AI/Compaction/SummarizationCompactionStrategy.cs:48`).

**crewai — dual-layer split: lossy live loop vs. durable store.** Conversation compaction fires reactively after a context-length exception and replaces the non-system message list with one `<summary>` user message in place (`lib/crewai/src/crewai/utilities/agent_utils.py:1069-1131`). Separately, after each task, an extractor distills discrete memory statements into vector/SQL stores with dedup and LLM consolidation (`lib/crewai/src/crewai/memory/encoding_flow.py:75-110`). The two layers share no code paths and never reconcile.

**langgraph — mechanics without policy.** The reducer `add_messages` supports overwrite, tombstone delete, and wipe-and-replace via `REMOVE_ALL_MESSAGES`; `pre_model_hook` documents exactly where a summary should be written, transiently (`llm_input_messages`) or durably (`libs/langgraph/langgraph/graph/message.py:206-213`; `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:396-424`). Retention lives at the storage layer (`prune`, thread TTLs). Summarization how-tos were deliberately redirected out of the repo (`docs/redirects.json:23-25`).

**letta — productized summarizer service.** A dedicated `letta/services/summarizer/` package with four config-declared modes behind `CompactionSettings`, triggered three ways (reactive on `ContextWindowExceededError` with ≤3 retries, proactive at 90% of context window post-step, manual REST endpoint), producing persisted `MessageRole.summary` records whose packed JSON embeds machine-readable `CompactionStats` (`letta/agents/letta_agent_v3.py:1218-1294,1438-1474`; `letta/system.py:207-238`).

**openhands — observation-only thin client.** All compression intelligence is server-side. The frontend persists condenser settings, offers a guarded manual `/condense` trigger, and classifies outcomes (`compacted` / `no_change` / `timeout`) by correlating a typed `Condensation` event against a live drop in `per_turn_token` metrics (`src/hooks/use-await-context-compaction.ts:6-37,96-110`). The summary text itself is never rendered or consumed (`src/components/conversation-events/chat/event-content-helpers/should-render-event.ts:139-145`).

These four models cluster into two archetypes worth naming: **engine-in-the-harness** (agent-framework, letta — and crewai's reactive half) versus **separated concerns** (langgraph substrate, openhands client/server split, crewai's extraction half). The engine archetype optimizes for autonomous correctness under failure; the separated archetype optimizes for composability and clean product boundaries, at the cost of nobody owning end-to-end summary quality.

## Pattern Catalog

### 1. View/storage separation — compression as projection, not deletion

- **Problem:** Summaries must shrink model input without destroying the evidence they were derived from.
- **Demonstrated by:** agent-framework (exclusion-as-annotation; excluded messages kept in storage so annotations survive reload — `python/packages/core/agent_framework/_compaction.py:1619-1621`), letta (compaction rewrites only the in-context ID list via `_checkpoint_messages`; zero delete calls in the summarizer package — `letta/agents/letta_agent_v3.py:758-816`), langgraph (transient `llm_input_messages` leaves stored state untouched — tested at `libs/prebuilt/tests/test_react_agent.py:1924-1954`), openhands ("removed from the View given to the LLM" while the UI transcript stays whole — `src/types/agent-server/core/events/condensation-event.ts:13-16`).
- **Why it works:** Every downstream capability — auditing, drift compensation, regeneration, recall tooling — becomes possible later, because the inputs still exist.
- **When to copy:** Always, unless storage cost is truly prohibitive. This is the strongest convergence in the study.
- **When risky:** Unbounded transcript growth (all four note monotonic storage growth); mitigate with retention/TTL policies as langgraph does at the checkpoint layer (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:374-415`).
- **Contrast:** crewai's `messages.clear()` destroys the raw side for conversations (`agent_utils.py:1121-1131`) — the study's clearest negative demonstration.

### 2. Provenance links between summaries and their source spans

- **Problem:** A summary that can't be traced to what it replaced is unauditable and unrecoverable.
- **Demonstrated by:** agent-framework's bidirectional ID links (forward `SUMMARY_OF_MESSAGE_IDS_KEY`/`SUMMARY_OF_GROUP_IDS_KEY`, backward `SUMMARIZED_BY_SUMMARY_ID_KEY`, asserted by tests — `python/packages/core/agent_framework/_compaction.py:35-37,1373-1392`). Partial forms elsewhere: letta embeds `CompactionStats` (trigger, tokens/messages before/after) inside the summary JSON itself (`letta/schemas/letta_message.py:406-420`); openhands' wire contract declares `forgotten_event_ids` + `summary_offset` (`condensation-event.ts:13-26`) — though its frontend parses and discards them.
- **Why it works:** Drift becomes auditable-by-construction: you can always reconstruct which raw content a summary stands for, which is the precondition for any future evaluation.
- **When to copy:** Any system where summaries feed long-running agents or where compliance/debugging matters.
- **When overkill:** Short-lived sessions where the summary dies with the process.
- **Evidence gap:** .NET agent-framework carries only an `_is_summary` marker, weakening drift auditing relative to its own Python twin (`dotnet/src/Microsoft.Agents.AI/Compaction/CompactionMessageGroup.cs:40`).

### 3. Atomic compression units — never split what the API contract joins

- **Problem:** Naive truncation breaks tool-call pairing, approvals, and system prompts, producing invalid provider requests.
- **Demonstrated by:** agent-framework unions function-call declarations with possibly distant results into one group id (`python/packages/core/agent_framework/_compaction.py:105-122,150-198`); letta walks every eviction cutoff back to assistant/approval boundaries and never evicts pending approvals (`letta/services/summarizer/self_summarizer.py:265-289`); langgraph validates tool-call integrity after any history rewrite (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:243,651`); crewai preserves attached files through summarization by re-attachment (`agent_utils.py:1069-1072,1129-1130`).
- **Why it works:** Structural validity is checkable; semantic fidelity is not. These harnesses enforce what can be enforced.
- **When to copy:** Universally — this is table stakes, and it appears in some form in five of five sources.

### 4. Layered triggers: proactive estimate + reactive recovery + manual escape hatch

- **Problem:** Context overflow must be prevented cheaply but also survived when prevention fails.
- **Demonstrated by:** letta implements the complete trio — post-step estimate against 90% of window, retry loop on `ContextWindowExceededError`, and `POST /v1/agents/{id}/summarize` (`letta/agents/letta_agent_v3.py:1438-1474,1218-1294`; `letta/server/rest_api/routers/v1/agents.py:2430`). agent-framework layers three execution sites (per-model-call, pre-run, post-turn) with mid-loop deferral (`python/packages/core/agent_framework/_clients.py:366-394`; `_compaction.py:1534`). openhands adds the manual surface with progressive urgency (primary CTA past 70% fill). Contrasts: crewai is reactive-only — the token estimator exists solely to chunk work *after* the first failing call (`lite_agent.py:999-1011`), costing one wasted round-trip per overflow episode; langgraph has no trigger concept at all.
- **Why it works:** Each layer covers another's failure mode; the manual path doubles as an operations tool.
- **When to copy:** Any long-running harness. The proactive threshold needs a conservative margin (letta's multiplier rationale and GPT-5 special case are documented at `letta/services/summarizer/thresholds.py:27-41`).

### 5. Observability embedded in the artifact vs. measured externally

- **Problem:** Operators need to know compression happened, how much it saved, and whether it's degrading.
- **Demonstrated by:** Three distinct schools. letta packs stats *into* the record so they travel wherever the message goes (`letta/system.py:207-238`). .NET agent-framework emits OTel spans with before/after tags per operation (`dotnet/src/Microsoft.Agents.AI/Compaction/CompactionTelemetry.cs:20-44`). openhands infers success externally from metric movement with a race-aware pre-request baseline (`src/hooks/use-compact-context-action.ts:85-88`). Python agent-framework logs only — the study's weakest operational story for otherwise strong code.
- **Why it works:** Embedded stats survive export; spans aggregate well; external measurement works across trust boundaries where neither of the others is visible.
- **When to copy:** Pick by boundary: in-process → artifact or span; cross-process/client-server → event-plus-proxy.

### 6. Failure philosophies: no-mutation, rollback, fail-open, fallback chains

- **Problem:** The summarizer is itself an LLM call that can fail — and a failed compaction must not corrupt state.
- **Demonstrated by:** Four distinct answers, all defensible. Python agent-framework performs zero mutation until text returns (`_compaction.py:1367-1395`) with a consecutive-failure escalation ladder; .NET marks up front then rolls back in a catch block (`SummarizationCompactionStrategy.cs:196-208`); letta runs mode fallback chains (self → sliding → all), provider fallbacks (Anthropic→Bedrock Opus), and payload shrinking before finally logging critical and continuing rather than bricking the agent (`letta/services/summarizer/compact.py:192-255,350-412`; `summarizer.py:714-816`); crewai fails open — extraction failure stores the entire raw blob rather than nothing (`memory/analyze.py:191-197`).
- **Why it works:** All four preserve the invariant "a failed compression leaves the system valid," differing only in whether the safe state is untouched, restored, degraded, or bloated.
- **When to copy:** Prefer no-mutation/rollback for shared state; fail-open only when the raw content is small enough to afford storing verbatim.

### 7. Sentinel-based atomic replacement as a reducer primitive

- **Problem:** Swapping N messages for one summary must be crash-safe and expressible in an append-oriented state model.
- **Demonstrated by:** langgraph's `REMOVE_ALL_MESSAGES` sentinel turns list removal into replace-all inside the existing reducer, with unknown-ID deletes raising loudly (`libs/langgraph/langgraph/graph/message.py:38,209-213,227-230`). Notably, the batch delta variant does *not* support it (`message.py:260-262`) — an intra-source asymmetry showing how easy this primitive is to forget in secondary code paths.
- **When to copy:** In any event-sourced or reducer-based state system needing durable rewrites.

### 8. Structured summary contracts with graceful parsing fallbacks

- **Problem:** LLM output must become a reliable artifact.
- **Demonstrated by:** crewai extracts `<summary>` tags via regex with full-text fallback and pydantic models with dual JSON/function-calling parse paths (`agent_utils.py:995-1009`; `memory/analyze.py:178-190`); letta mandates fixed sections (goals, what happened, errors/fixes, verbatim identifiers, next steps, lookup hints) per mode (`letta/prompts/summarizer_prompt.py:4-97`); agent-framework constrains to ≤5 sentences incorporating any prior summary (`_compaction.py:1176-1191`).
- **When to copy:** Fixed sections beat free-form prose when downstream consumers (or future summaries) must find specific content; always pair with a fallback parse path, as crewai does.

## Key Differences

**Trigger philosophy.** letta compacts proactively at 90% because observed runs hit hard errors near the window (`thresholds.py:27-40`); crewai deliberately waits for the provider exception and string-matches it (`is_context_length_exceeded`, `agent_utils.py:781-792`) — accepting one wasted failing call per episode and total bypass on providers with unhelpful errors; agent-framework's default summarization trigger counts messages, not tokens, so a few huge messages can overflow long before it trips (`_compaction.py:1223-1241`); openhands pushes the decision to the user via meter color and button urgency; langgraph refuses to have an opinion. This is maturity-driven divergence: letta's ops experience (product with many providers) produced the most defensive posture, while crewai's reactive stance reflects a framework minimizing assumptions about provider error surfaces.

**Replacement semantics.** agent-framework annotates and projects; letta swaps pointers; langgraph makes destruction explicit and loud; crewai clears in place; openhands never touches history at all. The dividing line is who owns durable truth: systems with a real session store (agent-framework, letta, langgraph checkpoints, openhands server) can afford non-destructive compression; crewai's in-memory message list has no durable backing for conversations, so its compression is necessarily destructive — the constraint shaped the design, not carelessness alone.

**What gets summarized.** agent-framework summarizes whole oldest atomic groups bounded by an 8,000-token input budget, skipping oversized groups verbatim (`_compaction.py:1138-1173`); letta's sliding window escalates eviction percentage until a token goal is met, anchored at assistant boundaries (`summarizer_sliding_window.py:144-198`); crewai chunk-parallelizes map-reduce style with `[Part i/n]` splitting for oversized messages (`agent_utils.py:867-992`). Same problem, three budget models: bounded-input, iterative-until-fit, and parallel-map.

**Who may summarize.** letta defaults to cheap delegated models (Haiku/GPT-5-mini/Gemini Flash seeded at agent creation — `letta/services/agent_manager.py:495-513`) or self-summarization for cache compatibility; agent-framework requires the caller to inject an explicitly trusted client and documents persistent injection risk in three places (`_compaction.py:1207-1216`); openhands hides the choice entirely behind one server-side setting. Delegating to a smaller model trades fidelity for cost — a decision letta makes configurable and openhands makes invisible.

**Transparency to humans.** openhands deliberately suppresses summaries from the chat stream — users see toasts and a meter, never the summary (`should-render-event.ts:139-145`); letta yields a client-visible compaction event and exposes stats through its API (`letta_agent_v3.py:818-851`); agent-framework samples print trace-link metadata in expected output. Product shape drove this: openhands optimizes a consumer UX, letta optimizes an operator platform.

## Tradeoffs

- **Durability vs. storage growth.** Keeping raw history plus annotations means stores grow monotonically even as model input stays bounded (agent-framework `_compaction.py:1619-1621`; letta pointer-swap model; langgraph append-only default). Auditability is bought with bytes; langgraph shows the mitigation (TTL/prune at the storage layer) and also its hazard (naive pruning silently severs delta reconstruction — `base/__init__.py:397-401`).
- **Proactive vs. reactive triggering.** letta pays a token count per step to avoid hard failures; crewai saves that cost and pays a failed provider round-trip per overflow instead. Best-fit depends on how expensive and how informative your provider's errors are.
- **Cheap-model delegation vs. fidelity.** letta's word caps (300/500) plus lightweight default models make summarization inexpensive but mean preserved decisions depend on a weaker model than the one doing the work (`summarizer_config.py:25-32`). agent-framework avoids the default entirely by requiring explicit opt-in.
- **Transparency vs. clean UX.** openhands hides summaries, sacrificing auditability for a tidy chat (`should-render-event.ts:143-145` vs. the rich unused payload at `condensation-event.ts:16-26`); letta/agent-framework expose machinery at the cost of complexity in client APIs.
- **Token-proxy verification vs. fidelity verification.** openhands' `per_turn_token`-drop test is cheap, robust, and measures exactly the wrong thing — a lossy summary saving many tokens scores identically to a faithful one, and a faithful no-op reports `no_change` (`use-await-context-compaction.ts:105-110`).
- **Heuristic token counting vs. provider independence.** chars/4 (agent-framework `CharacterEstimatorTokenizer`, crewai) and bytes/4 × 1.3 (letta) miscount CJK and JSON-heavy payloads; all three accept this rather than depend on a tokenizer library, with letta documenting the underestimate risk explicitly (`summarizer_sliding_window.py:21-24`).
- **Dual implementations vs. focused maintenance.** letta runs legacy + V3 summarizers with acknowledged deprecation debt (`settings.py:88-91`); agent-framework's Python/.NET twins diverge behaviorally (empty summarizer output: Python skips, .NET inserts `[Summary unavailable]`). Both pay coordination costs for coverage of different runtimes/user bases.

## Decision Guide

Choose your approach model by role:

- **You are building a harness/engine with durable session storage:** adopt annotation/projection over immutable history with bidirectional provenance links (agent-framework model), layered triggers (letta's trio), and mark-after-success or rollback failure semantics.
- **You are building a product/platform where transcripts are the product:** adopt eviction-pointer compaction with typed summary records and embedded stats (letta model); add a manual endpoint from day one — it is simultaneously a user feature, an ops tool, and a test harness.
- **You are building a framework library, not an application:** ship tested primitives plus one documented seam (langgraph model), and consider an optional built-in summarization node as the highest-leverage future addition — the seam already suffices as its interface.
- **You are a client of a remote agent server:** define a typed condensation event contract with coverage fields, guard manual triggers against races with pre-request baselines, and classify outcomes honestly (openhands model) — then push for read access to summaries, because token proxies cannot tell you what was lost.
- **You have no durable store behind conversations:** do not copy crewai's destructive clear blindly; first add a raw-output sink (as crewai did for task outputs in SQLite), then compress. If you must compress destructively, mandate verbatim-preservation sections in the prompt and accept that regeneration is impossible.

If forced to choose between investing in triggers, provenance, or evaluation: provenance first (it enables everything else), triggers second (they prevent the failures users see), evaluation third (nobody has it, so it is also your differentiator).

## Practical Tips

- **Separate view from state as two named concepts**, like langgraph's `llm_input_messages` vs `messages` or openhands' "LLM View" vs transcript. Teams that conflate them ship accidental data loss.
- **Make destructive edits loud.** Require exact IDs or an explicit sentinel; raise on unknown targets (langgraph `message.py:227-230`). There should be no silent truncation API.
- **Protect structural invariants mechanically, not by convention:** tool-call grouping, assistant-boundary cutoffs, system-message immunity, pending-approval retention. Every source enforces some of these; letta and agent-framework enforce the most.
- **Bound the summarizer's input, not just the output.** agent-framework's whole-group selection under an 8,000-token cap with skip-on-oversize (`_compaction.py:1138-1173`) and letta's clamp-then-middle-truncate ladder (`summarizer.py:564-647`) both prevent the compressor from becoming the thing that overflows.
- **Write recursive-refresh clauses into summary prompts** ("if a previous summary is being evicted, extract its critical info" — `summarizer_prompt.py:9`; "never omit earlier-summary details" — `_compaction.py:1190`). Rolling re-summarization otherwise silently drops old context.
- **Embed stats in the summary artifact** so observability survives export (letta's `CompactionStats`), and tag summarizer LLM calls separately in usage accounting (openhands treats `"condenser"` as its own usage id).
- **Defer persisted-history rewrites until the turn ends** if a function loop iterates the same list (agent-framework's `after_run_once_per_turn` and issue #4991 fix — `_compaction.py:1532-1534`).
- **Use anti-continuation guards when asking a model to summarize its own transcript:** a synthetic assistant turn prevents the LLM from answering instead of summarizing (`self_summarizer.py:67-79`).
- **Test the boring edges:** empty summarizer output, unsummarizable oversized groups, late-arriving tool results, fast-condensation races, and "still over threshold after fallback." Each appears as a pinned regression test in at least one source.

## Anti-Patterns / Caution Signs

- **Destructive in-place clearing with no retained raw corpus.** crewai forfeits verification, diffing, and regeneration for conversations (`messages.clear()`, `agent_utils.py:1121-1131`). If you cannot answer "what exactly did this summary replace?", treat that as a defect.
- **Coverage fields parsed but unused.** openhands reads only the event `kind` while `forgotten_event_ids`/`summary` go unconsumed (`type-guards.ts:286-289`) — dead contracts breed false confidence.
- **Contradictory configuration semantics across surfaces.** openhands' tooltip says events ("Minimum 20"), the schema says tokens; three artifacts disagree (`translation.json:2111` vs `mocks/settings-handlers.ts:332-333`). Caution sign that ownership of the dimension is split.
- **Duplicated protection logic.** letta's approval-protection invariant exists independently in three files (`self_summarizer.py:265-289`, `summarizer_all.py:41-61`, `summarizer.py:295-304`) — divergence would create inconsistent eviction behavior.
- **Two coexisting compression generations.** letta's legacy/v3 split and agent-framework's cross-language behavioral divergences show how quickly compression accumulates debt, because old summaries and new ones interleave in stored history.
- **Fire-and-forget compression with log-only failure.** letta's voice/static-buffer background tasks and crewai's shutdown-race abandonment lose data silently (`summarizer.py:124-134`; `unified_memory.py:641-650`).
- **Count-based triggers guarding token-sized problems.** agent-framework's default message-count trigger can be defeated by a few huge messages (`_compaction.py:1223-1241`); langgraph's `remaining_steps` looks like a budget but bounds iterations, not tokens (`chat_agent_executor.py:434-440`).
- **Silent reconstruction failures after retention operations.** langgraph's naive prune makes channels reconstruct as empty with no error (`base/__init__.py:397-401`) — the most dangerous documented mode in the study.
- **Magic-number thresholds scattered across modules.** letta's TODO calling for centralization (`thresholds.py:17-19`) is the honest marker; the unmarked equivalent is worse.

## Notable Absences

- **Semantic summary evaluation — absent in all five sources.** Each report explicitly searched for it and found nothing: agent-framework ("no automated evaluation of summary fidelity... searches returned nothing"), crewai (an evaluation framework directory exists but scores nothing about compression), letta ("no offline/eval harness measuring summary quality"), langgraph (nothing to evaluate), openhands (token proxy only). This is the dimension's universal gap.
- **Uncertainty preservation — absent everywhere.** No source tracks open questions or confidence in summaries. agent-framework's prompt bans speculation outright (`_compaction.py:1186-1189`); the nearest approximations are letta's "Lookup hints" sections and crewai's recall-side `evidence_gaps` (`memory/types.py:87-90`) — both retrieval aids, not uncertainty records.
- **Regeneration spanning evicted ranges.** Raw retention makes regeneration feasible in principle (agent-framework notes it needs no schema change), yet no source implements it: letta's `/summarize` fetches only currently in-context messages (`agents.py:2445`); agent-framework found no regenerate API; openhands has no targeted regeneration; crewai's cleared conversations cannot be regenerated at all.
- **Real tokenizers by default.** Every estimating source uses character/byte heuristics; real-tokenizer support exists only as pluggable extras (agent-framework's tiktoken sample).
- **Multimodal-aware summarizer input.** agent-framework collapses non-text contents to type names in the summarizer transcript (`:1126-1127`); letta renders `[N images omitted]`. Image/tool-schema information silently vanishes from summaries in both.

## Per-Source Notes

- **agent-framework (8):** Most rigorous compression core: atomic group model with union-find tool pairing, exclusion-as-annotation, bidirectional trace links, ~110 tests including issue-pinned regressions (#4991, #7011). Held back by absent evaluation/regeneration, log-only Python observability, and `.NET [Experimental]` status.
- **crewai (7):** Excellent fail-open engineering on the memory-extraction side (safe defaults, save-failure events, drain barriers, consolidation) undermined by a destructive, coverage-free conversation summarizer and purely reactive triggering. Its two layers never share truth.
- **langgraph (4):** Nothing automatic, by documented design; the substrate (`REMOVE_ALL_MESSAGES`, tombstones, prune doctrine, conformance suites) is precisely specified and tested, and the `pre_model_hook` seam is the canonical extension point. Rated down because the dimension's substance — triggers, prompts, coverage, refresh — simply is not here.
- **letta (8):** The most operationally mature pipeline: three coordinated trigger paths, four modes with fallback chains, provider rerouting, payload shrinking, protected approvals, embedded `CompactionStats`, and a regression test for summarization loops. Debt: dual summarizer generations and scattered magic numbers.
- **openhands (5):** A disciplined observation layer — typed contracts, race-safe baselining, honest outcome taxonomy — wrapped around a condenser it cannot show. The score reflects the boundary: within this repo, the dimension's substance is unverifiable, and the one available success signal (token drop) measures savings, not preservation.

## Open Questions

- **Would fact-recall probes against linked raw spans close the evaluation gap?** agent-framework's ID graph and crewai's raw task-output store both make spot-check harnesses feasible today; no source has built one, so the cheapest viable drift metric remains unknown.
- **Does uncertainty-preserving summarization help downstream performance?** No source records open questions/confidence, so there is no evidence either way — only the consistent absence.
- **How do chained summaries compose over very long horizons?** agent-framework demonstrates second-round accretion in samples; openhands' `summary_offset` implies insertion positions with no composition logic; letta's recursive clause handles one level. Nobody shows evidence of ten-generation summary chains retaining critical detail.
