## Executive Summary

Ten repositories — four agent frameworks, an observability platform, a policy engine, a durable-execution server, and a frontend application — were assessed on whether they teach contributors how to add agents, tools, evals, memory, tracing, and policies safely. Scores span 5–9 (mean ≈ 7.4; median 8). Three findings dominate.

First, **AI-agent contributor surfaces are now universal**: all ten sources maintain `AGENTS.md`-family instruction files, skills libraries, or automated review bots alongside human guides (e.g., langfuse's CI-validated `.agents/` hierarchy citing `.agents/README.md:147-160`; temporal's parallel `CONTRIBUTING.md` / `AGENTS.md` / `.github/copilot-instructions.md` stack). The interesting variation is no longer presence but *maintenance*: langfuse validates guide paths in CI, while letta and temporal show the drift that happens without such checks.

Second, **the strongest score predictor is whether documentation code actually executes**. pydantic-ai (9) runs every code fence in CI (`tests/test_examples.py:109`); opa evaluates its doc examples against a real binary (`docs/bin/eval-examples.sh:12-57`); agent-framework re-runs ~740 samples daily; openai-agents-sdk ships a purpose-built example runner. The three lowest scorers — letta (5), langgraph (6), openhands (6) — ship zero or one runnable in-repo example after deleting or archiving their example trees.

Third, **every observed documentation failure sits at an externalization or duplication seam**: dangling build tasks pointing at out-of-repo docs (agent-framework), orphaned nav pages (crewai), stale paths left from a monorepo exit (letta), archived stub notebooks (langgraph), and unverifiable cross-repo claims everywhere. No source escapes this pattern; the best ones convert it into CI failures rather than silent rot.

## Core Thesis

Contributor enablement in mature agent-infrastructure repositories has shifted from "write a good CONTRIBUTING.md" to **operating documentation as a tested, multi-audience system whose artifacts are generated from source and verified by CI**. Repositories that treat docs as build artifacts — executed snippets (pydantic-ai), generated references (opa, langfuse, letta, mkdocstrings users), drift gates (gen-check, schema-diff, agentic drift detectors) — score 8–9 regardless of whether teaching material lives in-repo or in sibling properties. Repositories where documentation is prose adjacent to code, or where teaching material was delegated outward without mechanical linkage, score 5–6 even when individual pieces are excellent. The remaining frontier is not more prose: it is closing the seams — starter/template projects and evals are the two most commonly missing pieces across all ten sources, and no source measures actual newcomer success instead of inferring it from documentation completeness.

## Approach Models

Clustering the ten sources by how they solve "teach contributors to extend safely" yields four models plus one transversal practice.

### Model A: Docs-as-curriculum (examples are part of the product)

**Sources:** agent-framework, openai-agents-sdk, partially pydantic-ai and opa.

Samples are organized as numbered curricula with strictly increasing complexity and a one-concept-per-file rule: agent-framework's seven-step get-started table from hello-agent to graph workflows (`python/samples/01-get-started/README.md:18-27`) mirrored identically across Python and .NET; openai-agents-sdk's annotated catalog linking all 216 example files (`docs/examples.md:5-133`). This model treats the example corpus as a maintained product surface: agent-framework type-checks samples (`python/samples/SAMPLE_GUIDELINES.md:111-115`) and re-executes them on a schedule (`.github/workflows/python-sample-validation.yml:47-60`); openai-agents-sdk runs them through a discovery-based runner with per-example logs (`examples/run_examples.py:1-10`). It fits frameworks whose users learn by copying runnable code; its cost is maintenance scale, which both sources offset with generation and automation.

### Model B: Docs-as-tested-artifacts (guides become build outputs)

**Sources:** pydantic-ai, langfuse, opa, and increasingly agent-framework.

Documentation itself is under test. pydantic-ai harvests and executes every fenced code block from README/docs/packages against mocked models (`tests/test_examples.py:109`, `231-392`), enforces README↔docs parity (`tests/test_docs_parity.py:49-59`), and files issues via a scheduled docs-drift detector (`.github/workflows/pydantic-ai-docs-drift.lock.yml:26`). langfuse validates every path cited by its `AGENTS.md` hierarchy and fails CI on broken shims (`package.json:11-12`; `.agents/README.md:151-160`). opa stores interactive examples as executable fixtures evaluated by script with generation-drift gating (`docs/bin/eval-examples.sh:12-57`; `docs/Makefile:68-74`). This model converts documentation rot from a review-time concern into a build failure and produced the two highest scores in the study.

### Model C: Externalized teaching material (repo = mechanics, site = pedagogy)

**Sources:** langgraph, letta, temporal, langfuse, openhands; crewai for examples specifically.

User-facing tutorials, examples, or API references deliberately live elsewhere: langgraph redirects its entire `docs/` tree to docs.langchain.com and marks `examples/` as archival (`examples/README.md:3`; `docs/generate_redirects.py:20`); letta deleted its example tree outright ("chore: remove old examples (#6255)" per git history, leaving only data files at `examples/notebooks/data/task_queue_system_prompt.txt:1`); temporal delegates samples to six SDK repos (`CONTRIBUTING.md:167`) while keeping extension-authoring contracts in-tree; openhands routes skill/tool/eval authoring to sibling repos via a placement table (`AGENTS.md:22-41`); crewai keeps the docs site in-repo but hosts all runnable examples in separate repos (`docs/edge/en/examples/example.mdx:8-60`). The model keeps repos lean and lets docs iterate independently, but severs the version-coupling and verification loop — a tradeoff every adopting source names explicitly.

### Model D: Contract-first extension teaching (validators over narratives)

**Sources:** temporal, opa, langgraph, crewai.

Extension authoring is taught through interface contracts bound to concrete artifacts rather than narrative tutorials: temporal's archiver guide walks declare→implement→register→configure with a retry/error FAQ (`common/archiver/README.md:13-84,199-250`); opa's built-in-function tutorial binds each of five steps to exact files and shows each verification command (`docs/docs/contrib-adding-builtin-functions.md:16-187`); langgraph teaches checkpointer correctness by shipping a conformance suite — "here is the validator" instead of "here are the rules" (`libs/checkpoint-conformance/README.md:19-45`); crewai anchors every "extend X" tutorial to the exact base class mirrored in code (`create-custom-tools.mdx:31-39` ↔ `base_tool.py:103`).

### Transversal practice: dual human/AI audiences

All ten sources write contributor guidance twice — once for humans, once for AI coding agents — in varying shapes: duplicated CLAUDE.md mirrors (langgraph `CLAUDE.md:1-57`; openai-agents-sdk), symlinked shim hierarchies validated in CI (langfuse), directory-scoped AGENTS.md trees (pydantic-ai lists 14), skills libraries with executable scripts (langfuse 35+ skills including validators; openai-agents-sdk 14 skills; agent-framework per-language `.github/skills/`), session hooks injecting rules (opa `.claude/settings.json:1-19`), and AI-contribution governance policies (letta `AI_POLICY.md:5-37` enforced by an auto-close bot; opa DCO-plus-AI rules; crewai `llm-generated` label requirement). Temporal goes furthest by making AI review a first-class CI citizen with a shared severity taxonomy for human and machine reviewers (`.github/copilot-instructions.md:120-129`).

## Pattern Catalog

### Pattern 1: Executed-documentation pipeline

- **Problem:** Prose tutorials and snippet rot silently as APIs evolve; readers copy broken code.
- **Demonstrated by:** pydantic-ai (every fence executed, `tests/test_examples.py:231-392`); opa (fixtures evaluated by real engine, `docs/bin/eval-examples.sh:26-52`); agent-framework (samples type-checked + scheduled live re-validation, `.github/workflows/dotnet-verify-samples.yml:1-24`); openai-agents-sdk (manual runner, `Makefile:101-123`).
- **Why it works:** It makes "the docs still work" a monitored property instead of an aspiration; failures surface at PR time with a failing test rather than months later as user reports.
- **When to copy:** Whenever docs teach code that can run deterministically. pydantic-ai's supporting tricks matter: declarative fence opt-outs for genuinely non-runnable cases, `requires=` stitching for multi-step examples, mocked model inference for keyless execution (`tests/test_examples.py:241-258,340-346`).
- **When it is overkill/risky:** When examples require live credentials or services — the mock harness becomes its own maintenance burden (pydantic-ai carries ~260 lines of prompt→response scripting, `tests/test_examples.py:475-738`), and skip annotations create silent escape hatches if unconstrained.
- **Evidence strength:** Direct, from four independent implementations with consistent outcomes.

### Pattern 2: AI-agent instruction hierarchy with CI validation

- **Problem:** Contributors (human and automated) need scoped context; unvalidated guidance decays invisibly.
- **Demonstrated by:** langfuse (root → package → feature guides with `agents:check` path validation, `.agents/README.md:147-160`); pydantic-ai (14 directory-scoped AGENTS.md files enumerated in root `AGENTS.md`); openai-agents-sdk (`.agents/references/README.md:31-48` maps "read before changing" boundaries); temporal (three coordinated surfaces).
- **Why it works:** Narrowest-scope placement keeps global invariants separate from local mechanics; CI validation turns stale guidance into red builds (langfuse) — the absence of such validation is exactly what produced letta's stale `apps/core` paths (`WEBHOOK_SETUP.md:180-194`) and temporal's acknowledged AGENTS-vs-Makefile drift risk.
- **When to copy:** Immediately, for any repo accepting AI-assisted contributions — this is now table stakes across all ten sources.
- **When it is overkill/risky:** Single-package repos don't need hierarchies; multiple overlapping copies without a single canonical file invite divergence (openai-agents-sdk explicitly flags AGENTS.md/CLAUDE.md/references overlap as a failure mode).
- **Evidence strength:** Universal adoption (10/10) makes the pattern claim robust; effectiveness comparisons rest on documented failure cases.

### Pattern 3: Tutorial-to-artifact anchoring ("tutorial with teeth")

- **Problem:** Tutorials that don't name exact files/interfaces leave contributors guessing where changes land.
- **Demonstrated by:** opa (each step names `ast/builtins.go`, YAML case dirs, `capabilities.json` plus its verify command, `contrib-adding-builtin-functions.md:16-187`); crewai (tutorial ↔ `BaseTool`/`BaseLLM`/`StorageBackend` anchors); temporal (seven-file RPC checklist, `docs/development/new-rpcs.md:1-16`); langfuse (four-step public-API playbook: route → contract → test → Fern regen, `web/AGENTS.md:258-264`).
- **Why it works:** Anchoring answers "can I build this?" from the document alone and makes the payoff visible (auto-generated reference entries, regenerated SDKs).
- **When to copy:** For any stable extension surface; this is the cheapest high-leverage documentation investment observed.
- **When it is risky:** Anchors decay during refactors — they need the drift-gate machinery of Pattern 5 or they become stale-path traps (letta's webhook tutorial).
- **Evidence strength:** Four independent sources; opa's litmus-test success (under-an-hour builtin) is attributed to it directly.

### Pattern 4: Teach-by-validator / conformance harness

- **Problem:** Extension authors must satisfy implicit behavioral contracts (round-trips, isolation, determinism) that prose describes poorly.
- **Demonstrated by:** langgraph's checkpointer conformance package (`libs/checkpoint-conformance/README.md:19-45`); openai-agents-sdk's `ScriptedModel` shipped inside the SDK (`src/agents/testing/model.py:249`); temporal's living test examples (`chasm/test_library_test.go:23-57`); langfuse's skills bundling executable validators (`add-model-price/scripts/validate-pricing-file.mjs`).
- **Why it works:** The validator encodes the full contract including edge cases prose forgets; passing it is proof, not assertion.
- **When to copy:** When an extension type has crisp invariants (storage backends, checkpointers, model doubles).
- **When it is overkill:** One-off extensions where writing the validator costs more than the extension.
- **Evidence strength:** Four sources; strongest where paired with Pattern 3.

### Pattern 5: Drift-gate machinery

- **Problem:** Regenerated artifacts (schemas, references, diagrams, translations) diverge from sources.
- **Demonstrated by:** opa's `make gen-check` rerunning generation and failing on dirty trees (`docs/Makefile:68-74`); langgraph regenerating `schema.json` and diffing (`.github/workflows/ci.yml:144-157`); temporal regenerating SVGs from d2 sources (`docs/Makefile:5-21`); pydantic-ai's scheduled agentic drift detector filing `[docs-drift]` issues (`.github/workflows/pydantic-ai-docs-drift.lock.yml:601-608`); crewai's broken-link CI (`.github/workflows/docs-broken-links.yml:64`).
- **Why it works:** Converts staleness into a mechanical failure mode; scales to artifact classes humans check poorly.
- **When to copy:** For anything derivable — opa states the principle directly: never hand-maintain what the binary knows (`main.go:31-36` go:generate suite).
- **Risky when:** Gates have escape hatches — opa's examples can skip output checks (`eval-examples.sh:18-23`) and agent-framework's validation jobs were quota-disabled mid-life (`.github/workflows/python-sample-validation.yml:62-64`), both silently degrading guarantees.
- **Evidence strength:** Six sources with converging designs.

### Pattern 6: Governance-as-automation for contributions

- **Problem:** Contribution policy stated in prose is inconsistently applied and easily ignored.
- **Demonstrated by:** langgraph's issue-link + assignment enforcement bot with race handling (`.github/workflows/require_issue_link.yml:226-441`); openhands' Python PR-description validator requiring Why/Summary/How-to-Test (`.github/scripts/check_pr_description.py:39`); letta's AI-disclosure bot closing violations (`.github/workflows/issue-guard.yml:158-168`); pydantic-ai auto-closing unlinked PRs (`.github/workflows/pr-guard.yml:178-205`); langfuse PR-title linting (`.github/workflows/validate-pr-title.yml:24-38`).
- **Why it works:** Rules become uniform and auditable; rationale can live in workflow comments next to enforcement.
- **Cost:** False positives and friction — langgraph's gate makes help-seeking structurally mandatory even for typo fixes; letta's disclosure bar raises first-contact cost.
- **When to copy:** High-traffic repos suffering noise; calibrate gate strength to actual PR volume, and exempt trivial/doc-only changes as pydantic-ai does.
- **Evidence strength:** Five sources; failure modes documented on both sides.

### Pattern 7: Scaffolding-as-onboarding

- **Problem:** First-project friction; blank-file paralysis for new extension authors.
- **Demonstrated by:** crewai's `crewai create crew|flow|tool|skill|template` generating working skeletons from embedded templates, including a pre-written AGENTS.md with a version-freshness protocol (`lib/cli/src/crewai_cli/cli.py:187-277`; `templates/AGENTS.md:8-20`); langgraph's `langgraph new` fetching three template repos (`libs/cli/langgraph_cli/templates.py:10-25`); agent-framework's declarative YAML agents as lightweight starters (`declarative-agents/agent-samples/`).
- **Why it works:** Turns "read five docs pages" into one command producing runnable code.
- **Risky when:** Templates fetch unpinned remote content — langgraph downloads ZIPs from `main` branches over plain HTTPS with reproducibility explicitly traded away (`templates.py:104-114`).
- **Evidence strength:** Three adopters; crewai is the cleanest in-repo implementation and among the top scorers on the litmus question.

## Key Differences

**Where examples live — the biggest fork.** agent-framework (~492 Python sample files, 248 .NET projects, counted via find), openai-agents-sdk (216 files), pydantic-ai, and opa keep substantial runnable material in-repo and back it with execution; letta (deleted), langgraph (archived to redirect stubs, `examples/tool-calling.ipynb` single-cell), temporal (SDK repos), openhands (n=1), and langfuse (external docs repo, `CONTRIBUTING.md:21`) externalize or remove it. The split tracks product shape more than quality: framework vendors treat examples as product marketing and onboarding; platform/server teams treat them as SDK-repo concerns; app teams scope them by repository boundary. Both sides contain 8s — what separates scores within each side is whether the chosen location has verification attached.

**How API references are produced.** Five mechanisms coexist: Fern spec-first pipelines (langfuse `fern/apis/**` + CI SDK regeneration; letta checked-in `fern/openapi.json` gated by `fern check`), mkdocstrings-from-source (openai-agents-sdk `mkdocs.yml:25-43` with stub generator; pydantic-ai `docs/api/*.md` directives), go:generate extraction from the binary (opa CLI reference and builtin metadata, `main.go:33`), external hosted references fed only by docstring discipline (langgraph reference.langchain.com; agent-framework Microsoft Learn — where the in-repo pipeline is broken, `.github/workflows/python-docs.yml:36-38`), and structural-only surfacing (openhands `.d.ts` emit + exports map, `package.json:206-248`). The generated approaches correlate with higher scores because they eliminate the hand-sync class of drift entirely; the external approaches inherit whatever discipline exists in repos outside study scope.

**Gate position in the contribution lifecycle.** Before-code gates: langgraph requires a maintainer-approved, assigned issue before any external PR survives (`require_issue_link.yml:365-441`); pydantic-ai routes features through a champion model (`CONTRIBUTING.md:32-50`). At-PR gates: openhands' description validator, letta's AI-disclosure checks, semantic title linters everywhere. Trust-with-verification: opa relies on DCO sign-off plus review, with AI-specific rules layered on (`contrib-code.md:193-229`). None of these positions is free: pre-code gates maximize signal at maximum velocity cost; at-PR gates shift cost onto contributors after work is done.

**What gets mechanically enforced.** Process compliance (titles, links, disclosures) is enforced nearly everywhere; content integrity (links, anchors, parity, paths) in the top tier; example liveness (execution) in only four sources; and API compatibility as a contributor-facing contract in exactly two — agent-framework's Package Validation against published baselines (`CONTRIBUTING.md:77-106`) and openai-agents-sdk's frozen release contract (`.github/workflows/tests.yml:296-332`). Enforcement depth, not breadth, distinguishes the 8s from the 5–6s: each source enforces a few things completely rather than everything lightly.

**Maturity transitions leave scars.** Two low scorers are mid-migration snapshots rather than settled designs: letta exited a monorepo and left vestigial configs (`project.json:6-9` targeting nonexistent `apps/core`; ruff still excluding the emptied `examples/*` at `pyproject.toml:174-177`); langgraph consolidated docs externally and kept archive stubs with only directory-level notices (`examples/README.md:3-11`). Their gaps are transitional debt, not philosophy — worth remembering when comparing against settled repos.

## Tradeoffs

**Externalized docs vs. self-containment.** Centralizing pedagogy in dedicated docs sites/properties (langgraph, letta, temporal, langfuse, crewai-examples) lets documentation iterate without releases and keeps repos lean; the cost is that a fresh clone cannot teach extension authoring, nothing pins docs versions to code versions, and cross-references degrade silently — langfuse's own checker only validates cross-repo paths when they resolve (`.agents/README.md:156-160`). The alternative — agent-framework keeping curriculum in-repo — buys verifiability at the cost of a heavyweight corpus inside every clone. Best fit: externalize end-user pedagogy, but keep at least one runnable extension example in-tree (temporal's compromise: external samples, in-tree archiver contract).

**Executing every snippet vs. harness maintenance.** Full-fence execution gives pydantic-ai near-zero doc rot; the price is a ~260-line mock surface evolving with every doc change and confusing failures when output format shifts outside normalization patterns (`tests/test_examples.py:395-405`). letta shows the opposite failure: with no execution, its sole tutorial cites dead paths and examples rotted until wholesale deletion. Middle grounds exist: opa executes fixtures against the real engine with explicit skip metadata; agent-framework schedules re-validation but already suffered a quota-driven silent disable (`.github/workflows/python-sample-validation.yml:62-64`).

**Hard pre-code gates vs. drive-by velocity.** Langgraph's approval gate filters noise effectively but means "clarity of process ≠ autonomy of process" — an outside contributor cannot proceed past step one without maintainer interaction, and typo PRs pay the same toll as features. Pydantic-ai reaches similar noise control with softer machinery (auto-close with exemptions for docs/trivial fixes, `pr-guard.yml:182,196-198`), suggesting gate strictness can be dialed by change class rather than applied uniformly.

**AI-agent-first organization vs. human discoverability.** openai-agents-sdk and openhands replaced `CONTRIBUTING.md` with `AGENTS.md` as primary guidance; both reports flag that newcomers following GitHub's community-standards conventions find nothing until CI rejects their PR (openhands' validator posts feedback comments post-hoc). The fix observed nowhere but recommended twice is cheap: a thin conventional `CONTRIBUTING.md` pointing into the agent-first hierarchy.

**Generated vs. hand-written reference material.** Generation wins wherever the source of truth is machine-readable — but opa's REST API is the cautionary counter-case in reverse: a self-described authoritative specification written as ~2,464 lines of Markdown with no OpenAPI artifact anywhere in-tree (`rest-api.md:6`), sacrificing client generation, diffable breaking-change detection, and machine validation purely for readability. Conversely, generation can add tooling lock-in: langfuse's local SDK/OpenAPI export requires an authenticated Fern account (`CONTRIBUTING.md:558-560`).

**Frozen snapshots vs. maintenance weight.** crewai freezes Edge docs into per-release directories across four locales, enforced by release tooling (`lib/devtools/src/crewai_devtools/cli.py:1135,1190`); immutability preserves historical accuracy but bloats navigation to a manifest large enough that CI must prune frozen versions before link-checking (`.github/workflows/docs-broken-links.yml:29-35`), and the translation-parity mandate taxes every English edit (`AGENTS.md:27-28`). Simpler alternatives: openai-agents-sdk generates locale trees from English with do-not-edit markers; most others simply don't version docs.

## Decision Guide

- **Choosing where examples live:** If your product surface is an extension API, keep runnable examples in-repo and execute them in CI (pydantic-ai, agent-framework). If you are a server/platform whose users consume SDKs, delegate user samples to SDK repos but keep at least one contract-first extension walkthrough colocated (temporal). Never delete example trees without leaving signposts — letta's emptied `examples/` with vestigial lint excludes is the anti-example.
- **Choosing an API-doc mechanism:** If you have a machine-readable contract (proto/OpenAPI-capable handlers), generate (Fern twins, opa). If your API is idiomatic-code, use mkdocstrings-style generation with curated member allowlists (pydantic-ai `docs/api/agent.md:3-27`). Only fall back to docstring-discipline-plus-hosted-reference when generation is genuinely impossible, and then invest in docstring linting (langgraph's Google-style rule) — never hand-write a REST specification (opa's gap).
- **Choosing gate strength:** Scale gates to noise, not principle. Issue-approval bots suit very high-traffic monorepos (langgraph); auto-close-with-exemptions suits mid-size (pydantic-ai); disclosure requirements target specific abuse (letta's AI dumps); title linting is cheap enough for everyone (six sources). Always exempt docs-only and trivial fixes, and document where enforcement lives — crewai's snapshot guard referenced in code but absent from its workflows folder erodes auditability.
- **Adopting an AGENTS.md hierarchy:** Do it now; add CI path/link validation from day one (langfuse) rather than retrofitting after drift (letta, temporal). Keep exactly one canonical file per scope; mirror rather than fork (langgraph's byte-similar CLAUDE.md), and prefer generation over duplication where possible (pydantic-ai's extracted `agent_docs/`).
- **Building scaffolding commands:** Worth it for CLI-centric frameworks (crewai). If templates must be fetched remotely, pin revisions — langgraph's unpinned `archive/refs/heads/main.zip` downloads are a supply-chain and availability liability. In-repo embedded templates avoid both problems.
- **Routing extension work to sibling repos:** Legitimate for app/product repos (openhands' placement table prevents wasted work), but publish the routing before clone-time — mirror it into the README — and accept that your repo will score poorly on extension-teaching dimensions by construction.

## Practical Tips

**Copy these:**

1. Execute your documentation's code fences against mocked models; make skips declarative and rare (pydantic-ai `tests/test_examples.py:109`).
2. Validate every path cited in agent-guidance files in CI; fail on broken references (langfuse `package.json:11-12`).
3. Write the one flagship extension tutorial that binds each step to exact files and verification commands, and show the automatic payoff (opa's built-in-function tutorial; temporal's archiver guide).
4. Ship your deterministic test double inside the library so contributors and users share one mocking story (openai-agents-sdk `src/agents/testing/model.py:249`).
5. Generate everything derivable — CLI references, function catalogs, schemas, diagrams — and gate with gen-check (opa `main.go:31-36`, `docs/Makefile:68-74`; temporal d2 pipeline).
6. Embed safety education in extension examples themselves: approval-mode warnings in tool samples (agent-framework `02_add_tools.py:22-24`), memoization/nondeterminism flags with hazard rationale (opa `extensions.md:130-140,184-188`), cancellation-teardown discipline (pydantic-ai `capabilities/custom.md:462-470`).

**Avoid or delay:**

1. Multi-locale hand-synced translation mandates until demand exists — start with generated translations (openai-agents-sdk model).
2. Frozen per-release doc snapshots unless users demonstrably need historical accuracy; redirects to a single current site are cheaper (langgraph model).
3. Pre-code approval gates unless PR volume genuinely demands them; try classification-based auto-close first.
4. Large in-repo sample corpora without committed automation to run them — the corpus becomes a liability the moment validation lapses (agent-framework's disabled job).
