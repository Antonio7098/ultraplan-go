## Executive Summary

No source in this study ships mature plan observability *and* evaluation. The best observable system (crewai, 6/10) can answer "what was the plan and which tool call satisfied which step?" via typed plan traces and per-action `plan_step_number` joins, but cannot answer "was the plan good?" without manual log correlation. Every other source is weaker on the first question or absent on the second. **agent-framework (4)** and **openhands (4)** persist a current plan snapshot durably (`TodoSessionStore`/`TodoFileStore` and `TASKS.json`/`PLAN.md`) and inject it into model context, but overwrite history, emit no versioned plan events, and carry no `plan_item_id` on actions, so `plan vs execution` debugging requires scraping `session.state` or `EventLog` against tool transcripts. **langgraph (3)** provides production-grade *generic* execution observability — `Checkpoint`/`StateSnapshot`/`PregelExecutableTask` with time-travel `get_state_history()` and `stream_mode="debug"` — that can reconstitute a user-implemented `state["plan"]` idiom, but has no `Plan` type, no plan item IDs, and no planning eval harness (its `plan-and-execute` tutorial was retired via `docs/redirects.json:190`). **openai-agents-sdk (2)** and **pydantic-ai (2)** have no plan artifact at all: the former's `ToolExecutionPlan` (`src/agents/run_internal/tool_planning.py:557-574`) is an internal per-turn scheduler discarded after `_execute_tool_plan`, the latter outsources planning entirely to `pydantic-ai-harness` (`docs/capabilities/third-party.md:8`).

Across all six, evaluation is uniformly ad-hoc. No planning dataset, no plan-quality metric (adherence, coverage, replan rate, decomposition quality), and no regression that fails CI on planning regressions was found in-source. Generic harnesses exist — `LocalEvaluator`/`keyword_check`/`tool_called_check` (agent-framework `python/packages/core/agent_framework/_evaluation.py:1060-1277`), `CrewEvaluator` 1-10 on final output (crewai `src/crewai/utilities/evaluators/crew_evaluator_handler.py:22-27`), trajectory scorers `TrajectoryMatch`/`ToolCorrectness` (pydantic-ai `pydantic_evals/pydantic_evals/evaluators/agentic.py:191-582`), outcome critics `AgentFinishedCritic` (openhands `_sdk_inspect/sdk/critic/impl/agent_finished.py:28`) — but all assert response text or final tool sequences, not plan structure. The diagnostic gap is consistent: crewai's `PlannerObserver` and agent-framework's `MagenticProgressLedger` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:310-355`) can diagnose stall/loop with LLM judgment, while everywhere else "poor planning" is indistinguishable from poor execution without forensic heuristics.

## Core Thesis

**Planning observability in this cohort is a consequence of persistence choice, not planning intent — and evaluation is orthogonal to both.** The only variable that predicts whether a failed run is debuggable as `plan vs execution` is what the system does with plan state between turns: discard (openai-agents-sdk `ToolExecutionPlan` dropped after `turn_resolution.py:828-894`), snapshot-overwrite (`TodoSessionStore` at `python/packages/core/agent_framework/_harness/_todo.py:245-285`, `TASKS.json` at `_sdk_inspect/tools/task_tracker/definition.py:252-266`, `StateSnapshot.values` at `libs/langgraph/langgraph/pregel/main.py:1145-1266`), or trace-and-log (crewai `TodoList`→`TodoItem` materialization at `src/crewai/experimental/agent_executor.py:427-444` plus `PlanStepStarted/CompletedEvent` at `src/crewai/experimental/agent_executor.py:446-522` and `ToolUsage*Event` tagged with `plan_step_number` at `src/crewai/agents/step_executor.py:387-453`). Discard yields no observable plan; snapshot yields "what is the plan now?" but not "how did it evolve?"; trace yields a replayable lineage but still requires manual join across `state.plan`/`todos`/`execution_log`/`observations`/`trace batch`.

That lineage alone does not produce evaluation. Even the most traced system (crewai) scores planning only as a proxy: `ReasoningEfficiencyEvaluator` measures verbosity/loops via Jaccard n-gram >0.7 (`src/crewai/experimental/evaluation/metrics/reasoning_metrics.py:43-259`), not adherence or coverage, and `MetricCategory` has no `PLAN_QUALITY` (`src/crewai/experimental/evaluation/base_evaluator.py:20-27`). The pattern repeats: agent-framework ships `evaluate_agent`/`evaluate_workflow` with `keyword_check`/`tool_called_check` that could be wired to plan adherence but never is; pydantic-ai's `TrajectoryMatch` F1 penalizes redundant tool calls identically whether they reflect a bad plan or a retry (`pydantic_evals/pydantic_evals/evaluators/agentic.py:287-366`); openhands critics score patch non-emptiness, not `task_list` completeness. Planning evaluation where it appears is therefore **availability without specificity** — harnesses exist, datasets and plan-scoped metrics do not.

The divergence maps cleanly to product constraints, not engineering quality. Libraries that position planning as application code (langgraph, pydantic-ai, openai-agents-sdk) correctly avoid reifying an opinionated `Plan` type when no consensus schema exists, and compensate with generic, audit-grade execution tracing (OTel `invoke_agent`/`chat`/`execute_tool` spans at `pydantic_ai_slim/pydantic_ai/capabilities/instrumentation.py:152-277`, `StateSnapshot` checkpoints at `libs/checkpoint/langgraph/checkpoint/base/__init__.py:38-123`). Product/harness frameworks that own the agent loop (agent-framework, openhands, crewai) must reify something LLM-writable, and choose flat `TodoItem` lists over graph DAGs for ergonomic reasons, at the cost of `depends_on` correctness and versioned history. Neither strategy has yet closed the `plan_item_id` gap — only crewai's `StepExecutor` tags it — nor the versioned append-only plan log gap, which is why every report's canonical answer to "can you debug plan vs execution?" is *yes, but only by manually correlating two or more logs, not via a unified diff*.

## Approach Models

Three approach models emerge when normalizing by what the framework treats as the plan boundary.

### Model 1 — Absent / Ephemeral (no durable plan artifact)

- **Sources:** langgraph, openai-agents-sdk, pydantic-ai
- **Vocabulary:** `PregelExecutableTask`/`StateSnapshot.values` (langgraph), `ToolExecutionPlan` with `function_runs`/`shell_calls` buckets (openai-agents-sdk), `GraphAgentState.message_history` + `Graph`/`Fork`/`Join` (pydantic-ai)
- **Where implemented:** `libs/langgraph/langgraph/pregel/main.py:1145-1266`, `libs/langgraph/langgraph/types.py:666-681`, `src/agents/run_internal/tool_planning.py:557-646,944-1101`, `pydantic_ai_slim/pydantic_ai/_agent_graph.py:299-344`, `pydantic_graph/pydantic_graph/graph_builder.py:158-193`
- **Main mechanism:** Planning is developer-prompted, not framework-typed. Langgraph's canonical idiom is `planner` node returning `Command(goto=next_step, update={"plan": next_plan})` against `state["plan"]: list[str|list[str]]` (`libs/langgraph/tests/test_pregel.py:5165-5219`); openai-agents-sdk builds a fresh `ToolExecutionPlan` each turn from `ProcessedResponse` and discards it after parallel execution; pydantic-ai documents `pydantic_ai_harness.planning.Planning` but ships none (`docs/capabilities/third-party.md:8-11`). Observability is *execution* observability: every checkpoint persists `channel_values`/`pending_writes` and every tool call is correlated by `call_id`/`run_id`, but no `plan.*` span or log exists.
- **Why this divergence is valid:** All three are libraries/platform kernels where fixing a plan DSL would be premature tax. Langgraph optimizes for deterministic superstep replay; openai-agents-sdk for minimal model-agnostic turn loop; pydantic-ai for slim core + capability composition (`AbstractCapability` at `pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:1`). Trading plan specificity for generality is deliberate.

### Model 2 — Snapshot List (plan as flat todo, persisted as overwriting snapshot)

- **Sources:** agent-framework, openhands
- **Vocabulary:** `TodoItem(id,title,description,is_complete)` mutated via `todos_add/complete/remove/get_*` (agent-framework); `TaskItem(title,notes,status:todo|in_progress|done)` without ID + `PLAN.md` 5-section markdown OBJECTIVE/…/TESTING (openhands)
- **Where implemented:** `python/packages/core/agent_framework/_harness/_todo.py:51-615`, `python/packages/core/agent_framework/_harness/_mode.py:33-54`, `_sdk_inspect/tools/task_tracker/definition.py:32-435`, `_sdk_inspect/tools/preset/planning.py:14-88`, `_sdk_inspect/tools/planning_file_editor/definition.py:67-125`
- **Main mechanism:** Expose todo tools backed by session or file store (`TodoSessionStore` at `python/packages/core/agent_framework/_harness/_todo.py:245-285`, `TodoFileStore` atomic `tmp.<pid>`→`os.replace` at `python/packages/core/agent_framework/_harness/_todo.py:288-443`, `TASKS.json` under `persistence_dir` at `_sdk_inspect/tools/task_tracker/definition.py:252-266`, `.agents_tmp/PLAN.md` at `_sdk_inspect/tools/planning_file_editor/definition.py:96-113`). Current plan is injected into prompt (`before_run` synthetic user message `### Current todo list` at `python/packages/core/agent_framework/_harness/_todo.py:597-615`, `system_prompt_long_horizon.j2:4-7`) or echoed via `TaskTrackerObservation.visualize`. History is overwrite, not append — revisions replace `session.state[source_id]` or `TASKS.json` in place, and every source's "future considerations" proposes an append-only JSONL/version chain.
- **Why this divergence is valid:** Session-oriented assistants need human-readable progress with near-zero DSL; injecting the list as context is cheap and model-visible. Cost is auditability: no `TodoUpdated`/`PlanReplanTriggered` event (agent-framework) or `plan_item_id` linkage, so evolution is only reconstructible by scanning `EventLog`/`session.state` order.

### Model 3 — Traced Plan-and-Execute (plan materialized as typed todos with execution linkage and observer adjudication)

- **Sources:** crewai (Agent-level PlanningConfig path only)
- **Vocabulary:** `ReasoningPlan`/`PlanStep(step_number,description,tool_to_use,depends_on)` → `TodoList`/`TodoItem(id:uuid4,step_number,status,depends_on,result)` + `StepObservation` + `AgentExecutorState{plan,todos,observations,execution_log,replan_count}`
- **Where implemented:** `src/crewai/utilities/reasoning_handler.py:30-104,187-223`, `src/crewai/utilities/planning_types.py:14-278`, `src/crewai/experimental/agent_executor.py:151-171,427-522,647-727,1180-1190`, `src/crewai/agents/step_executor.py:127-453,609-623`, `src/crewai/agents/planner_observer.py:39-242`
- **Main mechanism:** `AgentReasoning.handle_agent_reasoning()` produces `ReasoningPlan` via function-calling `FUNCTION_SCHEMA create_reasoning_plan`; `_create_todos_from_plan()` materializes `TodoItem`s one-for-one preserving `step_number` as stable join key; `StepExecutor.execute(todo,context)` tags `ToolUsageStarted/FinishedEvent` with `plan_step_number/description`; `AgentExecutor` emits `PlanStepStarted/CompletedEvent(success,result)` per todo; `PlannerObserver.observe()` after every step emits `StepObservationCompletedEvent(step_completed_successfully, remaining_plan_still_valid, needs_full_replan, goal_already_achieved)` and routes via `needs_replan|refine|continue` bounded by `max_replans:3`/`max_step_iterations:15` (`src/crewai/agent/planning_config.py:79-149`). Persistence is `TraceCollectionListener` batch + `execution_log` audit trail ("NOT used for LLM calls" at `src/crewai/experimental/agent_executor.py:168-171`).
- **Why it diverges to higher observability:** It is the only source where each action *structurally* declares its plan item (`plan_step_number`). That single field, plus DAG `depends_on` and parallel `execute_todos_parallel`, enables plan-vs-execution diffs without title substring matching — the precise capability missing in Models 1 and 2.

**What converges:** All three models agree that a plan is short-lived LLM-authored state unless the developer retains it, that `call_id`/`tool_call_id` is the universal execution join key, and that generic OTel/event tracing exists but is plan-blind. **Why they diverge:** product shape (library kernel vs harness vs product), maturity (crewai bounds planning explicitly with `reasoning_effort`/`max_steps`/`max_replans`, while langgraph/openai/pydantic defer bounds to application or turn limits), and tolerance for DSL tax (flat todo string lists vs typed `PlanStep`).

## Pattern Catalog

### Pattern 1 — Todo Collection as De Facto Plan Registry

- **Problem:** Give an LLM a mutable, human-readable plan without teaching a plan DSL.
- **Sources:** agent-framework `TodoProvider`, openhands `TaskTracker`, crewai `TodoList`, openai-agents-sdk ephemeral `ToolExecutionPlan`, pydantic-ai GH shim `todo_write.py:37` bridging Claude todos → `PlanItem`.
- **How it works:** Expose narrow tools (`todos_add/complete/remove/get_all/get_remaining` at `python/packages/core/agent_framework/_harness/_todo.py:505-590`, `task_tracker view|plan` at `_sdk_inspect/tools/task_tracker/definition.py:42-84`, `create_reasoning_plan` function schema at `src/crewai/utilities/reasoning_handler.py:50-104`) over `list[TodoItem]`. Persist via session map (`session.state[source_id]` at `python/packages/core/agent_framework/_harness/_todo.py:245-285`) or atomic JSON file (`TASKS.json`, `todos.<source_id>.json`). Inject current snapshot into prompt each turn.
- **Why it works:** Minimal authoring burden; any model can emit `title/description`; storage is trivial locks/files.
- **Copy when:** Single-agent session loops needing visible progress. Copy agent-framework's `WeakKeyDictionary` mutation lock (`python/packages/core/agent_framework/_harness/_todo.py:481-492`) and atomic `os.replace` pattern; copy crewai's `TodoStatus` four-state (`pending|running|completed|failed`) over agent-framework's binary `is_complete`.
- **Overkill/risky when:** Subtasks have ordering — flat lists without `depends_on` silently accept contradictory ordering; require whole-list resend for reorder (openhands `self._task_list = action.task_list` at `_sdk_inspect/tools/task_tracker/definition.py:174-179`) and lose stable refs.

### Pattern 2 — Stable Plan-Item ID + Per-Action Execution Link

- **Problem:** Answer "which planned step did this tool call satisfy?" without substring heuristics.
- **Sources:** crewai demonstrates it clearly; others demonstrate the absence.
- **How it works:** Assign `TodoItem.id: uuid4()` + `step_number` (1-based) at `src/crewai/utilities/planning_types.py:27-45` and preserve it through `_create_todos_from_plan()` at `src/crewai/experimental/agent_executor.py:427-444`; `StepExecutor` tags every `ToolUsage*Event` with `plan_step_number/description` (`src/crewai/agents/step_executor.py:395-449,621-622`); `PlanStepStarted/CompletedEvent` per todo at `src/crewai/experimental/agent_executor.py:446-522`. Agent-framework `TodoItem.id:int` is sequential (`python/packages/core/agent_framework/_harness/_todo.py:223-226`) but never attached to `FunctionTool`/`WorkflowEvent` (`python/packages/core/agent_framework/_tools.py:1-80` negative evidence); openhands `TaskItem` has no `id` and `ActionEvent` has no `plan_item_id` (`_sdk_inspect/tools/task_tracker/definition.py:32-39`, `_sdk_inspect/sdk/agent/agent.py:879-903`); langgraph/openai/pydantic-ai have no `plan_item_id` field on `PregelExecutableTask`/`ToolCallItem`/`ToolCallPart`.
- **Copy when:** Any claim about adherence, coverage, or replan rate must be quantified.
- **Risk if skipped:** Post-hoc title→tool matching misattributes vague titles ("Investigate issue") and cannot distinguish one tool satisfying multiple todos (agent-framework failure mode at `python/packages/core/agent_framework/_harness/_todo.py:51-107`).

### Pattern 3 — Execution Audit Trail Separated From LLM Context

- **Problem:** Debugging requires faithful execution facts that are not rewritten by context compression.
- **Sources:** crewai `execution_log` ("Audit trail for debugging NOT used for LLM calls" at `src/crewai/experimental/agent_executor.py:168-171`) + `StepExecutionContext` bundles only final dependency `result` strings (`src/crewai/experimental/agent_executor.py:647-678`); langgraph `StateSnapshot.tasks` + `pending_writes` merged via `tasks_w_writes` (`libs/langgraph/langgraph/pregel/debug.py:209-279`) + `map_debug_checkpoint/tasks` payloads (`libs/langgraph/langgraph/pregel/debug.py:38-206`); agent-framework `WorkflowRunResult` inherits `list[WorkflowEvent]` with `status_timeline` (`python/packages/core/agent_framework/_workflows/_workflow.py:103-167`); openhands file-per-event `EventLog` with UUID/timestamp/file locking (`_sdk_inspect/sdk/conversation/event_store.py:119-152`).
- **Copy when:** Long-horizon runs where compaction or fresh-context replay would otherwise drop plan mutations (agent-framework `fresh_context=True` discarding todo mutations at `python/packages/core/agent_framework/_harness/_loop.py:436-437,583-586` is the cautionary case).
- **Overkill when:** Single-turn ephemeral agents — history is `RunItem`s (`src/agents/items.py:686-740`) and need not be separated.

### Pattern 4 — Observer / Progress-Ledger Post-Step Adjudication

- **Problem:** Detect plan invalidation, loop/stall, or early goal achievement without a structural verifier.
- **Sources:** crewai `PlannerObserver.observe()` emitting `StepObservation` with `remaining_plan_still_valid/needs_full_replan/goal_already_achieved` (`src/crewai/agents/planner_observer.py:113-189`, `src/crewai/utilities/planning_types.py:212-278`) and routing via three `reasoning_effort` tiers (`src/crewai/experimental/agent_executor.py:555-1088`); agent-framework `MagenticProgressLedger(is_request_satisfied,is_in_loop,is_progress_being_made,next_speaker)` with `stall_count > max_stall_count=3 → _reset_and_replan` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:310-355,1109-1118`) and `JudgeVerdict` (`python/packages/core/agent_framework/_harness/_loop.py:152-214`); heuristic fallback `heuristic_observation` at `src/crewai/agents/planner_observer.py:87-111`.
- **Why it works:** Makes `plan vs execution` load-bearing for control flow (replan/refine/continue/goal-achieved) rather than offline forensics; bounds replanning (`max_replans:3`) to avoid unbounded reset loops.
- **Copy when:** Multi-step tasks where a plan may succeed early or deadlock on `depends_on`.
- **Risky when:** Observer LLM outage silently degrades — crewai falls back to `StepObservation(success=False, remaining_valid=False)` with a warning (`src/crewai/agents/planner_observer.py:304-352`), outer observer failure in Magentic increments stall and replans (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1083-1085`), so persistent model inability triggers bounded reset churn.

### Pattern 5 — Generic Execution Observability as Plan Substrate (OTel + checkpoints + spans)

- **Problem:** Provide plan-adjacent observability without committing to a plan schema.
- **Sources:** langgraph `TASK_NAMESPACE` UUID + `PregelTask.path` deterministic lineage (`libs/langgraph/langgraph/pregel/debug.py:38`, `libs/langgraph/langgraph/types.py:637-681`) + `stream_mode="values|updates|checkpoints|tasks|debug"` (`libs/langgraph/langgraph/types.py:122-367`); pydantic-ai `Instrumentation` emitting `invoke_agent/chat/execute_tool` with `gen_ai.tool.name` (`pydantic_ai_slim/pydantic_ai/capabilities/instrumentation.py:152-277`, `pydantic_ai_slim/pydantic_ai/_instrumentation.py:444-542`) + `GraphAgentState.run_id/conversation_id` (`pydantic_ai_slim/pydantic_ai/_agent_graph.py:299-344`); openai-agents-sdk `TaskSpanData/TurnSpanData/FunctionSpanData` hierarchy (`src/agents/tracing/span_data.py:28-451`) with `BackendSpanExporter`; agent-framework `OtelAttr WORKFLOW_*/EXECUTOR_*` (`python/packages/core/agent_framework/observability.py:294-330`) — none with `TODO_*`/`PLAN_*` attribute.
- **Copy when:** Building a library kernel where the right plan abstraction is unsettled — generic lineage keeps time-travel and trace correlation useful while deferring plan semantics.
- **Failure mode if copied alone:** `plan = ["step1", ["step2","step3"]]` typos surface only as `PregelTask.error` at runtime (`libs/langgraph/langgraph/pregel/debug.py:115-128`); invocation deduplication via `tool_invocation_identity` (`src/agents/run_internal/tool_planning.py:102-116`) guards execution but not plan-level duplicate/skip.

### Pattern 6 — Bounded Replanning Budget (hysteresis + caps)

- **Problem:** Prevent LLM replanning from looping infinitely on ill-formed dependencies or unparsable judgment.
- **Sources:** crewai `PlanningConfig(max_attempts,max_steps:20,max_replans:3,max_step_iterations:15,step_timeout)` (`src/crewai/agent/planning_config.py:79-149`) + dependency deadlock→replan routing (`src/crewai/experimental/agent_executor.py:1119-1132`); agent-framework Magentic `stall_count` decrement-on-progress/increment-on-stall (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1118`, `max_stall_count=3`); pydantic-ai `request_limit:50` defaults (`pydantic_ai_slim/pydantic_ai/usage.py:417-472`); langgraph `recursion_limit` / durability modes (`libs/langgraph/langgraph/types.py:89`, `libs/langgraph/langgraph/pregel/_loop.py:215-223`).
- **Copy when:** Any LLM-authored `depends_on` or ledger verdict drives control flow — caps convert an undecidable "is this productive?" into a bounded "have we spent N replans?".

### Pattern 7 — Framework-Agnostic Eval Harness Decoupled From Plan Semantics

- **Problem:** Score agent runs without tying the harness to a single plan vocabulary — the shared floor all sources occupy.
- **Sources:** agent-framework `EvalItem(conversation,expected_output,expected_tool_calls,split_strategy)` + `LocalEvaluator` + `keyword_check/tool_called_check` (`python/packages/core/agent_framework/_evaluation.py:182-373,682-850,1060-1277`) wired to `AgentEvalConverter` but not to todos (`python/packages/core/agent_framework/_evaluation.py:882-925`); crewai `CrewEvaluator` per-output 1-10 (`src/crewai/utilities/evaluators/crew_evaluator_handler.py:53-215`) + `ReasoningEfficiencyEvaluator` with `MetricCategory GOAL_ALIGNMENT…TOOL_INVOCATION` lacking `PLAN_QUALITY` (`src/crewai/experimental/evaluation/base_evaluator.py:20-27`); pydantic-ai `pydantic_evals.Dataset[InputsT,OutputT,MetadataT]` + `ToolCorrectness/TrajectoryMatch( F1 via LCS/multiset)` over `ctx.span_tree` (`pydantic_evals/pydantic_evals/evaluators/agentic.py:191-582`); openhands `CriticBase/APIBasedCritic/AgentFinishedCritic` scoring final patch/outcome not plan fidelity (`_sdk_inspect/sdk/critic/base.py:58-114`).
- **Why it persists:** Extensible and product-neutral — any agent without a plan still evaluable — but conflates activity with plan quality (`TrajectoryMatch` penalizes a redundant tool call identically whether it reflects a bad plan or a retry). Teams must author their own `plan_completeness`/`orphaned_todo` checks.

## Key Differences

- **Durability vs discard:** agent-framework and openhands overwrite a durable snapshot each `plan` mutation (`TodoSessionStore` `python/packages/core/agent_framework/_harness/_todo.py:245-285` and `TASKS.json` ` _sdk_inspect/tools/task_tracker/definition.py:174-179`), so history is "last write wins" and prior versions survive only in `EventLog`/`session.state` scans. Crewai keeps an in-memory `AgentExecutorState.todos/observations/execution_log` plus trace batch persistence but checkpoints are not versioned per revision. Langgraph makes every super-step a `Checkpoint` with `checkpoint_id`/`parent_config` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:92-123`), so full time-travel is native — if a `state["plan"]` channel is used, every revision is retained. Openai-agents-sdk and pydantic-ai keep no plan revision at all (`RunState` at `src/agents/run_state.py:761-878` and `GraphAgentState` at `pydantic_ai_slim/pydantic_ai/_agent_graph.py:299-344` lack `plan` fields).

- **Linkage present only once:** Crewai tags `plan_step_number` on both text and native tool paths (`src/crewai/agents/step_executor.py:395-453,609-623`) and emits per-step `PlanStepStarted/CompletedEvent`. No other source carries `plan_item_id` on tool spans — agent-framework explicitly lacks `todo_id` on `FunctionTool/Content/WorkflowEvent` (`python/packages/core/agent_framework/_tools.py:1-80`, `python/packages/core/agent_framework/_types.py:1-100`), openhands `ActionEvent` carries `tool_call_id` not `plan_item_id` (`_sdk_inspect/sdk/agent/agent.py:879-903`), langgraph `PregelExecutableTask` carries `id/path/triggers/writes` but not `plan_item_ref` (`libs/langgraph/langgraph/types.py:666-681`), openai/pydantic carry only `call_id/tool_call_id`.

- **Who answers "plan observable?":** Crewai and openhands answer yes with caveats — crewai's agent-level plan is observed via `AgentReasoningStarted/CompletedEvent` and trace listeners (`src/crewai/events/types/reasoning_events.py:24-48`, `src/crewai/events/listeners/tracing/trace_listener.py:509-557`) while its crew-level `CrewPlanner` output is detached (`src/crewai/utilities/planning_handler.py:73-78`); openhands three channels are Rich `visualize`, `TASKS.json`, and `EventLog` (`_sdk_inspect/tools/task_tracker/definition.py:85-145`, `_sdk_inspect/sdk/conversation/event_store.py:119-151`). Agent-framework answers "current snapshot is, history and trace are not" — OTel/Workflow events have no `TODO_*` attribute (`python/packages/core/agent_framework/observability.py:294-330`). Pydantic-ai and openai answer no — plan surfaces would be ad-hoc tool messages inside `message_history` (`pydantic_ai_slim/pydantic_ai/messages.py:1852-1856`), indistinct from ordinary tool traffic.

- **Telemetry vs plan-trace split:** Langgraph/openai/pydantic-ai invest heavily in generic spans and checkpoints but none emit `plan.*` attributes; agent-framework defines `WORKFLOW_*/EXECUTOR_*` spans and `FeatureIndex.CORE_TODO_PROVIDER` bit counting adoption not quality (`python/packages/core/agent_framework/_telemetry.py:36-50`). Crewai is the only source routing plan lifecycle to both `EventListener` console/OTel and `TraceCollectionListener` action batch (`src/crewai/events/event_listener.py:699-777`, `src/crewai/events/listeners/tracing/trace_listener.py:527-557`), though persistence gates on `should_enable_tracing`/`is_first_time`.

- **Evaluation posture:** Agent-framework, crewai, and pydantic-ai ship eval frameworks but none ships a planning eval — each requires custom `EvalCheck`/`Evaluator`/`Critic` to measure plan quality (agent-framework's `EvalItem.expected_tool_calls` not derived from todos at `python/packages/core/agent_framework/_evaluation.py:882-925`; crewai's `MetricCategory` without `PLAN_QUALITY`; pydantic-ai's `Dataset` typed generically at `pydantic_evals/pydantic_evals/dataset.py:177-246`). Openai-agents-sdk, openhands, and langgraph ship no in-repo eval harness for planning at all (openhands `VerificationSettings` at `_sdk_inspect/sdk/settings/model.py:143-228` and langgraph `bench/__main__.py:99-515` confirm the gap is not oversight but scope choice).

## Tradeoffs

**Typed plan trace (crewai) vs prompt-injected snapshot (agent-framework/openhands).** Benefit typed trace: each `ToolUsage*Event` and `PlanStep*Event` is joinable to a plan item, parallelism respects `depends_on`, and `PlannerObserver` can refine vs replan without regenerating all todos. Cost: N extra LLM observe calls per task (`reasoning_effort=high` most expensive at `src/crewai/experimental/agent_executor.py:681-968`), function-calling fallback drops `steps` to `[]` when unavailable (`src/crewai/utilities/reasoning_handler.py:256-276`), and console persistence depends on ephemeral/auth gating. Best-fit: long-horizon multi-step tasks where adherence matters. Alternative snapshot prompt: zero infra, model immediately sees open todos — but buries the plan in transcript text rather than a typed event that dashboards can aggregate, and `todos_remaining` predicate (`any(not is_complete)` at `python/packages/core/agent_framework/_harness/_loop.py:937-973`) cannot distinguish orphaned todos from genuine work.

**Generic graph execution (langgraph/pydantic_graph) vs flat todo registry (tods).** Benefit generic graph: compile-time `validate_workflow_graph` (`sources/agent-framework/python/packages/core/agent_framework/_workflows/_validation.py:1-60`), deterministic PUSH/PULL superstep scheduling, and barrier fan-in derive from channels/forks without per-plan code. Cost: no queryable plan artifact to lint or reorder offline; dynamic `Send` to unknown node is silently dropped (`libs/langgraph/langgraph/pregel/_algo.py:977-979`). Flat todos invert the tradeoff: human-readable, string-enumerable, trivial to overwrite — but no static validation, whole-list resend for reorder loses stable IDs, and "all todos done" ≠ "task complete" without a coverage check.

**Ephemeral turn plan (openai-agents-sdk) vs durable todo list.** Benefit ephemeral: minimal state, clean `gather_with_cancel` per turn, no store to version, model autonomy preserved (`src/agents/run_internal/tool_planning.py:944-1101`). Cost: crash loses in-flight plan, no cross-turn blocking query, `MaxTurnsExceeded` at `src/agents/result.py:1052` is unattributed to plan debt, and compliance question "did the agent follow the approved plan?" has no native answer. Durable lists survive restart via `GraphAgentState`/`RunState`/`Checkpoint` but pay I/O/locking overhead and history management tax.

**Heuristic/LLM judgment for plan diagnosis (Magentic/PlannerObserver) vs structural `todos_remaining` guard.** Benefit judgment: semantically rich — `is_in_loop`/`is_progress_being_made` and `remaining_plan_still_valid` detect meaningless activity that structural counts miss. Cost: parse fragility (agent-framework `JUDGE_VERDICT_DONE/MORE` fallback at `python/packages/core/agent_framework/_harness/_loop.py:192-199`, Magentic `_reset_and_replan` catch at `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1083-1085`), judge variance, correlated bias. Structural guard (`any(not is_complete)`) is deterministic and cheap but blind to narration-driven false completion ("I listed the directory" marked complete, crewai anti-narration prompt at `src/crewai/translations/en.json:88` is the only in-prompt mitigation).

**Evaluation generality vs plan specificity.** Benefit generic evaluators: work for any agent without a planning vocabulary (`TrajectoryMatch` F1 at `pydantic_evals/pydantic_evals/evaluators/agentic.py:287-366` works with or without todos). Cost: conflates planning and execution — redundant tool use penalizes F1 the same for bad plan vs retry. Plan-specific scorers (none shipped) would distinguish `plan_completeness`/`orphaned_todo`/`decomposition_quality` but require an agreed plan schema the field lacks.

## Decision Guide

- **You are a thin SDK over a provider API and want zero plan tax:** Stay ephemeral like openai-agents-sdk/pydantic-ai. Document "break down via prompts" (`src/agents/sandbox/instructions/prompt.md:102` pattern; `docs/capabilities/third-party.md:9` TODO capability) and delegate structured planning to an optional capability. Add only `custom_span("plan", data={items})` via the existing `TracingProcessor` plumbing if plan auditing is later required (`src/agents/tracing/processors.py:541+`, `src/agents/tracing/create.py:31-491`).

- **You need a human-visible durable plan for a single agent loop:** Copy agent-framework's per-session store with `WeakKeyDictionary` lock + atomic `os.replace` (`python/packages/core/agent_framework/_harness/_todo.py:280-370,481-492`) — not openhands' lock-free whole-list overwrite (`_sdk_inspect/tools/task_tracker/definition.py:174-179`). Immediately add three gaps the reports flag: persist `completion_reason` on `TodoItem` instead of transient tool arg (`python/packages/core/agent_framework/_harness/_todo.py:144-177`), emit `WorkflowEvent(type="todo_updated")` or OTel `todo.update` with `todo.id/reason/revision_id`, and version the store as append-only JSONL keyed to `WorkflowCheckpoint`-style `previous_checkpoint_id`.

- **You need dependency-aware parallelism with runtime replanning:** Pick the only out-of-the-box scheduler — crewai Plan-and-Execute. Copy `PlanStep→TodoItem` materialization preserving `step_number` (`src/crewai/experimental/agent_executor.py:427-444`), `get_ready_todos`/`can_parallelize` gating (`src/crewai/utilities/planning_types.py:22,133`), isolated `StepExecutionContext` with result-only propagation (`src/crewai/experimental/agent_executor.py:647-678`), and `PlannerObserver` Observe→Decide (`refine_and_continue` vs `replan_now` bounded by `max_replans:3` at `src/crewai/agents/planner_observer.py:39-242`). Do not copy the disconnected `CrewPlanner` (`src/crewai/utilities/planning_handler.py:57-78`) without emitting its `PlannerTaskPydanticOutput` as trace events and optionally seeding the `TodoList`.

- **You need deterministic orchestration and are comfortable building plan concerns atop it:** Pick langgraph/pydantic_graph. Treat the graph as the decomposition (nodes = subtask types) and define plan as a `Plan` channel typed `items:{id,description,status}` carried in `Checkpoint.channel_values` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:92-123`). Add `plan`/`plan_items` to `StreamMode` and annotate `ToolCallWithContext`/`TracePolicy` with `plan_item_id`; ship a `plan-vs-execution diff` helper over `get_state_history()`.

- **Rule of thumb for choosing how much to formalize:** If plans must be queried ("what is blocked? ready? coverage?"), you need `depends_on` + stable IDs + execution linkage — the crewai shape. If plans must be replayed after crash, you need checkpoint/versioned history — the langgraph shape. If neither, a snapshot todo list suffices, but pair any stale-state predicate (`todos_remaining`) with a numeric bound (`max_iterations`/`max_replans`) and never rely on title string matching for attribution.

## Practical Tips

**Patterns to copy now:**

- **Per-session serialized mutation + clamped monotonic IDs.** `TodoProvider._mutation_locks: WeakKeyDictionary[AgentSession, asyncio.Lock]` plus `_safe_next_id = max(next_id, max(item.id)+1)` (`python/packages/core/agent_framework/_harness/_todo.py:190-226,481-492`, mirrored in .NET `ConditionalWeakTable`) prevents duplicate `next_id` under concurrent `todos_add/complete` and is validated by `test_todo_provider_serializes_concurrent_mutations` (`python/packages/core/tests/core/test_harness_todo.py:322-367`).

- **Plan-to-todo materialization preserving a stable join key.** Convert `PlanStep[]` → `TodoItem[]` one-for-one preserving `step_number` as the cross-artifact key (`src/crewai/experimental/agent_executor.py:427-444`). Tag every downstream `ToolUsage*Event` with it (`src/crewai/agents/step_executor.py:395-453`) — this is the single cheapest lift for plan↔execution observability across the study.

- **Reason-gated completion with persisted audit.** Require `TodoCompleteInput(id, reason)` validation (`python/packages/core/agent_framework/_harness/_todo.py:144-177`) *and* persist `reason`/`removed_reason` on `TodoItem` (currently transient) plus tombstone removed items — the reports' top-recommended fix for post-hoc diagnosis without transcript scraping.

- **Heuristic degrade for observation cost.** When `observe_steps=False` or `reasoning_effort=low`, return no-LLM `StepObservation` (`src/crewai/agents/planner_observer.py:87-111`) to keep pipeline shape but cut latency (`src/crewai/experimental/agent_executor.py:590-645`). Mirror with Magentic's decrement-on-progress stall hysteresis (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1118`).

- **Audit trail not fed to LLM.** Mark `execution_log` as "NOT used for LLM calls" (`src/crewai/experimental/agent_executor.py:168-171`) — prevents context bloat while keeping a ground-truth trace distinct from `pydantic_ai.all_messages` drift (`_instrumentation.py:220-234` staleness warning).

**Patterns to avoid or delay:**

- **Do not create a second plan surface without a bridge.** Openhands `TASKS.json` + `PLAN.md` (`_sdk_inspect/tools/task_tracker/definition.py:238-263` vs `_sdk_inspect/tools/preset/planning.py:14-53`), agent-framework todos+workflows, pydantic-ai core+external harness all bifurcate responsibility — one plan registry per run is enough until a `TodoWorkflowAdapter` is proven.

- **Do not use overwrite-only plan persistence.** Both agent-framework and openhands lose history on `session.state[source_id]` / `TASKS.json` replace; add append-only `todos.<id>.jsonl` or `previous_checkpoint_id` chain before claiming auditability.

- **Do not treat generic tracing as plan tracing.** Workflow/executor `WORKFLOW_*` spans and `TaskSpan`/`TurnSpan` hierarchy do not substitute for `plan.*` attributes (`python/packages/core/agent_framework/observability.py:294-330`, `src/agents/tracing/span_data.py:64-133`) — dashboards cannot chart `plan vs execution` until a dedicated `TodoUpdated` event or `gen_ai.plan.*` attribute exists.

- **Do not ship a planning mode without its evaluation counterpart.** All six sources demonstrate that a shipped plan representation (CrewPlanner, TodoProvider, planning agent) without a paired `plan_completeness`/`adherence`/`decomposition_quality` evaluator and dataset drifts untested — `Crew.test(n_iterations,eval_llm)` 1-10 on final output and `TrajectoryMatch` proxy do not bound plan emission drift (`src/crewai/crew.py:2253`, `pydantic_evals/pydantic_evals/evaluators/agentic.py:191-245`).

**Caution signs the design is becoming brittle:**

- `any(not is_complete)` as the sole loop predicate with no `orphaned_todo`/`blocked` derivative (`python/packages/core/agent_framework/_harness/_loop.py:937-973`).
- Titles parsed to infer `kind`/`priority` because no typed `tool_to_use`/`blocked_by` field exists.
- `fresh_context=True` snapshotting `session.to_dict()` before loop and restoring before each iteration, silently discarding in-loop `todos_add/complete` (`python/packages/core/agent_framework/_harness/_loop.py:436-437,583-586`).
- `max_replans`/`max_stall_count` hitting caps and finalizing with incomplete plan as success (`src/crewai/experimental/agent_executor.py:1056-1064`, `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1118`), or `max_turns` aborting with lost plan (`src/agents/result.py:1052`).
- `BatchTraceProcessor` dropping spans when queue is full (`src/agents/tracing/processors.py:602-621`) or plan events gated on auth/ephemeral (`src/crewai/events/listeners/tracing/trace_listener.py:212-221`) — observability silently off by default.

## Anti-Patterns / Caution Signs

- **Silent plan divergence with no validator.** Instructions to "adjust todos accordingly" on topic change (`python/packages/core/agent_framework/_harness/_todo.py:35-48`, `python/packages/core/agent_framework/_harness/_mode.py:33-70`) are unenforced; an agent can add tasks without removing obsolete ones and loop on phantom work with no `plan deviation` detector (also reported as orphaned `todo`/`in_progress` tasks in openhands `_sdk_inspect/tools/task_tracker/definition.py:174-179`).
- **Completion reason not persisted / tombstone missing.** `TodoCompleteInput.reason` validated but not stored on `TodoItem` (`python/packages/core/agent_framework/_harness/_todo.py:51-107`); `todos_remove` has no reason field — audits answerable only via transcript scraping.
- **Index/identity fragility on replan.** Positional `TaskItem` with no stable `id` shifts on reorder (`_sdk_inspect/tools/task_tracker/definition.py:122-130`); agent-framework `fresh_context` discards mutations; crewai text fallback returns `[]` steps (`src/crewai/utilities/reasoning_handler.py:440-444`) hiding malformed plan.
- **Observation parse failure masking real failure.** `_parse_observation_response` markdown/instance dict fallbacks plus conservative `StepObservationCompletedEvent` on failure (`src/crewai/agents/planner_observer.py:191-352`) and agent-framework judge fallback markers `VERDICT: DONE/MORE` (`python/packages/core/agent_framework/_harness/_loop.py:192-199`) convert tool-hallucination into soft failures that adjudicators must re-interpret.
- **Two planning modes divergence.** Crew's static whole-crew `CrewPlanner` ( `src/crewai/utilities/planning_handler.py:37-115`) vs agent-level dynamic `TodoList` execution are shipped together but unintegrated — users assume crew plan seeds todo execution, it does not.
- **Forged or lost trace.** Langgraph `DeltaChannel` pruning breaks `get_state_history()` walks (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:374-415`); openai `BatchTraceProcessor` lossy queue can drop plan spans even after `custom_span("plan")` workaround; openhands `fork` not explicitly copying `TASKS.json` (`_sdk_inspect/sdk/conversation/impl/local_conversation.py:383-407`) breaks plan continuity.
- **Max-turns/budget exhaustion conflated with success.** `MaxTurnsExceeded` fires with no attribution to which plan steps consumed turns (`src/agents/result.py:1052`); crewai dependency deadlock routes to replan then silently finalizes incomplete when `max_replans` exhausted (`src/crewai/experimental/agent_executor.py:1056-1064`).

## Notable Absences

Shared across all six sources (evidence-backed), not just somewhere:

- **Versioned, append-only plan log.** All durable stores are overwrite snapshots (`session.state`, `TASKS.json`, `PLAN.md` file overwrite via `PlanningFileEditorExecutor` at `_sdk_inspect/tools/planning_file_editor/impl.py:46-55`, `ChannelValues` per checkpoint). No `todos.<id>.jsonl` / `previous_checkpoint_id` plan chain, no `todos_get_history(revision_id)`, no `plan-version` filter on `EventServiceBase.search_events` (`openhands/app_server/event/event_service_base.py:94-143`).
- **Structured `plan_item_id` join from actions to plan items.** Only crewai tags it (`plan_step_number`); the other five have explicit negative evidence of absence (`python/packages/core/agent_framework/_tools.py:1-80`, `_sdk_inspect/sdk/agent/agent.py:879-903`, `libs/langgraph/langgraph/types.py:666-681`, `src/agents/items.py:412-461`, `pydantic_ai_slim/pydantic_ai/messages.py:2174`).
- **Plan trace/event schema and plan-aware OTel attributes.** No `WorkflowEvent(type="todo_updated")`, `PlanStepStarted/CompletedEvent` outside crewai, `PlanSpanData`, `gen_ai.plan.*`, or `pydantic_ai.plan.items` span (`python/packages/core/agent_framework/observability.py:294-330`, `src/agents/tracing/span_data.py:28-451`, `pydantic_ai_slim/pydantic_ai/_instrumentation.py:444-542`). Plan operations are invisible in deployed trace backends even with `enable_instrumentation`.
- **Plan-quality metrics, rubric, or evaluator.** No `plan_completeness`/`adherence`/`coverage`/`orphaned_todo`/`decomposition_quality`/`replan_rate`/`premature-goal` metric. Found: `keyword_check`/`tool_called_check` (`python/packages/core/agent_framework/_evaluation.py:1060-1148`), 1-10 output scoring (`src/crewai/utilities/evaluators/crew_evaluator_handler.py:24`), `ReasoningEfficiencyEvaluator` loop/verbosity heuristics (`src/crewai/experimental/evaluation/metrics/reasoning_metrics.py:43-259`), `TrajectoryMatch` F1 (`pydantic_evals/pydantic_evals/evaluators/agentic.py:191-582`) — all proxy or post-hoc.
- **Planning eval datasets and planning regression tests.** No dataset file under any source's `tests/` or `python/samples` (`python/packages/core/tests/core/test_local_eval.py:1-80` only keyword/tool smoke tests; `src/crewai/tests/agents/test_agent_executor.py:1446-1698` asserts plan creation not improvement; `tests/evals/test_agentic_evaluators.py` at `pydantic-ai` only trajectory relevance). The old `examples/plan-and-execute` tutorial is explicitly retired (`docs/redirects.json:190` pointing to `langchain/middleware/built-in#to-do-list`).
- **Attribution of planning to success rate.** No A/B harness `planning_config=None` vs `PlanningConfig(...)`, no correlation of `TodoProvider` usage vs non-todo runs, no benchmark integrating plan quality with task success (`EvalResults` could support it at `python/packages/core/agent_framework/_evaluation.py:373-443`; `pydantic_evals.Dataset` at `pydantic_evals/pydantic_evals/dataset.py:281` could measure lift but is not used for planning — all reports search-confirmed absence).

## Per-Source Notes

- **agent-framework (4):** Best snapshot persistence in the study (atomic `TodoFileStore`, per-session locks, tested clamping) paired with the sharpest auditability tradeoffs: overwrite history, transient `reason`, no trace linkage, OTel blind to todos, and isolated Magentic quality island (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:285-355`) not shared with the harness path most samples use (`python/packages/core/agent_framework/_harness/_agent.py:176-177`). Copy the store, fix the event/trace/tombstone gap, and wire stall logic to the single-agent loop.

- **crewai (6):** Highest observability via typed `PlanStep→TodoItem` DAG and explicit `plan_step_number` join plus observer-pipeline plan evolution tracking; also the clearest caution on dual-track planning debt (`CrewPlanner` invisible to trace). Meets the dimension's "debug plan vs execution?" question alone among the six, but pulled to 6 by the evaluation gap — `MetricCategory` needs `PLAN_QUALITY` and a small curated planning dataset with `depends_on` correctness.

- **langgraph (3):** Absent for planning, mature for generic execution — the paradigm case for Model 1's deliberate tradeoff. Its `Checkpoint`/`StateSnapshot`/`stream_mode=debug|tasks|checkpoints` substrate is the most reusable primitive here: if a `state["plan"]` channel is adopted, `get_state_history()` plus a `PlanStreamPart` extension (`libs/langgraph/langgraph/types.py:122`) gives versioned plan replay for free. Do not evaluate it as a failed planner; evaluate it as an execution fabric awaiting a `PlanChannel` middleware.

- **openai-agents-sdk (2):** Explicitly reactive — `ToolExecutionPlan` is internal scheduling, not a plan artifact, and discarding it avoids committing to a planning contract. Strength is clean per-turn fan-out isolation via `gather_with_cancel` at `src/agents/run_internal/tool_planning.py:984-1036`. For plan observability, the unshipped fix is minimal: `PlanSpanData` + `plan_item_id` on `ToolCallItem`/`FunctionSpanData` + `plan_snapshot` in `RunState` (extending `CURRENT_SCHEMA_VERSION` at `src/agents/run_state.py:191`) before `_execute_tool_plan`.

- **openhands (4):** Most durable forensic base via ordered file-per-event `EventLog` and `EventServiceBase` pagination, but hamstrung by positional `TaskItem` with no stable `id`, no `plan_item_id` on actions, whole-list `plan` replace robustness, and split telemetry (`TASKS.json` vs `.agents_tmp/PLAN.md` at `_sdk_inspect/tools/planning_file_editor/definition.py:98-110` with legacy path ambiguity). The reports' future-work consensus — stable IDs + `parent_plan_version` + `plan-vs-execution diff` UI interleaving `TaskTrackerObservation`/`PlanningFileEditorObservation` with `ActionEvent` — would move this source to the top of Model 2.

- **pydantic-ai (2):** The isolated source's absence is honest and documented — planning lives in `pydantic-ai-harness` (`docs/capabilities/third-party.md:8-11`). Inside the boundary, `ModelMessage`/`run_id`/`tool_call_id` history, spec-compliant OTel, and `pydantic-graph` control-flow instrumentation are capable substrates, but `Graph` models topology not task plans, and `pydantic_evals` trajectory scorers remain execution proxies.
