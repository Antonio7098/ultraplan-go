## Executive Summary

Four sources were studied for this dimension; three produced substantive evidence and one (`langgraph`) was an empty local checkout, contributing a no-evidence gap rather than a negative finding about the upstream project.

The dominant finding is a shared architecture shape: **none of these systems builds one global lock manager**. Each places synchronization at the resource owner — striped file locks in agent-framework's session stores (`python/packages/core/agent_framework/_sessions.py:1902-1905`), a capacity-1 semaphore per workflow run in temporal (`service/history/workflow/context.go:116`), conversation-directory leases owned by openhands' separate backend (`scripts/dev-safe.mjs:1136-1148`) — and then backs the in-process coordination with a *durable layer below*: OS-atomic file writes (`os.replace`, `O_EXCL|O_NOFOLLOW`) in agent-framework, database conditional writes guarded by fencing tokens in temporal (`common/persistence/cassandra/mutable_state_store.go:25-31`), and TTL'd disk leases in openhands' backend contract.

Maturity tracks operational stakes rather than engineering quality. Temporal, a distributed multi-host server that must survive failover mid-write, earns 9/10 with layered fencing, typed conflict errors, priority preemption, and a runtime deadlock detector. Agent-framework, an in-process framework where cross-process coordination is explicitly out of scope, earns 7/10 with tested serialization but no contention telemetry and no lock-acquisition timeouts. The analyzed openhands slice is a frontend with no authority to lock anything; it scores 5/10 by observing and repairing a backend lease model it cannot see inside.

For the dimension's guiding question — *can two tools edit the same file safely?* — the evidence answers **yes within one process** for agent-framework (serialized writes plus atomic replace, proven by concurrency tests at `python/packages/core/tests/core/test_sessions.py:1736-1793`), **yes by construction** for temporal's analogous case of two concurrent updates to one workflow (per-run semaphore plus DB-level CAS rejecting stale writers, `common/persistence/cassandra/errors.go:48-104`), and **undecidable from within the source** for openhands, whose UI is deliberately a read-only observer so user-vs-agent conflicts cannot originate there (`src/components/features/files/file-list.tsx:1`). LangGraph cannot answer it from the current checkout.

## Core Thesis

Resource safety in these harnesses follows one principle implemented three ways: **isolate through ownership boundaries, coordinate cheaply in-process, and arbitrate durably below the process**. No source trusts its locks alone for cross-owner safety. Agent-framework's locks are backed by atomic filesystem operations so crash-consistency survives lock failure (`python/packages/core/agent_framework/_sessions.py:2022`); temporal's semaphores are backed by database CAS conditions so a stale owner after failover gets a typed error instead of corrupting state (`common/persistence/cassandra/errors.go:116-159`); openhands' frontend trusts nothing locally and instead repairs the backend's lease fallout with probe-guarded cleanup (`scripts/dev-safe.mjs:1150-1182`). Which bottom layer a system chooses — filesystem, database, or another service's lease file — is dictated by product shape (library vs. distributed server vs. UI over a service) far more than by design quality. The practical lesson is not "copy temporal everywhere" but "know which failures your layer must survive and put exactly enough arbitration below your locks to survive them."

## Approach Models

Three distinct approach models emerge from the analyzable sources, each answering "who owns the resource and who arbitrates conflict?" differently:

- **Owner-embedded decentralized locking (agent-framework).** There is no central lock manager; every subsystem embeds its own synchronization and documents its scope inline — shell sessions declare themselves single-owner ordering primitives ("There is no per-caller isolation", `python/packages/tools/agent_framework_tools/shell/_session.py:11-19`), session files use 64-way hash-striped thread locks plus per-event-loop asyncio locks (`python/packages/core/agent_framework/_sessions.py:1902-1905`, `_sessions.py:2438-2455`), and foreign-runtime sandboxes are wrapped in single-thread actor confinement (`python/packages/hyperlight/agent_framework_hyperlight/_execute_code_tool.py:101-131`). Isolation between tenants comes from ownership contracts and container boundaries, not from mediating shared access.
- **Layered defense-in-depth fencing (temporal).** Four independent layers fence each other: DB conditional writes assert `IF range_id = ?` and per-row version conditions (`common/persistence/cassandra/mutable_state_store.go:25-31`); shard leases bump a monotonic `RangeId` epoch renewed under drain semantics (`service/history/shard/context_impl.go:1162-1206`); each workflow run serializes behind a capacity-1 priority semaphore reached only through the cache's lock-and-release protocol (`service/history/workflow/cache/cache.go:304-325`); and task-queue partitions gate their own persistence behind a single-writer mutex placed specifically to dodge concurrent-Cassandra-LWT timeouts (`service/matching/db.go:90-95`). A runtime deadlock detector probes the hottest locks on an interval (`common/deadlock/deadlock.go:41-59`).
- **Delegated coarse leasing with observe-and-repair edges (openhands).** The actual lock manager lives in a separate backend service; the analyzed frontend sees only the contract — each conversation directory carries `owner_lease.json` binding it to one agent-server instance for a 45-second heartbeat-refreshed TTL (`scripts/dev-safe.mjs:1136-1148`). The frontend contributes the recovery protocol: probe the port to prove staleness before unlinking leases (`scripts/dev-safe.mjs:1113-1133`, used at `scripts/dev-static.mjs:592-618`), allocate ports with documented race acceptance and named-port collision diagnostics (`scripts/dev-safe.mjs:200-299`), serialize UI commands over one FIFO-correlated WebSocket channel with total-teardown semantics (`src/hooks/use-bash-command-runner.ts:49-206`), and defeat read staleness with a monotonic mutation counter instead of locking (`src/stores/use-workspace-mutation-counter.ts:1-53`).
- **(langgraph)** — no approach model could be characterized; the checkout contains zero files (`studies/agent-harness-study/sources/langgraph.ultraplan-source.yml:1-2` identifies the intended upstream).

## Pattern Catalog

Patterns included because they appear in multiple sources or are demonstrated unusually clearly in one:

### 1. Striped / keyed locks for large key spaces
- **Problem:** Thousands of small resources (session files, arbitrary IDs) need serialization without serializing everything or allocating a lock per item.
- **Demonstrated by:** agent-framework maps file paths onto a fixed pool of 64 class-level `threading.Lock`s via `hash(path) % 64` (`python/packages/core/agent_framework/_sessions.py:2067-2070`); temporal provides a reusable hash-sharded `IDMutex` with refcounted entries deleted on last unlock (`common/locks/id_mutex.go:11-15`, `:64-98`); openhands allocates multiple ports sequentially "to avoid race conditions between checks" (`scripts/dev-safe.mjs:287-299`).
- **Why it works:** Bounded memory, no per-instance setup, collisions probability-limited by stripe count while unrelated keys proceed in parallel.
- **Copy when:** Many independent keyed resources with low expected contention per key.
- **Overkill/risky when:** Hot keys cluster — agent-framework notes stripe collision is benign but unobservable (`_sessions.py:1902-1905`), and temporal leaves `IDMutex` fairness unparameterized (`common/locks/id_mutex.go:11-15`). If you need fair queuing on a hot key, striping hides the problem.

### 2. Durable backstop beneath in-process locks (atomic ops / conditional writes)
- **Problem:** In-process locks say nothing about crashes, torn writes, or cross-process owners.
- **Demonstrated by:** agent-framework writes snapshots via temp-file + `os.replace` and creates-if-absent via `O_CREAT|O_EXCL|O_NOFOLLOW`, closing probe-then-open symlink races (`python/packages/core/agent_framework/_sessions.py:2022`; `python/packages/core/agent_framework/_harness/_file_access.py:891-930`); temporal makes every persistence mutation a DB-guarded CAS so "even a buggy or stale owner cannot corrupt state" (`common/persistence/cassandra/mutable_state_store.go:25-31`), mirrored in SQL via row locks plus Go-side condition checks (`common/persistence/sql/execution_util.go:573-596`).
- **Why it works:** Crash-consistency and stale-owner protection stop depending on lock correctness alone.
- **Copy when:** Durability matters at all — which is essentially always for persisted state.
- **Cost:** Every writer must handle the backstop's failure mode gracefully (typed conflict errors, quarantine paths), or the backstop just converts silent corruption into noisy errors.

### 3. Fencing tokens / expiring leases validated below the application
- **Problem:** Ownership can outlive validity — failover, hard kills, restarts faster than timeouts.
- **Demonstrated by:** temporal bumps `RangeId` on shard and queue takeover with DB templates enforcing `IF range_id = ?`, so old hosts self-detect via `ShardOwnershipLostError` (`service/history/shard/context_impl.go:1180-1184`; `common/persistence/cassandra/shard_store.go:37`; `service/matching/db.go:150-174`); openhands' backend binds conversations to an `owner_instance_id` with a 45 s heartbeat TTL, surfacing `ConversationLeaseHeldError` on conflict (`scripts/dev-safe.mjs:1136-1148`).
- **Why it works:** A stale owner cannot silently win; the storage or contract layer rejects it with a distinguishable signal.
- **Copy when:** Any second process can own the same resource — including "a restarted copy of yourself."
- **Overkill when:** Strictly single-process; agent-framework explicitly chooses documented last-writer-wins instead (`python/packages/core/agent_framework/_sessions.py:1878-1898`), which is coherent for a library.

### 4. Fail-fast bounded acquisition over indefinite waits
- **Problem:** Queued work behind a wedged holder turns contention into unbounded latency or hangs.
- **Demonstrated by:** temporal clamps lock deadlines and converts timeout into visible `ErrResourceExhaustedBusyWorkflow` (`service/history/workflow/cache/cache.go:327-357`), and all blocking acquisitions take a context and abort on cancellation (`common/locks/priority_semaphore_impl.go:83-121`); openhands rejects all queued/in-flight bash commands on socket error/close/unmount and watchdog-aborts hung handshakes (`src/hooks/use-bash-command-runner.ts:82-85`, `:141-174`).
- **Why it works:** Contention becomes a fast, diagnosable outcome callers can retry, not a mystery hang.
- **Divergence worth noting:** agent-framework lacks general acquisition timeouts — a command holding the shell `_run_lock` queues successors indefinitely, mitigated only by command-timeout/interrupt respawn (`dotnet/src/Microsoft.Agents.AI.Tools.Shell/ShellSession.cs:63-66`). This is the clearest single maturity gap between the 7 and the 9 in this study.
- **Copy when:** Interactive latency matters. Cost: clients must implement retry.

### 5. Probe-before-destructive-action (compare/guard, then act)
- **Problem:** Cleanup and recovery operations can destroy live state if their premise went stale.
- **Demonstrated by:** openhands requires a TCP liveness probe before unlinking any lease (`scripts/dev-safe.mjs:1113-1133`, `:1150-1153`); agent-framework's reader re-reads a snapshot immediately before quarantining so it never removes a concurrently replaced file (`python/packages/core/agent_framework/_sessions.py:2055-2065`); temporal drains in-flight requests before bumping the fencing epoch so conditioned requests fail cleanly (`service/history/shard/context_impl.go:1163-1169`).
- **Why it works:** Converts "cleanup raced live work" from corruption into a checked precondition.
- **Caveat:** openhands shows the weak form — the probe is caller discipline, not an enforced mechanism (`scripts/dev-safe.mjs:1150-1153`); temporal's drain is structural and stronger.

### 6. Deadlock prevention: structural avoidance first, detection second
- **Problem:** Nested multi-lock code paths invite ABBA deadlocks.
- **Demonstrated by:** agent-framework prevents structurally — batch approval locks sorted by identity before acquisition (`python/packages/ag-ui/agent_framework_ag_ui/_approval_lifecycle.py:753-756`) and MCP connect/close marshalled through a single lifecycle-owner task instead of nested locks (`python/packages/core/agent_framework/_mcp.py:1163-1193`); temporal adds runtime detection — two documented ordering rules (`service/history/shard/context_impl.go:123-128`; `common/namespace/nsregistry/registry.go:125-129`) plus a pluggable detector that pings registered hot locks and can dump goroutines, fail health checks, or abort the process (`common/deadlock/deadlock.go:111-128`). Openhands has the trivially safe variant: nothing acquires two locks at all.
- **Why it works:** Sorted acquisition removes the cycle structurally; owner-task marshalling removes nesting entirely; detection catches whatever discipline misses.
- **Shared weakness:** Neither mature source mechanically enforces ordering — temporal says so outright, and agent-framework carries a maintenance comment mandating a lock replacement if a method ever goes async (`dotnet/src/Microsoft.Agents.AI.Workflows/Execution/FanInEdgeState.cs:39-41`).

### 7. Isolation via ownership contracts and sandbox boundaries, not shared mediation
- **Problem:** Multi-tenant safety without paying coordination costs on every operation.
- **Demonstrated by:** agent-framework declares shells single-owner per conversation/user with loud documentation but no runtime enforcement (`python/packages/tools/agent_framework_tools/shell/_session.py:16-19`), hardens containers by default (`--network none`, non-root UID, read-only rootfs, capability drop; `python/packages/tools/agent_framework_tools/shell/_docker.py:68-73`; `dotnet/src/Microsoft.Agents.AI.Tools.Shell/DockerShellExecutor.cs:384-394`), validates that escape-hatch args cannot weaken those flags (`python/packages/tools/tests/test_docker_shell_tool.py:231-235`), and confines micro-VM sandboxes to a single worker thread (`python/packages/hyperlight/agent_framework_hyperlight/_execute_code_tool.py:101-131`); temporal names namespace its isolation boundary and delegates worker-code sandboxing to SDKs by architecture (`service/frontend/workflow_handler.go:458-461`).
- **Copy when:** Tenants need real isolation (untrusted code, cross-user state).
- **Risk:** Contract-only enforcement leaks silently — agent-framework warns that naive tool-instance sharing causes cross-tenant leakage with nothing enforcing it at runtime.

### 8. Optimistic staleness control for readers
- **Problem:** Readers must see fresh externally-mutated data without locking writers.
- **Demonstrated by:** openhands bumps a monotonic workspace-mutation counter on every agent edit and cache-busts file URLs with it (`src/stores/use-workspace-mutation-counter.ts:36-52`); agent-framework accepts concurrent mutation and quarantines corruption with compare-before-move rather than blocking writers (`python/packages/core/agent_framework/_sessions.py:2055-2065`).
- **Copy when:** One side is a pure reader/UI. Not applicable when read-modify-write cycles exist.

### 9. Idempotent, panic-safe release (single-source showcase)
- **Problem:** Exceptions or double-unlocks during release poison the resource for everyone after.
- **Demonstrated clearly by:** temporal's release closure uses compare-and-swap-once semantics, recovers panics, force-clears dirty state (fail-stop panic if dirty post-release), records hold duration, and still guarantees unlock exactly once (`service/history/workflow/cache/cache.go:359-405`).
- **Copy when:** Any lock acquired across complex, fallible work. This pattern is cheap insurance that only temporal demonstrates end-to-end.

### 10. Collect-under-lock, flush-outside-lock (single-source showcase)
- **Problem:** Holding a lock across awaitable I/O multiplies contention and deadlock surface.
- **Demonstrated clearly by:** agent-framework's `RunPersistenceGate` swaps the pending list inside the lock and executes persistence callbacks after releasing it (`dotnet/src/Microsoft.Agents.AI.AgentHooks/Core/RunPersistenceGate.cs:27-61`); the same concern appears as an ordering rule in temporal — never acquire the shard `ioSemaphore` while holding `rwLock` (`service/history/shard/context_impl.go:123-128`).
- **Copy when:** Any lock scope would otherwise span network/disk I/O.

## Key Differences

- **Central primitives library vs. scattered owner-embedded locks.** Temporal ships a dedicated `common/locks` package with interfaces (`Locker`), sharded mutexes, and tested priority semaphores (`common/locks/lock.go:3-10`; `common/locks/priority_semaphore_test.go:53-100`). Agent-framework deliberately scatters primitives at each resource owner with inline scope statements (`dotnet/src/Microsoft.Agents.AI.Tools.Shell/ShellSession.cs:74-80`), keeping coupling low but making guarantees vary per package. Openhands embeds none, because it holds no resources. This is product shape, not quality: a server reused across subsystems benefits from a shared library; a plugin-style framework does not.
- **Observability of contention.** Temporal exposes acquisition-failure counters, hold-duration histograms, deadlock gauges, and per-lock ping latency (`service/history/workflow/cache/cache.go:315-372`; `common/deadlock/deadlock.go:114-151`). Openhands surfaces named-port collision errors, lease-release counts in startup logs, and mutation-counter-driven refetches (`scripts/dev-safe.mjs:277-284`; `scripts/dev-static.mjs:611-618`). Agent-framework has **no lock-contention telemetry anywhere in core** — LWW overwrites happen silently by design (`python/packages/core/agent_framework/_sessions.py:1893-1896`). This is the widest spread on any axis in the study.
- **Cross-process story.** Temporal assumes hostile concurrency across hosts and fences accordingly; openhands' backend uses disk leases with TTLs precisely because processes die hard (`scripts/dev-safe.mjs:1141-1148`); agent-framework explicitly declines the problem, documenting LWW and pushing multi-host coordination to hosting stores (`python/packages/core/agent_framework/_sessions.py:1893-1898`). All three positions are defensible; only temporal's is *proven under failover* (handover-rejection tests at `service/history/shard/handover_events_test.go:161-165`).
- **Lock granularity.** Temporal is finest — one token per workflow *run*, per-partition queue managers, hash-sharded ID mutexes (`service/history/workflow/context.go:116`; `common/locks/id_mutex.go:18-28`). Agent-framework is deliberately mixed: fine stripes for session files but one provider-wide write lock serializing all harness file tools even on *different* files (`python/packages/core/agent_framework/_harness/_file_access.py:1338-1343`). Openhands is coarsest — whole conversation directories and whole ports, nothing finer (`scripts/dev-safe.mjs:1171`).
- **Sandbox boundaries.** Only agent-framework implements executable-isolation boundaries in-source: hardened Docker defaults whose weakening args are testably rejected, plus Hyperlight micro-VM actor confinement (`python/packages/tools/tests/test_docker_shell_tool.py:231-235`; `python/packages/hyperlight/agent_framework_hyperlight/_execute_code_tool.py:110-125`). Temporal architecturally excludes user code from the server; openhands' execution lives in its absent backend. Consequence: the "sandbox config" evidence area is satisfiable only by the framework source.
- **Deadlock posture.** Structural prevention (agent-framework, openhands) versus prevention-plus-runtime-detection (temporal). Detection buys coverage of unknown future violations at the cost of tuning risk — temporal's `AbortProcess` mode fatals on suspicion if budgets are mis-set (`common/deadlock/deadlock.go:125-127`).

## Tradeoffs

- **Fencing + CAS vs. documented last-writer-wins.** Temporal gains stale-owner immunity and typed conflicts (`common/persistence/cassandra/errors.go:146-159`) at the cost of every write carrying version preconditions and every client handling ranked conflict errors. Agent-framework avoids all that machinery for a library (`python/packages/core/agent_framework/_sessions.py:1878-1898`) and pays with silent cross-process data loss. Best-fit rule: pay for fencing the moment a second owner (another host, a restarted process, a human operator) can touch the same durable state.
- **Fail-fast busy errors vs. queued waiting.** Temporal's deadline clamping yields predictable latency but forces client retry loops (`service/history/workflow/cache/cache.go:351-354`); openhands' reject-everything teardown loses results rather than retrying them (`src/hooks/use-bash-command-runner.ts:141-174`). Both trade throughput-under-contention for diagnosability. Failure mode either way: retry storms without backoff.
- **Coarse provider-wide locks vs. per-key locks.** Agent-framework's single `FileAccessProvider._write_lock` makes read-modify-write tools safe across agents sharing one store but serializes unrelated edits (`python/packages/core/agent_framework/_harness/_file_access.py:1338-1342`); temporal recovers parallelism with per-run tokens and keeps shard-level coarseness only where lease/failover semantics demand it, using an I/O semaphore to stop coarse shard locking from throttling persistence (`service/history/shard/context_impl.go:123-137`). Coarse-first is cheaper to prove correct; fine-grained should be earned by measured contention.
- **Structural deadlock avoidance vs. runtime detection.** Sorted acquisition and owner-task marshalling cost nothing at runtime but only cover known patterns; temporal's detector covers unknown ones but needs per-lock time budgets and can mis-fire fatally (`common/deadlock/deadlock.go:125-127`). Mature systems eventually want both — but detection is the later investment.
- **Contract-based isolation vs. enforced isolation.** Single-owner shell contracts keep the common case free of coordination (`python/packages/tools/agent_framework_tools/shell/_session.py:11-19`) but rely on hosts reading documentation; the alternative — runtime ownership tokens — is listed in agent-framework's own future work. Openhands' read-only UI eliminates user-agent write conflicts *by construction* at the cost of functionality (`src/components/features/files/file-list.tsx:1`): eliminating a conflict class by removing the capability is legitimate, sometimes the cheapest isolation there is.
- **Accepted races vs. eliminated races.** Openhands accepts the port check-then-use window with `strictPort` fail-fast mitigation (`scripts/dev-safe.mjs:207-212`); temporal eliminates its equivalent by draining before fencing (`service/history/shard/context_impl.go:1163-1169`). Acceptance is fine when blast radius is one developer's dev server; unacceptable when it is production state.

## Decision Guide

Choosing between the models found in these sources:

1. **Building a library/framework running inside one process?** Use the agent-framework model: locks embedded at each resource owner, striped keyed locks for file-shaped key spaces, atomic OS operations as the durability backstop, and explicitly document what you do not support (cross-process LWW). Do not build leases you cannot enforce.
2. **Multiple processes or hosts can own the same durable resource?** Use the temporal model, in ascending order of necessity: (a) conditional writes/CAS at the storage layer first — it is the highest-value single investment; (b) fencing epochs on ownership handover next; (c) a central, tested primitives library once several subsystems share lock needs; (d) runtime deadlock detection last, when scale makes unknown violations plausible.
3. **Building a client/UI over a system that owns the locking?** Use the openhands model: never invent local arbitration; make the backend's conflict signals (`ConversationLeaseHeldError`) visible; implement guarded repair flows (probe before cleanup); prefer fail-fast teardown over optimistic waiting; use monotonic counters for reader freshness.
4. **Executing untrusted code?** Sandbox boundaries are mandatory regardless of model — agent-framework is the only source with in-scope evidence: default-deny container flags, validated escape hatches, and thread confinement for FFI-bound runtimes (`python/packages/tools/agent_framework_tools/shell/_docker.py:68-73`).
5. **Have both background and interactive consumers of the same locks?** Temporal's priority semaphore lets APIs preempt timer/replication holders (`common/locks/priority_semaphore_impl.go:46-58`) — adopt priorities only when that split actually exists; otherwise plain capacity-1 mutual exclusion is simpler and sufficient.

## Practical Tips

Patterns worth copying:

- Stripe or hash-shard locks over large key spaces; reuse a tested primitive like temporal's refcounted `IDMutex` rather than ad-hoc maps of locks (`common/locks/id_mutex.go:64-98`).
- Put an atomic/conditional backstop under every durable mutation — `os.replace` + `O_EXCL` at minimum (agent-framework), storage-layer CAS if multi-writer is possible (temporal).
- Clamp acquisition deadlines and convert timeouts into typed, actionable errors (`ErrResourceExhaustedBusyWorkflow`).
- Make conflict failures *typed and ranked* so callers can prioritize responses — temporal scans failed CAS batches and emits `ShardOwnershipLostError` above generic condition failures (`common/persistence/cassandra/errors.go:88-104`).
- Quarantine corrupt state instead of deleting it, with a re-check before moving (agent-framework, `_sessions.py:2055-2065`).
- Keep critical sections I/O-free: collect under lock, flush outside (agent-framework `RunPersistenceGate`; temporal's ioSemaphore-after-rwLock ordering rule).
- Write concurrency tests that inject slow writers and assert serialization, as agent-framework does for history writes and todo mutations (`python/packages/core/tests/core/test_sessions.py:1736-1793`; `test_harness_todo.py:322`).

Patterns to delay until needed:

- Runtime deadlock detectors (tuning burden, abort risk) — add after lock-count and call-path growth outruns review discipline.
- Priority semaphores — only with a genuine interactive/background split.
- Cross-process leasing/fencing — only when a second owner becomes possible; until then documented LWW plus atomic replace is honest and simpler.
- Per-key locks inside coarse-locked providers — measure contention first; agent-framework's coarse harness lock is correct and only becomes a problem under parallel-agent load.

Caution signs that the locking design is going brittle:

- No acquisition timeout anywhere in a system whose commands can wedge (agent-framework's exact gap).
- Lock scopes creeping across `await`/I/O boundaries.
- Race acceptance documented in docstrings instead of fixed or tested (openhands' port window; its untested `releaseStaleConversationLeases()`).
- Security-relevant state structures left unsynchronized while everything around them is locked (agent-framework's `ContentVariableStore`, `python/packages/core/agent_framework/security.py:345-347`).
- Lock-ordering rules accumulating as comments across components — the count of such comments is a leading indicator of future deadlock bugs in both agent-framework and temporal.

## Anti-Patterns / Caution Signs

- **Documentation-only ownership contracts.** "One session per conversation" that nothing enforces at runtime invites silent cross-tenant leakage when a host shares a tool instance naively (`python/packages/tools/agent_framework_tools/shell/_session.py:16-18`). If a contract is safety-critical, enforce it with an ownership token or equivalent.
- **Denylist validation of dangerous capabilities.** Agent-framework rejects isolation-weakening docker args via `_validate_extra_run_args`, which must chase every new dangerous flag forever (`python/packages/tools/tests/test_docker_shell_tool.py:231-235`). Prefer allowlists or structural impossibility.
- **Caller-obligation safety invariants.** Openhands mandates "probe the port before unlinking leases" by convention only (`scripts/dev-safe.mjs:1150-1153`); compose the guard and the destructive action into one mechanism instead.
- **Single multiplexed channel with total teardown.** One bash WebSocket serving all UI commands means any `BashError` rejects every outstanding command and slow commands head-of-line block later ones (`src/hooks/use-bash-command-runner.ts:136-149`). Fine for a dev tool; hazardous above that scale without per-command timeouts or cancellation.
- **Silent last-writer-wins on user-visible state.** Losing a writer without an error or metric (`python/packages/core/agent_framework/_sessions.py:1893-1896`) is acceptable only when explicitly surfaced to operators — here it is not observable at all.
- **Unobservable correctness mechanisms.** Stripes, quarantines, and LWW overwrites in agent-framework produce no metrics; when something is slow or lossy, operators cannot distinguish contended from broken. Temporal demonstrates the fix is not expensive: counters and histograms around acquire/release (`service/history/workflow/cache/cache.go:315-372`).
