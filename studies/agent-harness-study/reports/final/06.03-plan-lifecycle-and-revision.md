## Executive Summary

No source except Temporal (8/10) provides a durable, versioned, explainable plan lifecycle. The field splits into three camps: **Todo-list planners** (agent-framework, crewai) that have explicit steps but overwrite history; **no-plan harnesses** (letta, openai-agents-sdk, pydantic-ai) that delegate decomposition to the LLM or to graph topology; and **engine/history infrastructures** (langgraph, Temporal) that provide generic checkpoint/replay but no plan semantics. OpenHands is a separate outlier: a single `PLAN.md` markdown file edited by a planning agent.

Creation is the most mature phase everywhere — every todo harness can create typed steps, and every engine can compile a graph or start a run. Update and replanning diverge immediately: crewai separates lightweight description tweaks from full regeneration (`lib/crewai/src/crewai/agents/planner_observer.py:215`, `lib/crewai/src/crewai/utilities/planning_types.py:185`), agent-framework gates completion on a `reason` string (`python/packages/core/agent_framework/_harness/_todo.py:162`), while letta/openai-agents-sdk/pydantic-ai have no plan-mutation API at all. Langgraph and Temporal mutate state or history but not a typed plan.

Revision history is the systemic gap: five sources keep only an in-memory snapshot or overwrite the file (`python/packages/core/agent_framework/_harness/_todo.py:265`, `frontend/src/stores/conversation-store.ts:35`); two keep execution history (model messages, checkpoints) but not plan diffs (`sources/openai-agents-sdk/src/agents/run_state.py:1774`, `libs/langgraph/langgraph/pregel/_checkpoint.py:149`); only Temporal keeps an immutable, branchable event log (`service/history/historybuilder/history_builder.go:163`). Drift detection exists only in crewai/Magentic's LLM-judged `is_in_loop`/`is_progress_being_made` stall counter (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109`) and Temporal's determinism guard (`service/frontend/workflow_handler.go:1313`); everywhere else it is prompt advice or absent.

The central lesson: if you want to answer "why did the plan change?" you must add a versioned `PlanRevision{version, parent, reason, diff}` store yourself — none of the agent harnesses ships it.

## Core Thesis

**Plan lifecycle maturity is inversely correlated with plan concreteness.** Sources that reify a plan as code/topology/history (Temporal, langgraph) get durability, branching, and replay for free but have nothing typed to validate or drift-check. Sources that reify a plan as a todo list (crewai, agent-framework) get typed steps, dependency-aware scheduling, and per-step observation but sacrifice durability — they overwrite pending items, keep `execution_log` only in memory, and clear on `invoke()` (`lib/crewai/src/crewai/experimental/agent_executor.py:2879`). Sources that refuse to reify a plan at all (letta, openai-agents-sdk, pydantic-ai) are the most flexible with any LLM but the least auditable: the only justification is the transcript.

Two convergences hold despite those differences:

1. **Completion is always a predicate on remaining work or a terminal event**, never a content validator: `todos_remaining` (`python/packages/core/agent_framework/_harness/_loop.py:773`), `TodoList.is_complete` (`lib/crewai/src/crewai/utilities/planning_types.py:67`), schedulability (`libs/langgraph/langgraph/pregel/_loop.py:652`), `RunState.current_turn > max_turns` (`sources/openai-agents-sdk/src/agents/run.py:1477`), `setStateStatus` (`service/history/workflow/mutable_state_state_status.go:16`). No harness validates "output satisfies plan" — that is delegated to LLM synthesis or trusted.

2. **Abandonment is always implicit**, even where it is explicit in the state machine: todos are removed, state is cleared, a new `RunId` is forked, or `END` is routed. No source emits a `plan_abandoned(reason)` lifecycle event that survives for audit.

## Approach Models

Sources cluster into five models. A source can appear in more than one row.

### A. Todo-List / Structured Steps (explicit, mutable, overwriting)

**agent-framework, crewai.** Plan is `TodoItem(id, title, description, is_complete)` or `PlanStep → TodoItem(status in pending/running/completed/failed)` (`python/packages/core/agent_framework/_harness/_todo.py:45`, `lib/crewai/src/crewai/utilities/planning_types.py:11`). Lifecycle: `todos_add/complete/remove` or `apply_refinements` vs `replace_pending_todos`; completion is `is_complete` or count-zero; replanning is user-feedback-driven or `PlannerObserver` LLM judgment with `reasoning_effort` gating. Strength: typed steps, dependency-aware `get_ready_todos`/`can_parallelize` (`lib/crewai/src/crewai/utilities/planning_types.py:112`), serialization with mutation locks. Weakness: snapshot persistence only — no `revision_id`, no diff chain.

Best-fit: single-agent task decomposition where the LLM plans and executes within one session and audit beyond the session is not required.

### B. File-as-Plan (human-readable, isolated)

**openhands.** Plan is `.agents_tmp/PLAN.md` with 5 markdown headers (`_sdk_inspect/tools/preset/planning.py:14`), produced by `AgentType.PLAN` sub-conversation and edited only through `PlanningFileEditorTool` (`_sdk_inspect/tools/planning_file_editor/definition.py:62`). Lifecycle is prompt-driven phases (Understand → Plan → Synthesize → Refine) with no state machine. Strength: inter-agent contract without serialization; visible in workspace. Weakness: raw file mutations, no per-revision metadata, Build has no completeness gate.

Best-fit: coding agents where plan review by a human before execution is the primary goal and the execution agent can read a file.

### C. No Plan — Reactive / Turn-Loop (implicit, model-owned)

**letta, openai-agents-sdk, pydantic-ai.** No `Plan` class exists (`letta/schemas/tool_rule.py:13` shows zero `class Plan`; `pydantic_graph/basenode.py:33` same). Plan is the model's next token or the graph's next node return (`pydantic_graph/basenode.py:37`). Lifecycle is run/step lifecycle: `LettaAgentV3.step() for i in range(max_steps)` (`letta/agents/letta_agent_v3.py:328`), `Runner.run → SingleStepResult.next_step` (`sources/openai-agents-sdk/src/agents/run_internal/run_steps.py:171`), `BaseNode.run → End` (`pydantic_graph/basenode.py:61`). Replanning is hook redirection (`capabilities/abstract.py:567`), handoff, or simply the next LLM call.

Best-fit: general-purpose chat/tool harnesses where decomposition is prompt-dependent and framework stays unopinionated.

### D. Engine-as-Plan — Graph/Channel Schedule (static topology + dynamic writes)

**langgraph.** Plan is the compiled `Pregel(nodes, channels, trigger_to_nodes)` (`libs/langgraph/langgraph/pregel/main.py:758`) plus per-superstep task set from `prepare_next_tasks` (`libs/langgraph/langgraph/pregel/_algo.py:392`). Lifecycle is BSP: `tick → apply_writes(versions_seen, channel_versions) → _put_checkpoint(source: loop/update/fork)` (`libs/langgraph/langgraph/pregel/_loop.py:599`). Changes via `Command(update, goto, Send)` (`libs/langgraph/langgraph/types.py:799`), `Send(node, arg)`, or `bulk_update_state` (`libs/langgraph/langgraph/pregel/main.py:1590`). History is checkpoint-generic.

Best-fit: durable DAG/state-machine workloads where topology should be versioned and replayable but decomposition itself is not LLM-generated.

### E. Execution-History-as-Plan — Event-Sourced Branching (durable, auditable)

**temporal.** Plan is the deterministic workflow program; history is the truth. Mutations funnel through `HistoryBuilder.add` (`service/history/historybuilder/history_builder.go:163`) into immutable events, tracked by `VersionHistories` branch tokens and rebuilt by `MutableStateRebuilder.ApplyEvents` (`service/history/workflow/mutable_state_rebuilder.go:72`). Lifecycle is `Start → Update/Signal/Cancel/Patch/ContinueAsNew/Reset → Completed/Failed/Terminated/TimedOut` under total `setStateStatus` (`service/history/workflow/mutable_state_state_status.go:16`). Drift is non-determinism, not semantic drift.

Best-fit: long-running, regulated, or multi-run workflows that need crash recovery, reset/fork, and cryptographic-grade audit of every revision.

## Pattern Catalog

### 1. Per-session serialized mutations with atomic file replace

**Problem:** Concurrent tool calls mutate the same plan store and race.
**Sources:** agent-framework (`python/packages/core/agent_framework/_harness/_todo.py:395`, `480`).
**Why it works:** `WeakKeyDictionary[AgentSession, asyncio.Lock]` plus `tmp.<pid>` → `os.replace` gives per-sessionmutual exclusion and crash-safe writes; `WeakKeyDictionary` auto-evicts on GC so no leak.
**When to copy:** Any todo store backed by JSON on disk or in session state where the LLM can fire `todos_add` twice in parallel.
**When overkill:** In-memory only stores within a `Flow` that already serializes triggers (langgraph can rely on `apply_writes` sorting).
**Evidence:** `python/packages/core/agent_framework/_harness/_todo.py:335-425`, `dotnet/src/Microsoft.Agents.AI/Harness/Todo/TodoProvider.cs:45`, `python/packages/core/tests/core/test_harness_todo.py:85-145`.

### 2. Reason-gated completion

**Problem:** Operator needs "why was step 7 closed?" without scraping transcript.
**Sources:** agent-framework `TodoCompleteInput(reason)` validated non-empty (`python/packages/core/agent_framework/_harness/_todo.py:160`); crewai `StepObservation.replan_reason`/`PlanReplanTriggeredEvent.replan_reason` (`lib/crewai/src/crewai/utilities/planning_types.py:271`); Magentic `MagenticProgressLedgerItem.reason` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:295`).
**Why it works:** Forces LLM to justify at the mutation site; minimal friction (one string field).
**When to copy:** Always for `complete`/`fail` transitions; leave `add` un-gated to keep planning fluid.
**When overkill:** If plan is never audited, free-text `reason` just adds prompt tokens.
**Evidence:** `python/packages/core/agent_framework/_harness/_todo.py:585-610`; `lib/crewai/src/crewai/events/types/observation_events.py:110-121`.

### 3. Tiered lightweight refinement vs full regeneration

**Problem:** Most drift is a description tweak, not a DAG change — full replan wastes tokens.
**Sources:** crewai `PlannerObserver.apply_refinements` mutates only `description` in-place (`lib/crewai/src/crewai/agents/planner_observer.py:215`) vs `TodoList.replace_pending_todos` full regeneration (`lib/crewai/src/crewai/utilities/planning_types.py:185`); agent-framework `todos_complete(reason)` vs `todos_remove` mirrors same split.
**Why it works:** Refinement is zero-LLM-call and preserves `status/depends_on/tool_to_use`; replan preserves completed/failed and rebuilds pending. Three-tier `reasoning_effort` routing (`lib/crewai/src/crewai/experimental/agent_executor.py:680`) lets cost track adaptivity.
**When to copy:** Any multi-step plan where observation is cheaper than replanning.
**When overkill:** Single-shot plans or when tool/dependency changes are frequent (refinement limited to `description` — `lib/crewai/src/crewai/agents/planner_observer.py:235` — then still forces replan).
**Evidence:** `lib/crewai/src/crewai/agents/planner_observer.py:113-242`; `lib/crewai/src/crewai/experimental/agent_executor.py:747-1013`.

### 4. Stall-counter drift detector with LLM progress ledger

**Problem:** Detect "stuck in loop / no progress" without a numeric metric.
**Sources:** agent-framework Magentic `is_in_loop`/`is_progress_being_made` → `stall_count +=1` else decrement; `stall_count > max_stall_count(3)` → `_reset_and_replan` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1109-1118`); crewai `remaining_plan_still_valid`/`needs_full_replan` LLM judgment (`lib/crewai/src/crewai/translations/en.json:88`) with `_should_replan` heuristics (`lib/crewai/src/crewai/experimental/agent_executor.py:2574`).
**Why it works:** Model self-assesses verifiably per step; counter debounces transient misjudgments.
**When to copy:** Multi-step loops where you can afford one extra LLM call per step (crewai `high` effort) or per inner-loop batch (Magentic).
**When risky:** LLM false-positive `is_in_loop` triggers premature `chat_history` clear; heuristic fallback defaults to `success=True` and hides failures (`lib/crewai/src/crewai/agents/planner_observer.py:208`).
**Evidence:** `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:310-345`, `385-393`.

### 5. Dependency-aware ready queue enabling DAG-parallel execution

**Problem:** Steps have `depends_on`; naive sequential execution wastes time; naive parallel breaks dependencies.
**Sources:** crewai `TodoList._dependencies_satisfied` treating `failed` as terminal + `get_ready_todos`/`can_parallelize` + `StepExecutionContext(task_goal, dependency_results)` (`lib/crewai/src/crewai/utilities/planning_types.py:112`, `lib/crewai/src/crewai/utilities/step_execution_context.py:13`) feeding `execute_todos_parallel` with `asyncio.gather` (`lib/crewai/src/crewai/experimental/agent_executor.py:1258`).
**Why it works:** Ready-set is recomputed from status, not re-planned; failed considered terminal prevents permanent block.
**When to copy:** Plans with fan-out/fan-in (research → synthesize patterns).
**When overkill:** Linear plans or single-tool agents.
**Evidence:** `lib/crewai/src/crewai/utilities/planning_types.py:90-154`; `lib/crewai/src/crewai/experimental/agent_executor.py:1105-1391`.

### 6. Append-only execution history as durable audit (without plan diff)

**Problem:** Process crashes lose plan state.
**Sources:** openai-agents-sdk `RunState.to_json` merging `model_responses + generated_items` with id/call_id dedup and 17 schema versions (`sources/openai-agents-sdk/src/agents/run_state.py:191`, `1707`); langgraph `Checkpoint(id=uuid6(step), channel_values, channel_versions, versions_seen)` with `DeltaChannel` walks (`libs/langgraph/langgraph/pregel/_checkpoint.py:149`); openhands `EventLog` append of `PlanningFileEditorObservation` (`_sdk_inspect/sdk/conversation/event_store.py:147`).
**Why it works:** Append-only plus monotonic IDs gives point-in-time replay and fork; even without plan semantics, operators can reconstruct intent by diffing successive messages/checkpoints.
**When to copy:** Any hosted multi-tenant service needing pause/resume or crash recovery.
**When gaps remain:** Overwriting a `plan` channel or `state.plan` string still requires manual diff — no `PlanRevision{version, diff, reason}`.

### 7. History-is-truth with branching resets (Temporal pattern)

**Problem:** Bad revision should not mutate history — it should fork it.
**Sources:** Temporal `ResetWorkflowExecution` rebuilds to `WorkflowTaskFinishEventId-1` and forks `resetRunID = uuid.NewString()` (`service/history/api/resetworkflow/api.go:136`), preserving base history; `ContinueAsNew` chains via `PrevRunID` (`service/history/workflow/mutable_state_impl.go:3011`); `VersionHistories` branch tokens (`service/history/workflow/mutable_state_rebuilder.go:101`).
**Why it works:** Correction is durably auditable and replayable; `checkMutability` rejects writes to completed/zombie runs (`service/history/workflow/mutable_state_impl.go:4947`).
**When to copy:** Workflows with retention, compliance, or cherry-pick-reset needs.
**When overkill:** Short-lived single-session agents where branching adds query complexity.

### 8. Deterministic non-determinism guard

**Problem:** Workflow code changed mid-run and would silently drift.
**Sources:** Temporal replays history and fails the workflow task with `WORKFLOW_TASK_FAILED_CAUSE_NON_DETERMINISTIC_ERROR` instead of advancing (`service/frontend/workflow_handler.go:1313`, `service/history/api/respondworkflowtaskcompleted/workflow_task_completed_handler.go:790`).
**Why it works:** Drift is fail-closed, not silent; `GetVersion`/`TemporalChangeVersion` markers make intentional drift explicit (`common/searchattribute/sadefs/constants.go:26`).
**When to copy:** Any deterministic replay engine (langgraph could add similar command-sequence validation — it already has `ValidateCommandSequence` at `service/history/api/...` for Temporal; langgraph's closest is budget-only via `RemainingSteps`).
**When overkill:** Pure LLM turn loops that are intentionally non-deterministic per call.

## Key Differences

| Concern | Choice A | Choice B | Why they differ |
|---------|----------|----------|-----------------|
| What is stored | Typed steps (`TodoItem`, `PlanStep`) — agent-framework, crewai | Messages/history only — letta, openai-agents-sdk, pydantic-ai | Step-typed sources target task decomposition UX; message-only sources stay unopinionated so any prompt works |
| How to mutate | In-place overwrite of file/snapshot — agent-framework, openhands | Versioned append + branch — Temporal; checkpoint chain — langgraph, openai-agents-sdk | Overwrite is simplest for single-session ergonomics; branching serves multi-run audit/compliance |
| Replanning grain | LLM observation per step (crewai `observe_steps`, Magentic progress ledger) | No replanning — next LLM call is the plan (letta, openai, pydantic) | Per-step observation costs a model call; reactive sources avoid that cost entirely |
| Justification | Required `reason` on complete/replan (agent-framework, crewai) | No reason field (langgraph `Command`/`StateUpdate`, letta `Step`, pydantic hooks) | Justification only matters if audit/compliance matters; infrastructure engines treat reason as user payload, not framework field |
| Completion signal | Count-zero `todos_remaining`/`TodoList.is_complete` (agent-framework, crewai) | Schedulability empty + `status=done` (langgraph) / total state machine `setStateStatus` (Temporal) / `max_turns` or `is_request_satisfied` (Magentic/letta) | Count-zero fits todo lists; schedulability fits BSP; state-machine fits long-running workflows |
| Abandonment | `todos_remove` / `failed` as terminal / `goal_achieved` skip (agent-framework, crewai) | `RunState` dropped / `cancel(mode)` / `delete_thread` / `Abandon as empty plan patch` | Todo sources can surgically delete; run-scoped sources only abandon the whole run |
| History durability | `durability="exit"` hides intermediate revisions; no `checkpointer` → no history (langgraph) vs `BlockHistory` for memory not plan (letta) | `Step`/`Run` rows + WAL `HistoryBuilder` always durable (letta Step, openai RunState, Temporal) | Langgraph defers to user to configure a `BaseCheckpointSaver`; Temporal always persists before advancing |
| Drift story | Stall counter + `remaining_plan_still_valid` LLM flag (crewai, Magentic) | Determinism violation (Temporal) vs nothing | Stall counters suit LLM drift; determinism suits code drift; nothing suits "drift is the model's problem" |

## Tradeoffs

### Explicit typed plan vs implicit emergent plan
- **Typed (crewai, agent-framework):** Benefit — dependency-aware scheduling, structured observation, testable `is_complete`. Cost — schema debt, overwrite-without-history, refinement limited to `description`. Fails when plan needs tool/edge changes or cross-session replay. Alternative is reactive next-token planning (letta) which has zero schema cost but cannot be validated.
- **Implicit (letta, openai, pydantic):** Benefit — zero planning boilerplate, works with any instruction. Cost — no `plan_version`, no diff, no drift metric; "explain why plan changed" requires transcript parsing. Fails under audit or on compaction where reasoning text is evicted (`letta/prompts/summarizer_prompt.py:178`).

### In-place overwrite vs versioned history
- **Overwrite (`python/packages/core/agent_framework/_harness/_todo.py:265`, `frontend/src/stores/conversation-store.ts:35`):** Benefit — simplest persistence, atomic replace prevents corruption (`python/packages/core/agent_framework/_harness/_todo.py:410`). Cost — lost `why`/`when`; recovery needs file-level backups. Alternative is Temporal-style `VersionHistories` branching or langgraph checkpoint chain which preserves everything but requires traversing ancestors and handling `prune`/`DeltaChannel` ancestry gaps (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:378`).
- **Versioned (Temporal, langgraph checkpoints, openai RunState):** Benefit — replay, fork, reset. Cost — pruned deltas can silently reconstruct as empty; openai `RunState` warns about ambiguous history requiring application repair (`sources/openai-agents-sdk/src/agents/run_state.py:872`). Keep `snapshot_frequency` bounded or retention will explode without `ContinueAsNew`.

### LLM-judged replanning vs deterministic guard
- **LLM-judged (crewai, Magentic):** Benefit — semantic judgment (`remaining_plan_still_valid`, `is_in_loop`) catches subtle drift. Cost — per-step latency, false positives, asymmetric fallbacks (`heuristic_observation` empty vs `success=True` on exception — `lib/crewai/src/crewai/agents/planner_observer.py:208-352`). Best-fit: long-horizon tasks where drift is semantic, not structural.
- **Deterministic (Temporal `NON_DETERMINISTIC_ERROR`, langgraph `ValidateCommandSequence`):** Benefit — fail-closed, no hallucination. Cost — cannot detect "wrong but deterministic" semantic drift; `ValidateCompleteWorkflowExecutionAttributes` only checks existence (`service/history/api/command_attr_validator.go:219`). Best-fit: regulated or retry-heavy systems.

### Single file vs distributed state channels
- **File (`PLAN.md`):** Benefit — trivial inter-agent handoff (`frontend/src/hooks/use-handle-build-plan-click.ts:27`). Cost — provider-specific path divergence (`.agents_tmp` vs `agents-tmp-config`, `openhands/app_server/app_conversation/live_status_app_conversation_service.py:1140`), stale preview collapsing, sandbox-pause erasure (`openhands/app_server/app_conversation/app_conversation_router.py:1156`). Alternative is channel-triggered `TodoList`/`StateGraph` where each step is a schedulable node.

## Decision Guide

**Do you need audit ("why did plan change?") and resume across crashes?**
- Yes, strongly — Choose **E (Temporal) or D (langgraph with checkpointer)**. Add a typed `PlanRevision{version, parent, reason, diff}` on top; engine gives you durability, you add semantics. Budget for `ContinueAsNew`/snapshot frequency and `TemporalChangeVersion` indexing.
- Yes, within one session — Choose **A with a versioned `PlanStore`**. Wrap `TodoFileStore` pattern with append-only JSONL keyed by `previous_checkpoint_id` (mimic `WorkflowCheckpoint` at `python/packages/core/agent_framework/_workflows/_checkpoint.py:40`) and persist `TodoCompleteInput.reason` on the item. Replace `todos_remove` delete with tombstones.

**Do you need the LLM to decompose open-ended tasks?**
- Yes — Choose **A (crewai/agent-framework)**. Start with `reasoning_effort=medium` (default is `medium` even when unset — `lib/crewai/src/crewai/experimental/agent_executor.py:564`), enable `observe_steps` only on `high` for drift-sensitive runs, use `get_ready_todos` DAG parallelism where steps fan out.
- No / workflow is fixed — Choose **C/D/E** (letta/openai/pydantic graph or LangGraph/Temporal). Encode flow as typed nodes/edges (`pydantic_graph/basenode.py:37`) or `StateGraph.add_node/add_conditional_edges` (`libs/langgraph/langgraph/graph/state.py:667`), and get fork/join for free.

**Do you need a human to review/edit the plan before execution?**

## Practical Tips

### Patterns to copy
- **Add a `reason` field to every state-changing mutation.** `TodoCompleteInput(reason)` (`python/packages/core/agent_framework/_harness/_todo.py:162`) is the cheapest audit win — extend to `todos_add(reason)` and `todos_remove(reason)` and persist it.
- **Keep a `PlanRevision` log even if you keep overwriting the latest.** One append-only JSONL/delta table (`version, parent_version, reason, actor, timestamp, diff`) turns `state.plan` overwrite into explainable history — pair with langgraph's `CheckpointMetadata{source, step, parents}` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:38`).
- **Separate lightweight refinement from full replanning.** Copy crewai's `apply_refinements` (description-only, no LLM reseed) vs `replace_pending_todos` (full LLM regeneration) split; it saves tokens and preserves completed work.
- **Use `get_ready_todos` + `StepExecutionContext(dependency_results)`** for DAG-parallel steps. Isolate each `StepExecutor`'s message window (`lib/crewai/src/crewai/agents/step_executor.py:64`, `lib/crewai/src/crewai/utilities/step_execution_context.py:13`) so parallel steps don't leak history.
- **Guard plan stores with per-session locks + atomic replace.** `WeakKeyDictionary[AgentSession, asyncio.Lock]` plus `tmp.<pid>` → `os.replace` (`python/packages/core/agent_framework/_harness/_todo.py:395-425`) is the reference; add `test_todo_file_store_writes_state_atomically` (`python/packages/core/tests/core/test_harness_todo.py:85`) as regression.
- **Make intermediate checkpoints queryable.** Choose langgraph `durability="sync"`/`"async"` over `"exit"` during plan editing; with `"exit"` revisions are staged in `_exit_delta_writes` (`libs/langgraph/langgraph/pregel/_loop.py:215`) until exit and are not diffable.
- **Adopt stall-counter with decrement on progress.** `stall_count > max_stall_count` with -1 on progress (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1113`) debounces flapping between progress/no-progress.
- **Branch, don't mutate, when correcting history.** Copy Temporal's `ResetWorkflowExecution` fork-don't-edit pattern (`service/history/api/resetworkflow/api.go:136`): new `RunId` preserves the audit trail while fixing the lineage.

### Patterns to avoid or delay until needed
- **Don't collapse history in the UI to "last edit per phase."** OpenHands `usePlanPreviewEvents` grouping hides intermediate revisions (`frontend/src/components/v1/chat/hooks/use-plan-preview-events.ts:87`) — keep a collapsible timeline instead.
- **Don't make `low` reasoning effort hide drift entirely.** Crewai `low` skips `PlannerObserver` and only replans on `failed AND needs_full_replan` (`lib/crewai/src/crewai/experimental/agent_executor.py:767`) — at least emit a heuristic drift warning even at `low`.
- **Don't let heuristic vs LLM failure semantics diverge.** `heuristic_observation` → `success=True` on exception vs unparseable LLM → `success=False` (`lib/crewai/src/crewai/agents/planner_observer.py:208-352`) hides vs surfaces failures oppositely — unify to explicit `failed` with `reason`.
- **Don't clear plan lineage on `invoke()`/`feedback` reset.** `invoke()` wiping `plan, todos, replan_count, observations, execution_log` (`lib/crewai/src/crewai/experimental/agent_executor.py:2879`) loses lineage for HITL loops — carry `PlanRevision` forward or checkpoint before reset.
- **Don't trust payload validity on completion.** `ValidateCompleteWorkflowExecutionAttributes` (`service/history/api/command_attr_validator.go:219`) and `setStateStatus` (`service/history/workflow/mutable_state_state_status.go:16`) enforce structure, not semantics — add a payload JSON-schema gate if "successful" must mean correct.
- **Don't conflate `is_complete` with `is_successful`.** `TodoList.is_complete` counts `failed` as terminal (`lib/crewai/src/crewai/utilities/planning_types.py:69`) — surface `is_successful` separately or `finalize()` cannot tell termination from success.
- **Don't blow up replan context.** `_build_replan_context` concatenates all `completed+failed` results verbatim (`lib/crewai/src/crewai/experimental/agent_executor.py:2713`) — truncate/summarize before injection or the next replan exceeds context window.

### Decision rules (cheat sheet)
- Need explainable revision history? → versioned `PlanStore` with `revision_id`, `reason`, and diff — don't rely on `execution_log`/`EventLog` alone.
- Need semantic drift catch but can't afford per-step LLM? → start with Magentic stall counter (3) and promote to `PlannerObserver` at `reasoning_effort=high` only for long plans.
- Need parallel subtasks? → dependency-aware ready queue (`can_parallelize` check) over free `asyncio.gather`.
- Need reset/undo? → Temporal-style fork with `WorkflowTaskFinishEventId` boundary validation, not in-place file `undo_edit`.
- Need HITL edit mid-run? → langgraph `bulk_update_state` (`libs/langgraph/langgraph/pregel/main.py:1590`) or `RunState.add_input` gated by `response_accepted`/`stop_on_first_tool` (`sources/openai-agents-sdk/src/agents/run_state.py:971`), not raw channel overwrite.

## Anti-Patterns / Caution Signs

- **Silent plan divergence.** Instructions say "update todos on feedback" (`python/packages/core/agent_framework/_harness/_todo.py:27`) but nothing enforces it — agent can keep executing against stale `todos_get_all`. Signal: `todos_remaining` loops on orphaned items while executed tools don't match todo titles. Mitigate with a per-iteration `PlanValidator` comparing remaining todos to recent tool calls.
- **Lost reason context.** `TodoCompleteInput.reason` not stored on `TodoItem` (`python/packages/core/agent_framework/_harness/_todo.py:45`) — post-hoc query "why item 7 completed?" requires transcript scrape. Symptom: audit trail exists only in chat history, not state.
- **Stall oscillation.** `stall_count` decrements on progress (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:1113`) so flapping never reaches `max_stall_count`; or transient `is_in_loop` false positive triggers premature `_reset_and_replan` clearing `chat_history` (`python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:385`). Symptom: either never replans or replans too eagerly.
- **Fresh-context discard.** `AgentLoopMiddleware` with `fresh_context=True` restores baseline session each iteration (`python/packages/core/agent_framework/_harness/_loop.py:360`) — silently drops file-memory plan writes between iterations. Symptom: plan edits vanish inside the loop.
- **Heuristic hides failures.** `observe_steps=False` or `reasoning_effort="low"` uses `heuristic_observation` with `key_information_learned=""` (`lib/crewai/src/crewai/agents/planner_observer.py:105`); failed step not marked `needs_full_replan` is recorded as `failed` but execution continues linearly.
- **Execution continues on known drift.** No `plan_drift` metric — small description tweaks via `Command(update=...)` are indistinguishable from no drift (`No evidence found` in langgraph, letta, openai, pydantic). Symptom: three small rewrites accumulate into unrecognizable plan before threshold fires.
- **History gaps and pruned deltas.** `MaxTurnsExceeded` synthesized as success (`letta/schemas/letta_stop_reason.py:26`, `sources/openai-agents-sdk/src/agents/run.py:1496`) truncates as `completed`; Temporal/langgraph `prune` or `DeltaChannel` ancestry deletion silently reconstructs prior `plan` channel as empty (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:378`). Symptom: plan appears truncated or empty without error.
- **Non-cancellable batches.** `execute_todos_parallel` warns `pool.shutdown(cancel_futures=True)` cannot interrupt Python threads in flight (`lib/crewai/src/crewai/experimental/agent_executor.py:1808`); replan cannot abort current batch.
- **Plan file phantom disappearance.** `read_conversation_file` returns `''` for paused/archived sandbox (`openhands/app_server/app_conversation/app_conversation_router.py:1156`), erasing rendered plan. Symptom: `planContent` null while `EventLog` still has history.

## Notable Absences

- **Versioned plan store.** No harness except Temporal keeps a `PlanRevision` log. Agent-framework overwrites snapshots; crewai keeps `execution_log` only in memory and clears on re-invoke; openhands keeps raw file-edit events not diffs; letta keeps `BlockHistory` for memory but not plan; openai-agents-sdk and pydantic-ai keep message trajectories not plan diffs.
- **Plan diff API / `StreamMode="plan"`.** No source emits `PlanDiffPayload{added, removed, changed}` per superstep/step — even langgraph's `stream_mode="debug"/"tasks"/"checkpoints"` (`libs/langgraph/langgraph/types.py:122`) carries `id/name/error/result` not plan diffs. Temporal's view is raw events, not a derived plan diff.
- **Justification on most transitions.** Only `todos_complete`/`replan`/`progress ledger` carry `reason`; `todos_add`, `todos_remove`, `Command(update)`, `StateUpdate(values, as_node)`, `RunState.add_input`, `GraphRun.override_next`, `BlockHistory`, and `Pydantic` hook overrides have none.
- **Drift metric with threshold.** No numeric score (graph edit distance, description diff, step variance) — closest is binary `remaining_plan_still_valid`/`is_progress_being_made` or deterministic `NON_DETERMINISTIC_ERROR`. No source auto-triggers a validator before `tick()`.
- **Typed plan status machine.** No `PlanStatus = pending/in_progress/blocked/completed/abandoned` enum; `is_complete` booleans, `failed-as-terminal`, and `Status=completed` cover abandonment implicitly without a distinct `abandoned` lifecycle event.
- **Completion validator mapping output to plan.** Synthesis helpers (`_synthesize_final_answer_from_todos` `lib/crewai/src/crewai/experimental/agent_executor.py:2376`, `AgentOutputSchemaBase.validate_json` `sources/openai-agents-sdk/src/agents/run_internal/turn_resolution.py:1000`) check schema shape, not coverage of todo items. No validator checks "every pending item either completed or explicitly abandoned with reason."
- **Plan-conditioned tool gating.** No source binds `ToolRulesSolver`/`tool_use_tracker` to a committed `plan_hash` — tools are filtered by last response/history, not by declared plan cursor.
- **Compaction/dilution guard.** No source re-anchors the plan block before `compact()`; summarizer prompt instruction ("preserve important plan files verbatim" `letta/prompts/summarizer_prompt.py:11`) is unenforced, so summarization can evict the implicit plan.

## Per-Source Notes

- **agent-framework (5/10):** Strongest single-agent ergonomics among todo harnesses — atomic, isolated, path-traversal-safe stores with typed `TodoItem`. Magentic island shows the mature closed-loop (progress ledger + `REPLANNED` event + plan-review gate at `python/packages/orchestrations/agent_framework_orchestrations/_magentic.py:998`) but doesn't apply to the harness/todo path most samples use. Biggest lift is promotion of stall ledger to shared `AgentLoopMiddleware` drift guard and a versioned `PlanStore` with tombstones.

- **crewai (5/10):** Most feature-complete structured plan: `PlanStep→TodoItem`, `PlannerObserver`, dependency DAG, `StepExecutionContext` isolation, event-sourced lifecycle events, and synthesis validator. Also the most fragile: heuristic path inconsistent with LLM path, replan context unbounded, refinement cannot change `tool_to_use`/`depends_on`, dual `CrewPlanner`/`AgentReasoning` subsystems diverge, and history is wiped on re-invoke.

- **langgraph (5/10):** Engine-level excellence — monotonic `uuid6` ordering, ancestor walks, delta snapshots, deterministic `apply_writes` ordering (`libs/langgraph/langgraph/pregel/_algo.py:256`), `Send`+`Command` dual mutation vectors, interruption forks. Gap is plan semantics: everything generic. Without a typed plan channel on top, drift/justification/validator questions are N/A by design — redirected to `deepagents` (`docs/redirects.json:190`).

- **letta (2/10):** Deliberate minimalism — no plan artifact is the architecture. `ToolRulesSolver` is a capable sequencing DSL (intersecting `get_valid_tools` sets at `letta/helpers/tool_rule_solver.py:113`), but it constrains tool names, not plan content. Implicit plan lives only in reasoning text subject to `compact()` eviction; `RunStatus.completed` conflates goal achievement with `max_steps` truncation. Build a `Plan` block in `BlockHistory` only if you need the feature — framework won't do it.

- **openai-agents-sdk (3/10):** Best durability among reactive harnesses — 17-version schema history, id/call_id dedup, `NestedHistoryOwnedItemRef`, canonical `RunState.add_input` HITL mutation gate. `ToolExecutionPlan` is per-turn dispatch, not a task plan. Turn state machine (`NextStepRunAgain/Handoff/FinalOutput/Interruption` at `sources/openai-agents-sdk/src/agents/run_internal/run_steps.py:171`) is the lifecycle — if you need plan revision, add an explicit `Plan` layer with `plan_revisions[]` beside `generated_items`.

- **openhands (4/10):** Only source with a first-class user-visible plan artifact (`PLAN.md`). The planning agent isolation (separate sub-conversation with own websocket — `frontend/src/contexts/conversation-websocket-context.tsx:215`) and `allowed_edits_files` restriction are clean. Weakest operationally: no revision table, no completeness lint, manual non-atomic Build handoff, provider path coupling, and `EventLog`-reuse that pollutes history.

- **pydantic-ai (2/10):** Graph-is-plan is the lightest-weight model — return-type edge inference (`pydantic_graph/graph_builder.py:1641`) plus hook-driven `override_next` gives maximal composability. Also the least observable: no checkpoint protocol (`WORKAROUND-RECIPES.md:180` says to persist `plans, next step, joins` yourself), `run_stream` termination inconsistency (`pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:618`), and arbitrary `before_model_request` message rewriting with no drift flag.

- **temporal (8/10):** Sets the reference for lifecycle rigor — immutable `HistoryBuilder`, total transition function, version histories, deterministic replay, first-wins completion arbitration, buffered-events guard, and `checkMutability` zombie isolation. Loses points only because the "plan" is code rather than a structured `Plan{steps, deps, status}` artifact; plan-change observability via `TemporalChangeVersion` is opt-in, and payload validation is structural only.
