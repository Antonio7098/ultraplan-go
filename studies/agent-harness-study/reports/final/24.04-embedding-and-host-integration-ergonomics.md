## Executive Summary

Ten sources implement "embed a harness into someone else's host" in four fundamentally different shapes, and the score distribution follows the shape almost perfectly. The **library-first cluster** — langgraph (9), pydantic-ai (9), openai-agents-sdk (8), agent-framework (8), and opa's `rego`/SDK tiers (8) — treats embedding as the primary product: the harness is a plain constructible object, every dependency category (storage, tools, identity, policy, telemetry, secrets) has an explicit injection seam, and cancellation/shutdown are typed contracts. The **embeddable-server cluster** — temporal (8) as a Go library whose CLI is just another embedder, and letta (5)/langfuse (5) as service-first products — answers the dimension question ("can a host retain ownership of policy, state, telemetry, UX?") only partially or not at all: hosts integrate over HTTP and accept the vendor's process. The **UI-component outlier**, openhands (6), embeds presentation while structurally delegating the agent loop out-of-process. crewai (6) is library-shaped but leaks process-wide effects (import-time monkeypatching, singleton event bus with background threads, no cancellation API).

Convergence is strong where it matters: every source that scores 7+ exposes dependencies through interfaces rather than globals, surfaces approvals as resumable data rather than in-memory callbacks, and makes lifecycle explicit at least at one tier. Divergence is driven by product shape (library vs. platform), trust boundaries (in-process flexibility vs. out-of-process containment), language idiom (Go functional options vs. Python protocols vs. React provider injection), and compatibility burden (langgraph carries three streaming generations; opa carries a v0/v1 split). The most instructive failures are not in weak sources: even 8–9 scorers leak global state (temporal's `otel.SetErrorHandler`, opa's global built-in registries, langgraph's ambient contextvars), proving that embedding ergonomics is never "done" — it is an ownership boundary that must be continuously defended by interfaces and tests.

## Core Thesis

**Embedding ergonomics is determined less by how many extension points a harness offers than by who owns the process, and whether the ownership boundary is enforced by contracts or eroded by ambient state.** Sources where the host keeps the process (library-first cluster) converge on the same recipe: constructible objects with constructor/per-call dependency injection, structural protocols for host-supplied backends, resumable approvals as serialized state, and cooperative cancellation that preserves work. Sources where the harness owns the process (letta, langfuse) can still achieve excellent *operational* lifecycle quality — langfuse's staged worker shutdown and letta's readiness state machine are among the best evidence in this study (`worker/src/utils/shutdown.ts:29-116`; `letta/server/rest_api/app.py:175-291`) — but they forfeit host ownership of policy, identity, and UX because those concerns are code-owned constants or session-authenticated internals. The decisive test each source fails or passes is: *does importing and initializing the harness mutate state the host cannot scope?* Import-time side effects are the single strongest predictor of low scores in this dimension.

## Approach Models

**langgraph — compile-time DI over a `Runnable` contract.** The compiled graph is the embedding unit; checkpointer, store, cache, interrupt points, and stream transformers are all `StateGraph.compile(...)` arguments (`libs/langgraph/langgraph/graph/state.py:1177-1188`). Per-run dependencies travel in an explicit injected `Runtime` object (`libs/langgraph/langgraph/runtime.py:125-238`). Server/CLI modes are opt-in layers on the same graph objects; `RemoteGraph` even lets a remote deployment compose as a local node (`libs/langgraph/langgraph/pregel/remote.py:118-127`).

**pydantic-ai — generic typed agent plus wrapper algebra.** `Agent[AgentDepsT, OutputT]` is parameterized by a host-defined deps type delivered through `RunContext.deps` (`pydantic_ai_slim/pydantic_ai/_run_context.py:61-225`); cross-cutting behavior composes via capabilities and wrapper toolsets rather than subclassing (`pydantic_ai_slim/pydantic_ai/capabilities/abstract.py:162`; `pydantic_ai_slim/pydantic_ai/toolsets/wrapper.py:15`). Service shapes (Temporal/DBOS/Prefect workers, AG-UI/Vercel AI adapters) wrap the same agent via `WrapperAgent` (`pydantic_ai_slim/pydantic_ai/durable_exec/temporal/_agent.py:112`).

**agent-framework — layered hosting over an agent-object core.** The minimal unit is `AIAgent`/`Agent` invoked directly; on top sit four explicit hosting models: .NET DI registration (`AddAIAgent(...)` → `IHostedAgentBuilder`, `dotnet/src/Microsoft.Agents.AI.Hosting/HostApplicationBuilderAgentExtensions.cs:25-96`), two-tier HTTP hosting (batteries-included `MapOpenAIResponses` vs. bring-your-own-route conversion helpers, documented as an either/or decision in `dotnet/samples/04-hosting/af-hosting/README.md:5-15`), Python helper-first packages exposing only state holders and pure conversion functions (`python/packages/hosting/agent_framework_hosting/_state.py:74-117`), and platform-managed Foundry hosting.

**openai-agents-sdk — per-call parameter injection into a static runner trio.** `Runner.run/run_sync/run_streamed` accept `context`, `session`, `hooks`, `run_config`, and `error_handlers` per call (`src/agents/run.py:256-270`); every backend is a small protocol or ABC (`Session`, `ModelProvider`, `TracingProcessor`, `ShellExecutor`, `BaseSandboxClient`). There is deliberately no console script and no bundled server (`pyproject.toml:2`).

**opa — two-tier API with a plugin-manager composition root.** A maximalist low-level library (~60 functional options on `rego.New`, `v1/rego/rego.go:1428`) beneath a deliberately small high-level SDK (11 public option fields, `v1/sdk/options.go:36-97`), both sharing `plugins.Manager` as composition root; the server runtime and WASM target extend the same seams. Config crosses the boundary as opaque YAML/JSON bytes.

**temporal — options-pattern façade over a DI graph, proven by its own CLI.** `NewServer(opts ...ServerOption)` exposes ~25 options covering logger, authorizer, claim mapper, storage factories, metrics handler, and interceptors (`temporal/server_options.go:35-69`); internally Uber Fx graphs resolve them. The official binary consumes the identical embedding API (`cmd/server/main.go:222-243`), which is the study's clearest dogfooding evidence.

**crewai — facade exports with per-capability factory setters.** Hosts construct `Crew`/`Flow` and call `kickoff`; LLM, tools, memory storage, flow persistence, and human input each get their own protocol/ABC plus a small factory setter instead of one DI container (`lib/crewai/src/crewai/memory/storage/factory.py:33`; `lib/crewai/src/crewai/flow/persistence/factory.py:31`). Observability flows through a single process-wide event-bus singleton.

**openhands — provider-injected UI components over a remote agent loop.** `AgentServerUIProviders` accepts host query client, i18n, analytics config (or hard-disable), theme, and CSS-variable overrides (`src/components/providers/agent-server-ui-providers.tsx:48-123`); all agent functionality is delegated to an external agent-server through one typed client, with a CI test banning ad-hoc HTTP (`src/api/no-direct-agent-server-calls.test.ts:32-79`).

**letta — server process first, undocumented library second.** The sanctioned surface is the FastAPI REST app consumed via the external `letta-client` SDK; in-process `SyncServer` works (tests prove it, `tests/managers/conftest.py:87`) but managers are constructed inline with commented-out DI parameters marking an abandoned seam (`letta/server/server.py:117-126,148-193`).

**langfuse — containers and HTTP contracts only.** The unit of adoption is a web+worker container pair configured entirely through a zod-validated env schema (`packages/shared/src/env.ts:32-95`); the well-engineered AG-UI event vocabulary, durable approvals, and resumable SSE streams exist but are reachable only behind Langfuse session auth (`web/src/features/in-app-agent/server/router.ts:27-29`) — integration primitives without an external SDK face.

## Pattern Catalog

### P1. Constructible-object invocation contract
- **Problem:** Hosts must run harness work inside their own event loops without ceding process control.
- **Demonstrated by:** langgraph compiled `Runnable` (`libs/langgraph/langgraph/pregel/protocol.py:25`); pydantic-ai `Agent` with four run entry points (`pydantic_ai_slim/pydantic_ai/agent/abstract.py:470,666,826`); MAF `AIAgent.RunAsync` with `CancellationToken` (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIAgent.cs:38`); opa synchronous `rego` evaluation on the caller's goroutine (`v1/rego/rego.go:561-581`).
- **Why it works:** Nothing installs handlers, threads, or ports at construction; hosting models become opt-in layers rather than woven-in assumptions. Both sources that explicitly searched for hidden ambient mechanisms (MAF, langgraph) confirmed none beyond async-flow-scoped context.
- **Copy when:** Building any harness intended to live inside another application.
- **Overkill/risky when:** Never, for libraries. For platforms (langfuse), deliberately absent — the cost of supporting it is refactoring away module-scope wiring.
- **Evidence:** MAF found no `atexit`/signal/background-worker hits across its Python core; langgraph found no required singletons or import-time threads (`libs/langgraph/langgraph/pregel/main.py:2616-2660` region).

### P2. Functional-options/builder DI surfaces
- **Problem:** Hosts need to inject different dependency sets per embedding without breaking API evolution.
- **Demonstrated by:** opa (~60 `rego` options, `v1/rego/rego.go:929-1425`); temporal (~25 `ServerOption`s, `temporal/server_option.go:36-255`); MAF `.NET` builders returning `IHostedAgentBuilder` (`dotnet/src/Microsoft.Agents.AI.Hosting/IHostedAgentBuilder.cs:10-26`).
- **Why it works:** Options are additive and individually documented; temporal adds validation-at-construction with actionable error messages naming the exact missing companion option (`temporal/fx.go:299-308`).
- **Copy when:** Go projects, or any surface expecting third-party embedders across versions.
- **Overkill when:** The option set is small and stable — Python sources achieve the same with keyword arguments and protocols at lower ceremony.
- **Evidence:** opa applies identical option idioms across three packages so "a host engineer learns one pattern."

### P3. Structural protocols for host-supplied backends
- **Problem:** Hosts must plug custom storage/tools/telemetry without inheriting framework base classes.
- **Demonstrated by:** openai-agents `runtime_checkable Session` Protocol explicitly recommended for third parties (`src/agents/memory/session.py:15-67`); pydantic-ai `AbstractToolset` (`toolsets/abstract.py:76-171`); crewai `StorageBackend` protocol consulted before built-ins (`memory/storage/factory.py:33,48-51`); langgraph `BaseCheckpointSaver`/`BaseStore`/`BaseCache` (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:176-329`); MAF Python `SessionStore` and .NET abstract `AgentSessionStore` (`dotnet/src/Microsoft.Agents.AI.Hosting/AgentSessionStore.cs:48-103`).
- **Why it works:** Structural conformance means host code needs no import of the framework to qualify, and reference implementations ship alongside as working examples.
- **Copy when:** Any injectable backend; prefer protocols over ABCs for third-party seams (openai-agents documents exactly this reasoning).
- **Risky when:** The protocol is unstable — MAF's Python `SessionStore` is experimental (`python/packages/core/agent_framework/_sessions.py:1794`), so early adopters absorb churn on their persistence layer.

### P4. Approvals as resumable serialized state, not callbacks
- **Problem:** Human approval may happen seconds or days later, possibly in another process.
- **Demonstrated by:** langgraph `interrupt()`/`Command(resume=...)` backed by checkpoints (`libs/langgraph/langgraph/types.py:851-914`); pydantic-ai `DeferredToolRequests` output type plus `deferred_tool_results=` resume kwarg (`pydantic_ai_slim/pydantic_ai/_deferred.py:27-60`; `agent/abstract.py:476`); openai-agents `interruptions` list plus `RunState.to_string()` durable boundary (`src/agents/run_state.py:2042,2100`); langfuse tamper-proof decisions re-read from persisted events (`web/src/features/in-app-agent/server/router.ts:260-267`); letta `PendingApprovalError` typed surfacing (`letta/errors.py:48`).
- **Why it works:** Serializing the pause point decouples approval UX lifetime from agent-loop lifetime and survives restarts; langfuse's variant eliminates fingerprint-sync bugs by sending only IDs plus a boolean.
- **Copy when:** Any tool requiring human sign-off; pair with a checkpoint/persistence layer.
- **Cost:** Durability gating — langgraph interrupts require a checkpointer, so ephemeral hosts must add even a memory-only saver (`libs/langgraph/langgraph/types.py:869-871`); pydantic-ai hosts must persist results keyed by `tool_call_id` or conversations silently stall (`_deferred.py:27-60`).

### P5. Cooperative-drain versus hard-cancel duality
- **Problem:** Hosts need both "stop now" and "finish gracefully at a safe boundary."
- **Demonstrated by:** langgraph host-owned `RunControl.request_drain(reason)` raising `GraphDrained` at superstep boundaries after saving a checkpoint, with in-flight child tasks allowed to complete (verified by test, `libs/langgraph/langgraph/tests/test_pregel.py:140-160`); openai-agents `cancel(mode="after_turn")` finishing the turn and saving session state vs. `"immediate"` teardown (`src/agents/result.py:818-864`); langfuse shutdown aborting agent loops at step boundaries with runs finalized as FAILED(worker_shutdown) (`worker/src/features/in-app-agent/executeInAppAgentRun.ts:69-77`); pydantic-ai's attachable token for first-party cancel with external `Task.cancel()` still winning (`pydantic_ai_slim/pydantic_ai/_cancel.py:42-61,227-230`).
- **Why it works:** Draining preserves consistency; immediate abort preserves responsiveness. Exposing both under explicit names removes guesswork.
- **Copy when:** Any long-running loop with side effects.
- **Absent:** crewai has no public cancel API at all — interruption exists only as `KeyboardInterrupt` handling inside interactive helpers (`utilities/crew_chat.py:205`) — the study's clearest negative example.

### P6. Cancellation that returns usable state
- **Problem:** Cancelling mid-run usually destroys partial work.
- **Demonstrated by:** pydantic-ai `RunCancelled` carrying `all_messages()`, `usage`, and `run_id` snapshots recoverable from external cancellations too (`pydantic_ai_slim/pydantic_ai/exceptions.py:268-444`); openai-agents' after-turn mode saving session state before stopping.
- **Why it works:** Treating the cancellation exception as a data carrier converts abort into a first-class outcome the host can persist or retry.
- **Copy when:** Conversational state is expensive to rebuild.
- **Risky when:** Language/runtime support is uneven — pydantic-ai's attribution of external cancels degrades on Python 3.10 (`_cancel.py:227-230`).

### P7. Readiness handshake and staged shutdown
- **Problem:** Embedded services must signal liveness to orchestrators and tear down deterministically.
- **Demonstrated by:** opa host-supplied `Ready chan struct{}` closed when all plugins reach OK, with blocking-init fallback (`v1/sdk/options.go:54-57`; `v1/sdk/opa.go:209-229`) and bounded graceful-shutdown periods per plugin (`v1/plugins/plugins.go:397-403,926-952`); letta warming→ready→draining readiness states in FastAPI lifespan (`letta/server/rest_api/app.py:175-291`); langfuse's five-stage worker shutdown ending in ClickHouse flush and client disconnect (`worker/src/utils/shutdown.ts:29-116`); temporal reverse-init-order stops with a 5-minute per-service budget (`temporal/server_impl.go:44-53,109-124`).
- **Why it works:** Explicit state machines make orchestration probes meaningful and shutdown bugs reproducible.
- **Copy when:** Anything with background workers or warm-up phases.

### P8. Buffered-then-resolved logging
- **Problem:** Startup logs are lost when the real logger arrives late (plugin-based systems).
- **Demonstrated by:** opa buffers 1000 early entries in a ring buffer and replays them into whichever logger plugin resolves later (`v1/sdk/options.go:117-119`; `v1/plugins/plugins.go:1270-1290`).
- **Why it works:** Debugging early failure is exactly when diagnostics matter most.
- **Caution:** If neither logger nor fallback is configured, opa silently discards the buffer — the mitigation must have a default (`v1/sdk/options.go:44-48`).

### P9. Scoped-versus-global registration split
- **Problem:** Extension points want init()-style convenience but multi-instance safety.
- **Demonstrated by:** opa offering both instance-scoped `Function1..FunctionDecl` and process-global `RegisterBuiltin1..Dyn` (`v1/rego/rego.go:830-875` vs `760-828`); openai-agents shipping instance-scoped `MultiProvider` alongside global `set_default_openai_*` helpers (`src/agents/models/multi_provider.py:76-153` vs `src/agents/__init__.py:278-310`).
- **Why it works:** Hosts doing multi-tenant or embedded-multi-engine work use the scoped path; quickstart users keep convenience.
- **Copy when:** Any registry-style extension point. The split should be uniform — opa's own report notes it is not consistently enforced.

### P10. Test doubles shipped as public API, and contract-by-test
- **Problem:** Embedders cannot validate integrations against real LLMs cheaply.
- **Demonstrated by:** openai-agents `ScriptedModel` and scripted sandbox sessions inside `agents.testing` (`src/agents/testing/model.py:249`); opa `sdktest.NewServer`/`MockBundle` used directly in the official embedding example (`docs/docs/integration.md:210-224`); temporal's log-contract test failing on any unexpected warn/error across start→workload→stop (`temporal/server_test.go:75-98,301-309`); openhands CI guard enforcing the typed-client boundary plus packaging/export/CSS-isolation tests (`__tests__/library-entrypoints.test.ts:10-49`).
- **Why it works:** The embedding surface becomes executable specification; temporal's approach additionally pins the logging surface hosts inherit.

### P11. CLI/server binary as proof of embedding (dogfooding)
- **Problem:** Library embedding paths rot when nothing in-tree uses them.
- **Demonstrated by:** temporal's `cmd/server/main.go` consuming the same `NewServer` API as external embedders (`cmd/server/main.go:222-243`); opa's CLI constructing the same `runtime.Params` (`cmd/run.go:381,396-401`); MAF samples encoding ownership boundaries as normative documentation (`dotnet/samples/04-hosting/af-hosting/local_responses/Server/Program.cs:3-6`).
- **Contrast:** letta's only working in-process example is its test conftest (`tests/managers/conftest.py:60-90`) — functional but undiscoverable.

### P12. Save/restore nested provider state
- **Problem:** Libraries injecting contexts (query clients, i18n) can corrupt a host that also uses those contexts.
- **Demonstrated by:** openhands `AgentServerUIProviders` remembering ambient query client/i18n before overriding and restoring both on unmount (`src/components/providers/agent-server-ui-providers.tsx:65-88`).
- **Why it works:** Enables nested mounts and coexistence with host-owned instances of the same primitives.
- **Copy when:** Shipping UI components or anything that overrides host-global-ish objects.

## Key Differences

**Where does the process boundary sit?** This is the primary axis. langgraph, pydantic-ai, openai-agents-sdk, and MAF keep everything in-process — a compiled graph, an `Agent`, or a `Runner` call executes on the host's loop (`libs/langgraph/langgraph/pregel/protocol.py:25`; `pydantic_ai_slim/pydantic_ai/agent/abstract.py:470`). letta and langfuse invert it: the harness *is* the process and hosts integrate over REST (`letta/server/rest_api/app.py:294`; `docker-compose.yml:6-195`). openhands splits it vertically — presentation embeds, cognition delegates (`bin/agent-canvas.mjs:54-84`). temporal supports both simultaneously: same-process startup with loopback gRPC as the integration contract (`temporaltest/internal/lite_server.go:329-332`), trading serialization overhead for compatibility stability.

**Who owns policy?** Fully host-owned in the library cluster: crewai's before/after hooks can veto or rewrite calls (`hooks/tool_hooks.py:142-153`), temporal injects an `Authorizer` receiving full call targets (`common/authorization/authorizer.go:52-58`), openai-agents attaches guardrails per-run (`run_config.py:391-496`), pydantic-ai composes capabilities. Code-owned elsewhere: langfuse classifies every MCP tool in a source constant (`packages/shared/src/in-app-agent/server/mcpPolicy.ts:27,477-512`); letta reduces policy to data flags (`requires_approval` toggles). langgraph is honest about the gap: `@auth.on` handlers exist only in the external server product, so OSS library embedders implement policy above node boundaries themselves (`libs/sdk-py/langgraph_sdk/auth/types.py:182-215`; noted gap in its report).

**How is configuration injected?** Typed objects dominate libraries (MAF `HarnessAgentOptions` with paired enable/disable+inject knobs, `dotnet/src/Microsoft.Agents.AI.Harness/HarnessAgentOptions.cs:19-344`; temporal `WithConfig` structs). Environment dominates services (letta `Settings(env_prefix="letta_")` with YAML merged into environ at import, `letta/settings.py:9-15`; langfuse zod env schema). opa is the outlier accepting opaque config bytes — evolvable schema at the cost of compile-time checking (`v1/sdk/options.go:38-42`).

**Is telemetry default-on or opt-in?** openai-agents exports traces to OpenAI's backend unless disabled (`src/agents/tracing/provider.py:346-352`) and crewai ships a batching trace listener egressing to a remote backend (`events/listeners/tracing/trace_listener.py:140,781-799`) — both favor zero-config observability. MAF (`UseOpenTelemetry` opt-in decoration, `OpenTelemetryAgentBuilderExtensions.cs:47`), pydantic-ai (explicit `InstrumentationSettings(tracer_provider=...)`, `models/instrumented.py:63`), and temporal (config < env < custom-code exporter precedence, `temporal/fx.go:987-1009`) favor host ownership of the telemetry pipeline.

**Is cancellation first-class?** Six of ten sources expose explicit cancel/drain APIs with documented semantics (langgraph, pydantic-ai, openai-agents-sdk, opa via context, letta and langfuse at the service tier). MAF is asymmetric (.NET `CancellationToken` everywhere; Python relies on asyncio convention with zero token parameters). crewai has none — the starkest divergence in the set.

## Tradeoffs

**Explicitness vs. ergonomics.** langgraph requires threading `{"configurable": {"thread_id": ...}}` through every call because all state is injected (`libs/langgraph/langgraph/graph/state.py:1204-1214`), while crewai's ambient singletons make simple usage one-liners — until two subsystems in one process share hook registries unintentionally (`hooks/dispatch.py:98-135`). Explicit wins for products embedding multiple tenants; ambient wins for scripts.

**Import-time eagerness vs. boilerplate.** letta's import creates `~/.letta` directories and mutates `os.environ` (`letta/config.py:293-310`; `settings.py:15`), and crewai patches `warnings.warn` globally on import (`__init__.py:28-49`): zero setup friction, but tests and embedders must set env before any import — a fragile-global pattern. openai-agents enforces the opposite as a repo rule ("keep top-level imports free of runtime side effects", implemented via lazy exports, `src/agents/__init__.py:268-275`) and pydantic-ai even defers env-var validation behind `defer_model_check=True` (`agent/__init__.py:593-597`).

**Batteries-included vs. bring-your-own.** MAF formalizes this fork explicitly: `MapOpenAIResponses` gives speed but constrains hosting; conversion helpers give control at implementation cost (`af-hosting/README.md:9-15`). langfuse freezes lifecycle constants in shared source — heartbeat, queue timeout, approval TTL — explicitly refusing env-var tuning to prevent web/worker drift (`packages/shared/src/in-app-agent/server/tunables.ts:2-17`): a reliability win that simultaneously removes levers embedders normally expect.

**Durability-first vs. ephemeral simplicity.** langgraph unifies interrupts, drains, and HITL as persisted checkpoints — powerful, but the simplest embedding cannot do interactive approvals without adding a saver (`types.py:869-871`). langfuse acknowledges the residual durability window honestly: approved-but-unverified mutations fail with `OUTCOME_UNKNOWN` instructing manual verification (`executeInAppAgentRun.ts:160-167`). Ephemeral-first designs avoid both costs and both capabilities.

**Out-of-process trust boundaries vs. in-process flexibility.** openhands and langfuse push destructive capability (bash, file edits) into isolated sidecars — langfuse's sandbox rejects path escapes, caps request size, serializes operations, and kills process groups (`packages/in-app-agent-sandbox-runtime/src/server.ts:34-41,473-487`). The price: hosts cannot contribute tools, policy, or storage in-process at all; openhands' search for approval callbacks returned only mock-data matches.

**Global registries vs. multi-instance isolation.** opa's global built-in/target-plugin registration makes custom binaries trivial but means two embedded engines share namespaces (`v1/rego/rego.go:761`; `plugins.go:36-43`); temporal's `otel.SetErrorHandler` overwrite silently replaces a host's own handler during start and tracer shutdown (`temporal/fx.go:978-991,1088-1091`); crewai's hardcoded 10-thread bus pool is untunable per host (`event_bus.py:179-182`). Against this, langgraph compiles isolated graph instances freely and pydantic-ai scopes overrides to per-agent ContextVars (`agent/__init__.py:696-708`).

## Decision Guide

- **Embedding a coding/chat agent into your product's process, keeping your own UX, policy, and storage:** choose the library-first cluster. pydantic-ai if you want typed deps and thread-safe cancellation with state recovery; langgraph if you want durable pause/resume and drain semantics and accept checkpointer requirements; openai-agents-sdk if you want per-call injection and scripted test doubles; MAF if you are .NET-first or need dual-stack coverage (mind the parity gaps).
- **Evaluating deterministic policy inside another Go service:** opa's SDK tier — ready channels, atomic reconfigure, decision APIs — is purpose-built; use scoped `Function*` registrations if you may run multiple instances.
- **Needing durable workflow execution around agents:** temporal demonstrates the embeddable-server model done with full dependency-category injection; alternatively pydantic-ai's durable-exec wrappers or langgraph checkpointers put agent runs inside such engines without embedding the engine.
- **Shipping the harness as a managed service with minimal host integration effort:** the letta/langfuse model — accept code-owned policy and vendor identity; do not expect in-process seams. Verify operational knobs you need exist before committing; langfuse intentionally freezes some.
- **Embedding agent UX (not the loop) into an existing frontend:** openhands' component model — take its provider DI, CSS scoping, and telemetry isolation patterns, but plan to supply the missing headless event facade yourself.
- **Rule of thumb:** if a requirement contains the words "our policy," "our secrets," or "our telemetry sink," the service-first sources are disqualified regardless of their operational polish; if it contains "we don't want to run anything," the inverse holds.

## Practical Tips

- **Make the first traced run lazy and document it.** openai-agents lazily spawns its daemon export thread on first span precisely to stay fork/import safe (`tracing/setup.py:42-44`; `processors.py:584-595`) — copy the mechanism, but unlike it, make egress opt-in.
- **Give background executors a deterministic exit template:** cancel flagged tasks, wait for stragglers, re-raise the first task error only if the body didn't raise (langgraph `BackgroundExecutor.__exit__`, `libs/langgraph/langgraph/pregel/_executor.py:93-121`).
- **Ship no-op defaults instead of null-guarded infrastructure:** langgraph's `DEFAULT_RUNTIME` supplies `_no_op_stream_writer`/`_no_op_heartbeat` so nodes never branch on missing deps (`libs/langgraph/langgraph/runtime.py:107-110,285-293`).
- **Validate misconfiguration eagerly with messages naming the fix:** temporal fails `NewServerFx` when `TokenProvider` lacks remote-cluster TLS, stating the exact missing option (`temporal/fx.go:299-308`).
- **Separate ordered delivery from parallel dispatch in event buses:** crewai runs stream chunks inline for ordering while batching other sync handlers (`event_bus.py:505-519,628-637`); note its failure mode — a chatty listener saturates the fixed pool for everyone else.
- **Re-read decision inputs from persisted state server-side** (langfuse approval path, `router.ts:260-267`) so clients cannot desynchronize what they're approving.
- **Expose per-decision observability opt-ins rather than instance-wide tracing** (opa `DecisionOptions` tracer/profiler/metrics per call, `v1/sdk/opa.go:362-381`) so production hosts can debug one request cheaply.
- **Provide a host-visible drain/flush primitive distinct from shutdown** (crewai `flush(timeout)` vs `shutdown(wait)`, `event_bus.py:734-769,897-949`) — the concept is right even though its default `atexit` wiring is not.
- **Pin instrumentation schemas with version numbers** so host dashboards survive upgrades (pydantic-ai `InstrumentationSettings.version`, `_instrumentation.py:32,158-163`).
- **Scope run state in contextvars, but require argument-passing for anything correctness-critical,** because ambient inheritance breaks subtly under async (langgraph's documented hard failure on async Python < 3.11, `libs/langgraph/langgraph/config.py:53-56`).

## Anti-Patterns / Caution Signs

- **Import-time side effects.** crewai monkeypatching `warnings.warn` and rewriting `sys.modules` namespaces (`__init__.py:28-49,133-145`); letta creating `~/.letta` and mutating environ at import (`server.py:110`; `config.py:293-310`; `settings.py:15`); langfuse starting cleaners, runners, and migrations at module scope (`worker/src/app.ts:123-135,699-810`); openhands reading localStorage at module load (`api/backend-registry/active-store.ts:116-120`); langgraph reading env vars at import so later configuration silently no-ops (`libs/langgraph/langgraph/_internal/_config.py:32-35`). Caution sign in review: any code outside a function body touching filesystem, environ, network, or globals.
- **atexit as the primary shutdown story.** crewai registers bus shutdown at exit and spawns daemon threads on first emit (`event_bus.py:166-191,952-954`); openai-agents depends on `atexit` plus manual `flush_traces()` for delivery guarantees (`docs/tracing.md:63-69`). Long-lived hosts never exit cleanly; they need callable lifecycle.
- **Errors printed, not propagated.** crewai collects observer exceptions and merely prints them; async handlers gather with `return_exceptions=True` (`event_bus.py:401-427,445-456`) — broken integrations are invisible programmatically. Contrast openai-agents' `result.run_loop_exception` escape hatch making silent streaming failures checkable (`src/agents/result.py:790-816`).
- **Process-exiting library code.** opa server mode calls `os.Exit(1)` on listener failure, bypassing deferred cleanup (`v1/runtime/runtime.go:835` vs `691`) — hostile inside a supervised host process.
- **Non-idempotent lifecycle methods.** temporal panics on double `Stop` (unconditional channel close, `temporal/server_impl.go:110`); opa's `Manager.Stop` hangs when called twice (`v1/plugins/plugins.go:925`). Host cleanup paths race; lifecycle must tolerate them.
- **Singleton infrastructure blocking multi-instance embedding.** letta's module-level server global plus `~/.letta` contention (`rest_api/app.py:130-132`); openhands' shared query-client proxy and localStorage registry (`query-client-config.ts:83-117`); crewai's singleton bus and hook registries. Caution sign: module-level mutable state reachable from exported symbols.
- **Stdout pollution from library code.** letta prints during init and banners at startup (`server/server.py:378`; `app.py:298`), corrupting machine-parsed host logs.
- **Default-on egress.** openai-agents traces to OpenAI's backend and includes sensitive data by default (`provider.py:346-352`; `run_config.py:53-56`); crewai's tracing listener ships batches remotely post-kickoff (`trace_listener.py:781-799`). Compliance-sensitive hosts discover this late.
- **Stale lifecycle documentation.** opa's doc comment claiming plugins are never stopped contradicts actual behavior (`plugins.go:101` vs `945-947`) — misleading embedders about cleanup guarantees is as harmful as missing guarantees.

## Notable Absences

- **No source provides a first-class secrets-provider interface.** opa states it explicitly (secrets live in config bytes or custom auth plugins); temporal templates credentials from env into YAML (`common/config/config_template_embedded.yaml:22-23`); crewai falls back to writing settings JSON into temp dir/CWD when `$HOME/.config` is unwritable (`crewai_core/settings.py:76-107`); letta uses env-var BYOK. Vault-integrated hosts wrap the harness rather than configure it, nearly universally.
- **Multi-instance isolation is rarely tested or documented.** opa found no docs/tests on multiple `sdk.OPA` instances sharing globally registered builtins; letta has no guard against concurrent embedded instances contending for `~/.letta`; openhands inferred (not demonstrated) shared-singleton risk between two mounted Canvases.
- **No consolidated embedding documentation anywhere.** openai-agents distributes guidance across tracing docs, MCP manager docstrings, and examples with no dedicated page; temporal's README targets Docker operators, leaving the library story discoverable only from package comments and tests; openhands' library embedding docs total four paragraphs (`docs/DEVELOPMENT.md:151-177`); letta's only in-process example is test scaffolding.
- **Headless control surfaces lag UI ones.** openhands offers no event/callback API for hosts driving their own UX off harness events; temporal provides no push/event callback interface for host UX beyond RPC errors; opa has no streaming/partial decision output for long evaluations.
- **Cross-language stories are out-of-tree and unverifiable within this study:** langgraph JS SDK, MAF Go SDK, letta's `letta-client`, langfuse's client SDKs all live in separate repositories, fragmenting evaluation of the full embedding matrix (also true of MAF's moved-out durable-execution extension).

## Per-Source Notes

- **agent-framework (8):** Five-layer embedding stack from bare object to platform-managed hosting; samples serve as executable contracts for ownership boundaries. Weakest points: experimental Python `SessionStore`, .NET-only cancellation/isolation-key parity, and no harness-level teardown hook for long-lived resources like MCP connections.
- **crewai (6):** Broadest per-capability dependency seams in the Python library cluster (LLM, tools, memory, persistence, input provider) plus veto-capable LLM/tool hooks — undercut by import-time patching, singleton bus with hidden thread pool, silent observer errors, and zero cancellation surface.
- **langfuse (5):** As a platform, operationally excellent — staged shutdown with named reasons, durable claim/heartbeat/reconcile run correctness in Postgres, tamper-proof approvals, resumable SSE. As an embeddable harness, closed: no library mode, code-owned policy, session-authenticated internals, import-time wiring.
- **langgraph (9):** The reference model for compile-time DI and cooperative draining; `RemoteGraph` composing remote deployments as local nodes is unique in the set. Deductions are for ambient contextvar coupling, three streaming generations, and policy enforcement living outside the repo.
- **letta (5):** Server-tier lifecycle maturity (readiness states, leader-elected scheduler, Redis-with-fallback cancellation) coexisting with library-tier abandonment: commented-out constructor DI params are archaeological evidence of a rolled-back direction.
- **opa (8):** Most disciplined option-driven DI surface studied, with ready-channel handshake, plugin status machine, atomic reconfiguration, and buffered logging. Debts are global registries, `os.Exit` in server mode, double-stop hang, and no secrets interface; approvals/streaming absent by design for a deterministic engine.
- **openai-agents-sdk (8):** Cleanest structural-typing story (Protocol-recommended `Session`, shipped `ScriptedModel`), graceful-vs-hard cancel duality, redacted-error discipline, and durable serialized approval boundaries. Deducted for default-on telemetry egress, mutable process globals, and no serving recipe promoted to supported API.
- **openhands (6):** Demonstrates that UI embedding is a distinct discipline — CSS scoping as build-time contract, save/restore nested providers, named telemetry instances, CI-enforced client boundaries. Structurally cannot host policy/tools/secrets in-process; router coupling and toast-baked error handling limit framework-neutral reuse.
- **pydantic-ai (9):** Strongest cancellation design in the study (`CancellationToken` fan-out plus `RunCancelled` state snapshots), typed generic DI, capability/wrapper composition, versioned OTel schemas, and thin protocol adapters. Gaps: OTel-only observability and the first-run-only `capture_run_messages` ContextVar.
- **temporal (8):** Proof that a heavyweight distributed system can be a clean embedded library: ~25 options covering every dependency category, CLI-as-embedder dogfooding, log-contract testing, and tiered compatibility promises. Held back by "experimental" storage SPI labels, single-use lifecycle, and OTEL global mutation.

## Open Questions

- **Shutdown semantics for long-lived embedded resources:** MAF found no central teardown contract on either stack and could not verify DI-disposal sufficiency at runtime; whether hosts must hand-manage connected MCP sessions everywhere remains unresolved.
- **Multi-instance handler isolation in crewai:** whether contextvar runtime scopes fully isolate two concurrently running crews' event *handlers* (not just state) was not verifiable from source alone.
- **Behavioral verification under failure for batteries-included endpoints:** MAF located unit tests for service collection and state helpers but none covering streaming interruption of mapped endpoints; langfuse's Fern-generated client SDK ergonomics (retry, streaming helpers) live out-of-tree.
- **Mixed-loop usage of `Runner.run_sync`:** openai-agents describes the interaction between its thread-persistent default loop and host `asyncio.run()` calls in comments but ships no demonstrating test.
- **Temporal Cloud and hosted-service parity:** whether hosted variants share the embedding code could not be verified from any in-tree evidence (temporal, opa both note hosted variants outside their repos).
- **Injected-resource ownership contracts:** temporal specifies who stops its metric handler but not who closes host-injected Elasticsearch HTTP clients; similar unspecified ownership boundaries likely exist elsewhere.
- **SSR behavior of the openhands library:** suggested by lazy imports but untested; likewise multi-document Canvas instances share registries by structural inference only.
- **WASM/non-Go embedding depth for opa:** maintained bindings live outside the repo; lifecycle/cancellation parity with the Go SDK could not be assessed.
