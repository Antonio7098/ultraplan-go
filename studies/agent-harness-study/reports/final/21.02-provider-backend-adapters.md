## Executive Summary

Ten sources spanning agent SDKs and frameworks (agent-framework, crewai, langgraph, letta, openai-agents-sdk, pydantic-ai), deployable platforms (langfuse, temporal, opa), and a frontend client (openhands) were compared on whether models, stores, vector databases, tracing sinks, queues, and sandboxes are swappable. Every source establishes explicit backend interfaces at least somewhere — this is table stakes. What separates the field is *where* selection happens, *how* new implementations plug in, and *whether interchangeability is proven rather than claimed*.

Three sources score 9/10 (openai-agents-sdk, pydantic-ai, temporal) because they pair interfaces with mechanical proof: temporal runs identical conformance suites against Cassandra, MySQL, PostgreSQL, SQLite, and Elasticsearch (`temporal`: `common/persistence/tests/sqlite_test.go:98-136`, sibling driver bindings); pydantic-ai introspects its own package so a newly added model class cannot escape its wire-conformance matrix (`pydantic-ai`: `tests/models/test_model_settings_support.py:623-640`); openai-agents-sdk ships first-party test doubles implementing its production SPIs (`openai-agents-sdk`: `src/agents/testing/model.py:249`). Six sources score 8 by having clear interfaces with multiple real implementations but gaps in proof breadth or extension mechanics (langgraph, letta, agent-framework, crewai, opa). Two score 7 (langfuse, openhands) — both deliberate partial abstractions where swappability concentrates where it pays (multicloud blob storage; user-facing remote-compute switching) and is absent where it does not (datastores; in-process transports).

The dimension's litmus question — *can you switch Postgres to SQLite with a config change?* — gets a literal **yes** only from products with config-file-driven selection: temporal (compare `config/development-postgres12.yaml:12` with `config/development-sqlite.yaml:14`; both flow through one `sql.NewFactory`, `common/persistence/sql/factory.go:45`) and opa (disk vs in-memory store toggled by presence of the `storage.disk` config block, `v1/runtime/runtime.go:490-519`). Letta achieves it approximately via env-derived engine choice with CI proving the SQLite path (`.github/workflows/reusable-test-workflow.yml:451-459`), though dialect conditionals are scattered across ~15 files rather than isolated. Langfuse answers a flat **no** for datastores (Prisma singleton, no seam, `packages/shared/src/db.ts:7-16`). The library sources reframe the question: langgraph swaps via one constructor line plus a deployment-time import string; pydantic-ai and openai-agents-sdk swap via a code-level string or object change, not an external config file.

## Core Thesis

**Swappable backends are universal; swappable-by-configuration and provably-interchangeable backends are rare.** Across all ten sources, backend maturity tracks three properties that are independent of having an interface:

1. **Selection locus.** Whether the choice of backend lives outside compiled code. Products built to be deployed (temporal YAML datastore maps, `common/config/config.go:258-268`; opa JSON config keys, `v1/storage/disk/config.go:29-67`) externalize selection into validated config files. Libraries consumed by developers keep selection in constructor arguments and strings (pydantic-ai `Agent('openai:gpt-5')` resolved by `infer_model`, `models/__init__.py:1529`; openai-agents-sdk `RunConfig.model_provider`, `src/agents/run_config.py:353-359`). Platforms serving many tenants move selection into persisted data records (langfuse's `adapter` column on API-key rows, `prisma/schema.prisma:354`; letta's per-agent stored `LLMConfig.model_endpoint_type` resolved per request, `letta/agent.py:358-362`).

2. **Mechanical equivalence proof.** Whether behavioral parity across implementations is continuously asserted. The strongest form is a shared test matrix instantiated once per backend (temporal's ~50-suite SQLite binding of shared suites; langgraph's core fixtures parametrizing every graph test over memory/sqlite/postgres variants, `libs/langgraph/tests/conftest.py:60-226`) plus a reusable third-party conformance package (langgraph-checkpoint-conformance, `libs/checkpoint-conformance/langgraph/checkpoint/conformance/validate.py:45`). Weaker forms are per-adapter suites without cross-implementation comparison.

3. **Safeguards wrap the interface, not implementations.** Temporal decorates every store uniformly with rate limiting, metrics, retries, tracing, and fault injection regardless of backend (`common/persistence/client/factory.go:109-260`); pydantic-ai wraps any model in `WrapperModel` subclasses for fallback/instrumentation/durability (`models/wrapper.py:32-157`); agent-framework composes function-calling, telemetry, and middleware as layers around any raw client (`python/packages/openai/agent_framework_openai/_chat_client.py:3430-3436`). Where this holds, adding a backend automatically inherits operational behavior; where it doesn't (openhands' per-service if-chains), each new branch point must re-implement discipline by hand.

Sources diverge legitimately, not just in quality: a workflow engine whose product *is* storage diversity (temporal) abstracts persistence exhaustively but has nothing to say about LLM providers; a frontend that must switch remote compute targets from a browser (openhands) invents a runtime registry of data records instead of class hierarchies; a library with a batteries-out philosophy (pydantic-ai) deliberately refuses store/vector/queue abstractions it cannot own well.

## Approach Models

Clustering the ten sources yields five approach models. They are responses to product shape more than to engineering skill.

### Model A — Library seam: typed interfaces selected in code
agent-framework, openai-agents-sdk, pydantic-ai, and langgraph's OSS libraries define abstractions their users satisfy by passing instances or strings at construction time. Selection is type-checked and IDE-discoverable but never purely declarative. openai-agents-sdk resolves model strings through an injectable `ModelProvider` per run (`src/agents/run_internal/turn_preparation.py:134-143`); pydantic-ai resolves `'provider:model'` strings through factory functions with injectable provider factories (`pydantic_ai_slim/pydantic_ai/models/__init__.py:1529-1650`); langgraph takes saver/store/cache objects at `compile()` (`libs/langgraph/langgraph/graph/state.py:1179-1182`); agent-framework accepts any structurally-conforming client in the Agent constructor (`python/packages/core/agent_framework/_clients.py:96-127`).

### Model B — Config-product: externalized selection validated at startup
temporal and opa treat backend choice as a deployment concern expressed in config files and validated before serving traffic. temporal's union-config rule "one and only one datastore" aborts invalid startups with typed errors (`temporal`: `common/config/persistence.go:156-175`); opa's precedence chain is programmatic param → registered global → config default (`opa`: `v1/runtime/runtime.go:498-519`). Both bind the primary store once at process start — restart-required swaps accepted as the price of mid-flight consistency safety.

### Model C — Data-driven tenant selection
Where different tenants need different backends simultaneously, the discriminator moves into persisted records. langfuse stores the LLM `adapter` string on API-key rows so provider choice is data, not deployment (`packages/shared/prisma/schema.prisma:354`), and builds storage services per job from DB-stored integration configs (`worker/src/features/blobstorage/handleBlobStorageIntegrationProjectJob.ts:343-359`). letta instantiates the LLM client matching each agent's stored config at every step (`letta/agent.py:358-362`) and resolves BYOK credentials org-scoped from the DB at call time (`letta/llm_api/llm_client_base.py:399-437`). temporal resolves archivers per request from namespace URI schemes (`service/history/archival/archiver.go:187`).

### Model D — Runtime registries of mutable state
crewai, openai-agents-sdk, and openhands expose mutability itself as the extension surface, at three scopes: crewai offers process-wide setters (`set_memory_storage_factory`, `set_lock_backend`) documented as startup-intent plus a ContextVar-scoped RAG client swappable mid-flight (`lib/crewai/src/crewai/memory/storage/factory.py:28-55`; `rag/config/utils.py:26-81`); openai-agents-sdk allows live prefix-route edits through `MultiProviderMap.add_provider/remove_provider` (`src/agents/models/multi_provider.py:18-59`) and whole-tracing-pipeline replacement (`tracing/setup.py:27-66`); openhands lets end users add/edit/remove/activate entire remote backends through UI-driven store mutation with React Query keys re-scoped per backend (`src/contexts/active-backend-context.tsx:89-121`).

### Model E — Plugin/registry SPIs for third parties
opa and temporal make out-of-tree extension a first-class contract: opa's `plugins.Factory` + `runtime.RegisterPlugin`, `RegisterStorageBackend`, id-keyed signer/verifier maps, and named auth plugins (`v1/plugins/plugins.go:89-92`; `v1/runtime/runtime.go:95,104-108`); temporal's `AbstractDataStoreFactory` for custom datastores and `sqlplugin.RegisterPlugin` map for SQL dialects (`common/persistence/client/abstract_data_store_factory.go:14-25`; `common/persistence/sql/store.go:18-26`). langgraph's conformance package serves the same audience (third-party saver authors) through testing infrastructure rather than registration machinery.

## Pattern Catalog

### Pattern 1 — Interface + factory seam (universal)
- **Problem**: call sites must not know concrete backend technologies.
- **Seen in**: all ten sources. Representative forms: temporal `DataStoreFactory` (`persistence_interface.go:32-51`), langfuse `StorageServiceFactory.getInstance` (`StorageService.ts:279-348`), letta `LLMClient.create` match block (`llm_api/llm_client.py:10-145`), crewai RAG client registry (`rag/factory.py:20-78`), opa `rest.New` auth selection (`plugins/rest/rest.go:88-120`).
- **Why it works**: construction is centralized so cross-cutting wiring and validation happen once.
- **Copy when**: any backend family has two real implementations or credible third-party demand.
- **Overkill when**: only one implementation will ever exist — crewai's hard-wired kickoff-output SQLite store (`memory/storage/kickoff_task_outputs_storage.py:19-27`) and langfuse's deliberately unabstracted Prisma singleton (`db.ts:7-16`) are defensible non-decisions, not debts.
- **Evidence**: see citations above; each source report's evidence table lists the family-specific seam.

### Pattern 2 — Mechanical interchangeability enforcement (the 9-score differentiator)
- **Problem**: N implementations drift apart silently; docs claim parity that code loses.
- **Seen in**: temporal instantiates shared behavioral suites per backend driver (~50 suite bindings for SQLite alone, `common/persistence/tests/sqlite_test.go:98-136`); langgraph parametrizes the entire core test suite over 7 sync + 5 async checkpointers and ships a standalone conformance package for external implementers with capability auto-detection (`libs/checkpoint-conformance/.../capabilities.py:74-91`); pydantic-ai probes every API-backed model class's actual outbound wire payload against documented settings lists and walks the package so new classes cannot escape the matrix (`tests/models/test_model_settings_support.py:584-640`); agent-framework verifies protocol conformance without inheritance via `MockChatClient` fixtures (`python/packages/core/tests/core/conftest.py:108`); opa runs build-tagged e2e benchmark pairs against disk vs inmem stores (`v1/test/e2e/authz/disk.go:11-15`).
- **Why it works**: parity becomes a CI invariant instead of a documentation claim.
- **Copy when**: you maintain ≥2 backends behind one interface — this is the single highest-leverage practice observed.
- **Risky when**: the matrix depends on environment-contingent fixtures (langgraph drops heavy backends under `NO_DOCKER`, `libs/langgraph/tests/conftest.py:39,62`), quietly narrowing what local runs actually prove.

### Pattern 3 — Decorator/wrapper composition of cross-cutting concerns
- **Problem**: retry/metrics/tracing/rate-limit logic would otherwise be duplicated per implementation.
- **Seen in**: temporal wraps every manager rate-limit→metrics→retry and adds OTel tracing and fault-injection factories around any backend (`client/factory.go:109-260`, `fx.go:210-217`); pydantic-ai's `WrapperModel` base spawns Fallback/Instrumented/Temporal/MCP-sampling wrappers over any model (`models/wrapper.py:32-157`); agent-framework layers function invocation, middleware, and telemetry around raw clients in Python and uses `DelegatingChatClient` decorators in .NET (`_chat_client.py:3430-3436`; `dotnet/src/Microsoft.Agents.AI.Foundry/FoundryChatClient.cs:54`); langgraph composes encryption and batching as serializer/store decorators (`serde/encrypted.py:8`; `store/base/batch.py:58`).
- **Why it works**: safeguards attach to the interface, so every current and future backend inherits them.
- **Copy when**: cross-cutting behavior applies to all backends of a family.
- **Overkill/risky when**: interface surface is large — temporal needed gowrap-generated delegation to keep decorators complete (`common/persistence/telemetry/*_gen.go`).

### Pattern 4 — Registration-function registries
- **Problem**: adding implementations should not require editing central dispatch.
- **Seen in**: opa `RegisterPlugin`/`RegisterStorageBackend`/`RegisterSigner` (`runtime/runtime.go:95,104-108`; `bundle/sign.go:109-127`); temporal sqlplugin `RegisterPlugin` with duplicate-panic guard (`sql/store.go:21-26`); crewai `register_rag_client_factory` (`rag/factory.py:25-33`); openai-agents-sdk sandbox options classes self-register on subclassing keyed by a `type` literal (`sandbox/session/sandbox_client.py:53-106`).
- **Why it works**: closed sets become open without dynamic loading; duplicates fail loudly (temporal panics; openai-agents-sdk raises `TypeError` on duplicate discriminators).
- **Copy when**: third parties or sibling teams add backends independently.
- **Watch for**: single-slot variants that silently overwrite — opa's storage-backend and tracing globals hold exactly one value (`runtime/runtime.go:71-72`; `tracing/tracing.go:30-35`), unlike its id-keyed signer/verifier maps which allow many.

### Pattern 5 — Capability flags and probing protocols
- **Problem**: optional features (TTL, semantic search, streaming, hosted tools) shouldn't bloat base contracts.
- **Seen in**: langgraph `supports_ttl` raising a fix-naming `NotImplementedError` (`libs/checkpoint/langgraph/store/base/__init__.py:920-924`); agent-framework `SupportsCodeInterpreterTool`/`WebSearch`/... protocols probed instead of type-checking providers (`python/packages/core/agent_framework/_clients.py:668-869`); opa embeddable stubs (`WritesNotSupported`, `PolicyNotSupported`) letting partial backends satisfy a wide Store (`storage/interface.go:144-180`); pydantic-ai intersects profile claims with what the adapter class actually implements (`models/__init__.py:863-903`); openai-agents-sdk probes compaction support duck-typed (`memory/session.py:133-152`); letta's base classes raise descriptive errors for unimplemented batch/stream capabilities (`llm_api/llm_client_base.py:280-290,355-359`).
- **Why it works**: contracts stay minimal; variance between equal-looking backends becomes discoverable.
- **Copy when**: backends differ in optional features users might assume.
- **Limit**: flags don't help if callers ignore them — langgraph's vector index silently no-ops without `index` config even though the store is API-compatible (`store/base/__init__.py:716-721`).

### Pattern 6 — Persisted/data discriminators for per-tenant or per-object backends
- **Problem**: deployment-level selection can't express "this project uses Azure Blob, that one S3."
- **Seen in**: langfuse `adapter` column + zod connection schemas parsed per record (`schema.prisma:354`; `resolveAiSdkModelConfig.ts:31-100`); letta per-agent `LLMConfig` + `cast_to_subtype()` upcasting generic provider rows to 24 typed subclasses (`schemas/providers/base.py:179-258`); temporal namespace URI schemes dispatching archival per request (`service/history/archival/archiver.go:187`); openhands `Backend {kind, authMode}` records mutated at runtime (`api/backend-registry/types.ts:1-18`).
- **Why it works**: backend choice becomes queryable, migratable data with normal CRUD semantics.
- **Copy when**: multi-tenant platforms need per-tenant isolation of backend choice.
- **Requires**: connection-time validation for user-supplied endpoints — langfuse gates user-configured integrations behind SSRF checks and simply refuses GCS/OCI until validation exists (`handleBlobStorageIntegrationProjectJob.ts:356-357`).

### Pattern 7 — Dual-write migration bridges
- **Problem**: moving between backends without downtime needs overlapping writes with pinned reads.
- **Seen in**: temporal dual visibility — write modes off/on/dual plus namespace-scoped read preference and shadow reads, driven by dynamic config (`visibility/manager_selector.go:43-71`; `visibility_manager_dual.go:20-46`); letta fans telemetry writes to all configured backends concurrently with per-backend failure isolation while pinning reads to the first, explicitly designed for migration (`services/telemetry_manager.py:16-80`).
- **Why it works**: cutover becomes an operator-controlled dial, not a big-bang rewrite.
- **Copy when**: backend migration of live data is anticipated.
- **Cost**: read/write path complexity and validated combination rules (temporal forbids mixing advanced-SQL and ES, `config/persistence.go:44-84`).

### Pattern 8 — Failure-driven and fallback chains
- **Problem**: transient provider failures shouldn't kill runs; missing infra shouldn't kill startup.
- **Seen in**: pydantic-ai `FallbackModel` swaps backends on `ModelAPIError` or custom handlers (`models/fallback.py:86-120`); letta tries Modal→E2B→Local sandboxes with logged fallback (`tool_executor/sandbox_tool_executor.py:71-128`); openhands marks backends disabled after consecutive health-probe failures and falls back healthy-local→any-local→first-registered (`hooks/query/use-backends-health.ts:34-35,90-120`; `active-store.ts:29-62`); crewai selects Redis lock only if `REDIS_URL`+redis present else file lock (`lock_store.py:99-121`).
- **Why it works**: resilience lives above the adapter seam.
- **Danger**: fallback without signal — see Anti-Patterns below.

### Pattern 9 — Lazy imports + optional dependency groups keeping cores lean
- **Problem**: vendor SDKs are heavy; unused backends shouldn't tax install or import.
- **Seen in**: pydantic-ai lazy-imports every provider inside its dispatch branch matched to per-provider extras (`providers/__init__.py:152-279`; `pyproject.toml:72-161`); agent-framework resolves provider namespaces via `importlib` on first access (`python/packages/core/agent_framework/azure/__init__.py:27-31`); crewai loads chromadb/qdrant through a `require()` helper at factory time (`rag/factory.py:58-76`); openai-agents-sdk keeps Docker/litellm imports optional (`sandbox/sandboxes/__init__.py:30-41`).
- **Why it works**: adapters ship separately; failures occur only at use time with install hints.
- **Cost**: error-at-use instead of error-at-startup unless paired with eager validation elsewhere.

### Pattern 10 — Shipped test doubles as part of the public adapter story
- **Problem**: users can't unit-test harness code without live backends.
- **Seen in**: pydantic-ai `TestModel`/`FunctionModel`/`TestEmbeddingModel` implementing production interfaces (`models/test.py:62`; `function.py:52`); openai-agents-sdk `ScriptedModel`/`scripted_sandbox_session()` published under `src/agents/testing/` with repo policy preferring them (`testing/model.py:249`; AGENTS.md); opa ships an in-tree mock store consumers test against (`internal/storage/mock/mock.go:73-79`); langgraph's `InMemorySaver` doubles as reference implementation and test fixture (`checkpoint/memory/__init__.py:33`).
- **Why it works**: doubles exercise the exact SPI contracts users implement, catching contract bugs both ways.

## Key Differences

**Selection locus splits cleanly by product shape.** Deployable servers externalize selection to config files with startup validation (temporal `defaultStore` naming a `datastores` entry, `common/config/config.go:258-268`; opa `storage.disk` key, `storage/disk/config.go:29-67`; langfuse env flags like `LANGFUSE_USE_AZURE_BLOB`, `env.ts:263-296`). Libraries keep selection in code — openai-agents-sdk explicitly notes swapping session stores means editing construction code, env vars covering endpoints/keys/model names only (`docs/models/index.md:187-224`). This difference is valid, not a quality gap: ops teams need redeploy-free reconfiguration; library users need type safety and IDE discovery.

**Extension mechanics split open registries from closed dispatch.** Adding an SQL dialect to temporal requires zero core changes (register in `init()`, `sqlplugin/mysql/plugin.go:15-30`); adding an auth plugin to opa requires zero changes to selection logic thanks to reflection over credential fields (`plugins/rest/rest.go:103-115`). Conversely, adding a provider to letta means editing `ProviderType`, two factories, and two modules (`llm_api/llm_client.py`; `schemas/providers/base.py:210-258`), and pydantic-ai touches three hand-maintained if/elif chains (`providers/__init__.py:142-281`; `models/__init__.py:1583-1648`) — mitigated there by drift-detection tests, but still closed-source-of-truth-in-code. openhands sits at the extreme opposite: its cloud/local dispatch is duplicated as if-chains across ~15 services with nine branch sites in settings alone (`settings-service.api.ts:451-646`), making a hypothetical third backend kind expensive.

**Hot-swappability spans a spectrum, all bounded below mid-run mutation of live objects.** At the most dynamic end, openhands switches entire active backends synchronously from the UI (`contexts/active-backend-context.tsx:89-121`) and pydantic-ai swaps models mid-run on failure (`models/fallback.py:104-120`). In the middle, letta re-resolves the LLM client per request from stored agent state (`agent.py:358-362`), temporal re-evaluates visibility routing per call via dynamicconfig (`manager_selector.go:43-71`), and langgraph propagates checkpointer/store/cache per invocation through config keys (`pregel/main.py:2579-2601`). At the static end, langfuse memoizes singletons at module load so even storage changes need restart (`s3/index.ts:9-26`), and opa binds the store once during `runtime.New` (`runtime.go:505-519`). Notably, several sources treat non-hot-swappability as a deliberate safety feature: openai-agents-sdk blocks resuming a sandbox session on a mismatched backend identity (`sandbox/runtime_session_manager.py:444-449`).

**Proof strategy differs more than interface design does.** temporal and langgraph prove equivalence by running the same suites against every backend; pydantic-ai proves conformance by interrogating each adapter's wire output against declared capability lists; crewai proves substitution with end-to-end custom-`BaseLLM` tests inside a running Crew (`tests/test_custom_llm.py:83-333`); openhands proves transport discipline with an architectural guard test scanning all of `src/` for forbidden direct calls (`no-direct-agent-server-calls.test.ts:32-79`); opa proves interchange with compile-tag benchmark pairs. Interface declarations alone appear in none of the high scorers without accompanying enforcement.

**What each source abstracts reflects its domain honestly.** Storage diversity is temporal's product, so persistence is abstracted to the dialect level while LLM/vector/sandbox categories simply don't exist there. Langfuse's value is its own data platform, so datastores stay coupled while blob storage (multicloud portability matters) and LLM execution (breadth is the product) get exemplary seams. OpenHands' frontend owns no database; its analogue of the litmus question is repointing the whole app between local server and cloud via a UI form or env var (`agent-server-config.ts:98-100`). pydantic-ai states a primitives-over-batteries philosophy and stops at embeddings, delegating queues indirectly through three durable-execution engine adapters (`durable_exec/_base.py:40`).

## Tradeoffs

**Open registry vs closed match/if-elif chain.**
- Benefit (registry): third parties extend without core edits; duplicates panic loudly (temporal `sql/store.go:22-24`).
- Cost (registry): implicit init()-side-effect wiring is invisible in config; opa's single-slot globals silently replace prior registrations (`runtime/runtime.go:71-72`).
- Best fit: registries when extension frequency is high (SQL dialects, auth plugins); chains when the set is small and greppability valued.
- Alternative seen: pydantic-ai keeps chains but pairs them with an introspection test that fails when a new model class escapes the matrix (`tests/models/test_model_settings_support.py:623-640`) — closing the drift gap without giving up explicitness.

**Config-first vs code-first selection.**
- Benefit (config-first): operators swap Postgres→SQLite by editing YAML (temporal sample configs) or toggling a config block (opa); validated unions fail fast with typed errors (`config/persistence.go:156-175`).
- Cost (config-first): stringly-typed references lose compiler checking; temporal's top-level switch still requires core edits for a fourth technology (`client/fx.go:197-208`).
- Benefit (code-first): full type safety — pydantic-ai's generics enforce that `AnthropicModel` receives an `AsyncAnthropic` (`providers/__init__.py:24,42`).
- Failure mode (code-first): ops-only reconfiguration impossible; openai-agents-sdk documents programmatic recipes where a settings change would do (`docs/models/index.md:187-224`).

**Wide interface + capability stubs vs minimal abstract method.**
- opa's broad `Store` with embeddable `WritesNotSupported` stubs lowers the floor for partial backends but forces implementers to reason about transactions and triggers even when delegating (`storage/interface.go:33-44`). langgraph's `BaseStore` requires only `batch`/`abatch`, decomposing everything else into op objects — one transactional surface instead of six endpoints (`store/base/__init__.py:708-754`). Temporal's `ExecutionStore` carries ~25 methods including DLQ APIs, raising cost per adapter, mitigated by generated decorators and shared suites (`persistence_interface.go:116-167`).
- Comparative: langgraph's shape is cheapest for new authors; opa's maximizes engine simplicity; temporal's buys fine-grained operational control at author expense.

**Global mutable seams vs scoped injection.**
- crewai's `set_*_factory` functions avoid threading arguments through constructors but create hidden process-global state requiring reset discipline in tests (`memory/storage/factory.py:6-14`); openai-agents-sdk's tracing/global-client singletons make multi-tenant configurations awkward (`tracing/setup.py:11`). Contrast letta's constructor DI for pipeline stages (`FileProcessor(file_parser=..., embedder=...)`, `routers/v1/sources.py:520`) and agent-framework's .NET DI resolution (`AIAgentBuilder(Func<IServiceProvider, AIAgent>)`, `AIAgentBuilder.cs:26-35`).
- Middle ground seen: crewai scopes the genuinely dynamic seam (RAG client) in a ContextVar, reserving globals for startup-intent configuration.

**Silent fallback vs fail-fast.**
- Silent: letta maps unknown telemetry backends to postgres and unknown providers to OpenAI (`factory.py:25-28`; `llm_client.py:139-145`); crewai's knowledge search catches all exceptions and returns empty results so a broken vector backend looks like "no knowledge found" (`knowledge_storage.py:85-89`); openhands returns empty pages for cloud-only git search locally (`git-service.api.ts:42-44`); langgraph quietly ignores vector-index args on stores lacking support (`store/base/__init__.py:716-721`).
- Fail-fast: langfuse rejects cluster+sentinel Redis combos with logged error returning null (`redis.ts:238-246`); temporal's `Validate()` enforces "one and only one datastore"; openai-agents-sdk raises `UserError("Unknown prefix: ...")` unless pass-through is opted into (`multi_provider.py:222-225`); opa rejects unknown tracing transports at config validation, not first span (`distributedtracing.go:227-235`).
- Synthesis: the high scorers fail fast at boundaries (startup, resume, construction) and degrade gracefully only inside steady-state operation (trace export skipping without keys, `processors.py:131-134`), never conflating "unsupported" with "empty."

**Restart-time memoization vs per-request resolution.**
- Memoized module-level singletons (langfuse `s3/index.ts:9-26`, `redis.ts:455-461`) keep call sites clean but turn backend changes into deploy events. Per-request resolution (letta clients, temporal selectors) costs lookup overhead and requires careful caching (temporal memoizes archiver providers per scheme, `archiver/provider/provider.go:124-129`).

## Decision Guide

Choosing among the observed models:

1. **Building a deployable platform with an ops team?** Use temporal's shape: union-config discriminator with `Validate()` for top-level technology choice, a name-based plugin registry for sub-layers expected to grow (their SQL dialects), and decorator pipelines so every backend inherits resilience. Accept startup-only binding for stateful primaries; reserve runtime dials (dynamicconfig-style) for routing concerns where dual-write bridges exist.
2. **Building a library developers consume?** Use openai-agents-sdk/pydantic-ai's shape: small ABCs/Protocols, string-or-instance injection, injectable factory seams, shipped test doubles, and a drift-prevention conformance test. Don't build a config-file layer — env vars for credentials/base URLs suffice until users ask.
3. **Multi-tenant platform where tenants bring their own backends?** Persist the discriminator on the tenant record (langfuse adapter column, letta LLMConfig), validate user-supplied connection parameters at save/connect time (SSRF checks), and gate unvalidated transports off explicitly rather than exposing them half-safe.
4. **Expecting to migrate between backends post-launch?** Design the dual-write bridge early (temporal visibility selector/shadow-reads; letta telemetry fan-out) — retrofitting it later touches every call site.
5. **Only one plausible implementation today?** Hard-wire it deliberately and document why (langfuse datastore coupling; crewai kickoff store). Add the seam when a second implementation materializes — premature interfaces ossify wrong shapes (langfuse's optional-behavior members accumulating on `StorageService`, `uploadFileBuffered` stats being S3-only, `StorageService.ts:238-242`).
6. **Need third-party ecosystem extensions?** Provide registration machinery *plus* a runnable conformance suite (langgraph-checkpoint-conformance is the reference design): registration alone invites broken adapters because the real contract lives in behavioral subtleties, as OPA found relying on doc comments for its store contract (`storage/interface.go:19-44`).
7. **Frontend/client switching remote targets?** Consider openhands' registry-of-data-records model with health probing, per-backend cache keying, and URL pinning — but factor dispatch into a capability-descriptor interface before the second backend kind arrives, not after fifteen services have branched.

## Practical Tips

- **Make parity a test, not a promise.** Parametrize your core suite over every implementation of a family (langgraph `conftest.py:60-226`); instantiate shared suites per backend in CI (temporal `sqlite_test.go:98-136`); add a package-introspection guard so new adapters can't skip the matrix (pydantic-ai `test_every_api_backed_model_class_is_probed`).
- **Wrap the interface with safeguards once.** Retry/rate-limit/metrics/tracing decorators applied at the factory mean a new backend inherits production behavior for free (temporal `client/factory.go:109-260`); fault-injection wrappers targeted per store/method then exercise failure paths deterministically (`faultinjection/data_store_factory.go:25-33`).
- **Fail loud at boundaries, quiet in steady state.** Validate config unions, duplicate registrations, and mismatched resume identities eagerly (temporal, openai-agents-sdk); allow non-fatal degradation only for auxiliary flows (skipped trace export without keys).
- **Prefer capability discovery over type checks.** Probe protocol membership or flags (`Supports*` protocols; `supports_ttl`) so optional features compose without fat interfaces, and raise errors that name the fix when unsupported paths are hit (`NotImplementedError` messages in langgraph).
- **Keep heavy SDKs out of the core.** Per-provider optional dependency groups with lazy branch-local imports (pydantic-ai, crewai, agent-framework); convert absence into either graceful degradation with visible logging or actionable install instructions — never a bare crash, and never a silent no-op (contrast aiocache's debug-log disablement in crewai's file store with litellm's explicit install-guidance failure).
- **Separate who-am-I-talking-to from what-wire-do-they-speak.** pydantic-ai's Provider×Model split lets nineteen vendors share one chat adapter (`models/__init__.py:123-159`); agent-framework's Raw+Full split separates wire translation from composed behavior. New OpenAI-compatible vendors then cost one thin subclass (`providers/_openai_compatible.py:13-55`).
- **Ship the mock.** Publish test doubles conforming to production SPIs (pydantic-ai TestModel/FunctionModel; openai-agents-sdk ScriptedModel) — they document the contract better than prose and catch contract drift in both directions.
- **Enforce architecture mechanically.** When convention matters (all calls through transport choke points), write the scanning test (openhands `no-direct-agent-server-calls.test.ts:32-79`) rather than trusting review.
- **Give user-supplied endpoints connection-time validation.** SSRF/DNS/IP checks at connect, not per request (langfuse `connectionValidation`), and withhold backends lacking validation from user-facing surfaces entirely (`handleBlobStorageIntegrationProjectJob.ts:356-357`).

## Anti-Patterns / Caution Signs

- **Unknown identifiers silently resolving to defaults.** letta routes unrecognized telemetry backends to postgres and provider types to OpenAI (`factory.py:25-28`; `llm_client.py:139-145`); crewai drops unmatched models to LiteLLM changing streaming/auth behavior without an error (`llm.py:468-471`). Caution sign: misconfiguration surfaces as subtly-wrong production behavior.
- **Error-swallowing adapters.** CrewAI knowledge search returns `[]` on any backend exception (`knowledge_storage.py:85-89`); openhands git search returns empty pages outside cloud (`git-service.api.ts:42-44`). A dead backend becomes indistinguishable from absent data.
- **Dispatch logic metastasizing.** Count your branch sites: openhands has ~20 in automation-service alone (`automation-service.api.ts:252-767`); letta scatters `database_engine` conditionals across ~15 files including ORM column definitions (`orm/passage.py:35-40`). Each new backend kind or dialect multiplies audit surface.
- **Interface drift via optional members.** langfuse's `uploadFileBuffered` returning stats only on S3, kept because "existing callers ignore it" (`StorageService.ts:238-242`) — optional-behavior accretion signals the interface is becoming a log of historical accidents.
- **Single-slot globals that overwrite silently.** opa's registered-storage-backend and tracing slots (`runtime/runtime.go:71-72`; `tracing/tracing.go:30-35`): a second registration replaces the first with no diagnostic. Prefer id-keyed maps (as opa itself did for signers/verifiers).
- **Import-time binding of schema to config.** letta fixes vector column types at class-definition time based on the current engine (`passage.py:35-40`), ruling out same-process swaps and entangling schema definition with deployment config.
- **Capability asymmetries gated ad hoc by callers.** openhands documents "Cloud has no equivalent yet, so callers must gate usage" (`provider-connections-service.api.ts:8-9`) instead of negotiating capabilities via server metadata (its `/server_info.usable_tools` shows the right pattern, `agent-server-compatibility.ts:27-34`).
- **Environment-contingent guarantees.** langgraph's parity matrix drops Docker-dependent backends locally (`conftest.py:39,62`) — CI proves what local runs don't; be explicit about which equivalences hold where.
- **Lifecycle gaps in the extension contract.** OPA documents that plugin `Stop` may never be called (`plugins/plugins.go:101`), leaving sink adapters buffering events responsible for their own flush safeguards — extension SPIs must specify shutdown semantics or adapters leak.
- **Plaintext credentials in convenience stores.** openhands persists backend API keys in localStorage (`storage.ts:95-102`) while deliberately keeping git tokens server-side — inconsistent secret posture within one mechanism.

## Notable Absences

Conspicuous gaps, each stated with its search boundary from the source report:

- **Generic vector-store abstractions**: none in agent-framework (vector search reachable only via hosted-tool protocols and per-package context providers), langfuse, openai-agents-sdk, pydantic-ai, opa, or openhands. Only langgraph (Postgres/pgvector + sqlite-vec stores behind `BaseStore`), letta (pgvector/sqlite-vec natively plus TPUF/Pinecone enums), and crewai (LanceDB/Qdrant behind `StorageBackend`/`BaseClient`) offer real ones.
- **Queue/broker abstractions**: agent-framework defers durable queues to an external repo; langgraph has only internal in-process primitives (`_internal/_queue.py:12,70`); langfuse is BullMQ-coupled across ~30 queue classes with Kafka absent from the codebase (`getQueue.ts:36-115`); crewai, openai-agents-sdk, and letta (beyond the Temporal stub) have none; temporal's queues are always backed by the selected datastore (`persistence_interface.go:170-185`).
- **Sandbox abstractions**: langgraph zero matches repo-wide; crewai ships only single-vendor E2B tools; pydantic-ai none by philosophy. Strong sandboxes exist precisely in agent-framework (Hyperlight WASM/Monty/local/Docker shells), openai-agents-sdk (core unix_local/docker + seven hosted extension clients behind `BaseSandboxClient`), and letta (Local/E2B/Modal).
- **Tracing-sink seams in libraries that need them elsewhere**: langgraph delegates observability to LangChain callbacks with no sink interface (zero OTel matches); openhands fixes telemetry to PostHog with only endpoint/key configurable (`services/telemetry.ts:12-23`); crewai's product-telemetry endpoint is hard-coded to its collector (`telemetry/constants.py:9`) even as its event bus remains fully pluggable. Meanwhile dedicated sinks exist in openai-agents-sdk (`TracingProcessor`/`TracingExporter`), agent-framework (arbitrary OTel exporter lists), pydantic-ai (injected tracer/meter providers), letta (postgres/clickhouse/socket), and temporal/opa (config-selected exporters).
- **Name-based backend registries in OSS libraries**: langgraph requires importing concrete classes (mitigated at server layer by `CheckpointerConfig.path` import strings); pydantic-ai/openai-agents-sdk selection is code-resident strings.
- **Live migration tooling for primary stores**: neither temporal nor letta ships in-repo migration for the main database despite both demonstrating the dual-write pattern elsewhere (visibility; telemetry).

## Per-Source Notes

- **agent-framework (8)** — Two-language adapter estate: Python Protocols/ABCs plus layered mixins; .NET reuses Microsoft.Extensions.AI `IChatClient` with decorator pipelines. Composition-time binding only; strongest capability-probing design in the set; vector-store and queue categories missing or out-of-tree (`python/packages/core/agent_framework/_clients.py:85-201`; `dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:80`).
- **crewai (8)** — Every category an agent harness touches has a Protocol/ABC+factory seam except three hard-wired outliers (product telemetry, kickoff SQLite, file cache). Distinctive constructor-as-factory LLM routing and contextvars-scoped runtime swaps; silent degradation paths are the main hazard (`lib/crewai/src/crewai/llm.py:393-512`; `knowledge/storage/knowledge_storage.py:85-89`).
- **langfuse (7)** — Exemplary where abstractions exist: four-cloud `StorageService` with SSRF-validated user integrations, six LLM adapters dispatched on a persisted column with exhaustive switch checks. Datastores and queues deliberately unseamed; selection restart-bound except DB-record-driven cases (`packages/shared/src/server/services/StorageService.ts:279-348`; `prisma/schema.prisma:354`).
- **langgraph (8)** — Persistence-first design with the study's cleanest interchangeability story: dependency-free base package, shared test matrices, and a third-party conformance package with capability auto-detection. No registry shorthand in OSS libs; queues/sandboxes/tracing absent (`libs/checkpoint-conformance/README.md:27-81`; `libs/langgraph/tests/conftest.py:60-226`).
- **letta (8)** — ABCs at every seam with genuine per-request provider switching driven by stored agent state and DB-resolved BYOK keys; dual-write telemetry designed for migrations. Closed match-factories, silent defaults, and ~15-file dialect conditioning cap the score (`letta/agent.py:358-362`; `services/telemetry_manager.py:16-80`).
- **opa (8)** — Config-first Go interfaces with registry/plugin SPIs; the only non-temporal source answering the litmus question literally (config-block presence swaps disk↔inmem). Single-slot globals and restart-only store binding are the limits; build-tag benchmark pairs are a clever interchange proof (`v1/runtime/runtime.go:490-519`; `v1/test/e2e/authz/disk.go:11-15`).
- **openai-agents-sdk (9)** — Small explicit SPIs at every boundary, run-scope injection, prefix-routing with ambiguity knobs, self-registering discriminated options, shipped fakes, and security-motivated guards (no implicit sandbox default; resume identity checks). Code-first selection is the sole structural limitation (`src/agents/models/interface.py:37-65`; `sandbox/runtime_session_manager.py:444-499`).
- **openhands (7)** — A frontend reinventing backend adapters as user-mutable data records with health probing, per-backend cache keying, and a CI-enforced transport choke point — genuinely runtime-swappable by end users. Pays in if-chain duplication, silent asymmetries, and plaintext key storage (`src/api/backend-registry/types.ts:1-18`; `no-direct-agent-server-calls.test.ts:32-79`).
- **pydantic-ai (9)** — Provider×Model decomposition yielding extreme reuse (19 providers on one chat adapter), wrapper-decorator composition, profiles as layered capability truth, and the set's most aggressive anti-drift testing. Dispatch chains hand-maintained; no file-based selection (`pydantic_ai_slim/pydantic_ai/providers/__init__.py:42-136`; `tests/models/test_model_settings_support.py:584-640`).
- **temporal (9)** — The reference implementation for storage-heavy products: abstract factory over nine store interfaces, SQL dialect plugin registry, uniform resilience/fault-injection decorators, per-backend conformance suites, dual-write visibility migrations, URI-scheme archiver dispatch. Startup-only primary binding and minor interface leakage (`CassandraBlob`) remain (`common/persistence/persistence_interface.go:32-51`; `common/persistence/client/factory.go:109-260`).
