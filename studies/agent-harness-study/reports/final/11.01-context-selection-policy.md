## Executive Summary

All seven harnesses treat context selection as an engineered subsystem rather than an accident of prompt concatenation, but they implement three distinct architecture families. **Seam-based pipelines** (pydantic-ai, agent-framework, openai-agents-sdk) rebuild or project the model-facing message list at named, ordered assembly points and expose user-installable policies (history processors, context providers, input filters) as the only subtraction mechanism ([pydantic-ai report](../source/11.01-context-selection-policy/pydantic-ai.md), `pydantic_ai_slim/pydantic_ai/_agent_graph.py:1451-1623`; [agent-framework report](../source/11.01-context-selection-policy/agent-framework.md), `python/packages/core/agent_framework/_agents.py:1616-1637`). **Materialized-state systems** (letta, langgraph) make context durable, inspectable state — letta persists an explicit message-ID window governed by a dual-trigger compaction engine ([letta report](../source/11.01-context-selection-policy/letta.md), `letta/agents/helpers.py:177-220`, `letta/agents/letta_agent_v3.py:1439-1474`), while langgraph reduces selection to schema declaration over typed channels and delegates curation entirely to graph authors ([langgraph report](../source/11.01-context-selection-policy/langgraph.md), `libs/langgraph/langgraph/graph/state.py:1515-1547`). **Boundary/template assemblers** (crewai, openhands) express policy as imperative prompt composition (crewai's i18n-slice append chain, `lib/crewai/src/crewai/utilities/prompts.py:93-141`) or as a client-side conversation-start envelope with history policy delegated to a backend (openhands' `buildStartConversationRequest`, `src/api/agent-server-adapter.ts:1050-1231`).

Four findings converge across all seven despite these differences. First, the default policy is maximal inclusion: every source sends everything it has unless the application opts into trimming, compaction, or filtering (pydantic-ai's documented default, openai-agents-sdk's `limit=None`, langgraph's bare `state["messages"]`). Second, every source gives the model sanctioned ways to grow its own context — retrieval tools, progressive disclosure, or delegation — making modern context selection partly model-controlled. Third, no source redacts sensitive fields on the path into the model; redaction exists only on observability surfaces (traces, logs, telemetry) or is explicitly delegated to application code. Fourth, every source hardens tool-call/result pairing against selection damage — through repair, rejection, or atomic-group invariants — because structural validity is what providers reject first.

The maturity frontier is explainability, not mechanism. CrewAI uniquely renders memory-match scores and reasons *into the prompt itself* (`lib/crewai/src/crewai/memory/types.py:92-106`); agent-framework stamps machine-readable attribution on every injected message; letta exposes a per-section token breakdown API; openhands records which skills activated per message. But no source can fully answer "why was this specific document included?" for arbitrary context items, and none maintains per-item inclusion audit logs.

## Core Thesis

Modern agent harnesses have converged on one architectural commitment — **preserve complete truth, project a filtered view, and make every deviation from "include everything" an explicit, attributable act** — while remaining deliberately silent on content-level sensitivity, which every source either restricts to observability channels or pushes to application code. The separation of canonical record from model view appears in six of seven sources in different guises (langgraph's `llm_input_messages` vs persisted `messages`, openai-agents-sdk's `input_items` vs `new_items`, pydantic-ai's canonical history vs cleaned wire view, agent-framework's exclusion flags with reasons, letta's summarize-in-place over queryable storage, openhands' `forgotten_event_ids`); crewai is the lone counter-example, replacing history in place during summarization. What separates the top scorers from the rest is not whether they can select context but whether selection is *inspectable and safe by construction*: typed seams with tests (pydantic-ai, 9), provenance stamped at merge time plus non-destructive compaction (agent-framework, letta, openai-agents-sdk, 8), versus scattered imperative logic or unauditable delegation (crewai, langgraph, openhands, 7). The universal gap is safety: not one source scans content bound for the model, leaving secrets-and-PII handling as the least mature axis of context engineering across the entire ecosystem.

## Approach Models

### 1. Ordered subtractive pipeline over retained truth (pydantic-ai)

Pydantic AI retains the entire conversation append-only and re-sends all of it each step, then runs a fixed sequence: append new request → resolve instructions fresh → run `before_model_request` capability chain (where user `ProcessHistory` processors prune/rewrite/summarize) → validate → normalize (`_clean_message_history`: drop orphaned results, repair dangling calls, merge consecutive) → project through the provider adapter → trim at `CompactionPart` boundaries → pre-count tokens ([pydantic-ai report](../source/11.01-context-selection-policy/pydantic-ai.md), `pydantic_ai_slim/pydantic_ai/_agent_graph.py:1451-1623,2960-2986`; `docs/capabilities/process-history.md:1-15`). Each pass is a named, documented function whose ordering rationale is argued in prose in the docstring (`_agent_graph.py:2963-2982`). Derived state (discovered tools, loaded capabilities) is recomputed from the single `post_compaction_window` boundary rule rather than remembered, so it self-heals across failover (`messages.py:2774-2814`). This model fits libraries that must stay provider-neutral while letting applications choose their own budget policy.

### 2. Provider pipeline with provenance stamping (agent-framework)

Agent Framework merges caller input with pluggable history providers, then enriches via ordered `ContextProvider.before_run` / .NET `AIContextProvider.InvokingAsync` plugins contributing messages, instructions, tools, and middleware into a shared carrier; a final compaction stage annotates groups and projects only included ones ([agent-framework report](../source/11.01-context-selection-policy/agent-framework.md), `python/packages/core/agent_framework/_agents.py:1625-1637`; `dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:762-808`; `python/packages/core/agent_framework/_compaction.py:705-736`). Two properties distinguish it: every injected message is stamped with `_attribution` metadata including cross-session origins (`python/packages/core/agent_framework/_sessions.py:661-694`), and compaction exclusion always records a reason string rather than deleting (`_compaction.py:718-727`). This model fits multi-source enterprise agents where downstream governance needs to know *which component* contributed each item.

### 3. Rebuild-per-call with a last-mile hook (openai-agents-sdk)

The runner reconstructs model input from scratch each call: session fetch under `SessionSettings.limit` → new turn input → generated items minus approval items → normalization (orphan pruning, internal-metadata stripping, dedupe-preferring-latest) → system prompt → tool schema resolution → the optional `call_model_input_filter` immediately before sending ([openai-agents-sdk report](../source/11.01-context-selection-policy/openai-agents-sdk.md), `src/agents/run_internal/run_loop.py:2097-2152`; `src/agents/run_internal/items.py:171-304`; `src/agents/run_config.py:438-446`). Handoffs add a second selection layer (`Handoff.input_filter`, opt-in `nest_handoff_history` transcript compression with digest-based provenance, `src/agents/handoffs/history.py:83-157`). Concrete shipped policies — `ToolOutputTrimmer`, `OpenAIResponsesCompactionSession` — are themselves just callables implementing the filter protocol (`src/agents/extensions/tool_output_trimmer.py:87-202`). This model fits SDKs that want one universal mutation point regardless of upstream storage choice.

### 4. Materialized window + compaction engine (letta)

Letta's context is two persisted artifacts: a recompilable system message templated from compiled memory state, and an explicit DB-backed `message_ids` list mutated only through dedicated APIs ([letta report](../source/11.01-context-selection-policy/letta.md), `letta/services/helpers/agent_manager_helper.py:251-332`; `letta/services/agent_manager.py:999,1622-1638`). A configurable engine evicts oldest-first up to assistant/approval-boundary cutoffs, inserts recursive summaries at position 1, and verifies results against the trigger threshold with a mode-fallback ladder (self→sliding→all) (`letta/services/summarizer/summarizer_sliding_window.py:144-198`; `letta/services/summarizer/compact.py:274-296,359-407`). Triggers are dual: proactive at 90% of window after each step, reactive on overflow errors (`letta/agents/letta_agent_v3.py:1218-1284,1439-1474`). This model fits hosted products running long-lived agents where the operator, not each application, must guarantee bounded input.

### 5. Declarative channel projection (langgraph)

LangGraph expresses selection as type-level artifacts: a node sees exactly the state channels named in its input schema, wired at compile time (`libs/langgraph/langgraph/graph/state.py:1515-1547`; `libs/langgraph/langgraph/pregel/_read.py:102-105`); the prebuilt agent passes whole `messages` unless a `pre_model_hook` returns a separate `llm_input_messages` view or rewrites history via the `REMOVE_ALL_MESSAGES` sentinel (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:396-424`; `libs/langgraph/langgraph/graph/message.py:209-213`); tools declare their own context needs via `InjectedState`/`InjectedStore` annotations, stripped from model-visible schemas and protected against LLM-forged values (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1421-1430,1814-1819`). Inclusion policy beyond this is delegated — deliberately, with trimming framed as user-authored hook content (`chat_agent_executor.py:397`). This model fits graph-programming teams who want auditability from the definition alone and accept hand-rolled curation.

### 6. Imperative template composition (crewai)

CrewAI composes context as a fixed code-defined order: i18n role/tool/task slices → output-schema instructions → upstream task outputs joined with dividers (unbounded) → top-5 recalled memories → LLM-query-rewritten knowledge snippets above 0.6 similarity → files and opt-in date, appended onto one flat task string ([crewai report](../source/11.01-context-selection-policy/crewai.md), `lib/crewai/src/crewai/utilities/prompts.py:93-141`; `lib/crewai/src/crewai/crew.py:1866-1874`; `lib/crewai/src/crewai/agent/core.py:540-566`). Memory scoring is genuinely sophisticated — weighted semantic/recency/importance composite with half-life decay, oversample-then-trim, confidence-routed deep recall (`lib/crewai/src/crewai/memory/types.py:135-286,345-380`; `lib/crewai/src/crewai/memory/recall_flow.py:1-68`) — but inclusion order and budgets live implicitly in `execute_task`. Overflow is handled reactively: substring-matched provider errors trigger chunked LLM summarization if `respect_context_window` is enabled, else `SystemExit` (`lib/crewai/src/crewai/utilities/agent_utils.py:781-832`). This model fits opinionated team workflows, at the cost of per-source budgets and centralized policy.

### 7. Boundary envelope with delegated interior (openhands)

OpenHands' frontend owns only what enters the model's *world* at conversation start — merged skill catalog under a deny-list, gated tools, workspace binding, initial message, runtime-services system suffix — via one pure builder (`buildStartConversationRequest`, [openhands report](../source/11.01-context-selection-policy/openhands.md), `src/api/agent-server-adapter.ts:1050-1231`), plus per-message augmentation (attachments, `src/utils/send-message-with-attachments.ts:50-79`) and input diversion (slash-command interceptors, `src/components/features/chat/interactive-chat-box.tsx:47-56`). History-view management belongs to the backend: the frontend observes condensation outcomes (`CondensationEvent.forgotten_event_ids`, `src/types/agent-server/core/events/condensation-event.ts:14-37`), exposes condenser knobs schema-driven (`src/routes/condenser-settings.tsx:3-12`), and offers manual compaction verified by correlating a real event with a measured `per_turn_token` drop (`src/hooks/use-await-context-compaction.ts:57-164`). This model fits client/server products where trust and authority must split across a process boundary.

## Pattern Catalog

### Pattern 1: Deterministic assembly seam before every model call

**Problem:** without a single choke point, "what did the model see?" becomes unanswerable and enrichment logic scatters across executors.
**Demonstrated by:** pydantic-ai (`_prepare_request`, `pydantic_ai_slim/pydantic_ai/_agent_graph.py:1451-1623`), agent-framework (provider loops invoked at fixed seams, `python/packages/core/agent_framework/_clients.py:366-394`; decorator choke point `dotnet/src/Microsoft.Agents.AI/AIContextProviderDecorators/AIContextProviderChatClient.cs:28-73`), openai-agents-sdk (`call_model_input_filter` last-mile hook, `src/agents/run_internal/turn_preparation.py:51-93`), langgraph (`pre_model_hook`, `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:396-424`).
**Why it works:** observation, testing, and extension happen in one place; agent-framework even guarantees failure notification to providers when the call throws (`AIContextProviderChatClient.cs:64-68`).
**Copy when:** building any runtime with more than one context source.
**Overkill/risky when:** a simple single-source pipeline can flat-append (crewai works fine until budgets matter — then the missing seam is exactly its weakness).
**Evidence:** tests pin behavior at each seam (openai-agents-sdk `tests/test_call_model_input_filter.py:18-400`; pydantic-ai `tests/test_history_processor.py:973-992`).

### Pattern 2: Model view ≠ stored truth (non-destructive selection)

**Problem:** destructive trimming destroys audit trails, breaks retries/resume, and makes debugging impossible.
**Demonstrated by:** langgraph's `llm_input_messages` view channel vs checkpointed `messages` (`chat_agent_executor.py:396-424,636-658`); openai-agents-sdk's filters shrinking `input_items` while `new_items` persist intact (`src/agents/handoffs/__init__.py:94-99`); pydantic-ai's canonical-history-in-place replacement vs deliberately-unstored wire view (`_agent_graph.py:1551-1568`); agent-framework's excluded-with-reason flags (`python/packages/core/agent_framework/_compaction.py:718-727`); letta's summarize-in-place keeping full storage searchable (`letta/services/summarizer/compact.py:462-465`); openhands' condensation events listing forgotten ids (`src/types/agent-server/core/events/condensation-event.ts:14-26`).
**Why it works:** enables audit replay, recovery after retry, and "what did the model forget" inspectors; compaction becomes reversible-by-design.
**Copy:** essentially always.
**Risk:** dual views can drift silently — openhands compensates with a system-prompt modal exposing the delta (`src/utils/system-message-adapter.ts:13-35`); crewai, lacking this pattern, loses verbatim history permanently on summarization (`lib/crewai/src/crewai/utilities/agent_utils.py:900-1131`).

### Pattern 3: Progressive disclosure (advertise → load on demand)

**Problem:** front-loading tool bodies, skill instructions, or document corpora consumes the window before work begins.
**Demonstrated by:** agent-framework MCP loader tools (`list_mcp_tools`/`load_tool`/`unload_tool`, `python/packages/core/agent_framework/_mcp.py:93-95,524-531`), skills advertisement plus `load_skill` (`python/packages/core/agent_framework/_skills.py:1931,2299`), and RAG-as-tool instead of auto-injection (`dotnet/src/Microsoft.Agents.AI/TextSearchProvider.cs:96-131`); crewai's metadata-only `<available_skills>` catalog with loader tool kept as cache anchor (`lib/crewai/src/crewai/utilities/prompts.py:165-209`); openai-agents-sdk deferred-loading tools discovered via `ToolSearchTool` (`src/agents/tool.py:1510-1574`); pydantic-ai tool search with discovery evidence re-derived only from the visible post-compaction window so phantom tools cannot survive pruning (`pydantic_ai_slim/pydantic_ai/toolsets/_tool_search.py:196-230`); letta's `<memory_metadata>` advertising out-of-window recall/archival counts and tags (`letta/prompts/prompt_generator.py:26-89`).
**Why it works:** baseline context stays small; the model pulls precisely what it needs; pydantic-ai shows how to keep derived state consistent with what is actually visible.
**Copy when:** any catalog exceeds roughly a screenful of tokens.
**Risk:** effective context becomes non-reproducible run-to-run (noted in crewai's tradeoffs), and discovery gaps cause refusals rather than silent misbehavior (pydantic-ai availability gating, `_tool_search.py:199-205`).

### Pattern 4: Structural validity as invariant under selection

**Problem:** selectors that break tool-call/result pairing produce API-rejected payloads or corrupted histories.
**Demonstrated by:** two philosophies. Repair-not-fail: pydantic-ai synthesizes results for dangling calls and drops orphaned results deterministically (`_agent_graph.py:2960-2986`); openai-agents-sdk prunes orphaned calls plus preceding dangling reasoning items (`src/agents/run_internal/items.py:171-304`). Fail-fast: langgraph rejects broken pairing with `INVALID_CHAT_HISTORY` before the model call (`chat_agent_executor.py:243-271`) and raises on unknown-ID removals (`libs/langgraph/langgraph/graph/message.py:227-230`). Atomicity invariants: agent-framework keeps reasoning/function-call/result groups atomic and ambiguous duplicates separate (`python/packages/core/agent_framework/_compaction.py:105-123`); letta makes pending approvals un-evictable and pairs approval+assistant sharing a `step_id` (`letta/services/summarizer/self_summarizer.py:265-289`).
**Why it works:** providers reject malformed sequences; both styles prevent a selector from ever emitting one.
**Copy:** universally. Choose repair-not-fail for resilience, fail-fast where corruption would be worse than failure.

### Pattern 5: Explainability artifacts at three depths

**Problem:** opaque inclusion erodes trust and debuggability — the dimension's guiding question goes unanswered.
**Demonstrated by:** three escalating depths. (a) *Structural provenance*: agent-framework's `_attribution` with source id/type/origin sessions (`python/packages/core/agent_framework/_sessions.py:661-694`; .NET `dotnet/src/Microsoft.Agents.AI.Abstractions/AgentRequestMessageSourceAttribution.cs:14-45`), openhands' per-message `activated_skills` with the added content (`src/types/agent-server/core/events/message-event.ts:11-24`), openai-agents-sdk's SHA-256 digest-based occurrence identity (`src/agents/run_internal/items.py:393-412`). (b) *Quantitative rationale*: crewai renders `(score=0.87)` plus match reasons (semantic/recency/importance) directly into the prompt text (`lib/crewai/src/crewai/memory/types.py:92-106,374-378`); letta's search tools return rrf_score/rank metadata (`letta/services/tool_executor/core_tool_executor.py:231-246`). (c) *Budget signaling*: letta's `<file_limits>` showing `chars_current` vs `chars_limit` and `ContextWindowOverview` per-section token API exposed over REST (`letta/schemas/memory.py:23-65,589-633`; `letta/server/rest_api/routers/v1/agents.py:601`).
**Why it works:** provenance answers "who put this here," scores answer "why this one," budget signals let the model manage its own slots.
**Copy:** out-of-band provenance metadata as the default; in-prompt scores only where the model benefits from judging reliability — crewai's unusual choice costs tokens and may bias generation, but makes inclusion legible to the model itself.
**Limit:** letta found no persistent per-item eviction rationale; openai-agents-sdk's ownership digests are private machinery not surfaced to users (`items.py:114-128`).

### Pattern 6: Secrets-by-reference transport (with one instructive exception)

**Problem:** secret values placed in prompts leak into logs, traces, and recall storage.
**Demonstrated by:** openhands rides every secret as a `LookupSecret` reference resolved server-side at spawn time, with Fernet-encrypted settings round-trips and fail-hard refusal to start conversations on redacted credentials (`src/api/agent-server-adapter.ts:1203-1228`; `src/api/settings-service/settings-service.api.ts:500-512`); letta wraps credentials in an encrypted `Secret` and passes decrypted values only as sandbox environment variables, never prompts (`letta/schemas/secret.py:34-69`; `letta/agents/letta_agent.py:1950-1959`).
**Why it works:** the executor gets the value; the context never does.
**Exception worth studying:** openhands' own SDK injects a `<CUSTOM_SECRETS>` block into the system prompt's `dynamic_context` — the frontend adds display-only masking backstops (`redact-custom-secrets.ts:8-31`, tested at `__tests__/utils/system-message-adapter.test.ts:59-76`) while acknowledging the model sees values by design (`system-event.ts:21-25`). Where the model genuinely needs the value, no reference scheme helps — and no source scans those paths.

### Pattern 7: Dual-trigger compaction with verification

**Problem:** overflow handling determines whether long runs die, waste round trips, or degrade gracefully.
**Demonstrated by:** letta checks proactively after each step at `context_window × 0.9` and reactively catches `ContextWindowExceededError` with bounded retries, then verifies post-compaction tokens against threshold with a dedicated error if the system prompt alone is oversized (`letta/agents/letta_agent_v3.py:1218-1284,1439-1474`; `letta/services/summarizer/compact.py:359-407`); openai-agents-sdk triggers server-side compaction at ≥10 candidate items, excluding user messages and prior compactions (`src/agents/memory/openai_responses_compaction_session.py:28-60`); pydantic-ai delegates triggering to provider-native capabilities with token thresholds (`pydantic_ai_slim/pydantic_ai/models/anthropic.py:2681,2723`); agent-framework composes strategies under a token budget with a deterministic enforcement fallback (`python/packages/core/agent_framework/_compaction.py:1400-1472`); crewai is reactive-only via fragile provider-error substring matching, defaulting to process death (`lib/crewai/src/crewai/utilities/agent_utils.py:781-832`).
**Why it works:** proactive triggers avoid wasted round trips; reactive triggers catch estimation error; verification catches non-convergence instead of looping silently (letta logs critical and continues, `compact.py:409-412`).
**Copy when:** any long-running deployment. Reactive-only is acceptable for short-lived library runs only if failure is loud — crewai's exit-by-default fails that test.

### Pattern 8: Trust-boundary filtering distinct from content policy

**Problem:** untrusted parties (client apps, the model itself) can inject privileged content into context.
**Demonstrated by:** pydantic-ai's `sanitize_messages` strips client-submitted system prompts, non-HTTP file URLs, forced downloads, uploaded files, and dangling tail calls — warning per rule with escape hatches named (`pydantic_ai_slim/pydantic_ai/messages.py:2953-3135`; warnings at `:3077-3133`), and distrusts client-supplied `CompactionPart`s entirely (`messages.py:3000-3005`); langgraph strips LLM-forged values for injected parameter names and hides injection from model-facing schemas, adversarially tested (`libs/prebuilt/langgraph/prebuilt/tool_node.py:1421-1430`; `libs/prebuilt/tests/test_tool_node.py:2202-2232`); openai-agents-sdk applies its reasoning-ID policy symmetrically on read and write so stored history can't poison requests (`src/agents/run_internal/session_persistence.py:362-368`); agent-framework documents non-validation as an API contract, shifting trust decisions to provider authors (`dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:34-39`).
**Why it works:** separating *who may say what* from *what content is acceptable* lets frameworks enforce the former structurally while honestly declining the latter.
**Copy:** always draw the model-vs-system and client-vs-server lines explicitly; note the divergence — libraries sanitize inputs they receive, agent-framework documents its refusal to.

## Key Differences

**What converges.** Despite three architecture families, all seven agree on: default-maximal inclusion with opt-out subtraction (pydantic-ai documents "send everything" as the null policy, `docs/message-history.md:690-920`; openai-agents-sdk `limit=None`, `src/agents/memory/session_settings.py:30-39`; langgraph's bare-history default, `chat_agent_executor.py:139-142`); model-initiated context growth through sanctioned tool channels (retrieval tools in letta/crewai/agent-framework, hosted search plus deferred loading in openai-agents-sdk, child-conversation delegation in openhands, `src/services/child-conversation-launch.ts:488-496`); protection of tool-pairing structure during any selection (Pattern 4); and redaction confined to observability surfaces — traces, logs, telemetry — never the model path.

**Why they diverge.** The dominant variable is product shape, not quality. Libraries (pydantic-ai, openai-agents-sdk, langgraph, agent-framework) ship seams and delegate policy because their users' contexts differ too widely to pick defaults for; hosted/product systems (letta, openhands) implement concrete engines because operators need guarantees, not options — letta must compact proactively for long-running hosted agents, openhands splits authority across a client/server trust boundary and therefore audits only the envelope it owns. Maturity drift creates a second axis: letta carries three coexisting loop generations applying different effective policies (`letta/agents/letta_agent.py:1550-1618` vs `letta_agent_v3.py:1218-1284`; v2 deprecated at `letta_agent_v2.py:1361`), crewai's selection logic is duplicated across three executors that already diverge (`lib/crewai/src/crewai/lite_agent.py:599-620` injecting memory into the system message vs user-prompt appends elsewhere), and langgraph has deprecated its factory toward external middleware (`chat_agent_executor.py:53-56`). A third axis is cache economics: systems paying per-prefix-token engineer ordering around stability — crewai pins volatile blocks to the tail with breakpoint markers (`lib/crewai/src/llms/cache.py:27-32`), letta skips system-prompt rebuilds unless content actually changed (`letta/agents/letta_agent_v2.py:760-792`), pydantic-ai distinguishes self-planted standing prompts from externally supplied ones via provenance stamps (`pydantic_ai_slim/pydantic_ai/messages.py:1979-1985`). Systems without that pressure (early-stage or server-managed histories) don't pay this complexity.

**Differences that are not quality differences.** LangGraph's low built-in surface is deliberate minimalism backed by its own threat model documentation, not neglect (`.github/THREAT_MODEL.md:179,396`). OpenHands' frontend score reflects an evidence boundary, not absent machinery — the backend simply wasn't in scope. CrewAI's flat single-string prompt trades structured provenance for plumbing simplicity, a coherent choice for its template-driven team-workflow niche even though it forfeits per-source budgets.

## Tradeoffs

- **Centralized engine vs delegated seams.** Letta's compaction engine guarantees bounded windows uniformly but is hard to evolve — three generations of divergent behavior prove it (`letta/agents/letta_agent.py:1587` warns configs can break the floor). LangGraph's delegation stays flexible but means "two agents in the same org can have wildly different effective context policies" (`libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py:397,311-317`). Agent-framework and openai-agents-sdk split the difference: strong defaults for structure, hooks for policy.
- **In-prompt transparency vs out-of-band metadata.** CrewAI renders scores and match reasons into the text the model sees (`lib/crewai/src/crewai/memory/types.py:92-106`) — maximally legible, token-costly, potentially biasing. Agent-framework keeps equivalent information in `additional_properties` (`_sessions.py:661-694`) — clean prompts, invisible to the model. Neither source evaluates the bias question empirically.
- **Proactive vs reactive compaction.** Letta's post-step check costs estimation work every turn but avoids wasted round trips; crewai's error-triggered summarization saves accounting until overflow, then pays one failed round trip per incident and depends on substring-matching provider error strings (`agent_utils.py:781-792`). Pydantic-ai outsources the dilemma to providers, gaining accuracy and losing portability (`models/anthropic.py:2681`).
- **Repair-not-fail vs fail-fast normalization.** Pydantic-ai synthesizes missing tool results so providers accept the history (`_agent_graph.py:2977-2979`); langgraph halts on invalid pairing (`chat_agent_executor.py:243-271`). The former maximizes availability at the risk of masking upstream bugs; the latter surfaces corruption immediately at the cost of failed turns.
- **Flat prompt vs structured carrier.** CrewAI's single augmented string keeps plumbing trivial but forfeits per-source budgets, deduplication, and labels — knowledge snippets arrive merely as "Additional Information" while memory gets scored annotation (`lib/crewai/src/crewai/knowledge/utils/knowledge_utils.py:4-12`). Agent-framework's `SessionContext` keyed by `source_id` enables filtered retrieval and selective persistence (`_sessions.py:557-618,757-790`) at the cost of a richer API surface users must learn.
- **Local vs server-managed history.** Openai-agents-sdk handles the duality honestly: server-managed conversations disable local filters with warnings, forcing an acknowledged either/or between provider-side memory and client-side control (`src/agents/run.py:652-668`; `src/agents/run_config.py:366-381`). Agent-framework detects and flags conflicts between local history providers and service-managed conversations (`dotnet/src/Microsoft.Agents.AI/ChatClient/ChatClientAgent.cs:827-852`).
- **Heuristic vs exact token accounting.** Both crewai (`len//4`, `agent_utils.py:835-844`) and letta (bytes/4 with blanket 1.3 safety margin, `letta/services/summarizer/summarizer_sliding_window.py:21-24`) choose fast approximations that can mis-trigger in both directions; pydantic-ai's pre-request counting exists but aborts rather than trims when over budget (`usage.py:444-459`; `_agent_graph.py:1603-1621`).

## Decision Guide

Choose by product shape, then by trust posture:

- **Building a library/framework** where applications own policy → seam-based pipeline with typed extension points and shipped example policies (follow openai-agents-sdk's `call_model_input_filter` + dataclass-policy-object pattern, `tool_output_trimmer.py:136-202`, or pydantic-ai's capability model, `capabilities/process_history.py:25-42`). Make the null policy explicit in docs; warn loudly when nothing is configured (openai-agents-sdk lists this as its own future work).
- **Building a hosted product** with long-running agents → materialized window plus compaction engine with dual triggers, eviction invariants, and post-verification (letta's design, `compact.py:180-412`). Add a per-section observability API early — it doubles as a debugging surface and a customer-trust artifact.
- **Needing multi-source enrichment with audit requirements** → provider pipeline with merge-time provenance stamping and reason-bearing exclusions (agent-framework). Stamp at the single merge point, not ad hoc per contributor.
- **Graph/workflow programming** where the definition should suffice as audit → channel-projection model (langgraph), accepting that you will write your own trimmer and that `Prompt` callables bypass schema guarantees (`chat_agent_executor.py:160-164`).
- **Template-driven team workflows** with modest context complexity → imperative composition (crewai) is viable, but adopt three upgrades from peers before scaling: bound inter-task concatenation, replace exit-on-overflow with a compaction path, and extend memory-style scoring to knowledge snippets.
- **Client/server product** where the browser is untrusted → boundary-builder pattern (openhands): one pure function owning the start payload, secrets-by-reference, backend-owned history knobs rendered schema-driven, and outcome verification rather than trusting acks.
- **Any of the above**: if context items come from retrieval, decide deliberately between auto-injection and on-demand exposure — agent-framework ships both modes of its `TextSearchProvider` behind one enum (`TextSearchProviderOptions.cs:149-154`), which is the cleanest treatment of the fork seen in this study.

## Practical Tips

- **Separate canonical record from model view from day one.** Every mature source converged here independently; retrofitting it (as crewai must) is far harder than starting with `llm_input_messages`-style views or exclusion flags.
- **Stamp provenance at the merge point.** A single `{source_id, source_type, origin}` write per injected message (agent-framework) enables downstream filtering, governance, and audit forever after; openai-agents-sdk shows digests work even when items get rewritten mid-flight (`items.py:393-412`).
- **Make exclusion a recorded decision, not deletion.** Reasons like `"truncation"`/`"sliding_window"`/`"token_budget_fallback"` cost almost nothing and turn "why is the model confused?" from mystery into lookup (`_compaction.py:718-727`).
- **Adopt progressive disclosure once any catalog grows past ~a screenful**, and recompute derived discovery state from the visible window only, as pydantic-ai does, so pruned evidence can't leave phantom tools (`_tool_search.py:196-230`).
- **Pair proactive thresholds with reactive handlers and verify the result.** Estimate tokens cheaply, add a safety margin, still catch the overflow error, then re-count after compaction before proceeding (letta's ladder is the reference implementation).
- **Protect interaction atomicity explicitly**: pending approvals un-evictable, approval+assistant pairs inseparable (letta), reasoning/call/result groups atomic (agent-framework), files preserved through summarization (crewai, `agent_utils.py:1069-1131`).
- **Give the model visibility into its own context budget** — letta's `<file_limits>` chars-current-vs-limit pattern (`memory.py:589-633`) and `<memory_metadata>` counts let the model ration its own slots instead of discovering limits by failure.
- **Route secrets around context, not through it**: reference indirection resolved at execution time (openhands, letta sandbox env vars), plus display-layer backstops for defense in depth.
- **Warn on every silent removal with the rule name and escape hatch** — pydantic-ai's sanitization warnings (`messages.py:3077-3133`) are the best observability-for-restrictions pattern in the study.
- **Write adversarial tests for your trust boundaries**: langgraph's "LLM-supplied auth ignored, graph-state wins" test (`test_tool_node.py:2202-2232`) and pydantic-ai's processor-contract edge cases (`test_history_processor.py:973-992`) are models to imitate.

## Anti-Patterns / Caution Signs

- **String-prefix or substring classification of context items.** OpenHands hides synthetic messages by prefix matching, self-described as "Brittle by design" with the durable fix identified but deferred (`should-render-event.ts:20-22`); crewai detects overflow by substring-matching provider error strings (`agent_utils.py:781-792`); letta skips system-prompt rebuilds based on substring containment, acknowledging it can miss deletions (`letta/services/agent_manager.py:1562-1563`). Three independent sources hitting the same wall marks it as an ecosystem-wide trap.
- **Selection logic duplicated across executors/loops.** Crewai's three executors already inject memory differently (`lite_agent.py:599-620` vs `agent/core.py:656-657`, undocumented and untested); letta's v1/v2/v3 generations apply different trigger policies with dead paths annotated "Seems like this is doing nothing?" (`letta_agent.py:1602-1605`). If you find a second implementation of your selector, consolidate before behaviors diverge further.
- **Unbounded concatenation feeding the window.** Crewai joins *all* prior task outputs with no cap (`formatter.py:26`); langgraph's tool outputs enter verbatim with no size handling (`tool_node.py:1441-1443` flagged in its own future work). Caution sign: any join() whose input length nobody bounds.
- **Fail-open enrichment.** Agent-framework's retrieval logs and returns empty context on search failure — resilient, but silently changes what the model sees (`TextSearchProvider.cs:199-203`); crewai swallows knowledge-retrieval exceptions into events, leaving the prompt unaugmented (`agent/utils.py:188-197`). Silent degradation deserves at minimum a surfaced signal.
- **Dangerous defaults on overflow.** `respect_context_window=False` turning an operational hiccup into `SystemExit` (crewai) and unbounded growth with no warning when neither limit nor filter is configured (openai-agents-sdk's own gap note) both show defaults mattering more than capabilities.
- **Naive instruction merging without precedence.** Multiple providers' instructions concatenated with `\n`, no conflict resolution (agent-framework, `dotnet/.../AIContextProvider.cs:166-172`). Caution sign: instructions from N sources becoming one blob.
- **Compaction starvation edges.** Sessions dominated by huge user messages never cross item-count compaction thresholds because user messages are excluded candidates (openai-agents-sdk, `select_compaction_candidate_items`); unsatisfiable budgets where one group exceeds the whole budget keep the result oversized (agent-framework, `_compaction.py:797-815`). Test your selector against adversarial size distributions.
- **Format-coupled heuristics.** Fernet `gAAAAA` prefix sniffing deciding encryption handling (openhands, `agent-server-adapter.ts:540,572-583`) and hardcoded model-family special-casing in thresholds (letta, `thresholds.py:14-24`) both break silently when formats or names change.

## Notable Absences

- **No model-path sensitive-field redaction anywhere.** Verified independently per source: crewai found no PII/masking logic in the context path at all (`security/security_config.py:20-87` covers fingerprints only); letta has no scanner on ingestion paths and concedes tool output could echo secrets into context unredacted; langgraph's threat model states "No field-level encryption or redaction" with unbounded retention (`.github/THREAT_MODEL.md:179,396`); pydantic-ai applies `redact_binary_content` exclusively to OTel serialization (`_instrumentation.py:141-167`); openai-agents-sdk confines redaction to traces/logs/guardrail placeholders (`util/_error_tracing.py:46-53`); openhands' redaction is presentation-only while the SDK injects secret blocks into prompts by design; agent-framework's core accepts provider data "as-is" with Purview/FIDES handling fragmented across optional packages (`security.py:91`).
- **No declarative, configuration-driven context policy.** Policy is code-defined in every source. Agent-framework searched `docs/design`/`docs/specs` and both cores and found none; crewai lists a declarative `ContextPolicy` as future work; openhands distributes policy across builders, settings defaults, and served schemas.
- **No relevance-scored general document selection outside memory/RAG niches.** Openai-agents-sdk explicitly found no embeddings/rerank/relevance scoring (`run_internal/` searched); pydantic-ai exports an embeddings primitive that is not wired into selection anywhere in the agent graph; langgraph has no automatic retrieval pipeline — RAG exists only in user-space example notebooks.
- **No per-item inclusion/eviction audit logs.** Letta searched `services/summarizer/*` and step managers; langgraph confirms nothing tags why a message entered context beyond its producing channel/node. Section-level breakdowns (letta) and event-level skill attribution (openhands) are the closest artifacts.
- **No first-class user-profile or workspace-state signals** in most cores: agent-framework says implement a custom provider; pydantic-ai routes such signals only through dependency injection consumed by dynamic instructions; openai-agents-sdk has no core-loop mechanism.
- **Crewai lacks any display/context separation** — it is the only source with no notion of a model view differing from stored truth, and correspondingly the only one whose summarization destroys verbatim history irrecoverably (modulo re-asking the summarizer LLM).

## Per-Source Notes

- **agent-framework (8)** — The most complete provenance story: attribution stamps, origin-session tracking, exclusion reasons, and compaction telemetry (.NET) make inclusion traceable component-wise. Weakened by experimental core APIs (`MAAI001` suppressions), instruction-concatenation without precedence, and security features scattered across opt-in packages with streaming gaps (`purview/_middleware.py:240-241`). Go SDK out of scope.
- **crewai (7)** — Best-in-study explainability for memory (scores + match reasons in-prompt) and a genuinely sophisticated adaptive recall flow, undermined by implicit inclusion order duplicated across three executors, unbounded inter-task context, crude token estimation, lossy one-shot summarization, and zero sensitive-data handling. The `respect_context_window=False` → `SystemExit` default is the study's most dangerous default.
- **langgraph (7)** — Cleanest declarative story: selection visible from graph definitions alone; injection trust boundary hardened with adversarial tests; sentinel-driven bulk delete is elegant. Deliberately ships no budget management, no summarization, no model-path redaction — and documents those gaps in its own threat model. Factory deprecation signals policy ownership moving out of repo.
- **letta (8)** — Most operationally complete engine: dual triggers, four eviction modes with fallback ladders, post-verification, eviction invariants protecting approvals, anti-recursion search filters, per-section token observability API, background curation agents. Held back by v1/v2/v3 behavioral divergence, substring change detection, approximate counting, and no per-item eviction rationale.
- **openai-agents-sdk (8)** — Best single mutation point (`call_model_input_filter`) with the strongest structural-validity machinery (orphan pruning, dedupe-preferring-latest, digest occurrence identity, rewind verification) and honest handling of server-managed vs local duality. Budgets are item/character-count only; the provenance ledger exists but isn't user-visible; final payload observability is thin.
- **openhands (7)** — Studied as the frontend boundary: exemplary pure-builder auditability, secrets-by-reference transport, verified manual compaction, and the study's richest display/context decoupling (three independent UI filters, none touching model context). Backend selection internals out of scope; brittle prefix classification and the profile-launch enrichment gap (software-agent-sdk#3967) are known, tracked weaknesses.
- **pydantic-ai (9)** — Highest score for good reason: the pipeline is an ordered composition of named pure passes with argued ordering; the processor contract is pinned by edge-case tests including cache-prefix regression nets; derived state is recomputed wire-truthfully; sanitization warns per rule. Deducted for unbounded default growth, fully-delegated redaction, provider-coupled auto-compaction, and inclusion rationale being implicit in part types rather than an inspectable artifact.

## Open Questions

- **What does the OpenHands backend actually do?** How the agent-server selects the LLM View between condensations and what triggers its condenser could not be determined from the frontend source; the condenser's retention heuristics remain unstudied (per-source Gaps).
- **Which letta loop serves a given production request?** Routing appears distributed across run-manager call sites (`letta/services/run_manager.py:657-754`) with no definitive dispatch matrix located — effective policy depends on it.
- **Does any hosted/platform layer add filtering?** CrewAI's AMP platform and OpenHands cloud may apply context filtering invisible in these repos; only hook points were found.
- **Would in-prompt scoring bias the model?** CrewAI renders memory scores into prompts without evaluating whether the numbers anchor generation; agent-framework keeps equivalents out-of-band. Nobody has measured the difference.
- **Cross-language convergence in agent-framework**: Python `ContextProvider` vs .NET `AIContextProvider` naming/semantics divergence noted as future work; the Go SDK lives out-of-repo entirely.
- **Can compaction summaries be trusted semantically?** Echoing the adjacent 03.07 finding: every summarization path trusts an LLM-produced summary without checking preserved facts against discarded transcript; this dimension adds that even the *selection* around those summaries lacks per-item rationale logging everywhere.
- **Where should redaction live?** Pydantic-ai proposes a stage between `before_model_request` and cleaning; openai-agents-sdk proposes a hook distinct from `call_model_input_filter` to stop conflating selection with transformation; letta proposes `validate_function_response`/input-ingestion seams. No source has implemented any of them yet.
