## Executive Summary

Across six agent harnesses, message routing and termination converge on a small set of shapes despite very different implementation choices. Every framework answers "who speaks next?" with one of four strategies: a deterministic framework policy (round-robin in agent-framework's .NET group chat, `GroupChatManager.cs:44-52`; crewai's fixed task list, `crew.py:1582-1627`), an LLM choosing among tools that name other agents (`transfer_to_<agent>` in openai-agents-sdk, `handoffs/__init__.py:207-211`; `handoff_to_<target>` in agent-framework Python; delegation-by-role tools in crewai hierarchical mode), a structured LLM election over conversation state (agent-framework's Magentic progress ledger, `_magentic.py:1086-1154`), or a user-supplied router callable over graph state (langgraph conditional edges, `_branch.py:83-120`; agent-framework's `selection_func`, `_group_chat.py:239-254`; crewai `@router` methods).

Termination is universally layered rather than centralized: natural completion (quiescence, final output, task list exhaustion), numeric budgets as hard backstops, graceful degradation before the backstop fires, and human gates implemented as checkpointed pauses — never blocking waits. The single most consistent finding is negative: **no source ships a runtime cycle/deadlock detector for conversational loops**. LangGraph explicitly derives safety from its Bulk Synchronous Parallel model rather than detection code (`pregel/_loop.py:599-681`); pydantic-ai relies on budgets plus structural acyclicity (`usage.py:429`); openai-agents-sdk and crewai searched-for cycle logic does not exist (their reports document the absence). Liveness rests entirely on numeric ceilings — and those defaults vary by two orders of magnitude across sources (10 model turns vs. 10,007 supersteps), reflecting different units of work rather than different confidence.

The headline question — *can a multi-agent conversation terminate without human intervention?* — is **yes in every source**, but with documented exceptions where operators can disable the bound (`max_turns=None` in openai-agents-sdk; agent-framework's Python group chat with neither `max_rounds` nor a termination condition, documented as unbounded at `_group_chat.py:142-143`), and with one scope caveat: openhands only *surfaces* termination decided server-side in a sibling repo.

## Core Thesis

Routing and termination in agent harnesses are not one subsystem but two orthogonal axes that sources mix differently:

1. **Who decides routing** spans a spectrum from fully static (edges written at build time) to fully dynamic (the model picks the next agent by emitting a tool call). Where routing is dynamic, every mature source compensates with *arbitration and feedback machinery*: first-wins arbitration when a model emits multiple handoffs (openai-agents-sdk `turn_resolution.py:563-597`; agent-framework .NET last-wins warning, `HandoffAgentExecutor.cs:457-465`), tolerant target matching with self-correction errors (crewai role sanitization returning the valid roster, `base_agent_tools.py:72-108`), and synthetic tool outputs so the model learns why a route was ignored.
2. **Termination is guaranteed by composition, never by one mechanism**: a natural-exit condition + a budget enforced outside model control + a degradation ladder + pause-based human gates. The strongest implementations make the budget unconditional and config-enforced (langgraph recomputes `stop = step + recursion_limit + 1` from checkpoint metadata so resume cannot reset it, `pregel/_loop.py:1700-1701`; pydantic-ai applies a default-on `request_limit=50` even with zero configuration, `_run_context.py:70-78`).

The corollary all six sources demonstrate: **make control flow addressable data, and liveness becomes enforceable**. Turn tokens, reserved TASKS channels, typed NextStep unions, ExecutionStatus enums, and usage-limit objects are all instances of the same move — routing decisions and turn counts become serializable, checkpointable, auditable state instead of implicit call-stack behavior. Sources that keep routing implicit (convention-based handoffs, prompt-only contracts) pay for it with undetectable misroutes and convention drift.

## Approach Models

Three approach families emerged from clustering, cut two ways: by *routing authority* and by *execution substrate*.

### Family A — Dataflow-graph engines (routing = writes into typed channels)

**langgraph** is the purest expression: everything reduces to channel writes resolved at superstep boundaries; static edges are just unconditional writers, conditional edges are router callables (`BranchSpec`), and dynamic dispatch travels over a reserved non-accumulating `Topic(Send)` channel cleared each step (`pregel/main.py:804-809`). **agent-framework** shares this substrate (a Pregel-like superstep runner raising `WorkflowConvergenceException` past 100 iterations, `_runner.py:106-177`) but layers opinionated orchestration patterns on top, compiling group chat/handoff/Magentic down to plain graphs. **crewai Flows** is a lighter cousin: `@listen`/`@router` triggers resolved to quiescence by the runtime (`flow/runtime/__init__.py:3048-3179`), without channel semantics or per-superstep checkpoints.

What you get: build-time structural validation, deterministic merge of concurrent routes, checkpoint/resume of routing state. What you pay: one-step latency between agents and a mental model shift from "conversation" to "graph."

### Family B — Tool-call-as-routing-signal (routing = the model names the next agent)

**openai-agents-sdk** is canonical: handoffs are ordinary function tools named `transfer_to_<agent>`, classified by a central `process_model_response` router and resolved each turn into exactly one of four `NextStep` variants (`run_steps.py:155-181`). **agent-framework**'s handoff pattern uses the same trick (`handoff_to_<target>` intercepted by middleware before real execution, `_handoff.py:132-154`). **crewai hierarchical** achieves the same effect through delegation tools whose arguments name coworkers by role (`agent_tools.py:22-36`). **pydantic-ai** offers delegation-as-tool plus a variant nobody else has: output functions as *forced* handoffs, where the model must call an output tool that ends the run and the function body starts the next agent (`docs/output.md:118-129`).

What you get: maximal flexibility, provider-native tool-calling paths, no bespoke inter-agent protocol. What you pay: nondeterminism, which every source counters with arbitration rules, tolerant matching, and a turn/request cap outside model control.

### Family C — No speaker selection (one agent, explicit sequencing)

**openhands** (frontend slice) has strictly one user ↔ one agent per conversation plus one planning sub-conversation; turn-taking is the server-streamed `ExecutionStatus` enum (`common.ts:67-75`). **pydantic-ai** similarly has one "speaker" per run node; multi-agent coordination happens across runs, sequenced by application code sharing `message_history`. Both prove a useful point: much of the group-chat machinery in other sources exists to solve problems that simply don't arise when conversations are pairwise and sequential — classic deadlock is structurally impossible in both.

These families are orthogonal to a second axis: whether handoff contracts are framework-typed (openai-agents-sdk's `Handoff` dataclass with input filters and nesting, `handoffs/__init__.py:126-201`), topology-enforced but payload-unchecked (langgraph `Command(goto=..., update=...)`), or pure convention (pydantic-ai's "pass `usage=ctx.usage`" rule, checked by nobody).

## Pattern Catalog

### 1. Handoff-as-tool-call interception
- **Problem**: transfer control between agents without building a bespoke inter-agent messaging protocol.
- **Demonstrated by**: openai-agents-sdk (`turn_resolution.py:206-213`, bare-name matching so namespaced calls can't hijack routes), agent-framework Python (`_AutoHandoffMiddleware` short-circuits execution with a synthetic result, `_handoff.py:132-154`), crewai (`DelegateWorkTool`), pydantic-ai (delegation tools, output functions).
- **Why it works**: reuses the provider's native function-calling path; interception before execution means zero side effects and deterministic results; tool descriptions become executable routing documentation (openhands calls this out explicitly as "spec-as-prompt", `launch-child-conversation-client-tool.ts:14-59`).
- **Copy when**: agents are LLM-driven and your provider supports reliable tool calling.
- **Overkill/risky when**: routing must be provable or auditable ahead of time — then use static edges (Family A). Also risky without parallel-call suppression: agent-framework Python forces `allow_multiple_tool_calls=False` (`_handoff.py:287-289`) precisely because two handoffs in one response is ambiguous; openai-agents-sdk arbitrates first-wins with synthetic ignore outputs instead.
- **Evidence**: strong in four independent sources; tested extensively in all four.

### 2. Budget-as-liveness-backstop, enforced outside model control
- **Problem**: guarantee termination regardless of what the model does.
- **Demonstrated by**: every source, with different units — openai-agents-sdk `DEFAULT_MAX_TURNS=10` (`run_config.py:45`), pydantic-ai default-on `request_limit=50` (`usage.py:429`), langgraph `recursion_limit` (default env-overridable 10007) converted to `GraphRecursionError` (`pregel/main.py:3002-3011`), crewai `max_iter=25` per agent plus `max_method_calls=100` flow breaker (`flow/runtime/__init__.py:3248-3256`), agent-framework caps at four layers (40 manager iterations, 50 autonomous turns, 100 supersteps, configurable Magentic round/reset/stall limits), openhands goal loops at user-settable `max_iterations` default 500.
- **Why it works**: the check lives in the loop scaffold, not in model behavior; openhands even requests stuck detection unconditionally on every conversation start (`agent-server-adapter.ts:1012`).
- **Copy when**: always. This is the closest thing to a universal law in the study.
- **Risky when**: the budget is optional. openai-agents-sdk's `max_turns=None` and agent-framework's unbounded group-chat config show the failure mode: termination then depends wholly on model cooperation.
- **Refinement worth copying**: langgraph recomputes the bound from checkpoint metadata on resume so a restored run can't get a fresh budget (`_loop.py:1700-1701`), and pydantic-ai deliberately gives same-id background polls their own ceiling because they add no tokens and would evade usage limits (`models/_continuation.py:70-97`).

### 3. Graceful-degradation ladder in front of the hard limit
- **Problem**: hitting a hard cap wastes all work done so far.
- **Demonstrated by**: langgraph prebuilt agent injects "Sorry, need more steps" when `remaining_steps < 2` and falls through to END (`chat_agent_executor.py:620-634`); crewai appends a forced-final-answer instruction and makes one last LLM call on `max_iter` (`agent_utils.py:376-433`, end-to-end tested); openai-agents-sdk converts `MaxTurnsExceeded` into a schema-validated synthesized output via error handlers (`run_loop.py:742-786`); crewai A2A injects escalating "FINAL turn" warnings before cutting off (`a2a/wrapper.py:713-728`); agent-framework Magentic yields a synthesized "terminated due to reaching maximum … count" partial answer (`MagenticOrchestrator.cs:250-261`).
- **Why it works**: separates "the loop must stop" from "the user gets nothing."
- **Copy when**: users consume the final output directly.
- **Caution**: degraded outputs must be distinguishable from genuine completion — agent-framework notes callers must inspect events/state to tell them apart.

### 4. Pause-don't-block for humans and external services
- **Problem**: waiting on a human looks like deadlock if implemented as a blocking wait.
- **Demonstrated by**: pydantic-ai deferred tools end the run with a `DeferredToolRequests` output that external code resolves and resumes by fail-closed `tool_call_id` binding (`_tool_execution.py:964-1050`); crewai `HumanFeedbackPending` exception with `resume_async(feedback)` (`flow/runtime/__init__.py:2948-2973`); openai-agents-sdk `NextStepInterruption` carrying approval items resumable via `RunState`; agent-framework `request_info` HIL gates with empty-response-means-stop semantics (`_handoff.py:461-465`); langgraph `GraphInterrupt` with checkpointed pause/resume; openhands confirmation gate blocking on `WAITING_FOR_CONFIRMATION`.
- **Why it works**: converts potential deadlock into persisted, resumable state.
- **Copy when**: any human approval or slow external dependency exists. Universal across all six — treat blocking waits as a design error.

### 5. Replay/idempotency protection around routing side effects
- **Problem**: reconnects, resumes, and resend races can double-execute handoffs and billable actions.
- **Demonstrated by**: openhands claims `tool_call_id` in a localStorage ledger before any network work (`child-conversation-launch.ts:196-227`); openai-agents-sdk reconciles already-executed handoff call IDs on resume so transfers don't re-fire (`turn_resolution.py:1964-1969`); langgraph dedupes interrupted PUSH tasks on checkpoint resume (test `test_large_cases.py:4645`); agent-framework bookmarks shared conversation state so re-entrant invocations replay only new messages (`HandoffAgentExecutor.cs:262-308`).
- **Why it works**: routing effects are exactly the kind of non-idempotent operations that replays corrupt; claiming or reconciling by call ID makes redelivery harmless.
- **Copy when**: any persistence/resume/reconnect boundary touches routing.

### 6. Checkpointed routing state
- **Problem**: long or interruptible multi-agent runs must survive restarts mid-conversation.
- **Demonstrated by**: agent-framework serializes round-robin cursors, current-speaker ids, autonomous-turn counters, and Magentic ledgers into checkpoints (`RoundRobinGroupChatManager.cs:74-86`, `MagenticOrchestrator.cs:357-404`); langgraph saves checkpoints on drain and interrupt (`errors.py:54-64`); openhands anchors WS replay to the REST-loaded tail via `resend_mode='since'&after_timestamp` (`conversation-websocket-context.tsx:368-400`).
- **Why it works**: "whose turn is it" becomes durable protocol state (agent-framework's `TurnToken` makes this explicit, `TurnToken.cs:12-19`).
- **Copy when**: runs exceed a single process lifetime or need auditability.

### 7. Tolerant target resolution with self-correction feedback
- **Problem**: LLMs misname routing targets.
- **Demonstrated by**: crewai sanitizes/casefolds requested coworker roles and returns the full valid roster on mismatch so the model retries correctly (`base_agent_tool_tools.py` evidence at `base_agent_tools.py:20-35, 99-108`); openai-agents-sdk gives ignored extra handoffs synthetic outputs explaining why, plus a span error listing all requested agents (`turn_resolution.py:563-597`); agent-framework feeds ledger parse failures back to the model in bounded retries with linear backoff (`MagenticManager.cs:66-105`).
- **Why it works**: the error message doubles as a corrective prompt; the loop self-heals without human intervention.
- **Copy when**: models choose targets from a roster.
- **Counter-example to avoid**: failing silently — langgraph drops unknown-target Sends with only a log warning (`_algo.py:961-999`), which its own report flags as a diagnosability gap.

### 8. Reserved control plane separated from data plane
- **Problem**: routing signals shouldn't be confusable with conversation content.
- **Demonstrated by**: langgraph reserves the `TASKS` channel and rejects direct user writes to it (`_write.py:114-116`); agent-framework's dual-envelope participant abstraction distinguishes agent requests from custom-executor envelopes (`_base_group_chat_orchestrator.py:453-495`) and filters internal handoff tool traffic from what the next agent sees (`HandoffAgentExecutor.cs:241-251`); openai-agents-sdk separates model-visible input from session history in `HandoffInputData.input_items` (`handoffs/__init__.py:94-99`).
- **Why it works**: prevents routing metadata from derailing models and prevents users from forging control signals.
- **Copy when**: your protocol mixes control and content.

## Key Differences

The most consequential divergences, with reasons grounded in product shape:

- **Centralized election vs. decentralized tool choice vs. no selection.** Agent-framework ships all three (group chat manager / handoff tools / Magentic ledger) because it positions itself as a patterns library. CrewAI chose task-driven coordination ("tasks, not free-form chat") making termination trivially decidable — a deliberate fit for its workflow-automation audience (`process.py:4-11`). OpenAI Agents SDK went all-in on model-chosen routing because its unit of product is a single agent chain handed off along the way; there is no "group." Pydantic-ai and OpenHands have no selection problem to solve given one-speaker architectures. These are constraint responses, not quality differences.
- **Topology enforcement.** LangGraph validates graph structure at compile time (`state.py:1129-1175`) and still can't validate conditional-edge payloads; openai-agents-sdk enforces no topology at all, relying on declared handoff sets plus dynamic `is_enabled` predicates (`turn_preparation.py:105-115`). The difference tracks library philosophy: graph-first frameworks sell verifiability, SDK-first frameworks sell composability.
- **Sync vs. async handoff mechanics.** CrewAI executes delegated work synchronously inside the delegator's tool call (`base_agent_tools.py:112-124`) — A→B→A deepens the stack rather than deadlocking, and there is no queue. Everything else routes via asynchronous message hops. CrewAI's choice simplifies reasoning and makes mutual-blocking deadlock structurally impossible, at the cost of serialized work.
- **Failure posture on invalid routes.** Fail-fast camp: langgraph branch routers reject `None`/START targets immediately (`_branch.py:207-210`); pydantic-ai fails closed on duplicate/mismatched deferred-result IDs (`_tool_execution.py:405-420`); crewai raises on a manager agent carrying tools (`crew.py:1522-1529`). Warn-and-degrade camp: langgraph silently drops unknown Sends; agent-framework resolves duplicate handoffs last-wins with a warning while its Python stack structurally prevents them (divergent defenses for the same hazard); openai-agents-sdk ignores extra handoffs after the first. Neither posture dominates — fail-fast suits development, degrade suits long-running operations — but inconsistency *within one framework* (agent-framework's two stacks) is a genuine defect.
- **Budget granularity and defaults.** Ten turns (openai-agents-sdk) assumes expensive model calls and short chains; 10,007 recursion steps (langgraph) assumes cheap graph nodes; 500 goal iterations (openhands) assumes browser-scale automation. The lesson: budget units should match the cost of the thing being bounded, and defaults encode assumptions operators must understand before changing.
- **Where termination is decided.** Five sources decide inside the framework runtime; openhands decides nowhere locally — it renders server verdicts (`FINISHED`/`ERROR`/`STUCK`, streamed `GoalStatus`) and provides override controls. Its report is explicit that claims about loop enforcement internals would be unsupported within its boundary — correct evidence discipline for a frontend slice.

## Tradeoffs

- **Determinism vs. adaptivity.** CrewAI's fixed task list proves termination but removes replanning (`process.py:4-11`); hierarchical mode regains adaptivity only through probabilistic LLM tool choices. LangGraph's static edges are analyzable; `Command(goto=...)` escapes analysis. Best-fit: deterministic for compliance-critical flows, adaptive where tasks are open-ended. Failure mode of the adaptive side: ping-pong livelock bounded only by budget (openai-agents-sdk documents A↔B loops consuming turns until `MaxTurnsExceeded`).
- **LLM-selected speakers vs. algorithmic policy.** Flexible routing hallucinates names and emits malformed ledgers routinely, forcing fallback/retry machinery (agent-framework's defensive parsing ladder, `_group_chat.py:419-542`); a round-robin manager avoids the entire class (and its .NET host even treats re-selection of the current speaker as termination rather than livelock, `GroupChatHost.cs:78-85`). Cost of the deterministic side: cannot route based on content.
- **Star vs. mesh topology.** Agent-framework's default handoff mesh costs O(n²) edges and broadcast volume (`_handoff.py:1003-1010`); the group-chat star broadcasts once through the host but centralizes a potential bottleneck. Star scales better for large participant sets; mesh removes the coordinator as both bottleneck and single point of policy.
- **Convention-based vs. typed handoff contracts.** LangGraph `Command` and pydantic-ai delegation compose freely but transfer payloads unchecked — correctness rests on application tests (both reports flag this as their main gap). OpenAI Agents SDK's `Handoff` dataclass with input filters, strict-JSON validation, and nesting buys predictability and tracing at the cost of flexibility (fixed destinations, `handoffs/__init__.py:343`).
- **Fail-fast vs. resilience on misroutes.** Silent Send drops keep long map-reduce jobs alive but mask bugs as early termination (langgraph's own tradeoff note); immediate branch-validation errors catch typos but would kill streaming jobs on transient issues. Choose per environment, not per framework.
- **Human gates vs. liveness.** Default HIL modes block indefinitely pending input (agent-framework's default handoff pauses after every response; Magentic plan sign-off has no revision-round cap found, `_magentic.py:1035-1038`). Autonomous modes restore liveness but need their own budgets. There is no free lunch; pick which resource you're spending.
- **Duplicated loop implementations vs. abstraction cost.** OpenAI Agents SDK duplicates sync/streaming termination (~600 lines apart, parity maintained by contributor discipline and tests); OpenHands duplicates main/planning WS handlers (~200 lines, admitted in comments at `conversation-websocket-context.tsx:649-651`); agent-framework reimplements semantics across C# and Python and has already drifted (parallel-handoff prevention exists only in Python). Duplication is often chosen consciously for idiomatic surfaces, but every instance in this study shows measurable drift risk.

## Decision Guide

Choosing a routing/termination model for a new harness or application:

1. **Pick routing authority by how predictable the task graph is.** Known sequence → static assignment (crewai sequential, langgraph static edges). Content-dependent branching → user-supplied router functions over state (langgraph conditional edges). Genuinely open-ended collaboration → LLM-chosen routing with mandatory arbitration (openai-agents-sdk style). If you need both adaptivity and auditability, use structured-output election with a ledger (agent-framework Magentic) so progress and stalls are inspectable state.
2. **Make the liveness budget unconditional.** Prefer frameworks/environments where the cap cannot be disabled and survives resume (langgraph's checkpoint-derived stop; pydantic-ai's default-on limit). If you must offer an escape hatch like `max_turns=None`, gate it behind explicit operator intent and alert on its use.
3. **Match budget units to cost.** Bound model round-trips for expensive calls, graph steps for cheap nodes, wall-clock for latency SLAs (crewai's optional `max_execution_time`), and money directly where possible (pydantic-ai `cost_limit` — noting its warning-only degradation when pricing data is missing).
4. **If models choose targets, invest in the feedback loop, not just validation.** Sanitize inputs, return valid alternatives in errors, emit synthetic outcomes for ignored requests, and retry format failures against the model (patterns 7 and 1).
5. **Implement human involvement as pausable state, never blocking waits** (pattern 4), and give every pause a resume contract keyed by immutable IDs with fail-closed binding.
6. **Treat handoffs as side-effectful transactions**: claim-or-reconcile by call ID before executing (pattern 5), and filter internal routing traffic from downstream context (pattern 8).
7. **Prefer one routing substrate with patterns compiled onto it** (agent-framework's architecture) over parallel bespoke mechanisms per pattern — it inherits engine-level ordering, checkpointing, and validation for free.

## Practical Tips

- **Add the degradation ladder before the exception.** Order observed across sources: managed remaining-step introspection → canned/instructed final message → hard error (langgraph's `RemainingSteps` → "need more steps" → `GraphRecursionError`). Each rung preserves partial value.
- **Arbitrate ambiguous multi-routing deterministically and explain the outcome to the model.** First-wins with synthetic ignore outputs (openai-agents-sdk) beats silent last-wins warnings (agent-framework .NET) because the model can correct next turn.
- **Guard degenerate selections explicitly.** Re-selecting the current speaker should terminate (or warn loudly), not spin — agent-framework .NET handles this; its Python stack leaves it to user code and round caps.
- **Separate retry budgets per loop type.** Pydantic-ai maintains distinct budgets for output retries, per-tool retries, and model-request retries (`tool_manager.py:256-265`, `_agent_graph.py:361-378`); a shared counter lets one pathological loop starve the others.
- **Bound things that "add no tokens."** Background polls, wait loops, and revision rounds evade usage-based limits; pydantic-ai's separate `MAX_BACKGROUND_POLLS=1000` and agent-framework's uncapped plan-revision loop (gap) bracket the right and wrong handling.
- **Make timeouts cooperative.** CrewAI's thread-pool timeout returns control but leaks the running thread (`agent/core.py:904-918`); cancellation tokens with attribution (pydantic-ai `_cancel.py:42-257`) stop the actual work.
- **Version your routing contracts.** OpenHands degrades honestly when the server predates parent-link support (< 1.37.1) rather than assuming a phantom relationship (`constants/child-conversation.ts:30-37`).
- **Test termination as a first-class behavior.** All high-rated sources have dedicated suites: max-turns parity across sync/streaming (~40 tests, openai-agents-sdk), stall/reset-limit assertions (agent-framework), circuit-breaker `RecursionError` tests (crewai), recursion-limit raises and send-dedupe-on-resume (langgraph).

## Anti-Patterns / Caution Signs

- **Documented-unbounded configurations shipped as legal API states**: agent-framework Python group chat without `max_rounds` or a termination condition (`_group_chat.py:142-143`); openai-agents-sdk `max_turns=None`. Caution sign: any boolean or None that switches off the only liveness guarantee.
- **Observation-only safety instrumentation**: crewai counts delegations per task but enforces no ceiling (`task.py:1142-1146`) — telemetry without enforcement invites runaway hierarchies until `max_iter`.
- **Window-of-one detectors**: comparing only against the immediately previous call means alternating A/B/A/B oscillation evades detection until budget exhaustion (crewai `tool_usage.py:784-788`). Sliding-window or fingerprint-set comparison closes it cheaply.
- **Silent misroute absorption**: unknown Send targets logged-and-dropped (langgraph); no-handoff-target agents warned-not-failed at build (agent-framework `_handoff.py:1095-1099`). These convert routing bugs into mysterious early exits — the hardest class to diagnose.
- **Lossy status mapping**: OpenHands collapses `STUCK` into `ERROR` client-side with an acknowledged TODO (`use-agent-state.ts:30-31`) — downstream consumers lose the distinction between "failed" and "needs intervention."
- **Duplicated critical paths drifting**: sync/streaming loops (openai-agents-sdk), main/planning handlers (openhands), dual-language stacks (agent-framework). Caution sign: alignment enforced by comments and contributor discipline rather than shared primitives.
- **Liveness inferred from silence**: no application-level heartbeat means a dead-but-OPEN socket "looks healthy" (openhands, `conversation-websocket-context.tsx:210-214`); reconnect attempts defaulting to `Infinity` bound rate but not total.
- **Timeouts that don't reclaim resources** (crewai thread leak) — the system appears bounded while consumption continues.

## Notable Absences

Consistent gaps across the corpus — useful as a maturity checklist:

- **No runtime cycle/liveness detector anywhere.** Six sources searched; none ship conversational-loop cycle detection. All rely on budgets. Multiple reports independently propose the same fix (per-pair hop counters naming the repeating agents, SCC analysis warning when a component lacks an END-reaching path).

## Per-Source Notes

- **agent-framework (8)** — Richest pattern library: superstep engine + group chat (star, TurnToken), handoff (mesh, middleware-intercepted tools in Python / predicate switches over `HandoffState` in .NET), Magentic (ledger-driven election with stall/reset counters). Defense-in-depth termination; checkpointed cursors; ~dozens of targeted tests. Weakened by dual-stack drift, recursion-based Python autonomous loops, and the documented unbounded config.
- **crewai (7)** — Tasks-not-chat philosophy makes termination provable by construction (fixed task count, no agent-added tasks). Forced-final-answer escape hatch and flow `RecursionError` breaker are excellent. Hierarchical delegation cycles unenforced; consecutive-repeat-only detection; timeout thread leak.
- **langgraph (9)** — Highest score in the study: BSP model makes blocking deadlock structurally impossible and termination provable (`done` quiescence or enforced recursion bound), compile-time validation, resume-safe Send dedupe, drain control, managed `RemainingSteps` for soft stops. Handoffs remain convention; silent Send-drop is the flagged soft spot.
- **openai-agents-sdk (8)** — Cleanest articulation of tool-call routing as a typed state machine (four NextStep variants); richest max-turns test coverage including handler-synthesized outputs and session persistence. No cycle detection; `max_turns=None` footgun; sync/streaming duplication burden.
- **openhands (7)** — Studied as a frontend slice; honest about its boundary. Strongest replay-safety engineering (claim-before-act ledgers, event dedup, anchored WS replay, flush-before-transition ordering). Cannot itself guarantee loop termination; heartbeat-less transport and uncapped reconnects are its residual risks.
- **pydantic-ai (8)** — Smallest routing surface, most rigorous enforcement: classification-before-execution router (five ToolKinds), always-on default request limit checked at three lifecycle points, pause-don't-block deferral with fail-closed ID binding, retry-wins output revocation, precise cancellation attribution. Delegation hygiene and recursion cycles rest on convention/budgets only.

## Open Questions

- Would a shared **cycle-detection primitive** (per-edge hop counters or SCC-with-no-END-path warnings) be worth standardizing? Four of six reports independently arrive at versions of this suggestion; none implement it.
- Do **agent-framework's two stacks** intend semantic convergence? Parallel-handoff prevention (Python-only), same-speaker guard (.NET-only), and unknown-speaker policy differences suggest drift is unintentional but unmanaged.
- What governs **Magentic plan-review revision loops** (no revision-round cap found, `_magentic.py:1035-1038`) and do callers reliably distinguish limit-exhaustion partial answers from genuine completion?
- How do **event-driven/realtime sessions** (openai-agents-sdk realtime, openhands server internals) bound liveness without turn loops? Out of scope of the studied files; unresolved.
- Is **silent misroute absorption** ever the right default versus strict mode? Langgraph's report proposes config-gated strictness; no source ships both postures behind one flag yet.
- Does crewai's enterprise layer (outside the studied repo) provide the delegation-cycle enforcement the core library lacks? Unverifiable within this study's boundaries.
