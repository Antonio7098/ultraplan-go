## Executive Summary

Across all seven sources, human intervention is a designed protocol, not an escape hatch. Every framework that scores 8+ converges on the same skeleton: when a human decision point arrives (tool approval, plan review, gated action), the run **halts at a durable boundary**, persists enough state to survive process death, and exposes a **typed resume operation** through which the human's answer re-enters execution — `Command(resume=...)` in langgraph (`libs/langgraph/langgraph/langgraph/types.py:798-848`), `Workflow.run(responses={request_id: data})` in agent-framework (`python/packages/core/agent_framework/_workflows/_workflow.py:709-746`), serialized `RunState` + `state.approve(...)` in openai-agents-sdk (`src/agents/run_state.py:1255`), `ApprovalCreate` messages in letta (`letta/schemas/message.py:178-197`), `resume(feedback)` after SQLite-persisted pauses in crewai (`lib/crewai/src/crewai/flow/runtime/__init__.py:1285-1387`). Temporal generalizes this to event sourcing: signals, updates, pauses, and resets are all immutable history events (`service/history/api/signalworkflow/api.go:90-101`).

Three findings stand out. First, **no source allows true mid-step injection into a live LLM/tool call** except at the edges: openhands keeps its composer active while the agent runs (`src/components/features/chat/interactive-chat-box.tsx:62-65`), agent-framework offers queue-and-drain message injection (`python/packages/core/agent_framework/_sessions.py:1383-1433`), and temporal provides async signals plus validator-gated synchronous updates (`service/frontend/workflow_handler.go:2297`, `service/frontend/workflow_handler.go:5414`) — but even these land at step/superstep boundaries internally. Second, **correction is fork-based everywhere**: five distinct fork mechanisms emerged (checkpoint restore, storage-level branch, shared-message conversation fork, derived client conversation, checkpoint copy), and direct transcript editing is either absent or explicitly refused (letta returns HTTP 405 for message edits, `letta/server/rest_api/routers/v1/agents.py:1627-1644`; openhands has no edit/delete-event UI). Third, the field-wide weakness is **actor attribution**: only letta stamps editor identity onto memory history (`letta/orm/block_history.py:34-37`); langgraph checkpoints carry structural provenance but no author (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:38-62`), openai-agents-sdk approvals carry no principal, and temporal relies on caller-supplied identity strings.

Scores range 7–9: temporal (9) and langgraph (9) lead — one on audit-by-construction and reset semantics, the other on first-class state surgery and time travel — while openhands (7) trails mainly because it is a client whose fork lineage is a title-suffix convention rather than durable data.

## Core Thesis

**Durable-boundary intervention beats live interception, and provenance is the unfinished business.**

Every mature source reached the same conclusion independently: holding a thread open for a human is worse than persisting a resumable state and terminating the run segment. Halting makes human latency unbounded-safe, enables cross-process resume, and forces interventions through validation points. The price is paid twice: applications must adopt a loop-shaped interaction style (run → collect requests → answer → re-run, shown in agent-framework's `run_interactive_session`, `python/samples/03-workflows/checkpoint/checkpoint_with_human_in_the_loop.py:227-273`), and systems lose immediacy — you cannot nudge an LLM call in flight, so long-running tools need internal interrupt points or cooperative drain (langgraph `RunControl.request_drain()`, `libs/langgraph/langgraph/runtime.py:79-104`).

For correction, the industry consensus is *fork, don't edit*. Editing persisted transcripts breaks sharing (letta's stated rationale for immutability, tied to fork-shared messages, `letta/services/conversation_manager.py:142-158`), replay determinism (temporal forbids arbitrary mutation because state derives from replayable history, `service/history/api/resetworkflow/api.go:74-77`), and lineage coherence. Forking preserves append-only semantics but shifts cost to branch management — and most sources under-invest there (weak lineage metadata in openhands and agent-framework, no explicit fork API at all in openai-agents-sdk).

Finally: traceability is where designs diverge most sharply relative to their maturity elsewhere. Temporal gets a complete audit trail *by construction* because interventions are events; letta gets actor-attributed memory history because versioning was a schema requirement; everyone else records *that* something happened without recording *who* did it. A team copying these architectures should treat the intervention ledger as a first-class deliverable, not an emergent property.

## Approach Models

Clustering by how humans reach into a run, five models emerge:

**1. Checkpoint-mediated interrupt protocol (langgraph).** A node calls `interrupt(value)`; a typed interrupt is persisted as a task-scoped checkpointer write (`libs/langgraph/langgraph/langgraph/pregel/_runner.py:584-591`); humans resume via `Command(resume=...)`, matched positionally or by deterministic content-derived interrupt ID (`libs/langgraph/langgraph/langgraph/types.py:593-618`). Uniquely, this model also exposes *direct state surgery*: `update_state(values, as_node="X")` applies arbitrary values as if node X had produced them, with `Overwrite` bypassing reducers (`libs/langgraph/langgraph/langgraph/pregel/main.py:1905-1938`; `types.py:977-1024`). Fork/time-travel is `get_state_history` + update against a historical checkpoint, tagged `"source": "fork"`.

**2. One interrupt primitive, many surfaces (agent-framework).** Tool approval, Magentic plan sign-off, group-chat guidance, agent-in-workflow escalation, and DevUI forms all compile down to `ctx.request_info(...)` → halt in `IDLE_WITH_PENDING_REQUESTS` → answer via `responses=` map (`python/packages/core/agent_framework/_workflows/_workflow_context.py:403-434`; `_magentic.py:993-1055`). .NET mirrors it with typed `RequestPort<TRequest,TResponse>` (`dotnet/src/Microsoft.Agents.AI.Workflows/RequestPort.cs:13-33`). AG-UI adds a server-owned authority lifecycle (register → claim → execute → settle/reject/cancel/expire) with full-replacement `editedArgs` argument editing at approval time (`python/packages/ag-ui/agent_framework_ag_ui/_approval_lifecycle.py:93-114`).

**3. Serializable-state lifecycle (openai-agents-sdk).** The run stops and returns `interruptions`; the host owns a versioned `$schemaVersion`-tagged `RunState` snapshot, records approve/reject decisions (sticky tool-wide or per-call), optionally stages new user input via `add_input()`, and resumes by passing state back into `Runner.run(agent, state)` (`src/agents/run_state.py:941-979`; `src/agents/run.py:256-259`). Realtime voice sessions are the one genuinely concurrent path (`src/agents/realtime/session.py:969-1049`). Nested agent-as-tool interruptions are routed recursively to the owning state (`src/agents/run_state.py:1095-1253`).

**4. Message-protocol approval loop (letta).** Approval requests are first-class messages (`role=approval`) in the conversation; the run stops with `stop_reason=requires_approval` (`letta/agents/letta_agent_v3.py:1681-1709`); the human answers with per-tool-call approve/deny+reason entries or substitutes human-executed results (`ToolReturnCreate`, `letta/schemas/message.py:200-217`). Because messages are immutable and shared across forks, transcript correction = conversation fork; persistent-memory editing goes through privileged PATCH APIs that force system-prompt recompilation (`letta/server/rest_api/routers/v1/agents.py:1268-1288`).

**5. Event-sourced intervention surface (temporal).** Humans never rewrite state (determinism); they append events: fire-and-forget Signals, validator-gated synchronous Updates with a formal `Created→Admitted→Sent→Accepted→Completed` state machine (`service/history/workflow/update/state.go:12-25`), read-only Queries, Pause/Unpause of workflows *and individual activities*, Terminate/Cancel, and ResetWorkflowExecution — which forks history at a chosen task-completed boundary via storage-level branch tokens and cherry-picks which past human inputs to reapply (`service/history/ndc/workflow_resetter.go:956-1094`).

Two further variants round out the set: **provider-pluggable review loops (crewai)** — `HumanInputProvider` protocols behind task-level `human_input=True` and flow-level `@human_feedback`, with pausing implemented as a caught-and-persisted `HumanFeedbackPending` exception (`lib/crewai/src/crewai/flow/async_feedback/types.py:148-218`) — and **client control surface (openhands)**, where every intervention verb is a typed backend command and the frontend contributes delivery integrity (optimistic queue, server-echo matching, watchdog timers) rather than state authority (`src/stores/optimistic-user-message-store.ts:115-141`).

## Pattern Catalog

### P1. Halt-and-resume instead of blocking callbacks
- **Problem:** Humans take seconds-to-days; holding threads or awaits for them is fragile and blocks scale.
- **Demonstrated by:** langgraph (interrupt persisted, stream ends, resume later), agent-framework (`IDLE_WITH_PENDING_REQUESTS`), openai-agents-sdk ("durable pause/resume boundary", `src/agents/run_state.py:752`), letta (stop_reason + persisted approval message), crewai (persisted pending-feedback rows in SQLite, `lib/crewai/src/crewai/flow/persistence/sqlite.py:205-244`), temporal (buffered signals trigger workflow tasks).
- **Why it works:** Human latency becomes unbounded-safe; runs survive crashes, deploys, and process moves; the same machinery serves crash recovery.
- **Copy when:** Any human gate could exceed a request timeout — i.e., almost always.
- **Risky/overkill when:** Sub-second interactive flows (realtime voice already shows the alternative: open sessions with live approve/reject).
- **Evidence:** langgraph `libs/langgraph/langgraph/langgraph/types.py:851-974`; agent-framework `_workflow.py:254,590`; openai-agents-sdk `docs/human_in_the_loop.md:187-203`.

### P2. Interventions ride the persistence layer, not a side channel
- **Problem:** Side-channel interventions are lost on restart and invisible to replay/debugging.
- **Demonstrated by:** langgraph (interrupts and resumes are checkpointer writes, `libs/langgraph/langgraph/langgraph/pregel/_loop.py:902-931`); temporal (every action is a history event, `service/history/api/signalworkflow/api.go:90-101`); letta (approvals are conversation messages); agent-framework (pending requests are part of checkpoint payloads, `python/packages/core/agent_framework/_workflows/_checkpoint.py:30-98`).
- **Why it works:** Durability, replication, and audit come free from the existing transaction machinery; nothing new to persist.
- **Copy when:** You have any durable state substrate — make interventions citizens of it.
- **Risky when:** It creates hard coupling: langgraph simply refuses to resume without a checkpointer (`_loop.py:905-908`); temporal's determinism rules forbid the convenience edits people expect.
- **Evidence:** see citations above; openai-agents-sdk serializes decisions into the state payload (`src/agents/run_state.py:1300-1339`).

### P3. Fork instead of edit
- **Problem:** Humans need to correct the past; mutating history corrupts sharing, replay, and lineage.
- **Demonstrated by (five mechanisms):** checkpoint restore into a new instance (langgraph time travel; agent-framework restore-any-checkpoint, `python/samples/03-workflows/checkpoint/checkpoint_with_human_in_the_loop.py:331-335`); named branch lineage on runtime state (crewai `RuntimeState.fork()`, `lib/crewai/src/crewai/state/runtime.py:352-389`); shared-immutable-message conversation fork (letta, `letta/services/conversation_manager.py:105-172`); storage-level history branch + selective reapply (temporal reset, `service/history/ndc/workflow_resetter.go:677-703`); client-derived conversation with composer prefill (openhands "Branch from here", `src/hooks/mutation/use-fork-conversation.ts:22-71`); implicit duplicate-checkpoint copies (openai-agents-sdk `to_state()` deep-copy, `src/agents/run_context.py:117-131`).
- **Why it works:** Append-only history stays intact; alternate continuations coexist; original runs remain comparable baselines (langgraph tests prove sibling-fork independence, `libs/langgraph/tests/test_time_travel.py:182-218`).
- **Copy when:** Corrections are exploratory or audits matter.
- **Risky when:** Branch proliferation is unmanaged — openhands' `(branch)` title suffix can be renamed away and no parent link is recorded (`user-assistant-event-message.tsx:69-75`).
- **Evidence:** as cited per source.

### P4. Typed, correlated decision identities
- **Problem:** A human's answer must land on exactly the right pending request, even across restarts, parallel requests, and reused call IDs.
- **Demonstrated by:** UUID `request_id` per request_info event (agent-framework, `_workflow_context.py:428-434`); xxh3_128 namespace-hash interrupt IDs addressable out-of-order (langgraph, `types.py:612-618`); adjacent-UUID pairing + tool-call-ID symmetric-difference validation (letta, `letta/server/rest_api/utils.py:304-371`; `letta/agents/helpers.py:121-145`); canonical `(invocation_type, call_id, scope, fingerprint)` tuples raising on ambiguity (openai-agents-sdk, `src/agents/run_context.py:938-952`); request-ID/update-ID dedup (temporal, `service/history/api/signalworkflow/api.go:45-50`).
- **Why it works:** Mismatched, forged, duplicated, or stale responses become detectable server-side instead of silently applied (e.g., forged standing-approvals dropped in agent-framework, `test_harness_tool_approval.py:708`).
- **Copy when:** More than one gate can be pending, or responses can arrive from queues/webhooks — which implies always.
- **Risky when:** Ergonomics suffers; single-value resume is friendlier, which is why langgraph permits it only when ≤1 interrupt is pending (`_loop.py:916-920`).
- **Evidence:** as cited per source.

### P5. Idempotent resolution at pause points
- **Problem:** Crashes, retries, races (approve vs cancel), and context compaction can cause double-execution of side effects.
- **Demonstrated by:** letta converts replayed post-compaction approvals into keep-alive turns via full-history search and resolves approve-vs-cancel deterministically (cancel wins) (`letta/agents/helpers.py:250-293`; tested `tests/integration_test_human_in_the_loop.py:1340-1453`); AG-UI replays retained terminal decisions idempotently and marks crash-orphaned occurrences INDETERMINATE, refusing auto-retry without an idempotency key (`_approval_lifecycle.py:506-520`, `808-847`); temporal collapses duplicates to Noops (`service/history/api/resetworkflow/api.go:124-134`); openai-agents-sdk admits staged input exactly once and fails closed when identities are ambiguous (`src/agents/run_state.py:1087-1093`).
- **Why it works:** Treats the human gate like a distributed transaction: at-most-once side effects, deterministic conflict resolution.
- **Copy when:** Approved actions mutate external systems.
- **Evidence:** as cited per source.

### P6. Fail-safe cleanup of abandoned gates
- **Problem:** Runs get cancelled/reset while a human decision is pending; stranded gates brick agents or leak stale authority.
- **Demonstrated by:** letta synthesizes denial + tool-return messages so cancelling an awaiting-approval run leaves valid transcript state (`letta/services/run_manager.py:671-783`); langgraph strips stale RESUME writes during time travel and clears stale INTERRUPT writes on fork, documenting the real bug this prevents (`libs/langgraph/langgraph/langgraph/pregel/_loop.py:874-900`, `964-971`); temporal lets started tasks resolve naturally while freezing scheduling, and fails updates fast against paused workflows (`service/history/workflow/mutable_state_impl.go:3355-3391`; `tests/pause_workflow_execution_test.go:208-213`); agent-framework logs warn-only notices when fresh input lands while requests pend (`_workflow.py:856-872`).
- **Why it works:** The invariant "no run is left waiting on nobody" is enforced structurally.
- **Copy when:** Any cancellation/reset path exists (it does).
- **Evidence:** as cited; note agent-framework chose warnings over enforcement — the weakest variant of this pattern.

### P7. Pluggable prompting surfaces and generated forms
- **Problem:** HITL defaults tuned for CLIs break servers; generic clients need to render unknown prompts.
- **Demonstrated by:** crewai's `HumanInputProvider`/`HumanFeedbackProvider` protocols with ContextVar-based global override (`lib/crewai/src/crewai/core/providers/human_input.py:445-483`); agent-framework DevUI ships JSON schemas for both request and expected response so any client can render arbitrary HITL prompts (`python/packages/devui/agent_framework_devui/models/_openai_custom.py:170-174`); openhands probes capability before showing takeover buttons (`src/hooks/query/use-unified-vscode-url.ts:49-83`).
- **Why it works:** Decouples *what* is asked from *where* the human is.
- **Copy when:** Your harness targets more than one host environment.
- **Risky when:** Defaults remain blocking stdin — the failure mode crewai documents for headless runs (`human_input.py:441-442`).
- **Evidence:** as cited.

### P8. Frontend delivery-integrity patterns (client-side only)
- **Problem:** Mid-run chat sends must not vanish, double-fire, or hang forever.
- **Demonstrated by:** openhands' optimistic pending queue with a 150 s watchdog flipping stuck sends to retryable errors, server-echo reconciliation with FIFO fallback, and two-layer duplicate-submission guards (`src/stores/optimistic-user-message-store.ts:131-141,169-198`; `src/stores/event-message-store.ts:14-26`).
- **Why it works:** Keeps the composer honest while the agent runs — the enabling condition for true mid-run feedback.
- **Copy when:** Building any steering UI over an async backend.
- **Evidence:** as cited; unique to openhands in this set because it is the only pure-frontend source.

## Key Differences

**Directness of state editing.** This is the widest divergence. langgraph treats editing as a public graph operation with reducer semantics and ambiguity errors (`update_state`, `InvalidUpdateError` on ambiguous `as_node`, `main.py:1905-1938`); letta allows privileged REST editing of memory blocks/config but hard-forbids transcript edits (405, `agents.py:1641-1644`); openai-agents-sdk channels everything through controlled methods (`approve/reject/add_input`, Session protocol) with private internals; agent-framework and crewai leave editing to hosts via serialize/edit/deserialize conventions (`_sessions.py:1750-1794`; offline JSON surgery on checkpoints); temporal and openhands structurally prevent it — temporal for determinism, openhands because the frontend never invents state. These are constraint-driven choices, not quality rankings: replay determinism (temporal) and message sharing across forks (letta) each forbid what langgraph's channel model naturally permits.

**Live feedback.** openhands alone sends user messages while the agent is RUNNING as a designed primary flow (`interactive-chat-box.tsx:62-65`); agent-framework supports enqueue-mid-run via middleware, callable even from tool code (`_sessions.py:1383-1433`); temporal offers the richest boundary-crossing model — async signals plus synchronous, validator-rejectable updates with wait stages (`workflow_handler.go:5414-5560`); crewai injects between iterations; langgraph, openai-agents-sdk, and letta deliberately restrict input to pause boundaries, compensating with rich pause-time payloads (denial reasons that steer the model, staged `add_input`, batched multi-tool decisions mixing approve/deny/returns — letta `integration_test_human_in_the_loop.py:1175-1290`).

**Fork mechanics.** Storage-level branching with input cherry-picking (temporal) is the most powerful and the most complex; checkpoint-restore-as-fork (langgraph, agent-framework, crewai) is flexible but usually unnamed as such — agent-framework explicitly reports no first-class fork API despite the capability; message-link-sharing forks (letta) save storage but make surgical fixes impossible; client-side derived conversations (openhands) are cheapest and weakest on lineage; deep-copied checkpoints (openai-agents-sdk) enable forking technically but it is undocumented intent.

**Traceability.** A clear maturity ladder: temporal records identity, reason, request-ID, and links on every intervention event, projects pause state into searchable attributes, and distinguishes human vs system actors by identity convention (`workflow_resetter.go:609,627,714`) → letta attributes memory edits to `letta_user` vs `letta_agent` with undo support (`block_history.py:12-48`) and persists approval exchanges as typed transcript messages → langgraph tags checkpoints `source: update/fork` with parent lineage and run IDs but no human identity (`base/__init__.py:38-62`) → agent-framework reconstructs interventions from scattered ledgers (UUIDs, lineage chains, AG-UI transition logs) without unification → openai-agents-sdk persists decisions durably but emits no tracing span and captures no actor → crewai audits flows well (events + `human_feedback_history`) but crew/task-level feedback survives only via training mode or lucky checkpoint timing → openhands relies on the event stream itself, with fork lineage reduced to a naming convention.

**Where takeover authority lives.** Server-owned (AG-UI `ApprovalLifecycle` explicitly forbids runner-side pending registries, `python/packages/ag-ui/AGENTS.md`; temporal history service), host-owned (openai-agents-sdk RunState custody), engine-owned (langgraph checkpointer), client-mediated (openhands), or operator-owned via CLI (crewai `crewai checkpoint resume`). Each matches the deployment shape: hosted UIs centralize to prevent double-execution; SDKs push custody to apps for flexibility.

## Tradeoffs

**Durability vs immediacy.** Persisted halts enable hours-long approvals and cross-process resume (all sources) but forbid nudging a live step; openhands' always-on composer buys immediacy only because its server queues and reconciles, adding a whole reliability layer (echo matching, watchdogs) to compensate (`optimistic-user-message-store.ts` throughout). Temporal hedges with two tiers — cheap async signals vs RPC-like validated updates — at the cost of a formal update state machine and flag-gated wait stages (`service/frontend/workflow_handler.go:5487-5500`).

**Re-execution vs stack preservation on resume.** langgraph re-runs node bodies from their start, returning stored resume values positionally (`types.py:864`, `955-965`) — simple and serializable, but pushes idempotency burden onto user code; letta avoids this by replaying the exact stored tool dispatch with `is_approval` flags (`letta_agent.py:248-271`), one code path for live and resumed execution, at the cost of persisting fuller execution detail.

**Edit power vs safety.** langgraph's `update_state` executes only the node's writers, not its body, so human edits bypass whatever validation lives in node code (`main.py:1953-1971`) — reducers are the only guardrail. letta's opposite choice (immutability + fork) protects siblings but turns typo fixes into re-runs. openai-agents-sdk's strict canonical identity prevents misattributed approvals yet burdens hosts with unique call IDs across nested runs (`run_state.py:1241-1252`).

**Sticky decisions vs blast radius.** `always_approve`-style standing rules reduce fatigue (openai-agents-sdk sticky scopes; agent-framework `ToolApprovalRule` persisted in session state) but grant run-wide or session-wide authorization; both mitigate via scoping — openai-agents-sdk binds hosted-MCP stickiness to server_label + tool name (`run_context.py:979-988`), and agent-framework drops forged standing-rule metadata outright (`test_harness_tool_approval.py:708`).

**Blocking defaults vs deployability.** crewai's zero-config stdin prompt is perfect locally, unusable headless (`input()` EOFError risk, `human_input.py:441-442`); the fix (providers) exists but is opt-in discovery. letta similarly blocks ordinary messages while approval pends (`PendingApprovalError`), trading urgency-steering for corruption-proof ordering.

**Feature flags vs uniform capability.** Temporal ships pause behind namespace-scoped config default-off (`common/dynamicconfig/constants.go:3704-3708`), and openhands forks/interrupts behave differently local vs cloud (`conversation-mutation-utils.ts:36-61`) — both gain safe rollout at the cost of environments where the intervention surface silently differs.

**Checkpoint fidelity vs inspectability.** agent-framework's JSON+base64-pickle checkpoints preserve rich objects but are neither human-diffable nor tamper-evident (`_checkpoint.py:249-261`); temporal's event log is fully auditable but accepts only what events can express.

## Decision Guide

- **Choose checkpoint-mediated interrupts (langgraph-style)** when your engine already has durable graph state and users need both approval gates and retrospective surgery/time-travel. Require a checkpointer up front; decide your resume-addressing scheme (positional single-value vs ID map) before shipping parallel branches.
- **Choose one-unified-primitive (agent-framework-style)** when many HITL surfaces (tools, plans, group chat, UI forms) would otherwise each invent halting semantics; the payoff is uniform halt/resume/test behavior, demonstrated by dedicated suites across all four layers (`test_request_info_and_response.py:177,263`).
- **Choose serializable-state lifecycle (openai-agents-sdk-style)** when runs must cross process/service boundaries or sit in queues for days; budget for schema versioning from day one — it is the difference between a durable contract and a compatibility nightmare.
- **Choose message-protocol approvals (letta-style)** when conversation history is already your durable substrate and you want interventions visible, replayable, and provider-agnostic inside the transcript itself; accept immutability and design fork UX early.
- **Choose event-sourced interventions (temporal-style)** when audit completeness, multi-tenant operations, or regulatory traceability dominate; you inherit determinism constraints that forbid casual edits, so pair resets with disciplined reapply policy.
- **Choose pluggable-provider review loops (crewai-style)** for developer-facing frameworks where the same library must serve CLI scripts, servers, and chat ops; mandate a non-blocking default provider story before v1.
- **If building the client for any of the above**, adopt openhands' separation: the client owns UX integrity (optimism, dedupe, retries) and never state authority; add durable fork lineage server-side rather than repeating the "(branch)" convention mistake.
- **Universal rule regardless of model:** every human gate needs (a) a correlation ID that survives restarts, (b) defined behavior when the run dies mid-gate, (c) an idempotency story for replayed answers, and (d) a record saying who answered. Three of the four exist nearly everywhere; (d) is the differentiator to build deliberately.

## Practical Tips

**Patterns worth copying:**
- Persist pending requests *inside* checkpoints so humans can answer across machine restarts (agent-framework `_checkpoint.py:59-61`; sample `checkpoint_with_human_in_the_loop.py:209-335`).
- Make denials informative: letta injects "Error: request to call tool denied. User reason: {reason}" as a tool return so the agent adapts without restart (`letta_agent.py:1739-1763`), and openai-agents-sdk supports custom rejection messages visible to the model (`run_state.py:1277-1281`).
- Log the exact recovery command at the moment it becomes relevant: crewai checkpoints print `Resume with: crewai checkpoint resume {id}` (`checkpoint_listener.py:172-175`).
- Batch parallel tool calls into one approval request allowing mixed per-call verdicts plus substitute returns (letta `helpers.py:295-306`); hide already-approved calls from mixed batches and reinject them on resume (agent-framework `test_harness_tool_approval.py:418-648`).
- Support partial resolution: deciding some interruptions now and leaving others pending re-pauses cleanly (openai-agents-sdk `docs/human_in_the_loop.md:57`).
- Turn repeated corrections into compounding value: crewai's `learn=True` distills HITL feedback into recalled lessons (`human_feedback.py:247-359`).
- Probe capabilities before rendering takeover affordances so deployments without editors show nothing instead of dead buttons (openhands `/api/vscode/status`).

**Patterns to avoid or delay until needed:**
- Live mid-step injection infrastructure (queue-and-drain middleware, command channels) until boundary-crossing feedback demonstrably frustrates users; three of four high scorers shipped without it.
- Named fork APIs before branch-lineage metadata exists — otherwise you reproduce openhands' untraceable branches.
- Sticky "always approve" until per-call overrides and scope binding are in place (both prerequisites appear in the two sources that support stickiness well).
- Interactive sandbox attach (exec-into-container consoles): no studied source provides it; PTY primitives that exist (openai-agents-sdk `sandbox_session.py:586-621`) are deliberately wired for agent tools, not human consoles.

## Anti-Patterns / Caution Signs

- **Warn-only correctness guards.** Agent-framework logs a warning when fresh input lands while requests pend but proceeds anyway (`_workflow.py:856-872`); stale answers can be applied to moved-on state. If your liveness depends on callers reading warnings, you have a latent race.
- **Lineage by naming convention.** openhands marks forks with a `"<title> (branch)"` suffix that renames erase, with no parent link recorded (`user-assistant-event-message.tsx:69-75`). If branches cannot be queried, fork-based editing will eventually strand someone.
- **Blocking stdin as the default HITL transport.** Crewai's headless `EOFError` failure and duplicated sync/async prompt paths show the drift cost (`human_input.py:237-316`); two executor implementations carrying the same flag plumbing is a bug factory.
- **Untampered intervention substrates.** Agent-framework checkpoints lack signatures/HMACs — the topology hash validates shape, not content, so edited blobs restore as-is (`_checkpoint.py:48-49`); crewai training capture uses pickle keyed by agent id (`training_handler.py:7-31`). If humans are trusted editors, tamper-evidence still matters for disputes.
- **Silent degradation of audit.** Temporal's rejected updates leave no durable history event (`api.go:283-294`); crewai auto-checkpoint failures are swallowed to warnings (`checkpoint_listener.py:241-244`); openai-agents-sdk has no approval tracing span. Negative space in the audit log is still a gap operators will hit.
- **String-parsing control flow.** openhands detects max-iterations by matching English error text (`use-handle-ws-events.ts:57-59`) — brittle glue between intervention UX and server behavior.
- **Capability skew across backends.** When local and cloud differ on forking and interrupt semantics (openhands) or features hide behind per-namespace flags (temporal), downstream automation meets inconsistent timing guarantees; document or unify.
- **Unbounded pending gates.** Crewai's pending-feedback rows have `created_at` but no TTL (`sqlite.py:229-244`); letta lacks stuck-approval alerting beyond a 3-hour stream expiry (`conversations.py:805-806`). Pending forever is a support ticket generator.

## Notable Absences

- **Actor attribution is near-universally missing.** Only letta stamps editor type/ID on memory edits; langgraph's checkpoint metadata, openai-agents-sdk's approve calls, agent-framework's Python approval path, and openhands' confirmations all lack human identity; temporal carries caller-supplied strings without evidence of per-operation RBAC (`workflow_handler.go` review boundary noted in source report).
- **Interactive sandbox/console takeover: none.** Every source explicitly searched and found no exec/attach-into-live-sandbox mechanism (letta, openai-agents-sdk, langgraph, openhands, temporal all document this absence); openhands deliberately made its terminal read-only and routes hands-on work to browser VSCode (`use-terminal.ts:107`).
- **Unified intervention ledgers: none.** Even the best sources scatter evidence across transcripts, checkpoints, lifecycle logs, and telemetry spans rather than offering one "who did what, when, with which arguments" query surface (explicitly listed as future work in agent-framework and openai-agents-sdk reports).
- **TTL/expiry on pending human decisions** exists only in AG-UI retention windows (24h default, `_approval_lifecycle.py:239-246`) and letta's stream expiry; crewai, langgraph workflow-level pending events, and openai-agents-sdk approvals linger indefinitely.
- **First-class fork APIs** are absent as named operations in agent-framework and openai-agents-sdk despite underlying capability; openhands' cloud backend prohibits forking entirely (`agent-server-conversation-service.api.ts:802-806`).
- **Mid-run injection into live steps** does not exist anywhere in the strong sense; the closest are boundary-landing mechanisms (signals/updates, enqueue-drain, queued REST sends) and realtime/live-session exceptions.

## Per-Source Notes

- **agent-framework (8):** Four-layer reuse of one typed interrupt primitive; strongest breadth (workflows, tool approval, plan review, group chat, AG-UI, DevUI). Weakest spots: indirect-only state correction, untampered checkpoints, warn-only safeguards, dual-language parity drift.
- **crewai (8):** Richest variety of intervention points (task-final-answer, decorator-marked flow steps, tool hooks, LLM hooks) plus the only operator CLI for checkpoint management. Weakest: blocking defaults, executor duplication, uneven durability of crew-level audit, no response deadlines.
- **langgraph (9):** Deepest intervention primitives — real state surgery with reducer semantics, content-derived interrupt IDs, provenance-tagged time travel, deployment-layer cancel/multitask strategies. Costs: boundary-only feedback, node re-execution idempotency burden, anonymous edits.
- **letta (8):** Best traceability and race handling (idempotent replays after cancel/compaction, synthesized-denial repair on cancellation, actor-typed undoable memory). Constrained by immutable transcripts and Redis-dependent features; sandbox layer is batch-only.
- **openai-agents-sdk (8):** Most disciplined durable contract — versioned snapshots with fail-fast readers, historical fixture tests, nested-interruption routing, fail-closed policy evaluation. Missing: actor identity, decision spans, an explicit fork API; standard Runner cannot be steered mid-turn.
- **openhands (7):** As a pure client, demonstrates that intervention UX is its own engineering discipline (delivery integrity, capability probing, status propagation). Its weaknesses — cosmetic fork lineage, cloud/local semantic splits, wire-supported-but-unused rejection reasons — are instructive precisely because they are visible UI-layer failures.
- **temporal (9):** Reference model for auditable takeover: interventions as events with identity/reason/request-ID/links, activity-level pause granularity, storage-level reset branching with selective human-input reapply, searchable pause state. Frictions: opt-in flags, reapply edge cases (CHASM issue #11384), no durable record of rejections, reset constrained to task-completed boundaries.

## Open Questions

- **Who intervened?** Does production deployment of langgraph/openai-agents-sdk/agent-framework add authenticated identity above the framework, or do audit gaps persist in practice? (Explicitly undetermined in all three reports.)
- **Authorization granularity:** Temporal's intervention endpoints rely on caller-supplied identity strings; whether per-operation RBAC (pause vs terminate) exists was outside the reviewed interceptor scope. Same question applies to letta's privileged PATCH APIs versus agent-side read-only blocks.
- **Cross-run propagation:** Does pausing/forking a parent affect children? Temporal's child-workflow-aware reset is stubbed (`workflow_resetter.go:883-900`); letta fork deletion-safety is tested but broader tree semantics are not.
- **Server-side enforcement for openhands:** confirmation and fork enforcement live in the sibling software-agent-sdk repo and could not be verified; whether confirmations persist as first-class events (vs status transitions) remains unknown.
- **Version-skew handling:** Whether `crewai checkpoint resume` is safe across library-version differences is only partially evidenced; openai-agents-sdk solves this formally — could its `$schemaVersion` changelog pattern transfer?
- **JS parity:** langgraph's sdk-js submodule was not populated, so client parity for command/checkpoint parameters is unverified.
- **Enterprise-tier features:** CrewAI docstrings reference enterprise integrations around HITL metadata that could not be verified in the OSS source.
