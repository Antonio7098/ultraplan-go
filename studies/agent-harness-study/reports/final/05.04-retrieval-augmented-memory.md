## Executive Summary

Across six sources, retrieval-augmented memory splits into three postures rather than one spectrum of quality. **letta (8/10)** owns a full product-grade pipeline: four retrievable corpora, a document-ingestion pipeline (parse → MIME-aware chunking → batched embedding → dual-write), hybrid vector/BM25 retrieval fused by Reciprocal Rank Fusion, and structural provenance on every passage. **crewai (7/10)** and **agent-framework (7/10)** ship opinionated but partial stacks — crewai runs LLM-in-the-loop encode/recall flows over episodic memory alongside a much weaker document-Knowledge path; agent-framework standardizes on context-provider lifecycle hooks and delegates vectors/reranking to backend services while keeping a self-managed markdown memory harness. **langgraph (7/10)** and **pydantic-ai (7/10)** deliberately stop at infrastructure primitives — a namespaced Store with opt-in semantic search, and an embeddings abstraction plus tool-corpus search respectively — leaving chunking, stores, and reranking to applications. **openhands (3/10)** is a boundary artifact: within its frontend repo, semantic retrieval is absent by design, with trigger matching, condensation, and memory loading delegated to a sibling SDK.

Two findings cut across all sources. First, **scoping is the most consistently engineered concern** — every source that retrieves anything does so through explicit hierarchical scopes (namespaces, scope paths, org/archive boundaries, capability gates), and several treat scope misconfiguration as a hard error. Second, **provenance is the clearest differentiator between scores**: the sources that preserve origin structurally at index time (letta's passage schema, agent-framework's typed citation annotations, pydantic-ai's typed history parts) score higher than those that discard it (crewai's knowledge chunks are stored as bare content strings), directly answering the dimension question "can the model trust retrieved memory because it knows where it came from?" — mostly no for documents, partially for memories.

Equally notable is what nobody ships: no active-path cross-encoder reranker exists anywhere in the cohort (letta's only reranker sits on a legacy Pinecone path), only pydantic-ai evaluates retrieval quality with an actual eval suite, and silent degradation to empty or recency-ordered results is the dominant failure policy everywhere except letta (labeled fallbacks) and pydantic-ai/langgraph (fail-fast capability gates).

## Core Thesis

Retrieval trust is manufactured at index time, not query time. The cohort converges on this from both directions: letta earns its 8 by making provenance a storage-schema invariant (`letta/schemas/passage.py:19-32`) and labeling degraded modes in result metadata (`letta/services/message_manager.py:1232-1239`), while crewai's weakest area is precisely where origin was never captured — knowledge chunks persisted as bare content strings with a metadata field explicitly marked "Currently unused" (`lib/crewai/src/crewai/knowledge/storage/knowledge_storage.py:118`, `lib/crewai/src/crewai/knowledge/source/base_knowledge_source.py:28`), which makes hallucinated facts untraceable even by the framework itself. Frameworks that defer indexing strategy to applications (pydantic-ai, langgraph) compensate by hardening the seams they do own — typed, replay-safe discovery records and escaped namespace scoping — implicitly acknowledging that once content enters a store without origin, no query-time mechanism can recover trust.

## Approach Models

**agent-framework — hook-based composition.** Retrieval is not a retriever interface but a lifecycle contract: `ContextProvider.before_run/after_run` injects messages/instructions/tools pre-inference and persists memory post-inference (`python/packages/core/agent_framework/_sessions.py:793-870`; .NET mirror `dotnet/src/Microsoft.Agents.AI.Abstractions/AIContextProvider.cs:42-78`). Five coexisting families — markdown file memory, .NET vector chat history, delegate text search, service-backed RAG (Azure AI Search/Mem0/Redis/Cosmos), and hosted-retrieval delegation — all fit the same hook shape.

**crewai — two parallel stacks with LLM-in-the-loop flows.** Unified Memory (`lib/crewai/src/crewai/memory/unified_memory.py:76`) treats encoding as an LLM-analyzed batch flow (`encoding_flow.py:112-501`) and recall as an adaptive-depth flow that distills queries, searches scopes in parallel, and routes on confidence (`recall_flow.py:58-380`). Knowledge (`lib/crewai/src/crewai/knowledge/knowledge.py:88`) is conventional fixed-chunk RAG into ChromaDB. The two share an embedding factory but no retrieval interface.

**langgraph — Store as infrastructure, not pipeline.** `BaseStore` defines namespace-scoped KV operations with semantic search enabled per-instance via `IndexConfig(dims, embed, fields)` (`libs/checkpoint/langgraph/store/base/__init__.py:708`, `:578-705`). "Chunking" is JSON-path field selection where array elements become individual vectors; there is no document loader or text splitter anywhere in the tree.

**letta — product-owned agentic memory subsystem.** Four corpora (archival passages, messages, file passages, tools) exposed primarily as agent-invocable tools whose docstrings teach search strategy (`letta/functions/function_sets/base.py:87-243`). Storage is SQL-first with Turbopuffer/Pinecone/pgvector mirrors; retrieval defaults to hybrid multi-query fused client-side by RRF k=60 (`letta/helpers/tpuf_client.py:1489-1559`).

**openhands — delegated retrieval behind a thin-client boundary.** Within the frontend repo there are only non-semantic approximations: keyset-paginated event history (`src/api/event-service/event-service.api.ts:102-181`), keyword-triggered skills whose matching is explicitly delegated server-side (`src/api/agent-server-adapter.ts:697-747`), and user-triggered condensation verified behaviorally (`src/hooks/use-await-context-compaction.ts:57-163`).

**pydantic-ai — strong primitives, separated surfaces.** Tool search is the one end-to-end retrieval subsystem (keyword-overlap default `pydantic_ai_slim/pydantic_ai/toolsets/_tool_search.py:451-483`, native BM25/regex strategies, custom callables). Embeddings are a six-provider abstraction with no store ("Pydantic AI does not prescribe a vector database", `docs/embeddings.md:133-135`). Document RAG is delegated to providers via `FileSearchTool` (`pydantic_ai_slim/pydantic_ai/native_tools/__init__.py:630-676`) or left to application code.

## Pattern Catalog

### P1. Explicit scope isolation with zero implicit inheritance
- **Problem:** agents sharing a memory substrate must not leak records across users, tenants, or privilege levels.
- **Demonstrated by:** agent-framework (Mem0 storage scope vs retrieval scope never inherit; empty retrieval scope → warning + no retrieval, `python/packages/mem0/agent_framework_mem0/_context_provider.py:50-61`; .NET constructor throw `dotnet/src/Microsoft.Agents.AI.Mem0/Mem0Provider.cs:107-112`), crewai (`root_scope` nesting prevents crews escaping their subtree, `unified_memory.py:152-159`; privacy requires matching `source`, `recall_flow.py:109-114`), letta (org-scoped environment-suffixed TPUF namespaces plus mandatory `agent_id` equality filters, `letta/helpers/tpuf_client.py:1110-1183`, `:1677-1693`), langgraph (LIKE-metacharacter escaping so `("foo",)` cannot match `("foobar",)`, `libs/checkpoint-postgres/langgraph/store/postgres/base.py:1283-1308`; reserved root namespace `libs/checkpoint/langgraph/store/base/__init__.py:1280-1283`), openhands (path-marker skill taxonomy, `src/utils/skill-scope.ts:79-106`).
- **Why it works:** scope errors become configuration errors visible at startup/write time rather than quiet leaks discovered in production; tests encode the invariant (e.g. `test_search_scope_does_not_inherit_storage_scope`, `python/packages/mem0/tests/test_mem0_context_provider.py:372`).
- **Copy when:** any multi-user, multi-agent, or multi-workspace substrate.
- **Risky/overkill when:** single-tenant local tools — the ceremony adds friction (Mem0's first-run warning that retrieval silently did nothing is the documented cost).
- **Weak variants to avoid:** string-convention scoping without enforcement — crewai's LanceDB scope filter is a LIKE predicate whose correctness depends on consistent path formatting (`lancedb_storage.py:387-390`), and openhands' home-directory regex heuristics misfile skills under unusual layouts (`skill-scope.ts:35-52`).

### P2. Structural provenance attached at index time
- **Problem:** retrieved content must be attributable for citation, debugging, and trust.
- **Demonstrated by:** letta (every passage carries `archive_id`, `source_id`/`file_id`, `file_name`, tags, timestamps, `letta/schemas/passage.py:19-32`; results additionally expose ranking provenance — `rrf_score`, `vector_rank`, `fts_rank`, `search_mode`, `letta/services/tool_executor/core_tool_executor.py:231-246`), agent-framework (Azure KB references → typed `Annotation(type="citation")` with url/title/reranker_score/sensitivity label, `python/packages/azure-ai-search/agent_framework_azure_ai_search/_context_provider.py:996-1048`; cross-session origin attribution `_memory.py:1321-1346`), pydantic-ai (discovery round-trips persisted as typed message parts tagged `tool_kind='tool-search'`, surviving serialization and provider replay, `pydantic_ai_slim/pydantic_ai/_tool_search.py:121-362`, `:442-575`).
- **Why it works:** provenance becomes a write-path invariant instead of a best-effort formatting convention; it also powers observability (a result knows *how* it was found).
- **Copy when:** always, for any corpus the model consumes.
- **Counter-evidence:** crewai stores knowledge chunks bare and strips id/score/metadata at injection (`knowledge_utils.py:4-12`) — an agent consuming snippets cannot cite which file produced a fact; langgraph preserves only `(namespace, key)` identity, pushing provenance into user-defined values.

### P3. Labeled degradation ladders
- **Problem:** fallback paths must be distinguishable from primary results, or broken configurations hide behind availability.
- **Demonstrated by:** letta marks SQL-fallback results with an honest `"sql_fallback"` mode label (`letta/services/message_manager.py:1232-1239`) and groups file results under named headers with scores (`files_tool_executor.py:654-673`); agent-framework's Azure provider degrades to keyword-only search with warnings after schema introspection (`_context_provider.py:698-753`); openhands attempts full pagination filters then falls back limit-only with a `strictPagination` escape hatch (`src/api/event-service/event-service.api.ts:120-163`).
- **Why it works:** operators can distinguish "no matches" from "search is broken"; callers can assert on mode.
- **Copy when:** any primary/fallback pair exists.
- **Contrast anti-pattern:** langgraph silently reorders by recency when semantic search is unconfigured (`base.py:548-563`), indistinguishable from real semantic output; agent-framework's .NET TextSearchProvider catches all retrieval errors into empty context (`TextSearchProvider.cs:199-203`).

### P4. Oversample-then-filter
- **Problem:** post-vector metadata filtering starves ANN results below top-k.
- **Demonstrated by:** crewai fetches ×2–×3 candidates before category/metadata/privacy/time filters (`types.py:12-17`, `lancedb_storage.py:391-393`); langgraph over-fetches `limit * estimated_vectors_per_doc * 2 + 1` to keep pagination stable across multi-vector items (`base.py:503-546`).
- **Why it works:** cheap insurance against filter-induced truncation without giving up index traversal.
- **Copy when:** filters apply after similarity search (the common case given pgvector/ANN limitations).
- **Risky when:** treated as completeness guarantees — both sources note heuristics can still truncate.

### P5. Staleness handled at write time OR read time — rarely both
- **Problem:** memory drifts; something must retire or merge stale records.
- **Demonstrated by:** write-time consolidation — crewai merges/updates/deletes above 0.85 similarity during save (`encoding_flow.py:272-310`), agent-framework consolidates topics on min-sessions/time cadence and refuses to advance the window when all LLM calls fail (`_memory.py:1541-1549`). Read-time expiry — langgraph TTLs with `omit_expired` read filtering and a background sweeper (`base/__init__.py:526-575`, `base.py:850-939`), crewai applies exponential recency decay (30-day half-life, `types.py:364-372`).
- **Why it works:** consolidation improves density; TTL/decay bounds damage without trusting an LLM's delete decisions.
- **Copy when:** pick per corpus — conversational memory tolerates consolidation; factual/knowledge corpora need expiry because wrong merges are irreversible (crewai executes deletes directly with no tombstone, `encoding_flow.py:452-455`).

### P6. Dual-write with a declared source of truth, tested for failure isolation
- **Problem:** combining durable relational truth with fast vector indexes risks divergence.
- **Demonstrated by:** letta writes Postgres first, mirrors same-ID rows to Turbopuffer, treats TPUF failures as non-fatal unless strict mode (`passage_manager.py:586-632`), and proves the property with `test_turbopuffer_failure_does_not_break_postgres` (`tests/integration_test_turbopuffer.py:1586`).
- **Why it works:** deletion/recovery stays tractable in SQL; the vector layer becomes rebuildable.
- **Cost:** eventual consistency — a failed mirror leaves passages invisible to vector search until resync; letta documents pending backfills in-code (`tpuf_client.py:1052-1055`), though soft-deleted messages can still resurface because the comment and implementation diverge (`tpuf_client.py:1052-1055` vs `message_manager.py:1201-1216`).
- **Copy when:** operating a long-lived service. Unnecessary for embedded libraries.

### P7. Capability gating with loud failure for unsupported features
- **Problem:** optional capabilities silently ignored produce wrong-but-plausible behavior.
- **Demonstrated by:** langgraph raises `NotImplementedError` when `ttl` is passed to a store with `supports_ttl=False` (`base/__init__.py:920-924`); pydantic-ai hard-fails named native strategies where unsupported rather than substituting an algorithm (`capabilities/_tool_search.py:168-177`); agent-framework detects stable-vs-preview Azure SDK builds and rejects unsupported options citing the installed version (`_context_provider.py:559-584`).
- **Copy when:** the user explicitly requested the capability. Note langgraph itself applies two different policies — loud for TTL, silent for missing `IndexConfig` — and the silent one is its documented failure mode.

### P8. Embedding-space drift detection
- **Problem:** changing embedders invalidates stored vectors invisibly.
- **Demonstrated by:** crewai raises `EmbeddingDimensionMismatchError` naming old/new models with remediation commands, deliberately subclassing `ValueError` so background saves surface it (`storage/backend.py:11-41`; test `tests/memory/test_dimension_mismatch.py:138`); letta regenerates mismatched-dimension embeddings at ingest (`tpuf_client.py:527-548`) and zero-pads to a max dimension so mixed models coexist (`schemas/passage.py:49-77`).
- **Contrast:** langgraph bakes dims/vector-type into DDL with no migration path (`base.py:105-124`); pydantic-ai only documents the re-embed requirement (`docs/embeddings.md:141`).

### P9. Meta-retrieval: searching the tool corpus itself
- **Problem:** large tool catalogs overflow prompts and degrade selection.
- **Demonstrated by:** pydantic-ai exclusively — deferred tools form a searchable corpus with undiscovered-first ranking so known tools can't crowd out new matches (`toolsets/_tool_search.py:465-482`), shaped empty-result messages that prevent retry loops (`:508-521`), cache-preserving wire design (`:362-367`), and a scenario-based eval across three models (`tests/test_tool_search.py:503-537`). agent-framework's .NET `TextSearchProvider.OnDemandFunctionCalling` is a lighter variant of the same eager-vs-on-demand toggle (`TextSearchProvider.cs:110-131`).
- **Why it works:** treats tool definitions as just another retrievable corpus, inheriting the same scoping/provenance machinery.
- **Copy when:** catalogs exceed roughly dozens of tools; overkill below that.

### P10. Read-your-writes barriers and batched op pipelines
- **Problem:** async memory writes race with subsequent reads; concurrent calls duplicate work.
- **Demonstrated by:** crewai's `recall()` drains pending background saves first (`unified_memory.py:297-370`, `:711-713`); langgraph coalesces and dedupes identical Get/Search/Put ops per event-loop tick before touching storage/embeddings (`store/base/batch.py:283-371`).

## Key Differences

**What converges despite different implementations.**

- *Hierarchical explicit scoping.* All six sources scope retrieval hierarchically and explicitly — namespaces (langgraph), scope paths (crewai), org/archive/env namespacing (letta), owner-encoded storage roots (agent-framework `_memory.py:700-745`), conversation/workspace binding (openhands), capability-gate exclusion (pydantic-ai). None infers scope from model behavior.
- *Lexical baselines persist alongside vectors.* agent-framework's core selector is pure keyword overlap (`_memory.py:1079-1098`), pydantic-ai's default tool search is keyword overlap (`_tool_search.py:451-483`), letta runs BM25 in every hybrid query, crewai filters scopes with SQL LIKE. Vectors supplement rather than replace cheap, debuggable lexical matching.
- *LLM-driven extraction/consolidation for memory writes.* agent-framework (`_memory.py:1398-1470`), crewai (`encoding_flow.py:112-501`), and indirectly openhands' condenser all use LLM analysis to convert raw interaction into storable units — while keeping raw transcripts available as a second corpus (agent-framework transcripts, letta messages).
- *No reranking anywhere.* Every source either lacks a reranker or relegates it to heuristic re-weighting: crewai's composite score (`types.py:345-380`), letta's rank-only RRF, agent-framework passthrough of server-side reranker scores, langgraph/pydantic-ai nothing. A ContextualAI cross-encoder exists in crewai-tools but is explicitly not wired into the pipeline (`contextual_rerank_tool.py:22-81`).
- *Mechanics-tested, quality-untested.* Tests verify filters, pagination, TTL, scoping, and failure isolation everywhere; only pydantic-ai measures whether retrieval finds the right thing (`test_tool_search_eval`, 4 scenarios × 3 models). agent-framework explicitly reports no retrieval benchmark; letta found no recall@k/nDCG fixtures; langgraph notes tests verify mechanics "not quality."

**Why sources diverge.**

- *Product shape.* letta is a hosted multi-tenant service, so it must own ingestion, hybrid search, isolation, and degradation end-to-end. langgraph and pydantic-ai are libraries whose users bring their own infrastructure — shipping a prescribed pipeline would compete with customers' stacks. agent-framework is a multi-package framework straddling both, resolved via the hook seam. openhands is a frontend repo where the studied behavior lives across a documented repo boundary (`src/api/agent-server-adapter.ts:714-721`); its low score reflects boundary placement, not negligence — within scope it engineers what it owns deliberately (observable condensation, scoped skills).
- *Where intelligence sits.* crewai puts the LLM in the retrieval hot path (query distillation, exploration rounds, synthesis, evidence-gap extraction). agent-framework confines the LLM to the write path and keeps reads deterministic and free. langgraph keeps LLMs out entirely. letta teaches strategy through tool docstrings instead. These are latency/cost/determinism tradeoffs, not maturity differences: crewai pays multiple LLM calls per deep recall (budgeted at `exploration_budget=1`, short queries bypass analysis) and needs recursion guards (`_skip_auto_memory`, `recall_flow.py:68`); agent-framework's reward is predictable reads at the cost of paraphrase-blindness.
- *Trust model for consolidation.* crewai lets the LLM delete records outright (irreversible); agent-framework keeps per-topic locks, atomic writes, and non-advancing failure windows (`_memory.py:1025-1050`, `:123-136`, `:1541-1549`); langgraph avoids LLM judgment entirely via TTL. Same goal — a tidy store — opposite risk profiles.
- *Compatibility pressure.* Multi-backend libraries accumulate parity debt: langgraph re-implements filters/scoring per engine and already diverges (SQLite `inner_product` mapped to `-1 * vec_distance_L1`, `libs/checkpoint-sqlite/langgraph/store/sqlite/base.py:512-515`); letta carries three parallel agent-loop implementations duplicating retrieval plumbing (`letta_agent.py:1823`, `letta_agent_v2.py:1184`, `letta_agent_v3.py:1878`). Single-stack sources don't face this.

## Tradeoffs

**Owned pipeline vs primitives.**
Source A uses X because..., while Source B uses Y because...:
- letta owns parse→chunk→embed→store→retrieve because a product must guarantee behavior without user assembly; cost is enormous surface — incomplete migrations (deprecated `source_id` still keyed in TPUF, `tpuf_client.py:1852-1858`), brittle error-text sniffing (`openai_embedder.py:93-107`), duplicated loop plumbing. Best-fit: services storing other people's data. Failure mode: inconsistency between layers hides in the gaps (tag filter applied after LIMIT, `agent_manager.py:2494-2527`).
- pydantic-ai/langgraph ship primitives because library users need portability more than opinion; cost is that application-built stores get zero framework safeguards — pydantic-ai's docs must *instruct* permission metadata per chunk (`docs/embeddings.md:106`) with nothing enforcing it. Alternative middle path seen in crewai: own two stacks and duplicate storage concerns while the weaker stack skips the stronger one's safeguards — the worst-reviewed outcome in the cohort relative to effort spent.

**Rank fusion vs score fusion vs no fusion.**
letta fuses ranks (RRF k=60) because vector and BM25 scores are incomparable magnitudes — stable ordering, but it cannot express confidence beyond position (`tpuf_client.py:1500-1503`). agent-framework leans on server-side semantic ranking with `vector_k = max(top_k, 50)` inflation (`_context_provider.py:755-797`). crewai/langgraph fuse nothing; single-signal ordering is simple but loses lexical recall entirely (langgraph has no lexical index at all).

**LLM-consolidation vs TTL expiry.**
Consolidation produces semantically merged, deduplicated memory (crewai drops intra-batch duplicates at cosine ≥ 0.98, `encoding_flow.py:121-140`) but trusts LLM delete decisions irreversibly. TTL is mechanical and reversible-in-effect (expired data is gone but was never mutated) but cannot merge paraphrases and needs sweeper infrastructure. agent-framework shows a hybrid: LLM consolidation gated by deterministic windows that freeze on failure.

**Strict scope enforcement vs convenience.**
.NET Mem0 throws at construction when scopes are absent; Python Mem0 warns-and-skips; letta refuses vector search entirely for multi-archive agents rather than merging unsafely (`agent_manager.py:2444-2446`). All trade setup friction for leak-class elimination — the cohort uniformly judges friction worth paying.

**Type-aware chunking vs naive chunking vs no chunking.**
letta's MIME registry of LlamaIndex splitters with two-tier fallback chains preserves structure but can silently degrade fidelity (MarkdownNodeParser → SentenceSplitter, `llama_index_chunker.py:81-85`). crewai's fixed 4000-char slicing is predictable but destroys CSV row and JSON structure alike (`base_knowledge_source.py:43-48`). langgraph's JSON-path pseudo-chunking is elegant for structured values but offers no length-aware splitting for long text (`embed.py:333-396` handles paths, not size). Delegation (agent-framework, pydantic-ai) removes the problem from the repo and the quality control with it.

## Decision Guide

- **Building a hosted service holding user documents?** Follow letta: SQL as source of truth with vector mirrors, structural provenance columns, hybrid retrieval with rank fusion, labeled fallbacks, and failure-isolation tests between primary and secondary stores.
- **Building a library?** Follow langgraph/pydantic-ai: expose a small operation interface (`get/put/search`), normalize embedding providers behind one seam, gate optional capabilities loudly, and document indexing strategy rather than prescribing it. Do not half-own a second stack (crewai lesson).
- **Building a multi-provider framework?** Standardize on a narrow seam — agent-framework's before/after hooks or pydantic-ai's typed message parts — so per-provider implementations converge on shared contracts instead of diverging behaviors.
- **Frontend or boundary repo?** Delegate retrieval semantics cleanly, then invest in observability of delegation outcomes: openhands' condensation hook verifies token drop rather than trusting HTTP ack (`use-await-context-compaction.ts:96-110`) — copy that; its silent skills-fetch catch (`skills-service.ts:58-63`) — avoid that.
- **Episodic agent memory vs document RAG?** For episodic memory, prefer write-time LLM extraction with raw-transcript retention (agent-framework, crewai, letta all converge here). For documents, prefer structural provenance + type-aware chunking (letta) if you control ingestion; if you don't, delegate to managed retrieval (pydantic-ai `FileSearchTool`, agent-framework hosted vector stores) and accept externalized quality control.
- **Choosing staleness policy?** Conversational/episodic → consolidation with failure-freezing windows. Factual corpora → TTL/expiry. Never LLM-directed hard deletes without tombstones.

## Practical Tips

Patterns to copy:

1. Attach provenance at index time as schema, not convention (P2). CrewAI's knowledge gap is unrecoverable retroactively; Letta's passage schema costs a few columns.
2. Label degraded modes in result metadata (`sql_fallback`, search_mode) so callers/tests can distinguish absence from breakage (P3).
3. Gate unsupported capabilities with raised errors when the user asked for them (P7).
4. Detect embedder/model drift with actionable errors naming remediation (P8); crewai's error taxonomy including the deliberate `ValueError` subclassing is worth reading.
5. Keep a lexical fallback path — it saved debuggability for every source that kept one and is the backbone of letta's hybrid.
6. Shape empty results as feedback ("no matching tools") so models don't burn retries on identical queries (pydantic-ai, `toolsets/_tool_search.py:508-521`).
7. Test failure isolation explicitly between primary and fallback stores (letta's `test_turbopuffer_failure_does_not_break_postgres`).
8. Filter tool-role and prior-search messages out of search results to prevent recursive contamination (letta, `core_tool_executor.py:151-165`).

Patterns to delay until needed:

- Cross-encoder reranking: no source operates one on an active path; add score thresholds and eval metrics first, rerankers only when measured misses justify the latency/cost.
- Adaptive LLM-orchestrated recall (crewai-style): powerful but adds latency, cost, recursion hazards, and prompt-bounded scope selection (capped at 20 candidates, `recall_flow.py:264`); start with direct search plus composite scoring.
- Write-local/sync-central sharding (crewai Qdrant Edge): multi-process sophistication justified only at real concurrency.

Decision rules of thumb:

- If you cannot name where a piece of retrieved content originated, do not inject it (crewai knowledge today fails this test).
- If a fallback cannot be labeled, it should fail loudly instead.
- If scoping depends on string formatting conventions, add a validation test before adding features.
- If your store bakes embedding dimensions into DDL, plan the migration story before the first model change, not after (langgraph's unmigrated gap).

Caution signs that the memory/retrieval design is going brittle appear in the next section.

## Anti-Patterns / Caution Signs

- **Two stacks for memory vs documents without a shared interface.** crewai's `memory/` and `knowledge/` directories duplicate vector-store integrations while the knowledge stack lacks memory's provenance, scoring, and consolidation. If you notice parallel retrieval stacks drifting apart, unify behind one protocol before adding features.

- **agent-framework (7):** Broadest family coverage via one hook contract; strongest scoping discipline (Mem0 split scopes, ANDed .NET equality filters, traversal-rejecting storage roots) and richest citation typing (reranker scores, sensitivity labels). - **crewai (7):** Most ambitious read/write intelligence (adaptive-depth recall, evidence-gap tracking propagated onto matches, temporal hints parsed to cutoffs) and good operational hygiene (locks, retries, drain barriers, drift detection with actionable errors). The Knowledge stack undermines the whole: naive chunking, discarded provenance, space-joined multi-query mangling, silent `[]` returns, irreversible consolidation deletes.
- **langgraph (7):** Cleanest primitive design — small op interface, opt-in semantic layer, capability flags, segment-correct namespace matching, TTL done properly, op batching with dedupe. Weak wherever quality lives: no thresholds/rerank/hybrid, ANN unusable under filters in Postgres, DDL-baked dimensions, cross-backend score drift including one apparent SQLite bug, offset pagination unstable under writes.
- **letta (8):** The reference implementation for product-grade retrieval: four corpora, hybrid-by-default with RRF, structural provenance plus ranking-metadata honesty, defense-in-depth scoping, layered fallback chains, cached query embeddings, failure-isolation and RRF unit tests. Gaps are specific rather than structural: no cross-encoder off Pinecone, SQL-path weaknesses (post-LIMIT tag filters, unscored substring fallback), soft-delete enforcement lag, fixed hot-path query embedding overriding agent configs.
- **openhands (3):** Score reflects the repo boundary, not engineering negligence — semantic retrieval provably lives elsewhere (verified negative searches for any vector/RAG dependency). Risks are opacity (users can't see what was condensed away) and silent corpus degradation (skills fetch swallowed).
- **pydantic-ai (7):** Deepest engineering on the narrowest surface: typed discovery parts surviving serialization/provider-replay/compaction, provider-adaptive strategy lattice with explicit commitment semantics, undiscovered-first ranking, cache-aware wire stability, OTel-instrumented embeddings with cost, and the cohort's only retrieval-quality eval. Document RAG is intentionally absent — the framework hardens everything except the classic-RAG center of this dimension, leaving those safeguards unrealizable for apps that follow its guidance.
