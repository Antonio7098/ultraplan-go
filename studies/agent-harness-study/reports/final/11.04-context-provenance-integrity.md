## Executive Summary

Across nine sources, **source attribution is the most mature provenance capability** — every system can answer "where did this come from" at some level of abstraction, from openhands' universal `id`/`timestamp`/`source` event envelope (`sources/openhands/src/types/agent-server/core/base/event.ts:10-25`) to opa's signed bundle manifests persisted in the store (`v1/bundle/store.go:44-51`). **Freshness is tracked mechanically but consumed semantically almost nowhere**: pydantic-ai stamps timestamps on every message part yet acts on none of them for TTL or staleness (`pydantic_ai_slim/pydantic_ai/messages.py:191`), and langfuse is the only source with a deliberate two-clock model separating client event time from server ingest time (`packages/shared/clickhouse/migrations/unclustered/0039_create_events_full.up.sql:95-98,112`). **Trust level as graded item metadata does not exist in any of the nine sources** — every repo-wide search for trust/authority annotations came back empty; trust is instead enforced as a boundary property: pydantic-ai's `sanitize_messages` channel model (`pydantic_ai_slim/pydantic_ai/messages.py:2953`), langgraph's deserialization allowlists (`libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:85-95`), opa's binary bundle signing (`v1/bundle/verify.go:199-207`). **Transformation traceability splits along ownership lines**: framework-owned transformations (compaction, masking, serialization) are frequently recorded — bidirectional summary↔source lineage in agent-framework Python (`python/packages/core/agent_framework/_compaction.py:1373-1392`), `erased`/`masked` path lists in opa decision logs (`v1/plugins/logs/mask.go:178,197`) — while user- or LLM-owned transformations are routinely unlogged, and crewai's consolidation pipeline actively *destroys* existing provenance on merged records (`sources/crewai/lib/crewai/src/crewai/memory/encoding_flow.py:461-471`).

Ratings cluster at 5–7 out of 10: no source reaches the 9–10 "proven under failure or scale" band for this dimension, because each has at least one structural hole — a context channel without provenance (crewai knowledge, opa Data API writes, langfuse legacy tables), a silent degradation path (langgraph blocked revival returning `None`, `libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py:645-653`), or provenance stripped exactly where the model would need it (letta's `archival_memory_search` omitting `file_id`/`source_id` that exist on the stored row, `letta/services/agent_manager.py:2651`).

## Core Thesis

Context provenance across these systems converges on one architectural law: **provenance survives only when it is part of the data's identity, not an annotation beside it**. Where `id`/`timestamp`/`source` are required wire-format members validated at ingress (openhands type-guards, `sources/openhands/src/types/agent-server/type-guards.ts:45-62`), or typed schema fields round-tripped by explicit storage mappers (crewai `_record_to_row`/`_row_to_record`, `lancedb_storage.py:247-287`; pydantic-ai's single `ModelMessagesTypeAdapter`, `messages.py:2768`), provenance is durable and testable. Where it rides in free-form side-channels — `AdditionalProperties` dictionaries in agent-framework (`AgentRequestMessageSourceAttribution.cs:22`) — durability becomes unverified convention; the report explicitly could not confirm .NET attribution survives JSON serialization of `AdditionalProperties`. And where provenance exists richly at rest but not in transit (letta) or strongly at one abstraction layer but not below (langgraph checkpoints vs store items; opa bundles vs Data API writes), downstream consumers inherit blind spots precisely because the provenance was never *of* the thing being consumed.

The second half of the thesis: **trust cannot be bolted onto context after the fact, so systems that lack item-level trust converge on boundary enforcement** — but boundary enforcement leaves the merged context window itself undifferentiated, meaning neither the model nor downstream middleware can treat a retrieved RAG fragment differently from user text once everything is concatenated (explicitly noted for agent-framework, and visible by absence in all nine sources).

## Approach Models

Clustering the nine reports yields four distinct models for *where provenance lives*, plus one shared model for *how trust is handled*.

### Model A — Wire-native universal envelope

Every context unit extends one provenance-bearing base, and the envelope *is* the serialization format.

- **openhands**: `BaseEvent` requires `id`, ISO `timestamp`, and `source: SourceType` from a closed union `"agent" | "user" | "environment" | "hook"` (`sources/openhands/src/types/agent-server/core/base/event.ts:10-25`; `common.ts:55-56`); runtime guards re-validate membership before anything enters app state (`type-guards.ts:45-62`).
- **pydantic-ai** is the closest library-side cousin: provenance lives inside a discriminated part hierarchy so origin/timestamp/outcome fields are validated and serialized *with* the content (`pydantic_ai_slim/pydantic_ai/messages.py:2470,:2520`).

This model makes invalid provenance a hard ingress error rather than degraded data — openhands drops events failing validation entirely (`conversation-websocket-context.tsx:779`), which protects integrity at the cost of silent failure (see Anti-Patterns).

### Model B — Granularity-scoped provenance

Provenance is first-class at one chosen level of abstraction and thin below it.

- **langgraph**: checkpoints carry machine-set `source ∈ {input, loop, update, fork}`, step counters, parent lineage, run id, and ISO timestamps (`libs/checkpoint/langgraph/checkpoint/base/__init__.py:38-48,:56-60,:102-103`), set mechanically at exactly four call sites (`libs/langgraph/langgraph/pregel/_loop.py:718,:1033`; `main.py:1733`); store items get timestamps + TTL but no writer field (`store/base/__init__.py:51-115,:526-534`).
- **opa**: bundles self-describe via manifest `revision`/`metadata`/`roots` (`v1/bundle/bundle.go:147-165`) persisted transactionally with activation (`v1/bundle/store.go:44-75`), while documents written through the Data API are stored bare with no origin whatsoever (`v1/server/server.go:1958-2012`).

Both chose the unit that matches their recovery/debugging use case — time-travel debugging for langgraph, policy-version auditing for opa — accepting that finer-grained questions ("which run wrote this store item?", "who patched this data value?") go unanswered.

### Model C — Product/database-grade provenance

Provenance becomes persistent schema with retention lifecycle, queryable columns, and migration discipline.

- **langfuse**: ingestion attribution (API key + SDK name/version) computed once at the auth boundary and threaded through queues into dedicated ClickHouse columns (`ingestionAttribution.ts:188-203`; migration `0035_add_ingestion_attribution_columns.up.sql:1-8`), plus a full instrumentation block on the v4 events table (`0039_create_events_full.up.sql:82-90`).
- **letta** at rest: ORM mixins attach scope/origin FKs uniformly (`OrganizationMixin`, `FileMixin`, `SourceMixin`, `letta/orm/mixins.py:43-56`); DB-level `created_at`/`updated_at` on every row (`letta/orm/base.py:16-17`).

### Model D — Side-channel / per-subsystem pragmatic attribution

Attribution attaches to existing objects via extension dictionaries or subsystem-specific records, trading guarantees for compatibility.

- **agent-framework**: `(SourceType, SourceId)` structs/dicts under reserved keys in `AdditionalProperties` in both languages (`AgentRequestMessageSourceAttribution.cs:22`; python `_sessions.py:692-694`), stamped centrally by pipeline hooks and immediately consumed by default filters (`AIContextProvider.cs:45`; `ChatHistoryProvider.cs:54`).
- **openai-agents-sdk**: origin lives on items describing the producing mechanism — `RunItemBase.agent`, `ToolOrigin` naming MCP server or parent agent (`src/agents/items.py:97-100`; `tool.py:285-300`) — with nothing describing external content sources.
- **crewai** is a split case within one codebase: typed provenance fields on `MemoryRecord` (`memory/types.py:60-73`) versus deliberately bare-string knowledge chunks (`knowledge_storage.py:118`).

### The shared trust model — boundary enforcement instead of labels

No source annotates items with graded trust. Instead:

- **Channel trust**: pydantic-ai treats server-held history as trusted and client-supplied history as hostile input filtered by `sanitize_messages`, documented as a stated design boundary including why signing is out of scope (`docs/message-history.md:404-417`).
- **Revival trust**: langgraph assumes all persisted bytes are hostile and constrains what can be deserialized (allowlists, strict mode, audit events, `jsonplus.py:85-95,:559-609`).
- **Artifact trust**: opa verifies JWS signatures with scoped keys and per-file hashes, failing closed when a bundle declares signatures but config lacks keys (`verify.go:199-207,:212-262`; `bundle.go:902-908`).
- **Structural trust**: openai-agents-sdk authenticates *types* rather than values — sandbox mounts must be exact SDK classes from closed tables, custom subclasses cannot promote themselves (`sandbox/_mount_security.py:146-257,:1337-1370`).
- **Governed trust**: agent-framework delegates policy to Purview middleware evaluating sensitivity labels out-of-band (`purview/.../_models.py:154-170,415-446`).

The consequence, stated most explicitly in the agent-framework report: once context merges into the window, nothing distinguishes verified from unverified origins *inside* the data.

## Pattern Catalog

### P1. Exclusion-not-deletion with machine-readable reasons

- **Problem**: compaction/redaction must shrink context without destroying the audit trail of what was removed and why.
- **Demonstrated by**: agent-framework writes `_excluded` + `_exclude_reason` with enumerated reasons (`truncation`, `sliding_window`, `summarized`, …) (`_compaction.py:33-34,:718-724,:866,:912,:965,:1062,:1458`); openhands' `CondensationEvent.forgotten_event_ids` + optional summary (`condensation-event.ts:13-26`); opa appends every mask op to `event.Erased`/`event.Masked` with paths (`mask.go:178,:197`); letta embeds `compaction_stats` counts into live context (`system.py:207-236`; `compact.py:415-430`).
- **Why it works**: the transformed record remains queryable; consumers can reconstruct what the model no longer sees, and tests can pin reason distributions.
- **Copy when**: any destructive transformation touches context that will be persisted.
- **Overkill/risky when**: hot paths transform ephemeral scratch context — the write cost buys nothing if nothing ever replays it.
- **Evidence quality**: four independent implementations; agent-framework additionally keeps excluded messages in storage specifically so annotations survive (`_compaction.py:1619-1621`).

### P2. Raw archive plus back-pointer for forensic replay

- **Problem**: derived rows lose information; you need the pre-transformation truth somewhere durable but separate.
- **Demonstrated by**: langfuse uploads raw event arrays to blob storage before transformation and stores `blob_storage_file_path` on each derived row (`processEventBatch.ts:279-292`; `IngestionService/index.ts:457`); openai-agents-sdk keeps raw rollout files alongside derived summaries with cross-referencing headers (`manager.py:191-213,:351-365`).
- **Why it works**: enables replay after failures (langfuse references a replay script at `otelIngestionQueue.ts:529-532`) and manual reconstruction of derivation chains, without polluting live records.
- **Copy when**: transformations are lossy or LLM-mediated and the input may need re-processing.
- **Overkill when**: inputs are trivially reproducible or already immutable upstream.
- **Evidence quality**: strongest in langfuse, where archive-before-transform is architecturally mandatory (blocking S3 upload before queueing).

### P3. Provided-vs-derived duality

- **Problem**: enrichment overwrites client claims, destroying the original data and any ability to audit the enricher.
- **Demonstrated by**: langfuse keeps `provided_usage_details` alongside `usage_details`, `provided_model_name` alongside resolved ids (`0039_create_events_full.up.sql:35-44`); pydantic-ai's `fill_run_metadata` fills only unset fields so producer-supplied provenance wins (`_utils.py:560-569`), and `ModelRequest.timestamp` defaults to `None` specifically to avoid minting fake freshness for old history (`messages.py:1840-1843`).
- **Why it works**: separation makes every computation auditable against its input claim.
- **Copy when**: any pipeline normalizes, computes, or infers metadata from user-supplied values.
- **Overkill when**: there is genuinely no producer claim to preserve.
- **Contrast case**: crewai dict-merges caller metadata with LLM-extracted metadata with silent overwrite semantics (`encoding_flow.py:330-337`).

### P4. Identity-encoded freshness and integrity

- **Problem**: timestamps can be fabricated, mis-sorted, or lost; ordering must be verifiable.
- **Demonstrated by**: langgraph checkpoint IDs are uuid6 whose embedded timestamp is strictly increasing, making sort order equal time order without parsing `ts` (`base/id.py:92-98`); pydantic-ai derives stable SHA1 identifiers from content bytes (`messages.py:209,:289`); langfuse media IDs derive from SHA-256 hashes with loud collision failures (`mediaService.ts:17-22,:99-103`).
- **Why it works**: identity cannot be backdated the way a timestamp field can; monotonic IDs make lineage walks cheap.
- **Copy when**: ordering or dedup correctness matters more than human-readable times.
- **Risky when**: clock guarantees cross process boundaries — uuid6 monotonicity holds within a process only.
- **Evidence quality**: three independent mechanisms aimed at the same invariant.

### P5. Self-verifying transformation stamps

- **Problem**: after transformation, how do you know the artifact in front of you was produced by *your own* trusted transformer?
- **Demonstrated by**: pydantic-ai's `STANDING_PROMPT_PLANTED_KEY` — only framework-minted compaction parts skip re-sending the system prompt; externally supplied look-alikes get the prompt re-inserted (`messages.py:1979-1985`; applied at `models/__init__.py:2100-2125`); openai-agents-sdk records a `__openai_agents_redacted_mount_authority: True` marker that blocks resume until rebind from a trusted manifest (`sandbox_session_state.py:349-399,:337-347`); langfuse strips the `langfuse-*` environment prefix from public input so internal evaluator traces cannot be impersonated (`types.ts:228-246`).
- **Why it works**: the marker's presence is meaningful only because the writing path is controlled, converting trust questions into checkable facts.
- **Copy when**: transformed artifacts will be re-ingested through paths that accept untrusted copies of similar artifacts.
- **Overkill when**: artifacts never cross a trust boundary.

### P6. Canonical log versus derived view

- **Problem**: presentation-layer transformations (merging deltas, replacing actions with observations) would otherwise corrupt the historical record.
- **Demonstrated by**: openhands keeps raw `events` separate from a rebuilt `uiEvents` projection (`use-event-store.ts:92-128`); langgraph's `DeltaChannel` persists full write history and deterministically replays it under a reducer associativity contract (`channels/delta.py:25-63,:139-157`); letta offers git-backed memory with PostgreSQL as cache (`block_manager_git.py:1-50`).
- **Why it works**: views can be discarded and recomputed; the provenance-bearing record is never destroyed.
- **Copy when**: UIs or aggregations derive structure from an append-only stream.
- **Cost**: langgraph's report warns naive pruning severs delta reconstruction chains silently (`checkpoint/base/__init__.py:374-415`).

### P7. Pipeline-stamped, consumer-enforced attribution

- **Problem**: ad-hoc tagging by callers produces sparse, inconsistent coverage.
- **Demonstrated by**: agent-framework stamps attribution centrally in `InvokingCoreAsync` overrides (`AIContextProvider.cs:174-176`; `ChatHistoryProvider.cs:151`) and then *acts on it*: default filters admit only `External` messages as provider input (`AIContextProvider.cs:45`) and exclude `ChatHistory`-tagged messages from reload (`ChatHistoryProvider.cs:54`) — provenance prevents echo loops; langgraph sets `source` at exactly four mechanical call sites (`_loop.py:718,:971,:1033`; `main.py:1733`); openhands narrows `source` literals per event family (`observation-event.ts:9-13`).
- **Why it works**: mechanical stamping at choke points gives coverage; operational consumption gives the stamping a reason to stay correct.
- **Copy when**: introducing any new provenance field — pair the writer with at least one reader, ideally a filter.
- **Evidence quality**: agent-framework is the clearest demonstration that provenance can be load-bearing rather than informational.

### P8. Serialization honesty

- **Problem**: silent fidelity loss during persist/resume masquerades as correct round-tripping.
- **Demonstrated by**: openai-agents-sdk's `context_meta` records `serialized_via`, `requires_deserializer`, `omitted`, storing the original class path "for reference only; never auto-import it for safety" (`run_state.py:2321-2340,:2336-2339`), backed by a schema version with an assertion-enforced changelog (`run_state.py:179-231`); pydantic-ai declares lossy UI adapters as lossy by design (`docs/message-history.md:369-379`) and preserves malformed tool args verbatim under an `INVALID_JSON` wrapper (`messages.py:35,:2225`).
- **Why it works**: fail-loud beats fail-wrong; restoration requires acknowledgment instead of yielding a mapping-shaped impostor of the original context.
- **Copy when**: serializing objects whose types you do not control end-to-end.

### P9. Deliberately surfaced provenance for the model

- **Problem**: the model itself often needs to know origin/freshness, but transports strip metadata.
- **Demonstrated by**: letta formats search hits with `{timestamp, time_ago, role, relevance}` in tool results and supports date-range filters (`core_tool_executor.py:176-232,:81-90`); openhands renders `SecurityRisk` warnings next to commands and gates confirmation buttons on risk level (`bash.tsx:24-37`; `conversation-confirmation-buttons.tsx:102-118`); letta injects a typed JSON `system_alert` carrying compaction stats directly into context (`system.py:207-236`); openai-agents-sdk enforces provenance through strict prompt contracts requiring `rollout_id`/`updated_at` annotations in generated memories (`memory_consolidation_prompt.md:291-305`).
- **Why it works**: treats the prompt as a deliberate projection channel for provenance, designed per-tool, instead of hoping transport preserves it.
- **Cost**: token overhead per hit; openhands' risk values remain self-reported by the same LLM being policed (`action-event.ts:42-61`).

## Key Differences

- **Granularity choice tracks product shape.** opa's context *is* a versioned artifact, so provenance lives on bundles and decisions reference revisions (`?provenance=true` assembled from store-persisted revisions, `server.go:2766-2787`). LangGraph's core use case is time-travel debugging, so checkpoints are provenance-rich while individual channel values are anonymous. openhands' product is an auditable conversation transcript, so every wire event carries the envelope. None of these differences is a quality ranking — they answer different questions.
- **Freshness semantics range from two-clock rigor to near-absence.** langfuse separates client event time (mandatory envelope `timestamp`, version vector for merges) from server time (preserved `created_at`, `index.ts:834-835`) with out-of-order mitigation machinery (`processEventBatch.ts:66-92`). pydantic-ai stamps comprehensively but consumes nothing (`ModelResponse.timestamp` documents local-receipt vs provider time at `messages.py:2559`). agent-framework has a response-level string with an unresolved TODO (`CreatedAtT = str`, `_types.py:318`) and no per-item timestamps at all.
- **Transformation logging follows ownership.** Where the framework performs the transformation, logs exist: agent-framework's bidirectional summary↔source lineage (`_summary_of_message_ids` + `_summarized_by_summary_id` backlinks, `_compaction.py:1373-1392`) versus its own .NET side which records only an exclude-reason string and `_is_summary` flag (`SummarizationCompactionStrategy.cs:210-218`). Where users perform it, logging vanishes: pydantic-ai history processors replace history wholesale with no ledger (`_history_processor.py:17-26`), and openai-agents-sdk truncates everything before a bare `CompactionItem` with no record of what was removed (`compaction.py:210-225`).
- **Serialization survival strategy differs structurally.** openhands validates provenance at the ingress firewall; pydantic-ai funnels everything through one canonical TypeAdapter with dedicated round-trip tests (`tests/test_messages.py:910`); opa mirrors manifest changes across proto + JSON Schema with a "never reuse a proto field number" rule (`bundle.go:145-146`); agent-framework relies on dictionary keys whose JSON persistence is unverified on .NET; letta actively regenerates identities on import (`marshmallow_block.py:17-33`).
- **Trust posture splits between detection and assumption.** opa detects declared signatures and fails closed only then (`bundle.go:902-908`) — an unsigned bundle activates silently. langfuse's masking defaults fail-open unless operators opt into fail-closed (`applyIngestionMasking.ts:210-215`). pydantic-ai openly documents that fabricated-but-coherent history is honored (`docs/message-history.md:406-417`). These are availability-over-confidentiality choices made consciously, not oversights.
- **Whether provenance reaches the model is a fork in the road.** letta strips identifiers at provider conversion (`message.py:1396-1402`) but surfaces timestamps through retrieval tools; openhands puts trust text directly into chat UI and transcripts; agent-framework keeps everything transport-level. Both letta and openai-agents-sdk reports independently identify "origin stripped exactly at the model boundary" as the decisive weakness of their respective designs.

## Tradeoffs

- **Side-channel flexibility vs type safety.** agent-framework gains custom source types and a stable core contract by living in `additional_properties` (`_sessions.py:692-694`), but nothing stops downstream code from stripping `_attribution` keys — correctness rests on convention and tests (`test_sessions.py:94-180`). Alternative seen in crewai/letta: typed schema fields, enforceable and automatically serialized, but requiring migrations for evolution.
- **Snapshot-granular cheapness vs per-item answerability.** langgraph keeps hot-path writes cheap with checkpoint-only provenance (`checkpoint/base/__init__.py:38-124`), at the cost that a store-item consumer cannot answer "which run produced this?" — the report proposes an optional writer field as the fix. opa pays the same price for Data API writes (`server.go:1958-2012`).
- **Persistence of exclusions vs storage growth.** Keeping excluded/summarized messages forever preserves lineage (agent-framework `_compaction.py:1619-1621`; openhands canonical log) but inflates stores indefinitely; agent-framework found no eviction/TTL mechanism, and langgraph warns pruning can sever DeltaChain reconstruction (`checkpoint/base/__init__.py:374-415`).
- **Durability vs latency.** langfuse blocks ingestion on S3 upload of raw payloads for replayability (`processEventBatch.ts:279-332`); openhands refuses partial transcript exports unless completeness is provable (`load-complete-events.ts:100-119`). Alternatives (fire-and-forget, best-effort exports) appear nowhere among the higher-rated sources.
- **Strict ingress validation vs forward compatibility.** openhands drops events whose `source` falls outside today's union — protective today, silently discarding tomorrow's new kinds; the same report notes the exporter takes the opposite tack, skipping malformed entries (`transcript-export/index.ts:488-491`).
- **Warn-and-degrade vs fail-closed revival.** langgraph returns raw dicts or `None` on blocked revival to maximize resumption odds after code changes (`jsonplus.py:645-653,:691-710`), with opt-in strict mode as the alternative; the cost is degraded context indistinguishable from legitimately empty context.
- **Token economy vs model-visible provenance.** Including `file_id`/timestamps/trust in every tool result inflates prompts (letta chose compactness at `agent_manager.py:2651`); the alternative — structured tool-result channels like letta's `time_ago` hits — costs tokens but lets the model reason about age and cite origins.

## Decision Guide

- **Pick the provenance unit from the recovery question you must answer.** If you debug by rewinding execution (→ checkpoint/snapshot granularity, langgraph). If you audit policy versions behind decisions (→ artifact/bundle granularity, opa). If you reconstruct conversations forensically (→ per-event envelopes, openhands). If you filter/redact by origin at recall time (→ item-level fields, crewai memory style) — and then budget enforcement tests, which crewai notably lacks (`tests/memory/test_qdrant_edge_storage.py:274` is the sole placeholder hit).
- **If consumers will act on provenance, give it a reader, not just a writer.** Copy agent-framework's pattern: a default filter that consumes attribution (`AIContextProvider.cs:45`) justifies the field's existence. Unconsumed provenance fields rot — see crewai's unused `metadata` slot on knowledge sources (`base_knowledge_source.py:28`).
- **Choose boundary-trust over label-trust until you have a concrete consumer of labels.** All nine sources reached this conclusion; a graded enum with no enforcement point adds schema weight without behavior. If you do introduce labels, give them a natural producer first (agent-framework suggests wiring Purview `label_id` flow as producer, `purview/.../_models.py:427-446`).
- **Make provenance survive your real serialization path, and test that path.** Prefer schema/wire-native fields (openhands, pydantic-ai, crewai mappers) over dictionary conventions (agent-framework's unverified .NET JSON story). One canonical serializer defining what survives beats several lossy ones pretending fidelity.
- **Separate clocks if late/out-of-order arrival is possible.** Event-time vs ingest-time (langfuse) avoids both false freshness and wrong merge ordering; at minimum preserve creation time across updates — the InMemoryStore reset (`store/memory/__init__.py:404-416`) and crewai consolidation defect show this invariant is easy to break and expensive to notice.
- **Never fabricate missing provenance.** Default missing timestamps to null-with-marker, not `utcnow()` (crewai's fallback masks corruption as freshness, `lancedb_storage.py:265-271`) and not load-time (which pydantic-ai explicitly avoided, `messages.py:1840-1843`).

## Practical Tips

- **Stamp mechanically at choke points; fill-if-unset.** Centralize writers (pipeline hooks like agent-framework's `InvokingCoreAsync`, or pydantic-ai's `fill_run_metadata`) so coverage doesn't depend on caller diligence, and never overwrite producer-supplied values (`_utils.py:560-569`).
- **Pair every strip/redact with an in-band marker.** opa appends masked paths to the event itself (`mask.go:178,197`); openai-agents-sdk records a durable redaction marker that gates resume (`sandbox_session_state.py:386-390`). Out-of-band-only evidence (metrics/logs) fails forensics — the langfuse masking-invisibility and opa ND-cache-stripping cases both demonstrate this.
- **Keep the raw input next to the derived output.** Blob archive with back-pointer (langfuse) or dual-write rollout+summary headers (openai-agents-sdk `manager.py:191-212`) keeps derivation chains navigable without touching live records.
- **Surface freshness to whoever must act on it — including the model.** Relative-time rendering in retrieval tools (`core_tool_executor.py:176-232`), recency-driven conflict rules in consolidation prompts (`memory_consolidation_prompt.md:320-333`: "fresher validated evidence usually wins").
- **Test both ends of provenance: stamping and consumption.** langgraph pins exact `Counter(metadata["source"])` distributions (`test_pregel.py:1519-1560`); langfuse tests exactly-once drop-telemetry counting across pipelines (`metadataDropped.test.ts:288-505`). CrewAI's missing read-side tests are precisely where its worst defect hid.
- **Record degradation as data, not just logs.** Attach a "degraded"/"revived-as-dict" marker to values that failed revival (langgraph future-work proposal) so downstream nodes can branch on integrity; convert silent event drops into observable signals (openhands improvement proposal for its WS guard).
- **Give provenance schemas an explicit evolution contract.** Assertion-enforced changelogs (openai-agents-sdk `run_state.py:220-231`), proto field-number discipline (opa), backward-compatible deserialization defaults (pydantic-ai legacy-history tolerance, `tests/test_messages.py:900`).

## Anti-Patterns / Caution Signs

- **Provenance destroyed by later writes.** crewai's consolidation rebuilds updated records without `source=`/`private=`, silently converting a private, attributed memory into public anonymous one (`encoding_flow.py:461-471`) — the highest-severity finding in this study. Caution sign: any merge/update code path that constructs replacement objects field-by-field instead of copying provenance first.
- **Silent timestamp fabrication or reset.** `utcnow()` fallbacks for missing timestamps (crewai `lancedb_storage.py:265-271`); `created_at=datetime.now()` on every put destroying creation time (langgraph InMemoryStore `store/memory/__init__.py:410-416` vs Postgres preserving it, `postgres/base.py:404-408`); client-supplied `created_at` accepted unvalidated (letta `passage.py:86` allows backdated provenance). Caution sign: age-based logic behaving differently between dev and production stores.
- **Side-channel fragility.** Reserved dictionary keys that any code can overwrite, with JSON survival unverified (agent-framework `.NET` AdditionalProperties; free-form `metadata:` dicts in letta passages propagated verbatim, `passage_manager.py:173,253`). Caution sign: provenance correctness argued from tests rather than types.
- **Boundary stripping without compensation.** Rich rows, blind tools: `archival_memory_search` omits `file_id`/`source_id` present on the passage row (letta `agent_manager.py:2651`); session read-backs select payload columns only, discarding stored timestamps (openai-agents-sdk `sqlite_session.py:288-323`); knowledge retrieval keeps only `result["content"]` (crewai `knowledge_utils.py:4-12`). Caution sign: "the data is there if you query the DB directly."
- **Out-of-band-only transformation evidence.** Policy drops leaving no tombstone beyond a debug line (opa `plugin.go:772-775`); encoder stripping `nd_builtin_cache` invisibly (`encoder.go:108-131`); masked rows indistinguishable from clean ones (langfuse); compaction truncation unrecoverable in-band (openai-agents-sdk `compaction.py:210-225`). Caution sign: audit conclusions that require correlating metrics with raw archives.
- **Opt-in integrity creating silent-trust defaults.** Unsigned OPA bundles activate without any verification config (`plugin.go:459-471`); langfuse masking fails open unless configured otherwise (`applyIngestionMasking.ts:210-215`); parsed-but-unchecked signature `iat` letting ancient signed bundles stay fresh forever (`bundle.go:122`). Caution sign: security properties that require operator configuration to exist at all.
- **Declarative trust labels.** Omitted score `source` defaults to `"API"` (langfuse `validateAndInflateScore.ts:107`); ANNOTATION self-declaration accepted from any project key; openhands' risk values originate from the same LLM being policed. Caution sign: trust fields writable by the party they describe.
- **Degradation that masquerades as emptiness.** Blocked revival returning `None` (langgraph `jsonplus.py:704-710`); corrupt session rows skipped without count (openai-agents-sdk `sqlite_session.py:303-308`); invalid-but-parseable events dropped with no indication (openhands `conversation-websocket-context.tsx:779`). Caution sign: context that shrinks invisibly across resume.

## Notable Absences

- **No graded per-item trust/authority annotation exists in any source.** Every report's repo-wide search (`trust|authority|credib*`) returned only unrelated hits or sanitization code. The closest approximations are binary or narrow: opa's bundle-level signature gate, openhands' action-only `SecurityRisk` enum (`common.ts:58-64`), letta's `Block.read_only`, crewai's access-control `private` flag — none grade the reliability of arbitrary retrieved content.
- **No freshness consumer.** Timestamps abound; TTL/staleness *decisions* driven by them are essentially confined to langfuse retention jobs (`dataRetentionQueue.ts:11-41`), opa's cache-Control-derived HTTP-cache expiry (`http.go:1109-1123`), langgraph's store TTL subsystem (`store/base/__init__.py:545-575`), and openai-agents-sdk's recency-sorted memory selection. Nothing ages conversational context items out based on recorded time — pydantic-ai states it plainly: freshness "is recorded, not acted upon."
- **No redaction-as-recorded-transformation in agent frameworks.** Redaction appears either as out-of-band masking (langfuse EE callback, no per-record flag) or as telemetry-layer scrubbing (pydantic-ai); no framework logs content-sanitization onto the affected items. opa's decision-log `erased`/`masked` lists are the exception, and they cover log events, not model context.
- **Cross-system provenance propagation is dropped everywhere it was checked.** agent-framework's mem0/Cosmos connectors surface no upstream timestamps into context messages; letta's external vector-store path was unaudited but its in-repo chunker fallback already loses chunker identity (`embedder/openai_embedder.py:204-211`); crewai discards file-to-chunk mappings at save time (`base_file_knowledge_source.py:71-76`).
- **Prompt-borne provenance rules lack validators.** openai-agents-sdk mandates header annotations in consolidation prompts but confirms only selection bookkeeping is tested (`test_memory.py:593,:602`); whether generated `MEMORY.md` files actually retain annotations is enforced by instruction, not schema.

## Per-Source Notes

- **agent-framework (6)**: Strongest consumption story — attribution filters prevent providers re-ingesting injected context (`AIContextProvider.cs:45`); unique `origin_session_ids` cross-session memory provenance documented for governance/audit (`_sessions.py:646-659`); Python compaction lineage is best-in-study, .NET lags it; freshness limited to a TODO-typed response string.
- **crewai (5)**: The cautionary tale. Typed memory provenance doubling as privacy filtering (`unified_memory.py:746-751`) undermined by an auto-save path that never writes `source` and a consolidation defect that erases it; the knowledge/RAG channel — likely the largest context volume — carries nothing.
- **langfuse (7)**: Most operationally mature: two-clock freshness, immutable merge keys protecting identity fields from update (`index.ts:158-207`), raw-blob replay, provided/computed duality. Held back by legacy-vs-v4 table skew and masking invisibility.
- **langgraph (7)**: Freshest thinking on identity — uuid6-encoded ordering, four-value machine-set source taxonomy, serde allowlists treating persisted bytes as hostile. Weakest link: store items and the InMemoryStore/Postgres created_at divergence.
- **letta (6)**: Richest at-rest lineage (passages, messages, block templates, actor-attributed checkpoint history with opt-in git backend) and the study's best model-facing freshness UX; decisive weakness is stripping that lineage at both the retrieval-tool and provider boundaries, plus ID regeneration on export.
- **opa (7)**: Best cryptographic integrity machinery (scoped-key JWS, per-file canonical hashing, pluggable verifiers) and exemplary in-band masking records; Data API writes and unchecked signature `iat` are the holes; provenance exposed at API boundary is thinner than what the store holds (`types.go:236-238`).
- **openai-agents-sdk (6)**: Serialization honesty is the standout — `context_meta`, enforced changelog, redact-then-block credentials. Item layer is provenance-poor by Responses-API wire necessity; sandbox memory shows what the design looks like when freshness is treated as first-class.
- **openhands (7)**: Cleanest universal model — provenance fields are the wire format, runtime-validated, with causal ID linkage (`action_id`, `llm_response_id`) and completeness-proven exports. Trust is narrow (self-reported, actions only), and condensation records arrive unused client-side.
- **pydantic-ai (7)**: Most disciplined library-side model — per-part timestamps avoiding fake-freshness bugs, channel-trust with per-strip warnings, self-verifying compaction stamps. Gap: no structured home for retrieved-content origin outside `Any`-typed metadata, and user history processors are unlogged.

## Open Questions

- Would a coarse application-layer trust enum (`user_authored | tool_return | file_derived | agent_written` — letta's proposed vocabulary) be worth adopting industry-wide given that all nine systems independently declined graded trust, or does channel-boundary trust scale better?
- Is there any architecture where recorded freshness gets *enforced* (age-out, refresh prompting) without someone first shipping a consumer that needs it — and would langfuse-style retention jobs translate from observability platforms to agent runtimes?
- Should provenance reach the model window by default (token cost vs citation/verification ability)? Letta's stripped-provider approach and its own surfaced-through-tools alternative coexist in one codebase; no source resolves the tension.
- Can side-channel attribution (dictionary keys) ever be made durable without schema promotion, given agent-framework's unverified .NET JSON round-trip? A converter guarantee would settle it.
- Do prompt-borne provenance contracts (openai-agents-sdk consolidation rules) hold under adversarial or careless model output, absent structural validation of the emitted artifacts?
- Several reports flagged unverifiable areas: letta's Turbopuffer-backed storage provenance (`tpuf_client.py` unaudited), langfuse experiment-lineage write coverage, langgraph `parents`-map completeness under deep subgraph nesting, and openhands' backend-side risk-analyzer contract. These remain unexamined evidence gaps, not negative findings.
