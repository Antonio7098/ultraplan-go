## Executive Summary

Extension compatibility testing across these ten sources is uniformly **immature as an author-facing capability**, even where internal contract quality is high. Only one source (langgraph) ships a publishable, importable conformance harness authors can run offline; one (openhands) approximates it with host-owned admission validators pinned to live contract fixtures. The other eight define explicit extension interfaces (BaseChatClient, BaseTool, ToolCreate, Model/Session, AbstractCapability, HistoryArchiver, Factory/Plugin, IngestionEvent) and cover them with extensive internal test suites and examples, but require authors to copy internal mocks and re-derive correctness. Stability guarantees are almost entirely **retroactive** — changelogs, upgrade guides, and external policy links — not **preventive** harnesses; automated enforcement exists only for public API surfaces (griffe, buf-breaking, released_api_contract, Package Validation) rather than for plugin/extension semantics.

The shared failure is not lack of effort on contracts — most sources show sophisticated contract design (capability enums, decorator composition, Zod/Fern drift tests, Unimplemented embedding) — but a missing distribution step: no `*.testing` package, no `validate_my_extension()` entry point, no offline fixture library. Langgraph proves the pattern works and is cheap to extract; openhands shows how to make even declarative cross-repo contracts testable without sharing code.

## Core Thesis

**Defining a clean extension interface is necessary but not sufficient for compatibility.** Across sources, durability depends on three separable investments, and most sources stop after the first:

1. **Explicit contract** (ABC/Protocol/Interface, typed schema) — universal (9/10 sources have it).
2. **Internal proof that the host honors the contract** (internal suites, mocks) — universal.
3. **Externalized proof that an author honors the contract** (publishable conformance package, offline fixtures, deterministic examples) — rare (langgraph fully, openhands partially).

Where #3 exists, it changes author workflow from "read docs and guess" to "`pip install harness && pytest` fails with a precise message." Where it does not, upgrades remain fragile: authors discover breakage only in production or via manual `Crew.kickoff()` / `POST /tools` / `makeZodVerifiedAPICall` against a live stack. Stability documentation follows the same split: sources that externalize stability as machine-checkable policy (pydantic-ai griffe allowlist, openai-agents released_api_contract, temporal buf-breaking, agent-framework .NET Package Validation) still scope it to *host surface* rather than *extension behavior*. The result is a systematic gap: extension authors cannot answer "does my implementation satisfy the contract?" without cloning the host repo and its infrastructure.

## Approach Models

Three approach models emerged; every source maps to one primary model, with hybrids noted.

**1. Published Conformance Package — "ship the harness"**
- *Model:* Extension point is reified as a separable package with capability enumeration, auto-detection of implemented methods, per-capability runner, fixture generators, and a structured report (pass/fail/skip). Authors add one dev dependency and call `validate(my_impl)`; CI can gate on `passed_all_base()`.
- *Sources:* **langgraph** is the pure exemplar (`libs/checkpoint-conformance/langgraph/checkpoint/conformance/__init__.py:1` re-exports `validate`/`checkpointer_test`; `capabilities.py:15` Capability enum + `_is_overridden` detection; `validate.py:32` dispatches to `spec/test_put.py:22` etc.; `report.py:24` CapabilityReport). The package is continuously validated in CI (`ci.yml:71`).
- *Why it works:* Turns behavioral contracts (17 put tests, delta-channel migration seams `test_delta_channel_history.py:17`) into executable spec, not prose. Fresh saver per suite + `lifespan` for DB setup (`initializer.py:59`) gives isolation without requiring pytest.
- *Limits:* Expensive to maintain breadth — langgraph covers checkpointer deeply but leaves `BaseStore` (`store/base/__init__.py:708`) and `BaseChannel` (`channels/base.py:19`) uncovered.

**2. Host-Validated Declarative Contracts — "host is the trust boundary"**
- *Model:* Extension definitions live outside the host (another repo, Fern YAML, proto); host bakes them at build and validates every manifest/payload at ingestion with fail-closed, schema-strict admission. Conformance is proven by pinning host derivation to live contract fixtures rather than by asking authors to run a harness locally.
- *Sources:* **openhands** (`manifest-validation.ts:576` `validateSetupEntry` 40 invariants, `interface-validation.ts:709` `validateInterfaceManifest`, `manifest-registry.ts:19` registry gate, `manifest-bundle.ts:68` pack checks, verified against `@openhands/extensions/testing/automations/*.json` fixtures in `automation-setup.test.ts:92` + `manifest-test-data.ts:14` factories, version pinned `package.json:26` `0.18.0`), **langfuse** (`fern/apis/server/definition/ingestion.yml:109` source of truth, `ingestion/types.ts:415` `createAllIngestionSchemas`, `openapi-deprecations.servertest.ts:96` drift test, `deprecations.ts:11` V3_SUNSET_DATE cohesion), **temporal** CHASM half (`library.go:11` `Library`/`Component`, `registry.go:69` Registry validation — name regex, FQN/ID collision, GoType uniqueness — plus `UnimplementedComponent` forward-compat `component.go:54`, and `chasmtest/test_engine.go:30` in-memory Engine fixture).
- *Why it works:* Gives strong production safety even when authors never run tests; hermetic builds (`vite build` snapshots) prevent drift.
- *Limits:* Safety is host-side; author ergonomics remain "read the JSON fixture and copy the factory" — no `npx check-extension ./my-automation` CLI. Coverage is uneven across extension kinds (openhands plugins/MCP have no harness; langfuse webhook contract has no fixtures; temporal archival lacks the Engine-quality fixture).

**3. Internal Suites + Docs-as-Spec — "thorough inside, manual outside"**
- *Model:* Extension point is an explicit typed interface (ABC, Protocol, Pydantic model) with extensive internal unit/integration tests and copious examples/guides. Stability is communicated via changelogs, upgrade guides, and occasionally automated surface diffing — but verification requires the author to replicate internal test patterns manually.
- *Sources:* **agent-framework** (`_clients.py:85` `SupportsChatGetResponse` Protocol + `_clients.py:217` `BaseChatClient` ABC, `conftest.py:108` MockChatClient internal, `samples/02-agents/skills/*` 8 samples, `PACKAGE_STATUS.md:4` lifecycle + `CHANGELOG.md:1` semver + `_feature_stage.py:43` experimental warnings + .NET `CONTRIBUTING.md:77` Package Validation), **crewai** (`tools/base_tool.py:103` `BaseTool` ABC, `tools/base_tool.py:676` `@tool`, `test_base_tool.py:14` 794-line suite, `create-custom-tools.mdx:22` + `publish-custom-tools.mdx:18` guides), **opa** (`plugins/plugins.go:89` `Factory` + `plugins.go:106` `Plugin`, `ast/builtins.go:15` `RegisterBuiltin`, `docs/extensions.md:46` hello + `docs/extensions.md:226` PrintlnLogger plugin), **letta** (`schemas/tool.py:110` `ToolCreate`, `schema_generator.py:15` `validate_google_style_docstring`, `test_tool_schema_parsing.py:91` parametrized schema suites, golden `*.json` fixtures), **openai-agents-sdk** (`models/interface.py:37` `Model`, `memory/session.py:15` `Session` Protocol + `session.py:59` `SessionABC`, `released_api_contract.json:1` + `released_api_contract_policy.json:1` surface freeze, `examples/memory/*.py` 15 examples), **pydantic-ai** (`capabilities/abstract.py:162` `AbstractCapability`, `toolsets/abstract.py:76` `AbstractToolset`, `models/__init__.py:366` `Model`, `griffe` gate `.github/scripts/check_api_compatibility.py:106` + `ci.yml:142`), **temporal** archival/auth half (`archiver/interface.go:44` `HistoryArchiver` + `provider/provider.go:54` `Custom*Factory`, `filestore/history_archiver_test.go:58` per-store suite not abstracted), **langfuse** also fits here for SDK authors outside the Fern boundary.
- *Why it converges:* SDK/library products prioritize host correctness and docs velocity over packaging a test harness; supplying fixtures feels like extra maintenance surface (`agent-framework` notes keeping `MockChatClient` internal avoids supporting a test API).
- *Why it diverges:* Product shape dictates where rigor lands — stateful persistence (langgraph checkpointer) justifies full harness; tool/plugin systems (crewai, opa, agent-framework skills) tolerate docs-as-spec; platform APIs (langfuse) delegate authoring to separate SDK repos where contracts are out of scope.

Clustering before comparing: **Convergence** across all three models is that contracts are explicit and internally tested; divergence is not primarily quality but allocation — teams invest the "publish a harness" effort only where the extension *stores durability-critical state* (langgraph checkpoints, openhands automation manifests, temporal CHASM). For stateless or best-effort extensions (tools, builtin functions, MCP wrappers, LLM middleware), the docs+internal-suite model is judged sufficient, even though it leaves author-side verification manual.

## Pattern Catalog

**P1. Conformance Package as Standalone Distribution**
- *Problem:* Host tests prove host works but do not prove an external implementation satisfies the contract; authors copy mocks and drift.
- *Demonstrated by:* **langgraph** (`checkpoint-conformance/__init__.py:1`, `validate.py:32`, `capabilities.py:15`, `test_utils.py:19`), aspirationally by temporal and openhands gaps (no `archiver/conformance_suite.go`, no `npx check-extension`).
- *Why it works:* Capability enum + `_is_overridden` auto-detection (`capabilities.py:90`) lets partial implementations get a precise `BASE vs FULL` report (`report.py:126`); `RegisteredCheckpointer.create()` per suite guarantees isolation; `lifespan` handles DB setup for expensive backends (postgres example `checkpoint-postgres/tests/test_conformance_delta.py:13`).
- *When to copy:* Any extension point where incorrect persistence, replay, or dedup silently corrupts data (checkpoints, sessions, stores, archivers, queues).
- *When overkill:* Single-method, stateless extensions (simple calculator tool, pure function builtin) where a docstring example + `ValueError` at instantiation suffices; maintaining 40+ behavioral tests for trivial surface creates churn.
- *Evidence:* `libs/checkpoint-conformance/langgraph/checkpoint/conformance/validate.py:45` + `spec/test_put.py:22-411` (17 tests) + `report.py:24-198` + `test_validate_memory.py:11-21` InMemorySaver self-test.

**P2. Capability-Based Test Matrix with Auto-Detection**
- *Problem:* Extensions support optional features; a monolithic suite forces stub implementations or false failures.
- *Demonstrated by:* **langgraph** (`capabilities.py:15` 9 values partitioned `BASE_CAPABILITIES`/`EXTENDED_CAPABILITIES`, `_CAPABILITY_METHOD_MAP`) and **openhands** (optional `createBundle`/`uploads` endpoints `interface-validation.ts:68` for backward compat) and **langfuse** (`createAllIngestionSchemas({isPublic})` `types.ts:415` public vs internal split).
- *Why it works:* `_is_overridden` identity check lets authors add only what they need; `validate(..., skip_capabilities, capabilities)` offers filtering (`README.md:98`), and `detected=False, passed=None` avoids penalizing unimplemented optional surface.
- *When to copy:* Pluggable persistence / protocol adapters where feature flags are common (prune, copy_thread, delete_for_runs, delta_channel_history).
- *Risk:* Identity-check auto-detection is brittle — langgraph maps only `a*` async methods (`capabilities.py:53`), so sync-only savers are untested; subclass calling `super().aput` without override still registers as detected.
- *Evidence:* `libs/checkpoint-conformance/langgraph/checkpoint/conformance/capabilities.py:73-96` + `report.py:126-138` conformance_level + `initializer.py:29` skip_capabilities.

**P3. Host Admission Validator as Executable Contract**
- *Problem:* Extension definitions arrive as data (JSON/YAML) from an untrusted producer; host must reject malformed or malicious manifests without trusting producer types.
- *Demonstrated by:* **openhands** (`validateSetupEntry` `manifest-validation.ts:576` shell metachar, path traversal, trigger collision; `validateInterfaceManifest` `interface-validation.ts:709` exact route match, docs URL prefix, icon allowlist; `manifest-registry.ts:19` first-wins dedup + warn-and-drop), **temporal** (`registry.go:69` regex, FQN/ID collision, GoType uniqueness, visibility alias), **langfuse** (Zod ingestion `types.ts:415`, queue payload `queues.ts:23` enums + `.optional()` rolling-deploy comments).
- *Why it works:* Validation owns trust, not types — `unknown[]` at ingestion (`manifest-sources.ts:19`) plus whole-manifest atomicity (one bad field rejects all) prevents partial-injection; registry catches archetype collisions at startup rather than at runtime.
- *When to copy:* Any cross-repo or user-supplied manifest (skills, automations, archiver configs, store registrations).
- *When to delay:* Single-repo extensions where producer and host ship together; admission overhead duplicates service validation already enforced downstream.
- *Evidence:* `src/manifests/manifest-validation.ts:587-622` + `interface-validation.ts:716-757` + `manifest-registry.ts:32` + `chasm/registry.go:234-284` + `packages/shared/src/server/queues.ts:395-436`.

**P4. Live-Fixture Derivation Parity**
- *Problem:* Host derives request bodies/routes/analytics from manifests; duplication between host and producer drifts silently and surfaces as 422 in production.
- *Demonstrated by:* **openhands** (`automation-setup.test.ts:92` `buildCreatePayload`/`buildPreflightBody`/`buildAssistedMessage` asserted byte-equal to 3 published JSON fixtures `incident-retrospective-drafter.json` etc.; `manifest-bundle.test.ts:77` tar + `config.json` provenance parity), **langfuse** (`openapi-deprecations.servertest.ts:96` OpenAPI `deprecated` set equals `getFernDeprecatedOperations()` set; `fern-deprecations.ts:71` + `stamp-deprecations.ts:29` idempotent generation), **pydantic-ai** (`test_public_interface_contracts.py:40` kw-only dataclass walker, signature parity).
- *Why it works:* Live fixtures turn prose spec into byte-equal contract; drift fails CI, not customers.
- *When to copy:* Any derived payload or generated spec (OpenAPI, queue payload, bundle tar, payload hashing).
- *Risk:* Fixture generation coupling — if fixture generator and host diverge in interpolation semantics (`interpolateValue` vs `interpolateText` in `automation-setup.ts:328`), tests pass locally but service rejects.
- *Evidence:* `__tests__/manifests/automation-setup.test.ts:132-240` + `web/src/__tests__/server/unit/openapi-deprecations.servertest.ts:96-146` + `web/scripts/openapi/stamp-deprecations.ts:64-120`.

**P5. In-Memory Reference Implementation + Lightweight Engine Fixture**
- *Problem:* Extension authors need a fast, cluster-free way to exercise their code against realistic host semantics (poll, conflict, dedup, long-poll).
- *Demonstrated by:* **langgraph** (`memory/__init__.py:33` `InMemorySaver` 626 lines, including optimized `get_delta_channel_history` walk), **temporal** (`chasmtest/test_engine.go:30` `chasmtest.Engine` with reuse/conflict, request-ID dedup `test_engine.go:240`, `PollComponent` blocking `test_engine.go:270`), **pydantic-ai** (`models/test.py:62` `TestModel` + `models/function.py:52` `FunctionModel` + `models/wrapper.py:32` `WrapperModel`), **openai-agents-sdk** (`testing/model.py:249` `ScriptedModel`, `testing/sandbox.py:572` `scripted_sandbox_session`, `voice/testing.py:153` `ScriptedSTTModel`).
- *Why it works:* Reference impl documents idiomatic overrides (delta-channel parent walk fallback `base/__init__.py:582`); lightweight engine reproduces production semantics (business-ID reuse, idempotency) without cluster bring-up (`fx.go:13` example library).
- *When to copy:* Always for stateful extensions; keep the fixture minimal but faithful — temporal's `MockNodeBackend` `test_engine.go:520` drift risk shows over-fidelity cost.
- *When to delay:* Stateless adapters where a single call mock suffices.
- *Evidence:* `libs/checkpoint/langgraph/checkpoint/memory/__init__.py:33-626` + `chasm/chasmtest/test_engine.go:88-329` + `pydantic_ai_slim/pydantic_ai/models/test.py:62` + `src/agents/testing/model.py:249`.

**P6. Dual Contract Layering (ABC + Protocol) with Forward-Compat Escape Hatches**
- *Problem:* Support both subclassing and duck-typing without breaking additive evolution.
- *Demonstrated by:* **agent-framework** (`_clients.py:85` `@runtime_checkable` `SupportsChatGetResponse` Protocol with 3 overloads + `_clients.py:217` `BaseChatClient` ABC with `additional_properties` dict and `Generic[OptionsCoT]`), **openai-agents-sdk** (`memory/session.py:15` `Session` Protocol + `session.py:59` `SessionABC` with `_session_accepts_wrapper` opt-in), **pydantic-ai** (`AbstractCapability`/`AbstractToolset` ABCs), **temporal** (`UnimplementedComponent`/`UnimplementedLibrary` with `mustEmbedUnimplementedLibrary` private method `library.go:25` + `component.go:54`).
- *Why it works:* `additional_properties` and `Unimplemented*` embedding let host add methods/fields without major bump; `@runtime_checkable` enables `isinstance` without inheritance.
- *When to copy:* SDKs with diverse consumers (typed Python + dynamic JS, or Go embedding); requires clear docs on which surface to implement (temporal's `rego.RegisterBuiltin2` vs `rego.Function2` duality confuses).
- *Evidence:* `python/packages/core/agent_framework/_clients.py:85-269` + `src/agents/memory/session.py:155-174` wrapper-opt-in + `chasm/library.go:25-52` Unimplemented trap.

**P7. Automated Surface-Drift Gate (griffe / buf-breaking / released_api_contract / Package Validation)**
- *Problem:* Human-reviewed changelogs miss breaking additions/removals; extension authors need machine-enforced SemVer.
- *Demonstrated by:* **pydantic-ai** (`check_api_compatibility.py:106` griffe `check --against <tag>` + fingerprint allowlist `api-compatibility-allowlist.json:1` + `ci.yml:142`), **openai-agents-sdk** (`test_released_api_contract.py:42` frozen `released_api_contract.json:1` baseline + policy `released_api_contract_policy.json:1` requiring review to change), **temporal** (`Makefile:17` `buf-breaking` + `develop/buf-breaking.sh:63` image vs merge-base for `proto/internal` + `chasm/lib`), **agent-framework** (.NET `CONTRIBUTING.md:77` Package Validation with `PackageValidationBaselineVersion` + `CompatibilitySuppressions.xml`), **langfuse** (`openapi-deprecations.servertest.ts:96` drift gate between Fern and OpenAPI).
- *Why it works:* Makes "is this breaking?" answerable at PR time with annotation (`::error`/`::warning` in `check_api_compatibility.py:71`).
- *Limits:* Gates cover host API surface (protos, exported symbols, OpenAPI) — not extension behavioral semantics (e.g., adding `HistoryArchiver` method is Go-breaking but not proto-breaking; `check_api_compatibility` detects signature break but not `wrap_tool_validate` timing change).
- *Evidence:* `.github/scripts/check_api_compatibility.py:46-71` fingerprint + `tests/test_released_api_contract.py:211` + `Makefile:434-437` + `CONTRIBUTING.md:71-104`.

## Key Differences

**Coverage breadth vs depth** — langgraph invests 40+ behavioral tests in one family (checkpointer put/get/list/delete/prune/delta_history) and leaves sibling families (`BaseStore` `store/base/__init__.py:708`, `BaseChannel` `channels/base.py:19`) uncovered; openhands mirrors this but across two declarative surfaces (setup + interface) while leaving plugins/MCP/skill frontmatter uncovered. Every other source spreads coverage thinly across many extension points (agent-framework: ChatClient + SkillsSource + Middleware + HistoryProvider + MCPTool + Workflow Executor; openai-agents-sdk: Model + Session + TracingProcessor + MCPServer + STT/TTS/VoiceWorkflow; temporal: Archival + CHASM + Auth; opa: Plugin + Builtin + Storage/TargetPlugin; crewai: BaseTool + StructuredTool + Hooks + MCP wrappers) — breadth traded for the inability to publish any single harness.

**Conformance as package vs. conformance as host validation** — langgraph's conformance is a library authors import (`checkpointer_test` decorator + `validate()` + `CapabilityReport.print_report()/to_dict()`); openhands/langfuse/temporal's conformance is code the host runs (`validateSetupEntry`/`validateInterfaceManifest` + `Registry.Register` + Zod schemas). The former gives authors a pre-publish `pytest` gate; the latter gives operators a deploy-time fail-closed gate. Agent-framework, crewai, letta, opa, openai-agents-sdk, pydantic-ai have neither as an author gate, even when they have strong host gates (griffe, buf-breaking, released_api_contract).

**Stability communicated where** — pydantic-ai documents semver explicitly (`version-policy.md:1` no intentional minors break, deprecations survive ≥3 months, beta disclaimer `version-policy.md:22`) and enforces via griffe allowlist; openai-agents-sdk codifies the same in `docs/release.md:1` (`0.Y.Z` where Y = breaking) and a frozen JSON baseline that requires PR review to change (`README.md:48`); agent-framework fragments it across `PACKAGE_STATUS.md:4` lifecycle stages, `_feature_stage.py:43` ExperimentalWarning dedup, .NET Package Validation, and `CHANGELOG.md:1` `[BREAKING]` tags; crewai/letta rely solely on `changelog.mdx:156`/`upgrading-crewai.mdx:94` and implicitly 0.x pre-1.0; OPA relies on `CHANGELOG.md:4` SemVer preamble + `capabilities.json:44` `deprecated:true` + `v0-compatibility.md:8` language shim (not Go API); temporal has no `CHANGELOG.md` at all and relies on `buf-breaking.sh:63` + `go.mod:5` retractions. The divergence reflects product constraints: library SDKs (pydantic-ai, openai-agents-sdk, langgraph) must promise import stability; platform services (langfuse, temporal) must promise wire/queue/proto stability during rolling deploys (`queues.ts:32-40` optional fields); frontend (openhands) must promise build hermeticity via pinned deps (`package.json:26`).

**Example role** — crewai, opa, agent-framework, temporal treat examples as the de facto conformance spec: `publish-custom-tools.mdx:241` `Crew.kickoff()` smoke test, `docs/extensions.md:46` hello builtin plus `docs/extensions.md:226` full PrintlnLogger plugin with YAML, `samples/02-agents/skills/file_based_skill.py:41` plus `docs/decisions/0021-agent-skills-design.md:524` CloudSkillsSource tutorial, `archiver/README.md:86` Option 2 external implementation, `chasm/lib/tests/library.go:24` PayloadStore. Openhands inverts this: examples are factories (`manifest-test-data.ts:14` `createSetupEntry`/`createInterfaceManifest`) and live catalog fixtures (`testing/automations/*.json`) — not tutorials but test data. Pydantic-ai/openai-agents-sdk straddle both: narrative doc snippets (`capabilities/custom.md:7`, `toolsets.md:861`) plus executable `examples/` directories compilation-tested in CI (`ci.yml:477`).

**Fixture fidelity vs maintenance** — temporal's `chasmtest.Engine` (`test_engine.go:30`) is high-fidelity (conflict policies, PollComponent long-poll, time-source injection `test_engine.go:70`) but couples to internal `MockNodeBackend` (`test_engine.go:520`) that can drift from production `service/history/chasm_engine.go`; langgraph's `InMemorySaver` and `build_delta_chain` `_delta_fixtures.py:20` deliberately avoid Pregel to stay minimal and declarative. Pydantic-ai/openai-agents-sdk doubles (`TestModel`/`FunctionModel`/`ScriptedModel`) optimize for runner testing rather than author testing — they snapshot calls and enforce FIFO (`testing/model.py:154` `_snapshot_model_call` + `assert_complete()`) but do not assert extension correctness.

## Tradeoffs

**Depth on one family vs breadth across many.** Langgraph's deep harness gives checkpoint author confidence `report.passed_all_base()` is meaningful, but leaves store/channel/store-implementation authors without any harness. Conversely, agent-framework and openai-agents-sdk expose 5-6 extension points with uniform "ABC + docstring + sample" quality but none reach harness depth. Best-fit depends on durability: persist-critical state (checkpoint, archiver, session) warrants depth; ephemeral adapters (middleware, tool invocation) tolerate breadth. Failure mode of the breadth approach is silent semantic drift (e.g., `RedisSession` watch-conflict retry `redis_session.py:393` indefinitely livelocks, `FileSkillsSource` link checks `test_skills.py:957` silently skip resources, `delete_for_runs` `base/__init__.py:340` silently severs DeltaChannel chain).

**Exporting fixtures reduces author burden but increases host maintenance.** Agent-framework keeps `MockChatClient`/`MockBaseChatClient` (`conftest.py:108`) and `MockAgent` (`conftest.py:75`) internal to avoid supporting a test API; crewai and opa do the same (`testPlugin` `plugins_test.go:186`, `Tester` `runtime/plugins_test.go:20`). Langgraph and temporal accept the cost: `test_utils.py:19` generators + `_delta_fixtures.py:20` delta chain + `chasmtest` package are versioned, documented, and included in CI matrices. When over-copied without discipline, exported fixtures drift — openai-agents-sdk `ScriptedModel` `ModelStep` validation `testing/model.py:641` enforces call-ID invariants for the runner side but does not expose a `validate_my_model` for the author side, creating confusion about "who is tested."

**Pin-and-snapshot hermeticity vs live-fetch availability.** Openhands pins `@openhands/extensions@0.18.0` and snapshots `AUTOMATION_CATALOG` at `vite build` (`manifest-sources.ts:1`), giving reproducible builds and diffable catalog changes, at cost of days-long delay for new extensions and cross-repo coordination. Crewai's workspace pin (`pyproject.toml:265` `crewai-core==1.15.17`) and langfuse's Fern generation do similar inside a monorepo. Live-fetch would make new extensions instantly visible but would require runtime signature/trust and a staleness warning/bubble currently absent (`openhands` notes stale pin silently withholds extensions).

**Changelog/upgrade-guide communication vs machine-enforced gates.** Crewai, OPA, letta, opa rely on human-authored notes (`changelog.mdx:444` "Breaking Changes — None", `CHANGELOG.md:2725` IR evaluator break, `upgrading-crewai.mdx:94` import renames). Pydantic-ai, openai-agents-sdk, temporal automate the gate (griffe fingerprint `check_api_compatibility.py:46`, `released_api_contract` baseline, `buf-breaking.sh:63`) and require allowlist/policy change to land a break. The former is low overhead but nondeterministic for planning; the latter is deterministic but blind to behavioral breaks (signature preserved, semantics changed).

**Inline schema inference (ergonomic) vs explicit schema (verifiable).** Crewai infers `args_schema` from `_run` annotations (`base_tool.py:207` `create_model`) and falls back to `_arun`; letta infers from Google docstrings + types (`schema_generator.py:409`). Ergonomics lower barrier, but hide errors until `run()` and make contracts harder to reason about — inferred narrowing silently drops `*args/**kwargs` (`base_tool.py:227`), and docstring non-compliance fails only at creation (`derive_openai_json_schema` `schema_generator.py:458`). Pydantic-ai/openai-agents-sdk lean explicit via `args_json_schema` / `ModelProfile` TypedDict (`profiles/__init__.py:110`), trading verbosity for checkability.

**Decorator composition (explicit) vs provider builder (implicit).** Agent-framework's `Aggregating/Caching/Filtering/Deduplicating` SkillsSource decorators (`_skills.py:36`) give fine-grained caching control and testability (`_CountingSkillsSource` `test_skills.py:81`) but add boilerplate and risk double-cache/missed-dedup when mixed with `AgentSkillsProviderBuilder` hiding wiring. Wrapper patterns (`WrapperModel` `models/wrapper.py:32`, `WrapperToolset` `toolsets.md:590`, `FilteredToolset`/`PrefixedToolset`) show the same tradeoff — middleware chaining is powerful but requires authors to understand `for_run` isolation.

## Decision Guide

**Choosing an approach**

- If your extension persists state that must survive restarts, replay, or compaction (checkpoint, session, archiver, queue payload): choose **Published Conformance Package** (langgraph model). Partition capabilities into `BASE` vs `EXTENDED`, auto-detect overrides, run fresh instance per capability, and gate CI on `passed_all_base()`. Reference: `capabilities.py:15-96` + `validate.py:32-128` + `report.py:24-198` + `test_utils.py:19-212`.
- If your extension is a declarative manifest/catalog supplied cross-repo or by users: choose **Host Admission Validator + Live Fixtures**. Treat data as `unknown` at ingestion, fail the whole manifest on one bad field, pin the publisher version and snapshot at build, prove derivation parity against byte-equal fixtures. Reference: `manifest-validation.ts:576-622` + `interface-validation.ts:709-757` + `manifest-registry.ts:19-52` + `automation-setup.test.ts:92-240`.
- If your extension is a stateless adapter (tool, function builtin, model provider, middleware): choose **Internal Suites + Docs-as-Spec** as a starting point, but plan to graduate the most critical adapter to a mini harness once duplication of internal mocks exceeds a few copies. Reference: `tools/base_tool.py:103`/`skills/_skills.py:106` internal suites + `examples/` — then extract `assert_tool_conforms` when feasible.
- If your surface is wire/proto (ingestion, OpenAPI, internal proto): choose **Contract-First + Drift Gate** (Fern/Zod + OpenAPI stamp test; buf-breaking). Reference: `fern/apis/server/definition/ingestion.yml:109` + `ingestion/types.ts:415` + `openapi-deprecations.servertest.ts:96` + `Makefile:434-437`/ `develop/buf-breaking.sh:63`.

**When to invest in what**

- Start with explicit typed contracts (ABC/Protocol/Pydantic, `mustEmbedUnimplemented*`) and internal regression tests — all ten sources do this, and it is non-negotiable.
- Add runtime structural validation early (registry name regex/FQN collision checks `registry.go:234-284`, Zod parse at ingestion edge `ingestion/types.ts:844`) — cheap, catches misconfiguration at startup/ingest with clear errors.
- Add drift gates for generated artifacts as soon as you have Fern/proto/OpenAPI/Big-Bundle generation (`stampDeprecations` `stamp-deprecations.ts:29`, `check_api_compatibility.py:106`, `test_released_api_contract.py:42`) — prevents silent downstream break.
- Promote to publishable harness only when external authors build persistence or compatibility-critical adapters. Langgraph waited until `BaseCheckpointSaver` semantics (incremental blobs, parent-chain walks, prune/delete_for_runs hazards `base/__init__.py:387-414`) demanded it; the signal is that internal mocks are being copy-pasted across several implementations (postgres/sqlite/custom saver).

**Decision rules**

- If `n_external_implementations >= 3` or extension state is durable → publish a conformance package under `package-name-conformance` with `capabilities` + `report` + `fixtures`.
- If extension data crosses a repo/process boundary → treat it as untrusted, validate host-side with fail-closed admission and prove derivation parity against live fixtures.
- If only surface stability matters (import paths, dataclass kwargs, TypedDict shapes) → freeze a manifest (`released_api_contract.json:1` / `allowlist.json:1`) and gate PRs with griffe/buf/Package Validation.
- If docs examples already serve as spec → promote golden `*.json` fixtures (`test_tool_schema_parsing_files/simple_d20.json:1`, `testing/automations/*.json`) to a versioned `fixtures/` directory authors can vendor.

## Practical Tips

**Patterns to copy immediately**

- Extract one internal mock per extension point into `pkg.testing` even before a full harness — e.g., `agent_framework.testing.MockChatClient` (`conftest.py:108`), `crewai.testing.make_tool_factory`, `letta.testing.validate_complete_json_schema` (`schema_validator.py:12`), `opa plugintest.FakeManager` (`plugins_test.go:103` logic). Authors who can `pip install pkg[testing]` and run a single assertion derive disproportionate confidence.
- Provide a reference in-memory implementation that demonstrates idiomatic overrides, not just a mock. `InMemorySaver` `memory/__init__.py:33` (including `get_delta_channel_history` optimization `memory/__init__.py:142-223` vs fallback `base/__init__.py:582-690`) and `TestModel` `models/test.py:62` are repeatedly cited as the clearest author guide. Add comments on why destructive ops (`prune` `base/__init__.py:387`, `delete_for_runs` `base/__init__.py:340`, `copy_thread` `base/__init__.py:361`) break delta reconstruction.
- Pin publisher and snapshot at build; validate version first. `package.json:26` exact pin + `manifest-sources.ts:18` build-time snapshot + `manifest-validation.ts:587` `version !== SETUP_VERSION` short-circuit prevents drift; `config/defaults.json:8` `minimumAgentServer` + `agent-server-compatibility.ts:243` semver gate shows how to floor external runtime compatibility.
- Make deprecation machine-readable: `capabilities.json:44` `deprecated:true`, `builtin_metadata.json:578` `deprecated:true`, `V3_SUNSET_DATE` `deprecations.ts:11` plus `attachDeprecation` `deprecations.ts:102` envelope and OpenAPI `deprecated:true` stamping `stamp-deprecations.ts:29` proven by `openapi-deprecations.servertest.ts:112`. Include `replacement` + `docsUrl` + `sunsetAt` in every signal and test that `V3_SUNSET_HUMAN` derives from `V3_SUNSET_DATE` (`openapi-deprecations.servertest.ts:148`).
- Gate public surface automatically: `check_api_compatibility.py:46` fingerprint (`sha256(package\0path\0message)`) + `allowed_breakages: []` `api-compatibility-allowlist.json:1` with `::error`/`::warning` annotations (`check_api_compatibility.py:71`) plus `test_public_interface_contracts.py:102` kw-only / signature parity checks catch accidental breaks before review.

**Patterns to avoid or delay**

- Do not publish a conformance package that only covers one of several peer contracts without documenting exclusions — langgraph's silence on `BaseStore`/`BaseChannel` and temporal's silence on `Authorizer`/`ClaimMapper` create false confidence that "we have conformance" implies all extensions are covered. Scope documentation should list `covered` vs `out-of-scope` per extension point.
- Do not rely on envelope `_deprecation` for array/primitive top-level responses — `deprecations.ts:108` returns body unchanged for arrays; a future array endpoint loses the signal. Prefer header + envelope or wrap `{ data: [], _deprecation }`.
- Do not infer schemas without an explicit opt-in to explicit schema — crewai's `args_schema` auto-generated from `_run` (`base_tool.py:207`) silently narrows `*args/**kwargs`, and letta's Google-docstring rule (`schema_generator.py:15-60`) fails only at runtime. Recommend `args_schema: type[BaseModel]` explicitly (`publish-custom-tools.mdx:88`) or `args_json_schema` path (`schemas/tool.py:48`).
- Do not keep archiver/persistence conformance duplicated per store (`filestore/history_archiver_test.go:58` + `s3store` + `gcloud`) without factoring a shared harness (`common/archiver/archivertest.Suite`) — duplication multiplies maintenance and blocks external stores from importing the suite.

**How to verify your extension today (given current gaps)**

- For tools/plugins/builtins with no harness: instantiate, call `_run`/`run`/`arun` directly, inspect `args_schema.model_json_schema()` (`base_tool.py:160`) and `formatted_description` (`structured_tool.py:127`), wire into minimal host (`Crew.kickoff()` `publish-custom-tools.mdx:241`, `POST /tools` `tool_manager.py:214`, `rego.Rego{}.WithBuiltins(map[string]*Builtin{...})` `topdown/builtins_test.go:15`, `NewQuery` `example_test.go:1057`), and diff your output against golden `*.json` fixtures (`test_tool_schema_parsing_files/simple_d20.json:1`).
- For manifests/ingestion: vendor the published JSON fixtures (`testing/automations/*.json`, `fern/apis/server/definition/ingestion.yml:44` batch examples) and validate with the host's Zod schemas (`types.ts:844` `createIngestionEventSchema()`) offline if exported, otherwise via live `makeZodVerifiedAPICall` against the test server (`traces-api.servertest.ts:246`).
- For checkpointer authors today: copy the pattern even before importing the package — `@checkpointer_test` `initializer.py:59` + `validate(report.print_report(); assert report.passed_all_base())` `test_validate_memory.py:11-21` + `build_delta_chain` `_delta_fixtures.py:20` delta seams, with `ProgressCallbacks.verbose()` `report.py:24`.

**Caution signs the design is becoming brittle**

- Internal mocks are copy-pasted across 3+ implementations or tests start asserting `mockEngine` business-ID reuse semantics (`chasmtest/test_engine.go:130` idempotency) — time to promote `chasmtest.Engine` to a published fixture.
- `CompatibilitySuppressions.xml` deleted after each release with baseline bump (`CONTRIBUTING.md:101`) or `allowlist.json` fingerprints churn on docstring reflow (`check_api_compatibility.py:46`) — signals the gate is tracking text, not semantics; add fuzzy/semantic matching or separate doc vs code gates.
- `warnings.filterwarnings("ignore", message=r"\[SKILLS\].*")` (`conftest.py:19`) or `extra="ignore"` (`schemas/tool.py:209` `ToolUpdate`) hides non-conformance — dead suppressions after experimental promotion or silent unknown-field acceptance mask backward-incompatible field renames.
- `registeredPlugins map[string]Factory` (`runtime.go:68`) global mutation without `ResetRegisteredPlugins` (`plugins.go:45` only for target plugins) forces `WithTempFS`/`subprocess` isolation in tests (`runtime/plugins_test.go:65`) — global registry without test isolation helper is a brittle extension point.
- Changelog lists `[BREAKING — experimental]` frequently (`CHANGELOG.md:58`) on surfaces authors depend on (MCP_SKILLS `PACKAGE_STATUS.md:131`) with no LTS branch — experimental churn is the brittleness signal that warrants pinning to git SHA or avoiding the surface until stable.

## Anti-Patterns / Caution Signs

- **Internal-only doubles as accidental spec.** Keeping `MockChatClient` (`agent-framework conftest.py:108`), `testPlugin` (`opa plugins_test.go:186`), `customHistoryArchiver` (`temporal archival_test.go:78`), `print_tool` fixture (`letta conftest.py:189`) inside `tests/` forces every external implementor to re-derive mocks; drift between implementations is not caught. Export at least one fake per contract.
- **Global registry without isolation helper.** `ast/builtins.go:15` `Builtins, BuiltinMap` mutated by `RegisterBuiltin` at `init()` (not thread-safe), `rego/plugins.go:36` panics on duplicate target, `runtime.RegisterPlugin` mutates `registeredPlugins` map — no `Reset*` for runtime plugins. Authors testing registration need subprocess/build-tag isolation.
- **Sync/async parity gap.** Langgraph conformance maps only `a*` methods (`capabilities.py:53` `PUT -> aput`); openai-agents-sdk `MCPServer` supports both sync and awaitable filters (`server.py:1021`) but has no matrix harness; crewai `_arun` defaults to `NotImplementedError` (`base_tool.py:374`) with no async-capability assertion. Sync-only or async-only implementors pass one side and fail silently on the other.
- **Two-path schema generation without migration test.** Letta's `Tool.args_json_schema` explicit vs docstring-inferred (`tool_schema_generator.py:67`) and crewai's optional `args_schema` vs inferred mimic the same dual path — but only internal `test_derive_openai_json_schema` `test_tool_schema_parsing.py:91` pins the mapping; no test asserts that the two paths produce equivalent schemas for the same tool.
- **Changelog-only breaking-change communication.** Crewai `upgrading-crewai.mdx:94`, OPA `CHANGELOG.md:4`, letta code-comment `# DEPRECATED` `enums.py:221`, temporal absence of `CHANGELOG.md` all rely on authors scanning docs/releases. Without deprecation timeline, `PendingDeprecationWarning`, or codemod guidance (`pydantic-ai version-policy.md:1` ≥3 month window is the positive counter-example), upgrades require manual grep for `deprecated`/`breaking`.
- **In-memory vs disk divergence without contract.** Agent-framework's `MCPSkillsSource` unpacks archives in memory (`_skills.py:50`) vs .NET on disk, openhands host duplicates Python `_render_payload` for derivation, temporal `chasmtest.Engine` maintains its own `MockNodeBackend` — any divergence not pinned by live fixtures fails only in production (422/empty delta state). Contract fixtures (`automation-setup.test.ts:92`, `openapi-deprecations.servertest.ts:96`) are the mitigation; their absence is the smell.
- **Large beta carve-outs with no per-interface tier.** Openai-agents-sdk marks `voice/realtime` `README.md:3` and LiteLLM/AnyLLM `models/index.md:682` as beta/best-effort, pydantic-ai has generic `beta` caveat `version-policy.md:22`, agent-framework experimental IDs `feature_stage.py:43`. Without per-method `@stable`/`@experimental` plus `__stability__` or `stability tier matrix` (`openai-agents-sdk` gap `released_api_contract_policy.json:403` optional_bindings vs `public_class_contracts`), authors cannot tell which `BaseTool` fields or `AbstractCapability` hooks are SemVer-covered.
