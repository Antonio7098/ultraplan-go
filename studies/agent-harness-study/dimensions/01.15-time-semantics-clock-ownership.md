# Dimension 01.15: Time Semantics and Clock Ownership

## Purpose

Study how runtimes define occurrence time, commit time, duration, deadlines, timeout origin, and clock ownership.

## Steps

1. Inventory timestamps, durations, deadlines, and timeout fields.
2. Determine which component records each value.
3. Separate wall-clock display from monotonic duration measurement.
4. Trace deadline and timeout propagation.
5. Inspect fake-clock, boundary, skew, and scheduler-delay tests.

## Evidence to Capture

- Clock access and abstractions
- Event and outcome timestamp fields
- Deadline and timer construction
- Duration calculation
- Time-sensitive tests

## Questions

1. Does time describe occurrence, observation, or commit?
2. Which clock is authoritative?
3. Can wall-clock changes corrupt duration or ordering?
4. Are timeout origin and responsibility visible?
5. Is a clock abstraction earned by concrete test needs?

## Output

Write findings to `reports/source/01.15-time-semantics-clock-ownership/{source-name}.md`
