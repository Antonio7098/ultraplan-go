# Dimension 13.05: Panic, Invariant, and Runtime Fault Boundaries

## Purpose

Study how runtimes distinguish failures in executed work from panics, invariant violations, and defects in the supervising runtime.

## Steps

1. Locate panic, exception, and invariant boundaries.
2. Identify which faults are recovered and which terminate the host.
3. Trace classification, cause preservation, and stack capture.
4. Determine whether runtime trust changes after an invariant violation.
5. Inspect diagnostic, redaction, and fault-injection tests.

## Evidence to Capture

- Recovery and exception boundaries
- Assertion and invariant mechanisms
- Failure origin and kind types
- Stack and cause retention
- Panic, corruption, and containment tests

## Questions

1. Can callers distinguish work failure from a runtime defect?
2. Which panics are safe to convert into run outcomes?
3. Are invariant violations recoverable, fatal, or policy driven?
4. Is enough evidence retained without leaking secrets?
5. Can the runtime continue safely after containment?
