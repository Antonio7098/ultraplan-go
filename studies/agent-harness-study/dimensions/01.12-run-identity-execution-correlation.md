# Dimension 01.12: Run Identity and Execution Correlation

## Purpose

Study how runtimes create, scope, expose, and correlate execution identity without encoding unstable semantics into identifiers.

## Steps

1. Identify when and by whom run IDs are created.
2. Check uniqueness, opacity, caller-supplied identity, and collision handling.
3. Trace parent, child, attempt, session, and external correlation identifiers.
4. Determine whether identity exists before work starts and survives terminal completion.
5. Inspect redaction, serialization, and logging behaviour.

## Evidence to Capture

- ID types and generators
- Creation and validation paths
- Parent-child and attempt linkage
- Event, trace, log, and persistence fields
- Collision, replay, and privacy tests

## Questions

1. Who owns identity generation?
2. Does an ID contain time, type, tenant, or other semantics?
3. Which correlations are identity and which are metadata?
4. Can callers safely supply correlation without controlling canonical identity?
5. Is identity stable across observation, persistence, and recovery?
